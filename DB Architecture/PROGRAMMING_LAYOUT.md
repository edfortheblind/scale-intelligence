# Database programming reference

The source and schema had already been captured, and a routine-to-table scan already existed. This delivery organizes the complete captured routine code and integrated table layouts in the three folders requested on 2026-10-08.

- [SP layout](SP%20layout/README.md): all 921 stored procedures, exact `.sql` source, parameters, retained logic contracts and table/dependency references.
- [Function layout](function%20layout/README.md): all 76 functions (66 scalar, nine multistatement table-valued, one inline table-valued), exact `.sql` source, parameters, return metadata and logic documentation.
- [Table layout](table%20layout/README.md): all 518 tables and all 16,968 captured table columns, with full captured metadata and the routines that refer to each table.

Start with a routine's documentation, open its SQL to inspect all its code, and follow its table links to the column and constraint layout. A table's documentation links back to its routines. Each object also has a structured JSON record. Filenames use captured object IDs; each folder index supplies the readable schema-qualified names.

## Layout completeness and limits

Each table includes every captured column and applicable captured type, nullability, collation, identity, default, computed expression, key, index, foreign key, check, trigger, statistics, storage, partition and security record. JSON retains the exact relevant raw records and query-capture statuses. Ordered index keys, included columns and foreign-key column pairs remain explicit.

This is a **complete layout of the captured metadata**, not a deployable `CREATE TABLE` reconstruction or a new live schema inspection. The collector did not retain original table DDL, extended-property description values, all newer SQL Server table/column options or complete per-principal permissions. Unavailable metadata classes and these capture limits remain visible.

The replica includes custom, staging and alternate objects. Membership in this capture does not prove that every object is an unmodified vendor-base SCALE object. No database routine was executed and no application records were collected for this task. Runtime behavior, deployment and correlated process timing acceptance remain unchanged.

## Rebuild and verify

```powershell
python tools/build_programming_layout.py
python tools/build_programming_layout.py --verify-only
```

`--verify-only` checks every exported file against the retained manifest and writes nothing. Changed, missing, added or renamed files fail verification; verification does not accept those changes as a new baseline. To save a new dated receipt, add `--verification-output` followed by a new `.json` path outside the source snapshot and export folders. Existing files cannot be overwritten through this option.

Run the build command only when deliberately regenerating the exports. A successful build establishes a new manifest after its source and structural checks pass. Preserve older verification receipts as dated evidence. [C34 verification correction](../_project/PROGRAMMING_VERIFICATION_C34.md) records the earlier check-only gap and its regression tests.

Rebuilding requires the retained private snapshot. The exported documentation and source are readable independently of that private snapshot. The builder first creates a [fresh table correlation](evidence/programming-layout-table-usage.json) against the current reviewed batches; the earlier table-usage report remains historical. Verification checks original source bytes/hashes, object identity sets, captured-input hashes, parameter/return metadata, table columns/constraints and local documentation links. See the [build summary](evidence/programming-layout-build-summary.json), [verification receipt](evidence/programming-layout-verification.json) and [export manifest](evidence/programming-layout-manifest.json).
