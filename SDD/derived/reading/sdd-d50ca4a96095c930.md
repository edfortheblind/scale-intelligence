```text
I. 
INTRODUCTION 
 
This document is designed to outline the proposed process for the SCALE implementation at 
Grupo Julio distribution center in Mexico. This implementation design includes one Distribution 
Center that will follow the functionality described in this document. Future implementations at 
other Grupo Julio’s facilities may result in either change being made to this document or entirely 
new functional flows per facility. 
 
The objective of this document is to define the proposed process and scope from a Manhattan 
Associates’ perspective and to identify key extensions to the Manhattan Associates suite of 
products. This document serves as a reference throughout the process for confirmation of the 
approach and definition of tasks. It will also serve as a reference for Manhattan Associates’ 
customer support organization after implementation, and potentially a reference point for any 
future Grupo Julio’s implementations. 
 

```

```text
IV. KEY DECISIONS / ASSUMPTIONS
```

<a id="p011-b003"></a>
## p011\-b003 — PDF page 11, block 3

```text
1) The scope of this document is limited to the standardized flows identified for the 
distribution center (DCs) of Grupo Julio in Mexico. In case additional flows are required 
for the future, a new design will need to be developed, to include potential new flows not 
covered by this design. 
2) Item master in SCALE is maintained with company information. All inventory in SCALE 
will have the company Grupo Julio. 
3) Host system assigns the company Grupo Julio for the interfaced Item Master, Receipt or 
Shipment. There is no manually maintained items. 
4) Item Master in SCALE includes units of measure, dimensions, and weights for all 
products for all units of measure. This information will be interfaced into SCALE from the 
Host system. 
5) All dimensions are stored using CM (Centimeters). 
6) All weights are stored using KG (Kilos). 
7) Grupo Julio will manage items with company information. An item that belongs to 
company A cannot be used to fulfill an order for company B, which means items cannot 
be shared across companies. 
8) Item master in SCALE does not maintain Item Cross Reference. 
9) Grupo Julio has only one storage template (pza), that is configured to have a single UOM 
(pza). 
10) The storage template has the ‘Group during check-in’ set to ‘Yes’. 
11) Grupo Julio maintains item location capacity by Item. 
12) Grupo Julio has all items configured with the same Item Class: Doblado. 
13) Grupo Julio does not have decimals for inventory quantities. 
14) Grupo Julio does not track serial numbers for items. 
15) Grupo Julio does not track lots. 
16) Handling Hazardous materials is outside the scope of this implementation. 
17) Grupo Julio uses base SCALE cross-docking. In 2015 version Grupo Julio had an 
extension (EX02) that was developed but never used. Grupo Julio has decided to not 
migrate this extension at this moment. If, in the future, Grupo Julio decides to revisit this 
extension, additional efforts will be required to analyze the requirements and the 
necessary adjustments to port the extension. 
18) Item categories is not used by Grupo Julio. 
19) An item in an order (shipment in SCALE) may have multiple details lines. This can happen 
because the order may be consolidated. 
20) Grupo Julio will not use Cubiscan for gathering dimensions and weight of the items during 
receiving. 
21) Location Unit of Measure Override will not be used. 
22) Grupo Julio does not have license plate tracked inventory locations. The only license 
plate tracked locations are the receiving dock locations. 
23) Reserve locations are not license plate tracked. 
24) P&D locations are not used in regular picking work. P&D will be used by PTL (Put to 
Light) integration. 
25) Base inbound QC is out of the scope of this implementation. 
26) Grupo Julio does not use “Quick Receive”. 

```

```text
existing open wave, or they may select Create New Wave to manually assign the 
shipment(s) to a new wave.  When executing the New Wave action, the system 
prompts the user to select a Wave Master to act as a template that manages the 
movement of shipments through the wave cycle. User selects the appropriate
```

```text
10.2.4 Container Creation / Creación de contenedores 
Container creation is the process in which SCALE determines the number of 
containers and each container’s contents for every shipment on the wave. A 
unique container number, commonly referred to as a UCC 128, is assigned to 
every container as it is created. 
 
La creación de contenedores es el proceso en el que SCALE determina el número 
de contenedores y el contenido de cada contenedor para cada envío en la ola. Se 
asigna un número de contenedor único, comúnmente denominado UCC 128, a 
cada contenedor a medida que se crea. 
 
SCALE first takes all items whose allocated unit of measure is set up as a 
‘shippable unit’ and creates full containers. Shippable units are defined in the item 
unit of measure configuration. Full containers are containers that are shippable 
without repacking into another container (box). Pallets, gaylords, and certain cases 
are generally configured as shippable units. 
 
SCALE primero toma todos los artículos cuya unidad de medida asignada está 
configurada como una "unidad transportable" y crea contenedores completos. Las 
unidades que se pueden acoplar se definen en la configuración de la unidad de 
medida del artículo. Los contenedores llenos son contenedores que se pueden 
enviar sin volver a empacar en otro contenedor (caja). Los pallets, gaylords y 
ciertos casos generalmente se configuran como unidades enviables. 
 
SCALE then takes the remaining ‘loose’ items whose allocated unit of measure is 
set up as ‘not shippable’ and groups them together by Packing Class. A Packing 
Class is defined on the Item Master and then defaulted on the Shipment Detail. 
Each Packing Class is associated with a container group. A container group is a 
listing of container types (box sizes) listed from largest container to smallest 
container. SCALE attempts to cube items into the least number of containers 
possible. The total weight and volume are calculated for all the items on the 
shipment with the same packing group. SCALE first tries to cube into the first 
container of the container group. If capacity still exists, the system tries cubing into 
the next container type and continues until either capacity in the next priority is 
reached or there are no additional priorities.
```
