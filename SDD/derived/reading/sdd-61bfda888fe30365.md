```text
Allow Splitting Of Container - Defines whether or not, you will be allowed to split off and pick a portion of the quantity into another container. To accommodate this action, the system will create a new work unit and container for the split quantity. This is helpful if the container that you are picking into gets full before you are done picking the current quantity. Typically this situation would occur if you created containers in the wave, and the current pick physically will not completely fit into the container that the system created for it.
```

<a id="b00123"></a>
## b00123 — word/document\.xml/body/\*\[123\]

```text
Allow Over Picking - Allows the user to pick more quantity than exists on a work instruction, as long as this quantity is within the location's available quantity. When an over pick is performed, the system will increment the transaction quantity, and process the pick as a complete/normal pick. This option is only available for RF replenishment and work order picking. For example, suppose a work order component work instruction calls for 980 eaches of an item. It may be easier physically, then, for the worker to pick two cases of 500 (for a total of 1,000 eaches) rather than breaking one case open and leaving 20 eaches loose at the location. If this checkbox is checked, the system will increment the instruction by 20 eaches, and process the pick as normal.
```

<a id="b00124"></a>
## b00124 — word/document\.xml/body/\*\[124\]

```text
Allow Pick In Transit - Allows the user to pick in transit quantities. If there is not enough quantity in the location to be picked but there is additional inventory that is 'on the way', this allows the user to pick from what is coming or 'in transit'. If the inventory is picked against what's in transit, the inventory will show a negative quantity.
```

<a id="b00125"></a>
## b00125 — word/document\.xml/body/\*\[125\]

```text
Close After Partial Pick Checkbox - Allows the user to partial pick the quantity of a work instruction, and the system will delete the remaining quantity from the work instruction. The system will then close the work instruction. Therefore, the remaining quantity will never actually be picked. For example, suppose you have a replenishment request that calls for 620 eaches of an item. The user, however, may only want to pick 600 eaches of the item (because that is a more round number in regards to how things are packed), so they just want the other 20 eaches to “go away.” If this option is checked, the system would delete the remaining 20 eaches from the work instruction (after the user picks the 600), and close the work instruction.
```

```

 System Built Cart Picking - Process
```

<a id="b00341"></a>
## b00341 — word/document\.xml/body/\*\[341\]

```text
The system directed cart building process enables the application to assign containers created in a wave to a cart when the user initiates the work unit using Warehouse Mobile. This enables the system to include on carts containers that were created after the initial day’s wave(s) have been run. Also, the system tries to assign containers to the cart in an order (configured by zone) that will provide an optimum walking path when the worker picks products into the cart. This improves the picker(worker) efficiency by reducing the picking time against the manually assigned containers to the cart.
```
