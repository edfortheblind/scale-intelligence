Property Placeholders in Spring.NET
View with Navigation Tools
Third Party Software > Spring.NET > Property Placeholders in Spring.NET

Spring.NET offers the ability to inject configuration values from a variety of sources into objects using property placeholders.  This gives the application the ability to define not only the configuration values in centralized and easily modifiable sources, but also allows the end user to change where and at what level these values are stored.

To describe how property placeholders work, let's dive into a simple contrived example.  The following object definition tells Spring.NET to construct a class Manh.ILS.Example.Class1 and to set the configValue constructor argument based on the configValuePlaceholder property placeholder.  Note that property placeholders always have the form ${property placeholder name}.

Object with Property Placeholder
Copy Code 
<object id="IClass1" type="Manh.ILS.Example.Class1, Example">
    <constructor-arg name="configValue" value="${configValuePlaceholder}" />
</object>

Next, the Spring.NET provided Spring.Objects.Factory.Config.VariablePlaceholderConfigurer is configured to tell Spring.NET where to look for property placeholder values.

VariablePlaceholderConfigurer
Copy Code 
<object type="Spring.Objects.Factory.Config.VariablePlaceholderConfigurer, Spring.Core">
    <property name="VariableSources">
        <list>
            <object type="Spring.Objects.Factory.Config.ConfigSectionVariableSource, Spring.Core">
                <property name="SectionNames" value="appSettings" />
            </object>
            <object type="Spring.Objects.Factory.Config.PropertyFileVariableSource, Spring.Core">
                <property name="Location" value="file://~/Example.properties" />
            </object>
        </list>
    </property>
</object>

The VariableSources property defines a list of sources that Spring.NET uses to find property placeholder values.  This example shows a ConfigSectionVariableSource that reads values from the appSettings section of a .NET configuration file, followed by a specific Java-style properties file read by the PropertyFileVariableSource.  Note that if a placeholder's value is defined in both of these sources, the one defined first will be used.  The above setup thus allows for process specific values in the application configuration to override values defined in Example.properties.

The applicatoin defines a VariablePlaceholderConfigurer object similar to this example in the Objects.xml file deployed in the Common folder.

For illustration purposes, the following shows how our example configValuePlaceholder could be defined as both a typical appSetting or in a Java-style property file:

.NET Configuration Example
Copy Code 
<appSettings>
    ...
    <add key="configValuePlaceholder" value="this is the value of configValuePlaceholder" />
    ...
</appSettings>
Java-style Property File Example
Copy Code 
configValuePlaceholder = this is the value of configValuePlaceholder
