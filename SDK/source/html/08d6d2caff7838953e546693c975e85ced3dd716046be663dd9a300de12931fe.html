Transaction Page Stored Procedures
View with Navigation Tools

Most transaction screens are bound via a stored procedure. This allows for a dynamic runtime binding that is easily customizable. This topic will describe the basic format of a transaction screen stored procedure. Please reference the How to: Tie a Transaction Page to a Stored Procedure topic for more information on tying a transaction screen to a stored procedure.

 Parameters

The parameters that will be passed to the stored procedure are defined by the query parameters passed to the transaction page in the URL. For example, the URL /<servername>/scale/trans/printselecteddocuments?InternalNum=23833&printProcess=70 will pass two parameters to the stored procedure - InternalNum and PrintProcess.

Please note that culture is automatically passed into every transaction stored procedure. This allows for resource translation inside the stored procedure. So the final parameters for the example above would be:

Transaction stored procedure parameters
Copy Code 
ALTER PROCEDURE MetaTrans_GetPrintSelectedDocuments(
@internalNum int, @printProcess int, @culture nvarchar(10))

Finally, please note that query parameters can be passed in the URL but not passed to the stored procedure by prefixing with an underscore. So the URL /<servername>/scale/trans/printselecteddocuments?InternalNum=23833&printProcess=70&_customParam=customValue would call the stored procedure in the exact same manner as the example above.  

 Returning scalar objects from the stored procedure

Most controls on a transaction screen are bound with simple values that can be returned as scalar values and bound based on data source names matching the column names in the stored procedure. For these types of simple controls, a scalar data table can be returned as illustrated below.

Scalar set
Copy Code 
--shipment level docs
SELECT 
   N'SCALAR' AS N'EntityType',
   N'PrintSelected' AS N'EntityName', 
   @printProcess AS 'PrintProcess', 
   SH.INTERNAL_SHIPMENT_NUM AS 'InternalNum',
   SH.SHIPMENT_ID AS 'Id', 
   N'SHIPMENTID' AS 'IdLabel', 
   N'' AS 'ShipperCode', 
   N'' AS 'CarrierSymbol', 
   SH.COMPANY AS 'Company',
   SH.WAREHOUSE AS 'Warehouse'
FROM 
   SHIPMENT_HEADER SH
WHERE 
   INTERNAL_SHIPMENT_NUM = @internalNum;
 Returning lists from the stored procedure

Other controls take lists and cannot be bound via the scalar set mentioned above. These can still be bound via the stored procedure by returning another data table representing an identifier/desription list. This list is still bound via the data source name matching the "EntityName" from the stored procedure. An example of this is illustrated below.

List binding
Copy Code 
select 
   N'ID_DESC_TABLE' AS N'EntityType', 
   N'DocumentTypes' as N'EntityName', 
   DT.DOCUMENT_TYPE AS N'Identifier', 
   DT.DESCRIPTION AS N'Description', 
   case when ((PRINT_PROC1 = @printProcess and DEFAULT1 = N'Y') 
      or (PRINT_PROC1 = @printProcess and DEFAULT1 = N'Y') 
      or (PRINT_PROC1 = @printProcess and DEFAULT1 = N'Y') 
      or (PRINT_PROC1 = @printProcess and DEFAULT1 = N'Y') 
      or (PRINT_PROC1 = @printProcess and DEFAULT1 = N'Y'))
   then N'Y' else N'N' end as 'DEFAULT'
from 
   DOCUMENT_TYPE DT
where 
   PRINT_PROC1 = @printProcess or PRINT_PROC2 = @printProcess or PRINT_PROC3 = @printProcess or PRINT_PROC4 = @printProcess or PRINT_PROC5 = @printProcess;
