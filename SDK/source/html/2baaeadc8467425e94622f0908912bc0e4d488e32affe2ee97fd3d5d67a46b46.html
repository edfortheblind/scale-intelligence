Extensibility > Warehouse Mobile Extensibility

We would like to enable warehouse mobile platform, to achieve extensibility in a very easy way, even in SaaS environment, without having access to the Application server, having to the disposition only the remotely accessible tools:

  • ActivityArchitect to change Warehouse Mobile Flows
  • Creation of Web API exit points
  • Creation of REST Web Service Exit Point Programs calling Azure Web functions or custom REST web services on different reachable hosting
  • Creation of Stored Procedure Exit Point Programs in the database

For example, we will have the possibility to insert a new step to the header/item receiving process. Extending the current flow with a new step, checking for truck status for receiving:

Configuration steps

Configuration schema to achieve extensibility

The main idea is that with the help of exit point we have to attach to the normal execution of the Warehouse Mobile flow, and redirect it to our new flow step we desire to be shown to the user, capture data input, and once again with the help of the exit points we save the data and we redirect the execution flow to continue with the original flow.

Screen Flow configuration

  1. Customize the header/item receiving flow

    1. Open the ActivityArchitect and make a duplicate for the existing Receiving flow in the activity architect

    2. Give a new Screenflow name and File name for the extended receiving

    3. Add a new flow step CustomEntry

    4. Set title and add a custom picker control “Truck status”

    5. On the Go action add the URI call that points to the configured endpoint and in the Next Flow textbox you need to add the next screen in the flow. In this exampled we used the LPEntry screen. The URI is /general/scaleapi/GenericWhsMobileApi/whmendpoint-executed?identifier=manhValidateCustomEntry

      We are doing this because we want to continue the execution, after the CustomEntry as it was continued from QtyEntry. Basically our intention is to insert the CustomEntry step between the QtyEntry and LPEntry.

  2. Assign the Extended Receiving flow to the desired receiving preference menu

    1. Open Warehouse Mobile menu configuration from Activity Architect main page

    2. Search for the Receiving preference, and choose to edit from actions, or click preference name link

    3. Assign the new Extended Receiving flow

End Point configuration

We need to create a new Warehouse Mobile Endpoint that will send the data from the Custom screen to the external webservice. In the below example we used an Azure web function written in Node.js to handle the screen change and to save the data to an Azure Blob Storage account.

How to configure a Warehouse Mobile Endpoint

Exit Points configuration

  1. Add the Web API exit points to capture and modify WarehouseMobile payload

    How to create a Web API exit point

  2. Write the custom web service to update the payload coming back from SCALE ReceiptApi/receipt-check-in

    You can use whatever you prefer, as this can even be on a different hosting, Azure web function, etc. There are couple of guidelines we need to take into account.

    The SCALE web api invoking methodology is sending in the POST body an array with following input parameters:

    1. @SessionXML, containing essential values as user, warehouse, etc.

    2. @URI is the uri for the SCALE api was captured by the exit point, in our case will be '/inbound/scaleapi/ReceiptApi/receipt-check-in'

    3. @DataModel this is the essential dataModel we have to update to redirect the WarehouseMobile execution to the new CustomEntry flow, that is why in the sample we take this value and update it.

    4. null value – not used for now

    When writing the external web service, please note that the Warehouse Mobile Exit Point and the Warehouse Mobile End Point send data in two different modes. The Warehouse Mobile End Point only sends the 3rd parameter. In this case the data needs to be handled a bit differently.

    For convenience we put here a Nodejs code a simple web service to achieve our goal.

    Sample Node JS Web Service Code

    const multipart = require("parse-multipart");
module.exports = async function (context, req) {
   var data_parsed = false;
   try {
      var dataModel = JSON.parse(req.body.Parameters[2]);
      data_parsed = true;
   }
   catch(error) {
   }
   if(data_parsed==false) {
      try {
         var dataModel = JSON.parse(JSON.stringify(req.body));
         data_parsed = true;
      }
      catch(error) {
      }
   }
   
   if(dataModel.SRCFlow == 'LPEntry' && dataModel.ReceivingPreference == '5607-RP') {
      dataModel.CustomEntry = '';
      dataModel.SRCFlow = 'CustomEntry';
   }
   else if(dataModel.SRCFlow == 'CustomEntry') {
      dataModel.SRCFlow = 'LPEntry';
      try{
         dataModel.custom.SRCFlow = 'LPEntry';
      }
      catch(error){
      
      }
   }
   if(dataModel.SRCFlow == 'LPEntry' && dataModel.ReceivingPreference == '5607-RP') {
      context.bindings.storage = dataModel.custom.CustomEntry;
   }
   
   context.res = {
      body: dataModel
   };
}
