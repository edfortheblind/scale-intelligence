How to: Create a Dynamic Action Requiring User Input via Modal Dialog with Yes/No Confirmation Prompt
View with Navigation Tools
User Interface Extensibility > Metadata Web Pages > Actions > How to: Create a Dynamic Action Requiring User Input via Modal Dialog with Yes/No Confirmation Prompt

At times an action may require user input that triggers a GET service call that peforms some type of validation that will present the user with a yes/no confirmation message. Based on the user's response to the yes/no confirmation, another POST, DELETE, or GET service call may be required. This is most complex action type currently supported through straight metadata.


An example of this that is shipped with the system is the "Save Search" action that is shipped with the insight screens. In this scenario, the user chooses the "Save Search" action, which presents a modal dialog asking the user to enter a name for their search. Once the user enters a name for their search, the system performs a GET service call that determines if that search name already exists for that user on the current insight screen. If it doesn't exist, then no "ConfirmationMessage" field is passed back. If it does exist, then a "ConfirmationMessage" of "Search name already exists. Do you wish to continue and overwrite the existing value?" is passed back and a yes/no confirmation prompt is given to the user. Any complexities beyond this type of scenario would required coding changes instead of metadata changes. In order to configure this type of scenario, setup the metadata as follows.

 Step 1: Create a new GET web service call
If a new web service call is required, create it. Reference the various web service sections of the SDK for more information. This web service method should contain a field in the return entity named "ConfirmationMessage" if a message should be displayed to the user (based on the input they entered). This message will be displayed to the user in a yes/no confirmation prompt.
 Step 2: Create a new POST or DELETE service call
If a new web service call is required, create it. Reference the various web service sections of the SDK for more information. This web service will be called after the yes/no confirmation if one exists, or will be called immediately if no yes/no confirmation needs to be displayed.
 Step 3: Create a modal dialog
Create the modal dialog control with the user input required. Reference the How to: Create a Dynamic Modal Dialog topic for instructions.
 Step 4: Create a screen control or find an existing screen control
Please reference the How to: Create Screen Controls topic for instructions on creating the control that will trigger the action.
 Step 5: Create the screen control event and parameters for displaying the modal dialog

Create a new SCREEN_CONTROL_EVENT record as follows. This defines what gets called when the event is fired. Insight Architect can also be used for this (How to: Use Insight Architect to Customize a Metadata Page).

Field Value
SCREEN_CONTROL_ID The Screen Control Id of the the control that fires the action
EVENT_ID click or another event to be fired depending on the type of the control
EVENT_NAME _webUi.dialog.showModalDialogByEvent


Now create a SCREEN_CONTROL_EVENT_PARAMETERS record to define the modal dialog control that should be displayed. Insight Architect can also be used for this (How to: Use Insight Architect to Customize a Metadata Page).

Field Value
PARAMETER_NAME ModalDialogName
PARAMETER_VALUE The name of the modal dialog control to display (e.g. SaveSearchModalDialog)
SCREEN_CONTROL_ID_EVENT_ID The Object Id of the screen control event
 Step 6: Create the screen control event and parameters to call the modal dialog action web service
In the footer section of the modal dialog control, one of the buttons should be configured as the "positive" action. This action will be triggered when the user inputs the proper data and chooses the affirmative action such as "OK" or "Save". This action is tied to an event through the same SCREEN_CONTROL_EVENT and SCREEN_CONTROL_EVENT_PARAMETERS records as other actions. There is a special function to perform a GET service call from a modal dialog window with the possibility of a yes/no confirmation prompt afterwards. The SCREEN_CONTROL_EVENT created should be as follows. Insight Architect can also be used for this (How to: Use Insight Architect to Customize a Metadata Page). 
Field Value
SCREEN_CONTROL_ID The Screen Control Id of the the control that fires the affirmative action
EVENT_ID click
EVENT_NAME _webUi.insightListPaneActions.modalDialogPerformGetWithConfirmation

This function should have SCREEN_CONTROL_EVENT_PARAMETERS records create for both the initial GET service call and the subsequent POST or DELETE service call after the yes/no confirmation. It will automatically show the yes/no confirmation if there is a ConfirmationMessage field returned by the GET service call. If the user chooses "no" the system will always stop processing and keep the modal dialog control open. If the user chooses "yes" the system will always call the POST or DELETE service that is configured. Both the GET and the POST or DELETE SCREEN_CONTROL_EVENT_PARAMETERS records are created in the standard metadata fashion spelled out in the How to: Perform a GET Service Call from Metadata Action, How to: Perform a GET Service Call from Metadata Action, and How to: Perform a DELETE Service Call from Metadata Action topics. In addition to all of these service related SCREEN_CONTROL_EVENT_PARAMETERS records, create a SCREEN_CONTROL_EVENT_PARAMETERS record to define the modal dialog control tied to these events. Insight Architect can also be used for this (How to: Use Insight Architect to Customize a Metadata Page).

Field Value
PARAMETER_NAME ModalDialogName
PARAMETER_VALUE The name of the modal dialog control to hide upon successful web service completion (e.g. AssignHoldCodeModalDialog)
SCREEN_CONTROL_ID_EVENT_ID The Object Id of the screen control event
 Step 7: Create the screen control event and parameters to hide the modal dialog for the cancel action
       

Modal dialogs will also have a "cancel" type action that will need to close the modal dialog without doing any processing. Create a new SCREEN_CONTROL_EVENT record as follows. This defines what gets called when the event is fired. Insight Architect can also be used for this (How to: Use Insight Architect to Customize a Metadata Page).

Field Value
SCREEN_CONTROL_ID The Screen Control Id of the the control that fires the cancel action
EVENT_ID click
EVENT_NAME _webUi.dialog.hideModalDialogByEvent


Now create a SCREEN_CONTROL_EVENT_PARAMETERS record to define the modal dialog control that should be displayed. Insight Architect can also be used for this (How to: Use Insight Architect to Customize a Metadata Page).

Field Value
PARAMETER_NAME ModalDialogName
PARAMETER_VALUE The name of the modal dialog control to hide (e.g. AssignHoldCodeModalDialog)
SCREEN_CONTROL_ID_EVENT_ID The Object Id of the screen control event
