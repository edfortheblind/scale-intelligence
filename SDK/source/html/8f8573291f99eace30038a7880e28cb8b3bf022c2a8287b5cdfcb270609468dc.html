How to: Define Lists tied to Controls
View with Navigation Tools
User Interface Extensibility > Metadata Web Pages > Shared > How to: Define Lists tied to Controls

Metadata based screens allow for controls such as drop downs, checked list boxes, etc. to be tied to a list of values. The list of available values is retrieved dynamically at runtime based on the metadata configured. Therefore these lists can be defined and controlled by clients at runtime.

The DATA_SOURCE_TYPE and DATA_SOURCE fields in the SCREEN_CONTROL table drive this dynamic list retrieval. The following are valid DATA_SOURCE_TYPE values for retrieving lists tied to controls:

 

Data Source Type Value Description
ConfigType 10 Retrieves lists for normal configurations; works exactly like the "ConfigType|…" lists within generic configurations. The supported list of types is defined in a generic configuration with record type of "METADATACONFIGTYPE".
Generic 30 Retrieves lists for generic configurations; works exactly like the generic lists within generic configurations. Any generic configuration record type is supported.
TableFields 40 Retrieves a list of columns for a database table.

 

 How to configure control lists based on ConfigType records

This section defines how ConfigType records can be used to fill dynamic lists tied to controls in metadata screens. The valid ConfigType values can be found in the "Metadata Config Type" configuration.

Specifying a DATA_SOURCE_TYPE of 10 (ConfigType) in the SCREEN_CONTROL table indicates to the system that it should use built-in retrieval logic based on the value in the DATA_SOURCE field to fill the list tied to the control. The following table contains a few samples – please reference the "Metadata Config Type" configuration for the full list of supported values.

 

Data Source Example
Warehouse To retrieve the list of authorized warehouses, specify data source type = 10 and data source = Warehouse.
Company To retrieve the list of authorized companies, specify data source type = 10 and data source = Company.
ProNumber To retrieve the list of Pro Number records, specify data source type = 10 and data source = ProNumber.

 

 

 How to configure control lists based on Generic record types

This section defines how generic configuration lists can be used to fill dynamic lists tied to controls in metadata screens. All generic configuration record types are valid for use in creating metadata lists.

Specifying a DATA_SOURCE_TYPE of 30 (Generic) in the SCREEN_CONTROL table indicates to the system that it should use built-in retrieval logic based on the value in the DATA_SOURCE field to fill the list tied to the control. The following table contains a few samples – please note that any generic configuration record type can be used.

 

Data Source Example
COUNTRY To retrieve the list of countries configured in the system, specify data source type = 30 and data source = COUNTRY.
DISPOSCODE To retrieve the list of disposition codes, specify data source type = 30 and data source = DISPOSCODE.
WORKTEAM To retrieve the list of work teams, specify data source type = 30 and data source = WORKTEAM.

 

 

 How to configure control lists based on TableFields

This section defines how the TableFields data source type can be used to fill dynamic lists tied to controls in metadata screens. All tables in the SCALE database are eligible.

Specifying a DATA_SOURCE_TYPE of 40 (TableFields) in the SCREEN_CONTROL table indicates to the system that it should use built-in retrieval logic based on the value in the DATA_SOURCE field to fill the list tied to the control. The following table contains a few samples – please note that any SCALE database table can be used.

 

Data Source Example
LOCATION_INVENTORY To retrieve the list of columns in the location inventory table, specify data source type = 40 and data source = LOCATION_INVENTORY.
SHIPMENT_HEADER To retrieve the list of columns in the shipment header table, specify data source type = 40 and data source = SHIPMENT_HEADER.
ITEM To retrieve the list of columns in the item table, specify data source type = 40 and data source = ITEM.
