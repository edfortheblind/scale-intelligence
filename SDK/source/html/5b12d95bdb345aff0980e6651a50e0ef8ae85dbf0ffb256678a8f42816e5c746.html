How to: Create a New Transaction Page
View with Navigation Tools
User Interface Extensibility > Metadata Web Pages > Transaction Pages > How to: Create a New Transaction Page

The tooling provided for creating a new custom Transaction page is not complete. For now, follow the instructions below in order to create a new Transaction page.

 Step 1: Copy an Existing Transaction Page Script

Browse to the directory that SCALE is installed to and then go to the sub folder Database | ILS | Scripts | _Metadata | Transaction. Pick a script for a screen that is the most similar to the page you want to create. Copy the script to another location, rename it, and open it.

 Step 2: Update Script with Page Level information

Update the script for all page level information as follows:

 

  • Form Id: Use a different Form Id for your new screen. At the top of the script you will see the Form Id being set similar to this: set @formId = 2767. Search and replace the actual Form Id value in the script with your new Form Id. The new Form Id value you use should be the next available Form Id >= 60,000. So in the example given above, the Form Id 2767 should be replaced by 60000 everywhere in the script.
  • Form record: Update the call to DBC_IFORM as follows:
    • @formKeyName = MNU_<customScreenName>Transaction (i.e. MNU_CustomTransaction)
    • @tableName = the name of the SQL Stored Procedure that will provide the view model for the Transaction screen. At the beginning you can leave the existing value in this field if you want the screen to open up initially as an exact replica of the screen script that was copied.
    • @associatedFormKey = null
  • Security: Remove all calls to dbc_ISecurityCheckpoint except for security_checkpoint 1 ("run").
  • Screen record: Update the call to DBC_IMAINUISCREEN as follows:
    • @functionalArea = the identifier of the functional area you want the screen to show up under in the menu
    • @menuResourceKey = the Resource Key to be used for the page title
    • @path = Update based on the Form Key Name entered on the Form record (i.e. /scale/trans/<portion of Form Key Name between the starting "MNU_" and ending "transaction")
    • @restrictionsId = set this to the configured Spring Id for the .NET class that will house the "restrictions" list for the screen, if any (see the Field Restrictions topic for more information)
    • @defaultsId = null
  • Licensing: Remove all calls to dbc_IMainUiWmLicenseXrefOriginal.
 Step 3: Run the Modified Script

Open SQL Server Management Studio and run the modified script ensuring there are no errors. Run an IISRESET and then try to browse to the new page. The URL will be in the format https://<serverName>/scale/trans/<portion of form key name>?<list of query parameters> (for example, if the Transfer Container script is copied, and the new form key name is listed as MNU_CUSTOMTRANSACTION, then the URL would be in the format https://<serverName>/scale/trans/custom?internalContainerNum=2822. Please note that if a new stored procedure is specified in the Table Name column of the Form record, then the screen will not function until the stored procedure exists and the controls on the script bind with it properly.

 Step 4: Modify the General Controls on the Page

Now that the new page exists, we can modify the screen metadata for the general controls on the page using either Insight Architect (How to: Use Insight Architect to Customize a Metadata Page ), modifying the script mentioned above, or straight SQL against the database. Transaction screens are formatted in the exact same way as Details screens, so please reference the topics How to: Modify an Existing Transaction Page and How to: Create Section Headers on a Detail/Transaction Screen  for a general overview of the Details and Transaction metadata.

 Step 5: Modify any Grids on the Page

Now modify the screen metadata for any grids that need to be on the page using either Insight Architect (How to: Use Insight Architect to Customize a Metadata Page ), modifying the script mentioned above, or straight SQL against the database. Reference the topic How to: Add a Grid to a Detail/Transaction Screen for a general overview of the metadata for grids on a Transaction page.

 Step 6: Modify the Actions

Now modify the screen metadata for the Actions on the page using either Insight Architect (How to: Use Insight Architect to Customize a Metadata Page ), modifying the script mentioned above, or straight SQL against the database. Reference the topic How to: Add Detail/Transaction Screen Menu Options for a general overview of the Actions metadata.
