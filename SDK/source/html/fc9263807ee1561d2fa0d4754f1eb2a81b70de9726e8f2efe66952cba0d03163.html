Notifications > Overview

The Notifications framework is architected as a two stage system - creation and then delivery - to ensure high performance and scalability. The overall idea is that various processes in the system would create notification messages and a background service (SCALE Monitor Service) would pick them up, templatize the message (if required) and deliver to (configurable) destinations.

It depends on a few configurations being in place (please consult product Help documentation for more details):

 Configurations
Configuration setting Description
SMTP server URL is configured in Technical values, For SaaS, value is taken from default database.
Notification record/s Table configuration header record for message, title etc. The ObjectID of the notification record is referenced from the generated Notification Messages.
Notification Address record/s Table configuration detail records tied to the Notification header for email addresses (semi-colon delimited), message template, delivery mechanism (Email, SMS etc.) and flag for file attachments.
Delivery Mechanism/s

Email and SMS delivery mechanisms come with the base product. These are configured as Dynamic_Calling_Details of record type NOTDELIVER. This allows for extensibility in the sense that additional mechanisms can be configured by providing a code implementation.

Note: SMS delivery mechanism leverages the email integration provided by most mobile carriers wherein they allow an email to be sent to a specific domain address and will translate this request into an SMS transmission to a mobile phone. The list of carrier supporting this feature is quite large and it generally documented on their web sites. A helpful list of Email to SMS gateways is available here.
 Notification template formats

The raw Notification messages can be styled based on template files that can support both plain text and HTML content (to support rich formatting). These templates also support tokens as described in the next section. This facilitates message content with rich styling, embedded url's and a lot more.

The notification templates are supported in two formats - Xml and text. The message content supported is primarily derived from what is traditionally supported in emails - text and html. The Xml template is useful in scenarios where the csv message data contains multiple rows and the final notification is expected to represent that information. The text template is useful in simpler scenarios where limited information from the first row of the csv data or a fixed alert is to be sent - which is often the case with SMS alerts.

Xml Template - Allows plain text or html content within an xml document
Copy Code 
<NotificationTemplate>   
    <Header>Message body header (supports tokens taken from 1st row in csv message data)</Header>
    <RowTemplate>Text here is repeated per row available in the csv message data (supports tokens)</RowTemplate>
    <Footer>Message footer (supports tokens taken from 1st row in csv message data)</Footer>
</NotificationTemplate>

Example showing template that generates html email content:
<NotificationTemplate>   
    <Header>
        <![CDATA[<html lang="en-us">
                <body>
                <p><span style='font-size:18.0pt;font-weight:bold;color:#00cc00'>Shipments on Loads confirmed on [[CURRENTDATETIME]] </span></p>
                <p><ul style='font-size:12.0pt;color:black'>]]>
    </Header>
    <RowTemplate>
        <![CDATA[<li>[[ROWINDEX]]. Shipment ([[SHIPMENT_ID]]) has been confirmed on load [[SHIPPING_LOAD_NUM]].
           It will be shipped in [[TOTAL_CONTAINERS]] parcels via [[CARRIER]] [[CARRIER_SERVICE]]. </li>]]>
    </RowTemplate>
    <Footer>
        <![CDATA[</ul></p> <p>Thank you for your patronage,
        [[WAREHOUSE]] </p>
                </body>
            </html>]]>
    </Footer>
</NotificationTemplate>

 The following example shows a text template for SMS (limited to max 160 characters) that has a web link to a shipment.

Text Template - Allows plain text or html content
Copy Code 
Shipment [[SHIPMENT_ID]] will be late. Link http://[[SERVERNAME]]/scale/details/shipment?internalNum=[[INTERNAL_SHIPMENT_NUM]]
 Notification template tokens

Notification templates support tokens that can be replaced dynamically from message data. In such cases the message data is assumed to be in CSV (comma separated value) format, with the first row representing column names. This facilitates dynamic message content based on actual data taken from the raw message. A token in the template is any field enclosed within double square brackets - [[Field]]

The following table lists all supported pre-defined tokens. Beyond this, anything from the csv message header can also be used as tokens.

Token Description Sample template/example
NOTIFICATIONMESSAGE Full raw notification message replaces this token The alert is - [[NOTIFICATIONMESSAGE]]. Thanks.
SERVERNAME The name of the application server that is delivering the notification The alert was generated from [[SERVERNAME]] environment.
CURRENTDATE Today's date in the current culture's short date format 2015-01-15T13:45:30 -> 01/15/2015 in the en-US culture
CURRENTDATETIME Current date with long time format 2015-01-15T13:45:30 -> 1/15/2015 1:45:30 PM in the en-US culture
CURRENTDATECUSTOM Allows custom formatting of date with formats

The alert was generated on [[CURRENTDATECUSTOM.d MMM]].

After template processing the notification looks like - The alert was generated on 15 Jan.
ROWINDEX Represents the index of the row from csv data. Typically this is to be used in RowTemplate section along with other csv based tokens, so that the section will be repeated per row data available in the csv message. If used in Header or Footer sections it will be replaced with value “1”
CONDITIONALDATA [[CONDITIONALDATA.Text.COLUMNNAME]] - should print "Text" if COLUMNNAME value is not null [[SHIPMENT_ID]] will be shipped via [[CARRIER]] [[CONDITIONALDATA. service .CARRIER_SERVICE]]

Any non-recognizable tokens in the template are replaced with null text in the final notification message.
