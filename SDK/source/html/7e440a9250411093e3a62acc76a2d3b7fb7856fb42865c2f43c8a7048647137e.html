This page reviews how SCALE automates the navigation between metadata screens. These patterns should be followed if you need to customize a screen or create a new metadata screen.

 Navigation Trail

SCALE tracks the last 10 pages that have been visited by the user in a Navigation Trail in the top Navigation bar on each page. The only exceptions to this are as follows:

  • If a user cancels out of a Details or Transaction page, that page is not included in the navigation trail history.
  • If a user successfully completes a Details or Transaction page, that page is not included in the navigation trail history.
  • Sign on pages and error pages are not included in the navigation trail history.
  • Any page that has excludeFromNavTrail=Y as a query parameter is not included in the navigation trail history.
 Cancel

Details and Transaction pages should all have a Cancel button. The cancel action should take the user back to the previous page in their navigation history. To do this, the cancel action on any page should call the SCALE provided function _webUi.detailsScreenBinding.cancel.

       
 Success

Upon successful completion of a Details or Transaction page, the user should be taken back to the previous page in their navigation history in most circumstances. Most screens can accomplish this navigation by simply specifing the base SCALE success callback functions for the web service call on the Details or Transaction page, which are _webUi.detailsScreenBinding.successCallbackUpdate and _webUi.detailsScreenBinding.successCallbackInsert.

If your screen requires logic beyond what exists in the base SCALE success callback functions, create your own callback function, do your custom logic, and then call _webUi.navigationTrail.navigateBackToPreviousPage.

Custom success callback
Copy Code 
// web service call specifying custom successCallbackUpdate
_httpRequest.performPost(postUrl, webserviceobject, customSuccessCallbackUpdate, errorCallbackUpdate, false);
var customSuccessCallbackUpdate = function (data, textStatus, jqXHR) {
    // do custom logic here
    _webUi.navigationTrail.navigateBackToPreviousPage(false, $.trim(data.MessageType), data.MessageCode, null);
};

There are certain screens that should stay open after success when opened from the main menu, but close when opened as an action against a specific record (i.e. close container). These screens will need their own callback functions as well, but should use the query parameter NavToPrev=Y when called from an action against a specific record. There is a generic function _webUi.navigationTrail.doesUrlIndicateFlowShouldNavigateToPreviousPage provided to check this query parameter.

Success callback for dual screens
Copy Code 
if (_webUi.navigationTrail.doesUrlIndicateFlowShouldNavigateToPreviousPage()) {
    _webUi.navigationTrail.navigateBackToPreviousPage(false, $.trim(data.MessageType),
        data.MessageCode, null);
}
else {
    // reset variables, screen, etc. but keep it open
}
