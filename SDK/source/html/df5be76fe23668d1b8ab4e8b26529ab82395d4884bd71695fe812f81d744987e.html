Web Api routing
View with Navigation Tools

Web Api routing is composed of three steps:

  • Find the route and parse the route data
  • Find the matching controller
  • Find the matching action
 Find the route and parse the route data
  • In this step the route will be parsed in order to find the controller, action, and other data in the URL.
  • Currently there are two routes defined in SCALE for Web Api 
    • Route Description
      Scaleapi/{Controller}/{Action}/{Id} In this route you will need to specify the action also. For example, in order to call update status on the LotApi Web Api controller, the route should be: POST scaleapi/LotApi/UpdateStatus. This is the recommended route.
      Scaleapi/ {Controller}/{Id} In this route you will need to specify the controller only. For example, in order to call update status on the LotApi controller, the route should be POST scaleapi/LotApi.
Note: Id is optional for both of these routes.
 Find the matching controller
Controller matching is done purely based on the value of the “controller” key in the route data. If the key “controller” doesn’t exist in the route data, controller selection will fail.
 Find the matching action
  • If the route data contains the key "action" then the action will be searched based on the action name and the verb.
  • If the route data doesn’t contain the key “action”, then the action will be searched based on the supported request method directly.
Note: Every route is defined in the IntegrationServices/HTTP/App_Start/WebApiConfig.cs file.
