Define Execution Identifier
View with Navigation Tools

When you configure events in the application you need to provide an Execution Identifier. This identifier is used to create an instance of the class that is responsible for processing the message received from an MHE. To create an execution identifier simply follow these steps:

 

1. Your identifier must implement interface IDIFApi which is located in assembly DeviceIntegrationFramework.Interfaces under the Common folder.

 

2. Define your execution identifier in Spring.NET. Put your object definition in a custom file and add an import directive in file  Objects.DeviceIntegrationFramework.BL.xml

Custom file with execution identifier entry
Copy Code

<objects xmlns="http://www.springframework.net">

<object id="IncomingTCPServerEndpointHandler" type="Custom.API.BL.CloseContainer, Custom.API.BL, Version=8.0.0.0, Culture=neutral, PublicKeyToken=a978a715ccadf176" singleton="false" autowire="constructor"/>

</objects>
Add import directive to file Objects.DeviceIntegrationFramework.BL.xml
Copy Code

<objects xmlns="http://www.springframework.net">

<import resource="file:/%SCALE_HOME%/Settings/Custom.xml" />

</objects>

3. Update your endpoint configuration. Specify the spring object id in column EXECUTION_IDENTIFIER of table DIF_EVENT

 

4. IDIFApi – Two methods are exposed by IDIFApi, both should be implemented by implementing class out of which only the one should have business logic while the other should just return.

Execute(int messageId)
Copy Code
void Execute(int messageId);

Here, DIFIncomingMessage messageId is parameter.

Execute(string difIncomingMsgAsJson)
Copy Code
void Execute(string difIncomingMsgAsJson);

Here, DIFIncomingMessage full message is parameter in JSON format.

 

A couple of things to note here

1. The application will only create once instance of the execution identifier to service all of the requests. If you need to have an instance created for each request your API will have to be a wrapper that creates an instance for each of the requests.

2. If the MULTI_THREADED flag on DIF_EVENT is on, your API and the business logic that it executes must be thread save.
