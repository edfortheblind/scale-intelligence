How to: Configure Layout of Metadata Pages

The metadata screen framework is built using Twitter Bootstrap. In particular the grid system layout is used to define the basic layout of the screen. This section will go into more detail about defining the layout css classes of the screen.

 Screen Layout Overview

Screen layout is defined in metadata via css class definitions. This section will provide an overview of how this layout is configured using the insight screen layout as an example.

An insight screen consists of a screen container with three panes (Search, List, and Detail). These elements of the screen are rendered when the metadata elements define Bootstrap css classes on the div elements of the html. In particular, the metadata insight screens are using the container, row and col classes.

The container is defined as a 12 column grid system. Css was used to achieve this 3 column layout css by defining each pane as 4 columns (col-md-4). This makes each pane the same size. The insight screen allows the search pane to be collapsed when in this view the list pane is modified to include additional columns, giving them different sizes. In this scenario the list pane column has 8 columns of the grid system (col-md-8), and the detail pane has 4 columns of the grid system (col-md-4). As the page is resized the media queries within the Bootstrap infrastructure alter the classes accordingly to size to the device viewport.

The contents of each pane can have their own css defined in metadata for a screen part, screen group, and screen control by specifying the appropriate css class.

 Defining Metadata Layout Classes

Each table has its own columns used to define the layout/css of the elements on the screen. Refer to the columns in the table below that are associated with defining the layout of each part of the metadata.


Table Name Column Description
SCREEN_PART DIV_CSS_CLASS Defines any css classes that should be applied to a screen part. The css is placed on the screen part div wrapper in the html. The Bootstrap column layout for the screen parts should be defined here in addition to any other css classes that should be applied over the entire screen part.
SCREEN_GROUP ROW_CSS_CLASS Used when a screen group is wrapped in a Bootstrap grid row. This column defines any css classes that should be applied to the groups row div in the html. The Bootstrap row class should be defined here in addition to any other css classes that should be applied over the entire screen group.
SCREEN_GROUP DIV_CSS_CLASS Defines any css classes that should be applied to a screen group. The css is placed on the screen group div wrapper in the html.
SCREEN_GROUP_COLUMN COLUMN_CSS_CLASS Defines any css classes that should be applied to the columns of a screen group that is nested in a Bootstrap grid row. The Bootstrap column layout for the screen group column should be defined here in addition to any other css classes that should be applied over the entire column.
SCREEN_CONTROL DIV_CSS_CLASS Defines any css classes that should be applied to the wrapper of a screen control. The css is placed on the screen control div wrapper in the html.
SCREEN_CONTROL CONTROL_CSS_CLASS Defines any css classes that should be applied to a screen control. The css is placed on the screen control itself in the html. For example, specifying an ellipsis for the label control when the text is longer than the control itself.


In addition to the Bootstrap grid layout the metadata framework also has its own set of custom classes found in the manh.css file. These classes define colors, padding, height, etc. for the metadata. More information on customizing the styles can be found in the How to: Override the Default Theme for Metadata Screens topic.
