How to: Customize Field Restrictions through Exit Point Programs
View with Navigation Tools
User Interface Extensibility > Metadata Web Pages > Detail Pages > How to: Customize Field Restrictions through Exit Point Programs

Restrictions represent the list of fields on a screen that should always be restricted (or read-only). The system provides the exit point Field Restrictions – Modify, that should be used to override the list of base restrictions. The sql utility function ModifyCommaSeparatedStringList can be used to modify field restrictions in stored procedure exit point programs.

 

The following example represents a sample implementation of the Field Restrictions – Modify exit point program using a stored procedure. 

Sample exit point program for Field  Restrictions - Modify exit point
Copy Code 
CREATE PROCEDURE [EXP_FieldRestrictionsModify] (
    @SESSIONVALUE xml,
    @FORMID numeric,
    @SCREENNAME nvarchar(max),
    @INTERNALNUM numeric,
    @RESTRICTIONS nvarchar(max),
    @RETURNVALUE nvarchar(max) output
)
AS
    SET NOCOUNT ON;
    DECLARE @fieldsToAdd nvarchar(max), @fieldsToRemove nvarchar(max), @userName nvarchar(max);
    SET @userName = '';
    SET @fieldsToAdd = '';
    SET @fieldsToRemove = '';
    IF (@FORMID = 2759) -- Work instruction
    BEGIN       
       
        -- If we want allow only a particular user to edit fields Description and User Defined 8
        -- If user is not 'userName' then do not allow user to edit Description and User Defined 8 field
        EXEC dbo.GetXMLAttributeValueByAttributeName @SESSIONVALUE,'Session/User',@userName OUTPUT
        IF (@userName <> 'userName')
        BEGIN
            SET @fieldsToAdd = 'ITEMDESCRIPTION,UDWORK_INSTRUCTION8'
        END

        -- Update base restrictions
        SELECT @RETURNVALUE = dbo.ModifyCommaSeparatedStringList(@RESTRICTIONS, @fieldsToAdd, @fieldsToRemove)
    END
    ELSE
       begin
         SELECT @RETURNVALUE = @RESTRICTIONS
       END
