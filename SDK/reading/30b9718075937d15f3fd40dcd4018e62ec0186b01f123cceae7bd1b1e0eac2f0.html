SOA Abstract Discussion

What Is Service Oriented Architecture?

Service Oriented Architecture (SOA) means many things to many people, depending on the context in which it exists. For the purposes of this discussion, it will be used to describe an architecture that exposes the application business processes that are consumable by disparate applications.

What Is the Need For Service Orientation?

This is because a major challenge that exists today is the integration of disparate applications within any given enterprise. It is quite common for a suite of applications to work in concert with each other in order to provide a fully functional supply-chain solution. Very rarely does a single application provide all the functionality required by a business operation. Services provided by other applications need to be leveraged to provide an enterprise-level solution. Applications within an enterprise may not be based on the same technology stack. There may be Java-based applications, C++-based applications, RPG programs etc. Service orientation provides a unified approach to integrating applications based on different technologies.

What Are The Tenets of Service Orientation?

To establish a service oriented architecture, it is recommended that four basic principles be followed. These are:

  1. Boundaries are explicit
     
  2. Services are autonomous
     
  3. Services share schema and contract, not class
     
  4. Service compatibility is based upon policy

While it is not the purpose of this paper to discuss these tenets in-depth, it can be stated in summary that: Services are independent, have a well-defined interface, communicate via messages expressed in XML and have policies that state how they can be consumed.

How Do Web Services Relate To SOA?

Web services and SOA web services are services that are exposed over the web or, more aptly put, are services that are accessed over a network protocol. Web services can be used to form the backbone of a SOA; however, implementing web services does not equate to having a SOA as the tenets mentioned above must be adhered too. Because of the ubiquitous nature of http, it has become the predominant protocol of choice for making web services available. However, services can be accessed by other common protocols such as TCP, SMTP, FTP, etc.

How Is XML Used With SOA?

As implied by the third tenet of service orientation, services communicate via messages in a format that is commonly understood by parties involved. The most commonly understood protocol for expressing messages is XML. The structure of the messages shared between services is described by XML Schema. SOAP is an XML-based messaging protocol that has become standardized and forms the basis of what are called “Web Services Specification” or WS-*, which are a set of specifications that state how SOAP-based messages are formed to handle scenarios such as security, addressing, metadata exchange, business process co-ordination etc. However it should be stated that service orientation does not require the use of SOAP-based messages.

Conclusion

In summary, the application provides a set of integration points that are exposed through Integration Services, are available both over HTTP and TCP. These services are intended for usage by external applications that need to leverage business processes provided by the application.

SOA Strategy As Applied To Manhattan SCALE

What Are The SOA Design Approaches?

There are 3 predominant architectural styles being used to develop services. These are:

  • REST – Representational State Transfer
     
  • SOAP (MEST) – Message State Transfer
     
  • RPC – Remote Procedure Call

The intent of this article is not to discuss, compare or evaluate the architectural styles between themselves. Rather, the article will explain the usage of the architectural styles within the application's SOA strategy.

What Are REST-Based Services?

The REST architectural style exposes entities as resources (nouns) over the web. Access to these resources is through the use of the standard HTTP verbs GET, POST, PUT and DELETE. The GET operation is idempotent, i.e. a GET does not change the state of the resource returned; it is a safe operation. The resources are commonly represented are XML documents.

This architectural style is ideal for service interaction that is synchronous and requires a wide-reach due to a large audience. Multiple message exchange patterns (MEPs) are generally not supported.

There is also lack of standardized document for REST-based services. Custom documentation must be created that explains how these services can be accessed.

The application services that are of a data-retrieval nature will generally be REST-based.

What Are SOAP Services?

The MEST architectural style focuses on the passing of messages between systems. These messages are normally SOAP-based and conform to the SOAP and WS specifications. Because service interaction is event driven i.e. a specific method on the service is not explicitly invoked, there are formal methods for interaction. A message is just sent a defined endpoint.

This architectural style is ideal for all types of service interactions. However it is a little more complex as there is an extra layer of SOAP processing that must be handled. This architectural style allows for use of a more diverse group of transport protocols such as SMTP, TCP, FTP etc.

Documentation for SOAP services is done using WSDL or SSDL.  

The application services that are leveraged for business processing will generally be SOAP.

What Are RPC Services?

RPC services are pretty similar to the concept of distributed objects. In this architectural style, methods are created on the service side and then exposed to consumer via a proxy. WSDL is sometimes used to create such proxies.   This discussion does not go into the architectural ramifications of this architectural style, as SCALE does not leverage this style.

What Are Request Schemas?

This is the XML schema that represents the data that is sent to the web service.

What Are Response Schemas?

This is the XML schema that represents the data is returned from the web service.
