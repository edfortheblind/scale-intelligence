How to: Create Screen Control Grid Columns
View with Navigation Tools
User Interface Extensibility > Metadata Web Pages > Shared > How to: Create Screen Control Grid Columns

The SCREEN_CONTROL_GRID_COLUMNS table allows for dynamic metadata configuration of various grid values, such as columns, column headings, column types. Please note that to create a new insight screen or add columns to an existing grid, currently C# code is required for the model in addition to updating or inserting SCREEN_CONTROL_GRID_COLUMNS records. Please review the How to: Create the Grid Model topic for more information.

 

For information on how to tie an event to the grid column see the How to: Create Screen Control Events topic.
 Step 1: Create select columns

Add a SCREEN_CONTROL_GRID_COLUMNS record for each column that should be in the grid as follows. Insight Architect can also be used for this (How to: Use Insight Architect to Customize a Metadata Page).

Field Value
FIELD The literal field name or aggregate value that will be executed as part of SQL query. For example, this could be something like "sum(On_Hand_Qty)".
FIELD_NAME The alias for the FIELD. If the FIELD is "sum(On_Hand_Qty)" and the FIELD_NAME is ON_HAND_QTY, then the query for the column will be rendered "sum(On_Hand_Qty) as ON_HAND_QTY".
FIELD_TYPE The column type. The full enumeration of available field types can be found in the "Metadata Field Types" configuration.
FIELD_WIDTH The default width of the column in the grid. Use null to specify that column should be "auto sized" based on the largest value in the column (header text or actual row values). Use integer value to specify an actual column width in pixels. The value will be overridden if the user changes the column width manually from the screen itself.
RESOURCE_KEY The resource key for the header text of the column.
SCREEN_CONTROL_ID The Object of the grid screen control the column is tied to.
SEQUENCE Used to determine the default order of the columns in the grid. This will be overridden if the user changes the column order manually.
SQL_CLAUSE_TYPE 20 (Select)
DECIMAL_POSITIONS Used to define what "Decimal Positions" configuration record the column should use.
HIDDEN Used to default a column to hidden.
COLUMN_TEMPLATE Used to define templating for grid columns. Please reference http://www.igniteui.com/grid/column-template for more information.
IS_PRIMARY_KEY Determines whether or not the column is the primary key for the grid. This is required if the "delete" option will be enabled in the grid. Only one primary key should be specified per grid.
ALLOW_SORT Determines whether or not the column can be sorted. Default value is Y. Set to N to turn off sorting for the column.
 Step 2: Create where columns

Extra filters on a query can either be processed directly by creating or modifying the SQL view that a grid is tied to, or by creating SCREEN_CONTROL_GRID_COLUMNS records. To add extra conditions that always apply to the search query, add a SCREEN_CONTROL_GRID_COLUMNS record for each extra condition as follows. Insight Architect can also be used for this (How to: Use Insight Architect to Customize a Metadata Page).

Field Value
FIELD The extra condition to apply to the query. For example, this could be something like "On_Hand_Qty > 0".
FIELD_NAME NULL
FIELD_TYPE NULL
FIELD_WIDTH NULL
RESOURCE_KEY NULL
SCREEN_CONTROL_ID The Object of the grid screen control the column is tied to.
SEQUENCE NULL
SQL_CLAUSE_TYPE 40 (Where)
DECIMAL_POSITIONS NULL
HIDDEN NULL
