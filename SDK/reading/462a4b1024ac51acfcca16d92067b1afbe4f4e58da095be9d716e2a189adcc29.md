    <div id="i-body-content" class="i-body-content" data-source-node="n46">
        <p data-source-node="n47">Insight Architect supports creating a basic Monitor page. Follow the below instructions for creating a new Monitor page.</p>

<div id="i-d0bc1aa7-053c-4b78-8fa4-150b839cf475-section-heading" class="i-section-heading" data-source-node="n48">
    <span class="i-section-heading-icon" data-source-node="n49"><span class="i-hidden" data-source-node="n50"> </span></span><span class="i-section-heading-text" data-source-node="n51">Step 1: Open the Insight Architect Monitor Builder</span>
</div>

<div id="i-d0bc1aa7-053c-4b78-8fa4-150b839cf475-section-content" class="i-section-content" data-source-node="n52">
    <p data-source-node="n53">Browse to the URL <a href="https://travstg.manhscale.com/%3cservername%3e/scale/trans/monitoringbuilder?internalFormId=0" data-source-node="n54">https://&lt;servername&gt;/scale/trans/monitoringbuilder?internalFormId=0</a> - this must be done manually as this page is not accessible via the main menu.</p>
</div>

<div id="i-03378d0f-aa7a-4056-8eda-1d43d04f3e8c-section-heading" class="i-section-heading" data-source-node="n55">
    <span class="i-section-heading-icon" data-source-node="n56"><span class="i-hidden" data-source-node="n57"> </span></span><span class="i-section-heading-text" data-source-node="n58">Step 2: Fill the Required Data in Insight Architect for the New Monitor Page</span>
</div>

<div id="i-03378d0f-aa7a-4056-8eda-1d43d04f3e8c-section-content" class="i-section-content" data-source-node="n59">
    <p data-source-node="n60">Fill in the required fields on the screen:</p>

    <ul data-source-node="n61">
        <li data-source-node="n62"><strong data-source-node="n63"><em data-source-node="n64">Form id</em></strong>: Will default to the next available Form Id. Either leave as is or change to desired Form Id.</li>

        <li data-source-node="n65"><strong data-source-node="n66"><em data-source-node="n67">Form key name</em></strong>: Format as MNU_&lt;monitoringscreenname&gt;_MONITORING (i.e. if my Monitor will be named "Custom", then use MNU_Custom_Monitoring.</li>

        <li data-source-node="n68"><strong data-source-node="n69"><em data-source-node="n70">Functional area</em></strong>: Choose the functional area that the new Monitor screen should be under in the menu.</li>
    </ul>

    <p data-source-node="n71">Expand the Summary Tiles section and add a record for each summary tile you want at the top of the Monitor page:</p>

    <ul data-source-node="n72">
        <li data-source-node="n73"><strong data-source-node="n74"><em data-source-node="n75">Sequence</em></strong>: Numeric value that controls the order in which the tiles will show up.</li>

        <li data-source-node="n76"><strong data-source-node="n77"><em data-source-node="n78">Data binding</em></strong>: The column name that must be returned from the stored procedure for the Monitor page.</li>

        <li data-source-node="n79"><strong data-source-node="n80"><em data-source-node="n81">Resource key</em></strong>: The resource key that will be translated for the summary tile.</li>
    </ul>

    <p data-source-node="n82">Expand the Actions bar section and fill the required fields:</p>

    <ul data-source-node="n83">
        <li data-source-node="n84"><strong data-source-node="n85"><em data-source-node="n86">Insight</em></strong>: Represents the parameters passed when the user clicks the Insight button in the Actions bar of the new Monitor page. Either enter the proper value if you are familiar with the formatting, or just enter "FORM_ID=2723,SearchPaneWhs=FROM_WHS;" for now and we will come back and update it later. This default value will just make the Insight button on the Actions bar go to the Inventory Insight screen filtered by the users current warehouse.</li>

        <li data-source-node="n87"><strong data-source-node="n88"><em data-source-node="n89">Breadcrumb resource keys</em></strong>: Enter a resource key that will be translated in the breadcrumb trail for each level drill-down the chart will have.</li>
    </ul>

    <p data-source-node="n90">Expand the Chart area section and fill the required fields:</p>

    <ul data-source-node="n91">
        <li data-source-node="n92"><strong data-source-node="n93"><em data-source-node="n94">Stored procedure</em></strong>: Specify the name of the stored procedure that will be used to return the chart data and summary tile data.</li>

        <li data-source-node="n95"><strong data-source-node="n96"><em data-source-node="n97">Data binding</em></strong>: Specify the column name in the stored procedure that will represent the chart data.</li>

        <li data-source-node="n98"><strong data-source-node="n99"><em data-source-node="n100">Insight URL</em></strong>: Represents the parameters passed when the user drills down to the last level of the chart and therefore into an Insight page with filters. Either enter the proper value if you are familiar with the formatting, or just enter "FORM_ID=2723,SearchPaneWhs=FROM_WHS;" for now and we will come back and update it later. This default value will just make the drill down in the chart go to the Inventory Insight screen filtered by the users current warehouse.</li>

        <li data-source-node="n101"><strong data-source-node="n102"><em data-source-node="n103">Insight criteria</em></strong>: Represents the common parameters passed when moving from a Monitor page to an Insight page. Either enter the proper value if you are familiar with the formatting, or just enter "from_whs=@warehouse;" for now and we will come back and update it later. </li>

        <li data-source-node="n104"><strong data-source-node="n105"><em data-source-node="n106">Drill down levels</em></strong>: Enter a drill down level (0, 1, 2 where 0 is chronologically first) and criteria for each drill down level you want in the chart. Each subsequent drill down level should have the criteria from the previous level plus one extra criteria. For example, level 0 might just be "from_whs=@warehouse;", level 1 be "from_whs=@warehouse,locating_zone=@locatingZone;", and level 2 be "from_whs=@warehouse,locating_zone=@locatingZone,location_type=@locationType;".</li>
    </ul>

    <p data-source-node="n107">Expand the Indicator tiles section and fill the required fields:</p>

    <ul data-source-node="n108">
        <li data-source-node="n109"><strong data-source-node="n110"><em data-source-node="n111">Stored procedure</em></strong>: Specify the name of the stored procedure that will be used to return the indicator tile data.</li>

        <li data-source-node="n112">
            <strong data-source-node="n113"><em data-source-node="n114">Indicator tiles</em></strong>: Create records for each indicator tile you want on the Monitor page:

            <ul data-source-node="n115">
                <li data-source-node="n116"><strong data-source-node="n117"><em data-source-node="n118">Resource key</em></strong>: The resource key that will be translated for the indicator tile.</li>

                <li data-source-node="n119"><strong data-source-node="n120"><em data-source-node="n121">Data binding</em></strong>: Specify the column name in the stored procedure that will represent the indicator tile data. </li>

                <li data-source-node="n122"><strong data-source-node="n123"><em data-source-node="n124">Tile criteria</em></strong>: Represents the parameters passed when moving from a Monitor page to an Insight page by clicking on an indicator tile. Either enter the proper value if you are familiar with the formatting, or just enter "from_whs=@warehouse;" for now and we will come back and update it later. </li>

                <li data-source-node="n125"><strong data-source-node="n126"><em data-source-node="n127">Go to Insight URL</em></strong>: Represents the URL that will be generated to go to an Insight page when an indicator tile is clicked. Either enter the proper value if you are familiar with the formatting, or just enter "FORM_ID=2723,SearchPaneWhs=@warehouse" for now and we will come back and update it later.</li>

                <li data-source-node="n128"><strong data-source-node="n129"><em data-source-node="n130">Caution criteria</em></strong>: Leave blank for now, we will come back later.</li>

                <li data-source-node="n131"><strong data-source-node="n132"><em data-source-node="n133">Warning criteria</em></strong>: Leave blank for now, we will come back later. </li>
            </ul>
        </li>
    </ul>

    <p data-source-node="n134">Click the Save button. The beginning of your new Monitor page will appear.</p>
</div>

<div id="i-57ae35ba-9f6d-4e21-bc78-48e17a0792af-section-heading" class="i-section-heading" data-source-node="n135">
    <span class="i-section-heading-icon" data-source-node="n136"><span class="i-hidden" data-source-node="n137"> </span></span><span class="i-section-heading-text" data-source-node="n138">Step 3: Modify the Required Stored Procedures</span>
</div>

<div id="i-57ae35ba-9f6d-4e21-bc78-48e17a0792af-section-content" class="i-section-content" data-source-node="n139">
    <p data-source-node="n140">Up until now we have used the Insight Architect tool to create the beginning of a Monitor page. Many of the values may still be the default values mentioned above just so that we could get a working base and now we can modify the more complex portions of the Monitor screen via the metadata portion of Insight Architect (<a href="9d1879df4946560f87a878505496d9ada1e9ac63368517e75e0d9428da242ec2.html" data-source-node="n141">How to: Use Insight Architect to Customize a Metadata Page</a> ).</p>

    <p data-source-node="n142">As a part of the previous step, the Insight Architect tool generated stored procedures based on the names you gave in the stored procedures fields above. It also put random number generation in for the chart, summary tiles, and indicator tiles, which is why your new screen is showing values when you have not told it what values to actually show. Since it has created a stored procedure skeleton for us, it is now easy to go modify the stored procedure(s) with the proper SQL to return the values we want to return in the columns that are now returning random numbers.</p>
