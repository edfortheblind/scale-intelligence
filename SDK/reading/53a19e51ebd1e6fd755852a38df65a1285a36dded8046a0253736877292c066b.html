3D Cubing is a new container creation strategy in SCALE. Container creation strategies till this point only looked at the volume, weight and critical dimensions of the item to be packed. 3D Cubing, in addition to these parameters, also analyzes the physical size of the items being placed into the carton and the geometric configuration of the carton’s volume to determine which set of items will fit together into a carton.The advantage of such an approach is that it never suggests a packing that is not feasible.

This section is divided into 3 parts. The first one indicates the current features that 3D Cubing leverages. The second talks about additional features that can be configured and the third discusses the exit point program and other changes that are required to enable the advanced features.

 3D Cubing features in Base SCALE

There are some changes in the way container creation configuration values are used by the 3D Cubing container creation strategy.

 

Configuration Description

Packing Class

The packing class is defined for an item or an item class. It is tied to a container group and packing criteria.

Packing Criteria

 3D Cubing supports a value for item break attribute.
Container Group

The container group contains a list of container types and the corresponding fill percentage. 3D Cubing ignores the fill percentage value.

Default Stabilization Value

This configuration can be accessed under Container Creation System Values. It denotes the amount of space that needs to be left out between 2 items when they are packed. For E.g. if the default stabilization code value is 0.5 then then 0.5 units of space if left out on either side so for an item having dimensions 2x3x4 the effective dimensions is 3x4x5.

 

 Advanced 3D Cubing Features

Below are the additional item and container type features that are supported by 3D Cubing.

 

Item Master Configuration Additions:

 

Configuration Description

Orientation

This is used for limiting item orientation. The “L”, “W”, or “H” dimension of the item has to be forced along the height axis of the container. If left blank, allow any orientation.

Cavity Length

This refers to the length of the cavity in the item.

Cavity Width

This refers to the width of the cavity in the item.

Cavity Height

This refers to the height of the cavity in the item.

Incremental Length

When like-items are nested, this is the additional length in a nested stack of adding one additional item.

Incremental Width

When like-items are nested, this is the additional width in a nested stack of adding one additional item.

Incremental Height

When like-items are nested, this is the additional height in a nested stack of adding one additional item.

Maximum Units Nested

 This refers to the maximum number of like-items that can be nested together.

Stackable Item

This value indicates whether the item can be positioned above or below other items in the container. If this value is ‘N’, then this item cannot be positioned above or below other items. If this value is ‘Y’, then there is no restriction.

Protection Factor

 Protection Factor (PF) indicates how sturdy a container is. The larger the item’s PF, the more fragile the item and the more protection is required from its container. Every item will be assigned to a container which has a PF that is greater than or equal to the PF required by the item.

Container Size

If an item’s Container Size matches that of the Container_Type, then packing is allowed. This value can indicate whether the container type should be Big, Medium or Small when all these container types are present in the relevant container group.

 

Container Type Configuration Additions:

 

Configuration Description

Protection Factor

Protection Factor (PF) indicates how sturdy a container is. The larger a container’s PF, the sturdier the container is and the more protection it offers. Every item will be assigned to a container which has a PF that is greater than or equal to the PF required by the item.

Container Size

 If an item’s Container Size matches that of the Container_Type, then packing is allowed. This is a string value and could represent what kind of container items should be packed in.

Minimum Container Weight

Minimum weight of the container. If the weight of items packed is less than this value, then the 3D Cubing algorithm generates an alert.

Minimum Container Volume

Minimum container volume.If the volume of items packed is less than this value, then the 3D Cubing algorithm generates an alert.

 2D Pack Algorithm

The 2D Pack Algorithm provides the feature to arrange a given item along a specific box edge. The 2D pack algorithm is used when the system is directed to use "ItemOrientation" during packing. The "ItemOrientation" needs to be set using exit point "3D Cubing Stabilization Code Assignment – Before". If the item orientation is not set, the system will not honor the 2D Pack algorithm.

Note:-System currently does not support Item Orientation along with stacking. If Item Orientation is set, system will consider only 2D Pack Algorithm.

  

"ItemOrientation" Property restricts the orientation of item in the box.

  • "L" – represents orientation along Length of the item.
  • "W" – represents orientation along Width of the item.
  • "H" – represents orientation along Height of the item.
  • Blank represents no orientation restrictions.

 

"ItemPlacement" Property decides the dimension to keep alongside of the big dimension of box in horizontal plane(X or Y axis) when new row is being created.

  • 0 - Keeps big dimension of item alongside of big dimension of box.
  • 1 - Keeps small dimension of item alongside of big dimension of box.

 

2D Pack algorithm details:

 

(1) The large dimension of the box after the orientation will be placed large side of the container (If, item orientation is set to height, either the length or the width of the container will be considered). It’s the beginning of the row.

(2) If the previous box fits, then try to place the next box in the same row. The next box should have a width less than the first box. If fits, then place the subsequent boxes.

(3) If the box doesn’t fit in step 2, rotate the box and try to fit. If the box still doesn’t fit, move to the next box (And leave the current box to try for the new row) for the same row and follow the same for all the remaining items till the space is left in the row. To do this follow step 2.

(4) Build the second row if items are yet to be placed and space is left in the container. To do this follow step 1.

 

  

For Example :

 

  

 

Row 1 is having boxes number 1, 2 and 3, and none of the row 1 box is having more width than box number 1. In row 1, box number 3 is placed after rotation.

Row 2 is having the box number 4 and 5. Though box 4 is big but it can’t be placed after the box 1 ,so placed in second row after placing 2 and 3 boxes.
