How to: Create Screen Controls
View with Navigation Tools
User Interface Extensibility > Metadata Web Pages > Shared > How to: Create Screen Controls

Screen controls represent a single control or set of controls within a single screen group. Screen controls are represented by the SCREEN_CONTROL database table. There can be 1-N screen controls (ordered by SEQUENCE field) for a particular screen group. Screen controls are tied to screen groups by the SCREEN_GROUP_ID field (SCREEN_CONTROL.SCREEN_GROUP_ID = SCREEN_GROUP.OBJECT_ID). In addition when the screen group has screen group columns there can be 1-N screen controls (ordered by the SEQUENCE field) for a particular screen group column. Screen controls are tied to screen group columns by the SCREEN_GROUP_COLUMN_ID field (SCREEN_CONTROL.SCREEN_GROUP_COLUMN_ID = SCREEN_GROUP_COLUMN.OBJECT_ID).

 Step 1: Determine the Object Id for the screen group or screen group column

Use the following SQL to determine the Object Id for the screen group or screen group column if you know the Form Id. This will return all screen groups or screen group columns on the page and you will need to find the appropriate screen group or screen grouop column from the list. Insight Architect can also be used for this (How to: Use Insight Architect to Customize a Metadata Page).

 

Find the Object Id for screen group or screen group column
Copy Code 
select * from SCREEN_GROUP where SCREEN_PART_ID IN (
    select OBJECT_ID from SCREEN_PART where SCREEN_ID in (
        select OBJECT_ID from MAIN_UI_SCREEN where FORM_ID = <form id>))


select * from SCREEN_GROUP_COLUMN where SCREEN_GROUP_ID in (
    select OBJECT_ID from SCREEN_GROUP where SCREEN_PART_ID IN (
        select OBJECT_ID from SCREEN_PART where SCREEN_ID in (
            select OBJECT_ID from MAIN_UI_SCREEN where FORM_ID = <form id>)))
 Step 2: Create screen control record

Create a new record in the SCREEN_CONTROL table tied to the corresponding SCREEN_GROUP or SCREEN_GROUP_COLUMN record for the screen group. Keep in mind that screen groups can be nested. Insight Architect can also be used for this (How to: Use Insight Architect to Customize a Metadata Page).

Field Description/Notes
CONTROL_NAME The name of the screen control.
RESOURCE_KEY The resource key of the label to show for the screen control, if any. Label can be to the left, above, or inline.
CONTROL_TYPE
 The type of the control. Please see the "Screen Control Type" configuration for an enumeration of all screen control types.
SEQUENCE Screen controls are rendered in sequence order.
DEFAULT_ACTION The button or link that should be triggered when the Enter key is pressed and focus is in the control. Please see the How to: Set Default Action for Enter Key topic for more details.
DIV_CSS_CLASS Used to configure the layout of the screen group. Please see the How to: Configure Layout of Metadata Pages topic for more details.
CONTROL_CSS_CLASS Used to configure the layout of the screen group. Please see the How to: Configure Layout of Metadata Pages topic for more details.
LABEL_ORIENTATION Where the label should be placed in relation to the control. Please see the "Label Orientation" configuration for an enumeration of all label orientations. Also see the How to: Set Label Orientation topic for more information.
DATA_SOURCE_TYPE The type of the data source. Please see the "Metadata Data Source Type" configuration for an enumeration of all data source types.
DATA_SOURCE The data source that will be used to fill the control. Values will vary based on the data source type specified.
DEFAULT_STATE The default state for the control. Please see the "Metadata Default State" configuration for an enumeration of all default states.
TOOL_TIP_RESOURCE_KEY The resource key for the tool tip tied to the control.
TEMPLATE_NAME The partial view name with controls as placeholder. Also see the How to: Set Template Name for a Screen Control topic for more information.
       
Please note that the dbc_IScreenControl stored procedure can be used to create screen controls.
