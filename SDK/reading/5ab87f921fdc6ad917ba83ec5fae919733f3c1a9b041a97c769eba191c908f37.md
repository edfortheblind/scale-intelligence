    <div id="i-body-content" class="i-body-content" data-source-node="n46">
        <p data-source-node="n47">The Notifications framework is architected as a two stage system - creation and then delivery - to ensure high performance and scalability. The overall idea is that various processes in the system would create notification messages and a background service (SCALE Monitor Service) would pick them up, templatize the message (if required) and deliver to (configurable) destinations.</p>

<p data-source-node="n48">It depends on a few configurations being in place (please consult product Help documentation for more details):</p>

<div id="i-SectionId-section-heading" class="i-section-heading" data-source-node="n76">
    <span class="i-section-heading-icon" data-source-node="n77"><span class="i-hidden" data-source-node="n78"> </span></span><span class="i-section-heading-text" data-source-node="n79">Notification template formats</span>
</div>

<div id="i-SectionId-section-content" class="i-section-content" data-source-node="n80">
    <p data-source-node="n81">The raw Notification messages can be styled based on template files that can support both plain text and HTML content (to support rich formatting). These templates also support tokens as described in the next section. This facilitates message content with rich styling, embedded url's and a lot more.</p>

    <p data-source-node="n82">The notification templates are supported in two formats - Xml and text. The message content supported is primarily derived from what is traditionally supported in emails - text and html. The Xml template is useful in scenarios where the csv message data contains multiple rows and the final notification is expected to represent that information. The text template is useful in simpler scenarios where limited information from the first row of the csv data or a fixed alert is to be sent - which is often the case with SMS alerts.</p>

<div id="i-SectionId-section-heading" class="i-section-heading" data-source-node="n165">
    <span class="i-section-heading-icon" data-source-node="n166"><span class="i-hidden" data-source-node="n167"> </span></span><span class="i-section-heading-text" data-source-node="n168">Notification template tokens</span>
</div>

<div id="i-SectionId-section-content" class="i-section-content" data-source-node="n169">
    <p data-source-node="n170">Notification templates support tokens that can be replaced dynamically from message data. In such cases the message data is assumed to be in CSV (comma separated value) format, with the first row representing column names. This facilitates dynamic message content based on actual data taken from the raw message. A token in the template is any field enclosed within double square brackets - [[Field]]</p>
