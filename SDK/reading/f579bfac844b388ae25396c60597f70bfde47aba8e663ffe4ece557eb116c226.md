    <div id="i-body-content" class="i-body-content" data-source-node="n40">
        <p data-source-node="n41">The following table describes the common use of HTTP headers by REST-Based Web Services in the application.  A specific service may override this default behavior, which will be described in the service's specific help topic.</p>

<p data-source-node="n42">For general information about HTTP Headers, consult <a href="http://www.w3.org/Protocols/rfc2616/rfc2616-sec14.html" data-source-node="n43">the corresponding section of the HTTP specification</a>.</p>

<p data-source-node="n44"> </p>

<p data-source-node="n45"></p>

<table class="members" data-source-node="n46">
    <tbody data-source-node="n47">
        <tr data-source-node="n48">
            <th class="nameColumn" width="84" data-source-node="n49">Header</th>

            <th class="descriptionColumn" data-source-node="n50">Description</th>
        </tr>

        <tr data-source-node="n51">
            <td width="84" data-source-node="n52"><a id="Accept" name="Accept" data-source-node="n53"></a>Accept</td>

            <td data-source-node="n54">
                <p data-source-node="n55">Communicates to the application the acceptable media types to include in response.  Acceptable values include <strong data-source-node="n56">application/json</strong>, <strong data-source-node="n57">application/xml</strong>, or a resource specific media type.  See each individual service's help topic for specifics.</p>

                <p data-source-node="n58">If a suitable media type cannot be determined, an error response with status code 406 (Not Acceptable) will result.</p>
            </td>
        </tr>

        <tr data-source-node="n59">
            <td data-source-node="n60"><a id="Accept-Encoding" name="Accept-Encoding" data-source-node="n61"></a>Accept-Encoding</td>

            <td data-source-node="n62">
                <p data-source-node="n63">Communicates to the application the acceptable encodings that will be applied to the corresponding response entity.  See <a href="b05aa4a4ff3488a09edf64e58286bc774076208b25af6e790509bae72294eefa.html" data-source-node="n64">Compression in REST-Based Web Services</a> for an example of where this header is used.</p>

                <p data-source-node="n65">Note the following:</p>

                <ul data-source-node="n66">
                    <li data-source-node="n67">Currently supported encodings: <strong data-source-node="n68">gzip</strong>, <strong data-source-node="n69">deflate</strong></li>

                    <li data-source-node="n70">The first supported encoding will always be honored across all services.</li>

                    <li data-source-node="n71">Parameters such as "q" values are ignored.</li>

                    <li data-source-node="n72">The special "identity" and "*" encodings are not supported.</li>

                    <li data-source-node="n73">If an Accept-Encoding is specified but no supported encodings are listed, an error response with status code of 406 (Not Acceptable) will result.</li>
                </ul>
            </td>
        </tr>

        <tr data-source-node="n74">
            <td data-source-node="n75"><a id="Accept-Language" name="Accept-Language" data-source-node="n76"></a>Accept-Language</td>

            <td data-source-node="n77">Communicates to the application the acceptable languages that should be used for localizable data on responses.  The application will use the first supported language in the list, and if none of the languages are supported or the Accept-Language is empty, the server's default language will be used.</td>
        </tr>

        <tr data-source-node="n78">
            <td data-source-node="n79">Authorization</td>

            <td data-source-node="n80">
                <p dir="ltr" align="left" data-source-node="n81"><span lang="EN" data-source-node="n82">A Oauth 2.0 Bearer Token is set in the Authorization header of every Inline Action HTTP Request. For example:</span></p>

                <p dir="ltr" align="left" data-source-node="n83"><span lang="EN" data-source-node="n84"><b data-source-node="n85">"Authorization: Bearer &lt;AbCdEf123456&gt;"</b></span></p>

                <p dir="ltr" align="left" data-source-node="n86"><span lang="EN" data-source-node="n87">The string "AbCdEf123456" in the example above is the bearer authorization token.</span></p>

                <p dir="ltr" align="left" data-source-node="n88"><span lang="EN" data-source-node="n89">If using bearer tokens, verify that the request is coming from the intended sender domain. If the token doesn't verify, the service should respond to the request with an HTTP response code 401 (Unauthorized)</span></p>

                <p dir="ltr" align="left" data-source-node="n90"><span lang="EN" data-source-node="n91">See <a href="1b044b3678b8df36572a2607e246cd42b6a06d9838c3d040b1378f8287b8005a.html" data-source-node="n92">Authentication in REST-Based Web Services</a> for more information.</span></p>
            </td>
        </tr>

        <tr data-source-node="n93">
            <td data-source-node="n94"><a id="Environment" name="Environment" data-source-node="n95"></a>Environment</td>

            <td data-source-node="n96">
                <p data-source-node="n97">If no environment are configured this value should be passed as Defaultaabf6698-37ae-45ee.</p>

                <p data-source-node="n98">If environments are configured this value should be the name of environment to which web service to be called. Environment name should match subdomain of hostname.</p>
            </td>
        </tr>

        <tr data-source-node="n99">
            <td data-source-node="n100">Cache-Control</td>

            <td data-source-node="n101">May be specified by The application to suggest how the client should cache a returned entity.  For example, if performing a GET on a resource that represents live, frequently changing data, a Cache-Control of <strong data-source-node="n102">no-cache</strong> may be returned.</td>
        </tr>

        <tr data-source-node="n103">
            <td data-source-node="n104"><a id="Content-Encoding" name="Content-Encoding" data-source-node="n105"></a>Content-Encoding</td>

            <td data-source-node="n106">
                <p data-source-node="n107">Describes the encoding that was applied to the included entity.  See <a href="b05aa4a4ff3488a09edf64e58286bc774076208b25af6e790509bae72294eefa.html" data-source-node="n108">Compression in REST-Based Web Services</a> for an example of where this header is used.</p>

                <p data-source-node="n109">Note the following:</p>

                <ul data-source-node="n110">
                    <li data-source-node="n111">Currently supported encodings: <strong data-source-node="n112">gzip</strong>, <strong data-source-node="n113">deflate</strong></li>

                    <li data-source-node="n114">The encodings applied by SCALE to a response entity are governed by the Accept-Encoding header on the request.</li>

                    <li data-source-node="n115">During a POST or PUT, a Content-Encoding may be specified on the request, which will force the application to decode the request entity before processing.  If the Content-Encoding contains an unsupported encoding value, an error response with status code of 415 (Unsupported Media Type) will result.</li>
                </ul>
            </td>
        </tr>

        <tr data-source-node="n116">
            <td width="84" data-source-node="n117"><a id="Content-Type" name="Content-Type" data-source-node="n118"></a>Content-Type</td>

            <td data-source-node="n119">
                <p data-source-node="n120">Describes the media type of the entity attached to both requests and responses.</p>

                <p data-source-node="n121">Requests must include this header for POSTs and PUTs.  If the specific media type of the attached entity is not know, then <strong data-source-node="n122">application/json</strong> or <strong data-source-node="n123">application/xml</strong> must be supplied.  If the media type is not recognized, an error response with status code of 415 (Unsupported Media Type) will result.</p>

                <p data-source-node="n124">The application will respond with the specific media type of a resource when available.  See each individual service's help topic for specifics.  Each media type ends with either <strong data-source-node="n125">json</strong> or <strong data-source-node="n126">xml</strong> to describe the serialization format.</p>
            </td>
        </tr>

        <tr data-source-node="n127">
            <td width="84" data-source-node="n128">MachineName</td>

            <td data-source-node="n129">
                <p data-source-node="n130">Indicates the client's machine name. In case of a terminal services user, it represents the machine from which the terminal services session was opened. It is the responsibility of the web service consumer to appropriately set this header.</p>
            </td>
        </tr>

        <tr data-source-node="n131">
            <td data-source-node="n132"><a id="Warehouse" name="Warehouse" data-source-node="n133"></a>Warehouse</td>

            <td data-source-node="n134">
                <p data-source-node="n135">Indicates the warehouse for which web service to be called</p>
            </td>
        </tr>
    </tbody>
</table>
