    <div id="i-body-content" class="i-body-content" data-source-node="n42">
        <p data-source-node="n43">Integration Endpoints refer to configurable extensions to the typical Manhattan SCALE system. These can be required components, such as Document Generators, where the base system ships and uses many different endpoints. They can also be optional components, such as Exit Points, that are used by consultants and/or customers to enhance the default functionality of the application to meet a specific business need. The application currently supports Integration Endpoints of the API types.</p>

<p data-source-node="n44"> </p>

<p data-source-node="n45">NOTE: In the application Integration Endpoints can be found under the Integration Services Folder of the Configuration Explorer.</p>

<div id="i-SectionId-section-heading" class="i-section-heading" data-source-node="n46">
    <span class="i-section-heading-icon" data-source-node="n47"><span class="i-hidden" data-source-node="n48"> </span></span><span class="i-section-heading-text" data-source-node="n49">API Endpoints</span>
</div>

<div id="i-SectionId-section-content" class="i-section-content" data-source-node="n50">
    <p data-source-node="n51">API Integration Endpoints are written in any .NET language and are invoked in the same process as the consuming Manhattan SCALE logic. Except where noted, you must configure the assembly's name, the namespace, the class name, and the entry method of the endpoint from the appropriate Integration Endpoint configuration (e.g. the Exit Point Program config). At runtime, the application loads the assembly from the GAC, creates an instance of the configured class, and uses reflection to invoke the endpoint's entry method.</p>

    <p data-source-node="n52"> </p>

    <p data-source-node="n53">Here is an example of an Exit Point Program API configuration.</p>

    <p data-source-node="n54"> </p>

    <p data-source-node="n55"><img border="0" alt="API Integration Endpoint Example" src="../source/assets/903285c68750639b68804f60bfd90f026f87ddbefd63118b0e9a41ffe59eb4b5.png" loading="eager" data-source-node="n56"></p>

    <p data-source-node="n57"> </p>

    <p data-source-node="n58">API style Integration Endpoints can throw an exception derived from Manh.ILS.General.IntegrationEndpointException of the WMW.General assembly. These exceptions can be used to:</p>

    <ul data-source-node="n59">
        <li data-source-node="n60">Return validation errors via IntegrationEndpointException.Message.</li>

        <li data-source-node="n61">Wrap other caught exceptions via the IntegrationEndpointException.InnerException to prevent an unexpected abort in the business process.</li>
    </ul>

    <p data-source-node="n62">Note that the action taken once the IntegrationEndpointException is caught entirely depends on the business process, so please consult the each specific Integration Endpoint’s documentation for details.</p>
