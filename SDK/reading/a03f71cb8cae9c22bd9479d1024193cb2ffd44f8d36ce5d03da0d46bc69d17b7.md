    <div id="i-body-content" class="i-body-content" data-source-node="n46">
        <p data-source-node="n47">This page reviews how SCALE automates the navigation between metadata screens. These patterns should be followed if you need to customize a screen or create a new metadata screen.</p>

<div id="i-4597ea1a-bac1-4f71-a325-306fe3c5ceb8-section-heading" class="i-section-heading" data-source-node="n48">
    <span class="i-section-heading-icon" data-source-node="n49"><span class="i-hidden" data-source-node="n50"> </span></span><span class="i-section-heading-text" data-source-node="n51">Navigation Trail</span>
</div>

<div id="i-4597ea1a-bac1-4f71-a325-306fe3c5ceb8-section-content" class="i-section-content" data-source-node="n52">
    <p data-source-node="n53">SCALE tracks the last 10 pages that have been visited by the user in a Navigation Trail in the top Navigation bar on each page. The only exceptions to this are as follows:</p>

    <ul data-source-node="n54">
        <li data-source-node="n55">If a user cancels out of a Details or Transaction page, that page is not included in the navigation trail history.</li>

        <li data-source-node="n56">If a user successfully completes a Details or Transaction page, that page is not included in the navigation trail history.</li>

        <li data-source-node="n57">Sign on pages and error pages are not included in the navigation trail history.</li>

        <li data-source-node="n58">Any page that has <strong data-source-node="n59">excludeFromNavTrail=Y</strong> as a query parameter is not included in the navigation trail history.</li>
    </ul>
</div>

<div id="i-aa60bb28-b4a6-4f81-9da4-e85b5b1c65e3-section-heading" class="i-section-heading" data-source-node="n60">
    <span class="i-section-heading-icon" data-source-node="n61"><span class="i-hidden" data-source-node="n62"> </span></span><span class="i-section-heading-text" data-source-node="n63">Cancel</span>
</div>

<div id="i-aa60bb28-b4a6-4f81-9da4-e85b5b1c65e3-section-content" class="i-section-content" data-source-node="n64">
    <p data-source-node="n65">Details and Transaction pages should all have a Cancel button. The cancel action should take the user back to the previous page in their navigation history. To do this, the cancel action on any page should call the SCALE provided function <strong data-source-node="n66">_webUi.detailsScreenBinding.cancel</strong>.</p>       
</div>

<div id="i-798204fd-64fd-4a4b-b8ea-121cb4c154dd-section-heading" class="i-section-heading" data-source-node="n67">
    <span class="i-section-heading-icon" data-source-node="n68"><span class="i-hidden" data-source-node="n69"> </span></span><span class="i-section-heading-text" data-source-node="n70">Success</span>
</div>

<div id="i-798204fd-64fd-4a4b-b8ea-121cb4c154dd-section-content" class="i-section-content" data-source-node="n71">
    <p data-source-node="n72">Upon successful completion of a Details or Transaction page, the user should be taken back to the previous page in their navigation history in most circumstances. Most screens can accomplish this navigation by simply specifing the base SCALE success callback functions for the web service call on the Details or Transaction page, which are <strong data-source-node="n73">_webUi.detailsScreenBinding.successCallbackUpdate</strong> and <strong data-source-node="n74">_webUi.detailsScreenBinding.successCallbackInsert</strong>.</p>

    <p data-source-node="n75">If your screen requires logic beyond what exists in the base SCALE success callback functions, create your own callback function, do your custom logic, and then call <strong data-source-node="n76">_webUi.navigationTrail.navigateBackToPreviousPage</strong>.</p>

    <p data-source-node="n95">There are certain screens that should stay open after success when opened from the main menu, but close when opened as an action against a specific record (i.e. close container). These screens will need their own callback functions as well, but should use the query parameter <strong data-source-node="n96">NavToPrev=Y</strong> when called from an action against a specific record. There is a generic function <strong data-source-node="n97">_webUi.navigationTrail.doesUrlIndicateFlowShouldNavigateToPreviousPage</strong> provided to check this query parameter.</p>
