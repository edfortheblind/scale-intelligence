    <div id="i-body-content" class="i-body-content" data-source-node="n46">
        <p data-source-node="n47">The metadata screen framework is built using <a href="http://getbootstrap.com/" data-source-node="n48">Twitter Bootstrap</a>. In particular the grid system layout is used to define the basic layout of the screen. This section will go into more detail about defining the layout css classes of the screen.</p>

<div id="i-a2a484c4-9892-49c1-a32f-86e5479f8872-section-heading" class="i-section-heading" data-source-node="n49">
    <span class="i-section-heading-icon" data-source-node="n50"><span class="i-hidden" data-source-node="n51"> </span></span><span class="i-section-heading-text" data-source-node="n52">Screen Layout Overview</span>
</div>

<div id="i-a2a484c4-9892-49c1-a32f-86e5479f8872-section-content" class="i-section-content" data-source-node="n53">
    <p data-source-node="n54">Screen layout is defined in metadata via css class definitions. This section will provide an overview of how this layout is configured using the insight screen layout as an example.</p>

    <p data-source-node="n55">An insight screen consists of a screen container with three panes (Search, List, and Detail). These elements of the screen are rendered when the metadata elements define Bootstrap css classes on the div elements of the html. In particular, the metadata insight screens are using the container, row and col classes.</p>

    <p data-source-node="n56">The container is defined as a 12 column grid system. Css was used to achieve this 3 column layout css by defining each pane as 4 columns (col-md-4). This makes each pane the same size. The insight screen allows the search pane to be collapsed when in this view the list pane is modified to include additional columns, giving them different sizes. In this scenario the list pane column has 8 columns of the grid system (col-md-8), and the detail pane has 4 columns of the grid system (col-md-4). As the page is resized the media queries within the Bootstrap infrastructure alter the classes accordingly to size to the device viewport.<br data-source-node="n57"></p>

    <p data-source-node="n58">The contents of each pane can have their own css defined in metadata for a screen part, screen group, and screen control by specifying the appropriate css class.</p>
</div>

<div id="i-eac35354-0fb1-4045-9620-3b62648bbb42-section-heading" class="i-section-heading" data-source-node="n59">
    <span class="i-section-heading-icon" data-source-node="n60"><span class="i-hidden" data-source-node="n61"> </span></span><span class="i-section-heading-text" data-source-node="n62">Defining Metadata Layout Classes</span>
</div>

<div id="i-eac35354-0fb1-4045-9620-3b62648bbb42-section-content" class="i-section-content" data-source-node="n63">
    <p data-source-node="n64">Each table has its own columns used to define the layout/css of the elements on the screen. Refer to the columns in the table below that are associated with defining the layout of each part of the metadata.</p>

    <p data-source-node="n65"><br data-source-node="n66"></p>

    <table data-source-node="n67">
        <tbody data-source-node="n68">
            <tr data-source-node="n69">
                <td data-source-node="n70"><strong data-source-node="n71">Table Name</strong></td>

                <td data-source-node="n72"><strong data-source-node="n73">Column</strong></td>

                <td data-source-node="n74"><strong data-source-node="n75">Description</strong></td>
            </tr>

            <tr data-source-node="n76">
                <td data-source-node="n77">SCREEN_PART</td>

                <td data-source-node="n78">DIV_CSS_CLASS</td>

                <td data-source-node="n79">Defines any css classes that should be applied to a screen part. The css is placed on the screen part div wrapper in the html. The Bootstrap column layout for the screen parts should be defined here in addition to any other css classes that should be applied over the entire screen part.</td>
            </tr>

            <tr data-source-node="n80">
                <td data-source-node="n81">SCREEN_GROUP</td>

                <td data-source-node="n82">ROW_CSS_CLASS</td>

                <td data-source-node="n83">Used when a screen group is wrapped in a Bootstrap grid row. This column defines any css classes that should be applied to the groups row div in the html. The Bootstrap row class should be defined here in addition to any other css classes that should be applied over the entire screen group.</td>
            </tr>

            <tr data-source-node="n84">
                <td data-source-node="n85">SCREEN_GROUP</td>

                <td data-source-node="n86">DIV_CSS_CLASS</td>

                <td data-source-node="n87">Defines any css classes that should be applied to a screen group. The css is placed on the screen group div wrapper in the html.</td>
            </tr>

            <tr data-source-node="n88">
                <td data-source-node="n89">SCREEN_GROUP_COLUMN</td>

                <td data-source-node="n90">COLUMN_CSS_CLASS</td>

                <td data-source-node="n91">Defines any css classes that should be applied to the columns of a screen group that is nested in a Bootstrap grid row. The Bootstrap column layout for the screen group column should be defined here in addition to any other css classes that should be applied over the entire column.</td>
            </tr>

            <tr data-source-node="n92">
                <td data-source-node="n93">SCREEN_CONTROL</td>

                <td data-source-node="n94">DIV_CSS_CLASS</td>

                <td data-source-node="n95">Defines any css classes that should be applied to the wrapper of a screen control. The css is placed on the screen control div wrapper in the html.</td>
            </tr>

            <tr data-source-node="n96">
                <td data-source-node="n97">SCREEN_CONTROL</td>

                <td data-source-node="n98">CONTROL_CSS_CLASS</td>

                <td data-source-node="n99">Defines any css classes that should be applied to a screen control. The css is placed on the screen control itself in the html. For example, specifying an ellipsis for the label control when the text is longer than the control itself.</td>
            </tr>
        </tbody>
    </table>

    <p data-source-node="n100"><br data-source-node="n101"></p>

    <p data-source-node="n102">In addition to the Bootstrap grid layout the metadata framework also has its own set of custom classes found in the manh.css file. These classes define colors, padding, height, etc. for the metadata. More information on customizing the styles can be found in the <a href="7eaab9b354ac6ddefb378d25cfc8c6669abe1a6a10da1eb3cddc7b9f552f750d.html" data-source-node="n103">How to: Override the Default Theme for Metadata Screens</a> topic.</p>
