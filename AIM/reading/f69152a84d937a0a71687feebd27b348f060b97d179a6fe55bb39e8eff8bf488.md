
        
        <h1 data-source-node="n56"><a name="kanchor1648" data-source-node="n57"></a>Receiving Touchpoint</h1>
        <p data-source-node="n58"><i data-source-node="n59">NOTE: The term "receipt header" / "receipt" and "receipt detail" / "receipt line" are used interchangeably in this topic.</i>
        </p>
        <p data-source-node="n60"> </p>
        <p data-source-node="n61"> </p>
        <p data-source-node="n62">The system supports the interfacing of receipt, receipt line, and container 
 data between your ERP and the application. SCALE can also return receipt 
 information back to the ERP after the receipt has been processed and its 
 product has been checked into the warehouse. Receipts can be uploaded 
 based on its receipt, receipt line, or container status. Also supported 
 are changes/deletions of parts of receipts, such as lone lines or containers. 
 In addition, you can also download purchase order and purchase order line data 
 into SCALE.</p>
        <p data-source-node="n63"> </p>
        <p data-source-node="n64">SCALE can place newly-interfaced receipt data in several places, which 
 are determined by settings on the Interface System Values Window. You 
 can have each receipt enter or leave the system with a certain status. 
 The receipt interface (download and upload) processes the following entities:</p>
        <ul type="disc" class="ul_1" data-source-node="n65">
            <li data-source-node="n66"><i data-source-node="n67">Receipts</i>: 
 These can be interfaced with or without associated details, containers, 
 or comments. <br data-source-node="n68"> </li>
            <li data-source-node="n69"><i data-source-node="n70">Receipt Lines</i>: 
 These can be interfaced either as part of a receipt header download, or 
 as a lone detail (which must be associated with an existing header). Details 
 are not required in a download. Note that if you interface details, they 
 must be associated with a header. A receipt detail cannot be deleted once 
 a container has been checked in.<br data-source-node="n71"> </li>
            <li data-source-node="n72"><i data-source-node="n73">Receipt Containers</i>: 
 These can be interfaced as either separate or nested containers. If you 
 interface containers, they must be associated with a detail (or multiple 
 details). The container types  can be authorized by company and warehouse and the authorization applies to the downloaded parent receipt containers. Generally, you will want to download containers if you are only 
 using SCALE for manifesting or for web purposes, and you are  NOT  creating containers via system processing. Containers are not required 
 in a download. <br data-source-node="n74"><br data-source-node="n75">To determine which containers can be uploaded, the system completes 
 the following process to determine eligibility:<br data-source-node="n76"><br data-source-node="n77">A) It verifies that the container has not previously been interfaced.<br data-source-node="n78"><br data-source-node="n79">B) It checks the status of the container (which itself is defined 
 on the "Receiving Upload Level" value, from the Interface System 
 Values Window). This status must be equal to or greater than the value 
 defined on the "Upload receipt containers at this status or higher" 
 value. For example, if the interface is configured to upload "Containers" 
 at a "Closed" status, then any          closed 
 container in the system will be eligible for uploading.<br data-source-node="n80"> </li>
            <li data-source-node="n81"><i data-source-node="n82">Purchase Order 
 Headers</i>: These can be interfaced with or without associated details.<br data-source-node="n83"> </li>
            <li data-source-node="n84"><i data-source-node="n85">Purchase Order 
 Details</i>: These can be interfaced either as part of a purchase order 
 header download, or as a lone detail (which must be associated with an 
 existing header). Details are not required in a download. Note that if 
 you interface details, they must be associated with a header. <br data-source-node="n86"><br data-source-node="n87"></li>
        </ul>

        <h4 data-source-node="n101">Receipt Header Rules...</h4>
        <ul type="disc" class="ul_1" data-source-node="n102">
            <li data-source-node="n103">The interface can retrieve address and item information 
 from the system, if it is not defined on the downloaded record. For example, 
 if either the Source ID or the Ship From values on the receipt header 
 are supplied, the interface will load the appropriate address information 
 defined in the system. If items are defined, the interface will load the 
 appropriate item information on the receipt detail. However, the interface 
 will never override interfaced values with values retrieved from the system.</li>
        </ul>
        <p data-source-node="n104"> </p>
        <p data-source-node="n105"> </p>
        <h4 data-source-node="n106">Receipt Container Rules...</h4>
        <ul type="disc" class="ul_1" data-source-node="n107">
            <li data-source-node="n108">Once a container on a receipt header has reached 
 this processing point, you cannot change/delete it. <br data-source-node="n109"> </li>
            <li data-source-node="n110">Since a container may include multiple items, 
 a container record should not display values in either the Item Field 
 or the Item Quantity Field.<br data-source-node="n111"> </li>
            <li data-source-node="n112">Quantities on receipt containers are always assumed 
 to be in the base unit of measure for the item.<br data-source-node="n113"> </li>
            <li data-source-node="n114">Nested Containers: 
 A nested container is one that has been physically placed into a larger, 
 parent container. The parent container is the box that other containers 
 are nested into. The nested container needs to be linked 
 to its parent container. To link these two records, the nested container's 
 Interface Parent Link ID Field should contain the parent container's interface 
 record ID. For example, if you interface a pallet, which includes five 
 cases, the pallet is the parent container. A container that is placed 
 into a larger one is the child container. In the example above, each case 
 is considered a child container. <br data-source-node="n115"><br data-source-node="n116">- When downloading a child container for a receipt, the child container 
 has to be in the same delimited file as it parent container. SCALE does 
 not support the downloading of a lone child container.<br data-source-node="n117"><br data-source-node="n118">- If you are processing in delimited or fixed length mode, a 
 parent container must be entered in the text file before its children.<br data-source-node="n119"><br data-source-node="n120">- If you are processing in direct 
 mode, nested container order is not relevant.<br data-source-node="n121"> </li>
            <li data-source-node="n122">Lone Containers: 
 The application allows you can interface a lone container, which is in 
 a different interface file than its receipt header and receipt detail 
 (the receipt header and detail were interfaced previously). The lone container 
 needs to be linked to its receipt header already in the system. To link 
 these two records, the lone container's Receipt ID Field should contain 
 the receipt header's receipt ID.<br data-source-node="n123"><br data-source-node="n124">- If you are processing in delimited 
 or fixed length mode, a parent container must be entered in the 
 text file before its child containers. If you are processing in direct 
 mode, container order is not relevant.<br data-source-node="n125"><br data-source-node="n126">- The lone container's Temporary ERP Line Number Field should contain 
 the detail's ERP Line Number.</li>
        </ul>

        <h4 data-source-node="n129">Purchase Order Download Notes...</h4>
        <ul type="disc" class="ul_1" data-source-node="n130">
            <li data-source-node="n131">You will not be able to link a receipt header/detail 
 to a purchase order in the same interface record.  You 
 will, however, be able to download a receipt header/detail that is linked 
 to a purchase order in the same interface file; they will just be two 
 separate records. Note that in the example below, the top two lines represent 
 one record.  The 
 last two lines are a separate record.  <br data-source-node="n132"><br data-source-node="n133">For example, suppose you have a delimited download file with the data 
 maps configured as the following:<br data-source-node="n134"><br data-source-node="n135">- <i data-source-node="n136">PO Header</i>: Map 
 Name | Interface Record ID | PO ID <br data-source-node="n137"><br data-source-node="n138">- <i data-source-node="n139">PO Detail</i>: Map 
 Name | Interface Record ID | Interface Link ID | PO Line Number | Item 
 | Total Quantity<br data-source-node="n140"><br data-source-node="n141">- <i data-source-node="n142">Receipt Header</i>: Map 
 Name | Interface Record ID | Receipt ID | Receipt ID Type <br data-source-node="n143"><br data-source-node="n144">- <i data-source-node="n145">Receipt Detail</i>:  Map Name | Interface 
 Record ID | Interface Link ID | ERP Order Number | Item | Total Quantity 
 | PO ID | PO Line Number <br data-source-node="n146"><br data-source-node="n147">Your data records, then, would look something similar to this:<br data-source-node="n148">- POHEADERMAP | 100 | JACPO-1 <br data-source-node="n149">- PODETAILMAP | 101 | 100 | 1 | NOR0001 | 1000<br data-source-node="n150">- RECHEADERMAP | 200 | JACREC-1 | PO<br data-source-node="n151">- RECDETAILMAP | 201 | 200 | 1 | NOR0001 | 250 | JACPO-1 | 1</li>
        </ul>

        <h4 data-source-node="n154">Locating Rule Assignment Note..</h4>
        <ul type="disc" class="ul_1" data-source-node="n155">
            <li data-source-node="n156">If you download a receipt with containers, the system will assign the same locating rule to both the detail and the containers IF the appropriate locating rule assignment criteria has criteria rules defined at the container level.</li>
        </ul>

        <h4 data-source-node="n159">General Guidelines...</h4>
        <p data-source-node="n160"> </p>
        <ul type="disc" class="ul_1" data-source-node="n161">
            <li data-source-node="n162">When updating an existing record, if a value is not interfaced for a field, the system treats it as “no change” and retains the existing value.<br data-source-node="n163"><br data-source-node="n164"></li>
        </ul>
        <p data-source-node="n165"> </p>
        <h4 data-source-node="n166">Rejection Causes / Validations / Notes...</h4>
        <ul type="disc" class="ul_1" data-source-node="n167">
            <li data-source-node="n168">The interface will validate (against SCALE configurations) 
 certain values that are downloaded. Use the Table Values Spreadsheet to 
 look up specific values to determine if they are validated.<br data-source-node="n169"> </li>
            <li data-source-node="n170">When downloading, the interface will reject a 
 receipt ID if it already exists in the system. However, you can configure 
 the system to allow the same receipt ID to exist multiple times. Use the 
 Interface Receipt Allow Duplicate Field (located in the Interface System 
 Values Window) to indicate how the application will handle duplicate receipt 
 ID's:<br data-source-node="n171"> </li>
            <li data-source-node="n172">The SCALE interface process does not support using 
 a comma as a "seperator" for numeric values. These values will 
 need to be interfaced into the system using decimals as separators (4.95, not          4,95). 
 The system can, however, display these values with a comma separator on 
 SCALE windows, but in the database they must be in a decimal format.<br data-source-node="n173"><br data-source-node="n174"></li>
            <li data-source-node="n175">Note that you cannot perform multiple actions on a single receipt in a single interface download file. 
For example, you cannot save/create a receipt and also delete it in a single XML file (they will need to be two XML files). One for save/create the receipt, and the second one for deleting the receipt.<br data-source-node="n176"><br data-source-node="n177"></li>
            <li data-source-node="n178">
                <p data-source-node="n179">In order to maintain the best performance when downloading receipts with many detail lines, your host ERP system should send the receipt header along with the details in the same file. This will create a single XML file during the interface.</p>
            </li>
        </ul>
        <ul data-source-node="n180">
            <li data-source-node="n181">
                <p data-source-node="n182">The system allows downloading new receipt line with 0 quantity in XML mode. However, the system does not support creating zero quantity entry using user interface. Additionally, updating a line with zero quantity through the receipt interface download is also not allowed.</p>
            </li>
        </ul>
