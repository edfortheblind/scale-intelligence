Receiving Preference Configuration

Overview

A receiving preference record enables you to control how an individual user or a group of users handle receipts. The *Default record should suit most employees, while specific preference records should be created for those with unique processing requirements.

 

General Information

 

Preference name - Provide a record name in the Preference Name Field, and provide a description.

 

Default receiving dock - The Default Receiving Dock Field to identify where the employee typically receives product. When this product is putaway using Warehouse Mobile, the value will appear in the From Loc Field.

 

SRC Identifier - The SRC screen flow for receiving.

For warehouse mobile - The following SRC screen flow can be set for the following

 

  • Receiving 30 - Receiving preference initiation method is Header-Item, then this will be set as SRC identifier

  • Receiving via License Plate (50) - Receiving preference for initiation method is License Plate.

  • Null - if the receiving preference is other than Header item or license-initiated method

Note:

  • When system is upgraded, then these existing receiving preferences will be retained in the warehouse mobile menu.

  • When receiving preference is saved the warehouse mobile menu will be automatically created for that preference.

Default Inventory Status

  • Select the Default Inventory Status Field to define the status all product will be assigned during check in. Generally, you should select the value Available. If you are creating this record for someone processing returns, you may want to define a hold or damaged status here.

Initiation Method Workflow

  • Use the Initiation Method (Workflow) Field to indicate the initiation workflow that you want the user to use during the receiving process. Included in each workflow are the separate activities that will occur during the pre-execution stage of receiving. Examples of these activities are the "initiation" field that the system will prompt for at the beginning of RF receiving (such as receipt ID, item, etc), whether QC inspection is active, or whether GS1 processing is to be used.

Work team

  • Select the Work Team Field to associate this record with a work team. Members on a work team share the following characteristics: same work zones, equipment types and work profiles.

 

Work Type

  • Select the Work Type Field to associate this record with a work type. Generally, you should select the value Receiving. The system generates labor management records based on work type. If you want to review history records for receiving, you will need to define a work type here.

 

Execution Method

Use the Execution Method Field to indicate how you want the system to process the items you are receiving in to the warehouse:

 

  • Check In: In this method, the system will check in only the container(s) that you entered. The system will perform this action using a batch process.

  • Check In and Locate: In this method, the system will check in and locate the container(s) that you enter, using the appropriate locating rule. The system will perform this action using a batch process. With this method, the system will also create work for the putaway actions (if the Create Putaway Work for this window is checked) generated from the locating process.

  • Check In and Locate (Immediate): In this method, the system will check in and locate the container(s) that you enter, using the appropriate locating rule. The system will perform this action immediately after the user presses OK, not using a batch process. With this method, the system will also create work for the putaway actions (if the Create Putaway Work for this window is checked) generated from the locating process. Also, to create putaway groups by RF, you must choose this execution method.

  • Quick Receive-User: In this method, the system will check in and locate the container(s) that you enter, and provide a separate screens for each entity checked in that allows the user to indicate where they want the container to be putaway. The system does not create putaway work using this method.

  • Quick Receive-System: In this method, the system will check in the container(s) that you enter, and attempt to locate each according to the appropriate locating rule. The system will display a screen for each container displaying either the location it has chosen to locate to, or asking the user to provide a location if none could be found. The system does not create putaway work using this method.

 

Bypass Location Capacity validation

 

The Bypass Location Capacity Validation Checkbox to indicate that the system will suppress the following validations (any other validations will remain to be enforced): dimensions (length, width, height, weight), volume, and item location capacity.

This setting has the following behavior depending on which quick receiving execution method is used:

  • Quick Receive-User: The validations mentioned above will always be bypassed.

  • Quick Receive-System: The validations mentioned above will be bypassed only if the user is overriding the system-selected location.

Override system selected location

 

Select the Override System Selected Location toggle button to indicate if the user should be able to enter an alternate putaway location (different than the system-selected location) during license plate check in (when using the Quick Receive-System execution method). Note that you cannot use this setting when using the Quick Receive-User execution method.

 

Advanced

 

Nest during check in

  • Select the Nest During Check In Checkbox to indicate that you want to nest container(s) on a receipt into one container. At the end of the check in process, the system will display a screen where you will enter a container ID and the container type. The system then will nest the container(s) that you checked in during that “session” into the new container.

Process immediate needs

  • Select the Process Immediate Needs Checkbox to indicate that you want the system to check to see if the item(s) that you are currently checking in has an existing immediate needs request associated with it. If this checkbox is checked, the system will process the immediate need for this item, if one exists.

Processing

 

Allow over receiving

  • Select the Allow Over Receiving toggle button if this employee can receive more product than is identified in the Original Total Quantity Field on the receipt line. If the employee does over receive, the system will not display any warning message or require any overrides on an Warehouse Mobile.

Create Putaway work

  • The Create Putaway Work toggle button if you want the system to generate work instructions for the located containers. If you select this checkbox, the system will call work creation and generate putaway instructions as soon as the container is located. The system releases the work automatically. If you don't select this checkbox, the system will not create work for what's located. Instead, it will automatically locate the container and put its quantity as On Hand at the destination location(s). Someone will need to ensure that the product is physically delivered to that location(s).

Execute group putaway

  • Select the Execute Group Putaway toggle button to indicate that you want users (assigned to this preference) to be eligible to process group putaways when locating product. When these users locate received items, each item will be assigned to one "putaway group," according to the group's settings (as defined on the Putaway configuration).

Cross Dock immediate needs

  • Select the Cross Dock Immediate Needs Checkbox to indicate that the system will attempt to locate product to the shipping dock location when fulfilling an immediate needs request. However, if this is not selected, then the system will attempt to locate only to put-to-store or immediate needs locations.

License Plate assignment method

Select the License Plate Assignment Method Buttons to identify if the user will assign or verify license plate IDs.

  • Manual - If you select manual, the user will assign the license plate ID as long as you are not checking in product to be grouped together for locating. In other words, the user will assign the license plate ID to manually created containers used to nest checked in product. The user will also assign the license plate ID during check in if the Group During Check In Checkbox is not selected for this item. This checkbox is on the Storage Template Window. If it's selected, the checked in product will be located to one location, regardless of how much there is. In this case, the system will require the user to verify that he/she accepts the license plate ID that the system assigned.

  • System - If you select system, the user never assigns a license plate ID; the system always assigns it. This applies to receipt containers generated during check in and manually created containers used to nest checked in product.

Miscellaneous Options

 

Container Locating Method -Use the Container Locating Method Field to identify how product will be located in the warehouse.

  • Parent - If you select the value Parent, the system will locate the largest container value. For example, if Container B is a pallet and holds 10 nested cases, the system will locate Container B. The 10 nested containers are moved with Container B; they cannot be located to separate locations. Note: Locating by parent will only locate to multi-item locations, regardless of whether the child containers under that parent have multiple items or not.

  • Child - if you select the value Child, the system will locate the lowest container level. Using the example above, the system would locate the 10 cases; it would not attempt to locate the entire pallet to a location. The system would select the locations based on the UM dimensions defined for a case. Note that when you select to locate the Child level, the system does not consider individual units to be containers. In other words, it would not try to break open a container and locate its contents.

Disposition Code Required

  • Select the Disposition Code Required Checkbox to indicate that the user needs to scan in a disposition code that the system will associate with each item checked in. A disposition code indicates if an item is in good condition, is damaged, etc. These are helpful when processing returns.

Reason Code Required

  • Select the Reason Code Required Checkbox to have the system force the user to enter a reason code when checking in items. Note that this setting is only available when the Disposition Code Required checkbox is selected. Reason codes can be configured in the Quality History Reason Codes configuration (set the process to Receiving).

QC Inspection active

  • Select the QC Inspection Active Checkbox to that you want the system to check every item you check in to see if it is eligible for the quality control process.

Verify Item Dimensions

  • Select the Verify Item Dimensions Checkbox to determine if the system will check item dimensions when checking in items. If any item does not have dimension(s), the user can choose whether the check in should continue or not:- If this checkbox is selected, the system will display a message warning the user that all the dimensions are not defined. The user then will be able to continue or cancel the check in, knowing that all the dimensions are not defined. Choose "Yes" to continue with the check in, or "No" to cancel.- If the checkbox is not selected, the system will not check to see if an item has dimensions when performing a check in.

Verify Item Unit of Measure

 

Select the Verify Item Unit of Measure Checkbox to determine if the user is required to confirm that a receipt has the same quantity per container as the system expects:

  • If this checkbox is selected, the system will display a verification window each time this user checks in a container. This verification window displays the unit of measure amounts that are defined on the storage template record for the item or item class (or the *Default record). The user can either attest that these values are correct or change them. Any changes made apply only containers on this receipt.

  • If this checkbox is not selected, the system will not ask the user to verify the container's quantity.

Note that this setting also applies when creating pre-check in receipt containers.
