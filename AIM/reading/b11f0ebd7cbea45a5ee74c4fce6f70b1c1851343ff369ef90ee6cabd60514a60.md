
        
        <h1 data-source-node="n56"><a name="kanchor690" data-source-node="n57"></a>Establishing Packing Preferences</h1>
        <p data-source-node="n58">A packing preference record allows you to manage how a user or group 
 of users will pack shipments. These actions are primarily done in the Packing Screen or the Close Container Screen (desktop or RF). You can create specific preference 
 records for employees with unique packing processing needs.</p>

        <h4 data-source-node="n134">Procedures...</h4>
        <p data-source-node="n135">Access the Packing Preferences Window. Create a new record and provide 
 a description. </p>
        <p data-source-node="n136"> </p>
        <h5 data-source-node="n137">Using the Packing Tab</h5>
        <ol data-source-node="n138">
            <li value="1" data-source-node="n139">Use the Initiation 
 Field to select the initiation value. When a user associated with 
 this record accesses the Packing Screen, the system will require him/her 
 to identify the shipment using this value. Commonly used initiation values 
 include the shipment number, ERP order number, and the invoice number.<br data-source-node="n140"><br data-source-node="n141"></li>
            <li value="2" data-source-node="n142">Use the Packing Work 
 Type Field to indicate the work type that you want to associate with the packing action, since the system creates no work instructions for packing (and therefore no work type would be assigned). The system uses this work type for labor tracking.. <br data-source-node="n143"><br data-source-node="n144"></li>
            <li value="3" data-source-node="n145">Use the Workbench - Verify Item Work Type Field to indicate the work type that you want to associate with the verify item functionality in the Shipping Container Workbench, since the system creates no work instructions for this action (and therefore no work type would be assigned). The system uses this work type for labor tracking.<br data-source-node="n146"><br data-source-node="n147"></li>
            <li value="4" data-source-node="n148">Use the VAS Work Type Field to indicate the work type associated with confirming a VAS activity in the VAS Container: Insight Screen. This value is used by the system when logging labor requests, and is needed since there are no work instructions created for confirming VAS activities.<br data-source-node="n149"><br data-source-node="n150"></li>
            <li value="5" data-source-node="n151">Use the Allow Over 
 Packing Checkbox if you want to allow users to over pack containers 
 on the Packing Screen. If you select this check box, a user could pack 
 an item quantity that is greater than the quantity available on a shipment 
 line.
<br data-source-node="n152"><br data-source-node="n153"></li>
            <li value="6" data-source-node="n154">Use the Status 
 Range Field to define when a shipment line is eligible for packing. 
 The system will only pack a shipment line record within this range. 
 This range provides you the flexibility to pack product that is not necessarily 
 in a status ready for packing.                     NOTE: 
 When product is packed, it moves to the first status after the In Packing 
 status. For example, if the range is from In Picking to In Packing, product 
 packed while it was still in the In Picking status moves automatically 
 to the first status after In Packing. This insures that it moves forward 
 through the system and skips the statuses it either bypasses or does not 
 require.           <br data-source-node="n155"><br data-source-node="n156"></li>
            <li value="7" data-source-node="n157">Use the Validate Item Checkbox 
 to indicate if employees will identify the item and quantity that they 
 are packing. To minimize processing time, many organizations do not require 
 item validation. However, you may want to require validation if your current 
 accuracy measurements are not acceptable, you handle expensive product, 
 or all items include a scannable barcode. The value you define here dramatically 
 impacts the appearance of the Packing Screen.<p data-source-node="n158"> </p></li>
            <ul type="disc" class="ul_1" data-source-node="n159">
                <li data-source-node="n160">
                    <p data-source-node="n161">If you select this checkbox, 
 the system will display input fields on the screen. These fields are displayed 
 above the item information grid. The user will need to enter the item 
 and item quantity in these fields. If the quantity is not entered, the 
 system will pack one unit. The user can also enter the weight being packed. 
 In this case, the item information grid is for display purposes only. 
 You will not use it to select product from. </p>
                    <p data-source-node="n162"> </p>
                </li>
                <li data-source-node="n163">
                    <p data-source-node="n164">If you do not select this 
 checkbox, you will select the item that you 
 want to pack from an item grid. You will select items by highlighting 
 them in the grid. You will identify the quantity 
 that you want to pack by using the +/- buttons. 
 The system will calculate how much the packed quantity weighs.
 </p>
                </li>
            </ul>
            <p data-source-node="n165"> </p>
            <li value="8" data-source-node="n166">Use the Verify Container ID Checkbox 
 to indicate if the system will display the last used container ID when 
 the user packs subsequent items.<p data-source-node="n167"> </p></li>
            <ul type="disc" class="ul_1" data-source-node="n168">
                <li data-source-node="n169">
                    <p data-source-node="n170">If the employee will pack 
 either full cases or multiple cases simultaneously, consider selecting 
 this checkbox. After he/she selects the Pack Button, the system will not 
 display this Container ID. The Container ID Field will display the value 
 New. However, the employee can select this container from the field.</p>
                    <p data-source-node="n171"> </p>
                </li>
                <li data-source-node="n172">If the employee 
 packs mainly loose pick shipments, consider NOT selecting this 
 value. After he/she selects the Pack Button, the system will display the 
 last used container ID in the Container ID Field. It will also default 
 this container's type in the Container Type Field. The user can still 
 use a new container ID by selecting the New option.</li>
            </ul>
            <p data-source-node="n173"> </p>
            <li value="9" data-source-node="n174">Use the Require Entry Of Quantity Checkbox to determine if the system will default the packed item quantity value in the Packed Quantity Field on the Packing Screen grid. If this checkbox is not selected, then the Packed Quantity value will be zero, and the user will have to manually indicate how much they are packing into the container.<br data-source-node="n175"><br data-source-node="n176"></li>
            <li value="10" data-source-node="n177">Use the Container 
 Assignment Method Buttons to define who will generate container 
 IDs; the system or the user.</li>
            <ul type="disc" class="ul_1" data-source-node="n178">
                <p data-source-node="n179"> </p>
                <li data-source-node="n180">
                    <p data-source-node="n181">If you use UCC-128 barcodes, 
 or other unique barcodes to identify a container, select System. The system 
 will create all container ID barcodes.</p>
                    <p data-source-node="n182"> </p>
                </li>
                <li data-source-node="n183">If you do 
 not use UCC-128 barcodes, or do not have a packing printer, select 
 Manual. All container IDs will be assigned by the user.</li>
            </ul>
            <p data-source-node="n184"> </p>
            <li value="11" data-source-node="n185">Use the Shipping 
 Container Workbench Mode Buttons to define which window the system 
 will display when choosing to edit item quantities (modify) or confirm 
 the contents of a container (verify) in the Shipping Container Workbench.<br data-source-node="n186"> </li>
            <ul type="disc" class="ul_1" data-source-node="n187">
                <li data-source-node="n188">If you choose 
 Modify, the system will allow you to adjust the lot and quantity 
 fields on the Shipping Container Contents Window. Typically you would 
 do this by manually entering in new values. <br data-source-node="n189"> </li>
                <li data-source-node="n190">If you choose 
 Verify, the system will allow you to confirm what item quantity 
 is actually packed in the Shipping Container Contents Window. Typically 
 you would do this by scanning in each item that is present in the container.<br data-source-node="n191"></li>
            </ul>
        </ol>

        <h5 data-source-node="n193">Using the Quality Control Tab</h5>
        <p data-source-node="n194">It is important to note that these quality control settings only apply to the full-screen QC Workbench, and NOT the RF Shipping Container QC screen.</p>
        <ol data-source-node="n195">
            <li value="1" data-source-node="n196">The Blind QC Inspection Checkbox is not currently used.<br data-source-node="n197"><br data-source-node="n198"></li>
            <li value="2" data-source-node="n199">Use the Lot Verification Required Checkbox to determine if the user will need to enter a lot value for lot-controlled items when performing inspection on a container, and how the lot field will appear on the QC Workbench's inspection grid. <br data-source-node="n200"><br data-source-node="n201">- If this checkbox is selected, the lot field will appear in the “scan item fields”, there will be a lot column in the inspection grid, and the inspection grid will display a separate grid row for each item/lot combination. <br data-source-node="n202"><br data-source-node="n203">- If this checkbox is not selected, the lot field will not appear in the “scan item fields”, there will not be a lot column in the inspection grid, and the inspection grid will summarize all of an item's lot instances into a single grid row .<br data-source-node="n204"><br data-source-node="n205">NOTE: It is recommended that you not turn off lot verification on a user's preferences while the user is currently performing QC inspection on containers. If this is done, the system might not  have any information about which lot(s) failed QC, so therefore the grid would not be able to accurately display to the user the correct failed quantity against the right item/lot combination.<br data-source-node="n206"><br data-source-node="n207"></li>
            <li value="3" data-source-node="n208">Use the Prompt When Unknown Item Entered Checkbox to determine if the system will display a prompt message when the user enters/scans an item in the QC Workbench that does not currently reside in the container being inspected. </li>
        </ol>

        <h5 data-source-node="n210">Using the Close Container Tab</h5>
        <ol data-source-node="n211">
            <li value="1" data-source-node="n212">Use the Auto Manifest at Close 
 Checkbox if the system will manifest containers as soon as they 
 are closed.<br data-source-node="n213"><br data-source-node="n214"></li>
            <li value="2" data-source-node="n215">Use 
 the Allow Container Creation During Close Checkbox if the employee 
 can create containers without identifying their contents. This allows 
 him/her to create containers "on the fly" on the Close Container Screen, 
 outside of the packing process. The employee identifies the shipment associated 
 with the container, but never links it to particular shipment lines. 
 Because the shipment line is not identified, the system cannot verify 
 accuracy of contents, or track the contents through the system. Note that this setting only applied to the Close Container screen that is accessed from the remote desktop system menu.<br data-source-node="n216"><br data-source-node="n217"></li>
            <li value="3" data-source-node="n218">Use the Allow VAS Override At Close Container and Load Confirm Checkbox to indicate the system's behavior when a container has pending VAS at the time of close container and shipping load confirmation. <br data-source-node="n219"><br data-source-node="n220">- At close container (when this setting IS NOT selected) if a container has pending VAS, the system will display a message indicating that the container cannot be closed because it has pending VAS activity(s).<br data-source-node="n221"><br data-source-node="n222">- At close container (when this setting IS selected) if a container has pending VAS, the system will display a message indicating that the container has a pending VAS activity, and you can choose whether to allow the container to close or hold it up because of the pending VAS. If you choose to override, the system will write transaction history recording this action.<br data-source-node="n223"><br data-source-node="n224">- At load confirmation (when this setting IS NOT selected) if a container has pending VAS, the system will not confirm the load, and the load's truck icon will turn red indicating to you this fact. The system will write transaction history recording this failure. You will then need to address the pending VAS and reconfirm the load.<br data-source-node="n225"><br data-source-node="n226">- At load confirmation (when this setting IS selected) if a container has pending VAS, the system will ignore the pending VAS and will not stop the load from confirming. Note that the system will still label the container as "VAS Pending" after the load has been confirmed, and will not write any transaction history.<br data-source-node="n227"><br data-source-node="n228"></li>
            <li value="4" data-source-node="n229">Use the Assign Shipment To Load Checkbox to indicate whether or not you want the system to automatically attempt to assign a shipment to a load when a user closes a container on the shipment. <br data-source-node="n230"><br data-source-node="n231">If this checkbox is selected, the system will automatically check to see if the shipment has been already assigned to a shipping load.  If it has not been, the system will either find the current open shipping load (for the appropriate carrier and scheduled ship date) and assign the shipment to it; or, the system will create a new shipping load.

<br data-source-node="n232"><br data-source-node="n233">If this checkbox is not selected, the system will not attempt to assign a shipment to a shipping load in this situation.<br data-source-node="n234"><br data-source-node="n235"></li>
            <li value="5" data-source-node="n236">Use 
 the Use Drop Down Checkbox to indicate that you want the system 
 to, by default, populate the Container ID Field on the Close Container 
 Screen with eligible containers from a specified shipment to close.<br data-source-node="n237"><br data-source-node="n238"></li>
            <li value="6" data-source-node="n239">Use the Initiation Method Buttons to indicate the active field (which contains the cursor) when entering the Close Container Screen:<br data-source-node="n240"><br data-source-node="n241">- Always Shipment ID: The Shipment ID Field will initially be active when the Close Container Screen is opened (and while closing containers). Note that if there are more open containers on the shipment, the Shipment ID Field value will be highlighted.  <br data-source-node="n242"><br data-source-node="n243">- Always Container ID: The Container ID Field will initially be active when the Close Container Screen is opened (and while closing containers). Note that if there are more open containers on the shipment, the Shipment ID Field should contain the Shipment ID, and the Container ID Field should have focus.  <br data-source-node="n244"><br data-source-node="n245">- Container ID Unless No Open Containers:  The Container ID Field will be active when there are multiple open containers on a shipment, and the Shipment ID Field will be active when the last open container has been closed.<br data-source-node="n246"><br data-source-node="n247"></li>
            <li value="7" data-source-node="n248">Use the Auto Print at Close Buttons 
 to determine how documents will be printed. You may want specific documents 
 to print when a container is closed.<br data-source-node="n249"><br data-source-node="n250"></li>
            <ul type="disc" class="ul_1" data-source-node="n251">
                <li data-source-node="n252">
                    <p data-source-node="n253">To print all packing 
 documents, select the Yes Button. The system will print 
 all the packing documents when each container is closed.</p>
                    <p data-source-node="n254"> </p>
                </li>
                <li data-source-node="n255">
                    <p data-source-node="n256">To allow the user to select 
 which documents to print, select the Prompt Button. The system 
 will display the Print Container Documents Screen. The user can select 
 packing documents to print from this window.</p>
                    <p data-source-node="n257"> </p>
                </li>
                <li data-source-node="n258">To 
 print no documents,  select 
 the No Button. The system will not print any documents when a container 
 is closed. Employees can still access the Print Container Documents Screen 
 from the Packing Screen.</li>
            </ul>
        </ol>

        <h5 data-source-node="n260">Using the Assigned Users 
 Tab</h5>
        <ol data-source-node="n261">
            <li value="1" data-source-node="n262">Use the Assigned 
 Users Tab to associate user profile records with this preference 
 record. When you create the *Default record, the system will automatically 
 select all user profile records that are not already associated with a 
 packing preference record. New users are also automatically associated 
 with the *Default record, unless you associate them with a specific packing 
 preference record.</li>
        </ol>
