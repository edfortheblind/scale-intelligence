
        
        <h1 data-source-node="n57"><a name="kanchor659" data-source-node="n58"></a>Inventory Transaction Touchpoint</h1>
        <p data-source-node="n59">Inventory transaction data, such as positive/negative adjustments and 
 transfers, can be uploaded to your ERP via the system interface. This 
 ensures that the ERP keeps its inventory balances aligned with the system's 
 balances.</p>
        <p data-source-node="n60"> </p>
        <p data-source-node="n61"> </p>
        <p class="p_6" data-source-node="n62">To see actual examples of 
 the inventory transaction touchpoint, see the following topics:</p>

        <h4 data-source-node="n73">General Guidelines...</h4>
        <ul type="disc" class="ul_1" data-source-node="n74">
            <li data-source-node="n75">The interface can upload transaction history records 
 that identify inventory changes at a particular location (or locations). 
 Short picks are always included in inventory transaction uploads. All 
 other adjustments can be interfaced if the Include in Interface Upload 
 Checkbox is selected on its Adjustment Type Window.<br data-source-node="n76"> </li>
            <li data-source-node="n77">The upload will include records for all locations 
 that were touched by an adjustment, since the last time that the inventory 
 interface was run. If multiple transactions were committed at one location, 
 the system will generate one record per transaction. If a transfer occurs, 
 one transaction record is generated per location involved. The record 
 cannot have been interfaced previously.</li>
        </ul>
        <p data-source-node="n78"> </p>
        <p data-source-node="n79"> </p>
        <h4 data-source-node="n80">Catch Weight Fields (XML Upload Only)</h4>
        <p data-source-node="n81"> </p>
        <ul type="disc" class="ul_1" data-source-node="n82">
            <li data-source-node="n83"><b data-source-node="n84">CatchWeight</b> and <b data-source-node="n85">CatchWeightUM</b> are available only when the upload output method is <b data-source-node="n86">XML</b>.</li>
        </ul>
        <p data-source-node="n87"> </p>
        <h4 data-source-node="n88">Rejection Causes / Validations / Notes...</h4>
        <ul type="disc" class="ul_1" data-source-node="n89">
            <li data-source-node="n90">The SCALE interface process does not support using 
 a comma as a "seperator" for numeric values. These values will 
 need to be interfaced into the system using decimals as seperators (4.95, not         4,95). 
 The system can, however, display these values with a comma seperator on 
 SCALE windows, but in the database they must be in a decimal format.</li>
        </ul>
        <p data-source-node="n91"> </p>

        <h4 data-source-node="n93">Selection of Transaction History Records for the Upload Interface...</h4>
        <p data-source-node="n94">Depending on what transaction type the transaction history record has, the upload interface handles it differently.  The following sections define how the system determines whether to upload the records based on transaction type.</p>
