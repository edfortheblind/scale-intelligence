
        
        <h1 data-source-node="n56"><a name="kanchor321" data-source-node="n57"></a>Configuring DIF TCP Protocol Properties</h1>
        <p data-source-node="n58">To setup the SCALE Device Integration Framework (DIF), you will need to address some configuration values in the application's database. The third step in this process is to configure the DIF protocol properties. A protocol property record contains the specific TCP data that is used to define the properties of a DIF endpoint. Note that there is no configuration screen to define protocols in the SCALE Configurations Explorer. You will need to configure these values directly in the application database's TCP_PROTOCOL_PROPERTIES table.</p>
        <p data-source-node="n59"> </p>
        <p data-source-node="n60">IMPORTANT: In order for changes to the TCP_PROTOCOL_PROPERTIES table to be reflected, you will need restart the DIF Processing Service. </p>
        <p data-source-node="n61"> </p>

        <h4 data-source-node="n81">Procedures...</h4>
        <ol data-source-node="n82">
            <li value="1" data-source-node="n83">Access your application database using a database editing tool such as SQL Server Management Studio.<br data-source-node="n84"><br data-source-node="n85"></li>
            <li value="2" data-source-node="n86">Access the TCP_PROTOCOL_PROPERTIES database table. Each database row represents the properties of a separate DIF endpoint.<br data-source-node="n87"><br data-source-node="n88"></li>
            <li value="3" data-source-node="n89">Define values for the following database fields:<br data-source-node="n90"><br data-source-node="n91">ACK (alpha 1): Represents whether or not the endpoint requires positive acknowledgments for messages. Supported values are Y (enabled) and N (disabled).<br style="color: #000000" data-source-node="n92"><br style="color: #000000" data-source-node="n93">ACK_DATA (alpha-numeric 50): Represents the value to use for acknowledgments. <br style="color: #000000" data-source-node="n94"><br style="color: #000000" data-source-node="n95">ACK_NAK_TIME_OUT (numeric 9,0): Represents the time (in milliseconds) for DIF to wait for an endpoint to send  a positive/negative acknowledgment for a message.<br style="color: #000000" data-source-node="n96"><br style="color: #000000" data-source-node="n97">CONNECT_MODE (numeric 1,0): Reserved for future use.<br style="color: #000000" data-source-node="n98"><br style="color: #000000" data-source-node="n99">ENCODING (numeric 1,0): Represents the encoding type used. Supported values are 0 ASCII, 1 UTF8, 2 UTF16, UTF7.<br style="color: #000000" data-source-node="n100"><br style="color: #000000" data-source-node="n101">END_OF_MESSAGE (alpha-numeric 25): Represents the end of the TCP message.<br style="color: #000000" data-source-node="n102"><br style="color: #000000" data-source-node="n103">ENDPOINT ID (numeric 9,0): Represents the endpoint tied to this protocol. This is a required field.<br style="color: #000000" data-source-node="n104"><br style="color: #000000" data-source-node="n105">HEARTBEAT_ACK (alpha 1): Represents whether or not to send an acknowledgment for a heartbeat message. Supported values are Y or N.<br style="color: #000000" data-source-node="n106"><br style="color: #000000" data-source-node="n107">HEARTBEAT_ACK_DATA (alpha-numeric 50): Represents the value to use for acknowledgments for heartbeat messages.<br style="color: #000000" data-source-node="n108"><br style="color: #000000" data-source-node="n109">HEARTBEAT_DATA (alpha-numeric 50): Represents the regular expression data to use for heartbeat messages.<br style="color: #000000" data-source-node="n110"><br style="color: #000000" data-source-node="n111">HEARTBEAT_INTERVAL (numeric 9,0): Represents the time interval (in milliseconds) for DIF to wait between sending
heartbeats.<br style="color: #000000" data-source-node="n112"><br style="color: #000000" data-source-node="n113">HEARTBEAT_TYPE (numeric 1,0): Represents the heartbeat type. Supported values are None (0), Constant (1), or Idle (2).<br style="color: #000000" data-source-node="n114"><br style="color: #000000" data-source-node="n115">KEEP_CONNECTION_OPEN (alpha 1): Represents if the connection needs to be kept open. Supported values are Y or N.<br data-source-node="n116"><br data-source-node="n117">KEEPALIVE_INTERVAL (numeric 9,0): Represents the keep alive interval for  connected socket.<br data-source-node="n118"><br data-source-node="n119">KEEPALIVE_TIMER (numeric 9,0): Represents how often the TCP will send keep alives. This value is represented in milliseconds.<br style="color: #000000" data-source-node="n120"><br style="color: #000000" data-source-node="n121">LOCAL_PORT (numeric 9,0): Represents the TCP port that the endpoint will listen or connect on.<br style="color: #000000" data-source-node="n122"><br style="color: #000000" data-source-node="n123">MAX_QUEUE_INCOMING_CONNECTIONS (numeric 9,0): Represents the maximum number of connections that can be queued for the socket listener.<br style="color: #000000" data-source-node="n124"><br style="color: #000000" data-source-node="n125">NAK (alpha 1): Represents whether or not the endpoint requires negative acknowledgments for messages. Supported values are Y or N.<br style="color: #000000" data-source-node="n126"><br style="color: #000000" data-source-node="n127">NAK_DATA (alpha-numeric 50): Represents the data to be used for negative acknowledgments.<br style="color: #000000" data-source-node="n128"><br style="color: #000000" data-source-node="n129">PROTOCOL_TCP_ID (numeric 9,0): Represents the unique protocol identifier. This is a required field.<br style="color: #000000" data-source-node="n130"><br style="color: #000000" data-source-node="n131">REMOTE_ADDRESS (alpha-numeric 25): Represents the IP address of the endpoint machine. Note that this field is required only if the connect mode is 1 (connect).<br style="color: #000000" data-source-node="n132"><br style="color: #000000" data-source-node="n133">REMOTE_PORT (numeric 9,0): Represents the port of the endpoint machine. Note that this field is required only if the connect mode is 1 (connect).<br style="color: #000000" data-source-node="n134"><br style="color: #000000" data-source-node="n135">RESPONSE_RETRY_MAX_COUNT (numeric 9,0): Represents the maximum number of retries if no response from the MHE is received.<br data-source-node="n136"><br data-source-node="n137">RETRY_ATTEMPTS (numeric 9,0): Represents the maximum number of retries at reconnecting the endpoint connection (if no heartbeat is returned, or a bad ACK is returned).<br data-source-node="n138"><br data-source-node="n139">RETRY_INTERVAL (numeric 9,0): Represents the time between retry attempts at reconnecting the endpoint connection (if no heartbeat is returned, or a bad ACK is returned).<br style="color: #000000" data-source-node="n140"><br style="color: #000000" data-source-node="n141">SOCK_RCVBUF (numeric 9,0): Represents the number of bytes the Receive buffer is set to 1024.<br style="color: #000000" data-source-node="n142"><br style="color: #000000" data-source-node="n143">SOCK_SNDBUF (numeric 9,0): Represents the number of bytes the Send buffer is set to 1024.<br style="color: #000000" data-source-node="n144"><br style="color: #000000" data-source-node="n145">START_OF_MESSAGE (alpha-numeric 25): Indicates the start of the TCP message.<br style="color: #000000" data-source-node="n146"><br style="color: #000000" data-source-node="n147">USE_KEEPALIVES (alpha 1): Represents a system setting which facilitates to check if the socket is healthy. This is a setting at .NET socket level. It tells the socket to use internal keep alives.<br style="color: #000000" data-source-node="n148"><br style="color: #000000" data-source-node="n149">USER_DEF1 - USER_DEF6 (alpha-numeric 25): Represents user identified values, similar to other places in the system.<br style="color: #000000" data-source-node="n150"><br style="color: #000000" data-source-node="n151">USER_DEF7 - USER_DEF8 (numeric 14,5): Represents user identified values, similar to other places in the system.<br data-source-node="n152"><br data-source-node="n153"></li>
            <li value="4" data-source-node="n154">When finished entering values, commit the changes to the database and exit your database editing tool.</li>
