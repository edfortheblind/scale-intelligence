
        
        <h1 data-source-node="n56"><a name="kanchor1813" data-source-node="n57"></a>Creating Initiation Workflow Records</h1>
        <p data-source-node="n58">In order to associate a RF receiving initiation workflow to a user's receiving preference, the workflow first needs to be defined in the system. This is done by creating an initiation workflow record. </p>
        <p data-source-node="n59"> </p>
        <h5 data-source-node="n60">Important Notes</h5>
        <ul data-source-node="n61">
            <li data-source-node="n62">The system ships with several default workflows, representing the initiation methods that SCALE supports. These workflows are shipped with all the activities (such as QC, GS1, etc.;) included as part of the workflow. Therefore, you may need to edit these workflows (or copy-and-create your own) to better match your warehouse's processing.<br data-source-node="n63"><br data-source-node="n64"></li>
            <li data-source-node="n65">When you update the receiving workflow by either amending the .xaml file being used, or point the configured workflow to a different .xaml file, the RF check-in process does not refresh the workflow automatically; typically, the old workflow file is cached and therefore will require an IIS reset in order for the changes to take effect. For more information, see the workflow section in the <a href="81d022a2ab379af5c9e945433d1bd3f6e09728fcfd355546989e79b3a0ecfa54.html" data-source-node="n66">SDK</a>.</li>
        </ul>

        <p data-source-node="n99"> </p>
        <h5 data-source-node="n100">Using the Header Fields</h5>
        <p data-source-node="n101"> </p>
        <p data-source-node="n102">Access the Initiation Workflow Window. Create a new record.</p>
        <ol data-source-node="n103">
            <li value="1" data-source-node="n104">Use the Identifier Field to provide a name for your workflow record.<br data-source-node="n105"><br data-source-node="n106"></li>
            <li value="2" data-source-node="n107">Use the Description Field to provide a helpful text summary of what activities are included in the workflow file.<br data-source-node="n108"><br data-source-node="n109"></li>
            <li value="3" data-source-node="n110">Use the Workflow File Field to indicate the actual .xaml file that you want to assign to this workflow record.<br data-source-node="n111"><br data-source-node="n112"></li>
            <li value="4" data-source-node="n113">Press OK. The system will then perform a validation in which it determines whether or not the activities in the workflow are in a logical order for processing. Note that during validation, the system ignores any custom activities that may have been added to the workflow. Also note that even if a workflow has been validated previously, every time you press OK, the system will perform validation on the workflow.<br data-source-node="n114"><br data-source-node="n115">- If the workflow passes validation, the system will save your initiation workflow record.<br data-source-node="n116"><br data-source-node="n117">- If the workflow does not pass validation, the system will display an error and allow you to choose another workflow file.<br data-source-node="n118"><br data-source-node="n119">For more detailed information on workflow (including listings of valid activity orders), see the <a href="81d022a2ab379af5c9e945433d1bd3f6e09728fcfd355546989e79b3a0ecfa54.html" data-source-node="n120">SCALE SDK</a>.</li>
        </ol>
