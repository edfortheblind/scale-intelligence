
        
        <h1 data-source-node="n56"><a name="kanchor1854" data-source-node="n57"></a>Apply At Container Contents Checkbox</h1>
        <p data-source-node="n58">This setting is typically used when packing hazardous items in containers. </p>
        <p data-source-node="n59"> </p>
        <p data-source-node="n60"> </p>
        <p style="font-weight: bold;text-decoration: underline" data-source-node="n61">Containers with one hazardous item...</p>
        <p data-source-node="n62">Containers with one hazardous item do not require special formatting or special handling; the “flat” transmission approach can be used with the applicable accessorials. The Assign Accessorial Window will show the active records for the accessorial details. </p>
        <p data-source-node="n63"> </p>
        <p data-source-node="n64"> </p>
        <p style="font-weight: bold;text-decoration: underline" data-source-node="n65">Containers with 1-3 hazardous items...</p>
        <p data-source-node="n66">In order to support multiple hazardous items packed into a single container, the external rating server accepts data values in a “complex type”, which is a data structure inside the transmission. If this "Apply at Container Contents" setting is active, then accessorial(s) are assigned in the following manner:</p>
        <ol data-source-node="n67">
            <li value="1" data-source-node="n68">The configuration manager would remove the “flat” accessorial details so that the “complex type” accessorial details will be shown during assignment.<br data-source-node="n69"><br data-source-node="n70"></li>
            <li value="2" data-source-node="n71">The user then would assign the accessorial to the container contents, populating the values that apply to the goods in the container. Other accessorials are assigned to the shipment or container and apply to all of the goods inside the container. <br data-source-node="n72"><br data-source-node="n73">- The Accessorial Assignment Window will only display “contents-level” accessorials when opened for container contents, and will show only “non-contents level” (“normal”) accessorials when opened for containers. It is not possible to assign these “contents level” accessorials at more than one level.<br data-source-node="n74"><br data-source-node="n75">- The Accessorial Assignment Window will display both types of accessorials when opened for full case containers.<br data-source-node="n76"><br data-source-node="n77"></li>
            <li value="3" data-source-node="n78">When accessorial values are gathered for transmission to the external rating server, the system sees that the assigned accessorial applies at the “contents” level and formats the accessorial values appropriately.<br data-source-node="n79"><br data-source-node="n80"></li>
            <li value="4" data-source-node="n81">The transmission is sent to the external rating server.<br data-source-node="n82"></li>
        </ol>
        <p data-source-node="n83"><b data-source-node="n84">Important Note:</b> Container contents records <u data-source-node="n85">must</u> <u data-source-node="n86">exist</u> for the system to assign accessorials in the manner described above; i.e., containers cannot be “created on the fly” since they would not have contents records to which an accessorial could be assigned.</p>
