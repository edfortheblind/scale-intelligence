        <p class="p_2" style="font-size: 10pt;font-weight: normal" data-source-node="n58">The following is discussed in this topic:</p>

        <h4 data-source-node="n67"><a name="introduction" data-source-node="n68"></a>Introduction...</h4>
        <p data-source-node="n69">Scan and Weigh is a functionality physically consisting of a conveyor 
 which shipment containers are put on and then arrive at a weighing station. 
  The weigh 
 station is as simple as putting the container on a scale and, through 
 an interface with the system, a record is inserted into the scan_and_weigh_requests 
 database table to either manifest or close the container. Most importantly, the record inserted into the scan_and_weigh_requests 
 table consists of a request type, a request string, and a processed field. 
  The request 
 type can be one of two values; manifest container or close container. 
  The request 
 type is specified by a constant in the request_type field and as the first 
 value in the request string.  The 
 two constants that can define the request type are:</p>
        <ul type="disc" class="ul_1" data-source-node="n70">
            <li data-source-node="n71">MANIFEST</li>
            <li data-source-node="n72">CLOSE_CONTAINER</li>
        </ul>
        <p data-source-node="n73">The request string is used by the processing class as a serialized DS of specific information.  The request string will contain the following information with a Record Separator character as the delimiter between each value:</p>
        <ul type="disc" class="ul_1" data-source-node="n74">
            <li data-source-node="n75">Request Type</li>
            <li data-source-node="n76">Warehouse</li>
            <li data-source-node="n77">Tracking Number</li>
            <li data-source-node="n78">Container ID</li>
            <li data-source-node="n79">Shipment ID</li>
            <li data-source-node="n80">Scanned Date/Time</li>
            <li data-source-node="n81">Scanned by Device</li>
            <li data-source-node="n82">Weight</li>
            <li data-source-node="n83">Weight UM</li>
            <li data-source-node="n84">End delimiter (ä)</li>
        </ul>
        <p data-source-node="n85"> </p>
        <p data-source-node="n86">Below is an example of a request string:</p>
        <p data-source-node="n87"> </p>
        <ul data-source-node="n88">
            <li data-source-node="n89">Format: &lt;request type&gt;&lt;record separator&gt;&lt;container id&gt;&lt;record separator&gt;&lt;container weight&gt;&lt;record separator&gt;&lt;end delimiter&gt;</li>
            <li data-source-node="n90">Example: 'MANIFEST'+char(30)+'00011465870025342824'+char(30)+'0.713'+char(30)+char(228)</li>
        </ul>
        <p data-source-node="n91"> </p>
        <p data-source-node="n92">- As per the example, not all values in the request string are required. 
  A request 
 type is always required.  The 
 tracking number can also be entered instead of a container id, or the 
 user can enter a container id and a tracking number.</p>
        <p data-source-node="n93"> </p>
        <p data-source-node="n94">- No further information is required for manifesting a container.</p>
        <p data-source-node="n95"> </p>
        <p data-source-node="n96">- If closing a container, the processing will look-up the carrier and 
 carrier service information.  If 
 no container id is specified, but a shipment id is specified, a new container 
 will be created during processing.  The 
 processing will also error if no container id and no shipment id is entered.</p>
        <p data-source-node="n97"> </p>
        <p data-source-node="n98">- The processed field can be one of three values; Y for processed, N for 
 not processed, E for error.  When 
 a request record is inserted, it initially has a processed field set to 
 N.  Currently 
 if a request string contains a weight different than what the system calculates 
 (contents weight + container weight) as the weight for the shipment, the 
 request record will error and the processed field will be set to E.  If 
 a container’s weight matches the calculated system weight, the request 
 record will be processed and the processed field will be set to Y.  </p>
        <p data-source-node="n99"> </p>
        <p data-source-node="n100">- Once a request has been written to the scan_and_weigh_requests table, 
 the scan and weigh schedule job (if configured and active to run) will 
 pick up the record and process it.  </p>
        <p data-source-node="n101"> </p>
        <p data-source-node="n102">- Packing preferences play a large role in the processing during scan 
 and weigh.  The 
 packing preference used during scan and weigh is specified on the user 
 profile of the person working at the scan and weigh station, who happens 
 to be inserting the request in the scan_and_weigh_requests table.  </p>
        <p data-source-node="n103">Only two fields on the packing preferences really can have an impact 
 on what takes place during close container.  These 
 two fields are ‘Auto Manifest At Close’ and ‘Allow Container Creation 
 During Close.’</p>
        <p data-source-node="n104"> </p>

        <h4 data-source-node="n227"><a name="scenarios" data-source-node="n228"></a>Scenarios</h4>
        <p data-source-node="n229"> </p>
        <p data-source-node="n230">Below are different scenarios in which one would see the scan and weigh 
 functionality:</p>
        <ul type="disc" class="ul_1" data-source-node="n231">
            <li data-source-node="n232">Close pre-created 
 containers (Pass CLOSE_CONTAINER, container id, container weight): 
 A customer may only want containers that are pre-created, either in packing 
 or in the wave, to be closed when the containers reach the scan and weigh 
 station.  The 
 results of the scan and weigh process will change the status of the containers, 
 as well as the leading status of the shipment to ‘Ship Confirm Pending.’ 
  The weight 
 on the container may also be updated.  This 
 process will only process correctly if the container is in the minimum 
 status of ‘In Packing.’<br data-source-node="n233"> </li>
            <li data-source-node="n234">Create containers 
 ‘on-the-fly’, Close Containers(Pass CLOSE_CONTAINER, shipment id, container 
 weight): The processing during scan and weigh allows for the creation 
 of containers ‘on-the-fly.’  When 
 the shipment contents reaches the scan and weigh station, it would be 
 packed and scan and weighed.  Based 
 on the information being passed into the request string, the container 
 will be created in the system before the system calls the close container 
 processing.  The 
 close container processing will change the status of the containers, as 
 well as the leading status of the shipment to ‘Ship Confirm Pending.’ 
  The weight 
 on the container may also be updated.  This 
 process will only process correctly if the container is in the minimum 
 status of ‘In Packing.’<br data-source-node="n235"> </li>
            <li data-source-node="n236">Create containers 
 ‘on-the-fly’, Close Containers, ‘Auto Manifest At Close’(Pass CLOSE_CONTAINER, 
 shipment id, container weight): A customer may not only want the 
 containers packed when a shipment’s contents reaches the scan and weigh 
 station, but they also may require the containers to be manifested during 
 close.  This 
 situation can still be handled via the scan and weigh processing.  The 
 ‘Auto Manifest At Close’ flag must be turned on in the Packing Preferences 
 configuration.  Containers 
 will be created based on what is passed into the request string.  The 
 scan and weigh processing will results in the update of the container’s 
 status, as well as the leading status of the associated shipment to ‘Ship 
 Confirm Pending’.  The 
 weight on the container may also be updated if it is different than what 
 is specified on the container.<br data-source-node="n237"> </li>
            <li data-source-node="n238">Close pre-created 
 containers, ‘Auto Manifest At Close’ (Pass CLOSE_CONTAINER, container 
 id, container weight): This scenario would allow a customer to 
 have shipments moving along the conveyor to the scan and weigh station 
 in pre-created containers, created either from the wave or in packing. 
  The request 
 string would be close containers, but the packing preferences would have 
 the ‘Auto Manifest At Close’ turned on.  The 
 scan and weigh process will call the close container processing, which 
 will update the container’s status, as well as the leading status of the 
 shipment, to ‘Ship Confirm Pending.’  The 
 weight on the container will also be updated if it is different than what 
 is specified on the container.<br data-source-node="n239"> </li>
            <li data-source-node="n240">Close pre-created 
 containers, ‘Allow Container Creation During Close’ (Pass CLOSE_CONTAINER, 
 container id, container weight): This scenario would be an alternate 
 way to create containers during the scan and weigh process.  On 
 the packing preferences configuration, there is a field called, ‘Allow 
 Container Creation During Close.’  When 
 a shipment’s contents reaches the scan and weigh station, it is put in 
 a container and weighed, triggering the scan and weigh processing.  The 
 scan and weigh processing triggers the close container processing, which 
 handles not only closing the container, but the container creation in 
 the system during close.  The 
 results of all processing, is a new container was created, it’s status 
 was updated, along with the leading status of the shipment, to ‘Ship Confirm 
 Pending.’  The 
 weight on the container will also be updated if it is different than what 
 is specified on the container.<br data-source-node="n241"> </li>
            <li data-source-node="n242">Close Containers, 
 ‘Allow Container Creation During Close’, ‘Auto Manifest At Close’ (Pass 
 CLOSE_CONTAINER, container id, container weight): This scenario 
 is triggered off two flags in the packing preferences; ‘Allow Container 
 Creation during close’ and ‘Auto Manifest At Close.’  If 
 both are turn on, and a close container request is submitted to the database, 
 the scan and weigh processing will trigger the close container processing, 
 which will not only close the container, but also create this new container 
 in the system, as well as manifest this new container at close.  The 
 results of this processing is a new container created and it’s status 
 was updated, along with the leading status of the shipment, to ‘Ship Confirm 
 Pending.’  The 
 weigh on the container will also be updated if it is different than what 
 is specified on the container.<br data-source-node="n243"> </li>
            <li data-source-node="n244">Close pre-created, 
 pre-manifested containers (Pass CLOSE_CONTAINER, container id, container 
 weight): Pre-created and pre-manifested containers can also arrive 
 via conveyor to the scan and weigh station.  This 
 container only requires closing.  Once 
 the container is weighed, the record to the scan_and_weigh_requests table 
 is inserted.  Scan 
 and weigh processing continues by calling the normal close container processing, 
 provided neither the ‘Allow Container Creation during Close’ nor the ‘Auto 
 Manifest at Close’ flags are turned on.  The 
 results of this processing include the status of the container changed, 
 as well as the leading status on the associated shipment, is updated to 
 ‘Ship Confirm Pending.’  The 
 weight on the container is updated if the weight measured differs from 
 the weight already on the container.<br data-source-node="n245"> </li>
            <li data-source-node="n246">Manifest pre-created 
 containers (Pass MANIFEST, container id, container weight): If 
 a customer is interested in only manifesting containers at the scan and 
 weigh station, this is the scenario that would best fit.  This 
 scenario will not close the containers, but only manifest them.  The 
 request type would be MANIFEST.  Once 
 the container has been weighed and the request inserted, the scan and 
 weigh processing will call the manifest processing.  The 
 result will be a manifested container with an updated tracking number. </li>
        </ul>
