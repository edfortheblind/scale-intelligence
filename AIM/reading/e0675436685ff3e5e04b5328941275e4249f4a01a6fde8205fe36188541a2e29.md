
        
        <h1 data-source-node="n56"><a name="kanchor475" data-source-node="n57"></a>Overriding Shipment Data in a Wave</h1>
        <p data-source-node="n58">The application provides a wave step that allows you to update data 
 (that you normally would not have access to) during the wave process. 
 You can configure this "override data" wave step to replace 
 a specific data field with a value that you define. To configure this 
 action, you will need to create a override data record (and a corresponding 
 criteria record), and include this "override data" wave step 
 in your default flow. Additionally, the system allows you to include multiple "override 
 data" wave steps in your wave flow. This allows you to override different 
 types of data at different times during the wave. To create additional 
 steps, you will first need to copy the default override wave step, and 
 then create the wave step(s) based on this base override data functionality. 
 Note that only override data wave steps (with the specific base Namespace/Class/Method) 
 will appear in the Wave Step Field on the Override Data Window. </p>
        <p data-source-node="n59"> </p>
        <h4 data-source-node="n60">Active Scale users note: </h4>
        <ul data-source-node="n61">
            <li data-source-node="n62">The override data configuration is available for Lower and Production level users only.</li>
            <li data-source-node="n63">Customer SQL checkbox is enabled for Lower and Production Level users only. <ul data-source-node="n64"><li data-source-node="n65">User can only view the text on selecting the checkbox. </li><li data-source-node="n66">Custom SQL text can be  selected and copied. </li></ul></li>
            <li data-source-node="n67">Lower and Production level users can Create, Delete, Copy existing override data.<ul data-source-node="n68"><li data-source-node="n69">When creating a new override data, users will not be able to select the SQL checkbox. The Update Criteria drop-down lists is available when creating new override data.</li></ul></li>
        </ul>
        <p data-source-node="n70"> </p>
        <p data-source-node="n71">WARNING: Since you can also use 
 this functionality to execute a custom SQL statement during the wave process, 
 you need to be careful that the SQL that you want to execute is valid. 
 If the system has an error when attempting to execute this SQL statement, 
 the system will not process your custom statement, and proceed to the 
 next wave step.</p>

        <h4 data-source-node="n136"><a name="1" data-source-node="n137"></a>Override Data Window...</h4>
        <p class="p_15" data-source-node="n138"> </p>
        <h5 data-source-node="n139">Using the Header Fields</h5>
        <p data-source-node="n140">Access the Override Data Window. Name a record and provide a description.</p>
        <ol class="ol_1" data-source-node="n141">
            <li value="1" data-source-node="n142">Use the Wave 
 Step Field to indicate the wave step that will initiate the data 
 override. <br data-source-node="n143"> </li>
            <li value="2" data-source-node="n144">Use the Priority 
 Field to indicate in what order the system will process the override 
 data wave step(s). During a wave, the system processes though these steps 
 one after another. This priority setting tells the system in what order 
 these updates should be processed. Therefore, if you have an override 
 data step that is dependent on data from another record, you can give 
 the one that needs to happen first a lower priority number. Thus, the 
 update will take place before the system starts doing the checks for the 
 next step.<br data-source-node="n145"> </li>
            <li value="3" data-source-node="n146">Use the Custom 
 SQL Checkbox to add your own SQL statement to this record. The 
 system will display a text edit box so you can enter your own custom code. 
 If you have entered any values in the other fields on this window, the 
 system will display this in the text box as SQL when you select this checkbox. 
 You can then edit these values directly from the SQL statement.<br data-source-node="n147"><br data-source-node="n148">	Also there is a special token included in the custom SQL called &lt;&lt;LAUNCH_NUM&gt;&gt;. You should 
 always leave this value unchanged unless you intend to update data for 
 things outside of this specific wave. If you leave the value in the statement, 
 the system will test the SQL statement when you exit. If you remove this 
 value, the system will not test the statement because it will not know 
 what wave you are trying to update.</li>
        </ol>
        <p data-source-node="n149"> </p>
        <h5 data-source-node="n150">Using the Update Criteria 
 Tab</h5>
        <ol start="1" class="ol_1" data-source-node="n151">
            <li value="1" data-source-node="n152">Use the Data 
 Selection Field to indicate the criteria record that you want to 
 use to determine exactly what data that the system will override. For 
 example, you could define a criteria record for a specific customer, company, 
 etc., and the system then would only override data for that customer/company. 
 <br data-source-node="n153"> </li>
            <li value="2" data-source-node="n154">Use the Override 
 Table Field to indicate which database table includes the field-level 
 data that you want to override. This table that you choose determines 
 which fields you can choose from in the Override Field. Remember that 
 you can choose to update   <span class="span_1" data-source-node="n155">any</span> 
 database table using the custom SQL option.<br data-source-node="n156"> </li>
            <li value="3" data-source-node="n157">Use the Override 
 Field Field 
 to indicate the shipping field value that you want the system to override.<br data-source-node="n158"> </li>
            <li value="4" data-source-node="n159">Use the Set To 
 Value Field to indicate the new value that you want the override 
 field to have. <br data-source-node="n160"> </li>
            <li value="5" data-source-node="n161">Use the Override 
 Existing Data Checkbox to tell the system that even if the override 
 field has a previous value, you want to replace this value with the new 
 one. Otherwise, the system would only override this field's value if it 
 was   blank,   null,   0 (if a numeric field), or   *Default.<br data-source-node="n162"> </li>
            <li value="6" data-source-node="n163">Press OK. 
 The system will save your record.</li>
        </ol>

        <h4 data-source-node="n166"><a name="2" data-source-node="n167"></a>Override Data Criteria Window...</h4>
        <p data-source-node="n168"> </p>
        <h5 data-source-node="n169">Using the Filter Tab (in 
 the Override Data Criteria Window)</h5>
        <p data-source-node="n170">Access the Override Data Criteria Window. Name a record and provide 
 a description.</p>
        <ul type="disc" class="ul_1" data-source-node="n171">
            <li data-source-node="n172">You can use these 
 records to determine which set of data that you want the system to override. 
 For example, if you want the system to only look at a certain customer 
 or company's data, you would define a criteria record to search for that 
 certain customer/company. You can then choose this record on the Override 
 Data Window's Data Selection Field.</li>
        </ul>
