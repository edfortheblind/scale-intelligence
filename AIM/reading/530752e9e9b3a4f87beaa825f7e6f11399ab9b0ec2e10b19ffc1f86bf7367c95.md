
        
        <h1 data-source-node="n56"><a name="kanchor1297" data-source-node="n57"></a>Shipping Container Verification Field</h1>
        <p data-source-node="n58">This field determines the method of shipping container verification during picking:</p>
        <ul data-source-node="n59">
            <li data-source-node="n60"><i data-source-node="n61">None</i>: The system will show the container ID in display mode (no additional user verification needed).<br data-source-node="n62"><br data-source-node="n63"></li>
            <li data-source-node="n64"><i data-source-node="n65">Container Verify</i>: The system will require the user to correctly identify the shipping 
 container that is being picked into.<br data-source-node="n66"><br data-source-node="n67"></li>
            <li data-source-node="n68"><i data-source-node="n69">Container Spot Verify</i>: The system will require the user to correctly identify the shipping container's spot on the picking cart. Note that this setting is only valid when using group user picking (otherwise the system ignores it).<br data-source-node="n70"><br data-source-node="n71"></li>
            <li data-source-node="n72"><i data-source-node="n73">Allow Override</i>: The system will default the container ID in the field, and the user can change this value if desired. The system then would validate this new ID to make sure that it does not already exist.</li>
        </ul>
        <p data-source-node="n74"> </p>
        <h5 data-source-node="n75">More Details On Picking Into Totes/Shipping Containers...</h5>
        <p data-source-node="n76">In the Work Special Handling configuration, there are various settings for shipping container verification that affect how the system handles prompting for a container ID when one is already associated with the shipment.  This handling can be different depending on whether the user is picking to tote, picking to a shipping container being created during the picking process, or picking to a shipping container created in the wave. Note that on the first pick for a work unit for work created from allocation requests, the system simply displays a blank input field for the container ID since no picks have yet been done for any ID.</p>
