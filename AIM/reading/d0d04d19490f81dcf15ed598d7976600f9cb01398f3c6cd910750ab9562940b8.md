
        
        <h1 data-source-node="n56"><a name="kanchor1001" data-source-node="n57"></a>Defining Work Special Handling Constraints</h1>
        <p data-source-node="n58">A special handling constraint record defines processing validations 
 or restrictions required for a specific group of work instructions. You 
 can use them to increase security for expensive product, support a customer 
 account's requests, provide guidelines for new employees, and minimize 
 errors occurring in specific warehouse zones. Note that these special handling constraints are only reflected in RF work processing, not in the full-screen Work Insight Screen.</p>

        <h5 data-source-node="n135">Using the General Tab<br data-source-node="n136"></h5>
        <p data-source-node="n137">You will use this tab to identify when the system will require special 
 handling.</p>
        <ol data-source-node="n138">
            <li value="1" data-source-node="n139">
                <p data-source-node="n140">To require special handling when 
 a particular item is processed, identify that item in the Item 
 Field. If a company is associated with that item, the system will automatically 
 default it in the Company Field.</p>
                <p data-source-node="n141"> </p>
            </li>
            <li value="2" data-source-node="n142">
                <p data-source-node="n143">To require special handling when 
 product is processed for a particular account, identify that account 
 in the Account Field.</p>
                <p data-source-node="n144"> </p>
                <p data-source-node="n145">NOTE: If you are defining this record 
 for inbound receipts, the account field identifies the vendor supplying 
 the product. If you are defining this record for outbound receipts, the 
 account field identifies the customer ordering the product.</p>
                <p data-source-node="n146"> </p>
            </li>
            <li value="3" data-source-node="n147">To require special 
 handling to meet warehouse requirements or special conditions, 
 use the Work Fields. You can use any combination of the following fields: 
 User Name, Work Type, Work Zone. Work level validation allows you to provide 
 additional guidelines for new or inexperienced personnel.</li>
        </ol>
        <h5 data-source-node="n148"> </h5>
        <h5 data-source-node="n149">Using the Key Values Tab<br data-source-node="n150"></h5>
        <p data-source-node="n151">You will use this tab to identify what special handling the system will 
 require. You can use any combination of these fields. If you define multiple 
 values here, the system will require that employee commit all validations.</p>
        <ol class="ol_1" data-source-node="n152">
            <li value="1" data-source-node="n153">Use the Shipping 
 Container Verification Field to verify shipping container IDs during picking:<br data-source-node="n154"><br data-source-node="n155">- <i data-source-node="n156">None</i>: The system will show the container ID in display mode (no additional user verification needed). Note that if the user partial picks the quantity, they will have to scan the container ID for the next instruction.<br data-source-node="n157"><br data-source-node="n158">- <i data-source-node="n159">Container Verify</i>: The system will require the user to correctly verify (by entering or scanning the ID) the shipping 
 container that is being picked into. <br data-source-node="n160"><br data-source-node="n161">- <i data-source-node="n162">Container Spot Verify</i>: The system will require the user to correctly identify the shipping container's spot on the picking cart. Note that this setting is only valid when using group user picking (otherwise the system ignores it).<br data-source-node="n163"><br data-source-node="n164">- <i data-source-node="n165">Allow Override</i>: The system will default the container ID in the field, and the user can change this value if desired. The system then would validate this new ID to make sure that it does not already exist.<br data-source-node="n166"><br data-source-node="n167">For more information on this setting, see the <a href="530752e9e9b3a4f87beaa825f7e6f11399ab9b0ec2e10b19ffc1f86bf7367c95.html" data-source-node="n168">field topic</a>.<br data-source-node="n169"><br data-source-node="n170"></li>
            <li value="2" data-source-node="n171">Use the Maximum 
 Pickup Quantity to define the maximum number of units that can 
 be picked at one time. When the employee is picking the product, the system 
 will require him/her to only pick the amount displayed here. If the work 
 instruction requires more than the value defined here, the system will 
 ask the user to pick this amount as many times as required to fulfill 
 the work instruction. This constraint increases the likelihood that the 
 employee will count the product.<br data-source-node="n172"><br data-source-node="n173"></li>
            <li value="3" data-source-node="n174">Use the Allow Splitting Of Container Checkbox to define whether or not you will be allowed to split off and pick a portion of the quantity into another container. To accommodate this action, the system will create a new work unit and container for the split quantity. This is helpful if the container that you are picking into gets full before you are done picking the current quantity. Typically this situation would occur if you created containers in the wave, and the current pick physically will not completely fit into the container that the system created for it.<br data-source-node="n175"><br data-source-node="n176"></li>
            <li value="4" data-source-node="n177">Use the Allow 
 Over Picking Checkbox to allow the user to pick more quantity than 
 exists on a work instruction, as long as this quantity is within the location's 
 available quantity. When an over pick is performed, the system will increment 
 the transaction quantity, and process the pick as a complete/normal pick. 
 This option is only available for RF replenishment and work order picking. 
 For example, suppose a work order component work instruction calls for 
 980 eaches of an item. It may be easier physically, then, for the worker 
 to pick two cases of 500 (for a total of 1,000 eaches) rather than breaking 
 one case open and leaving 20 eaches loose at the location. If this checkbox 
 is checked, the system will increment the instruction by 20 eaches, and 
 process the pick as normal.<br data-source-node="n178"><br data-source-node="n179"></li>
            <li value="5" data-source-node="n180">Use the Allow Pick in Transit Checkbox to allow the user to pick in transit quantities. If there is not enough quantity in the location to be picked but there is additional inventory that is 'on the way', this allows the user to pick from what is coming or 'in transit'. If the inventory is picked against what's in transit, the inventory will show a negative quantity. <br data-source-node="n181"><br data-source-node="n182"></li>
            <li value="6" data-source-node="n183">Use the Close 
 After Partial Pick Checkbox to allow the user to partial pick the 
 quantity of a work instruction, and the system will delete the remaining 
 quantity from the work instruction. The system will then close the work 
 instruction. Therefore, the remaining quantity will never actually be 
 picked. This option is only available for RF replenishment and work order 
 picks. For example, suppose you have a replenishment request that calls 
 for 620 eaches of an item. The user, however, may only want to pick 600 
 eaches of the item (because that is a more round number in regards to 
 how things are packed), so they just want the other 20 eaches to “go away.” 
 If this checkbox is checked, the system would delete the remaining 20 
 eaches from the work instruction (after the user picks the 600), and close 
 the work instruction.<br data-source-node="n184"><br data-source-node="n185"></li>
            <li value="7" data-source-node="n186">Use the Replenish On Outbound Short Pick Checkbox to indicate that when the user short picks an item quantity at a location, the system will attempt to run replenishment (based on the location's item demand resulting from the short pick). If there is enough In transit quantity that is on its way to the location for this item, then the system will display to the user a message asking whether or not they want to continue with the short pick. For more detailed information about this replenishment process, see the process diagram on the <a href="61f0a241aded189425d956f7a9408608bd793068a8dc510d53f5fb402c6c9b58.html" data-source-node="n187">Replenishment Process Summary</a> topic.<br data-source-node="n188"><br data-source-node="n189"></li>
            <li value="8" data-source-node="n190">
                <p data-source-node="n191">Use the Use Converted Quantity Checkbox for users who do not pick in the base UM and pick in either cases or pallets. If the user is not picking any item in eaches and always picks in an UM which is not the base UM, then the picks should also happen with the converted quantity (CS, PL etc.). For example, if 1 CS= 10 EA and a user picks 2 CS, the converted quantity is 20 EA. </p>
                <p data-source-node="n192"> </p>
                <p data-source-node="n193">So the system uses the converted quantity as the main pick quantity value and the base value as the secondary read-only values when the pick quantity is a multiple of the converted quantity. If the pick quantity is not a multiple of the converted quantity, the system uses base quantity UM as the pick quantity. Also, the system updates work, inventory, shipment, and transaction history correctly based on converted UM quantity picks.</p>
                <p data-source-node="n194"> </p>
                <p data-source-node="n195">NOTE: User cannot enter a decimal quantity for the converted quantity to a partial/short pick.</p>
                <p data-source-node="n196"> </p>
            </li>
            <li value="9" data-source-node="n197">Use the Item 
 Verify Checkbox to require that the user verify what item is processed. 
 Employees can verify an item by either scanning or manually entering its 
 barcode. The system will accept the item number or any value associated 
 with it on the Item Cross Reference Window, such as a UPC number.<br data-source-node="n198"><br data-source-node="n199">NOTE: The system only applies item verification during 
 RF device processing; it is not applied to work processed on the Work 
 Insight Screen.<br data-source-node="n200"> </li>
            <li value="10" data-source-node="n201">Use the Quantity 
 Verify Checkbox to require the user to identify how many item units 
 he/she is processing. For example, if this checkbox is selected, the system 
 will display a blank quantity field, and the user will have to actually 
 enter the quantity, thereby "verifying" it. If this checkbox 
 is not selected, the system will default the quantity value in the field, 
 and the user will not have to manually enter a value.<br data-source-node="n202"> </li>
            <li value="11" data-source-node="n203">Use the License Plate Verify Checkbox to require the user to identify the ID of the license plate that he/she is picking from. If this is not checked, the License Plate Field on the RF Pick Confirmation screen will be read-only. If it is checked, the system will display the correct ID, and the user will need to scan the license plate to verify the value.<br data-source-node="n204"><br data-source-node="n205"></li>
            <li value="12" data-source-node="n206">Use the Lot Verify Checkbox to require the user to identify the lot ID associated with the item quantity that he/she is picking. If this is not checked, the Lot Field on the RF Pick Confirmation screen will be read-only. If it is checked, the system will display the correct ID, and the user will need to scan the lot to verify the value.<br data-source-node="n207"> </li>
            <li value="13" data-source-node="n208">Use the License Plate Putaway Verify Method Buttons to determine how the system will require you to enter license plate IDs during putaway:<br data-source-node="n209"><br data-source-node="n210">- If Use Existing License Plate (No Override Allowed), the system will show the existing license plate ID in display mode, and not allow you to enter a new value.<br data-source-node="n211"><br data-source-node="n212">- If Verify Existing License Plate, the system will require you to enter the existing license plate ID for confirmation. An error will occur if you enter a new value.<br data-source-node="n213"><br data-source-node="n214">- If Existing License Plate (Allow Override), the system will show the existing license plate, and you can either use the existing license plate or enter a new value.<br data-source-node="n215"><br data-source-node="n216">- If User Specified, the system will not show the existing license plate. Therefore, you will have to enter a new value.<br data-source-node="n217"><br data-source-node="n218"></li>
            <li value="14" data-source-node="n219">Use the Override Pick Checkboxes to determine what value(s) that a user can change during RF pick confirmation. Note that this setting does not apply to work done in the full-screen Work Insight Screen. You can enable the user to override any/all of the following values: Location, Lot, License Plate. See <a href="5ea80956b207057fdc2d841bb836a676ef62f554f56c6da1c57f1997b9f84e20.html#override" data-source-node="n220">this topic</a> for rules that the system enforces for override picks.<br data-source-node="n221"><br data-source-node="n222">- Prompt On LP/Location/Lot Override Checkbox: When this setting is active, the system will display an alert message when you attempt to override one of the pick values described above.<br data-source-node="n223"><br data-source-node="n224"></li>
            <li value="15" data-source-node="n225">Use the Prompt for Quantity to perform Inline Partial Pick for Container Creation During Pick. The system will prompt with quantity field to enter the partial quantity. <br data-source-node="n226"></li>
        </ol>
        <h5 data-source-node="n227"> </h5>
        <h5 data-source-node="n228">Using the Cycle Count Tab <br data-source-node="n229"></h5>
        <p data-source-node="n230">You will use this tab to configure work special handling constraints related to cycle counting.</p>
        <p data-source-node="n231"> </p>
        <p style="font-style: normal" data-source-node="n232"><i data-source-node="n233">Note on Adding Items During Cycle Counting</i>: The system can provide the opportunity for you to add an item to a location when performing an RF cycle count. In order to activate this option, you must configure the user's "Add New Inventory" security setting in the RF Cycle Count security form (this setting is active by default). Also note that this add item functionality only applies when performing RF cycle counting (not during full-screen cycle counting).</p>
        <ol data-source-node="n234">
            <li value="1" data-source-node="n235">Use the License Plate Selection Method Buttons to indicate how you want to initiate license plate cycle counts:<br data-source-node="n236"><br data-source-node="n237">- System Initiated: This indicates that the system will tell the user the order of the license plates that they are required to cycle count.<br data-source-node="n238"><br data-source-node="n239">- User Initiated: This indicates that the user will be able to specify which license plate that they want to count.<br data-source-node="n240"><br data-source-node="n241"></li>
            <li value="2" data-source-node="n242">Use the Count Level Field to indicate what entity the user will count at a location:<br data-source-node="n243"><br data-source-node="n244">- <i data-source-node="n245">Standard Count</i>: The user will count the individual cycle count(s) present for the location.<br data-source-node="n246"><br data-source-node="n247">- <i data-source-node="n248">Blind Count</i>: As in a standard count, the user will count the individual cycle count(s) present for the location. However, the system does not present any information on screen *except* for the location ID. Therefore, the user is forced to count each item that is physically present in the location without the system guiding them in what should be counted.<br data-source-node="n249"><br data-source-node="n250">- <i data-source-node="n251">Count License Plates</i>: The user will count the number of license plate(s) that are currently present at a location. For example, suppose a certain product is housed in a second story location. Since users would not be able to easily access and count the quantity contained in these license plates, you could configure counts for this product to ask for the number of license plates present at the location, rather than a count of the actual quantity. Note that if a license plate count differs from what the system expected, the system will require the user to count the actual quantity contained per license plate and license plate count is allowed for multi locations. Also note that multi-item locations always force the user to count individual quantities (even if you have this setting selected on your work special handling). <br data-source-node="n252"><br data-source-node="n253">- <i data-source-node="n254">Group Count By Item/Company</i>: The user will count all of the quantity at a given location for the same item/company (regardless of the lot ID, inventory attribute, and/or license plate values):<br data-source-node="n255"><br data-source-node="n256">* If the user's total-quantity count does not meet the system's total-quantity count, the system will ungroup the cycle count work and display an error message.<br data-source-node="n257"><br data-source-node="n258">* If you are cycle counting multiple items at the same location OR an empty location, then you will have to confirm the counts individually (even if this setting is enabled).<br data-source-node="n259"><br data-source-node="n260">* If you choose to add an item when confirming a grouped count, the system will ungroup the cycle count work and you will need to confirm each count individually. Note that after you add an item, the system will give you the option to continue with the add item action, or to return to the group count.<br data-source-node="n261"><br data-source-node="n262">* If this setting is enabled AND lot/license plate verification is enabled, the system will ungroup the cycle count work and you will need to confirm each count individually.<br data-source-node="n263"><br data-source-node="n264">* The system logs group count labor activity as individual cycle counts.<br data-source-node="n265"><br data-source-node="n266"></li>
