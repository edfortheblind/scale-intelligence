
        
        <h1 style="text-align: left;font-size: 12pt" data-source-node="n56"><span style="font-size: 18pt" data-source-node="n57">Cycle Count Preference Configuration</span>
        </h1>
        <h4 data-source-node="n58">Overview</h4>
        <p data-source-node="n59">A cycle count preference record controls whether cycle count requests should be executed immediately, or created as "pending" requests. Note that when you are not executing work, this concept of immediate execution does not apply, so the system will create all requests as pending. Also, you can define positive and negative tolerance values which determine when a user can make a location adjustment. In addition, you can associate a work team and work type to a preference record.</p>
        <p data-source-node="n60"> </p>
        <h4 data-source-node="n61">General information</h4>
        <p data-source-node="n62"> </p>
        <p data-source-node="n63">Enter Preference Name and Description</p>
        <p data-source-node="n64"> </p>
        <p data-source-node="n65">Work Type</p>
        <ul data-source-node="n66">
            <li data-source-node="n67">
                <p data-source-node="n68">Select the Work Type Field to indicate the work type associated with this preference record.</p>
            </li>
        </ul>
        <p data-source-node="n69"> </p>
        <p data-source-node="n70">Work Team</p>
        <ul data-source-node="n71">
            <li data-source-node="n72">
                <p data-source-node="n73">Select the Work Team to indicate the work team associated with this preference record.</p>
            </li>
        </ul>
        <p data-source-node="n74"> </p>
        <p data-source-node="n75">Perform threshold counts immediately</p>
        <ul data-source-node="n76">
            <li data-source-node="n77">
                <p data-source-node="n78">Select the Perform Threshold Counts Immediately option to indicate if an RF user should be presented with a cycle count request immediately after the short pick, or if the system should write the request and give it to another user later. This will occur if a picking location's on hand quantity falls into one of the cycle count thresholds set up in the Cycle Count Threshold Window.</p>
            </li>
        </ul>
        <p data-source-node="n79"> </p>
        <p data-source-node="n80">Verify bad count</p>
        <ul data-source-node="n81">
            <li data-source-node="n82">
                <p data-source-node="n83">Select the Verify Bad Count on  indicate that you want the system to force an Warehouse Mobile user to enter a count's quantity again, IF the user count is different than the system count (this is known as a "bad" count).</p>
            </li>
        </ul>
        <p data-source-node="n84"> </p>
        <h4 data-source-node="n85">Reconcile Options</h4>
        <p data-source-node="n86"> </p>
        <p data-source-node="n87">Immediate reconcile of bad count</p>
        <p data-source-node="n88">Select the Immediate Reconcile of Bad Count Check box indicates if the user can immediately adjust the inventory in this location as long as it's within the above tolerances.</p>
        <p data-source-node="n89"> </p>
        <ul data-source-node="n90">
            <li data-source-node="n91">
                <p data-source-node="n92">If this check box is checked, the user assigned to this preference can immediately adjust the inventory in this location, as long as it's within the tolerances.</p>
            </li>
        </ul>
        <ul data-source-node="n93">
            <li data-source-node="n94">
                <p data-source-node="n95">If this check box is not checked, the user assigned to this preference can never adjust the inventory on his own. The system will place every cycle count request that this user encounters into a "pending review" status. This request then will have to be reviewed by someone authorized to perform cycle counts.</p>
            </li>
        </ul>
        <p data-source-node="n96"> </p>
        <p data-source-node="n97">Positive tolerance</p>
        <ul data-source-node="n98">
            <li data-source-node="n99">
                <p data-source-node="n100">Use the Positive Tolerance Field to determine the number of units above the number the system thinks is present in a location that the system will allow the user to perform an adjustment to the location. For example, suppose the value in this field is "5". Then, you are presented with a cycle count request that indicates that there should be 20 units of an item in a particular location. You count the units in the location, and there are 35. The system then will compare this number to the positive tolerance value defined in this window. This will determine if the user is allowed to make an adjustment. Since the item quantity in this location is 15 units over the tolerance, the system will put this request in a pending review status, and you will not be able to execute the cycle count. Once the cycle count is in the pending review status, it must be reviewed from the Cycle Count Request Insight screen by a supervisor.</p>
            </li>
        </ul>
        <p data-source-node="n101"> </p>
        <p data-source-node="n102">Positive price tolerance</p>
        <p data-source-node="n103"> </p>
        <p data-source-node="n104">Use the Positive Price Tolerance Field to determine the amount above the total net price value that the system thinks is present in a location, where the system will allow you to successfully perform cycle count work. If the total net price for an item/location exceeds this defined value, the system will place the "overage" quantity into suspense (thus not committed immediately so a supervisor can review this transaction). In this case, the system will close the cycle count work, and the cycle count request will be placed in a "review pending" status.</p>
        <p data-source-node="n105"> </p>
        <ul data-source-node="n106">
            <li data-source-node="n107">
                <p data-source-node="n108">For example, suppose the value in this field is 50.00, and you are presented with a cycle count request that indicates that there should be 400.00 dollars worth of an item in a particular location. When you count the units in the location, however, there is actually 575.00 dollars of the item present in the location. The system then will compare this number to the defined positive tolerance value. If the total net price falls within this tolerance, then the system will allow you to complete the cycle count and adjust the "overage" into the location. In this example, though, the item quantity in this location is 125.00 dollars over the defined tolerance. Therefore, the system will put this cycle count request in a pending review status. It does not update suspense quantity when the price/quantity exceeds the positive tolerance.</p>
            </li>
        </ul>
        <p data-source-node="n109"> </p>
        <p data-source-node="n110">Note that if you define a zero value in this field, the system will not consider net price for tolerance.</p>
        <p data-source-node="n111"> </p>
        <p data-source-node="n112">Negative tolerance</p>
        <ul data-source-node="n113">
            <li data-source-node="n114">
                <p data-source-node="n115">Use the Negative Tolerance Field to determine the number of units below the number the system thinks is present in a location that the system will allow the user to perform an adjustment to the location. For example, suppose the value in this field is 5. Then, you are presented with a cycle count request that indicates that there should be 35 units of an item in a particular location. Once the cycle count is in the pending review status, it must be reviewed from the Cycle Count Request Insight screen by a supervisor.</p>
            </li>
        </ul>
        <p data-source-node="n116"> </p>
        <p data-source-node="n117">Negative price tolerance</p>
        <p data-source-node="n118"> </p>
        <p data-source-node="n119">Use the Negative Price Tolerance Field to determine the amount below the total net price value that the system thinks is present in a location, where the system will allow you to successfully perform cycle count work.         <p data-source-node="n120"> </p>
        <ul data-source-node="n121">
            <li data-source-node="n122">

            </li>

        <p data-source-node="n124">Note that if you define a zero value in this field, the system will not consider net price for tolerance.</p>
