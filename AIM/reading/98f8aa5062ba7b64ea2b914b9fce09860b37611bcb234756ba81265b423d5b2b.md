
        
        <h1 style="text-align: left;font-size: 12pt" data-source-node="n56"><span style="font-size: 18pt" data-source-node="n57">Allocation Configuration</span>
        </h1>
        <h4 data-source-node="n58">Overview</h4>
        <p data-source-node="n59">An allocation rule set identifies the sequence rules the system will use to allocate products. A sequence rule determines the system  allocate product from a location. Generally, an allocation rule set includes multiple sequence rules, which the system processes in numerical order (1, 2, 3, etc.). Each sequence rule can be tied to a location selection and/or strategy.</p>

        <h4 data-source-node="n66">Allocation Rule configuration</h4>
        <p data-source-node="n67"> </p>
        <h5 data-source-node="n68">1. Rule Information </h5>
        <p data-source-node="n69"> Rule name and Description are defined for the rule. Users can add sequence detail records. Users can change the sequence number, but cannot use the same sequence number for multiple detail records.  The lower the sequence number, the sooner the system will process it.</p>
        <p data-source-node="n70"> </p>
        <h5 data-source-node="n71">2. Add New Sequence </h5>
        <p data-source-node="n72"> Sequence records are created by defining strategy, Location selection and UMs.</p>
        <p data-source-node="n73"> </p>
        <p data-source-node="n74"><b data-source-node="n75">Strategy</b> -  An allocation strategy defines the system's methodology for allocating product. It determines which from which location you will allocate, based on an operational requirement or directive. A sequence record can include both a strategy and a location selection value, or just one of these values. For example, if you select the strategy Maximize Space value, the system will attempt to empty as many locations as possible via allocation. Read <a href="a2d8089500b1e693033fa7cbf77ca4b879de2a70a0a976f2d5cb926deb137ba3.html" data-source-node="n76">Allocation Strategy</a> for more information.</p>
        <p data-source-node="n77"> </p>
        <p data-source-node="n78"><b data-source-node="n79">Location Selection </b>
        </p>
        <p data-source-node="n80"> A location selection record identifies the possible allocation locations. A sequence record can include both a strategy and a location selection value, or just one of these values. These help minimize processing time and increases your control over allocation activity. The location selection can also have a sort defined, which the system will use after the strategy's sort is completed.</p>
        <p data-source-node="n81"> </p>
        <p data-source-node="n82"><b data-source-node="n83">Sequence Details </b>
        </p>
        <p data-source-node="n84"> Configure rules to allocate the lot-controlled items and Unit of Measurement</p>
        <p data-source-node="n85"> </p>
        <ul data-source-node="n86">
            <li data-source-node="n87">
                <p data-source-node="n88">UMs - Select the unit of measurement for the rule. The system will only perform the allocation for locations that support UMs selected on this list.</p>
            </li>
        </ul>
        <ul data-source-node="n89">
            <li data-source-node="n90">
                <p data-source-node="n91">Any Lot (Multiple OK): Choose this option to have the system allocate items with any lot, when allocating multiple lots to fulfill the demand is acceptable. The system will use the allocation strategy and allocation location selection records to determine the order that the locations will be allocated from.</p>
            </li>
        </ul>
        <ul data-source-node="n92">
            <li data-source-node="n93">
                <p data-source-node="n94">Any Lot (Single Only): Choose this option to have the system allocate any lot, but just a single lot. The system will use the allocation strategy and allocation location selection records to determine ordering (just like normal allocation). But once a lot is selected, it will be the only lot allocated. If the allocation demand cannot be met with this lot, the system will reject the rest of the quantity. If not enough quantity can be found for one lot, the system will allocate the largest quantity of one lot, and fail the rest of the quantity. Note that this single lot may exist in multiple locations.</p>
            </li>
        </ul>
        <ul data-source-node="n95">
            <li data-source-node="n96">
                <p data-source-node="n97">Specified Lot (Single Only): Choose this option to have the system allocate only a specified lot. If the system cannot find the specified lot, allocation will fail. The system will only look for the lot specified (such as on the shipment or work order). It will not look for any other lots. If not enough quantity can be found for lot specified, the system will allocate all the quantity found for the specified lot and fail the rest of the quantity. Note that this single lot may exist in multiple locations. NOTE: If no lot is specified on the shipment line, then the system will not fail allocation, but will instead process as it would if using the "Any Lot (Multiple OK)" setting. When no lot is specified (as is often the case with replenishment which does not look at the lot on the shipment line), then allocation should not fail. Allocation will only fail in this scenario if no inventory/lot can be found which matches the specified allocation location selection criteria.</p>
            </li>
        </ul>
        <ul data-source-node="n98">
            <li data-source-node="n99">
                <p data-source-node="n100">Clear Location - When this toggle is selected, the system will allocate from a location inventory record (not the location as a whole) only if the location can be “emptied” without exceeding the demand quantity or the forward location capacity. Also, the system will filter out any location inventory records which has quantity more than the demand or the location capacity. Note: This applies to all types of allocation (shipment, replenishment, work order). <a href="2b555d6c8cfa376ee9c79f9f3a7a5bce1ac427ab24f5b286edb6b040a9538607.html" data-source-node="n101">Click</a> for more information.</p>
            </li>
        </ul>

        <h5 data-source-node="n103">Attribute Based Shipment Allocation</h5>
        <p data-source-node="n104"> </p>
        <p data-source-node="n105">Attribute-Based Shipment Allocation enables the system to use dynamic values from the shipment line as tokens to filter and select appropriate inventory. The inventory is allocated based on attributes that matches shipment-specific requirements provided by the host system.</p>
        <p data-source-node="n106"> </p>
        <p data-source-node="n107">Configuration</p>
        <p data-source-node="n108">To enable attribute-based allocation:</p>
        <ul data-source-node="n109">
            <li data-source-node="n110">
                <p data-source-node="n111">Navigate to Allocation &gt;&gt; Location Selection &gt;&gt; Filter Builder</p>
            </li>
            <li data-source-node="n112">
                <p data-source-node="n113">Toggle Use Shipment Line Value to enable dynamic filtering feature.</p>
            </li>
            <li data-source-node="n114">
                <p data-source-node="n115">The Value drop-down will populate with available columns from the shipment detail table.</p>
            </li>
            <li data-source-node="n116">
                <p data-source-node="n117">The system will validate that the selected attribute and the shipment detail value shares same data type.</p>
            </li>
        </ul>
        <p data-source-node="n118">Example:</p>
        <p data-source-node="n119">A shipment arrives from the host system, requiring items to be shipped from a specific country of origin. The country is stored in User Defined Field 1 on the shipment line — in this example, Spain.</p>
        <p data-source-node="n120"> </p>
        <p data-source-node="n121">Inventory Setup:</p>
        <ul data-source-node="n122">
            <li data-source-node="n123">
                <p data-source-node="n124">Inventory for item exists in multiple locations, each with different attribute values.</p>
            </li>
            <li data-source-node="n125">
                <p data-source-node="n126">Inventory Attribute 01 (ATTRIBUTE 1) is used to store the country of origin for each inventory location.</p>
            </li>
        </ul>
        <p data-source-node="n127">Configuration:</p>
        <ul data-source-node="n128">
            <li data-source-node="n129">
                <p data-source-node="n130">Allocation is configured to use a token referencing User Defined Field 1 from the Shipment details.</p>
            </li>
        </ul>
        <p data-source-node="n131">Allocation Process:</p>
        <ul data-source-node="n132">
            <li data-source-node="n133">
                <p data-source-node="n134">The system reads the dynamic value from the shipment (example, Spain).</p>
            </li>
            <li data-source-node="n135">
                <p data-source-node="n136">It uses this value as a token to filter available inventory locations.</p>
            </li>
            <li data-source-node="n137">
                <p data-source-node="n138">Only inventory locations where Inventory Attribute 01 is Spain will be considered.</p>
            </li>
        </ul>
