Canceling a Wave

You may need to cancel a wave to accommodate unique circumstances. The system allows you to cancel any wave that has been run, as long as it has not been released.

 

When a wave is canceled, the system will:

  • Return all of its shipments; allowing you to assign them to different waves.

  • Deletes any work instructions created for the canceled wave.

  • Looks at the Wave Master configuration to determine if it will also back out any allocations or replenishments it performed for this wave.

NOTE: If a carrier was associated with a shipment during the wave process, the system will not remove that carrier from the pooled shipment. You can manually remove the carrier. Shipments that were assigned to the canceled wave must be reassigned to new waves manually.

Procedures...

When a wave is selected to be canceled, the system prompts the user to either send the shipment back to the pool or assign it to another wave. There are a number of validations and actions that the system performs before a wave is canceled. However, before the wave can be canceled, the system will determine if the wave is eligible for cancellation. If the wave is ineligible, a message is displayed indicating that the wave cannot be canceled and a history record is written.

 

 

Canceling a wave from the Wave Insight Screen
  1. Access the Wave Insight screen from the Order Planning system menu.
     
  2. Search for completed waves in the Wave Insight with the “Show completed waves” wave status criteria turned on.
     
  3. Select a completed wave and tap on Cancel wave from the actions menu.

    Press one of the following buttons:

    - Return To Pool: Press this button if you want the system to send the wave’s shipment’s back to the pool. A success message will be displayed indicating the wave was submitted to batch for cancellation. Upon closing the success message, the system returns to the Wave Insight screen. Search for cancelled waves with the “Show cancelled waves” wave status criteria turned on to see the cancelled wave.

    - Add To Wave: Press this button if you want the system to add the wave’s shipments to an existing wave. The Add shipment to wave screen will open, which allows you to choose from an existing wave. Search for active waves with the “Show active waves” wave status criteria turned on to see the active wave the shipments were added.


    4. NOTE: Canceling a wave from the Wave Insight allows adding all shipments to an active wave. Cancel action from Cancel Wave screen returns back to the Wave Insight screen.

  4. The system will display the message that the waves have been submitted for cancellation. All the shipments are removed from the wave. If the Return All To Pool option is selected, the shipments are returned to the pool. If the Add To Wave option is selected, then the shipments are transferred to the selected wave.

 

If the wave is eligible for cancellation, the system performs the following actions to return the warehouse and shipments to their state prior to the wave running:

 

WAVE STEP: SYSTEM ACTION:
Allocation De-allocates all shipment lines. As part of this activity, it deducts the allocated quantities from the To Location and adds them to the On Hand quantity at the From Location. It also removes this amount from the In Transit quantity at the To Location.
Work, Shipment Allocation Deletes all work instructions created for the shipment allocations.
Work, Shipping Container Deletes all work instructions created for the shipping containers.
Paperwork (Label & Documents) Removes all paperwork and label requests from the print queues.
Manifesting Unmanifests any containers in the wave.
Pro/BOL Number Assignment Removes all routing and PRO numbers so they can be reused
Container Creation Deletes all the containers. The container IDs may be reused.
Dock Assignment Removes containers and pallets from dock positions.
Consolidate Shipments Returns the shipment details to their original shipments. The consolidation is ‘un-done’.
Work Order Creation Cancels the work order requests, cancels any inventory transfers of component pieces and cancels corresponding work.
Add BOM Component Lines Removes component line numbers from the shipment. Component allocation is deleted and the inventory buckets at the To and From Location reflect the cancellation (see Allocation Wave Step for more information).
Load Building System deletes any loads it built. The Load ID numbers are available for another load.

Pick Group Creation System deletes any loads it built. The Load ID numbers are available for another load.
Replenishment

If all requests can be rolled back, the System deducts the allocated quantities at the From Location. It also removes this amount from the In Transit quantity at the To Location.

If one or more requests cannot be rolled back, the System extracts those specific replenishment requests and their corresponding Replenishment Work from the Wave. The system writes process history for each replenishment request that it extracts from the wave.
Replenishment Work

For all requests that are rolled back, the System deletes the work instructions. For all requests that were not rolled back, the system extracts its corresponding work. The system writes process history for each replenishment work record that it extracts from the wave. See examples below.

 

 

Examples...

The 'Maintain Allocated Replenishments Upon Wave' checkbox located on the wave master determines if the system should maintain the replenishment request from the wave when it is canceled. The examples below display what the system performs when this checkbox is used.

 

Example 1: Leave the Replenishment, Round Up

 

Wave 1:

  • Needs 105 books.

  • Case holds 25 books.

  • Demand Replenishment is set to 'Round Up'

  • No books are in forward locations.

  • System brings forward 5 cases of product to location AA to support Wave 1.

Wave 2:

  • Needs 12 books.

  • System allocates the books from the replenishment cases brought forward in Wave 1.

Request to Cancel Wave 1:

  • System checks the quantities at Location AA if this replenishment were to be deleted:

    • Is the Allocated Quantity <= On Hand + In Transit?

    • Allocated Quantity is '12', but the On Hand + In Transit will be '0'

  • System verifies the Maintain Allocated Replenishments Upon Wave Cancellation checkbox is selected.

  • System leaves the request and work from the wave

  • System writes Cancel Wave History records, including records that identify that the replenishment requests and work were extracted.

 

Example 2: Leave the Replenishment, Fill Location 

 

Wave 1:

  • Needs 105 books.

  • Case holds 25 books.

  • Demand Replenishment is set to 'Fill'

  • No books are in forward locations which can hold 100 books.

  • System brings forward 4 cases of product to location AA and 4 cases to location BB to support Wave 1.

 

Wave 2:

  • Needs 12 books.

  • System supplies the books from the replenishment cases brought forward in Wave 1.

Request to Cancel Wave 1:

  • System checks the quantities at Location AA if this replenishment were to be deleted:

    • Is the Allocated Quantity <= On Hand + In Transit?

    • Allocated Quantity is '12', but the On Hand + In Transit will be '0'

  • System verifies the Maintain Allocated Replenishments Upon Wave Cancellation check box is selected.

  • System leaves the request and work from the wave

  • System writes Cancel Wave History records, including records that identify that the replenishment requests and work were extracted.

  • Replenishment request will still fill two locations (the system left the replenishment requests that were generated by the wave).

 

Example 3: Do not Leave the Replenishment 

(Maintain Allocated Replenishments upon Wave Cancellation is not selected).

 

 

Wave 1:

  • Needs 80 books.

  • Case holds 25 books.

  • Demand Replenishment is set to 'Fill'

  • No books in forward locations.

  • System brings forward 4 cases of product to location AA and 4 cases to location BB to support Wave 1.

 

Wave 2:

  • Needs 10 books.

  • System supplies the books from the replenishment cases brought forward in Wave 1.

 

Request to Cancel Wave 1:

  • System checks the quantities at Location AA if this replenishment were to be deleted:

    • Is the Allocated Quantity <= On Hand + In Transit?

    • Allocated Quantity is '12', but the On Hand + In Transit will be '0'

  • System verifies if the Maintain Allocated Replenishments Upon Wave Cancellation checkbox is not selected.

  • System displays an error message indicating that this wave cannot be canceled as its replenishment inventory services multiple waves.
