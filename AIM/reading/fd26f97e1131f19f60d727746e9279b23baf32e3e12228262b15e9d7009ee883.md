
        
        <h1 style="text-align: left;font-size: 12pt" data-source-node="n56"><span style="font-size: 18pt" data-source-node="n57">Item Configuration</span>
        </h1>
        <h4 data-source-node="n58">Overview</h4>
        <p data-source-node="n59">Define an item record in the system, which enables you to manage how it is processed, what allocation and locating rules are applied to it, and what handling controls (lot-controlled, serial number-tracked, etc) are required during processing. An item record identifies a product's unique characteristics, such as list price, department, style, and size. If your warehouse supports multi-company processing, you can identify the company on each item record.</p>

        <h4 data-source-node="n66">Configure Item</h4>
        <p data-source-node="n67"> </p>
        <h5 data-source-node="n68">1. Item Record Information</h5>
        <p data-source-node="n69">Configure the Item name, description and company details. </p>
        <ul data-source-node="n70">
            <li data-source-node="n71">
                <p data-source-node="n72">Item Template - Selecting the item template will accept the item name as structured in the template. </p>
            </li>
        </ul>
        <ul data-source-node="n73">
            <li data-source-node="n74">
                <p data-source-node="n75">Inventory Tracking - Enables the system to track this item at location inventory and perform allocation and replenishment operations.</p>
            </li>
        </ul>
        <ul data-source-node="n76">
            <li data-source-node="n77">
                <p data-source-node="n78">Company - Select the company associated to the Item.</p>
            </li>
        </ul>
        <h5 data-source-node="n79">2. General </h5>
        <p data-source-node="n80">These values are optional properties that will be associated with the item.</p>
        <p data-source-node="n81"> </p>
        <ul data-source-node="n82">
            <li data-source-node="n83">
                <p data-source-node="n84">Allocation Rule - An allocation rule determines how the system will select allocation locations. The system will consider this rule if not defined in the shipment line for the item. </p>
            </li>
        </ul>
        <ul data-source-node="n85">
            <li data-source-node="n86">
                <p data-source-node="n87">NMFC Code -This code links an item to a class for freight rating purposes. Each NMFC value is a sequence of letters and/or numbers representing a group of like items with similar characteristics. It is used primarily by LTL carriers.</p>
            </li>
        </ul>
        <ul data-source-node="n88">
            <li data-source-node="n89">
                <p data-source-node="n90">Packing Class - This identifies items that can be shipped in the same container. Packing classes also identify which containers this item can be packed into.</p>
            </li>
        </ul>
        <ul data-source-node="n91">
            <li data-source-node="n92">
                <p data-source-node="n93">Locating Rule -This determines how the system will locate this product in storage locations. The system will reference this field if a locating rule was not defined on the receipt container record.</p>
            </li>
        </ul>
        <ul data-source-node="n94">
            <li data-source-node="n95">
                <p data-source-node="n96">Item Class - This identifies a group of items that share common characteristics, such as unit of measure values and container dimensions.</p>
            </li>
        </ul>
        <ul data-source-node="n97">
            <li data-source-node="n98">
                <p data-source-node="n99">Storage Template - This groups together quantity UM values that service a general type of product, like liquid, gas, or solid products.</p>
            </li>
        </ul>
        <h5 data-source-node="n100">3. Item Characteristics</h5>
        <p data-source-node="n101">These values represent the basic characteristics such as Color, Style, Division, Department, Cost, List Price and Net Price that are associated with this item.</p>
        <ul data-source-node="n102">
            <li data-source-node="n103">
                <p data-source-node="n104">Shipment BOM - Three Options are available for selection. <a href="b45d784d273a77434f17685c390c11433edd1657e2fc0c63a7e707bd7fbb8e44.html" data-source-node="n105">Click</a> for more information.</p>
            </li>
        </ul>
        <ul data-source-node="n106">
            <li data-source-node="n107">
                <p data-source-node="n108">EPC - Indicate the pre-defined identifier for a company associated with a particular item. This value is used when the system computes an Electronic Product Code (EPC) information.</p>
            </li>
        </ul>
        <ul data-source-node="n109">
            <li data-source-node="n110">
                <p data-source-node="n111">Fedex - Configure the Internal and External Transaction number.</p>
            </li>
        </ul>
        <ul data-source-node="n112">
            <li data-source-node="n113">
                <p data-source-node="n114">GS1 - Configure GTIN for the item. <a href="ca156d855503fd8eca1405d143a049a7be2e5baff1e85b12ea9193a15cd7f39a.html" data-source-node="n115">Click</a> for more information.</p>
            </li>
        </ul>
        <h5 data-source-node="n116">4. Handling Properties</h5>
        <p data-source-node="n117">These values will determine how the items will be processed in the system.</p>
        <ul data-source-node="n118">
            <li data-source-node="n119">
                <p data-source-node="n120">Immediate Needs - Configure this item as eligible for immediate needs processing; and the locating rule that the system will use when processing this item.</p>
            </li>
        </ul>
        <ul data-source-node="n121">
            <li data-source-node="n122">
                <p data-source-node="n123">Inbound QC - Configure this item as eligible for inbound quality control processing; and the locating rule and UM that the system will use when processing this item. Also, you can use the Compute Quantity As buttons and the Inspection Qty field to further define the quantity you want the system to send to QC.</p>
            </li>
        </ul>
        <ul data-source-node="n124">
            <li data-source-node="n125">
                <p data-source-node="n126">Handling - Configure the catch weight, lot controlled, day to expire and Lot Template.</p>
            </li>
        </ul>
        <ul data-source-node="n127">
            <li data-source-node="n128">
                <p data-source-node="n129">Serial Number - It determine how the system will track serial numbers for this item. Choose the warehouse flow (Inbound, Inventory, or Outbound) based on which the system will track the serial number for the item.</p>
            </li>
        </ul>
        <ul data-source-node="n130">
            <li data-source-node="n131">
                <p data-source-node="n132">Internet - Enter the Web Image, Web Thumbnail Image URL and corresponding Description.</p>
            </li>
        </ul>
        <ul data-source-node="n133">
            <li data-source-node="n134">
                <p data-source-node="n135">Alternate - This will associate an alternate item with the current item. Typically, you would use an alternate item when you have designated the current item as obsolete or permanently out of stock. When an alternate item designation exists for an item, the system will alert the user that they are about to order an obsolete item, and that an alternate item is available. The user can then decide whether or not to use this alternate item on their order/shipment line.</p>
            </li>
        </ul>

        <h5 data-source-node="n151">7. <b data-source-node="n152">Item Cross Reference</b></h5>
        <p data-source-node="n153">You can create a cross-reference record for any item defined in the system. Generally, a cross-reference number is established to identify an item's UPC or GS1 number. A user processing an item can use either the item number or the cross-reference number to identify it on an Warehouse Mobile device. </p>
        <p data-source-node="n154">Packing Note: If you are packing, and a shipment happens to have more than one item that shares a single item cross reference, the system will force you to pack the entire quantity of the first item that appears in the record grid.</p>
        <ul data-source-node="n155">
            <li data-source-node="n156">
                <p data-source-node="n157">Use the Item Field to identify the item that you want to create a cross-reference record for.</p>
            </li>
        </ul>
        <ul data-source-node="n158">
            <li data-source-node="n159">
                <p data-source-node="n160">Use the Company Field to select the company associated with this item.</p>
            </li>
        </ul>
        <ul data-source-node="n161">
            <li data-source-node="n162">
                <p data-source-node="n163">Use the Cross-Reference Item Number Field to identify the number that you want to associate with this item. This value can be an alpha-numeric value.</p>
            </li>
        </ul>
        <ul data-source-node="n164">
            <li data-source-node="n165">
                <p data-source-node="n166">Use the Quantity Unit of Measure Field to associate a quantity UM with an item cross reference. Note that an item/company/item cross reference combination can only be assigned to one quantity UM. Also note that this quantity UM association is used only in certain parts of the system.</p>
            </li>
        </ul>
        <p data-source-node="n167">GTIN Enabled?</p>
        <p data-source-node="n168">You can use this field to assign a default quantity UM to a specific GTIN (Global Trade Item Number). If a quantity is specified on the GTIN, then it will be assumed to be of this quantity UM. For example, suppose you have a beverage item that only is stocked in cases. You would then need to associate a quantity UM of "CS" to this beverage's item cross reference. Therefore, any time this item's GS1 barcode is scanned, the system assumes it is a case (CS).</p>
