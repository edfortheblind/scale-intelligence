Replenishment to Satisfy Pool/Wave Demand...

 

This process diagram illustrates how the system creates replenishment requests for pool or wave needs. Each step in the process diagram is further explained in the descriptions below. To access a specific description, click on either the number or the step in the diagram. The system will navigate to the description. To review all of the descriptions, use the toolbar to scroll through them.

 

 

  

Step 1: Replenishment is initiated from either the wave cycle or the Inventory Insight.

  • If the replenishment is initiated from a wave, the system retrieves all of the replenishment master records with the 'wave' replenishment mode. It sorts the records in priority order. Later, these records are processed in priority order: the lower the priority number, the sooner it is run.

     

  • If the replenishment is initiated from the Inventory Insight, the system will display the Manual Replenishment screen. The user will select the replenishment master records that he/she wants to run.

 

Step 2: The system determines what items are eligible for replenishment.

  1. The system obtains the first replenishment master, based on priority, and references its replenishment type. The type defined here determines where the system will check for possible replenishment.

     

    • If the Use Demand from Pool type is selected, the system will check for replenishment opportunities in the order pool.

       

    • If the Use Demand from Wave type is selected, the system will check for replenishment opportunities in a wave being run. In this case, replenishment opportunities are only retrieved for this one wave.

     

  2. The system identifies which items to consider for replenishment based on the values defined on the Filter By Tab on the Replenishment Item Criteria Window. If an item in the pool/wave meets the criteria defined on the replenishment item criteria record, it is considered eligible for replenishment.

     

  3. The system organizes all items that it retrieves based on the values defined on the Order By Tab on the replenishment item criteria record.

     

Step 3: The system determines if replenishment is required.

  1. The system retrieves the demand UM values and the replenishment increment value from the replenishment master record.

     

    • It uses the demand UMs to determine what unit of measures need to be replenished. For example, if the demand UM is each, the system will only attempt to replenish requests for eaches. Requests for the same item in different units of measure are ignored.

       

    • If there are multiple demands using different unit of measures, the system converts the request to the lowest unit of measure on the demands and adds them together. It then performs one replenishment for the total demand amount and converts it back to the different UMs.

    • It uses the replenishment increment to determine what unit of measure to replenish the requests in. This can be a different UM than the Demand UM. For example, you may want to satisfy each demand only (demand UM), but need to move cases forward (replenishment increment).

     

  2. The system determines what units of measure and quantities were requested for the items eligible for replenishment.

     

    • If necessary, the system performs UM conversions upwards within a detail. For example, if a detail requests 30 eaches and there are 20 eaches in a case, the system would convert this request to 1 case 10 eaches. The system never performs UM conversions outside of a detail as the quantities might be destined for different customers.

       

  3. All quantities in the same unit of measure as the Demand UM (Step A) are eligible for replenishment. In Step B above, if the Demand UM is Each, the 10 eaches would be eligible for replenishment. The 1 case is not eligible for replenishment since the Demand UM does not include cases. The system converts this quantity based on the replenishment increment (Step A). In Step B, if the replenishment increment is Case, the system would attempt to replenish 1 case (10 eaches in a case).

 

Step 4: The system determines if the quantity needed is available in the 'replenishment locations'.

  1. The system identifies which locations it should attempt to replenish product to. The system reviews the locations defined on the Replenishment Location Criteria Window. Do any of these locations currently contain this product?

     

    • If yes, the system will begin replenishment at these locations.

       

    • If no, the system will reference the replenishment empty location criteria record associated with this replenishment master. This record identifies where the system should locate replenished product if the replenishment locations are either filled or don't contain the product.

     

  2. After the system identifies the replenishment locations, it determines how many On Hand units of the requested product they contain.

     

  3. The system compares the locations' total On Hand quantity with the requested quantity.

     

    • If the locations' quantity is greater than the request's quantity, replenishment is not required for this item request. If more items were requested in this pool/wave, the system will attempt to replenish them. Return to Step 2B.

       

    • If the location's quantity is less than the request's quantity, the system will check the quantity available in a replenishment is triggered. Continue to Step 5.

 

Step 5: The system finds a location that can support the requested quantity.

  1. For the first location available, the system determines how many units it can hold. The system accesses the Item Location Capacity record to determine how many units the first location can hold. It will reference the Maximum Quantity Field on this window.

     

    • If the Maximum Quantity is defined, the system uses it (and the UM Field) to determine how many units this location can hold.

       

    • If the Maximum Quantity is not defined, the system calculates how many units the location can hold. It performs this calculation by completing the following:

       

      • It compares the location's dimensions to the item's dimensions. The location dimensions are stored on the location type record. The item dimensions are stored for either the item or its item class on the item unit of measure record.

         

      • Maximum Quantity = (Location Length / Item Length) x (Location Width / Item Width) x (Location Height / Item Height) or (Location Length / Item Width) x (Location Width / Item Length) x (Location Height / Item Height), whichever is greater. Example?

  2. After the system identifies how much product this location can hold, it determines if it can be replenished by completing the following:

    • The system determines the location's percentage of fullness, by dividing the On Hand and In Transit Quantities (Step 3) by the Maximum Quantity (Step 4).

       

    • It compares this percentage to the value defined in the Minimum Replenishment Threshold Field on the Item Location Capacity record.

       

    • If this amount is equal to or less than value defined in the Minimum Replenishment Threshold Field, the system will trigger a replenishment for this location.

 

Step 6: The system uses the strategies to determine how much to replenish the location.

If a replenishment is required, the system uses the strategies defined on the replenishment master record. Currently, the system supports three strategies, Fill Location, Round Up, and Round Down.

  1. The system checks to see which replenishment strategy will be used:

    - If Fill Location Strategy, then the system will replenish enough product to fill an entire location.

    - If Round Up, then the system will round up when replenishing for less than a full increment. If the replenishment amount is for less than a full increment (pallet, case, etc), the system will round up and replenish the full increment. For example, if the replenishment amount is for 1.75 case, the system will replenish 2 cases.

    - If Round Down, then the system will round down when replenishing for less than a full increment. If the replenishment amount is for less than a full increment (pallet, case, etc), the system will round down and replenish the full increment. For example, if the replenishment amount is for 1.75 case, the system will replenish 1 case.

 

Step 7: The system uses the allocation rule to select the replenishment's from location(s)

The system determines which allocation rule it will apply to the replenishment quantity. It selects the allocation rule in the following order:

  1. The system attempts to assign the allocation rule defined on the Replenishment Master Record.

     

  2. If the rule is NOT defined on the Replenishment Master Record, the system will check the Item Record.

     

  3. If the rule is NOT defined on the Item Record, the system will assign the *Default allocation record.

     

See the Allocation Process Diagram for more information.

 

 

Step 8: Replenishment complete. Replenishment records must be processed by work creation.

  • The system completes Steps 3 - 7 for all locations that it needs to check.

     

  • If this replenishment was run manually (Step 1), the system will automatically run the work creation process (see the Work Creation Process Diagram for more information). The system will not run the work creation process if the replenishment master is defined to perform immediate execution on replenishment requests. This allows you to run replenishments without creating any work (see the replenishment setup procedures for more information).

     

  • If this replenishment was run automatically from a wave (Step 1), the system will run the work creation process, if it's included in the wave step flow (see the Work Creation Process Diagram for more information). If you are running immediate execution replenishment (see bullet above), the system will not need to invoke the work creation process.

  • If this replenishment is set for no work creation (Step 1), the system will allocate the inventory and generate replenishment requests for eligible locations, execute those requests (which marks the quantity On Hand at the destination location), and then generate a Replenishment Pick List (if paperwork is setup properly). This document would then be used to perform the actual inventory movements.

 

 

 

Replenishment to Satisfy Location Need...

 

This process diagram illustrates how the system creates replenishment requests to accommodate location need. Each step in the process diagram is further explained in the descriptions below. To review all of the descriptions, use the toolbar to scroll through them.

 

 

 

The replenishment process creates work requests to accommodate replenishments. Replenishment can be initiated manually from the Inventory Insight or it can be part of the wave cycle.

 

 

Step 1: Replenishment is initiated from either the wave cycle or the Inventory Insight.

  • If the replenishment is initiated from a wave, the system retrieves all of the replenishment master records with the 'wave' replenishment mode. It sorts the records in priority order. Later, these records are processed in priority order: the lower the priority number, the sooner it is run.

     

  • If the replenishment is initiated from the Inventory Insight, the system will display the Manual Replenishment screen. The user will select the replenishment master records that he/she wants to run.

 

Step 2: The system uses the Replenishment Criteria record to identify the locations eligible for replenishment and order them.

The replenishment criteria record is defined on the replenishment master record.

  1. The system selects the possible replenishment locations based on the values defined on the Filter By Tab on the Replenishment Criteria Window. This tab does not determine which locations will be replenished; rather, it filters through all the warehouse locations and selects which ones might be replenished.

     

  2. It sorts the selected locations based on the values defined on the Order By Tab on the Replenishment Criteria Window. If you define multiple values, the system applies them in the order that they appear in the record list.

     

Step 3: The system identifies how much product is in each location.

  1. First, the system identifies which items in the location are eligible for replenishment. It checks the values defined on the Filter By Tab on the Replenishment Item Criteria Window. If an item in the location meets the criteria defined on the replenishment item criteria record, it is considered eligible for replenishment.

     

  2. Next, For each eligible item, the system identifies the On Hand and In Transit Quantities associated with the location.

     

  3. It references the value in the Replenishment Increment Field on replenishment master record. If the location's UM is different than the record's UM, the system will convert the location's quantity to the UM defined on the replenishment master record.

     

Step 4: It determines how many units that location can hold.

The system will access the Item Location Capacity record to determine how many units this location can hold. It will reference the Maximum Quantity Field on this window.

  • If the Maximum Quantity is defined, the system uses it (and the UM Field) to determine how many units this location can hold.

     

  • If the Maximum Quantity is not defined, the system calculates how many units the location can hold. It performs this calculation by completing the following:

     

    • It compares the location's dimensions to the item's dimensions. The location dimensions are stored on the location type record. The item dimensions are stored for either the item or its item class on the item unit of measure record.

       

    • Maximum Quantity = (Location Length / Item Length) x (Location Width / Item Width) x (Location Height / Item Height) or (Location Length / Item Width) x (Location Width / Item Length) x (Location Height / Item Height), whichever is greater. Example?

Step 5: The system determines if this location should be replenished.

The system determines if a location should be replenished by completing the following:

  1. The system determines the location's percentage of fullness, by dividing the On Hand and In Transit Quantities (Step 3) by the Maximum Quantity (Step 4).

     

  2. It compares this percentage to the value defined in the Minimum Replenishment Threshold Field on the Item Location Capacity record.

     

  3. If this amount is equal to or less than value defined in the Minimum Replenishment Threshold Field, the system will trigger a replenishment for this location.

 

Step 6: The system uses the strategies to determine how much to replenish the location.

If a replenishment is required, the system uses the strategies defined on the replenishment master record. Currently, the system supports two strategies, Fill Location and Round Up.

  1. The system checks to see if the Fill Location Strategy is used?

     

    • If yes, the system will set the Maximum Replenishment Fill % to 100%. Note: after the replenishment is complete, this percent reverts back to its original value.

       

    • If no, the system will not change the Maximum Replenishment Fill %.

       

  2. The system multiplies the Maximum Replenishment Fill % by the location's Maximum Quantity (defined at Step 4). For example, if the Maximum Replenishment Fill % is 75% and the Maximum Quantity is 25, the system would want 18.75 units in that location (.75 x 25 = 18.75).

     

  3. It subtracts this sum from the location's quantity (On Hand quantity + In Transit quantity). For example, assume that there are 2 units in the location and 1 unit In Transit. The system would subtract the units associated with this location from the number obtained at Step B (18.75) - (2 + 1) = 15.75.

     

  4. It checks to see if the Round Up Strategy is used.

     

    • If yes, and the sum is not a whole number, the system will round the replenishment amount up. In the Step C example, the replenishment request is 16.

       

    • If no, and the sum is not a whole number, the system will round the replenishment amount down. In the Step C example, the replenishment request is 15.

 

Step 7: The system uses the allocation rule to select the replenishment's from location(s)

The system determines which allocation rule it will apply to the replenishment quantity. It selects the allocation rule in the following order:

  1. The system attempts to assign the allocation rule defined on the Replenishment Master Record.

     

  2. If the rule is NOT defined on the Replenishment Master Record, the system will check the Item Record.

     

  3. If the rule is NOT defined on the Item Record, the system will assign the *Default allocation record.

     

See the Allocation Process Diagram for more information.

 

 

Step 8: Replenishment complete. Replenishment records must be processed by work creation.

  • The system completes Steps 3 - 7 for all locations that it needs to check.

     

  • If this replenishment was run manually (Step 1), the system will automatically run the work creation process (see the Work Creation Process Diagram for more information). The system will not run the work creation process if the replenishment master is defined to perform immediate execution on replenishment requests. This allows you to run replenishments without creating any work (see the replenishment setup procedures for more information).

     

  • If this replenishment was run from a wave (Step 1), the system will run the work creation process, if it's included in the wave step flow (see the Work Creation Process Diagram for more information). If you are running immediate execution replenishment (see bullet above), the system will not need to invoke the work creation process.

  • If this replenishment is set for no work creation (Step 1), the system will allocate the inventory and generate replenishment requests for eligible locations, execute those requests (which marks the quantity On Hand at the destination location), and then generate a Replenishment Pick List (if paperwork is setup properly). This document would then be used to perform the actual inventory movements.
