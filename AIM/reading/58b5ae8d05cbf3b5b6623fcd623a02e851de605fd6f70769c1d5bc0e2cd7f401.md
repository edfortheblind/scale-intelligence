 New Order Header, Detail, Nested Containers, &amp; Comments on the Header 
 and the Detail</h4>
        <p data-source-node="n109"> </p>
        <table style="width: 100%" cellspacing="0" width="100%" class="table_1" data-source-node="n110">
            <col style="width: 50%" data-source-node="n111">
            <col style="width: 50%" data-source-node="n112">
            <tr valign="top" data-source-node="n113">
                <td style="width: 50%" width="50%" class="td_8" data-source-node="n114">
                    <h5 data-source-node="n115">Functional Scenario</h5>
                    <p class="p_10" data-source-node="n116">This scenario describes 
 the type of records that you would download in a typical outbound flow. 
 Also, this example includes such complexities as nested containers and 
 comments on the header and the detail. The data map below represents a 
 full order taken from the ERP system, complete with basic customer/shipping 
 data (header), item data (detail), container data, and additional order 
 comments. Downloading this data would result in a completely new shipment 
 being created in SCALE. </p>
                    <p class="p_10" data-source-node="n117"> </p>
                    <p class="p_10" data-source-node="n118">New shipments (orders) 
 can enter the application in several areas. For example, you could have 
 new orders enter into the system with a status of Packing Pending (they would then be available to 
 be packed). Or, you could choose to have them enter into the pool with a status of In Pool (they would then be available 
 to be added to a wave).</p>
                </td>
                <td style="width: 50%" width="50%" class="td_9" data-source-node="n119">
                    <h5 data-source-node="n120">Field Notes</h5>
                    <p data-source-node="n121">- <i data-source-node="n122">Status of New Shipments</i>: 
 When downloading new order headers, the interface system value "Interface 
 Shipment New Status" identifies the status that the system will assign 
 to the new shipment when it enters SCALE. </p>
                    <p data-source-node="n123"> </p>
                    <p data-source-node="n124">- <i data-source-node="n125">Interface Link ID</i>: When interfacing 
 a container with a header/detail, you need to tie the container to the      header using the Interface Link 
 ID value. In the above example, since the container also includes an item 
 quantity, the container must tie back to the detail using the ERP Order 
 Line Number value.</p>
                    <p data-source-node="n126"> </p>
                    <p data-source-node="n127">- <i data-source-node="n128">Parent Link ID</i>: The Parent 
 Link ID value is not used. Do not provide this value.</p>
                    <p data-source-node="n129"> </p>
                    <p data-source-node="n130">- <i data-source-node="n131">Nesting Containers</i>: To nest 
 a child container in a parent container, you need to link the parent's 
 Interface Record ID to the child's Interface Link ID.</p>
                    <p data-source-node="n132"> </p>
                    <p data-source-node="n133">- <i data-source-node="n134">"Contents" Records</i>: 
 For each item quantity inside a container, you need to provide a "contents 
 record," which actually represents the item quantity. In the example 
 below, the line below the "NESTCONT74334" child container is 
 the contents record for that container. If you do not provide this record, 
 the quantity of the container will be 0, even if you provide a Quantity 
 Field value.</p>
                    <p data-source-node="n135"> </p>
                    <p data-source-node="n136">- <i data-source-node="n137">Header Comments</i>: Header comments 
 should be linked to the shipment's Interface Record ID.</p>
                    <p data-source-node="n138"> </p>
                    <p data-source-node="n139">- <i data-source-node="n140">Detail Comments</i>: Detail comments 
 should be linked to the shipment line's Interface Record ID.</p>
                    <p data-source-node="n141"> </p>
                </td>
            </tr>

        <h4 data-source-node="n647"><a name="itemMasterDL" data-source-node="n648"></a>Item Touchpoint - Downloading 
 New Item Master Data</h4>
        <p data-source-node="n649"> </p>
        <table style="width: 100%" cellspacing="0" width="100%" class="table_1" data-source-node="n650">
            <col style="width: 50%" data-source-node="n651">
            <col style="width: 50%" data-source-node="n652">
            <tr valign="top" data-source-node="n653">
                <td style="width: 50%" width="50%" class="td_8" data-source-node="n654">
                    <h5 data-source-node="n655">Functional Scenario</h5>
                    <p class="p_10" data-source-node="n656">SCALE allows you to download 
 item master information from your ERP to the system. This allows you to 
 populate the item master configuration database table, so there is no 
 need to manually define your products in the system.</p>
                    <p class="p_10" data-source-node="n657"> </p>
                    <p class="p_10" data-source-node="n658">For example, suppose that 
 your company added a product to their sales inventory. You would then 
 need to create an item master record for this product in SCALE. While this 
 can be done manually via the Configurations Explorer, you can also download 
 this item master data from your ERP.</p>
                    <p class="p_10" data-source-node="n659"> </p>
                </td>
                <td style="width: 50%" width="50%" class="td_9" data-source-node="n660">
                    <h5 data-source-node="n661">Field Notes</h5>
                    <p data-source-node="n662">- <i data-source-node="n663">Numbered Field Values</i>: The 
 number designation after some of the item values (Weight 1, Quantity UM 
 1, etc) are there to identify the unit of measure definitions for this 
 item (in lieu of creating an item unit of measure record in SCALE). For 
 example, in the above example, each (1) and case (2) unit of measures 
 are being defined for the item. The conversion quantity values determine 
 how many units of an item is in a particular unit of measure (each=1, 
 case=10). The system will take this data and create a record in the Item 
 Unit of Measures Window for this item.</p>
                    <p data-source-node="n664"> </p>
                    <p data-source-node="n665">- <i data-source-node="n666">Restriction</i>: You cannot interface 
 an item in which the Item ID does not match an existing item template 
 in SCALE (an audit will be generated).</p>

        <h4 data-source-node="n757"><a name="itemBalDL" data-source-node="n758"></a>Item Balance Touchpoint - Uploading 
 Item Balance Data</h4>
        <p data-source-node="n759"> </p>
        <table style="width: 50%" cellspacing="0" width="50%" class="table_1" data-source-node="n760">
            <col style="width: 848px" data-source-node="n761">
            <tr valign="top" data-source-node="n762">
                <td class="td_8" data-source-node="n763">
                    <h5 data-source-node="n764">Functional Scenario</h5>
                    <p class="p_10" data-source-node="n765">You can upload item balance 
 information from the system to your ERP. This allows you to reconcile 
 the current item quantities in your warehouse with the ERP's item master 
 table. This is helpful so your ERP has a current and accurate listing 
 of the items in your warehouse and how many are available. In order to 
 gather the item balance data, the system:</p>
                    <p class="p_14" data-source-node="n766"> </p>
                    <p data-source-node="n767">- Groups all location inventory 
 records by warehouse, item, company, and inventory status. </p>
                    <p class="p_15" data-source-node="n768"> </p>
                    <p data-source-node="n769">- Excludes the records that 
 are associated to a location classes that are not defined to be included 
 in item balance uploads.</p>
                    <p class="p_15" data-source-node="n770"> </p>
                    <p data-source-node="n771">- Summarizes the quantity buckets 
 across the remaining records in the group.</p>
                    <p class="p_15" data-source-node="n772"> </p>
                    <p data-source-node="n773">- Checks to see if the Include 
 Zero On Hand Items flag is on. If so, then the system cycles through the 
 item master and adds a record for each item/company that is not yet represented 
 in the upload. </p>
                    <p class="p_15" data-source-node="n774"> </p>
                    <p data-source-node="n775">- Writes the information to 
 the delimited output file.</p>
                    <p data-source-node="n776"> </p>
