
        
        <h1 data-source-node="n56"><a name="kanchor1849" data-source-node="n57"></a>Defining an Item's Units of Measure</h1>
        <p data-source-node="n58">A unit of measure (UM) identifies a storage container used to move product 
 through the warehouse. The system uses this information to calculate how 
 much product can fit in a location based on its UM breakdown. Common examples 
 of UMs include cases, pallets, eaches and innerpacks. When you define 
 a unit of measure (UM), you are providing the system with the following 
 information:</p>
        <ul data-source-node="n59">
            <li data-source-node="n60">
                <p data-source-node="n61">Which UM values are available for each item/item class.</p>
                <p data-source-node="n62"> </p>
            </li>
            <li data-source-node="n63">
                <p data-source-node="n64">How many units a UM can hold, for each item/item class.</p>
                <p data-source-node="n65"> </p>
            </li>
            <li data-source-node="n66">
                <p data-source-node="n67">When a broken UM should be still be treated as this UM.</p>
                <p data-source-node="n68"> </p>
            </li>
            <li data-source-node="n69">
                <p data-source-node="n70">The movement class associated with the UM.</p>
                <p data-source-node="n71"> </p>
            </li>
            <li data-source-node="n72">The dimensions for the UM.<br data-source-node="n73"> </li>
            <li data-source-node="n74">If the UM should be treated as loose in container 
 creation.</li>
        </ul>
        <p data-source-node="n75">When an item does not have item unit of measure data, the system uses 
 the container type dimensions to populate the dimensions of the full case 
 container. If item unit of measure data exists, the system will use those 
 to populate the dimensions. Note that before you can define a unit of measure (UM), you must associate 
 the item with a storage template. If you do not, the system will use the 
 default storage record. Also, the item/company combination for an item 
 unit of measure must exist in the Item Window.</p>

        <h4 data-source-node="n146"><a name="header" data-source-node="n147"></a>Using 
 the Item Unit of Measure Window...</h4>
        <ol data-source-node="n148">
            <li value="1" data-source-node="n149">
                <p data-source-node="n150">Select either the Item Class or 
 the Item Button.</p>
                <p data-source-node="n151"> </p>
            </li>
            <ul type="disc" class="ul_1" data-source-node="n152">
                <li data-source-node="n153">
                    <p data-source-node="n154">To define the UM values for 
 an entire class, select the Item Class Button. The system will 
 activate the Item Class Field. Use this menu to identify the class that 
 you want to create this record for.</p>
                    <p data-source-node="n155"> </p>
                </li>
                <li data-source-node="n156">
                    <p data-source-node="n157">To define the UM values for 
 one item, select the Item Button. The system will activate the 
 Item Field. Select the item that you want to create this record for. Use 
 the Company Field to identify the company associated with this item.</p>
                    <p data-source-node="n158"> </p>
                </li>
            </ul>
            <li value="2" data-source-node="n159">Select the New 
 Action. The system will display the Item Unit of Measure Detail 
 Window. The Item or Item Class value that you defined is defaulted. You 
 will use this window to define the sequences.</li>
        </ol>

        <h4 data-source-node="n162"><a name="detail" data-source-node="n163"></a>Using the Item Unit 
 of Measure Detail Window...</h4>
        <p data-source-node="n164">The header will default the item/item class that you defined on the 
 Item Unit of Measure Window. If you defined a company, it will also be 
 defaulted.</p>
        <p data-source-node="n165"> </p>
        <h5 data-source-node="n166">Note on Record Sequence</h5>
        <p data-source-node="n167"> The system 
 sequences item UM detail records in order from lowest to highest, according 
 to its conversion quantity value. You will be required to configure a 
 conversion quantity of "1" for the lowest unit of measure (for 
 example, an "each").</p>
        <ol data-source-node="n168">
            <li value="1" data-source-node="n169">
                <p data-source-node="n170">Use the UM Field to identify 
 the unit of measure that you want to create.</p>
                <p data-source-node="n171"> </p>
            </li>
            <ul type="disc" class="ul_1" data-source-node="n172">
                <li data-source-node="n173">The first record that you create should be 
 the smallest unit of measure for this item/item class. Generally, the 
 smallest UM equals one saleable unit or one item/item class unit. Common 
 examples include one each, one piece, one unit, etc. Subsequent records 
 will be based on the first, smallest UM.</li>
            </ul>
            <p data-source-node="n174"> </p>
            <li value="2" data-source-node="n175">Use the Conversion 
 Quantity Field to identify how many eaches this UM contains. The 
 system uses this value to perform UM conversions for allocation and replenishments.</li>
            <ul type="disc" class="ul_1" data-source-node="n176">
                <p data-source-node="n177"> </p>
                <li data-source-node="n178">
                    <p data-source-node="n179">This value identifies how many Sequence 1 UMs can fit in subsequent 
 UM values. For example, if you are creating a UM for a casepack and a 
 case holds 50 units, the case's conversion value is 50. Of course, this 
 example assumes that the Sequence 1 UM equals an each, or one unit.</p>
                    <p data-source-node="n180"> </p>
                </li>
                <li data-source-node="n181">
                    <p data-source-node="n182">For the Sequence 1 UM, this value is almost always '1' if you 
 distribute individual units. For subsequent levels, the system converts 
 each UM back to the first UM (Sequence 1).</p>
                    <p data-source-node="n183"> </p>
                </li>
            </ul>
            <li value="3" data-source-node="n184">
                <p data-source-node="n185">Use the Treat As Full Percent Field 
 to indicate the percentage of an item quantity that the system will consider a "full" unit of measure, IF the system is attempting to allocate the complete quantity for a location/license plate. If the quantity is above the defined Treat As Full Percent value, then the system will treat that quantity as the next higher unit of measure (e.g., a case or pallet). <br data-source-node="n186"><br data-source-node="n187">For example, suppose the following:

<br data-source-node="n188">- The "full" quantity for the pallet unit of measure is defined as 100 EA


<br data-source-node="n189">- The Treat as Full Percent setting is defined at 50%


<br data-source-node="n190">- There is a quantity of 80 EA currently at the location <br data-source-node="n191"><br data-source-node="n192">Therefore, an allocation of 80 EA would be considered a "full" pallet allocation. However, an allocation of 79 EA would not.</p>
                <p data-source-node="n193"> </p>
            </li>
            <li value="4" data-source-node="n194">If appropriate, 
 use the Movement Class Field to associate this UM with a movement 
 class. The movement class identifies how quickly this item/item class 
 UM moves through your warehouse.<br data-source-node="n195"> </li>
            <li value="5" data-source-node="n196">Use the Treat 
 As Loose In Container Creation Check box to indicate that this unit 
 of measure should be treated as a "loose" piece. During container 
 creation, the system will check this setting to determine if this particular 
 UM is a full container unit of measure, or if it should be packed as a 
 loose piece.<br data-source-node="n197"> </li>
            <li value="6" data-source-node="n198">
                <p data-source-node="n199">Use the EPC Package ID Field 
 to indicate the unit of measure for an item packaged in a particular container. 
 This value is used when computing an Electronic Product Code (EPC).</p>
                <p data-source-node="n200"> </p>
            </li>
            <li value="7" data-source-node="n201">Use the Dimensions 
 Tab to identify the physical size and weight of the UM. The dimension 
 values identify the height, weight, and length of the UM. The weight value 
 identifies how much the UM weighs. For example, if a case of Item XYZ 
 weighs 50 lbs, its Case UM would equal 50.<br data-source-node="n202"> </li>
            <li value="8" data-source-node="n203">Press OK. 
 The system will add this record. It will not appear on the Detail Records 
 Tab until you select the Refresh List Data Action.</li>
        </ol>

        <h4 data-source-node="n206"><a name="Changing" data-source-node="n207"></a>Changing 
 an Item's Unit of Measures...</h4>
        <p class="p_10" data-source-node="n208">You can change an item unit of measure's 
 dimensions and/or conversion quantity (per item) on the Item Unit of Measure 
 Window. This allows you to account for new container standards, such as 
 a change in case quantity or weight. You can apply these changes to (A) 
 new inventory, or (B) new and 
 existing inventory in your warehouse.</p>
        <p class="p_10" data-source-node="n209"> </p>
        <p data-source-node="n210">Access the Item Unit of Measure Window. Open a unit of measure record.</p>
        <ol data-source-node="n211">
            <li value="1" data-source-node="n212">
                <p data-source-node="n213">Change the item unit of measure's dimensions (length, width, height, 
 weight, or conversion quantity). The system will then display a confirmation 
 message:</p>
                <p data-source-node="n214"> </p>
            </li>
            <ul type="disc" class="ul_1" data-source-node="n215">
                <li data-source-node="n216">Select "Yes" 
 if you want the system to apply the new dimensions to new inventory, 
 but you want the system to leave any existing inventory with its original 
 dimensions. The system write "overrides" for all of the existing 
 inventory so that it will have their previous dimensions. Any new inventory 
 will, by default, use the dimensions specified in this configuration. 
  <br data-source-node="n217"> </li>
                <li data-source-node="n218">Select "No" 
 if you want the system to apply the new dimensions to both new         and 
 existing inventory. In this case, the system will not override any dimensions, 
 which means that everything will use the dimensions specified in the configuration.</li>
            </ul>
            <p data-source-node="n219"> </p>
            <li class="li_3" value="2" data-source-node="n220">Press OK. The 
 system will save your changes.</li>
        </ol>
