
        
        <h1 data-source-node="n56">Cross Docking </h1>
        <p data-source-node="n57">Cross docking enables users to receive and allocate products directly from the receiving dock to the outbound  area without being stored in the warehouse. Cross docking eliminates the inbound putaway and outbound picking process of inventory, which results in the fulfillment operations being completed in reduced time and increased efficiency. </p>

        <h4 data-source-node="n81"><a name="Configuration" data-source-node="n82"></a>Configuration</h4>
        <p data-source-node="n83"> </p>
        <p data-source-node="n84">The following configuration is mandatory for cross-docking. </p>
        <p data-source-node="n85"> </p>
        <p data-source-node="n86"><b data-source-node="n87">Host System</b>: SCALE expects the HOST system to be configured to send the correct information to process cross docking. SCALE validates the following values</p>
        <ul data-source-node="n88">
            <li data-source-node="n89">
                <p data-source-node="n90">Shipment process type </p>
            </li>
            <li data-source-node="n91">
                <p data-source-node="n92"> Cross dock mapping information.</p>
            </li>
        </ul>
        <blockquote data-source-node="n93">
            <p data-source-node="n94"><b data-source-node="n95">Shipment Process Type</b> </p>
            <ul data-source-node="n96">
                <li data-source-node="n97">
                    <p data-source-node="n98"><b data-source-node="n99">Cross Dock Process</b> - The cross dock process type value will be validated by the SCALE from the host system to identify whether the interface is for cross dock or not. When interfacing the shipment with process type as cross dock, the SCALE will check for this configuration, then the shipment will be downloaded with Cross Dock pending status.</p>
                </li>
            </ul>
            <p data-source-node="n100"><b data-source-node="n101">Generic Config Header</b>
            </p>
            <ul data-source-node="n102">
                <li data-source-node="n103">
                    <p data-source-node="n104"><b data-source-node="n105">Cross Dock Mapping</b> – This configuration enables you to define the mapping values for the shipment and receipt line. You need to define the System Defined Values for the Shipment line and Receipt line field values which will be mapped for the cross-dock. This allows the system to validate and match the shipment line and receipt line field values. For example, the User Define field 3 for both shipment and receipt line must be same to process the cross docking. </p>
                </li>
            </ul>
        </blockquote>
        <p data-source-node="n106"> </p>
        <p data-source-node="n107"><b data-source-node="n108">Receiving Preference</b> – Putaway work is required to process cross dock. It is mandatory to select create putaway work.</p>
        <p data-source-node="n109"> </p>
        <p data-source-node="n110"><b data-source-node="n111">Custom Status Flow</b> – Users can optionally configure a custom status flow for dock management. The system will take the default dock management flow If a custom status flow is not defined.</p>
        <p data-source-node="n112"> </p>
        <h4 data-source-node="n113"><a name="Process" data-source-node="n114"></a>Basic Flow </h4>
        <p style="text-align: left" data-source-node="n115"> </p>
        <p style="text-align: left" data-source-node="n116"><b data-source-node="n117">1. Interface Download file to SCALE</b>:  Downloading the Shipment interface file. </p>
        <p data-source-node="n118">The host system will define the shipment process type as a cross dock in the shipment interface file and send it to SCALE for processing. While downloading, the system will validate for the shipment process type to be cross dock and if it matches, then the system successfully processes the shipment record.</p>
        <p data-source-node="n119">The downloaded shipment will be in Cross Dock pending status and the shipment header will have the Cross Dock process type as defined by the host system. Navigate to the Planned Shipment insight screen to view the downloaded shipment.</p>
        <p data-source-node="n120"> </p>
        <p data-source-node="n121"><b data-source-node="n122">2. Create/Download a Receipt</b> </p>
        <p data-source-node="n123">SCALE will now need a receipt to fulfill the Cross-dock shipment order downloaded from the host system. Users can either create or download a receipt. The receipt should have the mapping information sent by the host system with the shipment for Cross Docking. For example, User Defined 5 is set as System Defined Values for the Shipment line and Receipt line field values to match.  it is ready to be processed using the Warehouse Mobile</p>
        <p data-source-node="n124"> </p>
        <p data-source-node="n125"><b data-source-node="n126">3.</b><b data-source-node="n127">Receipt Check-in and locate process – Warehouse Mobile – Receiving</b></p>
        <p data-source-node="n128">Once the receipt is created, it will be processed only through <a href="21b18b42c82e530935c24cb0848bb4d666bef09aa74cbd6ce61dd8b24e457e99.html" data-source-node="n129">Warehouse Mobile – Receiving</a>. </p>
        <ul data-source-node="n130">
            <li data-source-node="n131">
                <p data-source-node="n132">Receiving Preference Configuration:</p>
                <ul data-source-node="n133">
                    <li data-source-node="n134">
                        <p data-source-node="n135"> Mandatory: Select create putaway work</p>
                    </li>
                    <li data-source-node="n136">
                        <p data-source-node="n137">Supported</p>
                        <ul data-source-node="n138">
                            <li data-source-node="n139">
                                <p data-source-node="n140">Check in and locate.</p>
                            </li>
                            <li data-source-node="n141">
                                <p data-source-node="n142">Check in and Locate (immediate)</p>
                            </li>
                        </ul>
                    </li>
                </ul>
            </li>
        </ul>
        <p data-source-node="n143"><b data-source-node="n144">Process Using Warehouse Mobile – Receiving</b>.</p>
        <p data-source-node="n145"> During the Receipt check-in process using warehouse mobile, the system will fetch the Cross Dock mapping value in the receipt line and will automatically identify a matching shipment line. For example, if the User-defined 4 – CRX1 is in the Shipment line and the User Defined 4 – CRX1 is in the Receipt line, the system will look for shipment with the same shipment line field. </p>
        <p data-source-node="n146">On successful check in, the system will locate the receipt containers.</p>
        <p data-source-node="n147"> </p>
        <p data-source-node="n148"><b data-source-node="n149">4. Locating</b>
        </p>
        <p data-source-node="n150">After check in, the locating process will create shipping containers for each receipt containers. The default container type (configured) will be set for these shipping container.</p>
        <p data-source-node="n151">During locating the shipping container will use default dock management flow to identify the <b data-source-node="n152">To location</b>. In case the custom status flow is configured, then dock assignment will happen based on the corresponding dock management flow.</p>
        <p data-source-node="n153">Once locating is successful, the system will update the receipt and shipment header/details</p>
        <p data-source-node="n154"> </p>
        <p data-source-node="n155"><b data-source-node="n156">5.</b><b data-source-node="n157">Cross Dock work Execution</b></p>
        <p data-source-node="n158">Cross Dock work will be executed using the Warehouse Mobile. The system will prompt the user to select the container type during putaway at the shipping dock.</p>
        <p data-source-node="n159"> </p>
        <h4 data-source-node="n160"><a name="Rules" data-source-node="n161"></a>Process Rules </h4>
        <p data-source-node="n162"> </p>
        <p data-source-node="n163">Downloaded shipments </p>
        <ul data-source-node="n164">
            <li data-source-node="n165">
                <p data-source-node="n166">In case the shipment process type does not match, the shipment will be downloaded with In Pool status. These shipments marked with cross dock pending status cannot be processed through a wave.</p>
            </li>
        </ul>
        <p data-source-node="n167"> Warehouse Mobile Receiving - Once the shipment is identified, the system will then validate the following matches the</p>
        <ul data-source-node="n168">
            <li data-source-node="n169">
                <p data-source-node="n170">Shipment and receipt line's item/company/lot.</p>
            </li>
            <li data-source-node="n171">
                <p data-source-node="n172">The shipment header's total quantity must match the receipt header's total quantity.</p>
            </li>
            <li data-source-node="n173">
                <p data-source-node="n174">The shipment line's total quantity must match the receipt line's total quantity.</p>
            </li>
        </ul>
        <p data-source-node="n175">Locating Process </p>
        <ul data-source-node="n176">
            <li data-source-node="n177">
                <p data-source-node="n178">For each receipt container located, the system will create one shipping container. The container type will default the container and the user can choose the container type during putaway.</p>
            </li>
            <li data-source-node="n179">The system will not honor the locating rules configured.</li>
            <li data-source-node="n180">License plate quantity must be less than or equal to the shipment line's quantity, if the quantity is more than the shipment lines quantity locating would fail.</li>
            <li data-source-node="n181">Single receipt cannot fulfill cross dock requests across multiple shipments or vice versa.</li>
            <li data-source-node="n182">Users cannot check in and locate using the Receipt workbench screen to process cross docking.</li>
            <li data-source-node="n183">If locating is un successful , the Process History will log locating failure reason. </li>
            <li data-source-node="n184">After the locating is completed, the system updates the shipment and receipt header details.</li>
        </ul>
        <p data-source-node="n185">Cross Dock Execution</p>
        <ul data-source-node="n186">
            <li data-source-node="n187">
                <p data-source-node="n188">A receipt putaway work will be created for processing a cross dock request.  </p>
            </li>
            <li data-source-node="n189">
                <p data-source-node="n190">Work for Pickup and Drop (P&amp;D) location is supported. </p>
            </li>
            <li data-source-node="n191">
                <p data-source-node="n192">Cross dock work cannot be processed from the Work Insight screen.</p>
            </li>
            <li data-source-node="n193">
                <p data-source-node="n194">Work Profile configuration listed will be ignored by the system even if configured.</p>
                <ul data-source-node="n195">
                    <li data-source-node="n196">
                        <p data-source-node="n197">Putaway into shipping container.</p>
                    </li>
                    <li data-source-node="n198">
                        <p data-source-node="n199">Automatic putaway.</p>
                    </li>
                    <li data-source-node="n200">
                        <p data-source-node="n201">Nest after putaway.</p>
                    </li>
                    <li data-source-node="n202">
                        <p data-source-node="n203">Use cross dock LP id from receiving</p>
                    </li>
                </ul>
            </li>
            <li data-source-node="n204">
                <p data-source-node="n205">Work Special Handling - receipt putaway verify method configuration is also ignored.</p>
            </li>
            <li data-source-node="n206">
                <p data-source-node="n207">Cross docking process will take priority over immediate needs processing if the receipt is eligible for cross docking, and the Item has an open Immediate needs request to be fulfilled.</p>
            </li>
            <li data-source-node="n208">
                <p data-source-node="n209">The system will prevent dock assignment directly to the dock door and fail to locate for cross docking.</p>
            </li>
        </ul>

        <h4 data-source-node="n211"><a name="Label" data-source-node="n212"></a>Label Printing Process</h4>
        <p data-source-node="n213">The receipt, shipping, and vendor label or document can be printed automatically when the check-in and locate process is completed.</p>
        <p data-source-node="n214"> For illustration, the recommended configuration and flow are detailed below:</p>
        <ul data-source-node="n215">
            <li data-source-node="n216">
                <p data-source-node="n217">Navigate to <b data-source-node="n218">Configuration &gt;&gt; Document Type</b>.</p>
            </li>
        </ul>
        <ul data-source-node="n219">
            <li data-source-node="n220">
                <p data-source-node="n221">Double-click on any of the document types to open the Document Type Window. Under General Tab, Print Procedure. Use the Print Procedure Field to identify the type of records the system will generate paperwork. See the Print Procedure Field topic for more information.</p>
                <ul data-source-node="n222">
                    <li data-source-node="n223">
                        <p data-source-node="n224">Vendor/shipping Label – Under Print Procedure, select Shipping Container as default.</p>
                    </li>
                    <li data-source-node="n225">
                        <p data-source-node="n226">Receipt container Label - Under Print Procedure, select Receipt shipping container.</p>
                    </li>
                </ul>
            </li>
        </ul>
        <ul data-source-node="n227">
            <li data-source-node="n228">
                <p data-source-node="n229">When the default check box is selected, the system automatically prints all documents associated with a print procedure.</p>
            </li>
        </ul>
        <ul data-source-node="n230">
            <li data-source-node="n231">
                <p data-source-node="n232">Using warehouse mobile receiving, complete the check-in process. Complete the locate process by Action &gt;&gt; Done. The default document configured will be printed when locating the receipt is  completed.</p>
            </li>
        </ul>
