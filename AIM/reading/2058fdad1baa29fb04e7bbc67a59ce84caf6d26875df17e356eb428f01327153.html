Order/Shipment Touchpoint

The system supports the downloading and uploading of order/line/ container/comment data between your ERP and the application. When orders are downloaded, the interface converts them into SCALE-supported shipment and shipment line(s). These shipments then typically would be placed in the shipment "pool," and thus eligible to be placed on a wave. You can download orders directly from your ERP's database table, or from a previously-generated delimited text file or XML file. Note that you can also choose to create order records in SCALE as well as shipments. These orders are used in viewing web data. Also supported are changes/deletions of parts of shipments, such as lone lines or containers.

 

Additionally, after a shipment has met a certain status, SCALE can also upload this shipment's data back to the ERP. This allows your order system to have accurate data on the progress of a shipment throughout its processing in the warehouse. When a shipment has met a certain status (as configured in the Functional Area Status configuration), SCALE generates an upload record.

 

The order interface (download and upload) processes the following entities:

  • Shipments: These can be interfaced with or without associated details, containers, or comments.
     
  • Shipment Lines: These can be interfaced either as part of a shipment download, or as a lone line (which must be associated with an existing shipment). Read Delimited Interface Tutorial for more information.
     
  • Shipping Containers: These can be interfaced as either separate or nested containers.  If you interface containers, they must be associated with a line (or multiple lines). Generally, you will want to download containers if you are only using SCALE for manifesting, and you are NOT creating containers via system processing.
     
  • Comments: Both shipment and line level comments are supported. These comments must be associated with either an existing shipment or line record.

General Guidelines...

  • After the system converts orders to shipments, the Order Number is included on the shipment record, so it can be tracked through the system. The lines include this number, as well as the Order Line Number, for the same purpose.
     
  • On a shipment line download, an item cannot be validated for both catch weight and a serial number.
     
  • The system can place newly-interfaced order data in several places, which are determined by settings on the Interface System Values Window. You can have each shipment enter or leave the system with a certain status.
     
  • The "Interface Shipment Download Records" interface system value determines what entity the system will create when it downloads orders from the ERP: Shipments or Shipments and Orders. "Shipments" are the outbound entity in SCALE. "Orders" are shipment data that is displayed in the Trading Partner Management module.
     
  • When downloading order details, the interface retrieves the item unit of measure record and applies them to the shipment line (when no unit of measure values are present on the detail itself).

  • Downloading values in the user defined fields of a shipment line overwrites the values defaulted from an item’s master record. If the value in the download file is 0 in User Defined Field 7 or 8, however, the system will retain the item master record's values for these fields.

  • When updating an existing record, if a value is not interfaced for a field, the system treats it as “no change” and retains the existing value.

  • Note that the system temporarily sets shipments to an In Pool Pending (90) status during an interface download to prevent the processing of shipments that are not completely interfaced.

  • For user defined fields 17-20, the time is considered to be UTC. Therefore, if no time is specified, it will be considered to be 00:00:00 UTC. This will be converted to local time when viewing in the application.

  • You can define an interface process record to upload files to a specific directory (the shipments that go to this directory are governed by a filter criteria record).

  • You can define the system to upload shipment data when reaches a certain trailing status (defined in the Functional Area Status configuration).

Rejection Causes / Validations / Notes...

  • The interface will validate (against SCALE configurations) certain values that are downloaded. Use the Table Values Spreadsheet to look up specific values to determine if they are validated.
     
  • The interface will reject a shipment ID if it already exists in the system and the Interface Shipment Allow Duplicate Field contains the value "No."
     
  • When downloading, the interface will reject a shipment ID if it already exists in the system. However, you can configure the application to allow the same shipment ID to exist multiple times. Use the Interface Shipment Allow Duplicate Field (located in the Interface System Values Window) to indicate how the system will handle duplicate shipment ID's:
     
  • The system will not allow you to download a line to a shipment that has already been processed through a wave.
     
  • The system will not allow you to download when you have identical record id for header and details. The record id should be unique for each record downloading.
     
  • The SCALE interface process does not support using a comma as a "seperator" for numeric values. These values will need to be interfaced into the system using decimals as seperators (4.95, not 4,95). The system can, however, display these values with a comma seperator on SCALE windows, but in the database they must be in a decimal format.

  • The system uses the shipment ID/company/warehouse values to determine unique shipments in the system when doing a download in for the new/save/change/delete actions.

  • In order to delete a shipment line, you must also send down a Change or Save record for the associated shipment.

  • Note that you cannot perform multiple actions on a single order/shipment in a single interface download file. For example, you cannot save/create an order/shipment and also delete it in a single XML file (they will need to be two XML files). One for save/create the order/shipment, and the second one for deleting the order/shipment.

  • Note that the shipment upload process updates the interface condition as "processed", marks a batch ID, and leaves records in the upload order tables UNTIL they are archived.
