        <h4 data-source-node="n79"><a name="ORDER" data-source-node="n80"></a>Order/Shipment Touchpoint...</h4>
        <p data-source-node="n81"> </p>
        <table style="width: 100%" cellspacing="0" width="100%" class="table_1" data-source-node="n82">
            <col style="width: 50%" data-source-node="n83">
            <col style="width: 50%" data-source-node="n84">
            <tr valign="top" data-source-node="n85">
                <td colspan="1" rowspan="1" style="width: 50%" width="50%" class="td_8" data-source-node="n86">
                    <h5 data-source-node="n87">New Action</h5>
                    <p class="p_10" data-source-node="n88">- New shipments (orders) 
 can enter the application in several areas. For example, you could have 
 new orders enter into the system with a status of Packing Pending (they would then be available to 
 be packed). Or, you could choose to have them enter into the pool with a status of In Pool (they would then be available 
 to be added to a wave).</p>
                    <p class="p_10" data-source-node="n89"> </p>
                    <p class="p_10" data-source-node="n90">- Suppose your ERP functional 
 flow allows you add order lines to an order after 
 it has been interfaced to SCALE. You then would need to download an individual 
 detail record in New mode. This will result in the new line(s) being assigned 
 to the already-existing order.</p>
                    <p class="p_10" data-source-node="n91"> </p>
                    <p class="p_10" data-source-node="n92"> </p>
                    <h5 data-source-node="n93">Delete / Change Actions</h5>
                    <p data-source-node="n94">- Suppose a customer wanted to delete or change a detail of an order 
 after it has been interfaced 
 into SCALE. You then would need to download the modified header and/or detail 
 data in Delete or Change mode. This will result in the new data being 
 removed (delete action) or assigned (change action) to the already-existing 
 shipment.</p>
                    <p class="p_10" data-source-node="n95"> </p>
                    <p data-source-node="n96">- Suppose a customer canceled part of an order for a certain product, 
 or added another item to an already-ordered shipment. You would then need 
 to modify the order (using the delete or change action) after it had been 
 interfaced to SCALE. Interfacing one of these actions will result in the 
 appropriate line(s) being removed (delete action) or added (change action) 
 to the already-existing order.</p>
                    <p data-source-node="n97"> </p>
                    <p data-source-node="n98"> </p>
                    <h5 data-source-node="n99">Save Actions</h5>
                    <p data-source-node="n100">- When you run an interface Save action, the system will do one of two 
 things, depending on the status of the data in the system:</p>
                    <p data-source-node="n101"> </p>
                    <p data-source-node="n102">- If the data already exists, 
 the system will handle this data record as a Change action.If the data does not exist, 
 the system will handle this as a New action. </p>
                    <p class="p_10" data-source-node="n103"> </p>
                </td>
                <td colspan="1" rowspan="1" style="width: 50%" width="50%" class="td_9" data-source-node="n104">
                    <h5 data-source-node="n105">Field Notes</h5>
                    <p data-source-node="n106">- <i data-source-node="n107">Status of New Shipments</i>: 
 When downloading new order headers, the interface system value "Interface 
 Shipment New Status" identifies the status that the system will assign 
 to the new shipment when it enters SCALE. </p>
                    <p data-source-node="n108"> </p>
                    <p data-source-node="n109">- <i data-source-node="n110">Interface Link ID</i>: When interfacing 
 a container with a header/detail, you need to tie the container to the                             <span class="span_1" data-source-node="n111">shipment</span> using the Interface Link 
 ID value. In the above example, since the container also includes an item 
 quantity, the container must tie back to the detail using the ERP Order 
 Line Number value.</p>
                    <p data-source-node="n112"> </p>
                    <p data-source-node="n113">- <i data-source-node="n114">Parent Link ID</i>: The Parent 
 Link ID value is not used. Do not provide this value.</p>
                    <p data-source-node="n115"> </p>
                    <p data-source-node="n116">- <i data-source-node="n117">Nesting Containers</i>: To nest 
 a child container in a parent container, you need to link the parent's 
 Interface Record ID to the child's Interface Link ID.</p>
                    <p data-source-node="n118"> </p>
                    <p data-source-node="n119">- <i data-source-node="n120">"Contents" Records</i>: 
 For each item quantity inside a container, you need to provide a "contents 
 record," which actually represents the item quantity. If you do not provide this record, 
 the quantity of the container will be 0, even if you provide a Quantity 
 Field value.</p>
                    <p data-source-node="n121"> </p>
                    <p data-source-node="n122">- <i data-source-node="n123">Shipment Comments</i>: Shipment comments 
 should be linked to the shipment's Interface Record ID.</p>
                    <p data-source-node="n124"> </p>
                    <p data-source-node="n125">- <i data-source-node="n126">Shipment Line Comments</i>: Detail comments 
 should be linked to the shipment line's Interface Record ID.</p>
                    <p data-source-node="n127"> </p>
                    <p data-source-node="n128">- <i data-source-node="n129">Downloading Changes to BOM Component 
 Lines</i>: To download a change to a BOM component line, you will need 
 to download three types of records: one (or more) for the component detail(s) 
 that you want to change (use the Interface Link ID to link back to the 
 finished item); one for the finished item detail that the component is 
 a part of (use the Interface Link ID to link to the shipment that 
 contains this finished item); and one for the shipment. This way, 
 the system has a way to link the component to the finished item, and the 
 finished item to the header. You do not have to make changes to the finished 
 item detail or the header, but they must be included in the download. 
 </p>
                </td>
            </tr>

 that is present in a location before a transaction is performed. The "after"

 is performed.</p>

        <h4 data-source-node="n179"><a name="ITEM" data-source-node="n180"></a>Item Touchpoint...</h4>
        <p data-source-node="n181"> </p>
        <table style="width: 100%" cellspacing="0" width="100%" class="table_1" data-source-node="n182">
            <col style="width: 408px" data-source-node="n183">
            <col style="width: 50%" data-source-node="n184">
            <tr valign="top" data-source-node="n185">
                <td class="td_8" data-source-node="n186">
                    <h5 data-source-node="n187">New Action</h5>
                    <p class="p_10" data-source-node="n188">- SCALE allows you to download 
 item master information from your ERP to the system. This allows you to 
 populate the item master configuration database table, so there is no 
 need to manually define your products in the system.</p>
                    <p class="p_10" data-source-node="n189"> </p>
                    <p class="p_10" data-source-node="n190">- For example, suppose that 
 your company added a product to their sales inventory. You would then 
 need to create an item master record for this product in SCALE. While this 
 can be done manually via the Configurations Explorer, you can also download 
 this item master data from your ERP.</p>
                    <p class="p_10" data-source-node="n191"> </p>
                    <p class="p_10" data-source-node="n192"> </p>
                    <h5 data-source-node="n193">Change Action</h5>
                    <p class="p_10" data-source-node="n194">- <span class="span_11" data-source-node="n195">Suppose 
 there has been a change to an item's master record in your ERP. You would 
 then need to download this information, in order to reflect this change 
 in the system's item master table. You can use the interface for this 
 change so there is no need to manually update item master records in SCALE.</span></p>
                    <p class="p_10" data-source-node="n196"> </p>
                    <p class="p_10" data-source-node="n197">- For example, suppose that 
 one of your company's products changed characteristics (item color, dimensions, 
 price, etc). You would then need to modify this product's item master 
 record in SCALE. While this can be done manually via the Configurations 
 Explorer, you can also download this modified item master data from your 
 ERP.</p>
                </td>
                <td class="td_9" data-source-node="n198">
                    <h5 data-source-node="n199">Field Notes</h5>
                    <p data-source-node="n200">- <i data-source-node="n201">Numbered Field Values</i>: The 
 number designation after some of the item values (Weight 1, Quantity UM 
 1, etc) are there to identify the unit of measure definitions for this 
 item (in lieu of creating an item unit of measure record in SCALE). For 
 example, in the above example, each (1) and case (2) unit of measures 
 are being defined for the item. The conversion quantity values determine 
 how many units of an item is in a particular unit of measure (each=1, 
 case=10). The system will take this data and create a record in the Item 
 Unit of Measures Window for this item.</p>
                    <p data-source-node="n202"> </p>
                    <p data-source-node="n203">- <i data-source-node="n204">Restriction</i>: You cannot interface 
 an item in which the Item ID does not match an existing item template 
 in SCALE (an audit will be generated).</p>
                    <p data-source-node="n205"> </p>
                    <p data-source-node="n206">- <i data-source-node="n207">For item master change actions</i>, 
 you only need to download values for the fields that you want to change. The exception is if you want to make unit of measure changes, 
 because you will need to identify on which unit of measure you want to 
 make the change on (in the above example, each UM). The system will make 
 the appropriate changes on the item records and/or item unit of measure 
 records.</p>
                    <p data-source-node="n208"> </p>
                    <p data-source-node="n209">- <i data-source-node="n210">Deleting item cross reference / unit of measure records</i>: You can download a delete of an item cross reference record or item unit of measure that exists for a specified item. Keep in mind the following:</p>
                    <blockquote data-source-node="n211">
                        <p data-source-node="n212">* You can download a delete of a single sequence for a valid item unit of measure, but not a base unit of measure.</p>
                        <p data-source-node="n213"> </p>
                        <p data-source-node="n214">* You can download a delete of all sequences for an existing item unit of measure record.</p>
                        <p data-source-node="n215"> </p>
                        <p data-source-node="n216">* The system will error if you attempt to download a delete of base unit of measure sequence, when higher sequences exist for the unit of measure.</p>
                        <p data-source-node="n217"> </p>
                        <p data-source-node="n218">* If you perform a delete item download, the system will delete the associated item cross reference and/or item unit of measure even if those elements are not included in the download XML record.</p>
                    </blockquote>

        <h4 data-source-node="n292"><a name="ITEMBALANCE" data-source-node="n293"></a>Item Balance Touchpoint...</h4>
        <p data-source-node="n294"> </p>
        <table style="width: 50%" cellspacing="0" width="50%" class="table_1" data-source-node="n295">
            <col style="width: 100%" data-source-node="n296">
            <tr valign="top" data-source-node="n297">
                <td style="width: 100%" width="100%" class="td_8" data-source-node="n298">
                    <h5 data-source-node="n299">Upload</h5>
                    <p class="p_10" data-source-node="n300">- You can upload item balance 
 information from the system to your ERP. This allows you to reconcile 
 the current item quantities in your warehouse with the ERP's item master 
 table. This is helpful so your ERP has a current and accurate listing 
 of the items in your warehouse and how many are available. In order to 
 gather the item balance data, the system:</p>
                    <p class="p_14" data-source-node="n301"> </p>
                    <p data-source-node="n302">- Groups all location inventory 
 records by warehouse, item, company, and inventory status. </p>
                    <p class="p_15" data-source-node="n303"> </p>
                    <p data-source-node="n304">- Excludes the records that 
 are associated to a location classes that are not defined to be included 
 in item balance uploads.</p>
                    <p class="p_15" data-source-node="n305"> </p>
                    <p data-source-node="n306">- Summarizes the quantity buckets 
 across the remaining records in the group.</p>
                    <p class="p_15" data-source-node="n307"> </p>
                    <p data-source-node="n308">- Checks to see if the Include 
 Zero On Hand Items flag is on. If so, then the system cycles through the 
 item master and adds a record for each item/company that is not yet represented 
 in the upload. </p>
                    <p class="p_15" data-source-node="n309"> </p>
                    <p data-source-node="n310">- Writes the information to 
 the delimited output file.</p>
                </td>

        <h4 data-source-node="n314"><a name="WORK" data-source-node="n315"></a>Work Order Touchpoint...</h4>
        <p data-source-node="n316"> </p>
        <table style="width: 100%" cellspacing="0" width="100%" class="table_1" data-source-node="n317">
            <col style="width: 50%" data-source-node="n318">
            <col style="width: 50%" data-source-node="n319">
            <tr valign="top" data-source-node="n320">
                <td style="width: 50%" width="50%" class="td_8" data-source-node="n321">
                    <h5 data-source-node="n322">New Action</h5>
                    <p class="p_10" data-source-node="n323">- A work order is a process by which you take one or more component items and make a different finished item out of them. SCALE allows you to download a work order and all of its components. Or, the download could contain just a work order header. In this case, the components would be determined by looking up the Bill of Materials for the finished item on the work order and creating the component items in the work order detail based on that.</p>
                    <p class="p_10" data-source-node="n324"> </p>
                    <h5 data-source-node="n325">Save Action</h5>
                    <p class="p_10" data-source-node="n326">- Instead of using 'New' or 'Change' as the action for the interface, it uses 'Save'. This writes the work order if it doesn't exist and updates the existing work order if it does exist.</p>
                    <p class="p_10" data-source-node="n327"> </p>
                    <p class="p_10" data-source-node="n328"> </p>
                    <h5 data-source-node="n329">Delete/Change Actions</h5>
                    <p class="p_10" data-source-node="n330">- Changes and deletions are allowed to an existing work order in the system. For example, a change could happen if an additional component line is added to the existing work order. However, if the quantity to be built on the work order changes, the system will automatically change the components to match. </p>
                    <p class="p_10" data-source-node="n331"> </p>
                    <p class="p_10" data-source-node="n332">- A deletion could occur if there is a deletion to a component line on the work order. Or, it could be delete the entire work order from the database.</p>
                    <p class="p_10" data-source-node="n333"> </p>
                    <p class="p_10" data-source-node="n334"> </p>
                    <h5 data-source-node="n335">Upload</h5>
                    <p class="p_10" data-source-node="n336">- During the inventory transactions upload process the results of the quantity of components used and the quantity of finished items created is sent to the host system. The 'Reference ID' and the 'Reference Type' on these records are used to link the transactions back to a work order on the host system. This insures that the inventory in the host system is in sync with the inventory in SCALE. It also allows the host system to perform any updates it might need to do in its own work order process. SCALE uses inventory adjustments to subtract the components and add finished items when a work order is completed. The <a href="adc0e535ed3b02667599d992fd1d12fd01c139d85fa991a10bb5a058f3dcdc9c.html" data-source-node="n337">Work Order System Values</a> configuration stores the adjustment types used when confirming a work order.</p>
                </td>
                <td style="width: 50%" width="50%" class="td_9" data-source-node="n338">
                    <h5 data-source-node="n339">Field Notes</h5>
                    <p data-source-node="n340">- <i data-source-node="n341">Work Order ID</i> : This field must be unique across the entire system.</p>
                    <p data-source-node="n342"> </p>
                    <p data-source-node="n343">- <i data-source-node="n344">Item/Company</i>: 	Item and Company are fields that work together.  The system standard for looking up an Item in the Item configuration is to first look for the specific Item and Company combination.  If that is not found, then look for the Item with a blank (or NULL) company.  Either one or the other combination should exist, but not both. When looking up an Item/Company in the Bill of Materials configuration, it always looks for the highest numbered Revision Number for that Item/Company. </p>
                    <p data-source-node="n345"> </p>
                    <p data-source-node="n346"> </p>
                    <p data-source-node="n347"> </p>
                    <p data-source-node="n348"> </p>
                    <p data-source-node="n349"> </p>
                </td>
            </tr>

        <h4 data-source-node="n353"><a name="BOM" data-source-node="n354"></a>Bill of Materials Touchpoint...</h4>
        <p data-source-node="n355"> </p>
        <table style="width: 100%" cellspacing="0" width="100%" class="table_1" data-source-node="n356">
            <col style="width: 50%" data-source-node="n357">
            <col style="width: 50%" data-source-node="n358">
            <tr valign="top" data-source-node="n359">
                <td style="width: 50%" width="50%" class="td_8" data-source-node="n360">
                    <h5 data-source-node="n361">New Action</h5>
                    <p class="p_10" data-source-node="n362">- A bill of materials is a listing of the component items and quantities of those items needed to create a finished item through a work order. SCALE allows you to download a finished item and its components, along with the quantity needed to make up the finished item.</p>
                    <p class="p_10" data-source-node="n363"> </p>
                    <h5 data-source-node="n364">Save Action</h5>
                    <p class="p_10" data-source-node="n365">- Instead of using 'New' or 'Change' as the action for the interface, it uses 'Save'. This writes the bill of materials if it doesn't exist and updates the existing bill of materials if it does exist.</p>
                    <p class="p_10" data-source-node="n366">  </p>
                    <p class="p_10" data-source-node="n367"> </p>
                    <h5 data-source-node="n368">Delete/Change Action</h5>
                    <p class="p_10" data-source-node="n369">- Changes and deletions are allowed to an existing bill of materials in the system. For example, a change could happen if an additional item is added to the existing bill of materials. </p>
                    <p class="p_10" data-source-node="n370"> </p>
                    <p class="p_10" data-source-node="n371">- A deletion could occur if there is a deletion to a an existing bill of materials from the database.</p>
                </td>
                <td style="width: 50%" width="50%" class="td_9" data-source-node="n372">
                    <h5 data-source-node="n373">Field Notes</h5>
                    <p data-source-node="n374">- <i data-source-node="n375">Item/Company</i>: 	Item and Company are fields that work together.  The system standard for looking up an Item in the Item configuration is to first look for the specific Item and Company combination.  If that is not found, then look for the Item with a blank (or NULL) company.  Either one or the other combination should exist, but not both. When looking up an Item/Company in the Bill of Materials configuration, it always looks for the highest numbered Revision Number for that Item/Company. </p>
                    <p data-source-node="n376"> </p>
                    <p data-source-node="n377">- <i data-source-node="n378">Build Location</i>: If filled, the location must have a Location Class of 'Work Order Build'.</p>
                    <p data-source-node="n379"> </p>
                    <p data-source-node="n380">- <i data-source-node="n381">Increase Quantity Type</i>: If the Increase Quantity Eligible field is Y, this field must be filled with A (for Amount) or P (for Percentage)</p>
                    <p data-source-node="n382"> </p>
                    <p data-source-node="n383">- <i data-source-node="n384">Increase Quantity Amount</i>: If the Increase Quantity Eligible field is Y, this field must be greater than 0.

If the Increase Quantity Type field is P, this field must be less than or equal to 100.</p>
                    <p data-source-node="n385"> </p>
                </td>
