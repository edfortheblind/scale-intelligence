
        
        <h1 data-source-node="n56"><a name="kanchor441" data-source-node="n57"></a>Identifying Rating Profiles</h1>
        <p data-source-node="n58">The system uses the rating profile record to estimate how many theoretical containers are associated with a shipment with shipment lines and no shipping containers. When rating is run during a wave, shipping containers have not been created yet. Since parcel carriers rate at the container level, the system must estimate how many containers are on a shipment. It uses the estimated theoretical container weight and/or volume values to estimate how many containers are on a shipment when the Rate at Shipment Level flag from the carrier's Rating ID is unchecked.  For example, if a shipment line weighs 100 pounds and the estimated container weight is set at 25 pounds, the system will estimate that there are 4 containers for this shipment line. By estimating the number of containers required, the system can better determine shipping costs.</p>
        <p data-source-node="n59"> </p>
        <p data-source-node="n60">If the "Rate at Shipment Level" setting is checked for the carrier's Rating ID, then the system creates theoretical containers based on the shipment line's LTL class.  For example, if a shipment line weighs 100 pounds and there is a single shipment line on the shipment, then system will estimate there is a single container for 100 pounds.  If there are two shipment lines with different LTL classes, then the system will estimate there are two containers.  Once container for each LTL class.  The container weight will be the sum of the shipment line weights for all lines of the same LTL class.  If there are two shipment lines with the same LTL class, then the system will estimate there is one container and with the weight of the two shipment lines.</p>
        <p align="left" class="p_38" data-source-node="n61"> </p>
        <p align="left" data-source-node="n62">NOTE: If there is a remainder from the first example's calculation, that remainder always equals one container. For example, if the shipment weighs 110 pounds, and the estimated container weight is set at 25 pounds, the system will estimate that there are 4 containers weighing 25 pounds and 1 container weighing 10 pounds.</p>

        <h4 data-source-node="n98">Procedures...</h4>
        <ol data-source-node="n99">
            <li value="1" data-source-node="n100">
                <p data-source-node="n101">Use Profile Name Field to 
 identify this record.</p>
                <p data-source-node="n102"> </p>
            </li>
            <li value="2" data-source-node="n103">
                <p data-source-node="n104">Use the Theoretical Container Weight 
 Field to identify the usual weight per container. Use the corresponding 
 UM Field to 
 identify the unit of measure. This value is not required. If you use the 
 value 0, the system will not use container weight in its calculation.</p>
                <p data-source-node="n105"> </p>
            </li>
            <li value="3" data-source-node="n106">
                <p data-source-node="n107">Use the Theoretical Container Volume 
 Field to identify the usual volume per container. Use the corresponding 
 UM Field to identify the unit of measure. This value is not required. 
 If you use the value 0, the system will not use container volume in its 
 calculation.</p>
                <p data-source-node="n108"> </p>
            </li>
            <li value="4" data-source-node="n109">Use the Re-Rate 
 at Ship Confirmation Checkbox if you want containers associated 
 with this profile rated again during ship confirmation. If the carrier or service is set to system calculated freight charges and there are freight charges already associated with the shipment, this check box will determine whether the system will re-rate the shipment.  For parcel carriers rating at the container level, this would involve remanifesting the containers.  If  the carrier or service is set to system calculated freight charges and there are no freight charges associated with the shipment, the shipment will be rated during ship confirm regardless of this setting.<br data-source-node="n110"><br data-source-node="n111"></li>
            <li value="5" data-source-node="n112">Use the Change 
 Manifest Date At Ship Confirm Checkbox to indicate that you want 
 the system to remanifest a container for the ship confirmation date:<br data-source-node="n113"><br data-source-node="n114">	- If this checkbox is selected, 
 the system will remanifest a container for a different date.<br data-source-node="n115"><br data-source-node="n116">	- If this checkbox is not selected, 
 a container will keep the date it was originally manifested for. For example, 
 if you ship confirm after midnight, you would not want to change the date 
 on all the containers that really left the date before (i.e. before midnight).</li>
        </ol>

        <h4 data-source-node="n118">More On Using the Theoretical Weight &amp; Volume Choices...</h4>
        <p data-source-node="n119">Generally, you will use only one of the theoretical values, not both. 
 The Theoretical Container Weight value is usually selected for items shipped 
 based on weight, such as dense, compact products. The Theoretical Container 
 Volume value is generally selected for items shipped based on volume, 
 such as lightweight, larger products. If you want to apply both a theoretical 
 weight and a theoretical volume, the system will first determine how many 
 containers are created if the volume value is applied. It will then calculate 
 how many containers are created if the weight value is applied. It will 
 apply the value that generates the fewest number of containers.</p>
