About License Keys

A license key allows you to legally run specific application module(s) on a certain database environment. These keys are used to restrict access to certain modules of the application. For example, if you only purchase rights to use the WM Full Feature of the system, your particular license key will restrict you from using advanced features of SCALE. When you purchase SCALE, you will be provided with a .licx file that contains the permanent license key.  In order to receive this license key, you will need to provide Manhattan with server information for each environment running SCALE (only a Manhattan representative has the authorization to create and distribute license keys).

 

The license is of Named User type. This type of license allows only a certain number of active users to be configured in the application at one time. Each user that signs onto the system must be part of the license, and you cannot "share" user spots like a concurrent user license allows.

 

During installation, the system will ask you to verify that an .licx file exists. Browse to the directory which should contain the license key file (ILS\<current version>\Server\). Note that if for some reason you do not have a license key, you can just leave this field blank and press Next. The installer will generate a temporary, all-access key that will get the application up and running. Since the temporary license key will only be valid for a limited number of days, you will need to work with Manhattan support to acquire a permanent license key. If you receive a permanent license key (post-installation of the application) you will need to rename or delete the DefaultLicenseKey.licx file and save the permanent license key in its place.  The license key file location can be found in the .config file (which is located in the “Common” sub-folder, under SCALE folder). Note that there can be only one .licx file at a time.

 

License keys are assigned by Manhattan per environment that runs part/all of the application. For example, you could have four servers (3 application servers and a database server), spread over two warehouses, and you would need three license keys (one for each application server). Note that machines used in a test environment will need a separate license key as well.

License Key Notes...

  • A new license key is required to upgrade to release version 2020 and later releases.

  • The system generates warehouse alerts when a license key error occurs (e.g. your key expires, a wrong license is used, etc.)

  • The system uses a service (the ILS Security Service) to communicate license key data between server(s).

 

Activating Inactive Users...

When using a named user license, you can reactivate "inactive" users. This allows you to enable users that have been inactivated for such things as seasonal employment or extended time off. Note that you can control whether or not users have access to this ability using the "Activate User Profile" checkpoint on the User Profile security form (this checkpoint is shipped as enabled for new installations). Depending on the number of users on your license, the system may not let you reactivate the user IF you would exceed the allowed number of users by activating a new one.

  1. Open the inactive user's User Profile record.

  2. Deselect the Inactive Checkbox.

  3. Press the OK button. The system will activate the user.

System Information Required for Manhattan Active SCALE (SaaS) license.

 

For new or renewal of license, the customer needs to provide the following

  • File name - The file name should be same as tenant name attribute for the server where the license is deployed.
  • Tenant Name - A tenant name will be used by an organization to manage specific instances inside the organization. Each customer will have multiple tenant names.

For example, the customer and tenant name is XYZ. A license key is generated with XYZProd as the file name. The tenant names added to the license key are XYZProd, XYZStage, and XYZQA. The XYZ license key will be deployed on the production server that has a tenant with the name XYZProd. The same license key is deployed on the stage server with renamed as XYZStage. The same is repeated for the QA server.

 

Burst/Ramp Licensing

 

Burst license is an increase in number of users to support additional seasonal workers during peak season/time of the year. Ramp license is an increase in number of users to accommodate additional workers the client expects to add as business increases.

 

License key warning warehouse alerts are written as follows

  • Once per day starting 15 days before the current date range ends.
  • On the first day of a new date range, when the user count increases.
  • On the first day user profiles have been deactivated.
Deactivation of user profiles
  • Once the burst date range ends, the system needs to deactivate the user profiles to get back to the number as specified before the burst license was activated. The system deactivates recently updated user profiles based on the date time stamp.

  • In the case the required number of user profiles have been deactivated prior to the burst end date, then the system will not deactivate any user profiles.

  • In situations where the client has deactivated some, but not all required user profiles before the burst end date, then the system will deactivate only the number of user profiles required to meet the user count for the new date range.
