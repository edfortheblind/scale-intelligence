
        
        <h1 style="text-align: left;font-size: 12pt" data-source-node="n56"><span style="font-size: 18pt" data-source-node="n57">Interface Configuration</span>
        </h1>
        <h4 data-source-node="n58">Overview</h4>
        <p data-source-node="n59">Each functional area has its own process settings for the interface, 
 which determines how its data can be downloaded and/or uploaded between 
 SCALE and the ERP. You may need to address these settings when configuring 
 the SCALE interface to work with your ERP's data. The following topic outlines 
 how you can review/edit these process records to meet your business needs. When you open a functional area record in the Interface Process Window, 
 the system will display a series of detail records in a list. These detail 
 records indicate the different processes that have been defined for this 
 particular functional area. The sequence of these records determine in 
 what order the system will execute them. You can create/edit/delete process 
 detail records according to your business needs.</p>
        <p data-source-node="n60"> </p>
        <h4 data-source-node="n61">Configure Interface Process</h4>
        <p data-source-node="n62"> </p>
        <p data-source-node="n63"> </p>
        <p data-source-node="n64"><b data-source-node="n65">Interface Sequence Information</b>
        </p>
        <p data-source-node="n66"> </p>
        <ol class="ol_1" data-source-node="n67">
            <li value="1" data-source-node="n68">Use the Interface 
 Mode Field to indicate what method this process will interface 
 data into the application: by using a delimited text file (fixed length 
 or not), directly from the interface tables, or via XML files. See the           <a href="178aec6d3faf8830199512924f58cf463d20acfbc6b6485c40a0948c32a1cd0e.html" data-source-node="n69">Interface Overview</a> 
 topic for detailed mode descriptions.<br data-source-node="n70"> </li>
            <li value="2" data-source-node="n71">Use the Max Trans 
 Per XML File Field to indicate the maximum number of data entities 
 (header-detail-container combinations) that the interface will convert 
 into XML at a time. <br data-source-node="n72"><br data-source-node="n73">Take, for example, a shipping delimited download. Suppose this value 
 is set at 200 and there are 600 entities ready to be processed. The interface 
 will convert 200 of these entities to XML and place them into the appropriate 
 SCALE database table. The system then will go out and retrieve the next 
 200 records and repeat the process, until all eligible data has been converted.<br data-source-node="n74"> </li>
            <li value="3" data-source-node="n75">Use the Data 
 Source Batch Size Field to indicate the maximum number of interface 
 data sources (files, or rows in a database table) that the interface will 
 retrieve at a time.<br data-source-node="n76"><br data-source-node="n77">Delimited 
 Mode...<br data-source-node="n78">Take, for example, a shipping delimited download. Suppose this 
 value is set at 100, and there are 500 delimited files ready to be processed. 
 The interface will retrieve the first 100 files (no matter how much data 
 is contained in each file), and begin processing them. Next, the system 
 then will go out and grab the next 100 files, repeating the process until 
 all eligible files have been processed.<br data-source-node="n79"><br data-source-node="n80">Regarding record processing order, the system will process them first 
 according to logical priority (i.e. shipments then shipment lines, 
 receipts then receipt lines, etc.), and within those tables it 
 processes by Interface Record ID. For example (Interface Record ID in 
 parenthesis):<br data-source-node="n81"><br data-source-node="n82">(1) Receipt Detail A1<br data-source-node="n83">(2) Receipt Header B<br data-source-node="n84">(3) Receipt Detail A3<br data-source-node="n85">(4) Receipt Detail A2<br data-source-node="n86">(5) Receipt Detail B1<br data-source-node="n87">(6) Receipt Header A<br data-source-node="n88"><br data-source-node="n89">The system will process these records in this order:<br data-source-node="n90">Receipt Header B<br data-source-node="n91">Receipt Header A<br data-source-node="n92">Receipt Detail A1<br data-source-node="n93">Receipt Detail A3<br data-source-node="n94">Receipt Detail A2<br data-source-node="n95">Receipt Detail B1<br data-source-node="n96"><br data-source-node="n97">Direct 
 Mode...<br data-source-node="n98">For direct downloads, the interface will act as described above, 
 except that it would grab the first 100 data rows from the database table, 
 and process them. When direct downloading items, receipts, or orders, 
 the system will process each batch's rows according to their interface 
 record ID value. <br data-source-node="n99"> </li>
            <li value="4" data-source-node="n100">Use the Upload Criteria Field to filter the  records to be uploaded for the upload process detail. Refer <a href="6fd3e460eb8997c2d0dc3c56b5f2a479d443827328a8044d426de3a9c14f2689.html" data-source-node="n101">Upload Criteria Field</a> for more details.<br data-source-node="n102"><br data-source-node="n103"></li>
            <li value="5" data-source-node="n104">Use the Upload Delete Criteria Field (shipment upload only) to indicate the filter criteria record that the system will use to determine for which shipments the system will write header/detail upload records when a shipment is deleted.<br data-source-node="n105"><br data-source-node="n106"></li>
            <li value="6" data-source-node="n107">Use the Upload Directory Field to define the directory where the system will place interface upload data files. This can allow you to configure uploads going to multiple directories (by creating multiple interface process records, each defined with a different upload filter criteria and upload directory).<br data-source-node="n108"><br data-source-node="n109"></li>
            <li value="7" data-source-node="n110">Use the Process 
 Field to determine if this interface process will download data 
 from your ERP to SCALE, or upload system data to your ERP.<br data-source-node="n111"> </li>
            <li value="8" data-source-node="n112">Use the XML Encoding 
 Field to indicate  the type of text encoding that you want the system to use when interfacing data files. If you are reading/writing a file (in delimited, fixed length, or XML mode), this field defines the format of the file itself. Note that interface error files also honor this encoding setting.<br data-source-node="n113"> </li>
            <li value="9" data-source-node="n114">Use the File 
 Extension Field to indicate to the system what files this process 
 should be looking for when interfacing delimited/XML data. These delimited/XML 
 files reside in the directory that is defined in the Interface System 
 Values Window.<br data-source-node="n115"> </li>
            <li value="10" data-source-node="n116">Use the Error 
 File Extension Field to indicate the extension that the system 
 should place on the error files it automatically generates if a problem 
 occurs when interfacing data.<br data-source-node="n117"> </li>
            <li value="11" data-source-node="n118">Use the Processed 
 File Extension Field to indicate the extension that the system 
 will add to files that have been processed by the interface. <br data-source-node="n119"> </li>
            <li value="12" data-source-node="n120">Use the Save 
 Processed Data toggle if you want the system to not delete interfaced 
 data:<br data-source-node="n121"><br data-source-node="n122">- In Direct Mode: The system 
 will leave the data in the database, and label it as processed.<br data-source-node="n123"><br data-source-node="n124">- In File-Based Modes: The 
 system will add a user-defined file extension to processed data files. 
 The system will not delete these files from their output directory. <br data-source-node="n125"></li>
        </ol>

        <p data-source-node="n127"><b data-source-node="n128">Flow Control</b>
        </p>
        <p data-source-node="n129"> </p>
        <p data-source-node="n130">Use the Interface Process Steps section to define what actions you 
 want the system to execute before and/or after the interface is run (such 
 as performing XML data translation or running exit point programs). <br data-source-node="n131"><br data-source-node="n132"></p>
        <p data-source-node="n133">          Description - provides 
 a name for this process step.<br data-source-node="n134"><br data-source-node="n135"></p>
        <p data-source-node="n136">           Sequence - I  indicates 
 in what order the system will execute this process step.<br data-source-node="n137"><br data-source-node="n138"></p>
        <p data-source-node="n139">          Timing - Indicates if you want this process step to run its custom code before 
 or after the system has run the interface.<br data-source-node="n140"><br data-source-node="n141"></p>
        <p data-source-node="n142">          Action Type - Indicates what action you want this interface process step to execute. 
 Select "XSL Transform" if you want the system to take SCALE data 
 and perform a custom translation, using a specific XSL style sheet (specified 
 in the Process Field). Note that any XSL transforms configured in the 
 Interface Process Window will be ignored when processing error files. 
 <br data-source-node="n143"><br data-source-node="n144"></p>
        <p data-source-node="n145">          Process - 
 identifies the specific XSL style sheet that the 
 system will execute when this process step is run.</p>
