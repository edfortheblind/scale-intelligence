
        
        <h1 data-source-node="n56"><a name="kanchor876" data-source-node="n57"></a>Creating Label Masters</h1>
        <p data-source-node="n58">A label master record manages the process of printing the labels from 
 a wave. The following labels are governed by these records: shipping labels, 
 vendor labels, and container contents labels. Label masters are useful 
 because they allow you to define how/when these labels will be generated 
 and printed. There are two additional label criteria windows that can be used to help filter the labels that are generated.</p>
        <ul data-source-node="n59">
            <li data-source-node="n60">Label Master Criteria - You use this window to define which shipments the system will generate 
 labels for by creating label master criteria filter rules. Labels can 
 be printed in the wave by using wave flow that includes the "Paperwork-Labels" 
 wave step.<br data-source-node="n61"><br data-source-node="n62"></li>
            <li data-source-node="n63">Label Selection Criteria - You can use this window  to determine the eligible containers for which you want labels. Labels can be generated by specific document types, which eliminates the need to create unnecessary document routing records for unwanted labels.</li>
        </ul>
        <p data-source-node="n64"> </p>
        <h5 data-source-node="n65">Notes</h5>
        <ul data-source-node="n66">
            <li data-source-node="n67">You must run a wave using a wave 
 master that has the appropriate label master and wave flow associated 
 with it. Otherwise, the system will use the wave master in the warehouse 
 with the highest priority (which may not be associated with your label 
 master).</li>
        </ul>
        <ul data-source-node="n68">
            <li data-source-node="n69">If a label master does not have a label 
 master criteria configured, or has one with no "order by" rules, 
 the system will collate the labels sent to a specific print device by 
 document type. For example, if 
 printing shipping labels and vendor labels, every shipping label will 
 print first, followed by every vendor label. To collate labels by container, you need to use a system-created 
 label master criteria record named "Collate By Container." This 
 record is set up with trivial criteria and a single "order by" 
 rule of      Shipping_Container.INTERNAL_CONTAINER_NUM, 
 which will properly collate by container. Note that this field must be 
 used in the "ordering of" other label master criteria records 
 if container collation is desired. Keep in mind that the system-created 
 "*Default" label master will use this "Collate by Container" 
 label master criteria record.</li>
        </ul>
        <ul data-source-node="n70">
            <li data-source-node="n71">Wave label processing (using label masters) 
 does not honor the Number of Copies 
 value found on the Document Routing Window. You can  work 
 around this by adding creating multiple Label Master Document Type records. 
 Please note, however, that this will incur extra processing, as the label 
 will be generated multiple times.  Also, 
 this does not work for all document types (such as FedEx Shipping Labels). <br data-source-node="n72"><br data-source-node="n73"></li>
            <li data-source-node="n74">Wave label processing does not generate labels for child containers when the "Print for Nested Containers" is selected on a label's Document Window record.<br data-source-node="n75"><br data-source-node="n76"></li>
            <li data-source-node="n77">When adding filter criteria, the Label Generation Process uses the following steps:<br data-source-node="n78"><br data-source-node="n79">1. Label master criteria<br data-source-node="n80"><br data-source-node="n81">2. Label selection criteria<br data-source-node="n82"><br data-source-node="n83">3. Document routing<br data-source-node="n84"><br data-source-node="n85">4. Sort and possibly set break labels:<br data-source-node="n86"><br data-source-node="n87">- Print device<br data-source-node="n88">- Order by label master criteria<br data-source-node="n89">- Document type<br data-source-node="n90"><br data-source-node="n91"></li>
            <li data-source-node="n92">When printing shipping labels in the wave, manifesting takes place after the containers have been selected for printing.  Therefore, the fields that get updated during manifesting are not valid for selection when configuring the label master.  These fields are as follows:<br data-source-node="n93"><br data-source-node="n94">Accessorial Charge<br data-source-node="n95">Base Freight Charge<br data-source-node="n96">Bundle ID<br data-source-node="n97">Date/Time Stamp<br data-source-node="n98">Freight Discount<br data-source-node="n99">Manifest Carrier Service Symbol<br data-source-node="n100">Manifest Date<br data-source-node="n101">Manifest For Date<br data-source-node="n102">Manifest State<br data-source-node="n103">MSN<br data-source-node="n104">Process Stamp<br data-source-node="n105">Returns Accessorial Charge<br data-source-node="n106">Returns Base Freight Charge<br data-source-node="n107">Returns Calltag Fee<br data-source-node="n108">Returns Freight Discount<br data-source-node="n109">Returns MSN<br data-source-node="n110">Returns Print Label<br data-source-node="n111">Returns Tracking Number<br data-source-node="n112">Returns Total Freight Charge<br data-source-node="n113">Tracking Number<br data-source-node="n114">Total Freight Charge<br data-source-node="n115">World Ease ID<br data-source-node="n116">World Ease Group Status</li>
        </ul>

        <h4 data-source-node="n223"><a name="labelMastCriteria" data-source-node="n224"></a>Creating Label Master Criteria Records...</h4>
        <p data-source-node="n225">Access the Label Master Criteria Window. The system uses the records 
 created on this window to determine the shipment(s) in a wave that will 
 require a certain label to be printed. You can also activate break labels 
 on the Order By Tab. These are used as a separator between a group of 
 labels for a wave's shipments. For instance, suppose your wave has two 
 shipments, and the system would need to generate three labels for each 
 shipment. If activated, a break label would then print in between the 
 two shipments' group of labels. The break label template provided with 
 SCALE displays the Shipment ID and Container ID fields as samples to aid 
 your customization efforts.</p>
        <ul type="disc" class="ul_1" data-source-node="n226">
            <li data-source-node="n227">Select the Create 
 Break Label Check box to indicate that you want the system to print 
 a break label. <br data-source-node="n228"> </li>
            <li data-source-node="n229">Use the Break 
 Label Template Field to indicate a template that you want the system 
 to use when generating break labels.</li>
        </ul>
        <p data-source-node="n230"> </p>
        <p data-source-node="n231"> </p>
        <h4 data-source-node="n232"><a name="labelSelection" data-source-node="n233"></a>Creating Label Selection Criteria Records...</h4>
        <p data-source-node="n234">Access the Label Selection Criteria Window. The system uses the records created in this window to determine which container labels to print. You can use this window to define a specific document type. By using the Label Master Criteria and Label Selection Criteria Windows together, you can eliminates the need to create unnecessary document routing records. This configuration filters using the shipping container and shipment header view tables. The system will error if a container is selected and no document routing records exist. </p>
        <p data-source-node="n235"> </p>
        <h5 data-source-node="n236">Example: Using Label Master Criteria and Label Selection Criteria</h5>
        <blockquote data-source-node="n237">
            <p data-source-node="n238">Desired Labels: Vendor labels for all containers and Container Contents for PL only</p>
            <ul data-source-node="n239">
                <li data-source-node="n240">10 containers in wave<br data-source-node="n241"><br data-source-node="n242"><ul data-source-node="n243"><li data-source-node="n244">5 PL<br data-source-node="n245"><br data-source-node="n246"></li><li data-source-node="n247">5 CS</li></ul></li>
            </ul>
            <ul data-source-node="n248">
                <li data-source-node="n249">2 Document Type Records Configured: Container Contents, Vendor Labels</li>
            </ul>
            <p data-source-node="n250">Label Master Criteria Configured: defined so ALL containers are eligible ('container_num' is not null )<br data-source-node="n251"><br data-source-node="n252"></p>
            <p data-source-node="n253">Label Master Selection Criteria Configured: PL containers are only chosen (Shipping_container type = PL)</p>
            <p data-source-node="n254"> </p>
            <p data-source-node="n255">In this example, the system will only create container and vendor labels for the 5 PL containers.</p>
        </blockquote>

        <h4 data-source-node="n258"><a name="labelMasters" data-source-node="n259"></a>Creating Label Masters...</h4>
        <p data-source-node="n260">Access the Label Master Window.</p>
        <ol class="ol_1" data-source-node="n261">
            <li value="1" data-source-node="n262">Use the Label 
 Master Field to provide a name for your master record. Also provide 
 a description.<br data-source-node="n263"> </li>
            <li value="2" data-source-node="n264">Use the Data 
 Selection Field to select a label master criteria record, which 
 determines the shipment(s) in a wave that will require this label to be 
 printed. These records are defined on the Label Master Criteria Window.<br data-source-node="n265"> </li>
            <li value="3" data-source-node="n266">Use the Print 
 Mode Field to determine when in the wave process you want these 
 labels to generate/print:<br data-source-node="n267"><br data-source-node="n268">- Print During Wave: The system 
 will generate and print the label files when executing the "Paperwork-Labels" 
 wave step.<br data-source-node="n269"><br data-source-node="n270">- Print At Release: The system 
 will generate and print the label files after a wave has been released 
 (manual release only).<br data-source-node="n271"><br data-source-node="n272">- Manual: The system will 
 generate the label files during the wave process, but will not print them. 
 The user then can manually print these labels using the "Reprint 
 Labels" option on the Wave Insight screen. This option is useful if 
 you do not want the user to wait for the system to generate the labels 
 when manually reprinting them (they will have already been generated via 
 the wave).<br data-source-node="n273"> </li>
            <li value="4" data-source-node="n274">Use the Document 
 Type Field to choose the label that you want to print during the 
 wave.<br data-source-node="n275"> </li>
            <li value="5" data-source-node="n276">Use the Generating 
 Class Field to indicate if you are printing a vendor label or shipping 
 label.<br data-source-node="n277"><br data-source-node="n278"></li>
            <li value="6" data-source-node="n279">Use the Label Selection Criteria Field to indicate the which containers are eligible for label printing.<br data-source-node="n280"><br data-source-node="n281"></li>
            <li value="7" data-source-node="n282">If necessary, 
 press the Add Button to create an additional detail to this master 
 record.<br data-source-node="n283"> </li>
            <li value="8" data-source-node="n284">Press OK when 
 finished. The system will save your record.</li>
        </ol>
