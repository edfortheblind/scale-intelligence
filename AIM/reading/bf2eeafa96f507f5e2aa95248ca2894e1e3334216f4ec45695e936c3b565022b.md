
        
        <h1 style="text-align: left;font-size: 12pt" data-source-node="n57"><a name="kanchor1707" data-source-node="n58"></a>Work Type</h1>
        <p data-source-node="n59">A work type is a specific category within a broader work group, defined by its processing characteristics or operational needs. For example, batch picking is a type of work that falls under the general picking work group. In this case, the work type "batch picking" identifies all picking tasks that are best handled in batch mode.</p>
        <p data-source-node="n60">The system includes several predefined work types, such as batch picking and order picking. However, you can also create custom work types tailored to your business processes. These custom types can later be used to define processing rules through the Work Profile configuration.</p>
        <p data-source-node="n61"> </p>
        <p data-source-node="n62">Create work Type</p>
        <ul data-source-node="n63">
            <li data-source-node="n64">
                <p data-source-node="n65">Work Type- Enter a unique name for your new work type.</p>
            </li>
        </ul>
        <ul data-source-node="n66">
            <li data-source-node="n67">
                <p data-source-node="n68">Description- Provide a brief description of the work type.</p>
                <p data-source-node="n69">Note: For Vocollect processing, this description acts as a numeric identifier used in voice communication.</p>
            </li>
        </ul>
        <ul data-source-node="n70">
            <li data-source-node="n71">
                <p data-source-node="n72">Labor Type - Specify the type of labor management record that should be generated for this work type.</p>
            </li>
        </ul>
        <ul data-source-node="n73">
            <li data-source-node="n74">
                <p data-source-node="n75">Labor Group - Select a group of users who perform similar functions related to this work type.</p>
            </li>
        </ul>
        <ul data-source-node="n76">
            <li data-source-node="n77">
                <p data-source-node="n78">Transaction Count Description - Define the label for a custom field that appears on the Manual Labor Entry Screen. This label will be paired with a numeric input field.</p>
                <p data-source-node="n79">For instance, if you create a work type called Sweeping Floors, and set the Transaction Count Description to Aisles Swept, the janitor can then log how many aisles were cleaned during a given time period.</p>
            </li>
        </ul>
        <ul data-source-node="n80">
            <li data-source-node="n81">

            </li>
        </ul>
        <ul data-source-node="n83">
            <li data-source-node="n84">
                <p data-source-node="n85">Default Priority - Set a priority level for tasks associated with this work type.</p>
                <ul data-source-node="n86">
                    <li data-source-node="n87">
                        <p data-source-node="n88">A user’s Work Profile includes a From Assignment setting, which controls how tasks are sorted. If this setting includes a priority-based sort (e.g., Priority/Location/FIFO), the system will use the priority defined here.</p>
                    </li>
                    <li data-source-node="n89">
                        <p data-source-node="n90">Note: Priority values are only applied when work is assigned through system-directed mode using an RF device. Manual (full-screen) task assignment does not support priority-based sorting.</p>
                    </li>
                </ul>
            </li>
        </ul>
        <ul data-source-node="n91">
            <li data-source-node="n92">
                <p data-source-node="n93">Pick Management Active - select toggle button to make the work type available in Picking Management windows.</p>
                <p data-source-node="n94">To be eligible for display in these configurations, both this toggle and the From Work Zone field in the work instruction must be defined.</p>
            </li>
        </ul>
        <p data-source-node="n95"> </p>
        <p data-source-node="n96"><b data-source-node="n97">Authorized Work Types</b>
        </p>
        <p data-source-node="n98"> Select the work types that set the which work instructions will be processed using this sequence.</p>
        <p data-source-node="n99"> </p>
        <p data-source-node="n100"><b data-source-node="n101">Work Initiation Method</b>
        </p>
        <p data-source-node="n102">Work Initiation Method to indicate how the work will be assigned to the user.</p>
        <ul data-source-node="n103">
            <li data-source-node="n104">
                <p data-source-node="n105">User initiated: The user selects which work he/she will process. </p>
            </li>
            <li data-source-node="n106">
                <p data-source-node="n107">Cart Picking: User picks product into containers/totes assigned to a cart. </p>
            </li>
        </ul>
        <p data-source-node="n108"><b data-source-node="n109">Container Picking Method</b>
        </p>
        <p data-source-node="n110">These settings are used to determine whether or not you are picking product into a shipping container or tote.</p>
        <ul data-source-node="n111">
            <li data-source-node="n112">
                <p data-source-node="n113">Pick Into Shipping Container - Users will be able to directly pick into the final shipping container.</p>
            </li>
        </ul>
        <ul data-source-node="n114">
            <li data-source-node="n115">
                <p data-source-node="n116">Pick into tote - Users will be able to directly pick into a tote (transport container). Also, users can pick multiple shipment lines going to different putaway locations into a single tote.</p>
            </li>
        </ul>
        <ul data-source-node="n117">
            <li data-source-node="n118">
                <p data-source-node="n119">Sort Picked quantity - This option is enabled only when Pick to Tote is selected. This is selected for Putwall sorting operation.</p>
            </li>
        </ul>
        <p style="font-weight: bold" data-source-node="n120">Assignment Methods</p>
        <p data-source-node="n121"> </p>
        <p data-source-node="n122"><b data-source-node="n123">From Assign Method </b>
        </p>
        <p data-source-node="n124"> </p>
        <p data-source-node="n125">This determines how the system will assign work units using system-directed work initiation.</p>
        <p data-source-node="n126"> </p>
        <p data-source-node="n127">Priority/Location/FIFO - The system assigns work based on priority: the lower the priority number, the higher the urgency. This way, the most important customers are handled first.</p>
        <ul data-source-node="n128">
            <li data-source-node="n129">
                <p data-source-node="n130">If the multiple pick instructions share the same priority, the system will assign the instructions in location order: the location closest to the user is assigned first.</p>
            </li>
            <li data-source-node="n131">
                <p data-source-node="n132">If multiple pick instructions share the same priority and location, the system will assign the instructions in FIFO. The first instruction generated during work creation is assigned first.This can minimize travel time.</p>
            </li>
        </ul>
        <p data-source-node="n133">Location/Priority/FIFO- Work is assigned based in location proximity order: the location closest to the user is assigned first. This minimizes travel time.</p>
        <p data-source-node="n134">Note: the system only recognizes number proximity in ascending order. In other words, if location 999-999-999 is physically next to 001-001-001, the system cannot recognize the distance between the locations.</p>
        <ul data-source-node="n135">
            <li data-source-node="n136">
                <p data-source-node="n137">If multiple pick instructions share the same location, the system will assign the instructions in priority order: the lower the priority number, the sooner the instruction is assigned.</p>
            </li>
            <li data-source-node="n138">
                <p data-source-node="n139">If multiple pick instructions share the same location and priority, the system will assign the instruction in FIFO order. The first instruction generated during work creation is assigned first.</p>
            </li>
        </ul>
        <p data-source-node="n140">First In, First Out (FIFO) -All work is assigned in the First In, First Out order. The first instruction generated during work creation is assigned first.</p>
        <p data-source-node="n141"> </p>
        <p data-source-node="n142"><b data-source-node="n143">To Assign Method</b>
        </p>
        <p data-source-node="n144">This determines how the system will assign putaway work instructions using system-directed work initiation.</p>
        <p data-source-node="n145"> </p>
        <ul data-source-node="n146">
            <li data-source-node="n147">
                <p data-source-node="n148">LIFO - All putaways are assigned in the Last In, First Out order, which means the last item picked is the first item put away.</p>
            </li>
        </ul>
        <ul data-source-node="n149">
            <li data-source-node="n150">
                <p data-source-node="n151">Location - All putaways are assigned in location proximity order: the putaway location closest to the user is assigned first. This is commonly used if you are processing product in a bin or other unorganized structure.</p>
            </li>
        </ul>
        <p data-source-node="n152"><b data-source-node="n153">Picking Options</b>
        </p>
        <p data-source-node="n154">The following settings determine various behaviors during picking</p>
        <ul data-source-node="n155">
            <li data-source-node="n156">
                <p data-source-node="n157">Default LP id as container ID on full picks - This option is used to indicate that you want the system to default the location's license plate ID (from which you are picking quantity from) as the container ID of the shipping container that you are picking the quantity into. Note that you can enter a different container ID as well, this license plate ID is only defaulted into the field (its use is not mandatory).</p>
            </li>
        </ul>
        <ul data-source-node="n158">
            <li data-source-node="n159">
                <p data-source-node="n160">Group picks by loc/LP- This checkbox is used in Warehouse Mobile picking, to indicate that if a work unit has multiple picks for the same item at the same location, you want the system to group this into one pick. Click to <a href="a135e84ab3c5b8787101fff98db8dbfbe973a45f2898b9de92cce65a33d31068.html" data-source-node="n161">read more</a>. if you are using the Cart Picking initiation method, the system always attempts to group picks.</p>
            </li>
        </ul>
        <ul data-source-node="n162">
            <li data-source-node="n163">
                <p data-source-node="n164">Print at WM Work Start - Indicate that you want the system to print shipping container label(s) when you begin to execute work units via Warehouse Mobile. Note that the system will only print shipping container labels that have the "Start WM Work" print procedure checked on the document type record. Also, the system will only print in this manner if you are executing work that was created from shipping containers.</p>
            </li>
        </ul>
        <p data-source-node="n165"><b data-source-node="n166">Putaway Options</b>
        </p>
        <p data-source-node="n167">The following settings determine various behaviors during putaway.</p>
        <ul data-source-node="n168">
            <li data-source-node="n169">
                <p data-source-node="n170">Putaway into Shipping Container - This option indicates that you want the user to place product directly into shipping containers during the WM putaway process. Using this option, the system will either create a new shipping container, or add the item to an existing shipping container (whichever is appropriate).</p>
            </li>
        </ul>
        <ul data-source-node="n171">
            <li data-source-node="n172">
                <p data-source-node="n173">Automatic Putaway - This option is used to indicate that you want the system to automatically putaway items during the work execution process. This would bypass having to manually putaway each item on a shipment. Typically, this setting would be used when you are picking directly into shipping containers (but you can use it in any work scenario, except dock management work, where it is not supported).</p>
            </li>
        </ul>
        <ul data-source-node="n174">
            <li data-source-node="n175">
                <p data-source-node="n176">Consolidation after putaway - This option identifies if you want to invoke the consolidation putaway process after performing a work putaway action on an Warehouse Mobile. Note that if the Automatic Putaway setting is selected, the Consolidation After Putaway setting will not be available to select.</p>
            </li>
        </ul>
        <ul data-source-node="n177">
            <li data-source-node="n178">
                <p data-source-node="n179">Nest After Putaway - This option is used in Warehouse Mobile group picking, when you are picking into a final shipping container (only when the work unit is for a single shipment). If you check this checkbox, the system will display a nesting WM screen after you have putaway your shipping containers. If you specify a container, the picked containers are then nested under it. This allows you to do is pick into shipping containers, and then place those shipping containers on a pallet for shipping. Note that the nest after putaway functionality is not supported when performing putaway to shipping container.</p>
                <p data-source-node="n180"> </p>
                <p data-source-node="n181">Also note that if receipt containers/license plates for these items were created during a wave, the system will group these as well. Suppose that 3 cases are ordered. During the wave, the system allocates the cases from the same location, and the system creates 3 full-case receipt containers/license plates. When a user performs the work via Warehouse Mobile, they will have to verify and confirm only one time for all 3 cases combined.</p>
            </li>
        </ul>
        <ul data-source-node="n182">
            <li data-source-node="n183">
                <p data-source-node="n184">Use Cross dock LP id from Receiving - This option indicates whether you want the system to use the license plate from receiving as the container ID when creating a new shipping container on the shipping dock. If this setting is not selected, then the user will have to manually enter a container ID in this situation. Note that this is an optional setting that is only available if you have enabled the Putaway Into Shipping Container option. Note that this functionality cannot be used if there was already a shipping container created for the shipment line during the wave or WM picking.</p>
            </li>
        </ul>
        <ul data-source-node="n185">
            <li data-source-node="n186">
                <p data-source-node="n187">Group putaway by shipping container - This setting indicates that you want the system to group putaway instructions by shipping container, when there are multiple putaway locations associated with multiple containers on the work unit. <a href="24b19cc7309a1872fd65fed79338b4054b7c8f4ff208b164f91fa2cd6d6eaa44.html" data-source-node="n188">Read More</a></p>
            </li>
        </ul>
