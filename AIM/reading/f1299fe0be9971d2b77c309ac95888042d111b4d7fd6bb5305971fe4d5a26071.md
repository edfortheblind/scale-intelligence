
        
        <h1 data-source-node="n56"><a name="kanchor117" data-source-node="n57"></a>Establishing Customers</h1>
        <p data-source-node="n58">A customer record allows you to identify a client that you ship product 
 to on a regular basis. The system supports parent and child customer records. 
 This allows you to share specific field values, such as the email address, 
 between multiple records. This is especially useful if you service large 
 corporations which require you to ship product to multiple sites, but 
 to send all bills to one, corporate office. Also, if you use multi-company 
 processing, you can establish customer records for each company. This 
 ensures that the client base for each company is recognized by the system.</p>
        <p data-source-node="n59"> </p>
        <h5 data-source-node="n60">Parent Records, Child Records, &amp; Inheritance</h5>
        <p data-source-node="n61">Usually, the parent record represents the corporate or billing address 
 associated with this customer. A child record represents the actual ship-to 
 addresses where product will be delivered. For example, chains such as 
 Wal-Mart probably have a corporate office, distribution centers and individual 
 stores. You deliver product to the distribution centers; the corporate 
 office handles freight bills. In this case, the corporate address is represented 
 by the parent record, since it only manages paperwork, not product. Each 
 distribution center will need its own child record. They can inherit shared 
 values, such as the address where freight bills should be sent. Since 
 you don't deliver product to the individual stores, you will not create 
 records for them. The system will only allow you inherit values if the 
 value in the Customer Field and the Company Field match the values on 
 a parent record. A parent record has the Parent Checkbox selected. Company 
 is included in this match since more than one company might use the same 
 customer ID number.</p>

        <h4 data-source-node="n187"><a name="parent" data-source-node="n188"></a>Defining a Parent Customer Record... </h4>
        <p data-source-node="n189"> </p>
        <h5 data-source-node="n190">Using the Header Fields</h5>
        <ol data-source-node="n191">
            <li value="1" data-source-node="n192">
                <p data-source-node="n193">Use the Customer ID Field 
 to provide the customer's number. </p>
                <p data-source-node="n194"> </p>
            </li>
            <li value="2" data-source-node="n195">Do not provide 
 a value in the Ship To Field since this is a parent record. This 
 field identifies an address that receives product from your warehouse. 
 If this customer only needs one record (does not have multiple ship to 
 addresses), provide a value here.<br data-source-node="n196"> </li>
            <li value="3" data-source-node="n197">
                <p data-source-node="n198">Use the Company Field to 
 identify the company that services this customer. If you use multi-company 
 processing, you will want to identify the company who services this customer. 
 This will ensure that each company's customer base is maintained. This 
 is especially helpful if duplicate customer numbers exist.</p>
                <p data-source-node="n199"> </p>
            </li>
            <li value="4" data-source-node="n200">Select the Parent 
 Checkbox. Generally, a parent record identifies the corporate office 
 or the billing office. The parent record can share values with its child 
 records. This minimizes setup time and ensures that and decreases the 
 likelihood of typos. Note that if you only ship to one address for this 
 customer, it will not require children records. You don't need to select 
 this checkbox.</li>
        </ol>
        <p data-source-node="n201"> </p>
        <h5 data-source-node="n202">Using the Address Tab</h5>
        <p data-source-node="n203">Use the Address Tab fields to define this customer's address and contact 
 information.</p>
        <ol data-source-node="n204">
            <li value="1" data-source-node="n205">
                <p data-source-node="n206">Use the Address Tab fields 
 to provide the customer's ship-to address. You can also identify the contact 
 name, his/her email address, phone number and fax number.</p>
                <p data-source-node="n207"> </p>
            </li>
            <li value="2" data-source-node="n208">Select the Residential 
 Checkbox if this customer's shipments are delivered to a personal 
 address, not a company address. Do not select this checkbox if the shipments 
 are delivered to a company, or corporate address. As a rule, you will 
 not select this checkbox because customer records are generally not created 
 for private residences.</li>
        </ol>
        <p data-source-node="n209"> </p>
        <h5 data-source-node="n210">Using the General Tab</h5>
        <p data-source-node="n211">Use the General Tab Fields to define basic carrier and order entry information.</p>
        <ol data-source-node="n212">
            <li value="1" data-source-node="n213">
                <p data-source-node="n214">Use the Carrier and Carrier Service 
 Fields to indicate how this customer normally ships their product.</p>
                <p data-source-node="n215"> </p>
            </li>
            <li value="2" data-source-node="n216">Use the On Hold 
 For Order Entry Checkbox to exclude a customer from having orders 
 placed for them. If this checkbox is checked, you will not be able to 
 place orders for this customer on the Order Entry Window. This is helpful 
 if you have a customer who is delinquent in payment, and wish to stop 
 processing orders for them until this due payment is received.</li>
        </ol>
        <p data-source-node="n217"> </p>
        <h5 data-source-node="n218">Using 
 the Categories Tab</h5>
        <p data-source-node="n219">These fields are not required. You only need to define these fields 
 if you want to associate category(s) to the customer record.</p>
        <ol data-source-node="n220">
            <li value="1" data-source-node="n221">Use the Category 
 Tab Fields to choose a category to associate to a customer. See 
 the topic          <a href="81c3121ebe6b148a3d285b36f42793fb2766057a3321d098d3fc7ee665cdfed3.html" data-source-node="n222">Customer Category 1-10 Fields</a> 
 for more information on these values.</li>
        </ol>
        <p data-source-node="n223"> </p>
        <h5 data-source-node="n224">Using the Freight Bill To 
 Address Tab</h5>
        <p data-source-node="n225">These fields are not required. You only need to define these fields 
 if the customer wants freight bills sent to a different address.</p>
        <ol data-source-node="n226">
            <li value="1" data-source-node="n227">Use the Freight 
 Bill to Address Tab fields to provide the bill-to address. You 
 can also identify the contact name, his/her email address, phone number 
 and fax number.</li>
        </ol>
        <p data-source-node="n228"> </p>
        <p data-source-node="n229"> </p>
        <h4 data-source-node="n230"><a name="child" data-source-node="n231"></a>Defining a Child Customer Record...</h4>
        <p data-source-node="n232">After you define the parcel customer record, you can create the parent's 
 child records. These records identify a specific address that you transport 
 product to.</p>
        <p data-source-node="n233"> </p>
        <h5 data-source-node="n234">Using the Header Fields</h5>
        <ol data-source-node="n235">
            <li value="1" data-source-node="n236">
                <p data-source-node="n237">In the Customer &amp; Company Fields, 
 provide the same values that you provided in the parent record's customer 
 and company fields. These values must be exactly the same (as the values 
 defined on the parent record).</p>
                <p data-source-node="n238"> </p>
            </li>
            <li value="2" data-source-node="n239">
                <p data-source-node="n240">In the Ship To Field, identify 
 the store that receives product and is also associated with the parent 
 record. The value in this field, along with the values in the customer 
 and company fields, will identify this record to the system.</p>
                <p data-source-node="n241"> </p>
            </li>
            <li value="3" data-source-node="n242">As soon as you have defined the values in these three fields (and 
 exited them), the system will recognize that you are creating a child 
 record. It will disable the Parent Checkbox and display the Inherited 
 Checkbox on each field that it can obtain a value from the parent record.</li>
        </ol>
        <p data-source-node="n243"> </p>
        <h5 data-source-node="n244">Using the Inherited Checkboxes</h5>
        <ul data-source-node="n245">
            <li data-source-node="n246">The system automatically selects the Inherited Checkbox for you, 
 when the value is defined on the parent record. If the field on the child 
 record should be different than the value defined on the parent record, 
 deselect the Inheritance Checkbox. The system will automatically clear 
 the field for you. 
	
	<p data-source-node="n247">NOTE: Remember that if 
 this child record's bills should be sent to the parent record, you must 
 identify that billing address on the Freight Bill To Address Tab. This 
 usually occurs when a corporate office receives all bills for its stores.</p></li>
        </ul>
        <p class="p_15" data-source-node="n248">After this record is created: The child record can be 
 a Ship To name and address on a shipment record. This is the customer 
 that you are shipping product to. Please note that if you had provided 
 a Ship To value on the parent record, that record could also be used as 
 the Ship To name and address on a shipment record.</p>

        <h4 data-source-node="n252"><a name="EDI" data-source-node="n253"></a>Indicating a Customer's Carrier EDI Reference Fields...</h4>
        <p data-source-node="n254"> On the Carrier EDI Reference configuration window, you can define what SCALE values (mapped to certain Symbol values) that the system will pass to the transportation system. However, you can use the checkboxes that are present on the Customer Window's Carrier EDI Reference Window to indicate, for a particular customer, whether or not these values are inherited, or select a different SCALE mapped field. You can access this window from the Actions Menu of the Customer Window. For more information on Carrier EDI Reference, see <a href="a55a1c0fcb8365cd1d52320bf809af154c9426905211128f778a468124034b26.html" data-source-node="n255">this topic.</a></p>
