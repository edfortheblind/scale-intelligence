                <td colspan="1" rowspan="1" class="td_15" data-source-node="n76">
                    <p data-source-node="n77">This setting determines whether buffering is active during scans for all Warehouse Mobile transactions.</p>
                    <p data-source-node="n78"> </p>
                    <p data-source-node="n79">If set to Yes, scan buffering is enabled, allowing users to buffer the scans during Warehouse Mobile transactions, with the system maintaining a queue of scanned records. The maximum number of scans that can be held in the queue is configured using the "Buffer Queue Size" value. For instance, if the buffer queue size is set to 5, scanning will be disabled when there are 5 records in the queue. Once the number of queued records decreases, scanning is re-enabled. Additionally, if a user encounters an error during a scan, all the unprocessed records in the queue will be cleared, requiring a rescan.</p>
                    <p data-source-node="n80"> </p>
                    <p data-source-node="n81">If set to No, buffering is deactivated for scanning in Warehouse Mobile. By default, the value is set to No.</p>

Users can configure this duration for a maximum of up to 5000 milliseconds. If a user enters a value exceeding 5000, such as 8000, the system will display the success message for 5000 milliseconds only. If the value is set to zero, the success message won't be displayed on the screen. The default value is set to 3000 milliseconds.</p>
