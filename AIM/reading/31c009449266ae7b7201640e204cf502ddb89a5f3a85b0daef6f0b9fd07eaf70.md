
        
        <h1 data-source-node="n56"><a name="kanchor1312" data-source-node="n57"></a>Defining Interface Process Records</h1>
        <p class="p_35" style="font-style: italic" data-source-node="n58">*** Interface process records are required 
 for all interface modes. ***</p>
        <p data-source-node="n59"> </p>
        <p data-source-node="n60">Each functional area has its own process settings for the interface, 
 which determines how its data can be downloaded and/or uploaded between 
 SCALE and the ERP. You may need to address these settings when configuring 
 the SCALE interface to work with your ERP's data. The following topic outlines 
 how you can review/edit these process records to meet your business needs. When you open a functional area record in the Interface Process Window, 
 the system will display a series of detail records in a list. These detail 
 records indicate the different processes that have been defined for this 
 particular functional area. The sequence of these records determine in 
 what order the system will execute them. You can create/edit/delete process 
 detail records according to your business needs.</p>
        <p data-source-node="n61"> </p>

        <h4 data-source-node="n135">Procedures (Header Window)...</h4>
        <p data-source-node="n136">Access the Interface Process Window. Open the functional area record 
 for which you want to review. The system will display a list of the current 
 process detail(s). Right-click on the list and select Open. Note that Work Order and Bill of Material interface records are only available in XML mode.</p>
        <p data-source-node="n137"> </p>
        <h5 data-source-node="n138">Using the Header Fields</h5>
        <ol class="ol_1" data-source-node="n139">
            <li value="1" data-source-node="n140">Use the Sequence 
 Field to indicate in what order you want the system to execute 
 this interface process. For example, suppose you assign a sequence of 
 "10" to a delimited download process record, and "20" 
 to a direct download process record. When you run the interface, the system 
 will first look to download any delimited files that are present in the 
 specified directory. If it finds some, it will interface them into the 
 application. If it finds none (or when it is finished), the system will 
 try to perform a direct download of the data. <br data-source-node="n141"> </li>
            <li value="2" data-source-node="n142">Use the Description 
 Field to provide a text description for your process detail record.</li>
        </ol>
        <p data-source-node="n143"> </p>
        <h4 data-source-node="n144">Procedures (Detail Window)...</h4>
        <p data-source-node="n145"> </p>
        <h5 data-source-node="n146">Using the General Tab</h5>
        <ol class="ol_1" data-source-node="n147">
            <li value="1" data-source-node="n148">Use the Interface 
 Mode Field to indicate what method this process will interface 
 data into the application: by using a delimited text file (fixed length 
 or not), directly from the interface tables, or via XML files. See the           <a href="178aec6d3faf8830199512924f58cf463d20acfbc6b6485c40a0948c32a1cd0e.html" data-source-node="n149">Interface Overview</a> 
 topic for detailed mode descriptions.<br data-source-node="n150"> </li>
            <li value="2" data-source-node="n151">Use the Max Trans 
 Per XML File Field to indicate the maximum number of data entities 
 (header-detail-container combinations) that the interface will convert 
 into XML at a time. <br data-source-node="n152"><br data-source-node="n153">Take, for example, a shipping delimited download. Suppose this value 
 is set at 200 and there are 600 entities ready to be processed. The interface 
 will convert 200 of these entities to XML and place them into the appropriate 
 SCALE database table. The system then will go out and retrieve the next 
 200 records and repeat the process, until all eligible data has been converted.<br data-source-node="n154"> </li>
            <li value="3" data-source-node="n155">Use the Data 
 Source Batch Size Field to indicate the maximum number of interface 
 data sources (files, or rows in a database table) that the interface will 
 retrieve at a time.<br data-source-node="n156"><br data-source-node="n157">Delimited 
 Mode...<br data-source-node="n158">Take, for example, a shipping delimited download. Suppose this 
 value is set at 100, and there are 500 delimited files ready to be processed. 
 The interface will retrieve the first 100 files (no matter how much data 
 is contained in each file), and begin processing them. Next, the system 
 then will go out and grab the next 100 files, repeating the process until 
 all eligible files have been processed.<br data-source-node="n159"><br data-source-node="n160">Regarding record processing order, the system will process them first 
 according to logical priority (i.e. shipments then shipment lines, 
 receipts then receipt lines, etc.), and within those tables it 
 processes by Interface Record ID. For example (Interface Record ID in 
 parenthesis):<br data-source-node="n161"><br data-source-node="n162">(1) Receipt Detail A1<br data-source-node="n163">(2) Receipt Header B<br data-source-node="n164">(3) Receipt Detail A3<br data-source-node="n165">(4) Receipt Detail A2<br data-source-node="n166">(5) Receipt Detail B1<br data-source-node="n167">(6) Receipt Header A<br data-source-node="n168"><br data-source-node="n169">The system will process these records in this order:<br data-source-node="n170">Receipt Header B<br data-source-node="n171">Receipt Header A<br data-source-node="n172">Receipt Detail A1<br data-source-node="n173">Receipt Detail A3<br data-source-node="n174">Receipt Detail A2<br data-source-node="n175">Receipt Detail B1<br data-source-node="n176"><br data-source-node="n177">Direct 
 Mode...<br data-source-node="n178">For direct downloads, the interface will act as described above, 
 except that it would grab the first 100 data rows from the database table, 
 and process them. When direct downloading items, receipts, or orders, 
 the system will process each batch's rows according to their interface 
 record ID value. <br data-source-node="n179"> </li>
            <li value="4" data-source-node="n180">Use the Upload Criteria Field to filter the  records to be uploaded for the upload process detail. Refer <a href="6fd3e460eb8997c2d0dc3c56b5f2a479d443827328a8044d426de3a9c14f2689.html" data-source-node="n181">Upload Criteria Field</a> for more details.<br data-source-node="n182"><br data-source-node="n183"></li>
            <li value="5" data-source-node="n184">Use the Upload Delete Criteria Field (shipment upload only) to indicate the filter criteria record that the system will use to determine for which shipments the system will write header/detail upload records when a shipment is deleted.<br data-source-node="n185"><br data-source-node="n186"></li>
            <li value="6" data-source-node="n187">Use the Upload Directory Field to define the directory where the system will place interface upload data files. This can allow you to configure uploads going to multiple directories (by creating multiple interface process records, each defined with a different upload filter criteria and upload directory).<br data-source-node="n188"><br data-source-node="n189"></li>
            <li value="7" data-source-node="n190">Use the Process 
 Field to determine if this interface process will download data 
 from your ERP to SCALE, or upload system data to your ERP.<br data-source-node="n191"> </li>
            <li value="8" data-source-node="n192">Use the XML Encoding 
 Field to indicate  the type of text encoding that you want the system to use when interfacing data files. If you are reading/writing a file (in delimited, fixed length, or XML mode), this field defines the format of the file itself. Note that interface error files also honor this encoding setting.<br data-source-node="n193"> </li>
            <li value="9" data-source-node="n194">Use the File 
 Extension Field to indicate to the system what files this process 
 should be looking for when interfacing delimited/XML data. These delimited/XML 
 files reside in the directory that is defined in the Interface System 
 Values Window.<br data-source-node="n195"> </li>
            <li value="10" data-source-node="n196">Use the Error 
 File Extension Field to indicate the extension that the system 
 should place on the error files it automatically generates if a problem 
 occurs when interfacing data.<br data-source-node="n197"> </li>
            <li value="11" data-source-node="n198">Use the Processed 
 File Extension Field to indicate the extension that the system 
 will add to files that have been processed by the interface. <br data-source-node="n199"> </li>
            <li value="12" data-source-node="n200">Use the Save 
 Processed Data Checkbox if you want the system to not delete interfaced 
 data:<br data-source-node="n201"><br data-source-node="n202">- In Direct Mode: The system 
 will leave the data in the database, and label it as processed.<br data-source-node="n203"><br data-source-node="n204">- In File-Based Modes: The 
 system will add a user-defined file extension to processed data files. 
 The system will not delete these files from their output directory. <br data-source-node="n205"><br data-source-node="n206"></li>
            <li value="13" data-source-node="n207">Press OK. 
 The system will save your record (if you made changes), and return you 
 to the process detail list.</li>
        </ol>

        <h5 data-source-node="n209">Using the Flow Control Tab</h5>
        <p data-source-node="n210"> </p>
        <p data-source-node="n211">- Use the Interface Process Steps section to define what actions you 
 want the system to execute before and/or after the interface is run (such 
 as performing XML data translation or running exit point programs). <br data-source-node="n212"><br data-source-node="n213"></p>
        <p data-source-node="n214">          * Interface Process 
 Detail Field  provides 
 a name for this process step.<br data-source-node="n215"><br data-source-node="n216"></p>
        <p data-source-node="n217">          * Sequence Field 
  indicates 
 in what order the system will execute this process step.<br data-source-node="n218"><br data-source-node="n219"></p>
        <p data-source-node="n220">          * Timing Field 
 indicates if you want this process step to run its custom code before 
 or after the system has run the interface.<br data-source-node="n221"><br data-source-node="n222"></p>
        <p data-source-node="n223">          * Action Type Field 
 indicates what action you want this interface process step to execute. 
 Select "XSL Transform" if you want the system to take SCALE data 
 and perform a custom translation, using a specific XSL style sheet (specified 
 in the Process Field). Note that any XSL transforms configured in the 
 Interface Process Window will be ignored when processing error files. 
  <br data-source-node="n224"><br data-source-node="n225"></p>
        <p data-source-node="n226">          * Process Field 
 identifies the specific XSL style sheet that the 
 system will execute when this process step is run.</p>
        <p data-source-node="n227"> </p>
        <p data-source-node="n228">- Press OK when finished. The 
 system will save your process detail record. </p>
