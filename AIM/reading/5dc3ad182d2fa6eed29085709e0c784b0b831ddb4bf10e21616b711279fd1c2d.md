        <h4 data-source-node="n64">Summary...</h4>
        <p data-source-node="n65">The Immediate Needs module links the receiving and outbound processes 
 to fulfill the immediate needs of your warehouse. There are two main components 
 of this process: the logging 
 of an immediate needs request, and the                      fulfillment 
 of that immediate need. Logging involves the process of the 
 system generating an immediate needs request to indicate that an entity 
 (shipment, work order, replenishment, or short-picked shipment) cannot 
 be completely fulfilled. Fulfillment involves the system taking 
 newly-received item quantity and automatically allocating this quantity 
 to fulfill the immediate need. Users can view a list of the current immediate 
 needs requests and their statuses on the Immediate Needs Insight screen.</p>
        <p data-source-node="n66"> </p>
        <p data-source-node="n67">An immediate need request's priority setting determines the order in which the system 
 will attempt to fulfill it. The system assigns a default 
 priority setting to a request, which is defined in the Immediate Needs 
 Trigger Window. However, you can also manually change a record's priority. Note that these priorities will only come into play for multiple 
 immediate needs requests of the same item.</p>
        <p data-source-node="n68"> </p>
        <p data-source-node="n69">When the system creates an immediate need request, you can view these 
 records in the Immediate Needs Insight screen. This window allows you to 
 search for immediate need requests using several search criteria fields. 
 Once an immediate need is fulfilled, the system will automatically close 
 and delete the request from the viewer window.</p>

        <h4 data-source-node="n86">Processing Flow...</h4>
        <p data-source-node="n87"> </p>
        <p data-source-node="n88">The following is how the system processes received-in quantities using immediate needs:</p>
        <ol data-source-node="n89">
            <li value="1" data-source-node="n90">If then entire quantity on the receipt container can be used to fulfill a single immediate need, the system cross docks the quantity to the shipping dock.<br data-source-node="n91"><br data-source-node="n92"></li>
            <li value="2" data-source-node="n93">If this quantity cannot be used to fulfill a single immediate need, then the system checks the Store Location Assignment Window to see if any immediate need is tied to a put-to-store location.  If it is, the system splits that quantity off to a separate child container and locates to that location. This is done for any other immediate needs the system can find with put-to-store locations.<br data-source-node="n94"><br data-source-node="n95"></li>
            <li value="3" data-source-node="n96">If there remaining immediate needs that are not tied to put-to-store locations, the system decides which locating rule to use, in the following manner:<br data-source-node="n97"><br data-source-node="n98">(1) the shipment line immediate need locating rule<br data-source-node="n99"><br data-source-node="n100">(2) the locating rule indicated in the Immediate Needs System Value<br data-source-node="n101"><br data-source-node="n102">(3) the original locating rule<br data-source-node="n103"><br data-source-node="n104"></li>
            <li value="4" data-source-node="n105">If there is any quantity remaining, the system performs standard locating.</li>
        </ol>

        <h4 data-source-node="n108">Immediate Needs Triggers...</h4>
        <p data-source-node="n109">There are four places where the system can trigger immediate needs requests:</p>
        <ul type="disc" class="ul_1" data-source-node="n110">
            <li class="li_11" data-source-node="n111">Shipment Allocation: The system will generate an immediate 
 needs request when allocation is run, and a detail line is partially or 
 completely rejected. See the process flows tab of this summary topic 
 for a detailed look at this trigger. Note 
 that components and finished items associated with the "Add BOM Component 
 Lines" wave step are ineligible for immediate needs processing.<br data-source-node="n112"><br data-source-node="n113"></li>
            <li class="li_11" data-source-node="n114">Shipment Short Pick: The system will generate an immediate 
 needs request when a short pick is performed at a location. The system 
 will log the remaining quantity as requiring an immediate need in the 
 same manner as an allocation rejection (when Immediate Needs is turned 
 on for short picking). This functionality is supported by short picking 
 through RF work execution, non-RF work execution, and shipment lines 
 (without work).<br data-source-node="n115"><br data-source-node="n116"></li>
            <li class="li_11" data-source-node="n117">Replenishment Allocation:The system will 
 generate an immediate need request whenever replenishment allocation fails 
 to bring forward the requested quantity.<br data-source-node="n118"><br data-source-node="n119"></li>
            <li class="li_11" data-source-node="n120">Work Order Component 
 Allocation:The system will 
 generate an immediate needs request when any work order components fail 
 allocation. </li>
        </ul>
