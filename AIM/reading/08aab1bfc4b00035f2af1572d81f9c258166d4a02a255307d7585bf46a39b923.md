
        
        <h1 data-source-node="n56"><a name="kanchor392" data-source-node="n57"></a>Work Order Touchpoint</h1>
        <p data-source-node="n58">The system supports the downloading of work order header and details between your ERP and SCALE. When 
 work orders are downloaded, the interface converts them into SCALE-supported 
 work order header and detail(s). You can download work orders directly which have been placed into an XML file Also supported are changes/deletions/save 
 of parts of work orders, such as an additional component line added to the existing work order. </p>
        <p data-source-node="n59"> </p>
        <p data-source-node="n60">The inventory transaction upload is used to update the ERP from any work orders that were originally downloaded. This provides the results of the quantity of components used and the quantity of finished items created is sent back to the ERP system. This insures that the inventory  is in sync with the inventory in SCALE. It also allows the ERP system to perform any updates it might need to do in its own work order process. SCALE uses inventory adjustments to subtract the components and add finished items when a work order is completed. The <a href="adc0e535ed3b02667599d992fd1d12fd01c139d85fa991a10bb5a058f3dcdc9c.html" data-source-node="n61">Work Order System Values</a> configuration stores the adjustment types used when confirming a work order.</p>
        <p data-source-node="n62"> </p>
        <p data-source-node="n63">Within the Work Order System Value there is a description called 'Work Order Allocation'. If this method is set to 'Creation', when the work order gets created by the interface, it will immediately start the allocation process for the work order. </p>
        <p data-source-node="n64"> </p>
        <p data-source-node="n65">Also within the Work Order System Value there is a description called 'Should WO be automatically released when entered?'. If this method is set to 'Yes', then when the work order gets created in the interface, it will release the work order immediately. This process is submitted and does not hold up the interface process waiting for this to finish.  </p>
        <p data-source-node="n66"> </p>
        <p data-source-node="n67">The work order interface processes the following entities:</p>
        <ul type="disc" class="ul_1" data-source-node="n68">
            <li data-source-node="n69"><i data-source-node="n70">Work Order Headers</i>: 
 These can be interfaced with or without associated details.<br data-source-node="n71"> </li>
            <li data-source-node="n72"><i data-source-node="n73">Work Order Details</i>: 
 These can be interfaced either as part of a work order header download, 
 or as a lone detail (which must be associated with an existing work order).<br data-source-node="n74"><br data-source-node="n75"></li>
        </ul>
        <p data-source-node="n76">
            <br data-source-node="n77">

        <h4 data-source-node="n84">General Guidelines...</h4>
        <ul data-source-node="n85">
            <li data-source-node="n86">When downloading a work order, the ERP can download the work order header information.  In this situation, the system will look up the Bill of Materials for that item/company.  If found, the work order details will be created from the Bill of Materials Detail records. 
If there is not a Bill of Materials associated with the item, the system just creates the work order with no details.<br data-source-node="n87"><br data-source-node="n88"></li>
            <li data-source-node="n89">When work order details are included in a download file, the system will not use the Bill of Materials configuration.  In other words, even if a bill of materials exists for a finished item/company, the interfaced work order details will override the bill of materials defined.<br data-source-node="n90"><br data-source-node="n91"></li>
            <li data-source-node="n92">There is a work order system value called “Work Order Allocation Method” that indicates when to perform allocation.  The options are to allocate upon 'Creation' or upon 'Release'.  When this value is set to 'Creation', then the work order is allocated immediately after being downloaded.<br data-source-node="n93"><br data-source-node="n94"></li>
            <li data-source-node="n95">When downloading a change to a work order, the download information can specify a new work order detail to an existing work order.  In order to do this, the information must have the work order header specified, along with the new work order detail and sent with a mode of 'Change' or 'Save'.<br data-source-node="n96"><br data-source-node="n97"></li>
            <li data-source-node="n98">Once a work order is established, the finished item on it cannot be changed.<br data-source-node="n99"><br data-source-node="n100"></li>
            <li data-source-node="n101">If the quantity to be built on the work order changes, the system compares the quantity to be built on the download to the quantity to be built from the original work order. If there is a difference, the system will recalculate the total quantity needed on each work order detail.<br data-source-node="n102"><br data-source-node="n103"></li>
            <li data-source-node="n104">When updating an existing record, if a value is not interfaced for a field, the system treats it as “no change” and retains the existing value.<br data-source-node="n105"><br data-source-node="n106"></li>
            <li data-source-node="n107">When downloading a delete to a work order, the download information can specify a single work order detail on an existing work order.  The system will delete only the work order detail specified.<br data-source-node="n108"><br data-source-node="n109"></li>
            <li data-source-node="n110">The work order download process will not access bills of material that are defined as inactive.  The system will retrieve the highest-numbered revision for an item/company that is defined as Active<br data-source-node="n111"></li>
        </ul>
        <p data-source-node="n112"> </p>

        <h4 data-source-node="n114">Rejection Causes / Validations / Notes...</h4>
        <ul type="disc" class="ul_1" data-source-node="n115">
            <li data-source-node="n116">The interface will validate (against SCALE configurations) 
 certain values that are downloaded. Use the Table Values Spreadsheet to 
 look up specific values to determine if they are validated.<br data-source-node="n117"> </li>
            <li data-source-node="n118">The interface will reject a 'New' work order ID if it 
 already exists in the system.             <br data-source-node="n119"> </li>
            <li data-source-node="n120">If the Build Location is interfaced down, it must be a valid location within the warehouse specified.

The location must have a 'Location Class' of “Work Order Build”
.<br data-source-node="n121"> </li>
            <li data-source-node="n122">The item must be interfaced down. 

If the Inventory System Value “Should Item be validated throughout system?” is set to “Y”, the item must exist in Item configuration.
'Item' and 'Company' are fields that work together. The system standard for looking up an Item in the Item configuration is to first look for the specific 'Item' and 'Company' combination. If that is not found, then look for the Item with a blank (or NULL) company. Either one or the other combination should exist, but not both.
</li>
        </ul>
        <ul type="disc" class="ul_1" data-source-node="n123">
            <li data-source-node="n124">The interface download field "Quantity to be Built" must be a number greater than or equal to '1'. The system will verify if the 'Quantity UM' is not the lowest sequence unit of measure in the Storage Template associated with the Item/Company. If the Item/Company has a value for this UM in the Item Unit of Measure configuration,
the system will take value and multiply it by the Conversion Quantity from the record stored in the database.
</li>
