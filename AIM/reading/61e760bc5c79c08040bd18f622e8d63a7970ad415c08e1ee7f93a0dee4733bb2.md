
        
        <h1 data-source-node="n56"><a name="kanchor1981" data-source-node="n57"></a>Processing Data Archiving Records</h1>
        <p data-source-node="n58">Data archiving moves records from an "active" database to 
 an "inactive" database, based on age and any other defined criteria. 
 This increases system speed and minimizes the number of records displayed 
 on application screens. You can schedule archiving processes 
 to run automatically (via "scheduled jobs") or manually, depending 
 on your business practices. When you archive records, the system will save them to a separate database table. You can then view these records using the Archive viewers. You can also restore them back to an active state. However, if you choose to delete the records from the database, the system will remove them permanently from active database tables. You cannot access or restore deleted records.</p>
        <p data-source-node="n59"> </p>
        <p data-source-node="n60">Archive to external storage can also be configured to improve the performance of the application. The archiving to an external storage database can be configured using few powershell commands. See the <b data-source-node="n61">SDK topic "How to: Configure External Data Storage for Archiving"</b> for more information.</p>
        <p data-source-node="n62"> </p>
        <p data-source-node="n63">WARNING: Archiving records will 
 take up considerable system resources. You should not run a archive job 
 during normal operational hours or during peak processing times. </p>
        <p data-source-node="n64"> </p>

        <h4 data-source-node="n103"><a name="Manually" data-source-node="n104"></a>Manually Running Archive 
 Masters...</h4>
        <p data-source-node="n105">You can manually activate the archiving of old records in the system. 
 When you activate a master, it will archive records according to rules 
 you define. You can define how you want to deal with this data by creating 
 an archive master in the Archive Master Window. The system displays these 
 masters in the Archive Data Window. You can also research archived records 
 on one of the Archive Viewers. Note that if you have checked the Run As Default Check box on the Archive 
 Master Window, certain master record(s) will already be checked when you 
 open the Archive Data Window. These masters are run automatically through 
 SCALE scheduled jobs.</p>
        <ol data-source-node="n106">
            <li value="1" data-source-node="n107">
                <p data-source-node="n108">Use the Archive Masters Check boxes 
 to indicate which archive master(s) that you want to activate. You can 
 also use the     Check All Check box to 
 select all of the masters.</p>
                <p data-source-node="n109"> </p>
            </li>
            <li value="2" data-source-node="n110">
                <p data-source-node="n111">Select OK. The 
 system will display a confirmation message verifying that you want to 
 archive this data:</p>
                <p data-source-node="n112"> </p>
            </li>
            <ul type="disc" class="ul_1" data-source-node="n113">
                <li data-source-node="n114">
                    <p data-source-node="n115">If you choose Yes, 
 the system will immediately archive/purge the records as defined on the 
 master rule.</p>
                    <p data-source-node="n116"> </p>
                </li>
                <li data-source-node="n117">If you choose 
 No, the system will return 
 you to the Archive Data Window.</li>
            </ul>
        </ol>

        <h4 data-source-node="n119"><a name="Researching" data-source-node="n120"></a>Researching Data Archiving Records...</h4>
        <p data-source-node="n121">You can view your warehouse's archived records in one of the Archive 
 Viewers.</p>
        <p class="p_5" data-source-node="n122"> </p>
        <h5 data-source-node="n123">Viewer Window Layout</h5>
        <p data-source-node="n124">When you open an Archive Viewer, the system will display a window with 
 two tabs. The Criteria Tab contains the fields you can use to perform 
 a search. The Results Tab displays the record(s) that the system found 
 to match your search criteria. You can use the fields on the Criteria 
 Tab to search for your archived records. The fields displayed on this 
 tab will depend on how this viewer was configured.</p>
        <p data-source-node="n125"> </p>
        <h4 data-source-node="n126"><a name="External" data-source-node="n127"></a>Archive to External Data Storage.</h4>
        <p data-source-node="n128">You can create and configure an external database to store archiving data for the application. This configuration will enable you to record the archive data directly to the external storage. The following are the feature capabilities. See the <b data-source-node="n129">SDK topic "How to: Configure External Data Storage for Archiving"</b> for more information on how to create, configure and upgrade using the PowerShell commands.</p>
        <p data-source-node="n130"> </p>
        <h5 data-source-node="n131">Create a new Archive Database </h5>
        <p data-source-node="n132">Using the <b data-source-node="n133">Add-ScaleArchiveDB</b> PowerShell command, create a new archive database. The external database will be of MS SQL type only.</p>
        <p data-source-node="n134"> </p>
        <h5 data-source-node="n135">Configuration of Archive DB</h5>
        <p data-source-node="n136">The new external archive database (MS SQL) can be configured using the <b data-source-node="n137">Set-ScaleArchiveDataStorage</b> powershell command. </p>
        <p data-source-node="n138"> The user is prompted with the following two options</p>
        <ul data-source-node="n139">
            <li data-source-node="n140">1- Default - The archive data will be stored in the main database and the external database will not be used for archiving.</li>
            <li data-source-node="n141">2- MS SQL - The archive data will be directed to be written in the external MS SQL database.</li>
        </ul>
        <h5 data-source-node="n142">Archive Custom Tables</h5>
        <p data-source-node="n143">The custom tables created for user-specific environment can also be archived in the external database. Users need to add the custom table to the Archive table list and then configure and run the archive masters.</p>
        <p data-source-node="n144"> </p>
        <p data-source-node="n145">See the <b data-source-node="n146">SDK topic "How to: Configure External Data Storage for Archiving"</b> for more information.</p>
