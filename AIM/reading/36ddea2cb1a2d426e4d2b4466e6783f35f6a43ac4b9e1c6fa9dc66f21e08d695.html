GS1 RF Processing

When checking into your warehouse product that uses GS1 barcodes, the RF receipt processing flow is somewhat different than it is when scanning typical barcodes. GS1 barcodes contain multiple informational segments (called application identifiers), such as quantity, lot, or license plate ID. As a result, the system presents the RF user with a different set of screens to scan in the GS1 barcode data. The goal of this topic is to illustrate the differences in the RF receiving flow when scanning GS1 barcodes. You can view steps for the typical RF check in flow by visiting one of the topics in the "Related Procedures" section below.

General Button Actions

The following buttons actions are used in GS1 RF screens:

 

Button

 

Description

 

OK

Accepts previously scanned data, and the system proceeds to the next GS1 scan screen.

 

Cancel

 

Returns the user to the receiving preferences screen without processing the check in.

 

Done

This button appears after one complete set of scans has been performed for a label, and the system displays the first scan screen for the next item to be checked in. When you press this button, the system will execute all the post-check-in processing (locating, etc.), and return you to the initiation screen.

 

Skip

 

The system allows you to skip a scan (for example, maybe the barcode is smudged and would not be readable by the RF device). When you skip a scan, the system will prompt you to manually enter the information that the system would have acquired via the scan.

 

Rescan

System disregards previously scanned information, and will navigate back to the GS1 scan screen. Also, the system will reset the scan number back to 1.

 

 

 

 

 

Basic GS1 Receipt Check In...

When initiating a basic RF Check In action, the system requires one or more of the following values: item, item cross reference, quantity, quantity unit of measure, and container ID.  The user enters this information using the Enter Item, Check In and Container ID screens.  For GS1 processing, the system replaces these screens with a single GS1 Scan screen. As in typical RF processing, the user may rescan, skip, or cancel when scanning GS1 barcodes. Note that the quantity UM is not directly defined on the GS1 barcode; instead, this is associated with an item cross reference record (in absence of this, the system uses the item's base unit of measure). If configured to do so, the system can also display a verification screen after each scan.

 

Note that example application identifiers are in parenthesis below each screen diagram. These could be mapped to different values depending on your configurations.

GS1 Processing and Serial Number Ranges

During the processing of GS1 scans, since the system allows the scanning of only a single serial number from a GS1 barcode, the system ignores a serial number template's "allow range entry" setting. You will, however, be able to enter serial number ranges as part of the normal check in process that occurs after the GS1 scan(s).

Nesting Containers During Check In

You will encounter this flow if, for example, your warehouse prefers to nest containers onto pallets during check in, for example. In order to activate this nesting, you need to have the "Nest During Check In" option selected on your receiving preferences. After you scan the GS1 barcodes of the containers you are going to nest, the system will display an additional screen for the parent container (such as a pallet) you want to nest into. Note that this functionality is not available in the separate RF main menu function "Receipt Container Nesting."
