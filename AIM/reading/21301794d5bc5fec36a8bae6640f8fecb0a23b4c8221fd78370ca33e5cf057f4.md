
        
        <h1 data-source-node="n56">Filter Data Configuration Window</h1>
        <p data-source-node="n57">You will use the filter data configuration windows to create and maintain 
 rule sets for specific functional areas, such as work creation, paperwork, 
 and wave processing. This type of window allows you to define the criteria 
 by which the system will filter through records and choose a select group 
 for processing.</p>
        <p data-source-node="n58"> </p>
        <p data-source-node="n59"> </p>
        <h4 data-source-node="n60">Accessing...</h4>
        <p data-source-node="n61">You can access these windows through the Configurations Explorer. Filter 
 data configuration windows deal with several functional areas of the system.</p>
        <p data-source-node="n62"> </p>
        <p data-source-node="n63"> </p>
        <h4 data-source-node="n64">Primary Components...</h4>
        <p data-source-node="n65">A filter data configuration window is composed of two tabs of information: 
 the Filter Data Tab and the    Order By Tab. The Filter Data Tab allows 
 you to create "rules" to filter specific data by. The Order 
 Tab allows you to arrange these rules in an order that meets your business 
 needs:</p>
        <p data-source-node="n66"> </p>
        <p data-source-node="n67"> </p>
        <h4 data-source-node="n68">Filter 
 Data Tab...</h4>
        <p data-source-node="n69">The Filter Data Tab has two field sections: the filter criteria fields 
 and the value list. The filter criteria fields specify the values that 
 the system will use to perform a specific action. In the graphic below, 
 a new criteria rule is being created, namely that if a carrier service 
 equals the value "UPS", then an action will be performed. The value list displays all of the filter criteria rules in the order 
 that they'll be processed. In the graphic below, there is already an existing 
 filter criteria listed in the value list, specifically if a carrier type 
 equals "Parcel". If the user were to press the Add Button in 
 the example below, then the carrier service filter criteria record would 
 be added to the value list.</p>

        <h4 data-source-node="n75">Order 
 By Tab...</h4>
        <p data-source-node="n76">The Order By Tab has two field sections: the order by fields and the 
 value list. For each record that you create, you can identify the following: 
 the request record that the system will use to organize the instructions, 
 as well as the order that they are organized (ascending/descending). The 
 value list displays all of the records created on the order by fields. 
 These records are processed in the order that they appear in the list.</p>

        <h4 data-source-node="n82">Tips for Using the Filter 
 Data Configuration Window...</h4>
        <p data-source-node="n83"> </p>
        <h5 data-source-node="n84">Partial 
 Values Using "LIKE"</h5>
        <ul type="disc" class="ul_1" data-source-node="n85">
            <li data-source-node="n86">If you want to enter a partial value in the Value 
 Field in conjunction with a "LIKE" operand, you 
 must use a percent sign to represent the unknown portion of the 
 value. If you do not, the system will consider the "LIKE" operand 
 to be an "equal (=)" operand.<br data-source-node="n87"><br data-source-node="n88">	For example, suppose that you want to include in a wave all orders 
 that have postal codes beginning with the numbers "52". You 
 would create such a rule by entering the value as seen in the graphic 
 below. If you had not included the percent sign to represent the unknown 
 portion of this value, the system would have looked for postal codes that 
 equal the value "52". Then, when the system tried to build this 
 Wave, an error would have occurred, as there is no postal code possible 
 that fits that criteria.<br data-source-node="n89"><br data-source-node="n90"><img loading="eager" data-source-node="n91"><br data-source-node="n92"></li>
        </ul>
        <p data-source-node="n93"> </p>
        <h5 data-source-node="n94">Implementing 
 Date Ranges Based On a Specific Date</h5>
        <ul type="disc" class="ul_1" data-source-node="n95">
            <li data-source-node="n96">You can also create rules for a specific date 
 range, based on a particular date. When you choose a date attribute in 
 a filter configuration, the system will display the Date Criteria Window 
 (see graphic below), which allow you to create more advanced date rules.<br data-source-node="n97"><br data-source-node="n98">	For example, suppose you wanted location to be cycle counted once every 
 60 days, and <span class="span_4" data-source-node="n99">not repeated</span>. You 
 could create a rule for this case in the Cycle Count Location Criteria 
 Window. The rule would be based off the Last Cycle Count Date Field, where 
 the system would check to see if a location has been counted in the past 
 60 days (starting with today's date). If it has, then the system would 
 not generate a request to count it again. However, if the Last Cycle Count 
 Date value is older than 60 days, the system then would generate a cycle 
 count request for this location.<br data-source-node="n100"><br data-source-node="n101"><img loading="eager" data-source-node="n102"></li>
        </ul>
