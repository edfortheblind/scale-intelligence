
        
        <h1 data-source-node="n56"><a name="kanchor119" data-source-node="n57"></a>Notes On Viewer Setup</h1>
        <h4 data-source-node="n58">Security Settings...</h4>
        <ul data-source-node="n59">
            <li data-source-node="n60">If you want to restrict access to this custom viewer, you will need to address it's security settings on the General Tab of the Security Window. You can also restrict the use of viewer actions on the Form Specific Tab of the Security Window.<br data-source-node="n61"><br data-source-node="n62"></li>
            <li data-source-node="n63">Viewer Colors and Icons settings are system-wide (not based on user).</li>
        </ul>
        <p data-source-node="n64"> </p>
        <h4 data-source-node="n65">Server/Machine Notes...</h4>
        <p class="p_46" data-source-node="n66">Take the following into consideration when creating/configuring viewer windows, actions, colors, or icons:</p>
        <ul data-source-node="n67">
            <li data-source-node="n68">While you can 
 make viewer configuration changes on the      application 
 server or a client machine, 
 keep in mind that the client update installer needs to run in order to 
 see your viewer changes on a client machine.<br data-source-node="n69"><br data-source-node="n70"></li>
            <li data-source-node="n71">Also, on a multi-server 
 environment, the viewer changes will need to be manually-applied to the 
 alternate server because this process is not automated. For example: </li>
            <p data-source-node="n72"> </p>
            <p data-source-node="n73">1. Suppose 
 you have two application servers: A and B. Also, you have 
 two client machines      Client-A 
 (tied to application server A), and      Client-B 
 (tied to the application server B).<br data-source-node="n74"> </p>
            <p data-source-node="n75">2. The 
 user is on Client-A and 
 changes the viewer color settings for the Background Job Queue Insight Screen. 
 These changes are immediately applied to Server-A 
 and will be applied to      Client-A 
 once the client updates are applied on the machine.<br data-source-node="n76"> </p>
            <p class="li_19" data-source-node="n77">3. The 
 changes will never get to Server-B
 or      Client-B because this 
 process is not automated. In order for these changes to be applied to 
 that environment, the XML file for the viewer would have to be copied 
 to them by hand. This file can be found in the      \\ILS\Viewers\XML\ 
 directory. The files are named      &lt;FormID&gt;_&lt;FormKeyName&gt;.xml.</p>
        </ul>
        <p data-source-node="n78"> </p>
        <p data-source-node="n79"> </p>
        <h4 data-source-node="n80">Multi Lingual Note...</h4>
        <p data-source-node="n81">Take the following into consideration when creating/configuring viewer actions:</p>
        <ul data-source-node="n82">
            <li data-source-node="n83">If you want 
 your custom action to appear in a different language in your viewer, 
 you will need to create a new resource key where the key is the Action 
 Name that you setup on there Actions Tab of the Viewer configuration window.</li>
        </ul>
