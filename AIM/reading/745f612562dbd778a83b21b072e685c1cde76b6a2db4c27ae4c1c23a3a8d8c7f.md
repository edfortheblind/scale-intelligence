
        
        <h1 data-source-node="n56"><a name="kanchor179" data-source-node="n57"></a>Researching Warehouse Alerts</h1>
        <p data-source-node="n58">A warehouse alert communicates to the user when a certain condition 
 in the warehouse exists and needs attention. Any time a warehouse action 
 (that is defined as an alert) emerges or occurs, the system writes an 
 alert request. Then, when the warehouse alerts scheduled job kicks off, 
 the system will process this request and generate an alert record. You 
 can configure these alerts to write "history" (special records that are viewable in the Warehouse Alert Viewer), send an email message, or 
 both. You can use these alerts to learn about problem(s) in your warehouse 
 and how to resolve them. Also, you can assign a priority to an alert to determine 
 when the problem should be resolved, in relation to other alerts. For example, suppose a container fails the scan &amp; weigh process 
 because it exceeds the weight accepted by the carrier. If you had an alert 
 defined for the manifesting process, the system would generate an alert 
 that you could review on the Warehouse Alerts Viewer. Note that warehouse alerts are referred to as "email alerts" 
 in SCALE's Trading Partner Management web module. </p>

        <h4 data-source-node="n81">Warehouse 
 Alert Descriptions...<br data-source-node="n82"></h4>
        <h5 style="font-weight: normal" data-source-node="n83">The 
 following are the default alert records shipped with the system:</h5>
        <ul type="disc" class="ul_1" data-source-node="n84">
            <li data-source-node="n85">Delete Shipment 
 Alert – This alert is logged anytime a shipment is deleted 
 from the system.<br data-source-node="n86"> </li>
            <li data-source-node="n87">Inbound Alert 
 - This alert is logged when a receipt first reaches 
 a configured leading status.<br data-source-node="n88"> </li>
            <li data-source-node="n89">Interface Alert 
 – This alert is logged when interface process failures occur that cause the system to generate audits. If you receive such an alert, you would look at the Audit 
 Log Window to get more information (though both the error file and history). Note that normal interface validation errors (for example,      X 
 field is required) would not trigger alerts of this type.<br data-source-node="n90"><br data-source-node="n91"></li>
            <li data-source-node="n92">Interface Rejection Alert - This alert is logged during interface processing when the system encounters an issue with the actual interface data file. Note that normal interface validation errors (for example,      X 
 field is required) would not trigger alerts of this type.<br data-source-node="n93"><br data-source-node="n94"></li>
            <li data-source-node="n95">Interface Validation Alert - This alert is logged during download interface processing when the system encounters a validation error with the downloaded data. For example, these validation errors could be such things as <i data-source-node="n96">X</i> field is required, or <i data-source-node="n97">X</i> field value does not exist, etc.<br data-source-node="n98"> </li>
        </ul>
        <ul data-source-node="n99">
            <li data-source-node="n100">License Key Warnings 
 – This alert is logged anytime a license key is violated. License key warning warehouse alerts are written as follows<ul data-source-node="n101"><li data-source-node="n102">Once per day starting 15 days before the current date range ends. </li><li data-source-node="n103">On the first day of a new date range, when the user count increases.</li><li data-source-node="n104">On the first day user profiles have been deactivated.</li></ul></li>
        </ul>
        <ul type="disc" class="ul_1" data-source-node="n105">
            <li data-source-node="n106">Manifesting Alert 
 – This alert is logged when errors are encountered in the 
 Scan and Weigh Scheduled Job.  The 
 following are the scenarios in which alerts of this type would be triggered:<br data-source-node="n107">	- shipment not found <br data-source-node="n108">	- shipment id not found <br data-source-node="n109">	- errors returned from close container/manifesting logic<br data-source-node="n110">	- errors returned when creating a new container<br data-source-node="n111"> </li>
            <li data-source-node="n112">Order Entry Alert 
 – This alert is logged when an error occurs during the order 
 entry process.<br data-source-node="n113"> </li>
            <li data-source-node="n114">Outbound Alert 
 – This alert is logged when a shipment first reaches 
 a configured leading status.<br data-source-node="n115"> </li>
            <li data-source-node="n116">Pro Number Alert 
 – This alert is logged when the number of pro numbers left 
 for a certain pro number set falls below the configured percentage (which 
 is set in the Rating System Values Window).</li>
        </ul>

        <h4 data-source-node="n121">Procedures...<br data-source-node="n122"></h4>
        <p data-source-node="n123">The procedures below identify how to open, update, close, delete, or 
 reprocess warehouse alerts. Note that some alert records do not have a 
 warehouse associated with them. Therefore, even though the Warehouse Alert 
 Tab defaults a value to the Warehouse Field, the system will return alert 
 records that have no warehouse associated with them, along with your warehouse's 
 records.</p>
        <ol data-source-node="n124">
            <li value="1" data-source-node="n125">
                <p data-source-node="n126">Access the Warehouse Alerts Viewer.</p>
                <p data-source-node="n127"> </p>
            </li>
            <li value="2" data-source-node="n128">To narrow the 
 records displayed in the record list, provide any appropriate filter 
 criteria on the Criteria Tab. For example, if you only want to view alerts 
 created today, you would provide today's date in the date range field. 
 Press the Search Button. The results will appear in the record list on 
 the Results Tab. You can then perform the following actions:<br data-source-node="n129"><br data-source-node="n130">	- Open/Review an Alert:To open an alert, select if from the 
 record list. Select the Open Action. The system will display the alert 
 on the Warehouse Alert Window. Each time you view a record on this window, 
 the system will identify it as reviewed. Your name will appear in the 
 Last Reviewed By Field when someone accesses it again. You can access 
 a different alert by using the Previous and Next Buttons. When you access 
 an alert, the system indicates that you have reviewed it, whether you 
 accessed it from the Warehouse Alert Viewer Window or by using the Previous 
 and Next Buttons.<br data-source-node="n131"><br data-source-node="n132">	- Update an Alert's Priority: Priority identifies when you believe 
 an alert should be addressed, in relation to the other open alerts. The 
 lower the alert's priority number, the sooner it should be addressed. 
 To change an alert's priority, first open it, and then change its priority 
 value. The system will identify the record as reviewed by you.<br data-source-node="n133"><br data-source-node="n134">	- Close an Alert:You will want to close an alert after you have resolved the issue. 
 You can only close an alert from the record list (on the Warehouse Alert 
 Viewer). Select the alert from the record list and select the Close Action. 
 The system will close the record. You will be identified as the person 
 who closed the record on Closed By Field. The system will log the date 
 and time that the record was closed. <br data-source-node="n135"><br data-source-node="n136">	- Delete an Alert:The system will allow you to delete any alert that appears in the 
 record list. The alert can be deleted even if it has not been either reviewed 
 or closed. Simply right-click an alert, and choose Delete.<br data-source-node="n137"><br data-source-node="n138">	- Reprocess an Alert:You can also reprocess email alerts 
 that were not correctly processed by the system. To do this, right-click 
 an alert and choose Reprocess. Note that you can only choose this option 
 if the alert is in an error status.</li>
        </ol>
