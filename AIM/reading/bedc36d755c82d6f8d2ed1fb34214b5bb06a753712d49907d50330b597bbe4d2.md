
        
        <h1 data-source-node="n56"><a name="kanchor1907" data-source-node="n57"></a>RF Immediate Dock Transfers (Without Work)</h1>
        <p data-source-node="n58">Typically, in a warehouse, you will either use work to facilitate the movement of containers into and through your shipping dock, or you will choose not to use work. The purpose of the RF Immediate Dock Transfer screen is to allow you to perform container transfer movements without using RF work execution. Instead, you need to scan the container ID, move the container to its new location on the dock, and then scan the destination location ID. If the transfer passes validations, the system will then move the inventory on hand from its original location to the destination location. The status on the container and its associated shipment line(s) are updated without creating work.</p>
        <p data-source-node="n59"> </p>
        <p data-source-node="n60">IMPORTANT: You can only use this dock transfer option if there is no work associated with the container you want to move. If the container has work created for it, then the system will not allow the transfer, and you will need to perform work execution  to move the container.</p>
        <p data-source-node="n61"> </p>
        <p data-source-node="n62">NOTE: This function not only enables you to move containers to the dock door, but you can also use it to move containers from any dock location to another dock location.</p>
        <p data-source-node="n63"> </p>

        <h4 data-source-node="n87"><a name="mop" data-source-node="n88"></a>Note About Transferring Multiple Order Pallets...</h4>
        <p class="p_5" style="color: #000000" data-source-node="n89">If you are transferring a multiple order pallet, the transfer will process just as it would with any shipping container. However, the Customer Name and Ship To informational field values will be represented with the term "Multiple" and the actual number of customer/ship to values are enclosed in parenthesis. </p>
        <p class="p_5" style="color: #000000" data-source-node="n90"> </p>

        <h4 data-source-node="n92"><a name="procedures" data-source-node="n93"></a>Performing an Immediate Dock Transfer...</h4>
        <ol data-source-node="n94">
            <li value="1" data-source-node="n95">Log onto an RF Device.<br data-source-node="n96"><br data-source-node="n97"></li>
            <li value="2" data-source-node="n98">Select the Immediate Dock Transfer option from the RF Main Selection screen. The system will display the Immediate Dock Transfer screen.</li>
            <p class="p_5" data-source-node="n99"> </p>
            <li value="3" data-source-node="n100">Scan the ID of the "top-level" (parent) container that you want to transfer to the shipping dock door. <br data-source-node="n101"><br data-source-node="n102">The following needs to be true of the container:<br data-source-node="n103"> <br data-source-node="n104">- The container must currently exist in the system.<br data-source-node="n105"><br data-source-node="n106">- The container must be a "top-level" (parent) container.<br data-source-node="n107"><br data-source-node="n108">- The container or its children cannot be associated with open or in process work instructions. </li>
            <p data-source-node="n109"> </p>
            <p data-source-node="n110">NOTE: This RF screen does not support special characters as follows: , / ? : @ &amp; = &lt; + $ # </p>
            <p data-source-node="n111">
                <br data-source-node="n112">
            </p>
            <li value="4" data-source-node="n113">Physically move the container to its destination location. Note if the container is associated with a load (and that load is assigned a dock door), the system will default the dock door location into this field.<br data-source-node="n114"><br data-source-node="n115"></li>
            <li value="5" data-source-node="n116">Scan the destination location. <br data-source-node="n117"><br data-source-node="n118">The following needs to be true of the destination location:<br data-source-node="n119"><br data-source-node="n120">- The destination location cannot be frozen.
	<br data-source-node="n121"><br data-source-node="n122">- The destination location needs to have a location class of Shipping Dock.<br data-source-node="n123"><br data-source-node="n124">- There needs to be a dock management flow detail record for the location subclass of the destination location.<br data-source-node="n125"><br data-source-node="n126">- If the destination location is a dock door location, then no other load can be assigned to that dock door.<br data-source-node="n127"><br data-source-node="n128">- The load that the shipment is assigned to must either be assigned to that dock door or no dock door.<br data-source-node="n129"><br data-source-node="n130"></li>
            <li value="6" data-source-node="n131">Press the Transfer Button. If the transfer is successful, then the system will display a success message at the bottom of the screen. <br data-source-node="n132"><br data-source-node="n133">- If the container's shipment is not assigned to a load, then the system will create a shipping load and assign it to the appropriate dock door.<br data-source-node="n134"><br data-source-node="n135">- If the container's shipping load was not previously assigned to a dock door, the system will assign the appropriate dock door to the container's load.<br data-source-node="n136"><br data-source-node="n137">- If the carrier on the container's shipment matches the load at the door (but the shipment is not assigned to that load), the system will add the shipment to that load.<br data-source-node="n138"><br data-source-node="n139">- The system will not allow the transfer if the container's shipment is unassigned to a load and does not have a carrier.<br data-source-node="n140"><br data-source-node="n141">- If, during the execution of a transfer, the system creates work for this container, and you then press the Transfer Button to close the transaction, the system will not allow the transfer to complete.<br data-source-node="n142"><br data-source-node="n143"></li>
            <li value="7" data-source-node="n144">You can then perform another dock transfer (go back to step 3 above), or exit the screen.<br data-source-node="n145"></li>
        </ol>
        <p data-source-node="n146"> </p>
        <h4 data-source-node="n147"><a name="tip" data-source-node="n148"></a>Tip: One or more shipping containers (but not all) on a Multiple Order Pallet fails to transfer to the "to" location...</h4>
        <p data-source-node="n149"> </p>
        <p data-source-node="n150">The multiple order pallet will have one or more containers at the "to" location and one or more containers at the "from" location.

</p>
        <ol data-source-node="n151">
            <li value="1" data-source-node="n152">Review Process History for Dock Transfer failure records for the multiple order pallet.  The multiple order pallet ID found in the Identifier 3 field of the history record.
<br data-source-node="n153"><br data-source-node="n154"></li>
            <li value="2" data-source-node="n155">Investigate and resolve the problem.<br data-source-node="n156"><br data-source-node="n157"></li>
            <li value="3" data-source-node="n158">Transfer the multiple order pallet to a location (Staging) other than the current locations on the shipping containers.  There should be only two different locations on the multiple order pallet containers.  If the problem was resolved, then all the containers on the multiple order pallet will be transferred to the "to" location.  This gets all the shipping containers back to the same "from" location.<br data-source-node="n159"><br data-source-node="n160"></li>
            <li value="4" data-source-node="n161">Transfer the multiple order pallet to the original "to" location.</li>
        </ol>
