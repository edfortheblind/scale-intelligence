Defining Wave Flows

A wave flow is a grouping of wave steps. These flows determine which wave steps that a shipment will be processed through, and the order in which the wave steps will be processed. Once you create a wave flow, you can associate it with the appropriate wave on the Wave Master Window.

Notes on Wave Steps
  • Remember, the system processes the wave steps based on their sequence number. The lower the sequence number, the sooner the wave step is processed. The Sequence Field will contain a value that is 10 more than the last sequence number used. You can change the sequence number, but you cannot use the same sequence number for multiple detail records.

  • If you try to insert a wave step that would result in a second Work Creation step, the system will warn you that you can cause duplicate work if data selection is not properly set up. Note that this validation is only performed when trying to add the shipping-related work creation steps, and not when adding the replenishment-related work creation step.

  • In order to have multiple waves running at the same time, you need to assign a value greater than one in the "Run Concurrently" field in the Batch Submission Queue table.

  • To include shipments in a wave, you must include the Start Wave step. The Start Wave step moves the shipments forward from the "In Pool" status to the "In Wave" status.

  • To allow the wave's shipments to be processed, you must include the Complete Wave step. The Complete Wave step moves the shipments forward to the first available status following the wave, such as 'In Picking'.

  • If you include the Shipment Consolidation step, run it before steps such as routing and work creation. Shipment consolidation can impact the weight and contents of a shipment, thus changing the carrier selected, the work generated, etc. It is recommended to run consolidation right after the Start Wave Step.

  • To have work instructions created for allocation and/or replenishment, you must include in your flow both the Allocation and Replenishment steps, as well as the corresponding allocation/replenishment work creation step (note that you could also run replenishment without work creation as long as the Create Work checkbox on the replenishment master is not checked). Also, the allocation/replenishment work creation step must be run after allocation and replenishment.

  • If you want paperwork to support the documents generated during other steps, such as carrier rating or work creation, make it run after them.

Procedures: Creating a Wave Flow Record...

  1. Access the Wave Flow Window.

  2. Name this record and provide a description.

  3. Press the Apply Button. The system will add this record and leave the window open.

  4. Right-click on the Detail Records Tab and select the New action. The system will display the Wave Flow Detail Window. This is where you identify each step in your flow.

  5. Use the Sequence Field to identify what order this wave step will occur, in relation to the other wave steps. The lower the number, the sooner the system will initiate the step.

  6. Use the Wave Step Field to select the wave step that you want to insert into your wave flow. See the Wave Step Descriptions section later in this topic for information on specific wave steps.

  7. Press OK on the flow detail window, and the system will add this step to your wave flow.

  8. Repeat steps 5-7 to add additional wave step(s) to your flow.

  9. Press OK on the wave flow window, and the system will save your wave flow.

 

 

 

Wave Step Descriptions...

 

IMPORTANT NOTE: Below are recommendations as to where you should place a wave step in your wave flow. The placement suggestions below are general guidelines, and note that it is possible that there could be other valid possibilities for placement that are not discussed in this topic.

 

 

 

10 - Add BOM Component Lines

 

This wave step should be placed before the allocation wave step. It adds component lines for any finished item in the wave that has a shipment BOM Action setting of "Add BOM Components as Shipment Details." The system then will link the component lines to their finished item line by the related internal line number field. What the system is doing is adding and/or relating shipment lines on the same shipment to one another in a parent/child fashion.

 

Example
  • Suppose your warehouse has a table, which consists of a table top and four legs, and you do not pre-assemble these tables before shipping. When a customer orders one of these, the system will create lines for the parent and component items, separately.

  • Therefore, the parent table:

    [line number] - [item] - [quantity]
    1.00 - ITEMA (Table) - 10

    becomes...

    [line number] - [item] - [quantity]
    1.00 - ITEMA (Table) - 10
    1.01 - ITEMA1 (Table Top) - 10
    1.02 - ITEMA2 (Table Legs) - 40

  • Note that you can either interface lines 1.01 and 1.02 yourself, or use the Add BOM Components wave step to have the system add them for you if they are set up in the Bill of Materials configuration, and the item has the Add BOM Lines setting selected.
Notes: Interfacing Parent Items and Their Components
  • When configuring your interface to download parent items and their component lines, keep the following in mind:

    - The system will allow you to interface component lines into SCALE (instead of using the "Add BOM Component Lines" wave step to create them). You can achieve this by configuring the Interface Link ID on the component line to have the same value as the Interface Record ID of its parent.

    - For example, suppose it takes two wheels to build a bicycle. You would then want to interface in a total of two lines:

    [line number] - [item] - [quantity] - [identifier]
    1.00 - bicycle (parent item) - 1.0 - Interface Record ID = 1
    1.01 - wheel (component item) - 2.0 - Interface Link ID = 1

    • - Since the Link ID of a wheel is equal to the record ID of the bicycle, the interface will know that the wheels are component items used to make the parent item (the bicycle).

 

 

 

20 - Allocation

 

This wave step is typically one of the first wave steps in your wave flow. It allocates product for shipment allocation lines. It generates work requests for allocation, and also generates container creation opportunities.

 

The multi-threaded allocation process involves having the system determine the number of shipments that it will attempt to allocate at one time (using multiple threads). A value in the Technical Values Window determines the number of shipments that the system will attempt to allocate simultaneously. This, in turn, determines the number of threads that the system will use. For example, if this value is set at 2, the system will concurrently try to allocate two shipments (each on its own separate thread). When the allocation process ends for one shipment, the system will begin allocating another shipment on the available thread. This process continues until all shipments have been allocated.

 

Note that there is a scaled-down version of dock assignment that runs during the allocation wave step. The allocation process only uses the default locations on the dock management flow record to determine the shipping dock location. The system ignores the dock selection and dock assignment strategies. Also, the container creation wave step is not required to be in your wave flow for this version of dock assignment to run successfully. For more information on this type of dock assignment, see the topic Dock Management Process Summary: Process Flows.

 

For detailed information on the allocation wave step, please see the Allocation Process Summary.

 

 

 

 

30 - Complete Wave

 

This wave step will always be the last step in your wave flow. It completes the run wave process. When this wave step is run, the system moves the statuses on the shipments forward; typically, from In Wave to Picking Pending, or whatever the next step in your outbound status flow happens to be.

 

 

 

 

40 - Container Creation

 

This wave step should be placed after the allocation wave step, and before the work creation wave step. The container creation process involves the system creating containers for allocated item quantities. This wave step determines how many container(s) it will create to pack these allocated item quantities. There are four strategies that can be used by this wave step to determine how to distribute quantities into newly-created containers: Consolidate And Do Not Split, Split And Do Not Consolidate, Consolidate And Split Only Once, and 3D Cubing.

 

For detailed information on the container creation wave step, please see the Container Creation in the Wave Process Summary.

 

 

 

 

50 - Load Building

 

This wave step should be placed before the work creation wave step. It assigns shipments to the appropriate shipping load(s). The following is a description of how the system runs the load building process, and a list of requirements for a shipment to use this functionality.

 

Load Building Process

When the user executes a manually-run wave (that includes load building wave step), the system will then attempt to assign all of a carrier's shipments on the wave to a shipping load (using shipment criteria). The system executes this process as follows:

  1. The system will order all of a wave's shipments by carrier and route, ignoring shipments that do not have a carrier assigned.

  2. The system will take each shipment and look for any open loads for the carrier/scheduled ship date/route. If the system finds one, the shipment will be added to that load.

  3. If there are no loads in the system for the carrier/scheduled ship date/route, the system will create a new load for the carrier/scheduled ship date/route, and place the shipment on the new load.
Requirements
  • The route field provides an additional way to differentiate shipments across loads. This is a free-text field, that has no validations, so you can enter any value you please.

  • The load building process updates the scheduled ship date to today's date, when shipment's scheduled ship date is less than today. During load building, the system will try to find an existing load that matches today's date; if it finds one, it will assign the shipment to it. Otherwise, the system will create new load for today's date and assign the shipment to it.

 

 

 

70 - Paperwork Documents

 

The placement of this wave step depends on the type of paperwork documents you are printing. For example, if you are printing only allocation pick lists, then you would place this wave step any time after the allocation step. However, if you are printing an order (work) pick list, then you would place this step after the appropriate work creation wave step. If you are printing only container pack lists, then you would place this step after the container creation or pallet building step (whichever is appropriate). This wave step queues all paperwork set to run during the wave cycle. You can generate both system-defined and custom paperwork documents from a wave.

 

 

 

 

75 - Paperwork Labels

 

The placement of this wave step depends on the type of paperwork labels you are printing. For example, if you are printing only container labels, then you would place this step after container creation or pallet building step (whichever is appropriate). This wave step drives the generation and printing of labels (shipping, vendor) in the wave. When this wave step is executed, the system will generate one file per printer, which is then split by size, based on the “Max Size of a Printed File for Wave Labels (KB)” technical value. The system places these files in the following directory on your application server: \ILS\Printing\WaveLabels. These label files are then sent to the printer(s) for printing. This allows label printing to not adversely affect the execution of other steps in the wave flow. Note that if a wave is canceled, the system deletes these files.

 

 

 

 

80 - Pick Group Creation

 

This wave step should be placed after the container creation wave step. It organizes containers into picking groups. A picking group includes containers for product all picked within the same location range/work zone, as defined in the pick location group configuration. A picking group can be thought of as an apparatus used to pick the product, such as a cart. Note that this wave step runs off container creation records.

 

 

90 - Reject BOM Component Lines

 

This step should be placed immediately after the allocation wave step. It ensures that only whole quantities of a work order's finished item are allocated at the component line level. Suppose the system needed to allocate two tables (two tabletops and eight legs) for an order. However, all that is currently available in the warehouse is two tabletops and five legs. This wave step then would allow the system to reject the extra leg and the extra table top, since it would be impossible to assemble a second table using one tabletop and one leg.

 

 

 

 

100 - Replenishment

 

The placement of this wave step depends on the type of replenishment you are using. This wave step determines the inventory replenishment needs for locations, and generates work requests in order for users to perform this replenishment. When the system runs the replenishment wave step, the system retrieves all of the replenishment masters that are selected on the Wave Master you are using. Note that if you do not use a wave master, and are running automatic replenishment in the wave, the system will run all eligible replenishment masters.

 

For example, if you are allocating based on in transit inventory, then you would place this wave step before the allocation step. However, if you are not allocating using in transit, then you would place this step anytime before the work creation-replenishment step. If you are not creating work and not allocating based on in transit, then you could place this wave step as the very last step before the compete wave step.

 

For more detailed information about the replenishment wave step, see the Replenishment Process Summary.

 

 

 

 

110 - Routing

 

The placement of this wave step depends on what other steps you have included in your flow. Typically, you could place the routing step any number of of places in your flow.

  • If your wave includes load building, routing should occur before load building, as the load building step would otherwise fail if the shipment is not assigned a carrier.

  • If your wave includes consolidate shipments, routing should occur after the consolidate shipments step, since the performance of the routing wave step could be impacted as there probably will be more shipments that the system has to process through.

This wave step attempts to route each shipment with the appropriate carrier, and attempts to generate an estimated shipping rate.

 

For detailed information on the routing wave step, please see the Carrier Management Process Summary.

 

 

 

 

120 - Rule Assignment

 

This step should be placed before the allocation wave step. It attempts to apply each allocation rule assignment record to all shipment lines on the wave (that currently are not associated with a rule).

 

This step works in the following manner:

  • The system uses the Always Override setting on the allocation rule assignment configuration, and attempts to apply each rule in priority sequence.

  • If the Always Override setting is unselected on all the records, then the system will stop when the first rule assigned.

  • However, if the Always Override setting is selected on a higher-numbered priority record that matches the shipment line's criteria, then that rule will override the original rule assigned.

  • It is recommended that you should either leave the Always Override setting unselected, or make certain that you have no overlapping criteria if you are concerned about a higher-numbered priority record overriding a lower-numbered priority record.

 

 

 

130 - Consolidate Shipments

 

The placement of this step depends on what criteria you want to use in your consolidation:

  • If you want to wait until after inventory is allocated to determine whether to consolidate, then place it after the allocation step.

  • If you want to consolidate prior to allocating, place it before the allocation step.

  • If you want the carrier assigned based on the consolidated information, then place this step before the routing step.

  • If the carrier could be different per shipment (which would therefore prevent the consolidation), then you would place this step after the routing step.

This wave step attempts to consolidate shipments with the same consolidation criteria. Note that consolidation during the wave does not consolidate when run after the container creation wave step.  In order to have the system consolidate successfully, you will need to put this step before container creation in your wave flow. Also note that if you cancel the wave or shipment, the system does not undo the consolidation.

 

 

 

 

140 - Start Wave

 

This wave step will always be the first step in the wave flow. It begins the run wave process. When this wave step is run, the system moves the statuses on the shipments forward one step; typically, from Wave Pending to In Wave.

 

 

 

 

150 - Work Creation: Allocation Requests

 

This wave step should be placed after the allocation step. It creates work instructions based on allocation requests.

 

For detailed information on the work creation-allocation requests wave step, please see the Work Process Summary.

 

 

 

 

160 - Work Creation: Shipping Containers

 

This wave step should be placed after the container creation step. It creates work instructions based on shipping containers.

 

For detailed information on the work creation-shipping containers wave step, please see the Work Process Summary.

 

 

 

 

180 - Work Creation: Replenishment

 

This wave step should be placed after the replenishment step. It creates work based on replenishment requests.

 

For detailed information on the work creation-replenishment wave step, please see the Work Process Summary.

 

 

 

 

190 - Work Order Creation

 

This wave step should be placed after the allocation wave step. It creates work orders for any finished items in a wave that could not be allocated. To do this, the system will find any lines on the wave that have a BOM action of "Create Work Order for Rejected Qty." For more information on work orders, see the work order section of the help. When the outbound status action for reject shipments is "Delete Shipments," and BOM action is "Create WO For Rejected Shipment," then rejected shipment lines behave as if the outbound status action for rejected shipments was set to “In Pool.”

 

 

 

 

200 - Pro and BOL Number Assignment

 

This wave step should be placed after the routing step (assuming that the shipment was not downloaded with an assigned carrier). It only assigns a Bill of Lading (BOL) Number if no number is assigned already, and the shipment matches the Pro/BOL Number Criteria as defined on the wave master record.  If there is no Pro/BOL Number Criteria specified on the wave master, or if the wave has only a wave flow specified and no wave master, the system will use the "*Default" data selection record to select the shipments.
 

It only attempts to assign a Pro Number if no Pro Number is assigned already.  The carrier/service needs to have a Pro Number Name assigned in order to assign a Pro Number, and the shipment needs to match the Pro/BOL Number Criteria on the wave master record.  If there is no Pro/BOL Number Criteria specified on the wave master, or if the wave has only a wave flow specified and no wave master, the system will use the "*Default" data selection record to select the shipments.
 

The system will generate a warehouse alert if the Pro Numbers remaining value is less than the configured warning percent (Technical Values Window), and a warehouse alert for the Pro Number warning is configured.

210 - Labor Plan Execution

 

This wave step should be placed after your work creation step. It processes through the configured labor group(s) of the labor plan that was assigned to this wave (either manually or on the wave master). The system selects the shipment lines that meet the labor group criteria (such as a certain work zone's shipments). It will then calculate the estimated time it will take to pick the item quantity for the shipment(s). This time data is then stored on the shipment, and users can view the estimates on the Labor Plan Workbench. Note that this step will use the labor plan that was associated to the wave master.

 

For more information and examples of this process, see the Labor Management Process Summary.

 

 

 

 

220 - Shipment Distribution

 

This wave step needs to be run before the allocation wave step. It consolidates shipment lines with open/existing shipments, or creates new shipments for each detail line. On a line by line basis, the system will take the mark for on each individual detail and search for an open shipment (not yet ship confirmed), with its ship to equal to this mark for. If it finds one, the system will transfer this shipment line onto that shipment, and blank out the mark for address fields on this line. If it does not find one, the system will start a new shipment, using the detail's mark for ID and mark for address information as the ship to ID and ship to addresses of the new shipment. The system will add this line to the new shipment.

 

 

 

 

230 - Pallet Building

 

This wave step needs to be run after the container creation and before the dock assignment and work creation wave step. In the wave flow, the pallet building should be placed between the container creation and work creation steps. If the dock assignment is present in the wave, then pallet building should be placed between container creation and dock assignment. It executes the logic that nests shipping containers onto a pallet, based on several factors, including dimensions, quantity, and item shape. You will only need to palletize shipping containers that are assigned to LTL carriers. This process is not limited to actual pallets. For example, you could also have the wave step place smaller shipping containers into a larger box. For purposes of discussion in the help system, however, this process is referred to as "pallet building" or "palletizing."

 

The system uses pallet building criteria records to determine which shipping containers will be available to nest, such as certain items or an item category. These records can also determine how the worker will containers are grouped onto the pallet.

 

The work unit field (on the work creation master) has to be either Tree Unit or the Tree Unit ID if you are doing pallet building in wave, so that all work instructions for the contents of the pallet are bunched on to a single work unit header. Then, when the last putaway for the work unit is complete, the "create next move" logic determines whether the pallet’s contents are entirely associated with the current work unit. If this is not done, the system bypasses the creation of the dock work for this pallet.

 

 

 

 

 

240 - Dock Assignment

 

This wave step should be placed after the container creation step and pallet building, but before the work creation step. It includes the logic that selects and assigns dock locations to shipping containers/shipment lines. The wave step uses the Dock Location Selection and Dock Location Assignment strategies to perform this function.

 

Please see the Dock Management Process Summary topic (the flow diagram section) for detailed information on how this wave step works.

 

 

 

 

250 - VAS Assignment

 

This wave step should be placed after the container creation step and pallet building step (if either/both are in your flow). It will assign Value Added Services (VAS) activities to all eligible containers that meet the rules defined on the VAS activity criteria records, or activities assigned to shipment/shipment lines (the activities in this case are either interfaced down from the ERP or manually assigned in the pool).

 

 

 

 

260 - QC Assignment

 

This wave step should be placed after the container creation step and pallet building step (if either/both are in your flow). It will assign outbound Quality Control (QC) to all eligible containers that meet the rules defined on the appropriate QC assignment record.

 

 

 

 

270 - Start Wave Statistics

 

This wave step must be the next step after the start wave step. It generates statistics for the Start Wave wave step.

 

The following statistics values are calculated as part of this wave step:

  • Total Shipments

  • Total Lines

  • Quantity Selected

 

 

 

280 - Consolidate Shipments Statistics

 

This wave step must be the next step after the consolidate shipments wave step. It generates statistics for the Consolidate Shipments wave step.

 

The following statistics values are calculated as part of this wave step:

  • Shipments Consolidated

 

 

 

290 - Allocation Statistics

 

This wave step must be the next step after the allocation wave step. It generates statistics for the Allocation wave step.

 

The following statistics values are calculated as part of this wave step:

  • Total Lines
  • Shipments Rejected
  • Lines Partially Rejected
  • Lines Completely Rejected
  • Allocated Quantity
  • Rejected Quantity
  • Immediate Needs Quantity
  • Total Quantity
  • For BOM items on the shipment line, the Total Lines will be updated for each Component line added plus the Parent line. The Allocated Quantity and Rejected Quantity will be updated for each BOM Component line plus the Parent line.

 

 

 

300 - Container Creation Statistics

 

This wave step must be the next step after the container creation wave step. It generates statistics for the Container Creation wave step. Note that if pallet building is included in your wave flow, then the container creation statistics step would be best placed after the pallet building step.

 

The following statistics values are calculated as part of this wave step:

  • Total Containers
  • Pallets
  • Full Containers
  • Loose Containers
  • Total containers = (Pallets created + Full Containers created + Loose Containers created)

 

 

 

310 - Reject BOM Component Lines Statistics

 

This wave step must be the next step after the reject BOM component lines wave step. It generates statistics for the Reject BOM Component Lines wave step. The rejection of the lines will also trigger the counting of a rejection of the parent item. If the lines are partially rejected, then parent will also be counted as partially rejected. If the lines are completely rejected, then parent will be also counted as completely rejected.

 

The statistics values listed below will be updated on the same field values that were created in the Allocation Statistics wave step:

  • Shipments Rejected
  • Lines Partially Rejected
  • Lines Completely Rejected
  • Rejected Quantity

 

 

 

320 - Add BOM Component Lines Statistics

 

This wave step must be the next step after the add BOM component lines wave step. It generates statistics for the Add BOM Component Lines wave step.

 

The statistics values listed below will be updated on the same field values that were created in the Start Wave Statistics wave step::

  • Total Lines
  • Total Quantity

 

 

 

330 - Pallet UM Conversion

 

This wave step must be placed in your wave flow after the allocation wave step, and before the container creation wave step. It involves taking a full UM parent container (such as a pallet) and generating containers to represent its nested child containers. When this wave step executes, the system creates these child containers, so that later the container creation wave step can nest them onto a parent, and writes process history to record the results. Specifically how this works is that the Pallet UM Conversion wave step converts a shipment allocation request to the "next-down" full UM converted quantity.

 

Then later, when the container creation wave step runs, the system inserts a parent container record and nests the converted containers onto the parent (e.g., nesting the cases onto the pallet). This is especially helpful if you process full pallets in your warehouse, since now the nested child containers (included on full pallets) will actually exist in the system. Therefore, you will be able to print vendor compliant labels against them. Note that without the use of this Pallet UM Conversion wave step, a single full pallet container would be created, which will not include any underlying nested cases.

 

Notes
  • In order for this wave step to work, you need a "full" UM container (PL for example) for pallet UM conversion to take place.

  • If either a wave master does not have a Pallet UM Conversion criteria record assigned, or if no wave master is used, then the system uses the *Default Pallet UM Conversion criteria record.

  • Note that it is possible that you could end up with a full UM record from the Pallet UM Conversion which has less than a full UM quantity.  There are two ways this can happen: 

    a) Pallet UM Conversion also looks at the Treat As Full Percent on the unit of measure record to determine how to do the conversion. If this percent value is configured at less than 100% (e.g. 70%), then you could end up with a CS (for example) that has only 70% of the quantity of a full CS.

    b) If your second-level full UM will not convert evenly into the top level UM (e.g., PL=25, CS=10), then you will end up with cases that have less than a full UM quantity.

  • It is recommended that you create/break work (shipping container work criteria > order by) on the Tree Unit value.  Then, set the work unit ID on the work creation master to be Tree Unit ID.  This will give you one work unit per full PL and each CS will be an instruction on the work unit.
