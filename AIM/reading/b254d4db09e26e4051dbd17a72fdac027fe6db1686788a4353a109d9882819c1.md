        <h4 data-source-node="n68">Summary...</h4>
        <p data-source-node="n69">The replenishment process determines when product should be moved from 
 bulk storage locations and transported to forward picking locations. This allows employees to efficiently complete 
 picks for individual orders without compromising the integrity of larger 
 UM increments. Replenishments are triggered by the system when the location's quantity falls below 
 a minimum threshold percent. You can set this percent value at the location
/location type level, or for an item/item class. 
A replenishment generates an allocation request from the 
 bulk location. The product is marked as <i data-source-node="n70">In Transit</i> to the forward location. The allocation of product for the replenishment is managed by the allocation 
 rule defined on the replenishment master. .</p>
        <p data-source-node="n71"> </p>
        <p data-source-node="n72">There are several methods of replenishment, which are described in more detail in the "Scenarios" section of this overview topic. You can research replenishment activity on the History Window. This 
 window will display each decision made during replenishment, including 
 why a replenishment was generated and why a certain location was selected.</p>

        <p data-source-node="n91"> </p>
        <h4 data-source-node="n92">Replenishment Masters...</h4>
        <p data-source-node="n93">All replenishment activity is managed by replenishment master records. 
 You can create multiple records to replenish product to specific warehouse 
 areas at different times.</p>
        <p data-source-node="n94"> </p>
        <p data-source-node="n95"> </p>
        <p data-source-node="n96"> </p>
        <h4 data-source-node="n97">Replenishment Strategies...</h4>
        <p data-source-node="n98">The system uses these strategies to help determine how the replenishment process will attempt to replace product at an inventory location. The following strategies are featured in SCALE:</p>
        <ul data-source-node="n99">
            <li data-source-node="n100"><i data-source-node="n101">Fill The Destination Location</i> 
 - The system will allocate enough product to fill the location, regardless 
 of the value in the Maximum Replenishment Percentage Field on the Item 
 Location Capacity Window.<br data-source-node="n102"><br data-source-node="n103"></li>
            <li data-source-node="n104"><i data-source-node="n105">Round Down To The Previous Whole Number 
 Increment</i> - If the replenishment amount is for less than a full 
 increment (pallet, case, etc), the system will round down and replenish 
 the full increment. For example, if the replenishment amount is for 1.75 
 case, the system will replenish 1 case.<br data-source-node="n106"><br data-source-node="n107"></li>
            <li data-source-node="n108"><i data-source-node="n109">Round Up To The Next Whole Number 
 Increment</i> - If the replenishment amount is for less than a full 
 increment (pallet, case, etc), the system will round up and replenish 
 the full increment. For example, if the replenishment amount is for 1.75 
 case, the system will replenish 2 cases.</li>
        </ul>
        <p data-source-node="n110"> </p>
        <p data-source-node="n111"> </p>
        <h4 data-source-node="n112">Automatic vs. Manual Replenishment...</h4>
        <p data-source-node="n113">Replenishment can be run in two different manners: <br data-source-node="n114"></p>
        <ul data-source-node="n115">
            <li data-source-node="n116"><i data-source-node="n117">Manually</i>: The replenishment process is kicked off by the user from the Inventory Insight.<br data-source-node="n118"><br data-source-node="n119"></li>
            <li data-source-node="n120"><i data-source-node="n121">Automatically</i>: The replenishment process can be kicked off automatically in two ways. One, during the wave, when the replenishment wave step is included in the wave flow. And two,  when the capacity of a location is driven below the minimum percent threshold (when using real time replenishment). </li>
        </ul>
        <p data-source-node="n122"> </p>
        <p data-source-node="n123"> </p>
        <h4 colspan="1" rowspan="1" width="22.717%" data-source-node="n124">Replenishment and Work Creation...</h4>
        <p data-source-node="n125">SCALE supports using replenishment with and without work creation: </p>
        <ul data-source-node="n126">
            <li data-source-node="n127">If a replenishment request is generated from a wave, the system will run the work 
 creation process if its included in the wave step flow, and the replenishment master used to create the request has a Create Work Method of Automatic (it ignores masters defined with other create work methods). If the work creation process is not included in the wave step flow, then no work will be created. Work also could be created at a later time manually in the Replenishment Insight screen.<br data-source-node="n128"><br data-source-node="n129"></li>
            <li data-source-node="n130">If a replenishment request is generated manually (Inventory Insight), whether the system will create work or not depends on what is defined on the replenishment master that was used to create the request. If configured to create work automatically, then the system will kick off the work creation process once the request is generated. If configured to create work manually, then the user can create work for this request in the Replenishment Insight screen.<br data-source-node="n131"><br data-source-node="n132"></li>
            <li data-source-node="n133">If a replenishment request is generated automatically (when the capacity of a location is driven below the minimum percent threshold, and real time replenishment is being used), whether the system will create work or not depends on what is defined on the replenishment master that was used to create the request. If configured to create work automatically, then the system will kick off the work creation process once the request is generated. If configured to create work manually, then the user can create work for this request in the Replenishment Insight screen.<br data-source-node="n134"></li>
        </ul>
        <p data-source-node="n135"> </p>
        <p data-source-node="n136"> </p>
        <h4 data-source-node="n137">Replenishment Insight Screen...</h4>
        <p data-source-node="n138">SCALE also includes a window called the Replenishment Insight screen, which allows the user visibility to open replenishment requests currently in the system. The user can view the information of a specific request from this screen. Also, after a request has been generated, work can be created manually from this screen. The user can "mark" a request for later work creation (which will be processed later via a scheduled job), or indicate that they want work created for this request immediately.</p>
