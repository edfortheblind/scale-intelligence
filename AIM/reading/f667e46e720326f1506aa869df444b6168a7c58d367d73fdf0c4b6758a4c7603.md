        <h4 data-source-node="n70">Basic Process Flow...</h4>
        <p data-source-node="n71"> </p>
        <p data-source-node="n72">The flow below assumes that the personal alerts scheduled job has run, and records have been written to the NOTIFICATION_MESSAGE database table. </p>
        <ol data-source-node="n73">
            <li value="1" data-source-node="n74">First, the process starts when the ILS Monitor Service detects a new record in the NOTIFICATION_MESSAGE database table.<br data-source-node="n75"><br data-source-node="n76"></li>
            <li value="2" data-source-node="n77"> The ILS Monitor Service calls the appropriate delivery mechanism to process the notification record.<br data-source-node="n78"><br data-source-node="n79"></li>
            <li value="3" data-source-node="n80">The defined template is applied to the notification message data, along with any formatting specific to the mechanism (such as maximum length restrictions for SMS text, etc.).<br data-source-node="n81"><br data-source-node="n82"></li>
            <li value="4" data-source-node="n83">The notification message is sent to the appropriate recipient(s). The system marks the notification record in the database as processed (or as an error, if there was a problem sending the notification).</li>
        </ol>
        <p data-source-node="n84">For more detailed information about this process, see the SCALE <a href="81d022a2ab379af5c9e945433d1bd3f6e09728fcfd355546989e79b3a0ecfa54.html" data-source-node="n85">SDK</a>.</p>
