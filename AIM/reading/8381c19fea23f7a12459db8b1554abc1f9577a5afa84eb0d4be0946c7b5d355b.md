
        
        <h1 data-source-node="n56"><a name="kanchor671" data-source-node="n57"></a>Locating Strategies Field</h1>
        <p data-source-node="n58">This field identifies the locating strategy used to determine where 
 checked in product should be located in the warehouse. A locating strategy 
 determines how the system will attempt to locate product, based on one 
 operational requirement or directive.</p>
        <p data-source-node="n59"> </p>
        <p data-source-node="n60"> </p>
        <h5 data-source-node="n61">Locating to Multi-Item Locations...</h5>
        <p data-source-node="n62">The locating process does a volumetric validation when locating an item 
 to a multi-item location. When locating to a multi-item location, the 
 system compares the current volume of the location's items to the total 
 volume of the location to determine if a receipt container will fit. Note 
 that locating to multi-item locations is done purely on the volume and 
 weight of what it is trying to put there vs. the volume and weight of 
 what is already there. Unlike locating to single item locations, there 
 is no calculation performed to figure out how much of something might 
 fit by flipping the item around.</p>
        <p data-source-node="n63"> </p>
        <p data-source-node="n64"> </p>
        <h5 data-source-node="n65">Predefined Locating Strategies...</h5>
        <p data-source-node="n66">The system provides several predefined locating strategies. Each strategy 
 represents a specific system algorithm that the system will use to locate 
 product. If this location is filled, then the system will split off the 
 remaining quantity and try to locate it (if the Split Quantity Checkbox 
 on the Locating Rule Detail Window is selected). See the <a href="4007cca3ce3ca3273f3ee4e6d51d7027ae1816c6f7ce71af9f254400514146aa.html" data-source-node="n67">Locating 
 Overview</a> for a brief description of each strategy.</p>
