        <h4 data-source-node="n65">Summary...</h4>
        <p data-source-node="n66">You can use the interface to transmit records between SCALE and your order 
 system (ERP). Below is a high-level overview about the interface 
 process, including what modes can be used to move data, and what touchpoints 
 are available. You can invoke an interface upload/download by 
 either starting it manually from SCALE, or have the system kick it off automatically 
 via a scheduled job. The interface will process though all the appropriate files/records in order of last modified time (earliest to latest).</p>
        <p data-source-node="n67"> </p>
        <p data-source-node="n68">If there is an error in running an interface job, 
 the system generates detailed error messages (in an XML-file format placed 
 on the server), which can help identify what records failed, and why. 
 Also, interface activity can be researched on the Process History Insight. Note that if you are interfacing more than one file, and the system encounters an error in processing a file's data, the system will continue to process the other files.</p>

        <h4 data-source-node="n106">Interface Modes...</h4>
        <p data-source-node="n107"> </p>
        <p data-source-node="n108">SCALE features the following methods of interfacing data to/from the system:</p>
        <ul data-source-node="n109">
            <li data-source-node="n110"><i data-source-node="n111">Delimited Mode</i>: This method involves data text files (with a user-defined file 
 extension) that the ERP places in a specified directory on your server. 
 When the interface process is initiated, the system retrieves these files, 
 parses the data (based on a data map record), and places the information 
 in a SCALE database table. Typically, you would use this mode if your ERP 
 can export data via text files, and you do not have the business need 
 to communicate directly to the system's database tables. <br data-source-node="n112"><br data-source-node="n113"></li>
            <li data-source-node="n114"><i data-source-node="n115">Fixed Length Mode</i>: This 
 mode is similar to Delimited mode as described above, except that all 
 the values must have a specific length, which is defined on the interface 
 data map record.<br data-source-node="n116"><br data-source-node="n117"></li>
            <li data-source-node="n118"><i data-source-node="n119">Direct Mode</i>: This mode involves writing the data directly to a system database table. 
 The data from the ERP is placed in a temporary database table prior to 
 the interface process being initiated. When the interface process is initiated, 
 the system retrieves the data from this "transfer" table and 
 places it into a SCALE database table. The purpose of these transfer tables 
 is to preserve the integrity of the system database tables.<br data-source-node="n120"><br data-source-node="n121"></li>
            <li data-source-node="n122"><i data-source-node="n123">XML Mode:</i> This mode involves the system retrieving your ERP's XML-formatted data 
 files. These XML files are placed in a specified directory, with a file 
 extension that the system can recognize. When the interface process is 
 initiated, the system parses the data (based on an XML style sheet), and 
 places it in a SCALE database table.</li>
        </ul>
        <p data-source-node="n124"> </p>
        <h4 data-source-node="n125">Interface Actions...</h4>
        <p data-source-node="n126"> </p>
        <p data-source-node="n127">There 
 are four actions that can be used when interfacing records to/from SCALE:</p>
        <ul data-source-node="n128">
            <li data-source-node="n129"><i data-source-node="n130">New</i>: This involves introducing new records to the system, or providing 
 data to the ERP.<br data-source-node="n131"><br data-source-node="n132"></li>
            <li data-source-node="n133"><i data-source-node="n134">Change: </i>This involves updating records already interfaced to the system 
 from the ERP.<br data-source-node="n135"><br data-source-node="n136"></li>
            <li data-source-node="n137"><i data-source-node="n138">Delete:</i>  This involves removing records from the system already interfaced 
 from the ERP.<br data-source-node="n139"><br data-source-node="n140"></li>
            <li data-source-node="n141"><i data-source-node="n142">Save:</i>  This involves updating a current record that the system sees is 
 a duplicate, rather than creating a second record with the updated information</li>
        </ul>
        <p data-source-node="n143"> </p>
        <h4 data-source-node="n144">Supported Touchpoints...</h4>
        <p data-source-node="n145">You can upload and/or download into SCALE the following types of data: Note: Record id need to be unique for each record being downloaded. Cannot have same record id for header and details.</p>
        <p data-source-node="n146"> </p>
        <ul data-source-node="n147">
            <li data-source-node="n148"><i data-source-node="n149">Receiving:</i> The system supports the interfacing of receipt header, detail, and container data between your ERP and the application. SCALE can also return receipt information back to the ERP after the receipt has been processed and its product has been checked into the warehouse. Receipts can be uploaded based on its receipt header, detail, or container status. Also supported are changes/deletions of parts of receipts, such as lone details or containers. In addition, you can also download purchase order header and detail data into SCALE. Duplicate serial numbers are validated  if the "Allow Duplicate Serial Numbers" flag in  the Inventory Control values is set to "N". The validation for the duplicate serial numbers is valid irrespective of the status in which the receipt is being downloaded.<br data-source-node="n150"><br data-source-node="n151"></li>
            <li data-source-node="n152"><i data-source-node="n153">Order/Shipment: </i>The system supports the downloading and uploading of order header, detail, container, and comment data between your ERP and the application. When orders are downloaded, the interface converts them into SCALE-supported shipment and shipment line(s). These shipments then typically would be placed in the shipment "pool," and thus eligible to be placed on a wave. You can download orders directly from your ERP's database table, or from a previously-generated delimited text file or XML file. Note that you can also choose to create order records in SCALE as well as shipments. These orders are used in viewing web data. Also supported are changes/deletions of parts of shipments, such as lone details or containers. In addition, you can define outbound statuses to automatically upload shipment data when the shipment meets a certain trailing status. <br data-source-node="n154"><br data-source-node="n155"></li>
            <li data-source-node="n156"><i data-source-node="n157">Inventory Transactions:</i> Inventory transaction data, such as positive/negative adjustments and transfers, can be uploaded to your ERP via the system interface. This ensures that the ERP keeps its inventory balances aligned with the system's balances.<br data-source-node="n158"><br data-source-node="n159"></li>
            <li data-source-node="n160"><i data-source-node="n161">Item</i>: Item master information can be downloaded from the ERP via the interface. This allows you to populate the item master configuration table, so you do not have to define your products manually in the system.<br data-source-node="n162"><br data-source-node="n163"></li>
            <li data-source-node="n164"><i data-source-node="n165">Item Balance:</i> Item balance data can be uploaded from SCALE to your ERP via the interface. This allows you to reconcile the current item quantities in your warehouse with the ERP's item master table. This is helpful so your ERP has a current and accurate listing of the items in your warehouse and how many are available.<br data-source-node="n166"><br data-source-node="n167"></li>
            <li data-source-node="n168"><i data-source-node="n169">Work Orders</i>:  SCALE allows you to download a work order and all of its component lines. Or, the download could contain just a work order. In this case, the components would be determined by looking up the Bill of Materials for the finished item on the work order and creating the component items in the work order detail based on that.<br data-source-node="n170"><br data-source-node="n171"></li>
            <li data-source-node="n172"><i data-source-node="n173">Bill of Materials</i>: A bill of materials is a listing of the component items and quantities of those items needed to create a finished item through a work order. SCALE allows you to download a finished item and its components, along with the quantity needed to make up the finished item.</li>
        </ul>
