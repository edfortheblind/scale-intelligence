
        
        <h1 data-source-node="n56"><a name="kanchor1914" data-source-node="n57"></a>Configuring DIF HTTP Protocol Properties</h1>
        <p data-source-node="n58">To set up the SCALE Device Integration Framework (DIF), you will need to address some configuration values in the application's database. The third step in this process is to configure the DIF protocol properties. A protocol property record contains the specific HTTP data that is used to define the properties of a DIF endpoint. Note that there is no configuration screen to define protocols in the SCALE Configurations Explorer. You will need to configure these values directly in the application database's HTTP_PROTOCOL_PROPERTIES table.</p>
        <p data-source-node="n59"> </p>
        <p data-source-node="n60">Note: For the changes to the HTTP_PROTOCOL_PROPERTIES table to be reflected, you will need to restart the DIF Processing Service.</p>

        <h4 data-source-node="n77">Procedures...</h4>
        <p data-source-node="n78">Access your application database using a database editing tool such as SQL Server Management Studio.<br data-source-node="n79"><br data-source-node="n80"></p>
        <p data-source-node="n81">Access the HTTP_PROTOCOL_PROPERTIES database table. Each database row represents the properties of a separate DIF endpoint.<br data-source-node="n82"><br data-source-node="n83"></p>
        <p data-source-node="n84">Define values for the following database fields:</p>
        <p data-source-node="n85"> </p>
        <blockquote data-source-node="n86">
            <p data-source-node="n87">OBJECT_ID (numeric 9,0): Represents the object ID.</p>
            <p data-source-node="n88"> </p>
            <p data-source-node="n89">ENDPOINT_ID - (numeric 9,0): Represents the endpoint tied to this protocol. This is a mandatory field.</p>
            <p data-source-node="n90"> </p>
            <p data-source-node="n91">DIF_OUTGOING_ENDPOINT_IDENTIFIER : Represents the unique identifier for outgoing endpoint.</p>
            <p data-source-node="n92"> </p>
            <p data-source-node="n93">RETRY_INTERVAL - (numeric 9,0): Represents the time between retry attempts at reconnecting the endpoint connection</p>
            <p data-source-node="n94"> </p>
            <p data-source-node="n95">RETRY_ATTEMPTS - (numeric 9,0): Represents the maximum number of retries at reconnecting the endpoint connection</p>
            <p data-source-node="n96"> </p>
            <p data-source-node="n97">PROCESS_STAMP (alpha-numeric,100) Represents the process entry record.</p>
            <p data-source-node="n98"> </p>
            <p data-source-node="n99">USER_STAMP (alpha-numeric,100) Represents the user name.</p>
            <p data-source-node="n100"> </p>
            <p data-source-node="n101">USER DEF1 - USER_DEF6 (alpha-numeric, 25): Represents user identified values, similar to other places in the system.</p>
            <p data-source-node="n102"> </p>
            <p data-source-node="n103">USER_DEF7 - USER_DEF8 (numeric 14, 5): Represents user identified values, similar to other places in the system.</p>
            <p data-source-node="n104"> </p>
            <p data-source-node="n105">DATE_TIME_STAMP (datetime): Records the date and time<br data-source-node="n106"><br data-source-node="n107"></p>
        </blockquote>
        <p data-source-node="n108">When finished entering values, commit the changes to the database and exit your database editing tool.</p>
