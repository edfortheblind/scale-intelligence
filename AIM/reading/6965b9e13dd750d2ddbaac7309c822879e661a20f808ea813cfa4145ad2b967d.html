Dock Management Processing

This topic includes procedures that outline dock management-related actions, such as assigning or transferring shipping containers to staging areas/dock doors on your shipping dock. The sections in this topic will discuss how the user will use the system (on the RF device or the Dock Location Transfer Screen) to execute these actions. Note that this topic does not discuss procedures for actions performed on the Dock Manager Window.

Note On The Procedures In This Topic

The following procedural steps are not meant to be a comprehensive breakdown of every permutation of dock management work execution. Rather, it is a sample flow of what would happen in the typical warehouse outbound flow that includes dock management functionality. For more detailed information on such outbound actions as picking, putaway, packing, and closing containers, see the topics Processing RF Work, Packing a Container, and Closing a Container.

 

 

 

 

Processing Containers/Details Through The Packing Area To Dock Locations...

[Performed Via RF Work Execution]

 

Below is the general flow of how a container would travel from an inventory location, to the packing area, and finally to a dock location (either a staging or dock door location). For these procedures, suppose that the container's status flow includes (in part) packing, staging, and loading. A container could be created out of the wave (and then nested into a larger parent container later), or lines could come out of the wave and be packed into containers later in the process. Note that the system currently supports only one packing area dock location. Typically, you would configure this to be your general shipping dock area, and you would create your packing stations as consolidation locations.

 

Procedures
  1. The user signs on to an RF device, and selects the Work option.

  2. On the RF Pick Confirmation screen, the user picks the container/line from an inventory location.

  3. On the RF Putaway Confirmation screen, the user puts away the container/line to the shipping dock (the configured packing area location).

  4. If consolidation after putaway is activated on your work profile, then the user consolidates the container/line to the appropriate consolidation location.

  5. The user ends the RF work session.

  6. If required, another user packs the container/linel.

  7. The user then closes the container. After the container is closed, the system creates the work needed to facilitate the trip required to take the container from the packing area to the destination staging area/position.

  8. The user signs on to an RF device, and selects the Work option.

  9. On the RF Pick Confirmation screen, the user picks the container from the packing area location.

  10. On the RF Putaway Confirmation screen, the user puts away the container to the staging/dock door location .

  11. The user ends the RF work session.

  12. The container now resides on hand at the staging/dock door location. You can access this container from the Dock Manager Window and the Inventory Insight.

 

 

 

Transferring Containers Between Dock Locations...

You can transfer shipping containers between staging and/or and dock door locations. The transfer action will assign, reassign, or pre-assign the shipping container to a dock location. Assigning and reassigning a dock location will adjust the inventory and create dock management work to facilitate the transfer. Pre-assigning a future “to” location will only mark the shipment/shipping container as pre-assigned to the location. No inventory adjustment or dock management work will be created when pre-assigning a future “to” location. Below is the general flow of how a container would be transferred between dock locations (staging areas/positions and dock doors). The example below assumes that the user wants to transfer a container from one staging position to another.

 

Important Notes
  • Transferring containers using this method will always create work. You cannot use this to "immediately" transfer a container. The only way you can do that is to use the RF Immediate Dock Transfer screen.

  • Irrespective of the success or failure of the container transfer (with regards to the assignment of a load to a dock door), the dock door will still remain assigned.

 

Procedures
  1. Assume that a container currently resides on hand at a staging position.

  2. The user selects the container, and selects the Dock Transfer action from the Shipment Insight. The system will display the Dock Location Transfer Screen.

  3. The user enters the destination "to" dock location (in this case, a staging position) and presses Save. The system creates the work to needed facilitate the trip required to take the container from the initial staging position to the destination staging position.

  4. The user signs on to an RF Device, and selects the Work option.

  5. On the RF Pick Confirmation screen, the user picks the container from the staging position location.

  6. On the RF Putaway Confirmation screen, the user puts away the container to the new destination staging position location .

  7. The user ends the RF work session.

  8. The container now resides on hand at a new staging position location.

 

 

 

RF Dock Management Work Execution Note...

The system will submit the RF dock management work execution to an asynchronous (batch) process upon putaway confirmation. Keep in mind that this will not be done if you are using the "nest after putaway" functionality.

 

On the dock management RF pick, the system will:

1. Display the pick screen based on work profile and work special handling.

 

2. On pick confirm the system will:

  1. Validate based on work special handling.

  2. Update the work instructions (mark the instructions to indicate the work has been picked).

  3. Perform no inventory adjustments.

  4. Write the Pick Successful trigger when the Billing Management trigger is active.

  5. Write the Labor Activity for the dock management pick (when labor management is active).

 

On the dock management RF putaway, the system will:

1. Display the putaway screen based on work profile and work special handling.

 

2. On putaway confirm the system will:

  1. Validate based on work special handling.

  2. Submit work execution as asynchronous call (batch job) on validation success.

    I. Validate pick quantity

    II. Validate shipment line status to move exists

    III. If deadlock or other technical failure, then retry based on "number of retries before failure" configuration.

    IV. If retry or validation failure, then:

    - Write failure process history.

    - Rollback transaction to pick and leave assigned to user.

    V. If validation success, then:

    - Confirm work instructions.

    - Move inventory from the "from" location to the "to" location. No equipment location will be used.

    - Write Dock Location Pick & Putaway transaction history.

    - Update shipment, shipment lines, and container.

    - Write the Pick Successful and Dock Management Loading Complete triggers when the Billing Management triggers are active.

    - Create the next dock move.

    - Deactivate the work (i.e., move work to IA_Work_Instruction)

  3. Log the labor activity for the dock management putaway (when labor management is active).

Overriding the putaway location

 

RF

 

- If needed, you can perform putaway location overrides by pressing the Override Location Button on the RF putaway confirmation screen.  Situations where you might want to override the putaway location might include the original destination location was full when you arrived to putaway a container; or, if you want to take a container directly to a dock door if a carrier's trailer is ready to leave the warehouse and is waiting for your container.

 

- If a container is nested onto a pallet, the user can only override if this is the first child container on the parent container (pallet) being put away. If there is already at least one child container already putaway, then you will not be able to override. This is restricted so all containers for a parent container are putaway into the same location.

 

- NOTE: You can toggle the display of the override button on the Security Window (on the Work Execution security record). This is helpful if you do not want to give users the option of overriding the putaway location. 

 

Deleting entities from the shipping dock

 

Shipment Insight screen

Shipping Container Insight screen

 

- Shipments and containers cannot be deleted when active work exists. Active work instructions include work in process and assigned to a user but yet started, and work on a user’s equipment.

 

- Shipping containers must be on hand at a packing area location to be deleted. Note that both the shipping container and shipment line status flow needs changed when transferring a container back to a packing location for unpacking or deleting. The packing pending and in packing statuses must be in the status flow for both the shipping container and related shipment lines.

 

- Shipping loads (which are assigned to a dock door) cannot be deleted unless they are empty (no shipments assigned to the load).

 

Note on closing containers

 

Close Container screen

 

- Creating a new container "on-the-fly" from the Close Container Screen will not create the next dock management move. Work creation currently is not capable of creating work for shipping containers without shipment lines. These containers will automatically be set to ship confirm pending status and cannot be used in dock management.

 

Unassigning loads from a dock door

 

Shipping Load screen

 

 

- You can unassign a shipping load from a dock door only from the Shipping Load Screen. See the topic Creating/Processing a Shipping Load for more details.

 

Note on when the from and to location have the same location subclass

 

  

- The system will not automatically create the next move when the status details for the From and To location have the same location subclass and have the create next move setting selected. The system will write process history describing the failure to create the next move.
