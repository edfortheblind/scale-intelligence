
        
        <h1 data-source-node="n56"><a name="kanchor188" data-source-node="n57"></a>Establishing Vendors</h1>
        <p data-source-node="n58">A vendor record identifies a company that supplies product to your warehouse. 
 You are not required to define vendor records, but they are helpful if 
 you need to contact a vendor concerning an particular receipt. You can 
 create parent and child vendor records. This is usually beneficial if 
 the parent record represents the corporate office and the child records 
 represent different distribution hubs.</p>
        <p data-source-node="n59"> </p>
        <h5 data-source-node="n60">Parent Records, Child Records, &amp; Inheritance</h5>
        <p data-source-node="n61">The parent record represents the corporate headquarters for the vendor. 
 Often, the parent record is also the location where you will send payment 
 for receipts. Each child record represents a distribution hub that sends 
 the receipts to your warehouse. By creating separate records for the corporate 
 office and each distribution hub, you can minimize setup time by using 
 inheritance. Inheritance allows you to default values from the parent 
 record to the child records. The system uses the Vendor, Company, and 
 Ship From values to link the corporate address with the child record.</p>
        <p data-source-node="n62"> </p>
        <p data-source-node="n63">NOTE: If you change an inherited 
 value on a parent record, the system will not automatically apply this 
 change to any existing child records. You would need to manually make 
 the change on each child record.</p>
        <p data-source-node="n64"> </p>
        <p data-source-node="n65"> </p>
        <h5 data-source-node="n66">Do I Need To Create Both Parent &amp; Child Records?</h5>
        <p data-source-node="n67">For the vendor record, you will only want to create both parent and 
 child records a group of distribution centers share the same corporate 
 address. Below are procedures for defining both the parent and the child 
 record.</p>
        <ul type="disc" class="ul_1" data-source-node="n68">
            <li data-source-node="n69">
                <p data-source-node="n70">If you are defining a vendor that 
 does not have a corporate address, just complete the procedures 
 for "Defining the Parent Record."</p>
                <p data-source-node="n71"> </p>
            </li>
            <li data-source-node="n72">If you defining 
 a vendor that has a corporate address and multiple distribution centers, 
 complete the procedures for "Defining the Parent Record" and 
 "Defining a Child Record."</li>
        </ul>

        <h4 data-source-node="n131"><a name="Parent" data-source-node="n132"></a>Defining the Parent Record...</h4>
        <p class="p_15" data-source-node="n133"> </p>
        <h5 data-source-node="n134">Header Fields</h5>
        <p data-source-node="n135">You will use the header fields to identify this vendor. Provide values 
 in the Vendor Field and the Description Field.</p>
        <ol data-source-node="n136">
            <li value="1" data-source-node="n137">
                <p data-source-node="n138">Use the Ship From Field 
 if this parent record also ships product to you . In this case, the parent 
 record represents both a billing address and a supplier. If this parent 
 record does not ship product, don't enter a value here.</p>
                <p data-source-node="n139"> </p>
            </li>
            <li value="2" data-source-node="n140">Select the Parent 
 Check box if this vendor is a parent record.</li>
        </ol>
        <p data-source-node="n141"> </p>
        <h5 data-source-node="n142">General Tab</h5>
        <ol data-source-node="n143">
            <li value="1" data-source-node="n144">
                <p data-source-node="n145">If you are creating a parent record, 
 use the address field to define the corporate address for this company. 
 Use the contact fields (Attention To, Fax Number, etc), to identify personnel 
 that you can contact at the corporate level.</p>
                <p data-source-node="n146"> </p>
            </li>
            <li value="2" data-source-node="n147">If you are not creating a parent record (this is 
 the distribution center), use the address fields to identify the vendor 
 who will directly send you product. Use the contact fields (Attention 
 To, Fax Number, etc.) to identify personnel at this organization that 
 you can contact.</li>
        </ol>
        <p data-source-node="n148"> </p>
        <h5 data-source-node="n149">Using the Verify Item Unit 
 of Measure Checkbox</h5>
        <p data-source-node="n150"> This setting determines if the system 
 will require you to, during the receiving process (processing a receipt from a specific vendor), verify that a received container holds the 
 amount of units as defined on the item's unit of measure record.  This check box can be defined on either the parent record or on  individual child records. Note that if you activate this setting on the  parent record, create child records, and then unselect this setting on the  parent record, it will remain selected on all child records (you  will need to manually remove it from each child record).</p>
        <p data-source-node="n151"> </p>
        <p data-source-node="n152">NOTE: This setting also applies when creating pre-check in receipt containers.</p>
        <p data-source-node="n153"> </p>
        <p class="p_15" data-source-node="n154"> </p>
        <p class="p_15" data-source-node="n155"> </p>
        <h4 data-source-node="n156"><a name="Child" data-source-node="n157"></a>Defining a Child Record...</h4>
        <p class="p_15" data-source-node="n158"> </p>
        <h5 data-source-node="n159">Header Fields</h5>
        <ol data-source-node="n160">
            <li value="1" data-source-node="n161">
                <p data-source-node="n162">In the Vendor Field, provide 
 the same value that you defined in this field on the parent record. The 
 values must be exact, or the system will assume that you are creating 
 a record not associated with the parent vendor.</p>
                <p data-source-node="n163"> </p>
            </li>
            <li value="2" data-source-node="n164">
                <p data-source-node="n165">Use the Ship From Field 
 to identify the distribution center that delivers product to you.</p>
                <p data-source-node="n166"> </p>
            </li>
            <li value="3" data-source-node="n167">
                <p data-source-node="n168">If the parent record's Company 
 Field contains a value, use the pull-down menu here to select that 
 same company. If the parent record did not define a company, you will 
 leave this field blank.</p>
                <p data-source-node="n169"> </p>
            </li>
            <li value="4" data-source-node="n170">You will not be able to provide a value in the 
 Parent Check box. As soon as the 
 system recognizes that this is a child record, it will disable this check box 
 and display the Inherited Check box on each field that can obtain a value 
 from the parent record.</li>
        </ol>
        <p data-source-node="n171"> </p>
        <h5 data-source-node="n172">General Tab</h5>
        <p data-source-node="n173">All inherited values reflect properties defined for the corporate office. 
 These include address and contact information. For each field with an 
 inherited value, determine if this value also applies to the distribution 
 center, which you are defining with this child record. For example, does 
 the distribution share the same address as the corporate office? If it 
 does not, deselect the Inherited Check box. The system will remove the 
 defaulted value from field. You can then identify the distribution center's 
 actual address.</p>
        <p data-source-node="n174"> </p>
        <p data-source-node="n175">The system will associate the parent record's address with the child 
 record via the Vendor Field and Ship From Field values, even when you 
 deselect the inheritance check boxes.</p>
        <p data-source-node="n176"> </p>
        <p data-source-node="n177"> </p>
        <h5 data-source-node="n178">Verify Item Unit of Measure 
 Checkbox</h5>
        <p data-source-node="n179">This check box can be defined on either the parent or child record. See 
 the description in the "Defining the Parent Record" for more 
 details. </p>
