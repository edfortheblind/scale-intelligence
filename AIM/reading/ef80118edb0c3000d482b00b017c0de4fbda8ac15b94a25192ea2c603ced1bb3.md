
        
        <h1 style="text-align: left;font-size: 12pt" data-source-node="n57">Rating System Values</h1>
        <p data-source-node="n58">The rating system values should only be reviewed or edited by a member of your IT staff or a system consultant. The system is shipped with the most common default values which should meet your business needs.</p>

                <td data-source-node="n77">
                    <p data-source-node="n78"><i data-source-node="n79">Allow Multiple Manifests</i>
                    </p>
                    <p data-source-node="n80"> </p>
                </td>
                <td colspan="1" rowspan="1" style="text-align: left;font-style: italic" data-source-node="n81">
                    <p class="p_43" style="text-align: left;font-style: normal" data-source-node="n82">Allow Multiple Manifests Per Day?</p>
                    <p class="p_43" style="text-align: left" data-source-node="n83"> </p>
                </td>
                <td colspan="1" rowspan="1" data-source-node="n84">
                    <p data-source-node="n85">This value indicates whether or not the system will allow more than 
 one manifest per day.<br data-source-node="n86"><br data-source-node="n87">- If this value is set at Yes, 
 you can have more than one manifest for that day (but not open at the 
 same time). For example, you can manifest for awhile, close the manifest, 
 and start a new one for that day.<br data-source-node="n88"><br data-source-node="n89">- If this value is set at No, 
 you can have only one manifest per day. When you close a manifest, and 
 start manifesting again, the system is manifesting for tomorrow and not 
 today.</p>
                    <p data-source-node="n90"> </p>
                </td>
            </tr>
            <tr valign="top" data-source-node="n91">
                <td data-source-node="n92">
                    <p data-source-node="n93"><i data-source-node="n94">Base Shipper From Whs</i>
                    </p>
                    <p data-source-node="n95"> </p>
                </td>
                <td colspan="1" rowspan="1" style="text-align: left;font-style: italic" data-source-node="n96">
                    <p class="p_43" style="font-style: normal" data-source-node="n97">Base Shipper Info From Cross Referenced Warehouse</p>
                    <p class="p_43" data-source-node="n98"> </p>
                </td>
                <td colspan="1" rowspan="1" data-source-node="n99">
                    <p data-source-node="n100">This value indicates if address changes to a warehouse are sent to a 
 cross-referenced Progistics shipper. If you choose <span class="span_1" data-source-node="n101">Yes</span>, 
 the system will send any warehouse address changes to the shipper in Progistics 
 for that warehouse. If you choose     No, 
 the system will not send to Progistics any address changes for the warehouse. 
 This is helpful when many shipper cross references are created within 
 the same warehouse, but they use different companies. The warehouse/company 
 combination could point to a different shipper in Progistics with a different 
 address; therefore, a change to the warehouse address field in the application 
 would not be desired for the Progistics shippers.</p>
                    <p data-source-node="n102"> </p>
                </td>
            </tr>
            <tr valign="top" data-source-node="n103">

                    <p data-source-node="n107"> </p>
                </td>
                <td colspan="1" rowspan="1" style="text-align: left;font-style: italic" data-source-node="n108">
                    <p class="p_43" style="font-style: normal" data-source-node="n109">Default LTL Rating Class</p>

                </td>
                <td colspan="1" rowspan="1" data-source-node="n111">
                    <p data-source-node="n112">This value assigns a default LTL 
 class if the shipment does not already have a class associated with it. 
 This value applies to LTL 
 carriers only.</p>
                    <p data-source-node="n113"> </p>
                </td>
            </tr>
            <tr valign="top" data-source-node="n114">
                <td data-source-node="n115">
                    <p data-source-node="n116"><i data-source-node="n117">FedEx Currency</i>
                    </p>
                    <p data-source-node="n118"> </p>

                    <p class="p_43" data-source-node="n121"> </p>
                </td>
                <td colspan="1" rowspan="1" data-source-node="n122">
                    <p data-source-node="n123">This value indicates currency designator to be used by the FedEx rating 
 software. For example, you would enter the value "USD" to indicate 
 that the FedEx system will use the United States dollars currency to rate.</p>
                    <p data-source-node="n124"> </p>
                </td>
            </tr>

                <td colspan="1" rowspan="1" style="text-align: left;font-style: italic" data-source-node="n130">
                    <p class="p_43" style="font-style: normal" data-source-node="n131">Print UPS Summary Barcode Label Default Checked?</p>
                    <p class="p_43" data-source-node="n132"> </p>
                </td>
                <td colspan="1" rowspan="1" data-source-node="n133">
                    <p data-source-node="n134">This value determines if the system will by default select the Print 
 Summary Barcode 
 Label Checkbox. This checkbox indicates if you want the system to automatically 
 print a UPS summary barcode 
 label after a manifest is closed.</p>
                    <p data-source-node="n135"> </p>

                    <p class="p_43" data-source-node="n143"> </p>
                </td>
                <td data-source-node="n144">
                    <p data-source-node="n145">This value determines if the system will by default select the Print 
 UPS Manifest Checkbox. This checkbox indicates if you want the system 
 to automatically print a UPS manifest document after a manifest is closed.</p>
                    <p data-source-node="n146"> </p>
                </td>
            </tr>
            <tr valign="top" data-source-node="n147">

                    <p data-source-node="n149"><i data-source-node="n150">Pro Number Percentage</i>
                    </p>

                </td>
                <td style="text-align: left;font-style: italic" data-source-node="n152">
                    <p class="p_43" style="font-style: normal" data-source-node="n153">Pro Number Range Remaining For Alert to be Given</p>
                    <p class="p_43" data-source-node="n154"> </p>
                </td>
                <td data-source-node="n155">
                    <p data-source-node="n156">This value determines the percentage of pro numbers remaining before 
 the system runs out. When this percentage is reached, the system will 
 send a warehouse alert that tells the user that a new range of pro numbers 
 is needed.</p>

                </td>
            </tr>

                    <p data-source-node="n175"> </p>
                </td>
                <td data-source-node="n176">
                    <p width="82.95%" data-source-node="n177">This value determines if the system will submit the close manifest process as a batch process. Note that if this value is set to Yes, and  re-manifesting is required, the system will perform this as part of the batch process as well. Also note that the system will not display any errors encountered during the batch process to user (the system will instead log these as process history records). </p>
