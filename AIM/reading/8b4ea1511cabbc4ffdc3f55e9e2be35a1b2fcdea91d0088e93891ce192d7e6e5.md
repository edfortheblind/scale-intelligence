        <h4 data-source-node="n121"><a name="access" data-source-node="n122"></a>RF Screen and the Relationship to Inventory Attributes Records...</h4>
        <p data-source-node="n123">Whether or not the system can display inventory attributes for certain location inventory is based on an RF screen’s relationship with the underlying data displayed on the screen. Below are explanations of these two types of data relationships.</p>
        <ul data-source-node="n124">
            <li data-source-node="n125">One-To-One (attributes viewable):  In this relationship there is a single record representing the data displayed on the RF screen.  For example, suppose you have a pick for a work unit with a single work instruction.  All the data displayed on the RF Pick Confirmation screen would be drawn from the data found on that work instruction. Therefore, the system can access the attributes from the inventory and display them on the RF screen.<br data-source-node="n126"><br data-source-node="n127"></li>
        </ul>
        <ul data-source-node="n128">
            <li data-source-node="n129">Many-To-One (attributes not viewable):  In this relationship, there are multiple records representing the data displayed on a single RF screen.  For example, suppose you have a batch pick with the "Group Picks by Loc/LP" setting enabled on the user’s Work Profile. This work unit will have multiple work instructions for the same item at the same location for multiple orders. Therefore, the system cannot access the attributes from the inventory, and willnot display them on the RF screen.</li>
        </ul>
        <p data-source-node="n130"> </p>

        <h4 data-source-node="n134"><a name="generalProc" data-source-node="n135"></a>General RF Screen Procedures...</h4>
        <p data-source-node="n136">The procedures below outline how you would use the Inventory Attributes RF screen, no matter where you access from in the system. You can use these procedures to capture, edit, or delete attribute values. </p>
        <ol data-source-node="n137">
            <li value="1" data-source-node="n138">Press the Attributes button from an RF processing screen.<br data-source-node="n139"><br data-source-node="n140"></li>
            <li value="2" data-source-node="n141">The system will open the first page of the Inventory Attributes screen, which displays the first five attribute values. Note that the system will display only five attributes fields per RF screen. <br data-source-node="n142"><br data-source-node="n143"></li>
            <li value="3" data-source-node="n144">Provide a value for the attribute field(s) that you want to capture/edit. Note that some screens only support the viewing of attribute values.<br data-source-node="n145"><br data-source-node="n146"></li>
            <li value="4" data-source-node="n147">Now select one of the action buttons:<br data-source-node="n148"><br data-source-node="n149">- Prev: The system will take you back to the previous page of attribute values. Note that this button will be inactive when you are viewing the first attributes page.<br data-source-node="n150"><br data-source-node="n151">- Next: The system will take you forward to the next page of attribute values. Note that this button will be inactive when you are viewing the last attributes page.<br data-source-node="n152"><br data-source-node="n153">- Save: The system will save the attribute value(s) that you have captured/edited (on screens where these actions are supported). Note that you only need to press this button once, even if you have added/edited values on multiple attribute pages, since the system saves all 20 attribute values at one time. Also, attribute value additions/changes cannot be saved in locations where allocated/in transit/suspense quantities exist for that inventory. In addition, you need the Edit security touchpoint enabled for the Save button to be available. <br data-source-node="n154"><br data-source-node="n155">- Cancel: The system will close the Inventory Attributes screen, without saving any value(s), and return you to the previous processing screen. </li>
        </ol>

        <h4 data-source-node="n173"><a name="receiving" data-source-node="n174"></a>Capturing Attributes - RF Receiving Check In...</h4>
        <p data-source-node="n175">You can capture attributes for inventory coming into your warehouse using the RF receiving check-in process. The system includes two receiving workflows (that includes the RF inventory attributes screen)  that are based on the header-item initiation method.  You can implement these workflows into your receiving process, or you can create custom inventory attributes workflows based on them. Note that you will have to manually create records in the RF Receiving Check In Initiation configuration in order to use these attribute workflows.</p>
        <p data-source-node="n176"> </p>
        <p data-source-node="n177">The two inventory attribute workflows that are included with the system are the following:</p>
        <ul data-source-node="n178">
            <li data-source-node="n179">Header-Item Inv Attrib<br data-source-node="n180"><br data-source-node="n181"></li>
            <li data-source-node="n182">
                <p data-source-node="n183">Inv Attrib Flow GS1</p>
            </li>
        </ul>
        <p data-source-node="n184"> </p>
        <h5 data-source-node="n185">Functional Notes</h5>
        <ul data-source-node="n186">
            <li data-source-node="n187">The RF check in process will prompt the user to capture inventory attributes after a license plate has been assigned.<br data-source-node="n188"><br data-source-node="n189"></li>
            <li data-source-node="n190">If you do not capture any attributes when prompted, the system will check in and locate the receipt container without attributes. <br data-source-node="n191"><br data-source-node="n192"></li>
            <li data-source-node="n193">When using the RF Inventory Attributes screen in capture mode, the system will not filter the attributes based on the "RF Inventory Attributes – Filter" exit point.<br data-source-node="n194"><br data-source-node="n195"></li>
            <li data-source-node="n196">See the <a href="#generalProc" data-source-node="n197">General Screen Procedures</a> section for more specific information on how to use the attributes screen.<br data-source-node="n198"><br data-source-node="n199"></li>
            <li data-source-node="n200">You can create your own pre-defined inventory attribute values that the user can select from on the RF Check In screen. See <a href="3afe0a0e91c3be424098655a59ac0655672a919ff3ef1c0b6cfc3c6a56a8444d.html" data-source-node="n201">Creating Inventory Attribute Values</a> for more details.<br data-source-node="n202"></li>
        </ul>

        <h5 data-source-node="n212">Functional Notes</h5>
        <ul data-source-node="n213">
            <li data-source-node="n214">The system requires that you save at least one attribute field value (you cannot save zero attribute values).<br data-source-node="n215"><br data-source-node="n216"></li>
            <li data-source-node="n217">You can create your own pre-defined inventory attribute values that the user can select from on the RF Location Inquiry screen. See <a href="3afe0a0e91c3be424098655a59ac0655672a919ff3ef1c0b6cfc3c6a56a8444d.html" data-source-node="n218">Creating Inventory Attribute Values</a> for more details.</li>

        <h4 data-source-node="n223"><a name="invMgmt" data-source-node="n224"></a>Viewing Attributes - RF Inventory Management...</h4>
        <p data-source-node="n225">You can view attributes for inventory that resides in warehouse locations using the RF Inventory Management screen (when it is accessed from the RF Location Inquiry results screen, and initiated by item/location). The attributes are visible from this screen since it displays inventory that has a one-to-one relationship with inventory attributes. </p>
        <p data-source-node="n226"> </p>
        <p data-source-node="n227"> </p>
        <h5 data-source-node="n228">Functional Notes</h5>
        <ul data-source-node="n229">
            <li data-source-node="n230">On the RF Inventory Management screen, the Attributes button is visible for all adjustment types.<br data-source-node="n231"><br data-source-node="n232"></li>
            <li data-source-node="n233"> On the RF Inventory Management screen, the Attributes button is not visible when inventory management is initiated by license plate. <br data-source-node="n234"><br data-source-node="n235"></li>
            <li data-source-node="n236">On the RF Inventory Management screen, the Attributes button is not active if the location inventory is not linked to inventory attributes.<br data-source-node="n237"><br data-source-node="n238"></li>
            <li data-source-node="n239">On the RF Inventory Management screen, the Attributes button is not visible when you access RF Inventory Management directly from the RF Main Menu. <br data-source-node="n240"><br data-source-node="n241"></li>
            <li data-source-node="n242">When you access RF Inventory Management directly from the RF Main Menu, and perform a positive/negative adjustment, the system will adjust inventory at the location without inventory attributes. <br data-source-node="n243"><br data-source-node="n244"></li>
            <li data-source-node="n245">   On the RF Inventory Management screen, when transferring inventory or changing inventory statuses, the system will notify you that the inventory does not exist if the system has one or more location inventory records linked to inventory attributes.</li>
        </ul>

            <li data-source-node="n260">

            </li>
            <li data-source-node="n264">On the RF Cycle Count Reconcile screen, the Attributes button is enabled when the cycle count request is linked to inventory attributes. It is not active when the request is not linked to attributes.</li>

        <p data-source-node="n271">You can view attributes for inventory when performing RF picking or putaway work confirmation.</p>
        <p data-source-node="n272"> </p>
        <p data-source-node="n273"> </p>
        <h5 data-source-node="n274">Functional Notes</h5>
        <ul data-source-node="n275">
            <li data-source-node="n276">On the RF Pick and Putaway Work Confirmation screens, the Attributes button is visible when the work instruction (shipment/receiving/inventory management/replenishment) is linked to inventory attributes. The system uses the From Inventory Attribute field on the work instruction to determine whether to display the Attributes button on these screens.<br data-source-node="n277"><br data-source-node="n278"></li>
            <li data-source-node="n279">
                <p data-source-node="n280">On the RF Pick Work Confirmation screen, the Attributes button is not visible when the "Group Picks by Loc/LP" setting is enabled on your work profile, since this scenario has a many-to-one relationship between the work instructions and the screen.<br data-source-node="n281"><br data-source-node="n282"></p>
            </li>
            <li data-source-node="n283">On the RF Putaway Work Confirmation screen, the Attributes button is not visible when work instructions are grouped during RF Putaway, since this scenario has a many-to-one relationship between the work instructions and the screen.<br data-source-node="n284"><br data-source-node="n285"></li>
            <li data-source-node="n286">
                <p data-source-node="n287">On the RF Pick and Putaway Work Confirmation screens, the Attributes button is not visible when work units are “grouped by inventory attributes” in group user mode on your work profile, since this scenario has a many-to-one relationship between the work instructions and the screen.</p>
            </li>
        </ul>

If you need more technical information on this exit point, please see the exit point section of the <a href="81d022a2ab379af5c9e945433d1bd3f6e09728fcfd355546989e79b3a0ecfa54.html" data-source-node="n295">SCALE SDK</a>.</p>

            <li data-source-node="n302">This filter is honored when the RF Inventory Attributes screen is accessed from the following screens: RF Location Inquiry, RF Inventory Management, RF Cycle Count, and RF Pick and Putaway.</li>

        <h4 data-source-node="n386"><a name="verifyingRF" data-source-node="n387"></a>Verifying Inventory Attributes on the RF Inventory Attributes Screen...</h4>
        <p data-source-node="n388">You can configure the system to make the user verify inventory attributes during the RF Pick and Putaway Confirmation actions. This is done by enabling the "RF Inventory Attributes - Verify" exit point. This exit point functions for the following type of work execution: shipment, receiving, inventory management, and replenishment. Then, during RF work execution, the system will automatically display the RF Inventory Attributes screen (in verify mode) when you press OK on the confirmation screens, IF the attribute values have not been successfully verified. The system will prompt for verification one attribute value at a time. After you have verified an attribute value, the system hides it and displays the verification field for the next attribute value. The system will display an error if the verification value does not meet the attribute value, or if the verification value is left blank. Finally, after you have successfully verified all of the attribute value(s), the system will then permit the pick/putaway confirmation.</p>
        <p data-source-node="n389"> </p>
        <h5 data-source-node="n390">Functional Notes</h5>
        <ul data-source-node="n391">
            <li data-source-node="n392">Note that you will need "Run" security access for the RF Inventory Attributes page to have the ability to verify attributes (the system is shipped giving all users security access to this action).</li>
        </ul>
        <p data-source-node="n393">Example:</p>
        <ol data-source-node="n394">
            <li value="1" data-source-node="n395">Suppose that you want the user to verify the inventory attributes after a pick or putaway is performed. Also, in the example below, suppose the "filter" exit point (explained earlier in this topic) is enabled as well.<br data-source-node="n396"><br data-source-node="n397"></li>
            <li value="2" data-source-node="n398">Then suppose you have the "verify" exit point enabled.<br data-source-node="n399"><br data-source-node="n400"></li>
            <li value="3" data-source-node="n401">The system then displays the RF Inventory Attributes screen, with a verify field under the first attributes edit box. You would enter the first validation value, and press the TAB button. The system then will validate that value, and if it is correct, display the verify field for the next attribute. If it is not the correct value, the system will display an error message, and you will have to enter the correct value.</li>
        </ol>
