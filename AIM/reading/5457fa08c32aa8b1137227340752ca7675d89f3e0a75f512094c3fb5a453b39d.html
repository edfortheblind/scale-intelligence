Status Process Summary

** Functionality **

 

 

Summary...

The system uses statuses to determine at what stage of processing an entity currently is at in your warehouse. Statuses for inbound processing identify the current processing state of a receipt or receipt line; statuses for outbound execution perform this task for a shipment or a shipment line. For both functional areas, the status is defined on the line. As different processes are committed against that line, its status changes. The header record, either the receipt or the shipment, identifies the most and least advanced statuses assigned to its lines. This allows you to quickly assess the general status of the entire receipt or shipment.

 

 

 

Related Topics...

- Setup Overview

 

 

 

Status Flows...

A status flow is a defined sequence of statuses grouped together to manage processing. It determines which procedures will be completed against a specific line record (receipt, shipment). Status flows are defined at the line level; this allows you to accommodate item level requirements.   When the system processes a flow, it executes each status (number) in sequential order. For example, status 100 is completed before status 101. The system will require that a status is completed before a new one is initiated.

 

 

 

How Status Flows Work...

  1. All status flows are assigned at the line level. If it is not defined, the system will assign the default flow.

  2. When a detail is interfaced to the system, the system will determine how its processed based on its status flow.

  3. The system will process the line through the statuses in the flow.

  4. As the line is processed, the system will update its "parent" entity (receipt/shipment) to reflect is progress. These records include two status fields: the Trailing Status Field and the Leading Status Field.

  5. As the shipment's/receipt's containers move through the functional area's major processes, the system cycles through the statuses.

 

 

Default Status Flow...

The default status flow is automatically assigned to all line records (for shipments and receipts) that are not associated with a custom status flow. Therefore, the default status flow should accommodate the majority of products that you process.

 

 

 

Inbound Statuses (default)...

Below are all of the Inbound Processing default statuses:

  • (100) Check In Pending: The receipt has arrived at the warehouse and is awaiting check in.

  • (200) Locate Pending: The units on at least one receipt line were checked in. The container(s) created during check in are awaiting locating.

  • (300) Putaway Pending: The containers were located and work creation generated putaway instructions for them. The containers are awaiting work execution to be called. The containers are brought to their storage locations during work execution.

  • (301) In Putaway: Work creation generated putaway instructions for the container(s). Someone has begun transporting the container(s) from the receiving dock to the storage location(s) selected during locating.

  • (900) Closed: All receipt lines for this receipt have been checked in and located. If the work creation was called, the container(s) have been physically moved to storage location(s). If work creation was not called, locating has selected storage locations for the container(s). In other words, if you do not require work creation, the container will move from status 200 to status 900, provided no custom default statuses are not added.

 

 

Outbound Statuses (default)...

Below are all of the Outbound Execution default statuses:

  • (90) In Pool Pending: The shipment's status before it is processed via the interface. The purpose of this status is to be a temporary status used by the interface download process to ensure that shipments do not get picked up for processing while the interface process is running. Also, shipments in this status cannot be added to a wave.

  • (100) In Pool: The shipment has not been processed in a wave, but has been created in the pool or downloaded via the interface. No work can be performed against this shipment.

  • (200) Wave Pending: The wave is being built. It has not been run.

  • (201) In Wave: A wave run was initiated and the wave has not been released.

  • (300) Picking Pending: A wave was released, but none of the work has been initiated.

  • (301) In Picking: At least one work instruction associated with this shipment has been assigned to an employee.

  • (400) Packing Pending: At least one work instruction associated with this shipment has been pick confirmed. It can now be packed.

  • (401) In Packing: At least one work instruction associated with this shipment has been packed.

  • (600) Staging Pending: All items of a shipment have been picked, packed, and/or consolidated.

  • (650) Loading Pending: All items of a shipment have been picked, packed, or consolidated, and/or staged.

  • (700) Ship Confirm Pending: At least one container associated with this shipment has been closed.

  • (800) Load Confirm Pending: All shipments on the load have been ship confirmed and the load is ready to be confirmed.

  • (900) Closed: The shipping load has been confirmed.

  • (990) Delivered: A shipment or parcel has been delivered to it's intended recipient through the system.

  • (994) Complete Rejected To Pool: System uses this in the status action to indicate that if the entire shipment cannot be allocated it will send it back to the pool.

  • (995) Finished Item Is Allocated: Assigned to a component line when its parent item has been allocated by the system.

  • (996) Component Item Is Allocated: Assigned to a parent item when the system could not allocate it, but all of its component item(s) were allocated.

  • (997) Immediate Need Pending: There is at least one shipment line that is ties to an outstanding immediate need.

  • (998) Delete Rejected: A quantity on a shipment line was rejected. The quantity will be deleted from the system.

  • (999) Rejected: During allocation, if any quantity on the line is rejected, this status will indicate that rejected quantity.

 

 

Custom Statuses...

The system also supports custom statuses, which are created especially for your specific business processes. Like a default status, a custom status is a process committed against either a shipment or a receipt, based on functional area.

 

Custom Status Flow

A custom status flow allows you to address unique processing requirements for a specific line. It must be associated with the line record before its interfaced to the system. Although its assigned before the line is interfaced, this flow must also be defined in the system on the Custom Status Flow Window. Custom status flows can accommodate any value on either the top level or line level. For example, many companies create a custom outbound execution status flow to accommodate emergency or rush orders. If the shipment line identifies the "Rush" flow in the Status Flow Field, this line (and its containers) will be processed using this custom status flow. A rush custom status flow probably does not require new statuses. Instead, it includes fewer statuses than the default status flow to streamline processing for time sensitive shipments or receipts. As the line is processed through the system, the system updates the top level record's trailing and leading status values. If this line is the least advanced line for the entity (receipt or detail), its status will be the header's trailing status. 

 

 

 

Trailing & Leading Statuses...

These values are defined on the top level record (receipt/shipment). The trailing status is the least advanced status associated with the record; the leading status is the most advanced status associated with the record. The system obtains this information from the containers created for the entity. You can use this information to research container activity and perform troubleshooting tasks.
