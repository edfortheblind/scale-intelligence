
        
        <h1 data-source-node="n56"><a name="kanchor1601" data-source-node="n57"></a>Defining Replenishment Master Records</h1>
        <p data-source-node="n58">A replenishment master record helps define how a replenishment request 
 is generated. It specifies the parameters for replenishing product based 
 on either location need or demand generated for a wave/order pool. You 
 can also create or edit the sequence records for a replenishment rule. 
 Each sequence rule identifies how the system will perform replenishment 
 (strategy).</p>

        <h4 data-source-node="n143"><a name="Basic" data-source-node="n144"></a>Basic Replenishment...<br data-source-node="n145"></h4>

        <h5 data-source-node="n147">Using 
 the Header Fields</h5>
        <ol data-source-node="n148">
            <li value="1" data-source-node="n149">
                <p data-source-node="n150">Provide a name and description.</p>
                <p data-source-node="n151"> </p>
            </li>
            <li value="2" data-source-node="n152">
                <p data-source-node="n153">Use the Replenishment Type Field 
 to identify which records the system will attempt to run replenishment 
 against.</p>
                <p data-source-node="n154"> </p>
            </li>
            <ul type="disc" class="ul_1" data-source-node="n155">
                <li data-source-node="n156">
                    <p data-source-node="n157">If you select Item 
 Location Capacity, the system will run replenishment based 
 on location need. This replenishment type is often used to replenish forward 
 locations depleted during by an earlier work crew. Note that this replenishment type uses the "Minimum Replenishment Threshold" value (defined on the item location capacity record) during processing.<br data-source-node="n158"><br data-source-node="n159"></p>
                </li>
                <li data-source-node="n160">If you select Top-Off Item 
 Location Capacity, use this type if you want to generate replenishment 
 requests based on location need. Note that this replenishment type uses the "Top-Off Minimum Replenishment Threshold" value (defined on the item location capacity record) during processing.<br data-source-node="n161"><br data-source-node="n162"></li>
                <li data-source-node="n163">
                    <p data-source-node="n164">If you select Demand 
 From Pool, the system will run replenishment based on item 
 demand in the pool. This replenishment type allows you to prepare for 
 upcoming demand. Note that this replenishment type uses the "Minimum Replenishment Threshold" value (defined on the item location capacity record) during processing.<br data-source-node="n165"><br data-source-node="n166"></p>
                </li>
                <li data-source-node="n167">If you select 
 Demand From Wave, the system will run replenishment 
 based on item demand in the wave that is run. Note that this replenishment type uses the "Minimum Replenishment Threshold" value (defined on the item location capacity record) during processing.<br data-source-node="n168"><br data-source-node="n169"></li>
                <li data-source-node="n170">If you select Demand From RF Outbound Short Pick, the system will run replenishment based on item demand from a location that has been short picked (if the user is configured to allow this via their work special handling settings). Note that this replenishment type does not allow you to configure for this master the Create Work Method (it is always set to automatic), the Replenishment Criteria (since the item and location are already known to the system), or the Replenishment Modes. Note that this replenishment type uses the "Minimum Replenishment Threshold" value (defined on the item location capacity record) during processing.</li>
            </ul>
        </ol>
        <p data-source-node="n171"> </p>
        <h5 data-source-node="n172">Using the General Tab<br data-source-node="n173"></h5>
        <p data-source-node="n174">The general tab fields tie together the different components required 
 to generate a replenishment request.</p>
        <ol data-source-node="n175">
            <li value="1" data-source-node="n176">
                <p data-source-node="n177">Use the Priority Field to 
 identify when this record should be selected, in relation to the other 
 replenishment master records. When replenishment is initiated, the system 
 cycles through these records in priority order. The lower the priority 
 number, the sooner the record is used: the record with priority 1 is processed 
 before the record with priority 2. Note that the system will process a 
 record with a priority of 0                     after 
 all other records have been processed.</p>
                <p data-source-node="n178"> </p>
            </li>
            <li value="2" data-source-node="n179">Use the Replenishment Increment 
 Field to identify the UM that 
 the system will replenish to the location. In the screen diagram above, 
 the Case UM is selected. The system will therefore bring forward only 
 cases to locations using this record.<br data-source-node="n180"><br data-source-node="n181"></li>
            <li value="3" data-source-node="n182">Use the Allocate All UMs to Clear Reserve Location Checkbox to determine if the system will look for all the units of measure in an allocation location inventory record to "clean up" the location during the replenishment allocation process. Keep in mind that this allocation happens in the order of the highest unit of measure to the lowest unit of measure. See the <a href="606e1459e06bc150de48933e37127841149d553565630bb8b216331a4442d575.html" data-source-node="n183">field topic</a> to see an example of this functionality.<br data-source-node="n184"><br data-source-node="n185">NOTE: This functionality is applicable only if the “Clear Location” (on the allocation rule detail) setting is active as well.<br data-source-node="n186"><br data-source-node="n187"></li>
            <li value="4" data-source-node="n188">
                <p data-source-node="n189">Use the Allocation Rule Field 
 to identify the allocation rule that you want to apply to this record. 
 During replenishment, the system will use this value to select the from 
 location(s) for this replenishment transaction. If you leave this field 
 blank, the system will use the allocation rule associated with the item.</p>
                <p data-source-node="n190"> </p>
            </li>
            <li value="5" data-source-node="n191">
                <p data-source-node="n192">Use the Demand UMs Checkboxes 
 to identify what unit of measure(s) the system will check for replenishment 
 need. In the graphic above, the unit of measure selected is Each. Therefore, 
 the system will only check to see if eaches need to be replenished in 
 the location or pool. These checkboxes are not available if the replenishment 
 type is Use Item Location Capacity.</p>
                <p data-source-node="n193"> </p>
            </li>
            <li value="6" data-source-node="n194">Use the Create 
 Work Method Checkbox to indicate how you want replenishment requests to be processed.<br data-source-node="n195"><br data-source-node="n196"></li>
            <ul type="disc" class="ul_1" data-source-node="n197">
                <li data-source-node="n198">
                    <p data-source-node="n199">Automatic: With this option, the replenishment process will allocate the inventory, generate the replenishment requests for eligible locations and mark the inventory as In Transit to the destination location. Work Creation is called directly after replenishment (or during the same wave for Demand Replenishment) and the system creates work  for these requests. If it cannot create work, the system deletes the requests and sets the inventory back to Available at the From Location.<br data-source-node="n200"><br data-source-node="n201"></p>
                </li>
                <li data-source-node="n202">Manual/Scheduled Job: With this option, the replenishment process will allocate the inventory and generate replenishment requests for eligible locations. The inventory is marked as In Transit to the destination location. The process will stop there, and it will be up to the user to manually kick off work creation for request(s) in the Replenishment Insight screen. From the viewer the user can either create work on the fly (the Create Work Immediately option) or mark it so the scheduled job picks it up (Mark for Work Creation option).<br data-source-node="n203"><br data-source-node="n204"></li>
                <li data-source-node="n205">None: With this option, the system will allocate the inventory and generate replenishment requests for eligible locations, execute those requests (which marks the quantity On Hand at the destination location), and then generate a Replenishment Pick List (if paperwork is setup properly). You would then use this document to perform the actual inventory movements.<br data-source-node="n206"><br data-source-node="n207"></li>
            </ul>
            <li value="7" data-source-node="n208">Use the Consolidate Replenishment Requests Checkbox to indicate that the system can consolidate replenishment requests that were created using this master. When this setting is active, the system will analyze each request and determine if the requests share the following criteria: Item/Company, To/From Warehouse, To/From Location, License Plate (at the From Location), and Lot (if applicable). If any requests share this criteria, then the system will determine if the To Location can physically handle combining the requests. If it can, the system will consolidate the requests. If the To Location cannot support the consolidation amount, then the system will create a new request.<br data-source-node="n209"><br data-source-node="n210">- This option is only available if you using the create work method of Manual/Scheduled Job. Note that this setting will consolidate across replenishment types and origination modes (as defined on the Replenishment Modes Tab of this window).<br data-source-node="n211"><br data-source-node="n212">- If this setting and the Create Multiple Requests For Excess Demand Checkbox are both selected, then the system will honor the user's desire to create requests that do not exceed the percentage that the To Location can hold.<br data-source-node="n213"><br data-source-node="n214">- If the system consolidates across different replenishment types, the request will take on the characteristics of the request from the replenishment master with the highest priority.<br data-source-node="n215"><br data-source-node="n216"></li>
            <li value="8" data-source-node="n217">Use the Create Multiple Requests For Excess Demand Checkbox if you want the system to only replenish to a permanent location instead of creating requests for empty location. This will only come into play when the replenishment quantity is greater than the amount that the location can support. See the <a href="85ec2419785a52c47bcc5c731ab5befe487564c8519677f9dc45e56e775b4783.html" data-source-node="n218">field topic</a> for more information on this setting.<br data-source-node="n219"></li>
        </ol>
        <h5 data-source-node="n220"> </h5>
        <h5 data-source-node="n221">Using the Replenishment Criteria Tab<br data-source-node="n222"><br data-source-node="n223"></h5>
        <p data-source-node="n224">You will use this tab to indicate which location(s) and/or item(s) that you want the system to consider for replenishment.</p>
        <ol data-source-node="n225">
            <li value="1" data-source-node="n226">
                <p data-source-node="n227">Use the Location Criteria Field to identify the replenishment location criteria 
 record that you want to associate with this record. This record 
 determines which location(s) the system will consider for replenishment. 
 The purpose of this record depends on the replenishment type:</p>
                <p data-source-node="n228"> </p>
            </li>
            <ul type="disc" class="ul_1" data-source-node="n229">
                <li data-source-node="n230">
                    <p data-source-node="n231">If the Use Item Location Capacity 
 Type is selected, this record determines which locations that system 
 will check for possible replenishment. In this case, any possible replenishment 
 is based on the needs of locations identified on the replenishment location 
 criteria record.</p>
                    <p data-source-node="n232"> </p>
                </li>
                <li data-source-node="n233">
                    <p data-source-node="n234">If either the Use Demand From 
 Pool Type or Use Demand From Wave Type is selected, this record 
 just determines which locations the system can replenish. Whether or not 
 a replenishment is required is dependent on demand from the pool or wave.</p>
                    <p data-source-node="n235"> </p>
                </li>
            </ul>
            <li value="2" data-source-node="n236">
                <p data-source-node="n237">Use the Empty Location Criteria 
 Field to identify which location, 
 or group of locations, the system can replenish to if the either of the 
 following situations occur:</p>
                <p data-source-node="n238"> </p>
            </li>
            <ul type="disc" class="ul_1" data-source-node="n239">
                <li data-source-node="n240">
                    <p data-source-node="n241">The amount of product that 
 you have to replenish exceeds the locations available for replenishment. 
 After the system replenishes to all of the locations that currently contain 
 the product, this field identifies the next location(s) that it can replenish 
 to.</p>
                    <p data-source-node="n242"> </p>
                    <p data-source-node="n243">OR</p>
                    <p data-source-node="n244"> </p>
                </li>
                <li data-source-node="n245">No locations 
 currently contain the item that you need to replenish. The system 
 uses this field to determine where to start replenishing.</li>
            </ul>
            <p data-source-node="n246"> </p>
            <li value="3" data-source-node="n247">
                <p data-source-node="n248">Use the Item Criteria Field to 
 identify which items in a wave or pool that the system will attempt to 
 replenish.</p>
            </li>
        </ol>

        <h5 data-source-node="n250">Using the Replenishment Modes
 Tab<br data-source-node="n251"></h5>
        <p data-source-node="n252">You will use this tab to identify how this replenishment master will 
 be run: manual replenishment, replenishment via a wave, or real-time replenishment.</p>
        <p data-source-node="n253"> </p>
        <p data-source-node="n254"> </p>
        <h5 data-source-node="n255">Using the Replenishment Strategy 
 Tab</h5>
        <p data-source-node="n256">You will use this tab to identify the replenishment strategy(s) associated 
 with this record. A replenishment strategy determines what methodology 
 the system will use to perform a replenishment. You can use the Sequence 
 Field to determine the order that the system will process them. This field 
 will contain the value 10 (or a multiple of 10). You can change the sequence 
 number, but you cannot use the same sequence number for multiple strategy 
 records. The sequence number determines when this record will be used. 
 The lower the sequence number, the sooner it's processed. Currently, the 
 system supports three strategies: Fill Location, Round Up, and Round Down.</p>
        <ul data-source-node="n257">
            <li data-source-node="n258">
                <p data-source-node="n259">If Fill Location is selected, 
 the system will replenish the location until it reaches 100% capacity. 
 It will                     not reference the value 
 defined on the Maximum Replenishment Fill Percent Field defined on the 
 item location capacity record.</p>
                <p data-source-node="n260"> </p>
            </li>
            <li data-source-node="n261">If Round Up 
 is selected, the system will round up to the next increment level.<br data-source-node="n262"> </li>
            <li data-source-node="n263">If Round Down 
 is selected, the system will round down to the next increment level.</li>
        </ul>

        <h4 data-source-node="n266"><a name="Real-Time" data-source-node="n267"></a>Real-Time Replenishment...<br data-source-node="n268"></h4>
        <p class="p_8" data-source-node="n269">In order for the system to run the real time 
 replenishment process, you first have to set up your replenishment master 
 record to run in "real time" mode:</p>
        <ol class="ol_1" data-source-node="n270">
            <li value="1" data-source-node="n271">Access the Replenishment 
 Master Window, and open/create a record.<br data-source-node="n272"><br data-source-node="n273"></li>
            <li value="2" data-source-node="n274">Use the Replenishment 
 Mode Field (the checkboxes on the Replenishment Modes Tab) to indicate 
 that you want to use "real time" mode for your replenishment 
 master. In this mode, the system will automatically run replenishment 
 throughout the day (based on settings in the Scheduled Job Window), for 
 locations that would typically need frequent replenishment (you can make 
 a location eligible for this on the Location Window). The replenishment 
 process will run quicker than usual because the system will check for 
 replenishment need only for the locations that are currently in the need 
 of replenishment, and ignore the ones that do not currently need replenishing. 
 This type of replenishment is helpful because you can have replenishment 
 masters running throughout the day, and keep your forward picking locations 
 full for order processing.<br data-source-node="n275"><br data-source-node="n276"></li>
            <li value="3" data-source-node="n277">Next, you will 
 need to enter values for the other fields as you would for "basic" 
 replenishment. See the procedures above for specific field information.</li>
        </ol>
