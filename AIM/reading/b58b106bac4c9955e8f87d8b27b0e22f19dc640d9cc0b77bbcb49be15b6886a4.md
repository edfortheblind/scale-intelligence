
        
        <h1 class="Heading12" data-source-node="n56"><a name="kanchor1916" data-source-node="n57"></a>Defining Document Routing Records</h1>
        <p data-source-node="n58">After you define a document, you need to provide its printing parameters 
 on the Document Routing Window. The print parameters determine the following:</p>
        <ul data-source-node="n59">
            <li data-source-node="n60">
                <p data-source-node="n61">If a document should be printed, based on printing criteria. The 
 printer criteria are values commonly included on printed documents, such 
 as Ship To, Carrier and Container Class.</p>
                <p data-source-node="n62"> </p>
            </li>
            <li data-source-node="n63">
                <p data-source-node="n64">How many copies of the document will be produced.</p>
                <p data-source-node="n65"> </p>
            </li>
            <li data-source-node="n66">What printer the document will be routed to, and 
 which document will be used.<br data-source-node="n67"> </li>
            <li data-source-node="n68">What machine the document will be printed from; 
 for example, a particular packing station's client machine.</li>
        </ul>
        <p data-source-node="n69">NOTE:</p>
        <ul data-source-node="n70">
            <li data-source-node="n71">A default printer configured on the user profile will override the document routing printer. This also includes the default printer will override printers assigned to workstations. </li>
            <li data-source-node="n72">In case of workstations assigned printers use document routing records to determine the printer. </li>
            <li data-source-node="n73">The default printer has to be blank in order for the workstation printer to be used.</li>
        </ul>

        <h4 data-source-node="n132">Procedures...</h4>
        <p data-source-node="n133"> </p>
        <p data-source-node="n134">1. Use the Document Type 
 Field to identify the general category associated with this document. 
 The system will limit the documents available (in the Document Field) 
 to only those values associated with this document type.</p>
        <p data-source-node="n135"> </p>
        <p data-source-node="n136"> </p>
        <p data-source-node="n137">2. Use the Routing Criteria fields 
 to define when this document will be printed, and where. The system will 
 select this record when all of the criteria are met. If you don't define 
 a value in any criteria field, the system will produce the document whenever 
 it is requested.</p>
        <blockquote data-source-node="n138">
            <p data-source-node="n139">- Use the Machine 
 Name Field to refer to the machine requesting the printing (i.e. the workstation). </p>
            <p data-source-node="n140"> </p>
            <p data-source-node="n141"> </p>
            <p data-source-node="n142"><b data-source-node="n143">Printing using the Remote desktop service</b>
            </p>
            <p data-source-node="n144">The system is smart enough to determine the appropriate workstation if using Remote Desktop Services. It does not expect the domain name suffix. For example, suppose you have a printer located 
 at a specific packing station, from which you want to generate Container 
 Contents Labels. If you define a Machine Name, no matter the user that 
 is signed onto this packing station client machine, the system will print 
 the label at the printer present at that station. This is helpful because 
 you do not have to set up this document by user, and force them to always 
 use the same packing station. Also the default printers on the user profile will override the printer assigned to the workstation.<br data-source-node="n145"><br data-source-node="n146"><i data-source-node="n147">Note on Session Information and Document Routing</i></p>
            <p data-source-node="n148">The system gathers "session" information when the application starts up, and stores this information for the duration that the application is open (without ever re-retrieving it). When a user goes from one client workstation to another and uses a previously open or disconnected remote desktop (RDP) session (i.e., a "stolen" RDP session), the system will NOT need to re-retrieve the session information. Therefore, the document routing process uses the "original" client device name when determining where a document should be routed. In order to prevent this (and have the document routed to the new workstation), you need to log off the RDP session when finished with a work station; or, if you disconnect from one workstation and connect to the same session from another workstation, you need to close the application and re-open it.</p>
            <p data-source-node="n149"> </p>
