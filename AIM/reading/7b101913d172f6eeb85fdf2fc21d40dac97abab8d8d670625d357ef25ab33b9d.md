
        
        <h1 style="text-align: left;font-size: 12pt" data-source-node="n57">Store Location Assignment </h1>
        <p data-source-node="n58"> </p>
        <p data-source-node="n59">You can use this window to assign put-to-store locations to a certain store (warehouse/company/customer/ship to combination). The system uses this record to determine which put-to-store location an allocation request's quantity should be placed. Please note that all four of the header fields (warehouse, company, customer, and ship to/store) need to exactly match on the allocation request in order for the system to use this record to process through the put-to-store location details. The system will cycle through the details (in listed priority order) until a match is found. When the match is found, the system will assign the put-to-store location to the request. Put-to-store locations are defined on the Location Window. They are created in the same way as other locations, with the exception of using the put-to-store location class.</p>
        <p data-source-node="n60">The inventory will be transferred to the put to store location while using the using store location assignment without considering the unit of measure state and loose items available with the shipment.</p>
        <p data-source-node="n61"> </p>
        <p data-source-node="n62">NOTE: You should configure your store location assignment records with a detail that sends items to a put-to-store location if all other details fail to be eligible for processing. For example, your last detail should have general criteria defined for it, such as warehouse = your current warehouse.</p>
        <p data-source-node="n63"> </p>
        <p data-source-node="n64">Access the Store Location Assignment Window, and create a new record.</p>
        <p data-source-node="n65"> </p>
        <p data-source-node="n66">Use the header fields to define the "store" for this assignment record. Note that all four header fields (warehouse, company, customer, ship to) must exactly match the allocation request for the system to use this record to determine which put-to-store location the user should putaway quantity to.</p>
        <p data-source-node="n67"> </p>
        <p data-source-node="n68">To create assignment details, press the Add Button. The system will display a row under the field name column.</p>
        <p data-source-node="n69"> </p>
        <p data-source-node="n70">Use the Store Location Assignment Criteria Field to indicate the criteria that you want the system to use when determining which put-to-store location to assign an item quantity.</p>
        <p data-source-node="n71"> </p>
        <p data-source-node="n72">Use the Put-To-Store Location Field to indicate the location ID of the put-to-store location that you want to assign to this store. This class of location resides on the shipping dock, and houses product whose destination is a particular store (shipment line mark for).</p>
        <p data-source-node="n73"> </p>
        <p data-source-node="n74"> </p>
        <p data-source-node="n75">Note: If the client needs to send full cases directly to the shipping dock, we achieve this by using an override data wave step and dock assignment. Container creation criteria is also required to only create containers for the Unit of Measure that need directed to the shipping dock. The override data wave step would change the status flow on the container to one that redirects the container to the shipping dock. Dock assignment would use the related dock management flow to reassign the full case container from the put to store location to the shipping dock. Work creation is required for both shipping containers and allocation requests.</p>
