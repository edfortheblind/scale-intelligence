
        
        <h1 data-source-node="n56"><a name="kanchor743" data-source-node="n57"></a>Current Container Count Field</h1>
        <p data-source-node="n58">This field displays the current count of containers that have matched a QC assignment criteria record. The system will increment this count value up by one every time QC evaluation occurs and a matching container is found. Note that this field is never editable by the user.<br data-source-node="n59"><br data-source-node="n60">Example:<br data-source-node="n61">Suppose you have a new QC assignment record and its <i data-source-node="n62">container application</i> is defined as 1 of 3 containers. For new records, the <i data-source-node="n63">current container count</i> begins at 0. When the system evaluates a container using this assignment record, the following occurs:<br data-source-node="n64"><br data-source-node="n65">- For the first container, the system will increment <i data-source-node="n66">current container count</i> to 1. No QC will be assigned.<br data-source-node="n67"><br data-source-node="n68">- For the second container, the system will increment the <i data-source-node="n69">current container count</i> to 2. No QC will be assigned.<br data-source-node="n70"><br data-source-node="n71">- For the third container, the system will increment the <i data-source-node="n72">current container count</i> to 3. QC is assigned to that container, since it is the third container that used this record, which matches the 1 of 3 <i data-source-node="n73">container application</i> criteria. <br data-source-node="n74"><br data-source-node="n75">- When a fourth container is evaluated using this record, the <i data-source-node="n76">current container count</i> is incremented to 4, and the pattern continues as described above.</p>
