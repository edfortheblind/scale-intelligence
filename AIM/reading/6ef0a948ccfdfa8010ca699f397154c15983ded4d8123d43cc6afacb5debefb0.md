
        
        <h1 data-source-node="n57"><a name="kanchor766" data-source-node="n58"></a>UCC Code Field</h1>
        <p style="font-style: italic" data-source-node="n59">** To read more about EPC generation, see the topic How an EPC is Generated **</p>
        <p data-source-node="n60"> </p>
        <p data-source-node="n61">Use this field to define a specific position of the UCC-128 barcode. 
 The UCC-128 barcode uniquely identifies a specific shipment. It can be 
 included on vendor compliant labels. During the container creation wave step, the 
 system generates a UCC-128 barcode and assigns it as the container's ID. The UCC-128 barcode has 20 positions; each 
 position helps to identify the shipment. The tables below provides the 
 purpose of each position number.</p>
        <p data-source-node="n62"> </p>
        <p class="p_1" data-source-node="n63"> </p>
        <h5 data-source-node="n64">Generating UCC-128 Shipping Container ID...</h5>
        <p class="p_1" data-source-node="n65"> </p>
        <table style="margin-left: 0;margin-right: auto" data-source-node="n66">
            <col data-source-node="n67">
            <col data-source-node="n68">

 Number</i>
                    </p>

                </td>

                <td valign="top" data-source-node="n78">
                    <p align="left" data-source-node="n79">Positions 1 - 2</p>
                </td>
                <td style="width: 72%" valign="top" width="72%" data-source-node="n80">
                    <p data-source-node="n81">Represents the UCC-128 serial shipping container code qualifier.  This value will always be '00' application identifier.</p>
                    <p align="left" class="p_13" data-source-node="n82"> </p>
                </td>
            </tr>
            <tr data-source-node="n83">
                <td valign="top" data-source-node="n84">
                    <p align="left" data-source-node="n85">Position 3</p>
                </td>
                <td style="width: 72%" valign="top" width="72%" data-source-node="n86">
                    <p data-source-node="n87">Represents the packaging type.  This value is the UCC Code from the Container Class associated with the container’s Container Type.</p>
                    <p align="left" class="p_13" data-source-node="n88"> </p>
                </td>
            </tr>
            <tr data-source-node="n89">
                <td valign="top" data-source-node="n90">
                    <p align="left" data-source-node="n91">Positions 4 - 10</p>
                </td>
                <td style="width: 72%" valign="top" width="72%" data-source-node="n92">
                    <p data-source-node="n93">Represents the UCC/EAN Manufacturer ID (Company prefix). The value can vary from 7-10 characters.</p>
                    <p data-source-node="n94"> </p>
                    <p data-source-node="n95">IF the shipment/shipping container is associated to a Company,</p>
                    <p data-source-node="n96">AND the UCC/EAN is defined for the Company,</p>
                    <p data-source-node="n97">THEN use the Company UCC/EAN number when generating the container ID.</p>
                    <p data-source-node="n98"> </p>
                    <p data-source-node="n99">IF the shipment/shipping container is associated to a Company,</p>
                    <p data-source-node="n100">AND the UCC/EAN is NOT defined for the Company,</p>
                    <p data-source-node="n101">AND the UCC/EAN is defined for the shipment’s warehouse,</p>
                    <p data-source-node="n102">THEN use the UCC/EAN number defined for the shipment’s warehouse.</p>
                    <p data-source-node="n103"> </p>
                    <p data-source-node="n104">IF the shipment/shipping container is NOT associated to a Company,</p>
                    <p data-source-node="n105">AND the UCC/EAN is defined for the shipment’s warehouse,</p>
                    <p data-source-node="n106">THEN use the UCC/EAN number defined for the shipment’s warehouse.</p>
                    <p data-source-node="n107"> </p>
                    <p data-source-node="n108">IF the UCC/EAN is defined for neither the Company nor Warehouse</p>
                    <p data-source-node="n109">THEN use ‘04’ with zeros appended at the end, i.e. ‘0400000’.</p>
                    <p align="left" class="p_13" data-source-node="n110"> </p>
                </td>
            </tr>
            <tr data-source-node="n111">
                <td valign="top" data-source-node="n112">
                    <p align="left" data-source-node="n113">Positions 11 - 13</p>
                </td>
                <td style="height: 2px;width: 72%" height="2" valign="top" width="72%" data-source-node="n114">
                    <p data-source-node="n115">These 3 flex positions will be used for Company prefix codes that are greater than 7 characters or for shipping container number if not needed for company prefix code.  The company prefix code has precedence over the shipping container number.</p>
                    <p align="left" class="p_13" data-source-node="n116"> </p>
                </td>
            </tr>
            <tr data-source-node="n117">
                <td valign="top" data-source-node="n118">
                    <p valign="top" data-source-node="n119">Positions 14-19</p>
                    <p valign="top" data-source-node="n120"> </p>
                </td>
                <td style="height: 2px;width: 72%" height="2" valign="top" width="72%" data-source-node="n121">
                    <p height="2" valign="top" width="72%" data-source-node="n122">Represents a next number (serial reference) that is generated by the system.  The next number used has the key “Shipping Container Number” in the Next Number configuration.  If the number is not long enough to fill the entire segment, this portion of the field is filled with leading zeros.</p>
                    <p height="2" valign="top" width="72%" data-source-node="n123"> </p>
                </td>
            </tr>

        <h5 data-source-node="n126">Notes...</h5>
        <ul data-source-node="n127">
            <li data-source-node="n128">Once the container ID is generated, the system must check to see whether that ID already exists in the database.  If the ID already exists as a shipping container ID or multiple order pallet ID, then the system increments the shipping container number next number and generates the ID again. This continues until a unique number is found.<br data-source-node="n129"><br data-source-node="n130"></li>
            <li data-source-node="n131">If the next number ever gets to 999999999, then it resets itself to 1 on the next request.<br data-source-node="n132"><br data-source-node="n133"></li>
            <li data-source-node="n134">If the system goes through all available next numbers and cannot generate a unique ID, it is an error condition and the process of creating the container stops with an error. Note that there is a "UniqueContainerIdCreation.TimeoutInSeconds" timeout configuration in the service.properties file (the default value is 30 seconds). The system will try to find a new unique container ID for the specified amount of time, and then fail the process.</li>
        </ul>
        <p data-source-node="n135"> </p>
        <h5 data-source-node="n136">Example: Container ID...</h5>
        <ul data-source-node="n137">
            <li data-source-node="n138">A standard carton container class has a UCC code of 0. Suppose the container does not have a company associated with it.  The EAN on the warehouse is 1146587. Also suppose the next number in the Next Number config is 2909. In this case, the container ID would be generated as follows: 00011465870000029092. If that container ID already exists, then the system would increment the next number to 2910 and try again.</li>
        </ul>
        <p class="p_1" data-source-node="n139"> </p>
        <h5 data-source-node="n140">Example: Container ID when UCC length is 10...</h5>
        <ul data-source-node="n141">
            <li data-source-node="n142">Suppose the company EAN is 1234567890, the next number is 9876543, and the container ID is 00012345678908765432. The “9” from the next number gets removed because of the UCC length.</li>
        </ul>

        <h5 data-source-node="n147">Generating UCC-128 Multiple Order Pallet ID...</h5>
        <p class="p_1" data-source-node="n148"> </p>
        <p class="p_1" data-source-node="n149">The generation of the UCC-128 multiple order pallet ID follows the basic rules as the UCC-128 Container ID.  This number must be unique.  If the ID already exists as a shipping container ID or multiple order pallet ID, then the system increments the shipping container number next number and generates the ID again.  This repeats until a unique number is found.  </p>
        <p class="p_1" data-source-node="n150"> </p>
        <p class="p_1" data-source-node="n151">The differences in the generation of the multiple order pallet ID are in the retrieval of the UCC Code (extension digit) and the UCC/EAN Manufacturer ID fields.  This value will be 0.  The UCC/EAN manufacturer ID will be based on the value found for the multiple order pallet’s warehouse.  If this value is not defined, then it will use ‘0400000’ as the UCC/EAN manufacturers ID.</p>
