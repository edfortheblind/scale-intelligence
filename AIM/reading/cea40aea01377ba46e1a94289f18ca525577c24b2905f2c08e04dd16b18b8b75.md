
        
        <h1 data-source-node="n56"><a name="kanchor211" data-source-node="n57"></a>Defining Location Selection Records</h1>
        <p data-source-node="n58">You will use location selection records, along with locating strategy 
 records, to identify the characteristics that a location must have to 
 be considered during locating. It also determines the order that the system 
 will organize the eligible location.</p>

        <h4 data-source-node="n110"><a name="basic" data-source-node="n111"></a>Basic Procedures...</h4>
        <ol class="ol_1" data-source-node="n112">
            <li value="1" data-source-node="n113">Using the Filter 
 Data Tab: You can use this tab to identify which locations should 
 be considered for locating. If a   strategy 
 is defined on the locating rule detail, that system uses the strategy, 
 along with the values defined on the filter data tab, to select locations 
 eligible for locating.<br data-source-node="n114"><br data-source-node="n115"></li>
            <li value="2" data-source-node="n116">Using the Order 
 By Tab: You can use this tab to organize these locations. After 
 the locations are organized, the system selects the number required to 
 process the order.<br data-source-node="n117"><br data-source-node="n118"></li>
            <li value="3" data-source-node="n119">When finished, 
 press OK. The system will save your location selection record.</li>
        </ol>

        <h4 data-source-node="n124"><a name="perm" data-source-node="n125"></a>Locating Close to an Item's Permanent 
 Location...<br data-source-node="n126"></h4>
        <p class="p_14" data-source-node="n127">When locating, you can have the system attempt 
 to find a location near an item’s permanent location. The location selection 
 process creates a set of locations based on any property of the item’s 
 permanent location, and then can be used in conjunction with any locating 
 strategy. This can be facilitated by using the Permanent 
 Location icon <img style="height: 16px;width: 16px" width="16" height="16" border="0" class="img_2" loading="eager" data-source-node="n128">. 
 This icon will appear next to the Value Field, only 
 if the Location table was selected in the Table Name Field. When 
 you press this icon, the system will display the   &lt;&lt;PermLoc&gt;&gt; 
 token in the Value Field. </p>
        <p class="p_14" data-source-node="n129"> </p>
        <p class="p_14" data-source-node="n130">For example, suppose your locations use an 
 aisle/bay/level template, and an item’s permanent location is 001/05/01.You 
 want to locate to an item’s permanent 
 location in the bulk area first. If that area is full, then you would 
 want to locate to an empty location that is in the same aisle and same 
 bay as the permanent location. If there are no openings in the same aisle 
 and bay, then you would want to locate to empty in the bulk location. 
 The locating rule, then, would have three sequences:</p>
        <ol class="ol_1" data-source-node="n131">
            <li class="li_15" value="1" data-source-node="n132">First, the system will 
 try to locate to a permanent location (using the Item 
 Location Assignment locating strategy), in a bulk location (using 
 a location selection rule that selects from your bulk locations). <br data-source-node="n133"><br data-source-node="n134"></li>
            <li class="li_15" value="2" data-source-node="n135"><i data-source-node="n136">If the 
 system fails to find a suitable location</i>: Then, the system will 
 try to locate to an empty location near the item's permanent location. 
 You would then use the Empty Location 
 locating strategy, and set up a location selection record using the location 
 template fields with the permanent location token as a value (see below). The system will use the token when processing the location selection 
 criteria, and find the item’s permanent location with the same unit of 
 measure:<br data-source-node="n137"><br data-source-node="n138">          LOCATION.TEMPLATE_FIELD1 = N’&lt;&lt;PermLoc&gt;&gt;’<br data-source-node="n139">          AND LOCATION.TEMPLATE_FIELD2 = N’&lt;&lt;PermLoc&gt;&gt;’<br data-source-node="n140"><br data-source-node="n141">Also, you could specify a <b data-source-node="n142">+</b> (plus) or <b data-source-node="n143">-</b> (minus) value to locate one way either direction from a permanent location. Note that the system will ignore these <b data-source-node="n144">+</b> and <b data-source-node="n145">-</b> values if the location template is not numeric. For example, you could have the system try to locate one bay in either direction of your permanent location, assuming in the example below that you are using an <i data-source-node="n146">aisle-bay-level</i> location structure (with location template field 2 representing a <i data-source-node="n147">bay</i>):<br data-source-node="n148"><br data-source-node="n149">          LOCATION.TEMPLATE_FIELD2 = N’&lt;&lt;PermLoc&gt;&gt;’+1<br data-source-node="n150">          AND LOCATION.TEMPLATE_FIELD2 = N’&lt;&lt;PermLoc&gt;&gt;’-1<br data-source-node="n151"><br data-source-node="n152"></li>
            <li class="li_15" value="3" data-source-node="n153"><i data-source-node="n154">If the system fails to find a suitable location</i>: Then, the system will 
 try to locate to any empty location (using the Empty Location locating strategy), in a bulk location (using a location selection rule that selects from your bulk locations).</li>
        </ol>
