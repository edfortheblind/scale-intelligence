
        
        <h1 data-source-node="n57"><a name="kanchor1314" data-source-node="n58"></a>Using the QC Workbench</h1>
        <p data-source-node="n59">The outbound quality control process involves taking a subset of the shipping  containers that are being shipped out of the warehouse, and inspecting the  contents in order to verify that they match what the system believes to be in  the container. If the container passes QC, then it would continue on through the  appropriate outbound status flow and eventually out the dock door. If the  container fails QC, then the item quantities in question would need to be  resolved before the container can move on to the next appropriate step in its  status flow.</p>
        <p data-source-node="n60"> </p>
        <p data-source-node="n61">You can use the QC Workbench to inspect the item quantities that are in a container. The workbench includes a detailed inspection grid that allows you to view the packed, counted, and failed quantities for each item. You can also enter reason codes in the grid, which indicate why an item failed QC.</p>
        <p data-source-node="n62"> </p>
        <p data-source-node="n63">Note that all of a container's contents must have been picked before a container is eligible for QC inspection.</p>

        <h4 data-source-node="n221"><a name="initiation" data-source-node="n222"></a>Initiating a Container...</h4>
        <p data-source-node="n223">Before you can start evaluating a container's contents, you first need to load the container into the QC Workbench.</p>
        <p data-source-node="n224"> </p>
        <p data-source-node="n225">NOTE: You can open the QC workbench from the <a href="56f58af05b639903354ee78fe799f51fefee04136179aa4cf2c434fc9c82a65a.html" data-source-node="n226">Shipping Container Insight</a> screen by selecting the Confirm QC option for a shipping container with a pending or failed QC status.</p>
        <p data-source-node="n227"> </p>
        <p data-source-node="n228">1. Access the QC Workbench. </p>
        <p data-source-node="n229"> </p>
        <p data-source-node="n230">2. Enter the ID of the container that you want to inspect.</p>
        <p data-source-node="n231"> </p>
        <p data-source-node="n232">3. Press the arrow button. The system will display the container's item quantities in the inspection grid.</p>
        <p data-source-node="n233"> </p>
        <p data-source-node="n234"> </p>

        <h4 data-source-node="n238"><a name="QCinspection" data-source-node="n239"></a>Directly Entering Counted Quantities Into Grid...</h4>
        <p data-source-node="n240">The following procedures describe how you could inspect a container's contents by counting each item's total quantity and then directly entering that value into the grid.</p>
        <p data-source-node="n241"> </p>
        <p data-source-node="n242">1. For each item quantity residing in the container, count the number physically present.</p>
        <p data-source-node="n243"> </p>
        <p data-source-node="n244">2. Enter the item's inspection value into the Counted quantity field: </p>
        <blockquote data-source-node="n245">
            <p data-source-node="n246">- If the Counted quantity matches the Packed quantity, then the item has passed QC, and the system will disable the Reason Code <i data-source-node="n247">Add/View</i> link (since there is no need to enter codes).</p>
            <p data-source-node="n248"> </p>
            <p data-source-node="n249">- If the Counted quantity does not match the Packed quantity, then you will need to enter a reason code to explain this discrepancy. <br data-source-node="n250"></p>
        </blockquote>
        <p data-source-node="n251">3. Press a row's Add/View link to enter reason codes for Failed quantities. When the Add/View link is pressed, the system will display the Reason Codes screen, where you can match quantity values to the appropriate reason code(s). Your reason code quantities must match the Failed quantity for the container before you are allowed to exit the Reason Codes screen. </p>
        <p data-source-node="n252"> </p>
        <p data-source-node="n253">4. Once all the container's item quantities have been inspected, you then need to confirm these results to the system. You can do this by pressing the Submit button. At the time of confirmation, the system writes transaction history for all item quantities confirmed, and writes process history indicating that the container has passed/failed QC inspection. See the <a href="#QChistory" data-source-node="n254">Quality Control History Generation</a> section later in this topic for more information on history.</p>
        <blockquote data-source-node="n255">
            <p data-source-node="n256">- If all item quantities passed inspection, the system will display a message indicating that the container passed QC inspection. The QC process for this container is now finished. </p>
            <p data-source-node="n257"> </p>
            <p data-source-node="n258">- If there are item quantities that do not pass inspection, the system will display a message indicating that the container had some Failed quantities and did not pass inspection. Now proceed to step 6 of these procedures.</p>
        </blockquote>
        <p data-source-node="n259">5. After the initial confirmation, you can enter reason codes for any Failed quantities (if you have not done so already). Do this by pressing the Add/View link in the Reason Code grid column for each Failed item quantity.</p>
        <p data-source-node="n260"> </p>
        <p data-source-node="n261">6. You will now need to resolve the Failed quantity of the container in a window outside of the QC Workbench. See the <a href="#resolveFailed" data-source-node="n262">Resolving Failed Item Quantities</a> procedures later in this topic.<br data-source-node="n263"></p>
        <p data-source-node="n264"> </p>
        <p data-source-node="n265">NOTE: If you choose, you can enter different Counted quantity values for item row(s) that have previously been confirmed, and perform a reconfirm. This is possible only as long as there are Failed item rows in the grid. You cannot perform a reconfirm if all item rows have passed inspection.</p>
        <p data-source-node="n266"> </p>

        <h4 data-source-node="n271"><a name="QCScanWeb" data-source-node="n272"></a>Scanning Counted Quantities Into Grid...</h4>
        <p data-source-node="n273">The following procedures describe how you could inspect a container's contents by scanning the bar code of each item counted. Note that it is strongly suggested that you configure your bar code scanner to have a TAB action occur after the scan, and not an ENTER action. As a result, when you scan the item ID, the cursor will jump to the next appropriate field (either Lot or Quantity, depending on the type of item scanned). However, if you only will be scanning non-lot-controlled items, configuring an ENTER action should be sufficient.</p>
        <p data-source-node="n274"> </p>
        <h5 data-source-node="n275">The Scan Item Count Fields</h5>

        <h5 data-source-node="n279"> </h5>
        <h5 data-source-node="n280">Container Inspection</h5>
        <p data-source-node="n281">- Note that the procedures below assume your packing preferences are defined to require lot validation.</p>
        <p data-source-node="n282"> </p>
        <p data-source-node="n283">1. Scan the bar code of the first item you want to inspect. Note that if the item exists in the container for multiple companies, the system will prompt you to choose the correct company value. Note that you could choose to instead enter an item's cross reference ID in the Item Field.</p>
        <p data-source-node="n284"> </p>
        <p data-source-node="n285">2. If you scanned a lot-controlled item, you would then enter the lot ID.<br data-source-node="n286"></p>
        <p data-source-node="n287"> </p>
        <p data-source-node="n288">3. In addition, you can change the unit of measure (UM) value. This is optional, as the system defaults this value to the base unit of measure for the item scanned.</p>
        <p data-source-node="n289"> </p>
        <p data-source-node="n290">4. Next, if needed, you can change the quantity value. This is optional, as the system defaults this value to 1. </p>
        <p data-source-node="n291"> </p>
        <p data-source-node="n292">5. When you are ready to apply the item count to the inspection grid, press the Count button. The system will raise the Counted Quantity of the item by the increment that you counted. Note that if you have the same item cross reference pointing to multiple items/companies, the system will count the first item (which matches this cross reference) that is listed in the grid.</p>
        <p data-source-node="n293"> </p>
        <p data-source-node="n294">6. To count another item quantity, repeat the steps outlined above.  </p>
        <p data-source-node="n295"> </p>
        <p style="font-weight: normal" data-source-node="n296">7. Once all the container's item quantities have been inspected, you will need to provide reason code(s) for any counted quantities that do not match an item's packed quantity. To do this, press an item row's Add/View button and the system will display the Reason Codes screen.</p>
        <p style="font-weight: normal" data-source-node="n297"> </p>
        <p style="font-weight: normal" data-source-node="n298">8. The final step in this process is to submit your counting results for evaluation. You can do this by pressing the Submit button:</p>
        <blockquote data-source-node="n299">
            <p data-source-node="n300">- If all item quantities pass inspection, the system will display a message indicating that the container passed QC inspection. The QC process for this container is now finished. </p>
            <p data-source-node="n301"> </p>
            <p data-source-node="n302">- If there is at least one item quantity that does not pass inspection, the system will display an error message. You will now need to resolve the container's Failed quantities. See the <a href="#resolveFailed" data-source-node="n303">Resolving Failed Item Quantities</a> procedures later in this topic for more information.<br data-source-node="n304"></p>
            <p data-source-node="n305"> </p>
            <p data-source-node="n306">Also, at the time of confirmation, the system writes transaction history for all item quantities confirmed, and writes process history indicating that the container has passed/failed QC inspection. See the <a href="#QChistory" data-source-node="n307">Quality Control History Generation</a> section later in this topic for more information.</p>
        </blockquote>
        <p data-source-node="n308"> </p>
        <h5 data-source-node="n309">Last Item Counted</h5>
        <p data-source-node="n310">When you count an item using the fields above the inspection grid and press the Count button, the system will not only add that item quantity to the inspection grid, but also log the item's information into the "Last item counted" section on the right side of the workbench. This section indicates the ID, description, and quantity of the item that was just counted. Keep in mind the following about this section:</p>
        <ul data-source-node="n311">
            <li data-source-node="n312">The "Quantity counted" value indicates the quantity and unit of measure of the item you just counted, exactly as you counted it. For example, if you counted 2 CS of an item, the "Quantity counted" value would be 2 CS, even if CS is not the item's base unit of measure.<br data-source-node="n313"><br data-source-node="n314"></li>
            <li data-source-node="n315">The "Total quantity" value indicates the current sum of the item that you have counted so far (converted into the item's base unit of measure).<br data-source-node="n316"><br data-source-node="n317"></li>
            <li data-source-node="n318">The "Container quantity" value indicates the whole quantity of an item that is packed into the container you are evaluating. </li>
        </ul>
        <p data-source-node="n319"> </p>
        <hr width="100%" align="center" data-source-node="n320">
        <p data-source-node="n321"> </p>
        <p data-source-node="n322"> </p>
        <h4 data-source-node="n323"><a name="QChistory" data-source-node="n324"></a>Quality Control History Generation...</h4>
        <p data-source-node="n325"> </p>
        <p data-source-node="n326">At the time a container count is confirmed, the system writes the following types of history records. Note that the system does not log quality history as part of the outbound QC process:</p>
        <ul data-source-node="n327">
            <li data-source-node="n328">Transaction History: The system generates a transaction history record for each item quantity that you confirm. The record includes such information as container ID, user name, item/quantity, and the reason code(s) for Failed counts.<br data-source-node="n329"><br data-source-node="n330"></li>
            <li data-source-node="n331">Process History: The system generates a process history record  indicating that the container has passed or failed QC inspection. The record includes such information as container ID, user name, previous QC status, and current QC status.</li>
        </ul>
        <p data-source-node="n332"><i data-source-node="n333">Reason Code Configuration Note</i>: Even though the reason codes used in the QC Workbench are defined in the Quality History Reason Codes configuration, the system does not generate quality history records for a Failed count confirmation. The reason codes defined in this configuration are simply listed on the QC Workbench, and logged on the QC Confirmation transaction history record when a Failed count occurs.</p>
        <p data-source-node="n334"> </p>
        <p data-source-node="n335"> </p>

        <h4 data-source-node="n339"><a name="resolveFailed" data-source-node="n340"></a>Resolving Failed Item Quantities...</h4>
        <p data-source-node="n341">Once the system flags an item quantity as Failed, you will then need to resolve this quantity so the container can pass QC confirmation. You will need to perform this action in a window outside of the QC Workbench. For example, suppose you have a container that has an item quantity that was under-packed by 1 EA. The system would fail this item quantity, and you would need to remove this item from the container via the Shipping Container Insight screen. After you have resolved an item's Failed quantity, then you can refresh the inspection grid data, and the appropriate Packed quantity values will update to their current state. You can then resubmit the container for QC inspection (see <a href="#Resubmit" data-source-node="n342">Resubmitting a Container for QC Inspection</a> section for more information).</p>
        <p data-source-node="n343"> </p>

        <h4 data-source-node="n348"><a name="Resubmit" data-source-node="n349"></a>Resubmitting a Container for QC Inspection...</h4>
        <p data-source-node="n350"> </p>
        <p data-source-node="n351">After a container has failed QC inspection, and you have <a href="#resolveFailed" data-source-node="n352">resolved</a> this failure, then you may need to enter different Counted quantity values for certain item(s). You can enter these new values directly into the grid's Counted Quantity. </p>

        <h4 data-source-node="n358"><a name="lotsSerials" data-source-node="n359"></a>Inspecting Item Quantities With Lots, Serial Numbers, Catch Weight, and Unknown Items...</h4>
        <p data-source-node="n360"> </p>
        <h5 data-source-node="n361">Lots</h5>
        <p data-source-node="n362">Lot-controlled items are fully-supported in the QC Workbench. You can choose to handle lots in one of two ways, depending on how you configure your packing preferences:</p>
        <ul data-source-node="n363">
            <li data-source-node="n364">Requiring lot validation during inspection: The system will display each item/lot combination as a separate row in the inspection grid. Therefore, the user will need to enter quantity values for each item/lot combination that they count as being part of the container. The system displays the Lot field near the top of the screen next to the Item field.<br data-source-node="n365"><br data-source-node="n366"></li>
            <li data-source-node="n367">Not requiring lot validation during inspection:  The system will summarize all of an item's lot instances into a single grid row on the inspection grid, so the system will not display a lot column in the inspection grid. </li>
        </ul>
        <h5 data-source-node="n368">Serial Numbers</h5>
        <p data-source-node="n369">Serial number tracked item quantities can be inspected in the QC Workbench; however, an item quantity that has serial numbers is displayed as one row in the grid. The serial numbers themselves are not displayed in the grid.</p>
        <p data-source-node="n370"> </p>
        <h5 data-source-node="n371">Catch Weight</h5>
        <p data-source-node="n372">Catch weight tracked item quantities can be inspected in the QC Workbench; however, an item quantity that has catch weights is displayed as one row in the grid. The catch weights themselves are not displayed in the grid.</p>
        <p data-source-node="n373"> </p>
        <h5 data-source-node="n374">Unknown Items (Not Currently Packed Into the Container)</h5>
        <p data-source-node="n375">You can also count items that the system does not list as part of the container (i.e., an "unknown" item). When you count an unknown item, the system will add a row representing the item to the inspection grid. Note that this action does not actually pack the item into the container, as you would need to do that separately in another window (like the Packing screen). Note that unknown item quantities are always flagged as Failed quantities when a container's count is submitted.</p>
        <p data-source-node="n376"> </p>
        <p data-source-node="n377">In addition, you can configure the system to prompt you when an unknown item is scanned. The setting that governs this prompt is located on the Packing Preferences Window. If this setting is active, when you scan an unknown item, a prompt window will appear alerting you of this fact. If you confirm that you want to add this item to the container, then the system will add this item quantity to the inspection grid. </p>

        <p data-source-node="n385"> </p>
        <p data-source-node="n386">You can choose to specify  a custom audio file to associate for QC errors. Note that this is the same audio file that is used for errors on the Packing Screen (the system is shipped with a default audio file). The system will play this audio file when you encounter an error in QC counting and an error message is displayed. These errors include but are not limited to the following:</p>
        <ul data-source-node="n387">
            <li data-source-node="n388">
                <p data-source-node="n389">Submit a count that results in failed quantity.<br data-source-node="n390"><br data-source-node="n391"></p>
            </li>
            <li data-source-node="n392">
                <p data-source-node="n393">Attempt to submit a count that does not have the proper reason code(s) defined.<br data-source-node="n394"><br data-source-node="n395"></p>
            </li>
            <li data-source-node="n396">
                <p data-source-node="n397">Do not provide a lot value when counting a lot item.<br data-source-node="n398"><br data-source-node="n399"></p>
            </li>

                <p data-source-node="n401">Attempt to count an invalid item when the system is configured in Inventory System Values to validate item throughout the system.</p>
