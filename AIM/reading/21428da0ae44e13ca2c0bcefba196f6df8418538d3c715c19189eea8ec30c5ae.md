
        
        <h1 data-source-node="n56"><a name="kanchor1402" data-source-node="n57"></a>Location Process Summary</h1>
        <p data-source-node="n58"><b data-source-node="n59">** Functionality **</b>
        </p>
        <p data-source-node="n60"> </p>
        <p data-source-node="n61"> </p>
        <h4 data-source-node="n62">Summary...</h4>
        <p data-source-node="n63">A location is the unique place in the warehouse where an item or license plate 
 can be picked, putaway, or replenished. Locations can be defined on the 
 Location Window. To minimize setup time, you can set up location types 
 which identify dimensions and quantity maximums for a group of locations. 
 Later, you can associate each location with its location type. This is 
 especially helpful if you have rows of the same storage type, such as 
 a racking system or pallet storage area. You can also define movement 
 classes per location. The movement class identifies what types of product 
 can be stored in the location.</p>

        <p data-source-node="n75">The following are key features of the location functional area:</p>
        <p data-source-node="n76"> </p>
        <h4 data-source-node="n77">Location Templates...</h4>
        <p data-source-node="n78">The system features location templates, which you can use to define 
 the structure of a location ID. A location template includes separators. 
 Later, employees can just enter the ID string and the system will automatically 
 apply the correct structure.</p>
        <p data-source-node="n79"> </p>
        <p data-source-node="n80"> </p>
        <p data-source-node="n81"> </p>
        <h4 data-source-node="n82">Location Classes...</h4>
        <p data-source-node="n83">The system provides predefined location classes. A location class identifies 
 the purpose of a location, such as storage or shipping dock.</p>
        <p data-source-node="n84"> </p>
        <p data-source-node="n85"> </p>
        <p data-source-node="n86"> </p>
        <h4 data-source-node="n87">Permanent Locations...</h4>
        <p data-source-node="n88">You can associate items with a permanent location. This allows you to 
 allocate items that you don't track as inventory, such as promotional 
 leaflets and other value-adds.</p>
        <p data-source-node="n89"> </p>
        <p data-source-node="n90"> </p>
        <p data-source-node="n91"> </p>
        <h4 data-source-node="n92">Pickup &amp; Dropoff Locations...</h4>
        <p data-source-node="n93">You can also create Pickup and Dropoff (P&amp;D) locations. P&amp;D 
 locations can be used as intermediate locations while performing inventory 
 movement. You can then associate P&amp;D locations with a regular inventory 
 locations. For example, suppose you have a narrow aisle that contains 
 several inventory locations. When items are picked from these locations, 
 the picker could then place the items in an outgoing P&amp;D location 
 at the end of the aisle. A different worker would then pick up these items, 
 and take them to their destination (which could be an incoming P&amp;D 
 location, packing station, or other area). </p>
