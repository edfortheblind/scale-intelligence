
        
        <h1 style="text-align: left;font-size: 12pt" data-source-node="n57">Shipper Cross Reference</h1>
        <p data-source-node="n58">This record links a shipper code to a specific warehouse and company combination. It controls which carriers can be rated for that shipper. When a shipper cross-reference record is created in the system, it is also automatically created in Progistics.</p>
        <p data-source-node="n59">In Progistics, the cross-reference record stores the shipper's identity, address, and the carriers eligible for rating. Before rating a shipment, Progistics checks this record. If a carrier is not registered for that shipper, it won’t be included in the rating process. Any changes or deletions to this record in the system will also be reflected in Progistics.</p>
        <p data-source-node="n60">You can define multiple cross-reference records for the same warehouse and company, as long as each record has a unique shipper code.</p>
        <p data-source-node="n61"> </p>
        <h4 data-source-node="n62">Create Shipper Cross Reference</h4>
        <p data-source-node="n63"> </p>
        <ul data-source-node="n64">
            <li data-source-node="n65">
                <p data-source-node="n66"><b data-source-node="n67">Shipper Code</b> - Use this field to link the warehouse/company to the shipper code you defined in the Shipper Code configuration.</p>
            </li>
        </ul>
        <ul data-source-node="n68">
            <li data-source-node="n69">
                <p data-source-node="n70"><b data-source-node="n71">Warehouse</b> - Identify the warehouse that will use this shipper. If you do not support multi-company processing, the warehouse is the entity that will ship product. In this case, Progistics would then create only one manifest, for the entire warehouse. Conversely, if you select a company (Step 3), the system will generate the manifest per company, regardless of the value defined in this field.</p>
            </li>
        </ul>
        <ul data-source-node="n72">
            <li data-source-node="n73">
                <p data-source-node="n74"><b data-source-node="n75">Company</b> - required only if your warehouse supports multi-company processing and the shipper code is tied to a specific company. The system will create a manifest for this specific company.</p>
            </li>
        </ul>
        <h5 data-source-node="n76">Toggle Button</h5>
        <p data-source-node="n77"> </p>
        <ul data-source-node="n78">
            <li data-source-node="n79">
                <p data-source-node="n80"><b data-source-node="n81">Default Shipper</b> -You can mark a cross-reference record as the default shipper using a toggle button. This setting tells the system which shipper code to use by default during rating when a matching warehouse/company is selected in the Shipment or Rate Shopping screens.</p>
            </li>
        </ul>
        <p data-source-node="n82">Notes</p>
        <ul data-source-node="n83">
            <li data-source-node="n84">
                <p data-source-node="n85">Only one default shipper is allowed per warehouse/company (or warehouse/blank company) combination.</p>
            </li>
            <li data-source-node="n86">
                <p data-source-node="n87">The first cross reference record created for a warehouse/company is automatically set as the default. This setting can’t be changed on that first record until more records are added for the same combination.</p>
            </li>
            <li data-source-node="n88">
                <p data-source-node="n89">Changing the default designation to another record will automatically remove it from the previous default.</p>
            </li>
            <li data-source-node="n90">
                <p data-source-node="n91">If multiple records exist for the same warehouse/company, you cannot delete the one marked as the default.</p>
            </li>
        </ul>
