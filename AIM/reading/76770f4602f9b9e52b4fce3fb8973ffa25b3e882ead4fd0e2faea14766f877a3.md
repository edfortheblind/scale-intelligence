        <h4 data-source-node="n64">Summary...</h4>
        <p data-source-node="n65">All work is created to respond to a request for product from such things as an allocation need, an inventory adjustment, or a replenishment need, for example. The work process is 
 the creation and execution of work through the warehouse. During the work creation process, the system decides what entities need to have work created for them, based 
 on values that you define. The system creates work unit(s), which represent the item quantities that 
need to be picked by warehouse employees for a certain shipment. The work execution process involves an employee actually performing the "action" that is required by a work instruction, whether it is picking an item from an inventory location, performing a cycle count at a location, etc.</p>

        <p data-source-node="n88">The following are key features of the work functional area:</p>
        <p data-source-node="n89"> </p>
        <p data-source-node="n90"> </p>
        <h4 data-source-node="n91">Group Picking...</h4>
        <p data-source-node="n92">Using the system's group picking, you can pick product into the appropriate 
 shipping containers, add the shipping labels, close the containers, and 
 ship them. Group picking is performed outside of work execution (if you 
 want to have work in a group picking situation, you should use the <a href="#rfgroup" data-source-node="n93">RF group picking</a> functionality). Below is more information 
 about this process. This picking method consolidates containers allocated from the same 
 area of your warehouse into a pick group. A pick group represents a tool 
 you use to retrieve allocated product, such as a cart. You define how 
 many containers can be included in a pick group (based on cart capacity, 
 etc) and which locations it services. During the wave cycle, the system 
 assigns containers created in a prior step to the appropriate pick group. Also during the wave, the system generates the Group Picking Pick List 
 Document, which identifies all of the containers in a group, their contents, 
 locations to visit etc. The employee picks into the appropriate containers 
 using the Group Picking Pick List Document.</p>
        <p data-source-node="n94"> </p>
        <p data-source-node="n95"> </p>
        <p data-source-node="n96"> </p>
        <h4 data-source-node="n97">RF Group Picking...</h4>
        <p data-source-node="n98">RF group picking is an alternative to the paper-based method of group 
 picking (as described above). This RF method allows users to pick either 
 into the actual shipping container or a tote. Users also can introduce a new transport container on-the-fly 
 if one becomes necessary during the picking process. For example, suppose you have several users picking part of one work unit into the same container
/tote. The first 
 user would scan the container/tote and pick an item into that container. 
 After the user is done with their pick, then they would place the container 
 on a conveyor belt, where it is passed along to the second user, where 
 they would then pick their item into the same container. This process 
 will continue until all picks for the work unit have been executed. After 
 all the picks are done, the putaway process begins. A second functional flow involves a user assigning several containers to one transport container (such as a cart), 
 thus creating a <i data-source-node="n99">picking group</i>. The system then will update 
 the work to form one picking group (based on the group number value). The user then would 
 begin picking. For each pick, the system will indicate to the user 
 the quantity to place in each shipping container, and the <i data-source-node="n100">container spot</i> on the cart where the product should be placed (this spot can be assigned by the system or user, depending on the configuration setting). After all the picks 
 are done, the putaway process begins. </p>
        <p data-source-node="n101"> </p>
        <p data-source-node="n102"> </p>
        <p data-source-node="n103"> </p>
        <h4 data-source-node="n104">Picking Management...</h4>
        <p data-source-node="n105">Picking Management is a different way to view and execute the work within 
 the warehouse. Through regular work execution, each work unit must be 
 completed by one user, moving throughout the warehouse and completing 
 all the work for that work unit. Picking management provides a way for 
 work to broken up by zone, and executed by multiple users.</p>
        <p data-source-node="n106"> </p>
        <p data-source-node="n107"> </p>
        <p data-source-node="n108"> </p>
        <h4 data-source-node="n109">RF Pick Directly Into a Shipping Container...</h4>
        <p data-source-node="n110">This type of RF processing involves users picking product directly into 
 either an actual shipping container or a tote. This picking action is 
 a derivative of user-directed work. When you pick directly into a shipping container, the system will perform 
 the packing action as part of the picking process. During the act of pick 
 confirmation, the user will be able to assign the picked item and quantity 
 to a shipping container. Until this container is closed, any other items 
 belonging the same shipment may be added to this container. When picking 
 into a tote, the user can group products on the same shipment together. 
 </p>
