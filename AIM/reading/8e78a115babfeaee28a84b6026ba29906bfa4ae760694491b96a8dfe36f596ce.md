                    <p data-source-node="n81">Should In Pool Quantities Count As 
 Allocated? - This value indicates whether or not the validation 
 performed by the "Available Checking" value (described above) 
 will include quantities for shipments already in the order pool. For example:</p>
                    <p data-source-node="n82">  </p>
                    <p data-source-node="n83">- When 
 the value is Y, shipments in the pool that need this item will 
 actually decrement the available quantity for the purposes of availability 
 checking. Suppose you have 20 of item AA001 in the warehouse with 10 allocated. 
 You also have a shipment in the pool that requires 4 of AA001. The system 
 thinks there are 6 available (20 on hand - 10 allocated - 4 for the shipment 
 in the pool = 6).<br data-source-node="n84"><br data-source-node="n85">- When the value is N, (using 
 the example above), the system thinks there are 10 available (20 on hand 
 - 10 allocated = 10).</p>

                    <p data-source-node="n97">Order Entry Ship To Max - This 
 value defines the number of ship to addresses you can add to an order 
 before the system will display a warning about loading default fields. 
 When you leave the Ship To Selection screen, the system will alert you 
 asking if you want the option of not populating the default customer information 
 fields on the following screens: the Default Carrier/Service Field on 
 the Routing Selection Screen, and the Default Categories Field on the 
 Miscellaneous Selection screen. This is helpful because the large number 
 of ship to's that the system has to retrieve data for could increase load 
 time significantly.</p>
