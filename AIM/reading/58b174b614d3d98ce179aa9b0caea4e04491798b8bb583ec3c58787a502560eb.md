        <h4 data-source-node="n80"><a name="generalProcess" data-source-node="n81"></a>General Container Creation Process...</h4>
        <p data-source-node="n82"> </p>
        <p data-source-node="n83">Below is a diagram describing the general flow executed by the system when the container creation wave step is run:</p>
        <p data-source-node="n84"> </p>
        <p data-source-node="n85">
            <img src="../source/assets/9815c43d168ef392af5165004998cde6ceff99e22ff63b97f3869af43811b193.gif" loading="eager" data-source-node="n86">
        </p>
        <p data-source-node="n87"> </p>
        <p data-source-node="n88"><b style="text-decoration: underline;font-style: normal" data-source-node="n89">Step 1</b>
        </p>
        <p data-source-node="n90">- During the wave, the allocation wave step generates allocation requests for a shipment. </p>
        <p data-source-node="n91"> </p>
        <p data-source-node="n92">- The user then starts the wave process by choosing to run a wave.                      </p>
        <p data-source-node="n93"> </p>
        <p data-source-node="n94">- Note that if your wave flow includes the container creation wave step, it must be executed after the allocation wave step.</p>
        <p data-source-node="n95"> </p>
        <p data-source-node="n96"> </p>
        <p data-source-node="n97"><b style="font-style: normal;text-decoration: underline" data-source-node="n98">Step 2</b>
        </p>
        <p data-source-node="n99">The system retrieves all requests for full UM containers. The system creates one container (per full unit of measure container quantity) for product allocated as a full container. For example, if a full case is defined as 8 EA, and the system allocates 17, the system would create two full containers, and leave 1 EA for performing loose packing.</p>
        <p data-source-node="n100"> </p>
        <p data-source-node="n101">A) The system checks to see if either the location and/or the allocation rule detail have items with unit of measure(s) that are specified as “Treat as Loose" (set in the Item Unit of Measure Window). If this setting is activated, then the system will not create full containers when inventory is allocated for this unit of measure.For example, suppose you have an item with a CS quantity of 4 EA in its item unit of measure.  However, on either the allocation rule detail or on the location, only the unit of measure EA is selected. The system then will not create full containers for the item (even if 8 EA were allocated) because they were allocated in a unit of measure of EA. Note that if there is no item unit of measure configured, the system will reference the "Treat As Loose" value defined on the shipment line.</p>
        <p data-source-node="n102"> </p>
        <p data-source-node="n103">B) The system creates the containers in priority order. Priority is determined by the priority of the shipment line associated with the container. </p>
        <p data-source-node="n104"> </p>
        <p data-source-node="n105">C) The system accesses the item unit of measure record for the item and UM of the new full container. The container type the system assigns to the full container is simply the quantity unit of measure (for example, CS or PL). Note that for this to occur, you need to define container types for your units of measure (CS, PL, etc.), so that the system can assign the correct container group on the containers it creates.The system also retrieves the following values from the item UM record: length, width, height, maximum weight, and empty weight.</p>
        <p data-source-node="n106"> </p>
        <p data-source-node="n107">D) The system generates a container ID for the container. It applies the values it obtained during Steps B and C (above) to this container.</p>
        <p data-source-node="n108"> </p>
        <p data-source-node="n109">E) The system completes this process (Steps B-D) for all full container quantities.</p>
        <p data-source-node="n110"> </p>
        <p data-source-node="n111"> </p>
        <p data-source-node="n112"><b style="text-decoration: underline;font-style: normal" data-source-node="n113">Step 3</b>
        </p>
        <p data-source-node="n114">A) After the system assigns container IDs to full containers, it determines if any loose quantity records need to be packed. During allocation, these loose quantities were created when the system broke lines into full container and the remaining eaches. The system organizes all of the loose quantity records based on two things: first, by packing class; and second (if needed) by the "order by" settings on the appropriate container creation criteria record. This ensures that related quantities can be packed together.</p>
        <p data-source-node="n115"> </p>
        <p data-source-node="n116"> </p>
        <p data-source-node="n117"><b style="text-decoration: underline;font-style: normal" data-source-node="n118">Step 4</b>
        </p>
        <p data-source-node="n119">A) The system retrieves the first loose quantity record and identifies its packing class. A loose quantity record represents one item allocated for one shipment. It can include multiple units of the same item.</p>
        <p data-source-node="n120"> </p>
        <p data-source-node="n121">B) The system determines which packing class should be used to process this record. If the packing class is defined on the shipment line record (either interfaced, or obtained from the item master), the system uses this value. If the record is not associated with a packing class, the system uses the *Default record.</p>
        <p data-source-node="n122"> </p>
        <p data-source-node="n123">C) The system retrieves the container group associated with this packing class.</p>
        <p data-source-node="n124"> </p>
        <p data-source-node="n125"> </p>
        <p data-source-node="n126"><u style="font-weight: bold" data-source-node="n127">Processing Notes</u>
        </p>
        <ul data-source-node="n128">
            <li data-source-node="n129">The following scenario is not supported: Creating containers during the wave (the work generated from allocation requests), and then executing the pick/putaway into a shipping container via RF, as the system would have no way to link the work from the allocation requests to the existing container that you would be picking into. <br data-source-node="n130"><br data-source-node="n131"></li>
            <li data-source-node="n132"><i data-source-node="n133">User Defined Fields:</i> When the system creates a "loose" container, the user defined fields on the record for that container are filled from the Shipment record.  The user defined fields on the individual container detail records are filled from the corresponding shipment line.  When the system creats a "full" container, the user defined fields are filled from the shipment line.</li>
        </ul>

        <h4 data-source-node="n141"><a name="multiThreaded" data-source-node="n142"></a>Multi-Threaded Container Creation...</h4>
        <p data-source-node="n143"> </p>
        <p class="p_5" style="font-weight: normal" data-source-node="n144">This process involves having the system determine 
 the number of shipments that it will attempt to create containers for 
 at one time (using multiple processing threads). A value in the Technical Values 
 Window determines the number of shipments that the system will attempt 
 to create containers for simultaneously. This, in turn, determines the 
 number of threads that the system will use. For example, if this value 
 is set at 2, the system will concurrently try to create containers for 
 two shipments (each on its own separate thread). When the container creation 
 process ends for one shipment, the system will begin creating containers 
 for another shipment on the next available thread. This process continues until 
 all containers have been created. </p>
        <p data-source-node="n145"> </p>

        <h4 data-source-node="n154"><a name="determine" data-source-node="n155"></a>Determining the Volume Amount To Pack Into a Container...</h4>
        <p data-source-node="n156"> </p>
        <p data-source-node="n157"> </p>
        <p data-source-node="n158">To determine the amount of volume needing to be packed into a container, the system calculates the volume of the item being packed times the quantity being packed:</p>
        <blockquote data-source-node="n159">
            <p data-source-node="n160">Volume to Pack = Item Length  x  Item Width  x  Item Height  x  Quantity of Item to Pack</p>
        </blockquote>
        <p data-source-node="n161"> </p>
        <p data-source-node="n162">The container itself can only be filled up to its fill percent.  This means if the fill percent is 80%, the container can only be packed up to 80% full.  Therefore, the usable volume of the container type is calculated as:</p>
        <blockquote data-source-node="n163">
            <p data-source-node="n164">Container Type Volume = Container Length  x  Container Width  x  Container Height  x  Fill Percent of Container Type</p>
        </blockquote>
        <p data-source-node="n165"> </p>
        <p data-source-node="n166">To find the remaining capacity of the container, the system takes the usable volume of the container type minus the volume already used:</p>
        <blockquote data-source-node="n167">
            <p data-source-node="n168">Remaining Capacity = Container Type Volume – Volume of Container Already Filled</p>
        </blockquote>
        <p data-source-node="n169"> </p>
        <p data-source-node="n170">If the remaining capacity is greater than or equal to the volume to pack, then the quantity will fit into the container.  If not, it cannot fit into the container.</p>
        <p data-source-node="n171"> </p>
        <p data-source-node="n172"> </p>
        <p data-source-node="n173"><a href="#top" style="font-style: italic" data-source-node="n174">Back To Top</a>

        <h4 data-source-node="n181"><a name="stabAm" data-source-node="n182"></a>Stabilization Amount/Codes...</h4>
        <p data-source-node="n183">Stabilization amount  refers to the amount of packing material (a single layer) between any two contact surfaces (i.e. items) in a container. This is communicated via item-specific codes are made up of character(s) in a numeric format (whole number or decimal). The maximum of these values for all items packed into a container will be used to define the amount of padding around each item in the container. These items are communicated via an “item list” (which is compiled by the 3D Cubing container creation strategy), that lists out per unit of measure each item/company and its associated stabilization code.</p>
        <p data-source-node="n184"> </p>
        <p data-source-node="n185"> </p>
        <p data-source-node="n186">Once the stabilization code has been assigned, then 3D cubing adds the item stabilization code value to either side of the item's dimensions. For example, suppose an item's dimensions are the following:</p>
        <blockquote data-source-node="n187">
            <p data-source-node="n188">Length = 2</p>
            <p data-source-node="n189">Width = 3</p>
            <p data-source-node="n190">Height = 4</p>
        </blockquote>
        <p data-source-node="n191">And, suppose that the stabilization code that has been assigned is "0.5". This indicates that you want 0.5 spacing on all sides of 1 EA of the item. </p>
        <p data-source-node="n192"> </p>
        <p data-source-node="n193">Therefore, the optimum packing dimensions for this item would be the following:</p>
        <blockquote data-source-node="n194">
            <p data-source-node="n195">Length = 2 + (0.5 x 2)</p>
            <p data-source-node="n196">Width = 3 + (0.5 x 2)</p>
            <p data-source-node="n197">Height = 4 + (0.5 x 2)</p>
            <p data-source-node="n198"> </p>
            <p data-source-node="n199">Packing dimensions for this item (with stabilization code applied) = 3 x 4 x 5</p>
        </blockquote>
        <p data-source-node="n200"> </p>

        <h4 data-source-node="n279"><a name="3DCBalgos" data-source-node="n280"></a>Packing Algorithms...</h4>
        <p data-source-node="n281"> </p>
        <p data-source-node="n282">The 3D cubing strategy process through several algorithms when attempting to determine if an item quantity will fit into a container type. If the item quantity is successfully packed using one of the algorithms, then the strategy will stop processing through the algorithms.</p>
        <p data-source-node="n283"> </p>
        <p data-source-node="n284">The algorithm processing sequence is as follows:</p>
        <ol data-source-node="n285">
            <li value="1" data-source-node="n286"><a href="#algo1" data-source-node="n287">Same Pack</a>
            </li>
            <li value="2" data-source-node="n288"><a href="#algo3" data-source-node="n289">Default Pack</a>
            </li>
            <li value="3" data-source-node="n290"><a href="#algo4" data-source-node="n291">Two-Item Pack</a>
            </li>
            <li value="4" data-source-node="n292"><a href="#algo5" data-source-node="n293">Three-Item Pack</a>
            </li>
        </ol>
        <p data-source-node="n294"> </p>
        <p data-source-node="n295"><a name="algo1" data-source-node="n296"></a>ALGORITHM ONE: SAME PACK</p>
        <p data-source-node="n297">The “Same Pack” algorithm is the first algorithm that the 3D Cubing container creation strategy runs when it attempts to determine if an item can be geometrically packed into a container type. In essence, the “Same Pack” algorithm tries to pack the largest item that needs to be packed. Suppose there are five EA of Item1 (h=2, w=3, h=4) and five EA of Item2 (h=1, w=2, h=3). The algorithm then would try to pack a quantity of ten EA of Item1 (the item with the larger dimensions). Logically, then, any container type that could fit ten EA of the larger Item1 could therefore pack five EA of Item1 and five EA of Item2.</p>
        <p data-source-node="n298"> </p>
        <p data-source-node="n299">Below are the specific processing steps of the “Same Pack” algorithm:</p>
        <p data-source-node="n300"> </p>
        <p data-source-node="n301">(A) All items to be packed are assumed to be of the same size as this imaginary item.  This imaginary item is assumed to have the following:</p>
        <blockquote data-source-node="n302">
            <p data-source-node="n303">Length = the largest length value of all the items.</p>
            <p data-source-node="n304">Width = the largest width value of all the items.</p>
            <p data-source-node="n305">Height = the largest height value of all the items.</p>
        </blockquote>
        <p data-source-node="n306">(B) The algorithm determines which container type(s) can be considered according to the items’ packing class settings. These items are checked as to what container type(s) they would physically be able to fit in. This imaginary item quantity can fit in a container type, the algorithm assumes that all of the actual items would fit. Note that the algorithm checks the volume prior to checking the dimensions.</p>
        <p data-source-node="n307"> </p>
        <p data-source-node="n308">(C) The algorithm uses six different ways of aligning items in a container type:</p>
        <blockquote data-source-node="n309">
            <p data-source-node="n310">I. 	- Largest dimension of the item along the largest dimension of the container</p>
            <p data-source-node="n311">- Middle dimension of item along the middle dimension of the container</p>
            <p data-source-node="n312">- Smallest dimension of item along the smallest dimension of the container</p>
            <p data-source-node="n313"> </p>
            <p data-source-node="n314">II. 	- Largest dimension of the item along the middle dimension of the container</p>
            <p data-source-node="n315">- Middle dimension of the item along the smallest dimension of the container</p>
            <p data-source-node="n316">- Smallest dimension of the item along the largest dimension of the container</p>
            <p data-source-node="n317"> </p>
            <p data-source-node="n318">III. 	- Smallest dimension of the item along the largest dimension of the container</p>
            <p data-source-node="n319">- Middle dimension of the item along the middle dimension of the container</p>
            <p data-source-node="n320">- Largest dimension of the item along the smallest dimension of container.</p>
            <p data-source-node="n321"> </p>
            <p data-source-node="n322">IV. 	- Smallest dimension of the item along the largest dimension of the container</p>
            <p data-source-node="n323">- Largest dimension of the item along the middle dimension of the container</p>
            <p data-source-node="n324">- Middle of the item along the smallest of the container.</p>
            <p data-source-node="n325"> </p>
            <p data-source-node="n326">V. 	- Middle dimension of the item along the largest dimension of the container</p>
            <p data-source-node="n327">- Smallest dimension of the item along the middle dimension of the container</p>
            <p data-source-node="n328">- Largest dimension of the item along the smallest dimension of the container.</p>
            <p data-source-node="n329"> </p>
            <p data-source-node="n330">VI. 	- Largest dimension of the item along the largest of the container</p>
            <p data-source-node="n331">- Smallest dimension of the item along the middle dimension of the container</p>
            <p data-source-node="n332">- Middle dimension of the item along the smallest dimension of the container.</p>
        </blockquote>
        <p data-source-node="n333">(D) If the number of items that can be packed equals the number of items that were sent to the algorithm, then processing was successful, and the items are packed into the container. </p>
        <p data-source-node="n334"> </p>
        <p data-source-node="n335"> </p>
        <p data-source-node="n336">Same Pack Example...</p>
        <p data-source-node="n337">Suppose a shipment has to be packed that has five items. The algorithm packs the first four items in the following manner:</p>
        <ol data-source-node="n338">
            <li value="1" data-source-node="n339">The <i data-source-node="n340">dimlarge</i>, <i data-source-node="n341">dimmiddle</i> and <i data-source-node="n342">dimsmall</i> of the item should be aligned along the <i data-source-node="n343">dimlarge</i>, <i data-source-node="n344">dimmiddle</i> and <i data-source-node="n345">dimsmall</i> of the container.<br data-source-node="n346"><br data-source-node="n347"></li>
            <li value="2" data-source-node="n348">However, suppose it is determined that the fifth item should be packed in the following manner:<br data-source-node="n349"><br data-source-node="n350">- The <i data-source-node="n351">dimmiddle</i> of the item should be aligned along the <i data-source-node="n352">dimlarge</i> of the container.<br data-source-node="n353">- The <i data-source-node="n354">dimsmall</i> of the item should be aligned along the <i data-source-node="n355">dimmiddle</i> of the container.<br data-source-node="n356">- The <i data-source-node="n357">dimlarge</i> of the item should be aligned along the <i data-source-node="n358">dimsmall</i> of the container.<br data-source-node="n359"><br data-source-node="n360"></li>
            <li value="3" data-source-node="n361">Then the fifth item will therefore be packed in this way.</li>
        </ol>
        <p data-source-node="n362"> </p>
        <p data-source-node="n363"> </p>
        <p data-source-node="n364"> </p>
        <p data-source-node="n365"><a name="algo3" data-source-node="n366"></a>ALGORITHM TWO: DEFAULT PACK</p>
        <p data-source-node="n367">The “Default Pack” algorithm is the second algorithm that the 3D Cubing container creation strategy runs when it attempts to determine if an item can be geometrically packed into a container type. This algorithm attempts to fit an item into a container, and then divides the remaining space into “cuboids.” A “cuboid” is a standard term for a rectangle in three-dimensional plane. It then tries to find the smallest cuboid into which the next item can fit. Each time an item is packed into the container, the container is divided into cuboids.</p>
        <p data-source-node="n368"> </p>
        <p data-source-node="n369"> </p>
        <p data-source-node="n370">Below are the processing steps of the “Default Pack” algorithm:</p>
        <p data-source-node="n371"> </p>
        <p data-source-node="n372">(A) The algorithm determines which container type(s) can be considered according to the items’ packing class settings.</p>
        <p data-source-node="n373"> </p>
        <p data-source-node="n374">(B) Then the algorithm determines the first item can fit into the selected container type.  </p>
        <p data-source-node="n375"> </p>
        <p data-source-node="n376">(C) The algorithm analyzes the container type's dimensions to determine if any dimension is smaller than that of the item. If this is the case, then the item cannot be packed into this container type, and the algorithm will evaluate the next available container type.</p>
        <p data-source-node="n377"> </p>
        <p data-source-node="n378">(D) Once the algorithm chooses a container type, it then finds the best possible alignment for this item to be packed into the container (after its dimensions have been sorted).</p>
        <p data-source-node="n379"> </p>
        <p data-source-node="n380">(E) The algorithm then packs the item into the container (as seen in the graphic below):</p>
        <p data-source-node="n381"> </p>
        <p data-source-node="n382">
            <img src="../source/assets/ad0fcd08b36095a1966160e0a50b51c6ba916460a37910313948c6be741ba38a.gif" loading="eager" data-source-node="n383">
        </p>
        <p data-source-node="n384"> </p>
        <p data-source-node="n385">(F) After the first item is packed, there very well may be some space left in the container. The algorithm considers this space in the form of three cuboids. Each of these cuboids is conceived as a separate container size (see graphic below). Note that these three container sizes overlap each other.</p>
        <p data-source-node="n386"> </p>
        <p data-source-node="n387">The first cuboid is to the left of the item:</p>
        <p data-source-node="n388">
            <img src="../source/assets/0ad6266898f7785f5c6828b5f00c2fb001cb4b6951b847e1f6efc6a8b5e76592.gif" loading="eager" data-source-node="n389">
        </p>
        <p data-source-node="n390"> </p>
        <p data-source-node="n391">The second cuboid is on top of the item:</p>
        <p data-source-node="n392">
            <img src="../source/assets/620501e8202b2e73fb84db0fe1bed7de1719c6a00849b1ecf6419111c8c1001d.gif" loading="eager" data-source-node="n393">
        </p>
        <p data-source-node="n394"> </p>
        <p data-source-node="n395">The third cuboid is behind the item:</p>
        <p data-source-node="n396">
            <img src="../source/assets/609918297fd018235c84fda780df8d338a7261360d576ca97dc0c9979d2cf7d4.gif" loading="eager" data-source-node="n397">
        </p>
        <p data-source-node="n398"> </p>
        <p data-source-node="n399"> </p>
        <p data-source-node="n400">(G) The algorithm then determines the volume of each of these cuboids. Based on the largest cuboid, the first "container size" is determined.</p>
        <p data-source-node="n401"> </p>
        <p data-source-node="n402">(H) Once this container size is in place, the remaining space is conceived into two sets of two containers sizes each. Each of this set will have non-overlapping container sizes. The algorithm gets the biggest one of this set and determines the remaining two container sizes.</p>
        <p data-source-node="n403"> </p>
        <p data-source-node="n404">(I) There is now one item and three "container sizes" available for the remaining space.</p>
        <p data-source-node="n405"> </p>
        <p data-source-node="n406">(J) The algorithm sorts these container sizes using their dimensions.</p>
        <p data-source-node="n407"> </p>
        <p data-source-node="n408">(K) The algorithm then retrieves the next item quantity to be packed and determines the smallest container size into which it will fit.</p>
        <p data-source-node="n409"> </p>
        <p data-source-node="n410">(L) The algorithm then repeats the process outlined above (from step D on), until all the items are cubed. This is more of a recursive process where the algorithm tries to fit in the item quantity into the smallest available space, and splits the remaining space (within that space) into three smaller spaces. </p>
        <p data-source-node="n411"> </p>
        <p data-source-node="n412"> </p>
        <p data-source-node="n413"><b style="text-decoration: underline" data-source-node="n414">Second Item Cuboids</b> </p>

        <p data-source-node="n423"> </p>

        <p data-source-node="n430"><a name="algo4" data-source-node="n431"></a>ALGORITHM THREE: TWO-ITEM PACK</p>
        <p data-source-node="n432">The “Two Item Pack” algorithm is the third algorithm that the 3D Cubing container creation strategy runs when it attempts to determine if an item can be geometrically packed into a container type. This algorithm is only used when the total allocation request quantity equals two items. It checks for all the combinations in which the items can be packed into the container starting with the smallest dimension. Each of the total allocation request quantity examples shown below would be eligible (note this is not a complete list):</p>
        <ul data-source-node="n433">
            <li data-source-node="n434">2 EA of ItemA</li>
            <li data-source-node="n435">2 EA of ItemB</li>
            <li data-source-node="n436">1 EA of ItemA + 1 EA of ItemB</li>
            <li data-source-node="n437">1 CS (treat as loose) of ItemA + 1 EA of ItemB</li>
            <li data-source-node="n438">2 CS (treat as loose) of ItemA</li>
            <li data-source-node="n439">2 PL (treat as loose) of ItemB</li>
            <li data-source-node="n440">1 CS (treat as loose) of ItemA + 1 CS (treat as loose) of ItemB</li>
            <li data-source-node="n441">1 PL (treat as loose) of ItemA + 1 PL (treat as loose) of ItemB</li>
        </ul>
        <p data-source-node="n442"> </p>
        <p data-source-node="n443">Below are the processing steps of the “Two Item Pack” algorithm:</p>
        <p data-source-node="n444"> </p>
        <p data-source-node="n445">(A) The algorithm determines which container type(s) can be considered, according to the packing class settings.</p>
        <p data-source-node="n446"> </p>
        <p data-source-node="n447">(B) The algorithm checks all the possible combinations of orientation of the dimensions of both items along any dimension of the container. It determines the most optimal packing after considering volume and critical dimensions conditions. All the combinations are checked starting from least feasible to most feasible. The sum of the items dimensions are attempted to be aligned with the following:</p>
        <blockquote data-source-node="n448">
            <p data-source-node="n449">- The smaller dimension of container.</p>
            <p data-source-node="n450">- The middle dimension of the container.</p>
            <p data-source-node="n451">- The largest dimension of the container.</p>
        </blockquote>
        <p data-source-node="n452"> </p>
        <p data-source-node="n453">Two-Item Pack Example...</p>
        <p data-source-node="n454">The method the algorithm uses starts by checking the smallest dimensions for both the item as well as container. Suppose you have the following:</p>
        <blockquote data-source-node="n455">
            <p data-source-node="n456">Item1:</p>
            <p data-source-node="n457">length=1, width=2, height=3</p>
            <p data-source-node="n458">smallest dimension=1, medium dimension=2, largest dimension=3</p>
            <p data-source-node="n459"> </p>
            <p data-source-node="n460">Item2:</p>
            <p data-source-node="n461">length=2, width=3, height=4</p>
            <p data-source-node="n462"><i data-source-node="n463">smallest dimension</i>=2, <i data-source-node="n464">medium dimension</i>=3, <i data-source-node="n465">largest dimension</i>=4</p>
            <p data-source-node="n466"> </p>
            <p data-source-node="n467">Container1:</p>
            <p data-source-node="n468">length=2, width=5, height=8</p>
            <p data-source-node="n469">smallest dimension=2, medium dimension=5, largest dimension=8</p>
        </blockquote>
        <p data-source-node="n470">So, the algorithm will first check whether the sum of the lengths of items are less than that of the container:</p>
        <blockquote data-source-node="n471">
            <p data-source-node="n472">1+2 &lt;= 2</p>
        </blockquote>
        <p data-source-node="n473">This is not true, so the algorithm will consider at other container dimensions:</p>
        <blockquote data-source-node="n474">
            <p data-source-node="n475">1+2 &lt;=5</p>
        </blockquote>
        <p data-source-node="n476">This is true, so the item can be potentially packed. On identifying a potential pack, the algorithm checks whether the other dimensions also match. In this example, the other dimensions are:</p>
        <blockquote data-source-node="n477">
            <p data-source-node="n478">2+3 &lt;= 5</p>
            <p data-source-node="n479">3+4 &lt;= 8</p>
        </blockquote>
        <p data-source-node="n480">So, since the following is true…</p>
        <blockquote data-source-node="n481">
            <p data-source-node="n482">2 &lt;= 8</p>
            <p data-source-node="n483">3 &lt;= 8</p>
            <p data-source-node="n484">1 &lt;= 2</p>
            <p data-source-node="n485">2 &lt;= 2</p>
        </blockquote>
        <p data-source-node="n486">…the algorithm can successfully pack the items into this container type.</p>
        <p data-source-node="n487"> </p>
        <p data-source-node="n488">Below is a graphic visualizing how this would look like (the item would be packed into two rows, one behind the other). Note that the graphic below represents the top view of the container:</p>
        <p data-source-node="n489"> </p>
        <p data-source-node="n490">
            <img src="../source/assets/56f46de20b21337f82b33ab8a5391313f697a1543ab3cee92ecc4381eb1ae220.gif" loading="eager" data-source-node="n491">
        </p>
        <p data-source-node="n492"> </p>
        <p data-source-node="n493"> </p>
        <p data-source-node="n494"> </p>
        <p data-source-node="n495"><a name="algo5" data-source-node="n496"></a>ALGORITHM FOUR: THREE-ITEM PACK</p>
        <p data-source-node="n497">The “Three Item Pack” algorithm is the fourth and final algorithm that the 3D Cubing container creation strategy runs when it attempts to determine if an item can be geometrically packed into a container type. This algorithm is only used when the total allocation request quantity equals three items. Each of the total allocation request quantity examples shown below would be eligible:</p>
        <ul data-source-node="n498">
            <li data-source-node="n499">3 EA of ItemA</li>
            <li data-source-node="n500">2 EA of ItemA + 1 EA of ItemB</li>
            <li data-source-node="n501">1 EA of ItemA + 1 EA of ItemB + 1 EA of ItemC</li>
            <li data-source-node="n502">1 CS (treat as loose) of ItemA + 2 EA of ItemB</li>
            <li data-source-node="n503">1 CS (treat as loose) of ItemA + 1 CS (treat as loose) of ItemB + 1 EA of ItemC</li>
            <li data-source-node="n504">3 CS (treat as loose) of ItemA</li>
        </ul>
        <p data-source-node="n505">The basic premise for this algorithm is that the items will always fit in the same plane. The question is which plane and so we loop through each plane (or dimension of the container).It is similar to the “two item pack” algorithm and this time the combinations of the dimensions of all three items are tried to align along the various dimensions of the container and the most optimal packing is found out. Once the dimension is fit, the problem reduces to a 2D problem. The items are then tried to fit first along long dimension of container, then the middle dimension, and finally the small dimension of the container.</p>
        <p data-source-node="n506"> </p>
        <p data-source-node="n507"> </p>
        <p data-source-node="n508">Below are the processing steps of the “Three Item Pack” algorithm:</p>
        <p data-source-node="n509"> </p>
        <p data-source-node="n510">(A) The algorithm checks to determine which container type(s) can be considered, according to the packing class settings of the item.</p>
        <p data-source-node="n511"> </p>
        <p data-source-node="n512">(B) The algorithm determines the smallest dimension onto which all the items can fit.  The algorithm first selected a dimension that it can definitely fit the all of the three items into; and then it will now check whether the other dimensions fit as well. In other words, since one dimension is now determined, the algorithm now needs to account for the other two dimensions.</p>
        <p data-source-node="n513"> </p>
        <p data-source-node="n514">(C) In order to fix a dimension as height, the algorithm runs through all container dimensions (smallest to biggest), checks them against the item dimensions (in order of biggest to smallest) to determine the smallest container dimension that can be set as the height.</p>
        <p data-source-node="n515"> </p>
        <p data-source-node="n516"> </p>
        <p data-source-node="n517">Three-Item Pack Example...</p>
        <p data-source-node="n518">- Suppose you have the following:</p>
        <blockquote data-source-node="n519">
            <p data-source-node="n520">Item1: Length=2, Width=3, and Height=4</p>
            <p data-source-node="n521">Item2: Length=3, Width=4, and Height=5</p>
            <p data-source-node="n522">Item3: Length=4, Width=5, and Height=6</p>
            <p data-source-node="n523">Container: Length=5, Width=6, and Height=9</p>
        </blockquote>
        <p data-source-node="n524">- The algorithm will first find the dimension into which all these items can fit:</p>
        <ul data-source-node="n525">
            <li data-source-node="n526">In this case, the algorithm would choose the planes along the dimension 9 (2+3+4 fits into this).<br data-source-node="n527"><br data-source-node="n528"></li>
            <li data-source-node="n529">The other dimensions (3+4+5) or (4+5+6) do not fit into any container dimension.</li>
        </ul>
        <p data-source-node="n530">- Now, the algorithm considers this dimension as being fixed, and it looks for ways to fit the items into the other dimensions. Since the calculations remaining only involve two dimensions, the algorithm then processes like the Two Item Pack algorithm.</p>

        <p data-source-node="n538">The 3D cubing container creation strategy has the ability to use a 2D packing algorithm if user specifies item orientation and stackability value of 0. </p>
        <p data-source-node="n539"> </p>
        <p data-source-node="n540">The algorithm for 3D cubing in the application first checks the "Stackability" and "ItemOrientation" attributes of each item. If the item is not stackable or has a fixed orientation (length, width, and Height) the system will call the 2D packing algorithm to place it in the cube. The 2D algorithm here is now enhanced with Item rotation feature which enables system to calibrate the length/width of item to pack a greater number of items in the containers in single row.</p>
