Processing Scenarios...

The following are some of the scenarios for which the SCALE retail functionality is typically used:

 

 

Warehouse Interfacing Store Orders/Distros From ERP

Suppose a company's warehouse houses items for all of its stores. When store orders (also called distros) are interfaced down from the ERP, each order line will contain the stores' name and address data (in the mark for fields). When these orders are waved, the system uses the shipment distribution wave step to "break out" each line as a new shipment, with the item quantity as its new line. These shipments then can be processed in the system and shipped to the appropriate store destination.

 

Note also that if new detail lines are interfaced into SCALE that have the same mark for information as a shipment that has already been waved, the system will add the lines to the existing shipment. Once the shipment is ship confirmed, however, no more lines can be added.

 

 

Warehouse Cross-Docking Product From Receiving Dock To Shipping Dock

In addition, a warehouse may receive in product that the company wants to immediately send directly to a store, without processing though the regular flow in the warehouse. To do this, the item(s) being cross docked need to be immediate needs eligible. When the product is checked in and located, the system decides if the quantity should be cross docked immediately to the shipping dock, putaway in a put-to-store location, or putaway at an inventory location. For more information on this decision making process, see the retail process flow.

 

 

Warehouse Locating Product To Put-To-Store Locations

When a warehouse receives in product, the system can locate this quantity in to a put-to-store location. A put-to-store location is a location on/near the shipping dock where loose item quantities are putaway, when their final destination is a specific store. Each put-to-store location is assigned to a specific store via the Store Location Assignment Window. For more information on this process, see the retail process flow.

 

 

Put to Store – Putaway Into Shipping Container

Users can pick an item from inventory, and put it away into a shipping container at a specific store's put-to-store location. For example, suppose you are picking 5 EA of ItemA, and you will putaway the quantity at RetailStore234's put-to-store location. At that location is a shipping container that, when ready, will be shipped to RetailStore234. The system will direct the picker to putaway the item quantity onto the container that currently resides at the put-to-store location. Note that you can also use the putaway into shipping container functionality during immediate needs putaway (in addition to this inventory example).

 

 

Using Specialized Inventory Tracking With Retail Functionality
  • Lot Tracking: Fully supported when locating to put-to-store locations.

  • Serial Number Tracking: These are not be supported when splitting receipt containers either for put-to-store processing, or when dealing with residual quantity. Cross docking is, however, supported.

 

Miscellaneous Notes
  • Unlocating Split Containers And Put-To-Store Locations: Suppose you check in and locate a quantity, some of which is located to a put-to-store location, and the remainder is located to an inventory location (to fulfill an immediate need). The system would split the receipt container into two separate containers. Note that if you unlocate these quantities, and then relocate, the system will not locate the quantity to a put-to-store location (as it previously did for the first locating action). It will instead locate that quantity to the Shipping Dock.
