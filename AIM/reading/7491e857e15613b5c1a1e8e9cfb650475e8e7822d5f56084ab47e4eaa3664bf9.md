
        
        <h1 data-source-node="n56"><a name="kanchor2091" data-source-node="n57"></a>Count Level Field</h1>
        <h5 data-source-node="n58">On the Work Special Handling Window (Cycle Count Tab)...</h5>
        <p data-source-node="n59">This field indicates what entity the user will count at a location:</p>
        <blockquote data-source-node="n60">
            <p data-source-node="n61">- <i data-source-node="n62">Standard Count</i>: The user will count the individual cycle count(s) present for the location.</p>
            <p data-source-node="n63"> </p>
            <p data-source-node="n64">- <i data-source-node="n65">Blind Count</i>: As in a standard count, the user will count the individual cycle count(s) present for the location. However, the system does not present any information on screen *except* for the location ID. Therefore, the user is forced to count each item that is physically present in the location without the system guiding them in what should be counted.</p>
            <p data-source-node="n66"> </p>
            <p data-source-node="n67">- <i data-source-node="n68">Count License Plates</i>: The user will count the number of license plate(s) that are currently present at a location. For example, suppose a certain product is housed in a second story location. Since users would not be able to easily access and count the quantity contained in these license plates, you could configure counts for this product to ask for the number of license plates present at the location, rather than a count of the actual quantity. Note that if a license plate count differs from what the system expected, the system will require the user to count the actual quantity contained per license plate. Also note that  multi-item locations always force the user to count individual quantities (even if you have this setting selected on your work special handling).</p>
            <p data-source-node="n69"> </p>
            <p data-source-node="n70">- <i data-source-node="n71">Group Count By Item/Company</i>: The user will count all of the quantity at a given location for the same item/company (regardless of the lot ID, inventory attribute, and/or license plate values):</p>
            <ul data-source-node="n72">
                <li data-source-node="n73">If the user's total-quantity count does not meet the system's total-quantity count, the system will ungroup the cycle count work and display an error message.<br data-source-node="n74"><br data-source-node="n75"></li>
                <li data-source-node="n76">If you are cycle counting multiple items at the same location OR an empty location, then you will have to confirm the counts individually (even if this setting is enabled).<br data-source-node="n77"><br data-source-node="n78"></li>
                <li data-source-node="n79">If you choose to add an item when confirming a grouped count, the system will ungroup the cycle count work and you will need to confirm each count individually. Note that after you add an item, the system will give you the option to continue with the add item action, or to return to the group count.<br data-source-node="n80"><br data-source-node="n81"></li>
                <li data-source-node="n82">If this setting is enabled AND lot/license plate verification is enabled, the system will ungroup the cycle count work and you will need to confirm each count individually.<br data-source-node="n83"><br data-source-node="n84"></li>
                <li data-source-node="n85">The system logs group count labor activity as individual cycle counts.</li>
            </ul>
        </blockquote>
