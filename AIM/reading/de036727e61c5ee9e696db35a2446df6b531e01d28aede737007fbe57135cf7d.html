Defining Document Types

A document type identifies a general document category, such as a pick list or a shipping label, and the physical structure (label or document) of all paperwork associated with the type. The majority of document types are predefined for you. However, you can also create new types to accommodate special documents that are not currently supported by the system.

Procedures...

Create a new record and provide a name and description.

  1. Use the Default Check box to identify if all paperwork generated for this print procedure should be selected on the Print Documents Window. You can also use it to determine if documents are automatically printed for some functional areas, such as packing.

     

    To preselect documents on the Print Documents Window: If the Default Check box is selected for a print procedure, any time a record for that procedure is processed and the user accesses the Print Documents Window, all documents generally printed for this procedure will be preselected.

     

    To automatically print documents: Some functional areas, such as packing, have auto print options. If the auto print option is selected, the Print Window is not displayed. Instead, the system automatically prints all documents associated with a print procedure, if the Default Check box is selected.

     

  2. Use the Print Procedure Field to identify what type of records the system will generate paperwork for. See the Print Procedure Field topic for more information.

     

  3. Use the Data Source Field to indicate if this document type can be produced in a wave. This value determines which data selection records are available when you are defining sequences on the Document Master Window. If this is a predefined record, you will not be able to change this value.
     

  4. Use the Detail Data Source Field to indicate the database table that you want this document to pull its detail information from. Note that when modifying a system supplied document type, it is not valid to change the detail data source setting that is shipped with the system. Additionally, when creating custom document types, you must make sure that document criteria logic exists if you wish to configure your document type with detail data source and your document with document criteria. Note that this field is only referenced by the system during wave processing.

     

  5. Use the Allow Print Preview Check box if employees will be able to view this document before printing. If this is a predefined record, you will not be able to change this value.

  6. Use the Classification Field to indicate to the system that the document type you are creating is a Document (i.e. a piece of paper) or a Label.

    Also, the user can at times override the document routing settings and manually specify a document/label printer to use during a particular business process (such as printing out of the wave). When the paperwork is printed, this setting is used to determine which printer the system will use to print.

  7. SQL Server Reporting Services: Use the Rendered Document PDF File Directory Field in the warehouse as well as in the document type to indicate where you want SQL Server Reporting Services to place rendered (created).pdf files. Note that these .pdf files are not automatically deleted from this directory after they are printed by the default PDF reader application. For additional information, refer to the Rendered Document PDF File Directory Field topic.


  8. Press OK. The system will save your record.
