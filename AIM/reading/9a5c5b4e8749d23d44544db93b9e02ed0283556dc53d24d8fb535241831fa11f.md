
        
        <h1 data-source-node="n56"><a name="kanchor546" data-source-node="n57"></a>Using SCALE's Dynamics AX Built-In Interface</h1>
        <p data-source-node="n58">The following is an overview of how the Microsoft Dynamics AX interface 
 works in SCALE. </p>
        <p data-source-node="n59"> </p>
        <p data-source-node="n60"> </p>
        <p data-source-node="n61"> </p>
        <h4 data-source-node="n62">Interfacing Dynamics AX Data...</h4>
        <p data-source-node="n63"> </p>
        <p data-source-node="n64"> </p>
        <h5 data-source-node="n65">Overview</h5>
        <p data-source-node="n66">SCALE is able to receive and transmit data from Microsoft's Dynamics AX application. 
 Data leaves the Dynamics AX system already formatted to SCALE XML standards 
 (no special style sheet transformation is required). Microsoft Dynamics AX and SCALE transfer data through the use of XML data files (using defined XML schemas), using either MSMQ or a write-to-folder protocol. MSMQ is a "listener service" which interacts with Dynamics AX when 
 transferring data between SCALE and Dynamics AX. This service will continuously 
 check for Dynamics AX data that is eligible to be downloaded/uploaded into 
 SCALE. </p>
        <p data-source-node="n67"> </p>
        <p data-source-node="n68">The system also checks for inbound documents during Queue synchronization, which is a configurable timed batch process. The imported documents can then be processed (batch enabled) into their respective recipient tables and fields. Any errors encountered during the import process will be flagged for manual correction for later import into the system.</p>
        <p data-source-node="n69"> </p>
        <p data-source-node="n70"> </p>
        <p data-source-node="n71"> </p>
        <h4 data-source-node="n72">Touchpoints Supported...</h4>
        <p data-source-node="n73">The Dynamics AX Interface supports the following touchpoints:</p>
        <ul type="disc" class="ul_1" data-source-node="n74">
            <li data-source-node="n75">Inventory Transaction Upload<br data-source-node="n76"><br data-source-node="n77"></li>
            <li data-source-node="n78">Item Master Download<br data-source-node="n79"><br data-source-node="n80"></li>
            <li data-source-node="n81">Receipt Upload &amp; Download<br data-source-node="n82"><br data-source-node="n83"></li>
            <li data-source-node="n84">Order Upload &amp; Download<br data-source-node="n85"><br data-source-node="n86"></li>
            <li data-source-node="n87">Production Orders (Bill of Material in SCALE)<br data-source-node="n88"><br data-source-node="n89"></li>
            <li data-source-node="n90">Returns</li>
        </ul>
        <p data-source-node="n91"> </p>
        <p data-source-node="n92"> </p>
        <h4 data-source-node="n93">General Process Flows...</h4>
        <p class="p_29" data-source-node="n94">Download Flow: 
 Dynamics AX will generate the data for the supported touchpoints. Dynamics AX will 
 then prepare this data as an XML file (formatted to a SCALE XML schema). 
 As this is going on, the Gateway Queue is continuously checking for eligible data to 
 download from Dynamics AX. Once Dynamics AX has finished formatting the data, the 
 data will be interfaced into SCALE via MSMQ, or writing the files to folders. SCALE will either retrieve the XML files from the MSMQ or by using the folder protocol.</p>
        <p data-source-node="n95"> </p>
        <p data-source-node="n96">Upload Flow: For eligible data, 
 the system will prepare an XML file via SCALE XML interface processing. 
 Queue synchronization will then retrieve any available files, and send them to Dynamics AX. 
 </p>
