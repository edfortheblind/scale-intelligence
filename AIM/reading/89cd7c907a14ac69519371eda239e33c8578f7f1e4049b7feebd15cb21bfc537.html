Creating a Scheduled Job

A scheduled job allows you to schedule the executing of repetitive processes that you want the system to run on a regular basis. You can schedule a system process (such as data archiving, interface, replenishment, etc.) to run automatically on a certain time/day.

 

Active Scale Users Note:

The scheduled job is available for Lower level users only.

  • Lower level users.
    • All editable fields will be enabled
    • Can Create, Delete, Copy criteria records
  • Production level user do not have access this screen.

Close and Run Scheduled Jobs Immediately... 

You can use the "Close and Run Now" action (accessible from the Actions Menu of this window) to have the system immediately close and run the selected job that you currently have open. The system will accomplish this by changing the Next Run Time to the current time. This will allow the application to pick to process any records that are available currently, and then reset the Next Run Time according to the scheduling information that you previously configured for this job.

 

 

 

Window Procedures... 

 

Using the Header Fields
  1. Use the Job Name Field to enter a name for your scheduled job.

  2. Use the Job Description Field to enter a text description for your scheduled job.

  3. Use the Job Type Field to indicate which type of job you want to schedule. These are defined on the Batch Submission Config database table on your application server. For a job type to appear in this field, it must be designated as "can be scheduled" in this table.

 

Using the Scheduling Tab
  1. Use the Days To Run Field to indicate what day(s) of the week that you want your scheduled job to run. You can only enter a value in this field if you chose the "days specified" value on the Run At Button.

  2. Use the Run From Button to schedule your job to run continuously during a certain period of time. For example, suppose you want to schedule the replenishment job to run every hour throughout the day. You would need to enter the times your warehouse is in operation (for example, "8am" and "5pm") in the time fields, and you would enter "60" in the minutes field.

  3. Use the Run At Button to schedule your job to run at one specific time during the day. You can also indicate the daily interval that the job is to run. For example, suppose you want to schedule the data archiving job to run every Monday at 2am. You would need to select the Monday checkbox in the Days To Run Field, enter "2am" in the time field, and select the "days specified" button.

 

Using the Parameters Tab
  1. Use the fields on the Parameters Tab to provide the additional data that the job requires to be passed in order for it to perform correctly. The fields that are displayed on this tab will depend on what job type you are scheduling.

 

 

List of Provided Scheduled Jobs...

 

The following is a list of the scheduled jobs provided with the system.

 

Address Validation

- Retrieves potential ship to address matches from Progistics.

 

 

Billing Management Manual Trigger

- Runs all Billing Management Triggers.

 

 

Build Wave

- Builds a wave (with all eligible shipments in the pool) for the indicated warehouse.

  • Only wave masters authorized for the selected warehouse will be available in the wave master list.
  • All wave masters will be shown when the warehouse field is empty.
  • See Defining Wave Masters for more information on wave master warehouse authorization.

 

 

 Create Replenishment Work

- Processes through replenishment requests to see which ones are eligible for work creation, and then calls the work creation process. Eligibility is determined by the following criteria:

1. System checks for replenishment requests that have the "Work Created?" setting set to No.

 

2. If the "Only Select Records With Mark For Work Creation Set To Yes" is selected (on the Scheduled Job Window), the system only retrieves the requests that meet this criteria. If this checkbox is not selected, the system retrieves the requests with the "Mark for Work Creation" set to both Yes and No. Users can mark requests for work creation on the Replenishment Requests Viewer.

 

3. From these requests, the system selects the ones that have the "Create Work Method" = Manual/Scheduled.

 

4. The system then confirms that the replenishment requests meet the following parameters as indicated on the Scheduled Job Window: - Warehouse - Replenishment Type - Replenishment Master

 

5. Finally, the system passes the requests that have met these criteria on to the work creation process.

 

Cycle Count

- If you leave the parameter Cycle Count Master blank, the system will run plans using all existing cycle count masters for a particular warehouse.

 

- If you leave the parameter Warehouse blank, the system will run plans, using the indicated master (that have the Run With Scheduled Job checkbox selected), for ALL warehouses.

 

 

Dashboard Data

- The system ships a "Receipt and Shipment dashboard data collection" scheduled job that runs for all warehouses by default. If you want the job to run at different times for each warehouse, then a scheduled job can be created for each warehouse and each area (Receipts by Time or Shipments by Time).

 

- The dashboard data scheduled jobs insert Planned by time and Actual by time records into the dashboard table for the configured warehouse. The Planned by time records display the number of receipts or shipments scheduled for today’s date at the time the scheduled job had run. An Actual by time record displays the number of receipts or shipments processed for today’s date at the time the schedule job had run. These records are used by the Warehouse Dashboard to show the results in the Receipts by Time and Shipments by Time graphs.

 

 

Data Archive

- Runs all default Data Archive Masters.

 

 

Interface Jobs

- Performs interface uploads/downloads for all interface touchpoints.

Notes:

- “All” mode works for multiple input file formats for download, so that the user can feed in multiple records of different format together.

 

- “All” mode also works when the “All” direction is selected, and the upload and download formats are not the same (such as XML downloads and direct uploads).

 

- “All” mode does not work when you have Upload as the only direction, since the system would have only one Upload mode sending data.

 

Movement Class Analysis Data Collection

- When this scheduled job is run, the system creates movement class records on the movement class analysis database table. These records are culled from the transaction history table (and the transaction history archive table, if the "days to collect" go back far enough). Note that the system will clear any existing records per warehouse in this database table before writing any new records for that warehouse. Therefore, only one set of movement class analysis data will exist in the database at a time.

 

Parameter Field Notes:

  • Warehouse: If you leave this field blank, the system will run the scheduled job over all warehouses.

  • Number of Days to Collect: This indicates the number of days back (starting with current day) that the system will collect data against.

    - The default value for this field is 90

    - The maximum value for this field is 9999

    - Decimal or negative values are not allowed

    - The values 0 and NULL are not allowed

  • Collect Data for Permanent Locations Only: This indicates if the system will collect data for only permanent locations (selected), or for all locations in the warehouse (not selected).

  • Include Archived Data: This indicates if the system will also collect data from the transaction history archive table.

 

Personal Alerts

- Runs any personal view data queries that are configured in SCALE. Once the data results are gathered, the system will send an email message/SMS text (depending on how the notification is configured) to the proper recipient(s).

 

 

Replenishment

- Performs replenishment (select master, mode) for the indicated warehouse.

 

 

Reporting Alerts

- Runs Crystal report(s), and has system send email(s) to people alerting them the report has been generated.

 

- Separate email addresses with a semicolon ( ; )

 

 

Scan and Weigh Processing

- Takes requests out of the Scan and Weigh Requests table on the system and performs the Close Container operation on them. It’s generally used when you want to move the statuses of the containers up when they pass by a scanner on the conveyor.

 

 

Slotting Location Interface Upload

- Runs the upload interface to the Slotting Optimization application for the indicated warehouse. For this upload, the system compiles the eligible item/location data into a text file, which Slotting retrieves and process, so it can make suggestions on inventory movement.

 

 

Slotting Move File Download

- Runs the download interface to the Slotting Optimization application for the indicated warehouse. For this download, the system retrieves the inventory moves file that was created by Slotting. SCALE will use this text file (which includes Slotting's recommendation for inventory transfers) to create inventory transfer work, in order to implement Slotting inventory movement recommendations.

 

 

Ship Confirm All

- Runs the shipment confirmation action for all shipments that are in a ship confirm pending status, and have the indicated order type.

Notes:

  • The Parameters tab allows for an Order Type to be designated for the scheduled job. When you define a specific order type, then the system will confirm only eligible shipments that meet this criteria. If you leave the Order Type blank (NULL), then the system will confirm all eligible shipments, regardless of order type.

  • This scheduled job always uses the "Do No Split" functionality. Note that the system does not honor shipping preferences when performing ship confirmation via this scheduled job (as it is user/preference neutral).

 

Wave Label Data Cleanup

- Deletes all wave label data that belongs to a wave, whose containers are beyond an indicated status.

 

 

Warehouse Alert Processing

- Generates the warehouse alerts that have been configured in SCALE.

 

 

Web Statistics Inbound/Item/Outbound

- The system will only use the Warehouse parameter in the Inbound and Outbound Web Statistics generation processes.

 

- The Item statistics process generates for items in all warehouses.

 

- If the Warehouse parameter is not specified, the system will generate web statistics for all warehouses.

 

- When you manually generate web statistics from the Main Menu, the system will it run the process for the user's current warehouse only.

 

 

Work Priority Escalation

 - This job escalates the priority of eligible work instructions/units (according to the rules defined on the Work Priority Escalation Criteria Window).

 

WORK RECORD ELIGIBILITY

The following parameters are used to determine eligibility:

 

- The Priority Escalate By parameter represents the number of digits that you want the system to update an instruction/unit up in priority (from its original priority) each time this scheduled job is run. Note that you can enter a negative number into this field, and the priority would be escalated higher (say, from 5 to 10).

 

- The Work Priority Escalation Criteria parameter indicates the filter criteria record that you want the scheduled job to use when deciding which work records are eligible for priority updates. This criteria includes rules that are more specific than the general parameters defined on this tab.

 

- The Instruction Aging Time Interval (in min) parameter indicates how long a work record (header or detail) must have existed before it is eligible for the scheduled job to select it for a priority update. This field is measured in minutes.

 

Note that the system will not escalate the priority if a system error occurs or the work instruction is not available to be modified. For example, suppose the Priority Escalate By value is 10, and the work instruction the system returned has a priority of 70. The system has selected a record to update, and before it can update the record, a picker deletes or completes the pick. The system then would not update the work instruction.

 

 

ESCALATION PROCESS

  1. The system selects all the work records (header and detail) that are eligible (aka meet the escalation criteria). The record also must not be “active” (currently being worked on).

    2.  

  2. Then the system goes through the eligible records and updates the priority setting. Note that since every instruction of a work unit is not necessarily being updated by this job (i.e. they were not eligible according to the criteria) the instructions on a particular work unit may have different priorities.


 

PRIORITY ESCALATION EXAMPLES

  • The Priority Escalate By value is 10, and the system returns an eligible work instruction that has a priority of 70. The system will therefore update the work instruction's priority to 60.

  • The Priority Escalate By value is -10, and the system returns an eligible work instruction that has a priority of 70. The system will therefore update the work instruction's priority to 80.

  • The Priority Escalate By value is 10, and the system returns an eligible work instruction that has a priority of 5. The system will therefore update the work instruction's priority to 0 (it will not drive the priority to a negative value).

  • The Priority Escalate By value is -10, and the system returns an eligible work instruction that has a priority of 0. The system will therefore update the work instruction's priority to 10.
