Carrier Configuration

Overview

 

This configuration is to define carrier and carrier service records. These carrier records are considered as Parent or Child record by the system.

 

What does Parent records, child records and inheritance signify

 

The parent record represents the transportation company that offers multiple services at different pricing scales, such as UPS or Fed Ex. A child record represents each service provided by that carrier, such as 2nd Day Delivery or Overnight Delivery. By creating separate records for the carrier and its services, you can minimize setup time by using inheritance. Inheritance allows you to default the appropriate carrier values onto the service records. As soon as you provide a value in the Carrier Field and access the Service Field, the system will display the Inherited option on all other field in the Carrier Window. You can select the option when appropriate, instead of manually entering this information. Of course, you need to define the parent record before you define the child records.

 

Do I Need To Create Both Parent & Child Records?

 

Before setting up a carrier, use the following question to determine if you can benefit from inheritance: Does the carrier provide multiple services that it charges different prices for?

 

  • If yes, you can minimize setup time by creating a parent record and multiple child records. The parent record would identify the carrier. Each child record would identify a specific service that the carrier supported. This will allow you to inherit shared values, such as address and carrier type.

     

  • If no, you should create just a parent record. If you only use one service provided by a carrier, or the carrier does not offer any services, you will not need to inherit values across multiple records. You will only need to create one parent record.

Note: If you select the Inherited option (on any field), the system will default the value from the parent record.

 

Configuration Hierarchy

 

 

Configure Carrier

 

1. Carrier Information

Enter the base carrier values used for parent and child carrier records.

  • Carrier Name, Service, Description, and Type.

  • Contact Name for carrier contacts.

  • Can be used to ship and Can be used in carrier assignment to control shipping and rating eligibility.

2. Authorized Companies

Select one or more authorized companies for the carrier record.

 

3. Authorized Warehouses

Select one or more authorized warehouses for the carrier record.

 
4. General Information

  • Pro Number Set Name for LTL or truckload pro number assignment.

  • Consolidation Dock Location Area for shipment consolidation defaults.

  • Load Size Definition and SCAC values.

5. Shipping Calendar

Configure carrier no-ship days and holidays.

  • Define weekend exclusions and holiday dates used in transit and commitment calculations.

  • Associate the correct shipping calendar to the carrier. Read Shipping Calendar Configuration.

  • This step is available when shipping calendar configuration is enabled.

6. Rating Information

Define rating behavior for the carrier.

  • Charge Requirement: Not Required, System Calculated, or Manually Entered.

  • Route Commit Required to control commitment enforcement during routing.

  • When System Calculated is selected, configure Rating ID, Rating Service, Rating Profile, and optionally FAK LTL Class.

7. Rating Defaults

Review and maintain default rating behavior tied to the selected charge requirement.

  • Maintain default Route Commit Required behavior used during carrier routing and selection.

8. Rating Profile, Rating ID, and Rating Service

Maintain supporting rating master records referenced by carriers.

  • Rating Profile estimates shipment container characteristics during rating.

  • Rating ID identifies the rating engine/source.

  • Rating Service defines carrier/service mapping for external rating calls.

9. Rating Service Endpoint

For supported rating IDs, define endpoint mappings used by rating service operations.

  • Examples include Close Manifest, Print Label, Manifest/Unmanifest Container, and related manifest endpoints.

10. Internet Information

  • Maintain Email Address, Website, Internet Tracking Link, and Available on Web.

11. Miscellaneous

  • Maintain additional miscellaneous carrier attributes, including FAK class behavior when applicable.

12. Carrier Commitments

Define commitment records used to evaluate delivery days for carrier/service scenarios.

  • Configure effective date range, origin and destination country/postal ranges, and days-to-deliver values.

  • Use no-end-date behavior when commitments are open-ended.

  • This section is available when carrier commitments configuration is enabled.
