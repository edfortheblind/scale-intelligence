Carrier Management Process Summary

** Functionality **

Process Flows

 

 

Summary

- Carrier Management controls how all facets of carrier assignment and shipping will be executed in your warehouse.

 

- You can create routing guides, which identify which carrier, or carrier group, can transport product for a specific customer or company. You can define these routing guides per weight range and/or number of containers. For example, this would be helpful if you want to route larger shipments to LTL carriers and smaller ones to parcel carriers.

 

- You can create shipping calendars, which identify days that a carrier, or group of carriers, cannot ship product. You can set no ship days for either specific dates, like holidays, or for Saturday and/or Sunday.

 

- To minimize setup time, you can create one standard carrier record and inherit those values to subsequent records. For example, you could create one record for UPS that identifies the carrier's SCAC Code and corporate address. You would then inherit these shared values on the records you create for UPS' services. This is especially helpful if a carrier offers multiple services.

 

- The system can estimate the number of containers on a shipment during the wave. It will use this information to rate the carriers during the wave.

 

- Most accessorials for UPS and FedEx are predefined for you. You can create additional accessorials to support either these carriers or other carriers that you use.

 

 

Related Topics

- Setup Overview

 

 

 

The following are key features of the allocation functional area:

 

 

Rating & Routing

Routing and rating determine which carrier will transport a shipment. They are run during a wave. First, routing determines if a particular routing guide should be applied to a shipment. If a routing guide should be applied to the shipment, the system will assign the carrier on the guide to the shipment.

 

If a carrier group is defined on the guide, the system will rate all carriers in the group. It will then assign the cheapest carrier to the shipment. If a routing guide was applied to the shipment, rating will calculate the how much it will cost to transport the shipment with the carrier defined on the guide.

 

If a routing guide was not applied to the shipment, rating will select a carrier based on costs. The cheapest carrier that can deliver the package is selected during rating (when no routing guide is applied).

 

 

 

Progistics

Progistics CS is an external rating system that supplies carrier rates to the system. It also generates all shipping labels and parcel manifests. You can access the Progistics application directly on the application desktop.

 

How Does Progistics CS Work?

When you install Progistics CS on your server, it includes the following: a Progistics Software Server, the Progistics Manager Software, and a Software Rate Server for each carrier that you use (and Progistics CS supports). These Software Rate Servers are installed on your site's server. This allows you to perform all manifesting activity onsite: your server will never need to communicate across the intranet or with any device not onsite. This maximizes processing time and ensures that you are not dependent on external systems for your rates.

 

When you create records on particular system configurations, such as the Shipper Code Window, the system communicates that information to the Progistics Software Server and the Progistics Manager Software. When you manifest a container with a particular carrier, the Software Rate Server for that carrier assigns a rate and tracking number to the parcel.

 

Please note that FedEx does require a physical application server, which is located at your site. To streamline the example, UPS is used to represent all non-FedEx carriers, since all other carriers use the same server setup.

 

  1. The system communicates to the appropriate Progistics server components to either convey configuration information or manifest a container:

     

    • When someone maintains a record on any of the following configurations, the system communicates this update to the Progistics Software Server and the Progistics Manager Software:

       

      1. Accessorial Window

         

      2. Rating ID Window

         

      3. Rating Service Window

         

      4. Shipper Code Window

         

      5. Shipper Cross-Reference Window

       

      Please note that these records are originally setup before you can manifest containers. However, you can create, edit and delete these records when you want. If you access the Progistics CS web page, you might configure some of these values. For example, you will need to register the shippers that you defined on the Shipper Code Window. Note that this web page is not an external website. It is actually maintained on either the Progistics Software Server or the Progistics Manager Software.

       

    • When the system transmits a manifest request to the Software Server. This manifest request includes the following information about the container: shipment number, carrier and service, container weight, ship date, ship to name and address, and other values required for processing.

       

      If this carrier is FedEx, continue to a. If this carrier is NOT FedEx, continue to step 2.

       

      1. The FedEx Rate Server Software transmits the manifest request to the FedEx PowerShip Server. This is a physical server that is located at your site, but owned and maintained by Federal Express.

         

      2. The FedEx PowerShip Server processes the request. It transmits the manifest information, rate and tracking number back to the FedEx Rate Server Software. Continue to Step 2.

       

  2. The Progistics component sends a response back to the system.

     

    1. If configuration information was passed during Step 1, the Progistics Services Server and Manager Software will communicate to the system that a record was updated or maintained.

       

    2. If manifesting was attempted during Step 1, the Server Software communicates manifesting information to the system, which stores relevant fields on the container. When necessary, the system retrieves the manifest information from the Server Software.

 

 

LTL Rating

LTL rating is performed within the SCALE system. The freight charge for these shipments is calculated by taking the total weight of the shipment, the final destination and the makeup of the product in the shipment. The makeup of the shipment is broken down into LTL classes. The rate charged is typically lower per pounds for items with lower LTL freight classes. The rate is also determined by the distance traveled. Once all of the carriers and rate base configurations have been defined, the regular rating processing takes place.

 

 

 

Manifesting

Manifesting associates a container with a carrier's parcel manifest. Only containers associated with a parcel carrier are manifested. When a container is packed and closed, the system may automatically manifest it (based on user's packing preference record). Containers can be manually manifested on the Shipping Container Insight screen.

 

During manifesting, the system transmits container specific information, such as its weight, carrier and carrier service, to Progistics CS. Progistics CS contacts the carrier's server and manifests the container. It also retrieves the container's tracking number and its rate. Progistics CS transmits this information to the system. The system displays this information on the Manifest Insight Screen and on the shipment line record. From a user perspective, this process is seamless and very fast.

 

You can remanifest a container as often as you want, until the manifest is closed.

 

Manifest Statuses

This value is defined by the system and displayed on the Shipping Container screen. It identifies the manifest state of the container.

  • Blank - No manifesting attempts have been committed. The container has not been manifested.

     

  • Error - At least one manifest attempt was committed and the container could not be manifested.

     

  • Manifested - The container was successfully manifested. It has been associated with a carrier's manifest. The container has a tracking ID and rate.

     

  • Closed - The container was manifested and shipped. Once a manifest is closed, containers on that manifested cannot be changed or removed from the manifest.

 

 

How Freight Bills Are Assigned

Freight bills can be assigned to the customer, a 3rd party, your warehouse or a company within your warehouse. The system assigns freight bills based on how you have configured the system. Below is a description of how the system determines who pays the freight bill.

  1. The system obtains the freight term from the shipment. If a freight term is not defined, the system assigns the Prepaid term. It checks the corresponding freight term record in the application. If the Shipper Pays Freight? Checkbox is selected for this freight term, the system will assign the shipping cost to the warehouse or a company within it.

     

    • If you support multi-company processing, the system will attempt to assign the shipping costs to the company who provided the product. If the Freight Bill To Tab on the company record contains a bill to address, the system assigns the shipping cost to the company. If this tab is blank, the system will assign the shipping costs to the warehouse.

       

    • If you do not support multi-company processing or a company is not associated with this shipment, the system will assign the freight costs to the warehouse.

     

  2. If the Shipper Pays Freight? Checkbox is not selected, the system checks the shipment record. If values are defined on the freight bill to tab, the system will assign the shipping costs to the party identified here. If this tab is blank, the system will reference the customer tab. If values are defined on the customer tab, that party is assigned the freight bill. If no values are defined on the customer tab, the system will bill the ship to name and address for the freight costs.

 

 

Carrier Compliance

Some carriers are not directly supported by the current SCALE rating system. Therefore, the application provides some generic functionality that can be used to rate shipments using any carrier that you desire. This functionality includes generic paperwork documents that allow container information to be generated for any carrier, as well as interface uploads (in XML format to the Enterprise Integration Services application) that can be used to send data back to any carrier.

 

To handle the container data uploads, the system places the Billing Management data into an output XML file which can be retrieved by the carrier's system. Certain carriers require to be sent to them a document that displays all of the containers that were shipped for a certain day. The system meets this requirement by generating an XML Container List which represents all of the containers on a shipping load, or all containers for a certain day. The system will place this document into the Billing Management output folder on the application server.

 

 

 

 

Rate Shopping

Rate shopping allows you to view potential carriers and their rate charges before assigning a carrier to a shipment. Unlike routing, rate shopping is an interactive process that is initiated by the user per shipment. You can also rate shop against a country/postal code combination before an actual shipment is created. This allows you to give a customer the best delivery option even before an order is placed.

 

Once you analyze the results of your rate search, you can assign a new carrier for your shipment, or choose to keep the existing carrier. Note that you can rate shop any shipment in any status (except shipments that are in an "in process" wave or have been ship confirmed). SCALE uses a web service to calculate the rates and display them on the Rate Shopping Window.

 

SCALE only allows you to rate shop for carriers that the application currently supports. The system will only consider carriers that have system calculated rates (as defined on the Carrier Window). Carriers with manually-assigned rates or no rates are not included in rate shopping.

 

 

 

UPS World Ease

UPS World Ease is a carrier service that expedites the shipping of product to international destinations. It allows for quick movement through the border customs process, and delivery to an intermediate consignee (a hub, for example), which quickly processes packages before shipping them to their final destination. View this diagram to see a more detailed look of the World Ease process flow:

 

World Ease shipments are packed using a special type of shipping label that is affixed each shipping container. These labels include the ship to address for both the intermediate consignee (a hub) and the final shipping destination. Also included with the shipping containers is a separate "document box," which contains the appropriate paperwork that World Ease requires to ship the packages over the border and into the hub destination.

 

SCALE uses "World Ease groups" to represent the container(s) whose final destination is the same intermediate consignee. The system assigns a container to a group during the container manifesting process. When a group is closed, you will be able to print the appropriate World Ease documentation, which includes a special box label, consolidated invoice, certificate of origin, and master invoice.
