
        
        <h1 data-source-node="n56"><a name="kanchor2019" data-source-node="n57"></a>Defining Item Location Capacity for a Location</h1>
        <p data-source-node="n58">When using real time replenishment, you will need to define an item 
 location capacity record for your location(s). This is because the real 
 time mode does not do any mathematical calculations based on dimensions 
 when determining if a location needs to be replenished. Therefore, this 
 mode will only work correctly if you have set up these item location capacity 
 records for each real-time location.</p>
        <p data-source-node="n59"> </p>
        <p data-source-node="n60">The process works as follows: any time a location's quantity is decremented, 
 and the location is set up for 
 real time replenishment, then the system evaluates the quantity based 
 on the capacity. If the location needs replenished, the system flags it 
 so it can be picked up the next time replenishment is run. The system 
 will look to see if the location is eligible for real time replenishment; 
 if it is, the system will replenish the location. If it is not, the system 
 will retrieve the item location capacity record for the particular item 
 and location. </p>
        <p data-source-node="n61"> </p>
        <p data-source-node="n62">Furthermore, if the item location capacity record is set up with a maximum 
 quantity, the system will determine if the quantity at the locations is 
 in need of replenishment. If a maximum quantity is not specified on the 
 item location capacity record, the location will automatically be marked 
 so that it can be reviewed the next time replenishment is executed. </p>
        <p data-source-node="n63"> </p>
        <p data-source-node="n64">For procedures on how to define these 
 records, see the topic     <a href="2fd6c50f08e2ed6af70e6f05558e1c9888dcbab24ffc4a5528b7ea90e18b5817.html" data-source-node="n65">Defining 
 Item Location Capacity.</a></p>
