
        
        <h1 data-source-node="n56"><a name="kanchor951" data-source-node="n57"></a>Configuring DIF Endpoints</h1>
        <p data-source-node="n58">To setup the SCALE Device Integration Framework (DIF), you will need to address some configuration values in the application's database. The second step in this process is to configure a DIF endpoint. An endpoint represents the connection that an MHE and SCALE use to communicate actions (events) via DIF. Note that there is no configuration screen to define endpoints in the SCALE Configurations Explorer. You will need to configure these values directly in the application database's DIF_ENDPOINT table.</p>
        <p data-source-node="n59"> </p>
        <p data-source-node="n60">Note: In order for changes to the DIF_ENDPOINT table to be reflected, you will need restart the DIF Processing Service. </p>
        <p data-source-node="n61"> </p>

        <h4 data-source-node="n81">Procedures...</h4>
        <ol data-source-node="n82">
            <li value="1" data-source-node="n83">Access your application database using a database editing tool such as SQL Server Management Studio.<br data-source-node="n84"><br data-source-node="n85"></li>
            <li value="2" data-source-node="n86">Access the DIF_ENDPOINT database table. Note that each database row represents the configuration record for a separate DIF endpoint.<br data-source-node="n87"><br data-source-node="n88"></li>
            <li value="3" data-source-node="n89">Define values for the following database fields:<br data-source-node="n90"><br data-source-node="n91">DESCRIPTION (alpha-numeric 25): Represents a short description of the endpoint.<br style="color: #000000" data-source-node="n92"><br style="color: #000000" data-source-node="n93">ENDPOINT_ID (numeric 9,0): Represents a unique identifier for an endpoint. This field is required.<br style="color: #000000" data-source-node="n94"><br style="color: #000000" data-source-node="n95">ENDPOINT_HANDLER (alpha-numeric 50): Represents the identifier passed into Spring.NET used to create an instance of the logic handling the protocol communication for the endpoint. The three endpoint handlers provided with the system are: IncomingTCPServerEndpointHandler, OutgoingTCPClientEndpointHandler, and IncomingTCPClientEndpointHandler<br style="color: #000000" data-source-node="n96"><br style="color: #000000" data-source-node="n97">EVENT_ID (numeric 9,0): Represents the event tied to this endpoint. This field is required.<br style="color: #000000" data-source-node="n98"><br style="color: #000000" data-source-node="n99">NAME (alpha-numeric 25): Represents the name of the endpoint.<br style="color: #000000" data-source-node="n100"><br style="color: #000000" data-source-node="n101">USER_DEF1 - USER_DEF6 (alpha-numeric 25): Represents user identified values, similar to other places in the system.<br style="color: #000000" data-source-node="n102"><br style="color: #000000" data-source-node="n103">USER_DEF7 - USER_DEF8 (numeric 14,5): Represents user identified values, similar to other places in the system.<br data-source-node="n104"><br data-source-node="n105">DIRECTION (numeric 9,0):  Represents the direction of the endpoint (0 for incoming, 1 for outgoing)<br data-source-node="n106"><br data-source-node="n107"></li>
            <li value="4" data-source-node="n108">When finished entering values, commit the changes to the database and exit your database editing tool.</li>
        </ol>
