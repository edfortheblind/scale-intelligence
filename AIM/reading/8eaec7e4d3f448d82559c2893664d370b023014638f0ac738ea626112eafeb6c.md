
        
        <h1 data-source-node="n56"><a name="kanchor1123" data-source-node="n57"></a>Defining a Bill of Material</h1>
        <p data-source-node="n58">A bill of material record defines a finished item and its requirements. 
 These requirements include what component parts are required to create 
 the finished item and instructions on how to assemble the finished item 
 from its components. When a work order is generated for a finished item, 
 the system defaults relevant bill of material records on both the work 
 order request and any paperwork generated for the finished item.</p>

        <h4 data-source-node="n181"><a name="BOM" data-source-node="n182"></a>Using 
 the Bill of Materials Window...</h4>
        <p class="p_15" data-source-node="n183"> </p>
        <h5 data-source-node="n184">Using the Header Fields</h5>
        <ol data-source-node="n185">
            <li value="1" data-source-node="n186">Use the Item 
 Field to identify the finished item.<br data-source-node="n187"><br data-source-node="n188"></li>
            <li value="2" data-source-node="n189">
                <p data-source-node="n190">If this finished item is associated 
 with a company, identify it in the Company Field.</p>
                <p data-source-node="n191"> </p>
            </li>
            <li value="3" data-source-node="n192">
                <p data-source-node="n193">Use the Revision Number Field 
 to differentiate between different versions of the same bill of material. 
 If you select the Copy action on an existing bill of material record, 
 the system will replicate that record, and increment its revision number 
 by 1. Therefore, if you have multiple bills of material with the same 
 finished item, when you create a work order, the system retrieves its 
 information from the bill of materials that has the highest-numbered revision. 
 Any other BOM's are ignored.</p>
                <p data-source-node="n194"> </p>
            </li>
            <li value="4" data-source-node="n195">
                <p data-source-node="n196">Use the Quantity 
 UM Field to identify the 
 finished item's unit of measure. Generally, you will select the lowest 
 unit of measure available, unless this record supports the creation of 
 multiple finished items.</p>
                <p data-source-node="n197"> </p>
            </li>
            <li value="5" data-source-node="n198">Use the Planned 
 Unit Build Time Fields to identify how long it should take for 
 someone to build one of these finished items. The time is in hours and 
 minutes.<br data-source-node="n199"><br data-source-node="n200"></li>
            <li value="6" data-source-node="n201">Use the Build 
 Location Field to indicate the location where you want to assemble 
 the finished item that this bill of materials represents. Note that the 
 location specified in this field must be a valid build location (i.e. 
 have a location class of "work order build"). Also, if you do 
 not provide a value in this field, the system will use the default build 
 location defined on the Work Order Preferences Window.</li>
        </ol>
        <p data-source-node="n202"> </p>
        <h5 data-source-node="n203">Using the Item Characteristics Tab Fields</h5>
        <p data-source-node="n204">When you identify the item/company above, the system will default values 
 in this tab's fields if the following conditions exist:</p>
        <ul type="disc" class="ul_1" data-source-node="n205">
            <li data-source-node="n206">The item/company combination is defined in the 
 system on the Item Window.<br data-source-node="n207"><br data-source-node="n208"></li>
            <li data-source-node="n209">The defaulted values were defined on the item 
 record associated with this finished item.<br data-source-node="n210"><br data-source-node="n211"></li>
            <li data-source-node="n212">The defaulted values were defined on the item 
 unit of measure record associated with this finished item or its item 
 class.</li>
        </ul>
        <p data-source-node="n213">- If these values are defaulted, 
 the system displays a note at the bottom of the page indicating that these 
 values were predefined. Provide any values that were not defaulted. Note 
 that if you want the finished item to be located to warehouse storage 
 locations, all dimension values must be provided.</p>
        <p data-source-node="n214">  </p>
        <p data-source-node="n215">- The Item Volume Unit of Measure 
 Value is never defaulted. Provide that value and press Apply. The 
 system will add this bill of materials record. You can now define the 
 components. </p>
        <p data-source-node="n216"> </p>
        <p data-source-node="n217"> </p>
        <h5 data-source-node="n218">Using the Components Tab Fields</h5>
        <p data-source-node="n219"> </p>
        <p data-source-node="n220">When you first access the Components Tab, it will appear blank. </p>
        <ol data-source-node="n221">
            <li value="1" data-source-node="n222">To create a new 
 component, right-click in the data grid and select New Component. 
 The system will display the Bill of Materials Detail Window.</li>
        </ol>
        <p data-source-node="n223"> </p>
        <h5 data-source-node="n224">Using the Instructions Tab</h5>
        <ol data-source-node="n225">
            <li value="1" data-source-node="n226">If appropriate, 
 use this tab to provide instructions on how to create the finished 
 item. These instructions print on the Work Order Instructions Assembly 
 Document. They are also displayed on the Work Order. You can 
 define up to 4000 characters on this tab.</li>
        </ol>

        <h4 data-source-node="n229"><a name="BOMdetail" data-source-node="n230"></a>Using the Bill 
 of Materials Detail Window...</h4>
        <p class="p_5" data-source-node="n231"> </p>
        <h5 data-source-node="n232">Using the Header Fields</h5>
        <ol class="ol_1" data-source-node="n233">
            <li class="li_6" value="1" data-source-node="n234">Use 
 the Component Item Field and the Company Field to identify the 
 component part. If this item was defined in the system, the system will 
 default the item description.</li>
        </ol>
        <p data-source-node="n235"> </p>
        <h5 data-source-node="n236">Using the General Tab Fields</h5>
        <ol data-source-node="n237">
            <li value="1" data-source-node="n238">Use the Build Level 
 Field to identify if component parts are used to create 
 another sub-component. For example, if the employee must first assemble 
 a picture frame (components = frame, glass, back) before it can be included 
 in a gift pack, all of the frame's components would be assigned to a different 
 build level than the remaining components.<br data-source-node="n239"><br data-source-node="n240"></li>
            <li value="2" data-source-node="n241">
                <p data-source-node="n242"> Use the Build Sequence 
 Field to identify-when this component is needed, in relation to 
 other components in the same build level.</p>
                <p data-source-node="n243"> </p>
            </li>
            <li value="3" data-source-node="n244">
                <p data-source-node="n245"> Use the Quantity 
 Needed Per Item Field and the Quantity UM Field to define how many 
 units of this item are required to make the finished item.</p>
                <p data-source-node="n246"> </p>
            </li>
            <li value="4" data-source-node="n247">
                <p data-source-node="n248">Use the Allocation 
 Rule Field to associate this component with a particular allocation 
 rule. Note that if you leave this field blank, the system will use the 
 allocation rule as defined on the Item Window.</p>
                <p data-source-node="n249"> </p>
            </li>
            <li value="5" data-source-node="n250"> Use the Location 
 Field to indicate that you want this component allocated from a 
 particular location.<br data-source-node="n251"><br data-source-node="n252"></li>
            <li value="6" data-source-node="n253">The Inventory Tracked 
 Check box will default the value defined on the Item record for 
 this component. If it is not defined on the Item Window, the system defaults 
 the value defined in the Inventory Tracking Field on the Inventory Values 
 Window.</li>
        </ol>
        <p data-source-node="n254"> </p>
        <h5 data-source-node="n255">Using the Increase Component Quantity Tab Fields</h5>
        <ol class="ol_1" data-source-node="n256">
            <li value="1" data-source-node="n257">Use the Eligible 
 Check box to indicate that this component qualifies for a quantity 
 increase (over allocation) during work creation for work orders. Note 
 that you can only edit these settings prior to the first time allocation 
 is attempted on the work order.<br data-source-node="n258"><br data-source-node="n259"></li>
            <li value="2" data-source-node="n260">Use the Compute 
 Qty As Field to tell the system how you want to indicate the amount 
 of extra allocation for a certain component.<br data-source-node="n261"><br data-source-node="n262">- If "amount" is chosen, 
 then the Increase Qty Field defines a hard quantity for the additional 
 quantity that the system will allocate. Suppose the quantity of the component 
 needed on a work order was 50, and the increase quantity was 10; the system 
 in this case would allocate 60.<br data-source-node="n263"><br data-source-node="n264">- If "percentage" is chosen, 
 then the Increase Qty Field defines a percentage increase for the additional 
 quantity that the system will allocate. For example, if the quantity of 
 the component needed on a work order was 50, and the increase quantity 
 was 10; the system in this case would allocate 55.<br data-source-node="n265"><br data-source-node="n266"></li>
            <li value="3" data-source-node="n267">Use the Minimum 
 Required Qty Field to indicate the minimum quantity of this component 
 that has to be requested on the work order before it will become eligible 
 for this component quantity increase.<br data-source-node="n268"><br data-source-node="n269"></li>
            <li value="4" data-source-node="n270">Use the Increase 
 Qty Field to indicate the actual value of the component increase 
 in allocation. For example, if you wanted the system to allocate ten more 
 components, you would enter "10" into this field. If you wanted 
 the system to allocate fifteen percent more components, you would enter 
 "15" into this field,   without 
 a percent sign.<br data-source-node="n271"><br data-source-node="n272"></li>
            <li value="5" data-source-node="n273">Use the UM Field 
 to view the unit of measure associated with this component.</li>
        </ol>
