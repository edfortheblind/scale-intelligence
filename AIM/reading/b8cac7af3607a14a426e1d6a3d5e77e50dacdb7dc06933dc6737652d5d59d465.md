        <h4 data-source-node="n318"><a name="Activating" data-source-node="n319"></a>Activating Rejected Quantity...</h4>
        <p class="p_5" data-source-node="n320"> </p>
        <p data-source-node="n321">You can move a portion (or all) of a shipment's quantity out of a "rejected" 
 status and into a status between Picking Pending and Ship Confirm Pending. 
 This action can be used to pack/ship a portion of a shipment that the 
 system had previously rejected during the allocation process. 
 For a shipment line to be eligible for this action, it must have quantity 
 in the Rejected (999) status. Also, the leading status of the detail line 
 must be less than or equal to the Ship Confirm Pending status.</p>
        <p data-source-node="n322"> </p>
        <p data-source-node="n323">When you activate a detail's rejected quantity, that inventory gets positively adjusted into the Packing location (or Put-To-Store location, if that is where the allocation request is for).  It is important to note that this inventory doesnot get subtracted from any location, so you must manually find the location where this inventory was taken from, and perform a negative adjustment at that location.</p>
        <p data-source-node="n324"> </p>
        <p data-source-node="n325">Note that if the system rejects a detail quantity in the wave (or during a short pick) and the quantity gets written back to the pool, and then later you use the Activate Rejected Quantity action, the quantity is still in the pool and will likely get shipped again later.  Also, if you end up canceling that shipment or detail after activating the quantity, that quantity is going to get written back to the pool again.  Therefore, if you plan to use Activate Rejected Quantity in your process, it is highly recommended that you set the "Default Status When Shipment Is Rejected" setting (as well as the "Default Status Of Short Picked/Short Putaway Portion Of Shipment" status action) to "Complete Rejection to Pool" or "Delete Rejected."  So, if you activate rejected quantity, there is not a duplicate quantity in the pool to be shipped.</p>
        <p data-source-node="n326"> </p>

        <h4 data-source-node="n352"><a name="Cancelling" data-source-node="n353"></a>Canceling Shipments...</h4>
        <p data-source-node="n354">You may need to cancel a shipment if you decide you do not want to ship 
 a shipment at this time, but you do not want to lose the shipment in the 
 system. When you cancel a shipment, the system sends the shipment back 
 to the shipment pool. If containers exist for a shipment that was canceled, then the system deletes the allocated inventory from the location where the container exists. The inventory will still be on hand at the Shipping Dock location. If containers do not exist for a shipment that was canceled, then the system will subtract the allocated or in transit inventory (depending on whether it's been picked and put away or not) from the To Location on the shipment's allocation requests. Note that the system will only allow you to cancel a shipment if the shipment's leading status falls within Packing Pending and Ship Confirm Pending.</p>

        <h4 data-source-node="n372"><a name="Confirming" data-source-node="n373"></a>Confirming Shipments...</h4>
        <p data-source-node="n374">After you confirm a shipment, the system cannot change the shipment's 
 properties or lines.  All shipments must 
 be confirmed before physically leaving the warehouse. You cannot confirm 
 shipments that have not been released from a wave. Also, you can have 
 the system automatically confirm shipments (of a certain status) via a 
 scheduled job. See the topic                   <a href="89cd7c907a14ac69519371eda239e33c8578f7f1e4049b7feebd15cb21bfc537.html" data-source-node="n375">Creating a Scheduled 
 Job</a> for more details.</p>
        <p data-source-node="n376"> </p>
        <h5 data-source-node="n377">Leading Confirmation Status</h5>
        <p data-source-node="n378">Ideally, a shipment is only confirmed when all its lines are 
 in the leading confirmation status. However, the system will allow you 
 to confirm any line within the entire confirmation status range. 
 If you do not want to confirm a line outside of the leading status, 
 you can split the shipment. All lines in the leading status will remain 
 on the original shipment, which is automatically shipped confirmed. All 
 lines not in the leading status are moved to the new shipment, which will 
 remain open.</p>
        <p align="left" class="p_38" data-source-node="n379"> </p>
        <h5 data-source-node="n380">Confirmation Status Range</h5>
        <p data-source-node="n381">A shipment can only be confirmed if its lines are within the 
 confirm status range, which is defined on the Shipping Preferences Window. 
 If one or more lines are outside of this range, the system will 
 allow you to split the shipment. All lines ready for confirmation will 
 remain on the original shipment, which is automatically shipped confirmed. 
 All lines not ready for confirmation are moved to the new shipment, which 
 will remain open. Also, you can choose not to confirm the shipment at 
 all if any quantity is in a status less than Ready For Ship Confirm. The 
 shipment will instead be transferred to an alternate load.</p>
        <p data-source-node="n382"> </p>
        <h5 data-source-node="n383">Split Shipments &amp; Shipment 
 ID Values</h5>
        <p data-source-node="n384">When a shipment is split, both shipments retain the same Shipment ID. 
 This allows you to easily identify the shipment and associate it with 
 the original order number. The system will assign a new Internal Shipment 
 Number to the new shipment.</p>
        <p data-source-node="n385"> </p>
        <h5 data-source-node="n386">Procedures</h5>
        <ol data-source-node="n387">
            <li value="1" data-source-node="n388">
                <p data-source-node="n389">Access the Shipment Insight screen.</p>
                <p data-source-node="n390"> </p>
            </li>
            <li value="2" data-source-node="n391">
                <p data-source-node="n392">Access the shipment record that 
 you want to confirm. Select the Confirm action.</p>
                <p data-source-node="n393"> </p>
            </li>
            <li value="3" data-source-node="n394">
                <p data-source-node="n395">How the system will proceed is 
 based on the status of each detail line on the shipment.</p>
                <p data-source-node="n396"> </p>
            </li>
            <ul type="disc" class="ul_1" data-source-node="n397">
                <li data-source-node="n398">
                    <p data-source-node="n399">If all lines are in the 
 leading shipping status, the system will attempt to confirm the 
 entire shipment.<br data-source-node="n400"><br data-source-node="n401"></p>
                </li>
                <li data-source-node="n402">
                    <p data-source-node="n403">If all lines are within 
 the shipping status range, you can either attempt to confirm the 
 entire shipment, split it, or move it to a different load. Exactly what the system will do depends on the split shipment setting on your <a href="ea51e197e210aeb91a8eb3f1dd81fee9b81135b4fc8f5b3a0ab00bd7f403f9ed.html" data-source-node="n404">shipping preferences</a> record. You can configure your preferences to either display the split options for you to choose from, or to have the system perform the split action (after confirming with the user that this is ok.<br data-source-node="n405"><br data-source-node="n406"></p>
                </li>
                <li data-source-node="n407">
                    <p data-source-node="n408">If at least one line 
 is not in the shipping status range, the system will let you split the shipment. You can confirm all 
 lines within this range. The system will not allow you to confirm a 
 line that is not in the shipping status range:</p>
                    <p data-source-node="n409"> </p>
                    <p data-source-node="n410">If you decide to split the shipment, you can confirm 
 all of the lines within the shipping status range or only those 
 lines in the leading status range.</p>
                    <p data-source-node="n411"> </p>
                    <p data-source-node="n412">a. If you decide to confirm all of the lines within the 
 range, all of these lines will remain with the original shipment. The 
 system will attempt to confirm this shipment. All lines below the 
 range the system will be associated with a new shipment, which cannot 
 be confirmed.</p>
                    <p data-source-node="n413"> </p>
                    <p data-source-node="n414">b. If you decide to confirm only the lines in the leading shipping 
 status, only those lines will remain with the original shipment. The system 
 will attempt to confirm this shipment. All lines below the leading 
 shipping status will be associated with a new shipment, which cannot be 
 confirmed.</p>
                    <p data-source-node="n415"> </p>
                    <p data-source-node="n416">If you decide to NOT split the shipment, the system 
 will not confirm any of the lines. The entire shipment will remain 
 open.<br data-source-node="n417"> </p>
                </li>
            </ul>
            <p data-source-node="n418"> </p>
            <p class="p_40" data-source-node="n419"><i data-source-node="n420">Confirming the Shipment...</i>
                <br data-source-node="n421"> After the lines are confirmed or split, 
 the system will attempt to confirm the actual shipment. At this point, 
 the system references the shipment information, such as postal 
 code and carrier information. As long as this information is correct, 
 the shipment is confirmed as its lines are already confirmed. If 
 for some reason this information is incorrect (bad postal code, carrier 
 does not deliver to postal code, etc), the system will not confirm the 
 shipment. Instead, it will display a confirmation message indicating why 
 the shipment failed confirmation.</p>
            <p data-source-node="n422"> </p>
            <p data-source-node="n423">Upon ship confirmation, the system will remanifest any containers 
 that are not manifested for today's date and 
 not on a closed manifest. The system will either remanifest the containers 
 for today's date (the true shipping date), or split them into another 
 shipment (if chosen).</p>
            <p data-source-node="n424"> </p>
            <p data-source-node="n425"><i data-source-node="n426">Pending/Failed QC Inspection Note...</i>
                <br data-source-node="n427">If a container has pending or failed QC inspection associated with it at the time of ship confirmation, then the system will prompt the user indicating that they cannot confirm the container's shipment until the QC is performed/resolved.<br data-source-node="n428"><br data-source-node="n429"><i data-source-node="n430">"ERROR" Container Note...</i><br data-source-node="n431">If you attempt to confirm a shipment that has containers of an ERROR container type, then the system will move any of these ERROR containers (if they are in the appropriate status), to a new shipment (assuming that you have your shipping preferences configured to split shipments), and the ship confirmation action will succeed. However, if these ERROR containers are not in a status to be split, then they will stay on the shipment, and the ship confirmation action will fail.<br data-source-node="n432"></p>
            <p data-source-node="n433"> </p>
            <li value="4" data-source-node="n434">After the shipment 
 is confirmed, the system will complete the following tasks, based 
 on your system configurations:</li>

                <p data-source-node="n436"> </p>
                <li data-source-node="n437">
                    <p data-source-node="n438">Assign a carrier.</p>
                    <p data-source-node="n439"> </p>
                </li>
                <li data-source-node="n440">
                    <p data-source-node="n441">Freeze the freight charges.</p>
                    <p data-source-node="n442"> </p>
                </li>
                <li data-source-node="n443">Transmit shipment information back to the 
 ERP.</li>

The new shipment will have the same shipment ID as the shipment the ERP order was deconsolidated from.  See process history for information on the status of the deconsolidated order.</p>

        <h4 data-source-node="n508"><a name="Deleting" data-source-node="n509"></a>Deleting Shipments...</h4>
        <p data-source-node="n510">Occasionally, you might need to delete a shipment that was canceled 
 or entered incorrectly. You can delete any shipment as long as its status is greater than or equal to Picking Pending and less than Load Confirm Pending. Deleted shipments are completely removed from the system.</p>
        <p data-source-node="n511"> </p>
        <p data-source-node="n512">Notes:</p>
        <ul data-source-node="n513">

        <h4 data-source-node="n632"><a name="UPS" data-source-node="n633"></a>UPS Returns Processing...</h4>
        <p data-source-node="n634">The system supports UPS return service accessorials for the following services: 
 UPS Ground, UPS 2nd Day Air, UPS 3rd Day Select and UPS Next Day Air: 
 </p>
        <ul type="disc" class="ul_1" data-source-node="n635">
            <li class="li_5" data-source-node="n636">Print 
 Return Label Accessorial: This produces a "returns" shipping 
 label (which is printed with at the same time as the regular shipping 
 label) that you will include in the shipping container. The customer then 
 would affix this return label onto the package if they want to send the 
 product back to the warehouse.<br data-source-node="n637"><br data-source-node="n638"></li>
            <li class="li_5" data-source-node="n639">Electronic 
 Return Label Accessorial: This does not include a physical label; 
 instead, UPS sends an email copy of the return label to the end customer. 
 If the customer does not want to keep the product, they can print out 
 the emailed return label, affix it to the package, and ship it back to 
 the warehouse. Note that for this accessorial, you must provide the return delivery address email.</li>
        </ul>
        <p data-source-node="n640"> </p>
        <p data-source-node="n641">When a container is manifested with the UPS Return accessorial 
 applied, the system will retrieve a tracking number and an MSN for the 
 return package.</p>
        <ul type="disc" class="ul_1" data-source-node="n642">
            <li data-source-node="n643">Returns Tracking 
 Number Field: This field is a unique identifier assigned to a parcel 
 when is manifested.<br data-source-node="n644"><br data-source-node="n645"></li>
            <li data-source-node="n646">Returns MSN (Master 
 Sequence Number) Field: This field is an internal identifier assigned 
 to a shipping container by Progistics. It is assigned at the same time 
 as the returns tracking number. Progistics uses it to search for containers 
 in its system. <br data-source-node="n647"><br data-source-node="n648"></li>
            <li data-source-node="n649">Returns Shipping/Accessorial 
 Charge Field: This value represents how much UPS will charge to 
 ship the returned package back to the warehouse, plus the accessorial 
 charge it levies for the return label. </li>
