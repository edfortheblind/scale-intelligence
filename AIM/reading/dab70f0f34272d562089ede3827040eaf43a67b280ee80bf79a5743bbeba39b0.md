
        
        <h1 data-source-node="n56"><a name="kanchor1264" data-source-node="n57"></a>Checking In and Locating Product (RF)</h1>
        <p data-source-node="n58">During check in, the system accepts product on the receiving dock into 
 the warehouse. On a RF Device, the system also allows you to locate this 
 product automatically after check in. The procedures below describe this 
 process.</p>
        <p data-source-node="n59"> </p>
        <p data-source-node="n60">NOTE: You cannot check in the receipt lines after a receipt has been closed (i.e. the Closed Date is specified).  However, you can still perform functions on existing receipt containers such as check-in, locate, and unlocate.</p>
        <p data-source-node="n61"> </p>

        <p data-source-node="n246"> </p>
        <p data-source-node="n247">4. ITEM CROSS REFERENCE: (if cross references are used) If an 
 item cross reference has more than one item, you will have to choose which 
 one you want to check in. Note 
 that if the item is in the cross reference and not in the item master, 
 the item will not be found. If it is not in the item cross reference and 
 the item master, the system checks to see if it is on a receipt.</p>
        <p data-source-node="n248"> </p>
        <p data-source-node="n249">5. COMPANY VALIDATION: (for multi-company warehouses) Additionally, the system checks to 
 see if the item has more than one company associated with it. If so, we 
 display to the user a screen to choose a company. If not, then the item 
 is not assigned a company. If the user does not have authority to access 
 an item's company, the system will not display this receipt. You can change 
 a user's authority in the Security Window.</p>
        <p data-source-node="n250"> </p>
        <p data-source-node="n251">6. MAIN CHECK IN SCREEN: Identify 
 the quantity and correct unit of measure for the product you want to check 
 in. If there is an Item Unit of Measure record for the item you are checking 
 in, the Item UOM field will indicate the conversion quantity next to a 
 unit(s) of measure. If no Item UOM records exist, the system will display 
 only the base unit of measure in this field. When finished, press OK.</p>
        <p data-source-node="n252"> </p>
        <p class="p_8" data-source-node="n253">7. 
 VALIDATIONS:  If 
 configured to do so, you will also have to enter:</p>
        <ul type="disc" class="ul_1" data-source-node="n254">
            <li data-source-node="n255">LICENSE PLATE ID: System will ask for the license plate ID that you want to associate with this 
 checked-in item. Provide one and press OK. Otherwise, the system will 
 create this ID for you.<br data-source-node="n256"><br data-source-node="n257"></li>
            <li data-source-node="n258">CHECK IN VERIFICATION: 
 System will display a "Check In Verification" message, 
 based on your receiving preferences record (the Verify Item Dimensions 
 Checkbox). You will need to decide if you want to continue checking in 
 product in which all the dimensions are not defined. Choose "Yes" 
 to continue, or "No" to cancel. If you did not choose to have 
 the system verify dimensions, then no message will appear.<br data-source-node="n259"> </li>
            <li data-source-node="n260">DISPOSITION 
 CODE: System will display a Disposition Code screen, which allows 
 you to enter information about the condition of the item you are checking 
 in. This information is not required, simply do not enter it if your warehouse 
 does not require it.<br data-source-node="n261"><br data-source-node="n262"></li>
            <li data-source-node="n263">INVENTORY TRACKING: System will display the Enter Special Information screen, 
 if the item you are checking in requires special tracking values such 
 as lot ID, serial number, and/or catch weight. For serial numbers, you 
 will need to provide, if necessary, the major and minor serial values 
 for an item. A new entry screen will appear for every each you are attempting 
 to check in. Note that if the item you are checking in is configured for serial number range entry, then the system will display a special screen that allows you to enter the first and last serial number in the range of numbers that is on the quantity that you are checking in. You can press the Skip Button to return to the regular serial number entry screen, so you can manually enter each number as opposed to providing the range.<br data-source-node="n264"><br data-source-node="n265">If you change the status or Expiration Date of 
 the lot for an item, the system will display the Lot Update Confirmation 
 Window. Review the detail information and press OK if you want to apply 
 the lot change. </li>
        </ul>
        <p data-source-node="n266"> </p>
        <p data-source-node="n267">8. START CHECK IN/LOCATING PROCESS: After pressing OK, the system will check in and locate the product. When 
 you do this, the system will only locate the containers that were just 
 created by the check in process. Note that a single check in can create 
 multiple containers.</p>
        <p data-source-node="n268"> </p>
        <p data-source-node="n269">- If the system converted the container's 
 unit of measure during check in, it will only locate in the unit 
 of measure it selected (during check in). For example, if the receipt 
 line included 10 eaches and the system converted that to 1 case, it 
 can only locate a case unit of measure. It cannot locate 10 eaches.</p>
        <p class="p_7" data-source-node="n270"> </p>
        <p class="p_7" data-source-node="n271">- You cannot locate items with different 
 unit of measure records to the same location. For 
 example, suppose location LOC123 contains a quantity of item A1 (with 
 a casepack of 10). You then locate an additional quantity of item A1 (with 
 a casepack of 8). The system will not locate this additional quantity 
 because of the difference in the UM's of each casepack. However, if you 
 locate some more A1 that has also has a casepack of 10, then the system 
 will allow you to locate, as both quantities of A1 have the same UM properties.</p>
        <p class="p_7" data-source-node="n272"> </p>
        <p class="p_8" data-source-node="n273">- If 
 the "Nest During Check In" checkbox on your Receiving Preferences 
 was selected, the system will nest the container(s) on a receipt 
 into one container. At the end of the check in process, the system will 
 display a screen where you will enter a license plate ID and the container 
 type.  The 
 system then will nest the container(s) that you checked in during that 
 “session” into the new container. Note that you can configure security 
 for this process to skip nesting (see the "RF Receiving Container 
 Nesting" value in the Security Window).</p>
        <p class="p_8" data-source-node="n274"> </p>
        <p class="p_8" data-source-node="n275">- When Using Delayed Locating: If the receipt container’s locating rule has Delayed Locating checked and the user’s receiving preference has Create Work Putaway checked, then the receipt container will locate to a location with the Receiving Pre-locate location class.  If either flag is unchecked, then the system locates based on the receipt container’s locating rule details.  The locating rule on the parent container is used when locating by parent, while the nested container’s locating rule is used when locating by child.</p>
        <p class="p_8" data-source-node="n276"> </p>
        <h5 data-source-node="n277">When Using Quick Receiving</h5>
        <p class="p_8" data-source-node="n278">- If the Bypass Location Capacity Validation Checkbox on your Receiving Preferences was selected, the system will suppress the following validations (any other validations will remain to be enforced): dimensions (length, width, height, weight), volume, and item location capacity.</p>
        <blockquote data-source-node="n279">
            <p class="p_8" data-source-node="n280">This setting has the following behavior depending on which quick receiving execution method is used:</p>
            <ul data-source-node="n281">
                <li data-source-node="n282">Quick Receive-User: The validations mentioned above will always be bypassed.<br data-source-node="n283"><br data-source-node="n284"></li>
                <li data-source-node="n285">Quick Receive-System: The validations mentioned above will be bypassed only if the user is overriding the system-selected location.</li>
            </ul>
        </blockquote>
        <p class="p_8" data-source-node="n286">- If the "Override System Selected Location" checkbox on your Receiving Preferences was selected, you can enter an alternate putaway location (different than the system-selected location) during license plate check in (when using the Quick Receive-System execution method). Note that you cannot use this setting when using the Quick Receive-User execution method.</p>
        <p class="p_8" data-source-node="n287"> </p>

The user will need to use either the Receipt Workbench, or RF Receiving with a Receiving Preference configured with the License Plate initiation method to locate a skipped receipt container.</p>

        <p data-source-node="n306"> </p>
        <h5 data-source-node="n307">Note 
 When Locating To Multi-Item Locations</h5>
        <p data-source-node="n308">The locating process does a volumetric validation when locating an item 
 to a multi-item location. When locating to a multi-item location, the 
 system compares the current volume of the location's items to the total 
 volume of the location to determine if a receipt container will fit. For 
 example, suppose a receipt container has 10 of Item A in it, for a total 
 volume of 100. Location AA001 currently contains Item A and Item B, with 
 a total volume of 250. Also, location AA001 has a total volume capacity 
 (using location type dimensions) of 500. The system, then, would successfully 
 locate the receipt container to the multi-item location. Note that the 
 system performs this volume check only when there is no item location 
 capacity records defined for the item you are trying to locate. If an 
 item location capacity record exists for the item/item class and location/location 
 type, the system would use it to determine the amount of the item that 
 can be placed into the location.  </p>
        <p data-source-node="n309"> </p>
        <p data-source-node="n310"> </p>
        <p data-source-node="n311">NOTE: The locating process does not execute the volumetric calculation on a multi-item location when the location type is defined with a blank value.  This is helpful if you want to, for example, create a returns location, and have the system treat it with infinite capacity so unlimited returns can be located there. In this case, you would want to make sure that no location type is assigned to the location (instead of, say, assigning a location type with a dimensions/volume = 999999), and the system will treat the location as infinite in size, and not execute the volumetric calculation during locating. </p>
