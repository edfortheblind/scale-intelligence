
        
        <h1 data-source-node="n56"><a name="kanchor1221" data-source-node="n57"></a>Defining Locating Rules</h1>
        <p data-source-node="n58">A locating rule identifies the rule details the system will use to locate 
 product. A rule detail determines which location the system will assign 
 product to. Generally a locating rule includes multiple details, which 
 the system processes in numerical order (10, 20, 30, etc.).</p>
        <p data-source-node="n59"> </p>
        <h5 data-source-node="n60">Note on Locating Non-Inventory Items<br data-source-node="n61"></h5>
        <p data-source-node="n62">Since non-inventory tracked
 items must be associated with a permanent location, the system will always 
 attempt to locate the item to permanent locations only.<br data-source-node="n63"></p>
        <p data-source-node="n64"> </p>

        <h4 data-source-node="n105">Procedures...</h4>
        <h5 style="font-weight: normal" data-source-node="n106">Before you identify a rule's details, access the Locating Rule Window. 
 Name this record and provide peripheral information (description, etc). 
 Select the Apply Button. The system will add the header record. Right-click 
 and select the New action. The system will open the Location Rule Detail 
 Window.</h5>
        <ol data-source-node="n107">
            <li value="1" data-source-node="n108">
                <p data-source-node="n109">Use the Locating Name Field 
 to default rule set's name.<br data-source-node="n110"><br data-source-node="n111"></p>
            </li>
            <li value="2" data-source-node="n112">
                <p data-source-node="n113">Use the Delayed Locating Checkbox (along with the Create Work Putaway checkbox on receiving preferences) to indicate whether this locating rule will temporarily locate the receipt container to the receiving pre-locate location.  If either checkbox is unchecked, then the system locates based on the receipt container’s locating rule details.</p>
            </li>
            <p data-source-node="n114"> </p>
            <li value="3" data-source-node="n115">
                <p data-source-node="n116">Use the Sequence Field to 
 indicate what order you want the system to process this rule detail. The 
 lower the sequence number, the sooner its processed. You cannot use the 
 same sequence number for multiple detail records. </p>
                <p data-source-node="n117"> </p>
            </li>
            <li value="4" data-source-node="n118">
                <p data-source-node="n119">Use the Locating Strategy Field 
 to assign a strategy to this detail. You must assign a strategy 
 to a rule detail. A sequence record can also include a location selection 
 value. A locating strategy defines the system's methodology for selecting 
 a storage location for checked in product. For example, if you select 
 the strategy Consolidate, the system will attempt to locate product to 
 locations that already contain it. Review descriptions of each locating 
 strategy on the    <a href="8381c19fea23f7a12459db8b1554abc1f9577a5afa84eb0d4be0946c7b5d355b.html" data-source-node="n120">Locating Strategy 
 Field</a>.</p>
                <p data-source-node="n121"> </p>
            </li>
            <li value="5" data-source-node="n122">
                <p data-source-node="n123">Use the Location Selection Field 
 to assign a location selection to this detail. This is    not required. A location selection record works with the strategy 
 to help narrow the locations considered for locating. This minimizes processing 
 time and increases your control over locating activity. The location selection 
 can also have a sort defined, which the system will use to organize the 
 locations selected for possible locating activity.</p>
                <p data-source-node="n124"> </p>
            </li>
            <li value="6" data-source-node="n125">
                <p data-source-node="n126">Use the Split Quantity? Checkbox 
 to indicate if you want to completely fill a location and split off any 
 remaining item quantity to be located in a different location (using the 
 locating rules).<br data-source-node="n127"><br data-source-node="n128">NOTE: The system cannot split a container that has serial numbers 
 tied to it.</p>
                <p data-source-node="n129"> </p>
            </li>
            <ul type="disc" class="ul_1" data-source-node="n130">
                <li data-source-node="n131">
                    <p data-source-node="n132">If this checkbox is checked, 
 the system will try to meet the requirements of the first locating rule. 
 If it cannot, then the system will split off the remaining quantity and 
 create a new receipt container, using the same values (such as unit of 
 measure, dimensions, etc). The system will then try to locate the remaining 
 quantity using the second locating rule. This will continue until all 
 the product is located, or locating fails because all of the existing 
 locating rules cannot be met.</p>
                    <p data-source-node="n133"> </p>
                </li>
                <li data-source-node="n134">If this 
 checkbox is not checked, the 
 system will try to meet the requirements of the locating rule(s). If it 
 cannot, then locating will fail.</li>
            </ul>
            <p data-source-node="n135"> </p>
            <li value="7" data-source-node="n136">Press OK. 
 The system will navigate back to the Locating Rule Window. The new rule 
 will be displayed in the data grid. To define additional sequence values, 
 select the New Action. Press OK again to save the complete rule record.</li>
        </ol>
