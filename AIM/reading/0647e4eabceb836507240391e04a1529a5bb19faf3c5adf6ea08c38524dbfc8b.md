
        
        <h1 data-source-node="n56"><a name="kanchor807" data-source-node="n57"></a>Defining Locations</h1>
        <p data-source-node="n58">You will need to define a location for every physical space where inventory 
 can be placed. This allows the system to always track and locate product 
 while its in the warehouse. You will also create dock location area and positions (packing, staging, and dock door) on this window</p>
        <p data-source-node="n59"> </p>
        <h5 data-source-node="n60">Note on Location Ranges</h5>
        <p data-source-node="n61">To minimize setup time, create a range of 
 locations instead of single locations. Since you can create locations in ranges, you can also edit an entire 
 range at one time. To edit a location range, open one record within that 
 range. When you edit the particular field value, enter a check in the 
 checkbox next to the field. The system will update this field value on 
 all records within the range. If you don't select the checkbox, changes 
 are only applied to this record.</p>
        <p data-source-node="n62"> </p>
        <h5 data-source-node="n63">Note on Deleting Locations</h5>
        <p data-source-node="n64"> You cannot delete a location record when transactions associated with 
 the location still exist. You must completely process these transactions 
 before the system will allow a location to be deleted.</p>

        <h5 data-source-node="n163">Using the Header Fields<br data-source-node="n164"></h5>
        <p data-source-node="n165">Access the Location Window. Create a new record.</p>
        <ol data-source-node="n166">
            <li value="1" data-source-node="n167">Associate this 
 record with the appropriate location template.<br data-source-node="n168"><br data-source-node="n169"></li>
            <p data-source-node="n170">- A location template defines the segment characteristics for a 
 location name. Location templates are defined on the Location Template 
 Window. Note: After you move the cursor from this menu, the system will 
 display the Location Entry Fields (Step 5), based on the template.<br data-source-node="n171"><br data-source-node="n172">NOTE: If there is no separator character defined for the template, 
 then all the segments will be concatenated together with no separator 
 at all.<br data-source-node="n173"> </p>
            <li value="2" data-source-node="n174">
                <p data-source-node="n175">Choose the Warehouse that 
 will contain the location(s).</p>
                <p data-source-node="n176"> </p>
            </li>
            <li value="3" data-source-node="n177">
                <p data-source-node="n178">Use the Location Entry Fields 
 to create a location or a range of locations.</p>
                <p data-source-node="n179"> </p>
                <p data-source-node="n180">- After you removed the cursor from the Location Template Field 
 (Step 2), the system will display the Location Entry Fields in the header. 
 The following types of location fields are included: Starting Location, 
 Ending Location and Increment. The actual number of fields for each type 
 depends on the template.</p>
                <p data-source-node="n181"> </p>
                <p data-source-node="n182">To create a single location: Enter a location name in the Starting 
 Location Field(s). Do                              not enter values in either the Ending Location 
 Field(s) or the Increment Field(s).</p>
                <p data-source-node="n183"> </p>
                <p data-source-node="n184">To create a range of locations 
 with the same attributes (using increments): Enter the first location's name in the Starting Location Field(s). 
 Enter the last location's name in the Ending Location Field(s). Identify 
 how you want the system to increment the location names that it creates. 
 See the                              <a href="c60f60733e48d0be10c5d6d861c6c2b0cc43d39b673217ee4469ae347bc21dc3.html" data-source-node="n185">Increment Field</a> description 
 for more information about setting up increments.</p>
            </li>
        </ol>
        <h5 data-source-node="n186"> </h5>
        <h5 data-source-node="n187">Using the General Tab</h5>
        <ol data-source-node="n188">
            <li value="1" data-source-node="n189">Use 
 the Location Class Field to 
 define the purpose of the location in relation to product. In most cases, 
 this value is "Inventory." See the topic <a href="735c86d3ab73c61314ed0e20406ead480c70ab66f6c7959350896c308a7d7ca1.html" data-source-node="n190">Location Class Field</a> for more details.<br data-source-node="n191"><br data-source-node="n192"></li>
            <li value="2" data-source-node="n193">Use the Location Subclass Field to indicate what type of specific designation (such as dock door, packing, or staging) that a dock location will represent. You must choose a Location Class of "shipping" in order to select a subclass value. Note that while this value is optional, all warehouses need at least one "packing" dock location, and that the system only supports one of these packing locations per warehouse. Also, choosing a dock location subclass causes your location to be multi-item enabled, and the dock location will not track license plates.<br data-source-node="n194"> </li>
            <li value="3" data-source-node="n195">Use the Location
 Type Field to identify the physical dimensions of the location. 
 Common location types include carton flow and rack.<br data-source-node="n196"> </li>
            <li value="4" data-source-node="n197">Use the Movement 
 Class Field to identify what items the location can store, based 
 on their movement classes. For example, if a location has the movement 
 class A, it should only store items with the movement class A.<br data-source-node="n198"> </li>
            <li value="5" data-source-node="n199">Use the Location 
 Status Field to determine how it should manage the location. Assign 
 the Frozen Status if you will not be using it soon. Assign the Empty Status 
 for all locations that are not frozen.<br data-source-node="n200"> </li>
            <li value="6" data-source-node="n201">Select the Real 
 Time Replenishment Checkbox to indicate that you want to make this 
 location eligible for real time replenishment (inventory storage locations 
 only).  See the <a href="5cd4fd4791e17a8dcbfcd241048f239594fb6f06869b157c8979e992722cd536.html" data-source-node="n202">field topic</a> for more details.<br data-source-node="n203"><br data-source-node="n204"></li>
            <li value="7" data-source-node="n205">Select the Allocate In Transit Checkbox to indicate whether or not the system should include "in 
 transit" quantity when computing "available" quantity: <br data-source-node="n206"><br data-source-node="n207">- If you do not select this value, the system will use the normal computation 
 (on hand - allocated - suspense). 
 <br data-source-node="n208"><br data-source-node="n209">- If you select this value, the system will include the "in transit" 
 quantity in the allocation computation (on 
 hand + in transit - allocated - suspense). In this case, then, 
 an allocation can potentially occur for an amount that is greater than 
 the "on hand" quantity.<br data-source-node="n210"><br data-source-node="n211">NOTE: This value would be selected                
 if you are performing replenishments within the flow of a normal work 
 day and/or running demand based replenishment. The system, then, could 
 allocate inventory during the wave,                  prior 
 to the inventory movement actually taking place. This allows your shipments 
 to allocate normally without having to execute all of the replenishments 
 (prior to running the wave).<br data-source-node="n212"> </li>
            <li value="8" data-source-node="n213">
                <p data-source-node="n214">Select the Multi-Item Checkbox 
 to indicate if this location can store more than one item. <br data-source-node="n215"></p>
                <p data-source-node="n216"> </p>
            </li>
            <li value="9" data-source-node="n217">Select the Track 
 License Plates Checkbox if you want to track item quantity at the license plate 
 level. Note that you cannot track license plates on a location that has a location class of Receiving Pre-Check In or Shipping Dock.</li>
            <p data-source-node="n218"> </p>
            <li value="10" data-source-node="n219">Use the Max Number 
 of Lots Field to limit the number of different Lot ID's that the 
 system can place into this location. Note that a value of zero ("0") 
 in this field indicates that the system will place no limits on how many 
 lots are allowed in a location. Note that multi item locations determine the maximum number of lots per item in the location. In other words, every different item present in the location will have its own individual maximum number of lots value.<br data-source-node="n220"> </li>
            <li value="11" data-source-node="n221">The Last Cycle 
 Count Field indicates when a user last executed a cycle count instruction 
 at this location.</li>
        </ol>
        <h5 data-source-node="n222"> </h5>
        <h5 data-source-node="n223">Using the Zones Tab</h5>
        <ol class="ol_1" data-source-node="n224">
            <li value="1" data-source-node="n225">Use the Zones

 system supports three functional zones: locating, allocation and work.<br data-source-node="n226"><br data-source-node="n227">- Locating zones group together 
 locations that share the same locating requirements. Locating zones are 
 reserved for future use.<br data-source-node="n228"><br data-source-node="n229">- Allocation zonesgroup together locations that share the same allocating requirements.<br data-source-node="n230"><br data-source-node="n231">- Work zones group together 
 locations serviced by the same work teams and equipment types.</li>

        <h5 data-source-node="n232"> </h5>
        <h5 data-source-node="n233">Using the Work Tab</h5>
        <ol class="ol_1" data-source-node="n234">
            <li value="1" data-source-node="n235">Use the Verification 
 Method Buttons to select how employees will identify this location 
 when performing transactions. <br data-source-node="n236"><br data-source-node="n237">- Select the None Button if 
 you do not require employees to verify that they are at this location.<br data-source-node="n238"><br data-source-node="n239"><br data-source-node="n240"><br data-source-node="n241">- Select the Location Button if you do require employees to identify 
 the location's ID when they are at this location.<br data-source-node="n242"> </li>
            <li value="2" data-source-node="n243">Use the Incoming 
 P&amp;D Field and the Outgoing P&amp;D Field to associate a pickup 
 and dropoff location to the location you are creating.<br data-source-node="n244"><br data-source-node="n245"></li>
            <li value="3" data-source-node="n246">Use the Allow Work Unit Selection On System-Directed Work Checkbox to indicate that you want this location  to be eligible for work unit selection when initiating system-directed work. When a user scans the location that they are currently at (on the system-directed work initiation screen), the system will go out and find some appropriate work to assign. When that work is assigned, the system will display an additional system-directed initiation screen, which allows the user to scan any work unit at the current location. Keep in mind that this second screen will only display if the work's from location is eligible for this type of work unit selection. If the location was not eligible, the system would display the first work instruction from the work unit that it selected. <br data-source-node="n247"><br data-source-node="n248">This type of system-directed work initiation is helpful because it allows the system to determine the location where the work will be performed, but the user is allowed to choose the actual work unit that will be executed.<br data-source-node="n249"><br data-source-node="n250"></li>
            <li value="4" data-source-node="n251">If appropriate, 
 assign picking and putaway sequence values to this location. The 
 Picking and Putaway Sequences provide you with an alternate method for 
 organizing location visits.<br data-source-node="n252"><br data-source-node="n253">- The Picking Sequence identifies 
 the order that the system generates picking work instructions for this 
 location. It is a numeric value. Picking sequences are optional, not required. 
 These can be used to during work creation.<br data-source-node="n254"><br data-source-node="n255">- The Putaway Sequence identifies the order that the system 
 generates putaway work instructions for this location. It is a numeric 
 value. Putaway sequence are optional, not required. These can be used 
 during work creation.<br data-source-node="n256"> </li>
            <li value="5" data-source-node="n257">The Vector Coordinate 
 Field is reserved for future use. You do not need to supply it 
 with a value.<br data-source-node="n258"></li>
        </ol>

        <h5 data-source-node="n264"> </h5>
        <h5 data-source-node="n265">Using the Dock 
 Tab<br data-source-node="n266"><br data-source-node="n267"></h5>
        <p class="p_15" data-source-node="n268">These fields are only available if you choose "Shipping Dock" as a location class value.</p>
        <ol class="ol_1" data-source-node="n269">
            <li value="1" data-source-node="n270">Use the Dock Area Button to indicate that you want this dock location to be defined as an inventory-tracked dock area. Dock areas can either represent the "to location" during dock location assignment, or a collection of inventory-tracked dock positions. A dock area may also be used as an overflow area when all dock positions in another dock area have been filled to capacity.<br data-source-node="n271"><br data-source-node="n272">You will then need to address the following dock area-related fields:<br data-source-node="n273"><br data-source-node="n274">- Anchor Criteria Field: Indicates the dock area anchor filter criteria record that you want the system to use when running the dock management selection strategy "Anchor Dock Area Using Shipment." For more information on this strategy, see the flow diagram in the <a href="0c77698ccfe7d7e04d05ab3b30be92ac8b6430702a653276c2e4e15a459fe918.html" data-source-node="n275">Dock Management Process Summary</a>.<br data-source-node="n276"><br data-source-node="n277">- Selection Priority Field: Determines the numeric priority value that is applied to this dock area location. The system uses this priority to determine which dock area will take precedence when a selection strategy is run.<br data-source-node="n278"><br data-source-node="n279">- Next Dock Area Field: Indicates the dock location you want the system to assign to a container for the "next leg" of its journey, i.e. creating its next move. In other words, you can use this field to pre-assign a dock location. The dock assignment wave step, prior to performing the selection strategy from the dock management flow detail, looks to see if there is a next dock area defined on the container's current dock area. If so, system uses the next dock area and does not use the selection strategy logic (it would go straight to the assignment strategy logic). If not, then the system uses the selection strategy logic as normal.<br data-source-node="n280"><br data-source-node="n281"></li>
            <li value="2" data-source-node="n282">Use the Next Dock Area Field to indicate the dock location you want the system to assign to a container for the "next leg" of its journey, i.e. creating its next move. In other words, you can use this field to pre-assign a dock location. The dock assignment wave step, prior to performing the selection strategy from the dock management flow detail, looks to see if there is a next dock area defined on the container's current dock area. If so, system uses the next dock area and does not use the selection strategy logic (it would go straight to the assignment strategy logic). If not, then the system uses the selection strategy logic as normal.<br data-source-node="n283"><br data-source-node="n284"></li>
            <li value="3" data-source-node="n285">Use the Position Button to indicate that you want this dock location to be defined as a dock position. Dock positions are inventory-tracked dock locations in a dock area, and they represent a specific area inside a dock area. Note that a dock area may include any number of dock positions (including zero). <br data-source-node="n286"><br data-source-node="n287"></li>
            <li value="4" data-source-node="n288">Use the Parent Dock Area Field to create a relationship between a dock position (the child) and a dock area (the parent). The system uses this link to group dock position(s) into the correct dock area on the Dock Manager Window. Note that these links are optional and are not required to use the dock management process. Also, a dock area and dock position do not need the same location template structure to be linked.<br data-source-node="n289"><br data-source-node="n290"></li>
            <li value="5" data-source-node="n291">Use the Number Of Rows Field to  indicate the number of dock position rows that you want the Dock Manager Window to display for this staging area (this setting only applies to the <i style="font-style: italic" data-source-node="n292">staging </i>location class). If  you enter a 0 for this value, the system will display <i data-source-node="n293">two</i> rows for this dock location area on the Dock Manager Window, IF you have associated position(s) to this dock location area. If you have not associated any position(s) to this dock location area (such as if you were creating a general dock location area), then the system will not display rows for it on the Dock Manager Window.</li>
