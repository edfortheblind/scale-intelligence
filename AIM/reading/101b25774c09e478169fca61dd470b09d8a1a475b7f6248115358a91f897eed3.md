
        
        <h1 data-source-node="n56"><a name="kanchor311" data-source-node="n57"></a>Defining Documents</h1>
        <p data-source-node="n58">You will need to define each SCALE document that you want to print. This 
 process includes associating it with a template, which provides its structure 
 and identifying what application will generate the document (SSRS, Progistics, etc). In addition, you will also associate 
 it with a document type, which will determine its format (label or document).</p>

        <h4 data-source-node="n98">Procedures: General Tab...</h4>
        <p data-source-node="n99">Create a new record. Provide a name in the Document Field, and a description 
 in the Description Field.</p>
        <ol data-source-node="n100">
            <li value="1" data-source-node="n101">Use the Document 
 Type Field to identify the document type for this document. The 
 document type determines the format of the document (paper or label), 
 and, for which functional areas it is used for (picking, packing, etc.).<br data-source-node="n102"> </li>
            <li value="2" data-source-node="n103">
                <p data-source-node="n104">Use the Document Template Field 
 to identify the template that will define this document's structure. The 
 templates are stored in the "Reporting\SSRS" directory on your application server. </p>
            </li>
            <p data-source-node="n105"> </p>
            <li value="3" data-source-node="n106">Use the Document 
 Criteria Field to indicate the document filter that you want to 
 assign to a document. When the system generates a particular paperwork 
 document, it will use this filter record to display the detail record 
 values on the document. Choose no value in this field if you want the 
 system to use the default layout for a document.<br data-source-node="n107"><br data-source-node="n108">- Note that you can only enter a value in this field when its corresponding document type has a value in its detail data source field.  In addition, that detail data source must have a record corresponding to that source type in the Document Criteria Window (such as <i data-source-node="n109">shipment allocation document criteria</i> or <i data-source-node="n110">work instruction document criteria</i>).  One other note is that there is special logic in SCALE to support document criteria, and that logic does not exist for all documents/labels.  Therefore, when modifying a system supplied document type, it is not valid to change the detail data source setting that is shipped with the system.  Additionally, when creating custom document types, you must make sure that document criteria logic exists if you wish to configure your document type with detail data source and your document with document criteria.<br data-source-node="n111"> </li>
            <li value="4" data-source-node="n112">Select the Progistics Bundle Document Check box to indicate that this document is part of a "bundle" and should be rated as such. A bundle in Progistics is a set of containers that are to be rated together as one. There will be one document generated per bundle. In SCALE, international shipments are rated in the same manner because they are manifested at the shipment level. Therefore, they would only need one document for the whole "bundle."

 

An example of a document that needs this check box selected is an international document, such as a commercial invoice.

 

<br data-source-node="n113"><br data-source-node="n114">DHL NOTE: DHL shipping labels (regardless of destination) need to have this checkbox selected. With DHL, their shipping labels are considered "bundle" documents, because you can actually send over what DHL calls a multi-piece shipment, which is simply a set of containers shipping to the same place. It will give them all the same tracking number. In SCALE, you would need to close all of the containers separately, and then perform a Manifest at Shipment Level action. 

 
<br data-source-node="n115"> </li>
            <li value="5" data-source-node="n116">Select the Print 
 For Nested Containers Check box if you want the system to print labels for any existing  nested child containers, as well as their parent container.<br data-source-node="n117"><br data-source-node="n118">- This setting is only available for selection when the Printed As Field is set to SCALE Label, and the document type you want to use has a print procedure setting of Shipping Container.<br data-source-node="n119"><br data-source-node="n120">- This setting can only be used to print labels post-wave.<br data-source-node="n121"> </li>
            <li value="6" data-source-node="n122">Use the Language 
 Field to indicate the language in which you want this document 
 to display text. <br data-source-node="n123"><br data-source-node="n124">Notes:<br data-source-node="n125">- The system uses this field for SQL Server Reporting Services (SSRS) documents.<br data-source-node="n126"><br data-source-node="n127">- SSRS Reports print the text resources for a document based on the value set in this field, not the language of the user printing the document.<br data-source-node="n128"> </li>
            <li value="7" data-source-node="n129">Select the appropriate 
 Printed As Buttons to identify the application which will handle 
 the printing of this document.               <a href="724f79bb2e00aa1cede869c149dd9e4f2aa9db436b84557a230c11469afc6163.html" data-source-node="n130">Click 
 here</a> to read a description about each option.</li>
        </ol>

        <h4 data-source-node="n132">Procedures: Report Connections Tab...</h4>
        <ol class="ol_1" data-source-node="n133">
            <li value="1" data-source-node="n134">Use the Retrieve 
 Report Connections Button to analyze the report, and determine which database connections qualify for runtime data and creates Report Connections for each.  An example of this would be an “ADO.NET (XML)” connection, which only points to a static XML file at design time. <i data-source-node="n135">This button is for technical resources only.</i><br data-source-node="n136"> </li>
            <li value="2" data-source-node="n137">The Data 
 Transformation Class Field represents the Local Object identifier of the IReportDataTransformation implementing class used to transform the data retrieved by the Report Connections.  This is used when it is too difficult to organize the data within the stored procedures and/or the report so .NET code must be used.  Please note that the ‘Retrieve Report Connections’ action will fill this field with the value of the report’s DATA_TRANSFORMATION_CLASS formula, if one exists. This field is for technical resources only.</li>
        </ol>
