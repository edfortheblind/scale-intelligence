Using Toolbox Utilities

The following is a comprehensive list of all the "Toolbox Utilities" that are shipped with the application. In general, the purpose of these utilities is to quickly perform a function in SCALE or a third-party application. These are especially helpful if for some reason you need to add/manipulate data outside of the application. You can access the Toolbox on the application server: Start | All Programs | Manhattan Associates | ILS | Tools. You can also access the toolbox by navigating to the following path on your application server: \\AppServer\ILS\, and opening the file "ILSToolbox.exe"

 

**IMPORTANT** - Please run the SCALE Toolbox as an Administrative user.

 

WARNING! Do not use these utilities unless you are a Manhattan representative, OR you are absolutely sure of the consequences of executing a certain utility. Key application data could be lost by the misuse of toolbox utilities.

Containers

 

You can use this utility to create shipping containers based on the allocation requests that are already in the database. This can be helpful to create containers when a wave fails prior to work creation.

 

This Utility...
  • Creates a single container with multiple details, if the details have the same packing class.

  • Creates separate containers, if the details have different packing classes.

  • Puts the created container in an In Packing status.

  • The wave number you enter must be a valid wave in the system. So, if you want to test only a few allocation requests and put them on a test wave, be sure to create a new wave (with no shipments assigned) in the Wave Insight screen.
Procedures
  1. Enter an existing wave number into the field.

  2. Press the Create Containers Button. The utility will create containers in the SCALE database based on the allocation requests that already exist for the associated wave.

Customers

You can use this utility to create a range of customers and/or ship to's. Note that one record each for customer/company combination

  1. Enter a range of customer numbers.

  2. Enter a range of ship to numbers.

  3. Select the company(s) that you want to associate with these new customers/ship to's.

  4. Select the country:

    - If you choose United States as a country, the appropriate postal codes will be derived from the state(s) you choose.

    - If you choose a country that is not United States, you will need to enter in a postal code range.

  5. Press the Create Button. The system will create the appropriate customer/ship to value(s) in the CUSTOMER database table.

    Press the View Errors Button to display any error messages that the system generated.

    Press the Reset Button to clear all the values selected in the data fields.
Address Value Notes
  • Address Line 1 is populated by the Customer ID followed by the text "customer creator"; Address Lines 2 & 3 are populated with NULL values.

  • City is populated by the text "City".

Items

You can use this utility to create a new item record, and assign permanent locations and units of measure to this item. Essentially, this utility performs the same functions as the SCALE Item, Item Unit of Measure, and Item Location Assignment configurations.

  1. Enter the item or range of items that you want to create.

  2. Use the tab fields to indicate the details of the item you are going to create.

    - Note that on the Values tab, when you enter minimum/maximum values for cost/price fields, the system will as a result assign a random price value (chosen as a number between these two values) for these fields on the new Item record.

  3. Enter values into the Item Location Assignment tab if you want to assign a permanent location to this item.

  4. Enter values into the Item Unit of Measure tab if you want to create quantity unit of measures for this item.

  5. Use the Quantity of Each Permutation to be Grouped Together Field to indicate that you want the system to create a number of different permutations of the same item (i.e. company, allocation rule, NMFC). Therefore, if there is a value in this field, the system will loop through that many times, and try to create that number of different permutations (with different company based on the company values that are selected in that check list box). Once the system reaches the number of permutations indicated, it will move onto the next item and repeat this process.

  6. Press the Create Button to create the item records. The data will be placed into the ITEM, ITEM_LOCATION_ASSIGNMENT, and ITEM_UNIT_OF_MEASURE database tables. Note that when the tool creates multiple item records, the system cycles through the value criteria in the order that they were chosen.

    Press the Reset Button to clear all the values selected in the data fields.

    Press the View Errors Button to display any error messages that the system generated.

Receipts

You can use this utility to create receipts and/or receipt lines. Note that this utility will allow you to create receipt lines that do not match the receipt's company designation. This can cause problems when processing receipts created with this utility.

  1. Use the General Setup fields to enter the receipt information.

    - The Receipt Prefix ID Field indicates the alphanumeric string you want to appear at the beginning of your receipt IDs.

  2. Use the Receipts/Details fields to enter in how many receipts you want to create, and how many lines you want on each of these receipts.

    - The Receipt ID Start Index Field indicates the number that will be added to the end of the IDs of your receipt(s). For example, if your receipt prefix ID was "TEST", and your start index was "2", if you created three receipts, they would be named "TEST-2", "TEST-3", and "TEST-4."

    - Note that the system will randomly choose a number of lines that falls between the minimum/maximum you provide.

  3. Assign vendor/ship from/company value(s) for the receipt(s).

  4. Select the item(s) you want to include on your receipt(s).

    - Press the Non Item Master Item Button to add item(s) that are not defined in SCALE to your receipt(s). You will be able to enter the item ID, description, cost, list price, and net price for these items. After you provide this data, the non item master item will be displayed in the item list and available for selection.

    - Note that the system will randomly choose a quantity value that falls between the minimum/maximum you provide.

  5. Press the Create Receipts Button to create the receipt(s). The data will be placed into the RECEIPT_HEADER and RECEIPT_DETAIL database tables. Note that when the tool creates multiple receipt records, the system cycles through the value criteria in the order that they were chosen.

    Press the Reset Button to clear all the values selected in the data fields.

    Press the View Errors Button to display any error messages that the system generated.

Database Upgrade

You can use this utility to upgrade both the SCALE application and system databases. The upgrade can be from a base release to service pack, a service pack to a base release, and a base release to the next base release. You can compare the environments in the list to the version listed in the header portion of the window to see if the environment(s) needs updating.

 

Application Section
  • Version: This field Indicates the release version of SCALE.

  • Service Pack: This field is not currently supported.

  • Build: This field indicates the build number installed.

 

Database(s) Section
  • Environment: This field indicates the environment database(s) configured in SCALE.

  • Database: This field is not currently supported.

  • Version: This field indicates the release version of SCALE that the environment database is on.

  • Build: This indicates the build number the environment's database is on.

  • Type: This field indicates the type of database (it will always be "SQL Server").

  • Unicode: This field indicates that the database supports Unicode (the value will always be "Yes" now).

 

Actions Available
  • Start Services: This action starts the ILS Services and IIS.

  • Stop Services: This action stops the ILS Services and IIS.

  • Reset Services: This action stops and starts the ILS Services and IIS.

  • Refresh Grid Data: This action reloads the grid’s list of databases.

  • Upgrade Button: Select an environment from the record list that you want to upgrade, and press the Upgrade Button.

Carrier Commitment Updater

You can use this utility to update the CARRIER_COMMITMENTS database table, with the system pulling data from a text file provided by the carrier. For example, suppose you need the delivery days for all zip codes from your origin (warehouse). Carrier(s) would then supply you a file with these days to deliver, and you would in turn need to update the CARRIER_COMMITMENTS table to reflect this. Note that you might need to change the format of the files you are supplied by the carrier, since this tool can only process delimited text files. In the delimited text file, you will need to specify the delimiter used in the file, and then just indicate which delimited field positions represent the Days to Deliver and Zip Code fields (these are the required fields, all other field positions will be ignored). This tool simply reads all of the records from the text file and then inserts them into the CARRIER_COMMITMENTS table.

  1. Select a carrier and carrier service.

  2. Select the carrier commitment file to upload.

  3. Enter a path and file name for the output file that the system creates as part of this process. This file includes all the carrier commitment records in a comma delimited format.

  4. Provide your warehouse's zip code in the Origin Zip Code field.

  5. Select the Delete Only checkbox if you want to simply delete all the records in the CARRIER_COMMITMENTS table for this carrier/service and origin, and not perform any updates. In this case, you will only need to select this checkbox, a carrier, a carrier service, and press the GO Button. If you want the system to delete and then add records, you would not select this checkbox.

  6. Use the Source File Options fields to indicate the delimiter that the carrier commitments file uses, and the positions of the Days to Deliver and Zip Code values in the records.

  7. Press the GO Button.

 

Note that this utility was created with the following values in mind:

  • The origin country is hard-coded as "US"

  • The destination country is hard-coded as "US"

  • The effective from date is hard-coded as 1/1/2001

  • The effective to date is hard-coded as 12/31/2999

Change System Value

You can use this utility to change the names of the following warehouse values: company, customer (ship to), item, vendor (vendor name), and warehouse. In other words, the system takes a given element and finds every instance of it in the database with the old name, and changes it to the new name. For example, if you specified and old company of "001" and a new company of "002", the system would find the Company field on every table in the system and change any instance of 001 to 002.

Database Lock Manager

You can use this utility to display and manipulate logical locks placed on database tables during such operations as locating or picking. This utility allows you to view and selectively release these record locks.

- Work Instructions Note: Work instructions are locked from the picking process if the record in the WORK_INSTRUCTION database table has a "Y" value for the LOCKED field.

System Tools Utilities... 

 

 

Cache Manager

You can use this utility to view and delete cache records (which includes both data records and data locks). You can view the cache summary records on the grid. You can use this utility to troubleshoot data discrepancies between SCALE and the data actually contained in the database. This tool allows you to delete specific cache records, and therefore cause the data to be retrieved from the database again to resolve data issues, instead of running an ILSReset (which can be an invasive process).

  • If you select a cache record from the grid, then the system will display more details (if they exist) below the grid.

  • You can delete a cache record by right-clicking the grid. Note that you can only delete one record at a time. Also, you must have administrative rights to delete these records.

  • It is not recommended that you delete lock entries from the cache; however, the tool does not prevent this action.

 

 

Configuration Coordinator

You can use this utility to easily capture and export SCALE configuration data from one SCALE environment to another. Also, this utility has the ability to record changes to SCALE configurations in the form of an installable package. These installable packages are an easy way to promote configuration data from a test environment to a production environment; or, to apply changes to multiple environments.

 

IMPORTANT NOTE: This utility uses the “SQL Server Change Data Capture (CDC)” functionality, which is not available in Azure SQL database. See your Manhattan representative for more details.

Starting a Project

Starting a project initiates the configuration change capture process, and records all of the changes made to SCALE configurations that are associated with the project.

  1. Select an existing configuration project from the list.

  2. Press the Start button. Note that the utility allows only one active project per environment. If the project does not have any historical data associated with it (i.e., it has not been run before), then the utility will start gathering data. If there is existing historical data, then proceed to step 3.

  3. If you are attempting to start a project which has historical data associated with it, the utility will display a dialog where you can choose from a set of predefined actions:

    - Append: The utility will append all new changes to any pre-existing data.

    - Archive: The utility will move all pre-existing data to an archive table and continue to capture fresh changes.

    - Delete: The utility will purge all pre-existing data and new changes will be captured.

    - Cancel: No action will be taken.
Stopping a Project

You would stop a project after completing configuration changes.

  1. Select a currently-running configuration project from the list.

  2. Press the Stop button. The utility will stop the data gathering process, and all configuration change information that has been recorded by the utility in SQL Server CDC tables will be moved to the CONFIG_DIR_COLLECTED_DATA database table.

    The system writes process history for 3 different types of operations done to configurations:

    - CDC_INSERT_OPERATION
    - CDC_UPDATE_OPERATION
    - CDC_DELETE_OPERATION

High Availability

You can use this utility to configure several values related to configuring high availability. This utility supports multiple environments. You can configure the following settings:

  • “URL Load Balancer” defines the server name where the load balancer is located. Changing this value on the utility will update the technical value "URL Load Balancer Server Name".

  • “MSMQ Cluster” defines the MSMQ role’s ClientAccessPoint: FormatName:DIRECT=OS:SCALE-MSMQ-CL. Changing this value on the utility will update the technical value "MSMQ cluster". For more details, see the Message Queuing Guide.

  • “External Storage Path” indicates the path that is to be used as the defined storage location for several functional areas. Changing this value on the utility will update the corresponding configuration/database values that point the system to the file storage location, such as the server path values from the Technical Values or Web System Values configuration windows.

    •  

  • When SCALE is installed within an Azure IaaS Virtual Machine, Azure File Storage can be used to automatically provide high availability for files that are heavily used by the application (such as interface files, wave labels, and so on). "Azure storage connection string" stores the connection string for storing this information in Azure.

  • Note that when the external storage path is used as an Azure file storage path (for example, https://sgfsnode.file.core.windows.net/ils), the word ‘ils’ in this path should always be mentioned in small letters.

SCALE Performance Monitor

You can use this utility to gather detailed system related data for every server in your SCALE environment (application and database). The resulting data can then be sent to Manhattan for further analysis. This utility collects several trace files that can be helpful in monitoring the SCALE application. The tool places the trace file output in the following directory: \\ILS\Toolbox\Performance Tracing\Traces\. In this directory will be a folder for each trace run, suffixed with the date/time of the run (e.g., Trace_20120808143215).

 

The following trace related data is captured by this tool:

  • Windows Performance Monitor traces for each active server defined in the grid on the screen, based on the Performance Monitor template specified. Two standard server templates (SCALEAppServer.xml and SCALEDBServer.xml) are provided to gather the Windows Performance Monitor data. These templates are stored on your application server in the following location: \\ILS\2013\Toolbox\Performance Tracing\Templates\. The resulting trace file output will be stored within a folder for each server name (e.g., <Server1> through <ServerN>), underneath the trace output folder structure mentioned above.

  • SQL Profiler traces for long running queries, blocked processes, and deadlocks. The resulting trace file output will be stored within the Database Information folder underneath the trace output folder structure mentioned above.

  • SQL Server output for various recommended configuration settings, index fragmentation and usage, and table sizes. The resulting trace file output will be stored within the Database Information folder underneath the trace output folder structure mentioned above.

  • SCALE activity output for different points in time during the trace run. The resulting trace file output will be stored within the Database Information folder underneath the trace output folder structure mentioned above.

  

To run the tool:
  1. Create entries in the grid for each SCALE-related server you want the Windows Performance Monitor traces to be captured. The tool will remember the grid settings.

  2. Activate each server you want to be included in the trace.

  3. Press the Start button to start the trace.

  4. The trace must be manually stopped. Press the Stop button to stop the trace.

 

Notes:
  • Caution should be used when using this utility in a production environment. Only experienced IT staff or Manhattan Representatives should be allowed to run this tool. Use toolbox security and the Windows administrative rights mentioned below to control who can run the tool.

  • You need to have administrative rights on all the servers configured in the grid and the SCALE database server. Also, keep in mind that the SCALE Toolbox needs to be run in Administrator mode in order to run this utility.

  • Only a single trace can be run with this utility at one time across all users and servers. The tool enforces this rule automatically.

  • All other similar traces outside of the tool should be stopped before running a trace with the tool, as this utility is not aware of other traces being run in SQL Server or Windows Performance Monitor.

Metadata Screen Utility

You can use this utility to generate SQL script files in order create custom metadata screens, and activate/deactivate/delete these screens. This is helpful, if, for example, you want to create a specialized version of an Insight screen.

 

Customizing a Base Metadata Screen

This action allows you to have the system generate a SQL script file for a base (shipped) metadata screen. This is helpful if you want to create a specialized version of a base metadata screen. This script file contains SQL for the metadata screen (from the MAIN_UI_SCREEN database table all the way down the configuration tree to the other related configuration tables).

  1. Select the Base button (note that you cannot export custom screens).

  2. Select an Environment. The system will load all of the existing custom screens into the Metadata screen field.

  3. Select the Metadata Screen you want to customize.

  4. Press the Customize button. The system will generate the SQL Script file, and display a success message. The system will place this file in the following directory: \\<AppServer>\ILS\_Custom\Export\<EnvironmentName>.

    Notes:
    - As part of the Customize action, the system also will execute the SQL script that was generated. This will create all the records in the appropriate metadata configuration tables in the database.
Exporting a Custom Metadata Screen

This action allows you to have the system generate a SQL script file for a customized metadata screen. This is helpful if you want to save a backup of a custom screen’s current state. This script file contains SQL for the metadata screen (from the MAIN_UI_SCREEN database table all the way down the configuration tree to the other related configuration tables).

  1. Select the Custom button (note that you cannot export base screens).

  2. Select an Environment. The system will load all of the existing custom screens into the Metadata screen field.

  3. Select the Metadata Screen you want to export.

  4. Press the Export button. The system will generate the SQL Script file, and display a success message. The system will place this file in the following directory: \\<AppServer>\ILS\_Custom\Export\<EnvironmentName>.

    Notes:
    - This directory is created upon the first export action, not by the application installer.

    - The system will append a suffix of “V1” to the file name, which indicates this is the first version of the script file for this metadata screen. When you perform an Export action again for this screen, the system will create another “version” of the SQL script file (V2, for example).

    - The file name starts with the Form ID of the metadata screen that you exported.

    - The system will always create a new version of a file when exporting, whether or not there have been changes made to the configurations since the last export of this screen.
Activating a Customized Metadata Screen

This action allows you to make a newly-customized metadata screen available for use on your production environment.

  1. Select the Custom button (you cannot activate base screens).

  2. Select an Environment. The system will load all of the existing custom screens into the Metadata screen field.

  3. Select the Metadata Screen that you want to activate.

  4. Press the Activate button. The system will change the Active Field on all related metadata configuration records for this screen to "Yes", and display a success message.

    Notes:
    - Keep in mind that when you activate a custom screen, then the system will also deactivate the related base metadata screen. For example, if you activate a custom Shipment Insight screen, then the system will deactivate the shipped version of the Shipment Insight screen.
Deactivating a Customized Metadata Screen

This action allows you to make a newly-customized metadata screen not available for use on your production environment.

  1. Select the Custom button (you cannot deactivate base screens).

  2. Select an Environment. The system will load all of the existing custom screens into the Metadata screen field.

  3. Select the Metadata Screen that you want to deactivate.

  4. Press the Deactivate button. The system will change the Active Field on all related metadata configuration records for this screen to "No", and display a success message.

    Notes:
    - Keep in mind that when you deactivate a custom screen, then the system will also activate the related base metadata screen. For example, if you deactivate a custom Shipment Insight screen, then the system will activate the shipped version of the Shipment Insight screen.
Deleting a Customized Metadata Screen

This action allows you to remove a customized metadata screen’s configuration records from the database.

  1. Select the Custom button (you cannot delete base screens).

  2. Select an Environment. The system will load all of the existing custom screens into the Metadata screen field.

  3. Select the Metadata Screen that you want to delete.

  4. Press the Delete button. The system will display a confirmation message, asking if you are sure you want to delete the screen. Once you confirm, the system will remove this screen’s configuration records from all of the appropriate database tables, and display a success message.

    Notes:
    - Keep in mind that when you delete a custom screen, then the system will also activate the related base metadata screen. For example, if you delete a custom Shipment Insight screen, then the system will activate the shipped version of the Shipment Insight screen.

    - Also as part of this action, the system will generate a SQL Script file representing the deleted screen, so that you have a backup in case you want to restore it at a later time.

    - The system does not delete any of the SQL script files that you have previously generated for a screen.

SQL Processor

You can use this utility to launch the SQL Processor mini-application. The SQL Processor is used to store SQL statements, run them, and save the results.

 

General Actions
  • To create a statement to be saved, select "--NEW--" from the Name drop down box.  Fill in the name, active flag, and SQL in the boxes.  Then select the Add button.
     
  • To update a statement, select the statement to be modified from the Name drop down box.  The SQL and active flag can be modified.  When you are done with the modifications, select the Update button.
     
  • To delete a statement, select the statement from the Name drop down box.  Select the Delete Button.
     
  • To run a statement, select the statement from the Name drop down box.  A statement can also be typed into the SQL box without creating a statement.  Select the Run button to execute the statement.
     
  • To save the results of an executed statement, go to 'File->Save Results'.  A window will open to let you choose the file path and name.
     
  • To save a group of SQL statements to be loaded or run at a later date, select 'File->Save SQL'.  A window will open to let you choose the file path and name.
     
  • To load a set of SQL statements, select 'File->Load SQL'.  A window will open to let you choose the file path and name.
When running this application from the command line there are three command options:
  1. /ini <filename>
    This option will open the application with the specified filename as the .ini file.  If this option is not used, the default of SQLProcessor.ini will be used.
     
  2. /sql <filename>
    This will open the application will the SQL statements in the specified file preloaded.  If no .sql file is specified, the application will be run with no preloaded statements.
     
  3. /n
    This will run the application in non-interactive mode.  When in non-interactive mode, the application will run the loaded SQL statements.  The results will be save according to the configurations set in the .ini file that was specified.  If there is no .sql file specified, no commands will be run.  The results will be saved with the name of the command, the date, and the time concatenated.  If there is an error running the SQL statement, the error will be reported in the file.  If there was an error saving the file, it will be reported in "Error.txt" in the same folder as the application. An example of invoking this is the following:  ilstoolbox "SQL Processor" /sql  <filename> /n NOTE: If you would like to store your SQL files in a location other than where the ILSToolbox.exe is located you will need to indicate the file path along with the file name when running the utility via the command line.
Steps to Schedule queries on SQL processor
  1. Create the SQL file through SQL processor which has to be scheduled. Select New from the Name drop down and write the SQL query to be run in the text box. Give a name for the query in the text box under the ‘Name’ text box and Click Add.

    If you have multiple queries, keep adding by clicking New and following the similar steps. Once all the queries are added, click File | Save SQL and save the file.

    For example, if there were 2 queries, the contents of the SQL file would look like this: USERPROFILE SELECT * FROM USER_PROFILE (NOLOCK) Y ¬
    WAREHOUSE SELECT * FROM WAREHOUSE (NOLLOCK) Y ¬

  2. Settings on SQL processor. Click the Settings tab, the SQL Processor Config UI comes up; Check the output type as CSV and click Save and Exit.

    Copy the SQLProcessor.Default.ini file to folder where the SQL file was saved earlier. (Note that the default ini location is in isolated storage, where the path is like: C:\Documents and Settings\&lt;username&gt;\Local Settings\Application Data\IsolatedStorage\&lt;gibberish&gt;\&lt;more gibberish&gt;\StrongName.&lt;yet even more gibberish&gt;\AssemFiles\SQLProcessorFile.Default.ini. Or it could be found in user’s Document’s folder)  

    The Contents of the ini file would look like – CSV, which means the output file will be saved in csv format.

  3. Create a batch file to run the SQL query using SQL processor. In the command, put the location of the ToolBox, then the location of the sql file which was created in Step 1. Specify the location of the ini file. The SQL processor will creates the output according to the ini file settings.

    The command would be like this: "C:\Program Files\Manhattan Associates\WarehouseMgt\wmtoolbox" "SQL Processor"

    /sql "C:\Manhattan\queries\Scheduled SQL Processor\ScheduleQuery.sql"

    /ini "C:\Manhattan\queries\Scheduled SQL Processor\SQLProcessor.ini" /n

  4. Create a scheduled task to run the batch file. Go to Control Panel->Scheduled Tasks-> Add new Scheduled Task. The Scheduled Task Wizard comes up .

    Click Next. On the next window Click Browse and select the batch file you have created, Select the frequency at which this job has to be done and Click Next.  

    In the Next screen give the date and time at which it is required to run and Click Next.  

    On the next screen give the user name/ password information for which the task has to be run.  

    Click the Finish button in the next screen.

    The queries will be run at the scheduled time and resulting CSV files will be saved in the same folder where the batch file is present with timestamp.
