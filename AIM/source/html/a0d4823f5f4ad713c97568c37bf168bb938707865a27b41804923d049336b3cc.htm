Reviewing Interface System Values

To share records between the ERP and the system, you will need to identify several system settings, some of which are defined for a specific functional area (such as shipping or receiving).

System Value Descriptions...

 

All Modes

 

Value Key

 

Value Description

 

50

This value indicates if the system will include a record for items that have zero (0) quantity currently in the warehouse.The setting does not use the item balance interface upload criteria to filter That is uploaded. The system will include all zero (0) quantity records regardless the item balance interface upload criteria.

 

60

Allow Duplicate Receipt IDs On Add?: This value indicates if the system will allow the same receipt ID to exist multiple times in the system. If you select 'Y', the system will allow the interface to download receipt ID's that already exist in the database. If you select 'N', the system checks to see if this receipt ID already exists in the database. If it does, the system will reject the receipt and display an error message saying that the ID already exists and system will not allow duplicates.

 

70

Status That New Receipt Records Are Placed In: This value identifies the status that the system will assign to interfaced receipts/lines/containers.

 

80

Receiving Upload Level: This value indicates what level (container, detail, or header) is checked for status during an upload.

- Container: Produces data (receipt container level) as soon as the container reaches the upload status, and the container is closed.

- Detail: Produces data (receipt container/detail level) when all other containers on the same receipt line have reached the upload status, and the detail is closed.

- Header: Produces data (receipt container/detail/header level) when all other containers on all receipt lines have reached the upload status, and the header is closed.

 

90

Upload Receipt Containers At This Status Or Higher: This value identifies what status a receipt must meet before the system can include its receipt in an upload file. This file provides information about the status of interfaced receipts in the system.

 

100

Allow duplicate Shipment IDs On Add?: This value indicates if the system will allow the same shipment ID to exist multiple times in the system.

If you select 'Y', the system will allow the interface to download shipment ID's that have the same shipment ID/warehouse/company.

 

If you select 'N', the system checks to see if this shipment ID/warehouse/company already exists in the database. If it does, the system will reject the shipment and display an error message saying that the ID already exists and system will not allow duplicates.

 

110

Shipping Interface Download Record Types To Create: This value determines what records the system will create when it downloads orders from the ERP. The system can generate shipments, or orders and shipments. Shipments are required to process records in the system.

Notes...

- Trading Partner Management displays records based on order number, so if you are using this module, select the Orders and Shipments option.

 

- When this setting is configured for Orders and Shipments, the system copies the Shipment ID to the ERP Order Number field if this field is blank on the order's interface file.

 

120

Status That New Shipping Records Are Placed In: This value identifies the status that the system will assign to interfaced shipments, lines, and containers.

 

140

Upload Deleted Shipments?: This value allows the upload of deleted shipments when performing a Shipping Upload. These shipments could have been deleted from allocation rejection or short picking when using the "Delete Rejected" Outbound Status Action; or, via manual deletion. Note that the system places the shipment's header and detail information in the UPLOAD_ORDER_HEADER and UPLOAD_ORDER_DETAIL tables until the upload is processed, and the system will mark the record as deleted in the database.

 

Also, when shipments / shipment lines are configured to include in the upload, the system will use the interface upload criteria records to filter the records when they are written to the upload order tables.

 

210

Allow Zero in UD7, UD8, UD9, and UD10 On Download?: This value indicates if you want the system to change the value for User Defined Fields 7-10 to a zero value when it is sent as part of a download interface save or change. If this setting is not activated, then the system will consider an interfaced zero value as no change to these user defined fields, and they will keep their original values. Note that User Defined Fields 9 and 10 are only available on the shipment download.

 

 

 

Delimited & Fixed Length Modes Only

 

Value Key

 

Value Description

 

10

Delimiter Token: This value indicates which character you want to use to separate fields on a Delimited/Fixed Length text file. Common delimiter tokens include such characters as: +, |, #.

This delimiter token must be a one character value. The token cannot be a letter, number or any symbol that you might include as data. For example, if some addresses use # sign for apartments, do not select this symbol as the delimiter token. The system cannot discern between data and token signs and will not parse the data correctly.

You can use ASCII values to specify a character that cannot be accessed by the keyboard. This is an additional safeguard to ensure that a value is not used as both the token and a value. For example, you could enter the ASCII value 124 to represent | (the pipe bar).

NOTE: Windows considers an asterisk a "wildcard" character (used for general searches), so the system will not allow you enter an asterisk into the System Value Field.

 

 

 

 

Delimited, Fixed Length, & Direct Modes Only

 

Value Key

 

Value Description

 

190

Interface Date Format: This value indicates the syntax that the system will expect date values to use when they are downloaded/uploaded. You will be choosing a format for the day-month-year, such as MMDDYYYY.

 

For interfaced date values that also require a time, the system always assumes the syntax is HHMMSS. Note that if your date value does not require a time, then the system will tack onto the end a time value of 000000 when saving to the database. This is done because the database requires all date values to have a time appended to them.
