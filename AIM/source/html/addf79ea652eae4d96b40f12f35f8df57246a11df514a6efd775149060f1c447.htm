Creating Cycle Count Preference Records

** Use with plan based and non-plan based (activity-driven) cycle counting **

 

A cycle count preference record controls whether cycle count requests should be executed immediately, or created as "pending" requests. Note that when you are not executing work, this concept of immediate execution does not apply, so the system will create all requests as pending. Also, you can define positive and negative tolerance values which determine when a user can make a location adjustment. In addition, you can associate a work team and work type to a preference record.

Procedures: General Tab...

Create a new record. Provide a name and description.

  1. Use the Perform Threshold Counts Immediately Check box to indicate if an RF user should be presented with a cycle count request immediately after the short pick, or if the system should write the request and give it to another user later. This will occur if a picking location's on hand quantity falls into one of the cycle count thresholds set up in the Cycle Count Threshold Window.
     
  2. Use the Verify Bad Count on RF Check box to indicate that you want the system to force an RF user to enter a count's quantity again, IF the user count is different than the system count (this is known as a "bad" count).

  3. Use the Immediate Reconcile of Bad Count Check box indicates if the user can immediately adjust the inventory in this location as long as it's within the above tolerances.

     

    • If this check box is checked, the user assigned to this preference can immediately adjust the inventory in this location, as long as it's within the tolerances.

       

    • If this check box is not checked, the user assigned to this preference can never adjust the inventory on his own. The system will place every cycle count request that this user encounters into a "pending review" status. This request then will have to be reviewed by someone authorized to perform cycle counts.

  4. Use the Positive Tolerance Field to determine the number of units above the number the system thinks is present in a location that the system will allow the user to perform an adjustment to the location. For example, suppose the value in this field is "5". Then, you are presented with a cycle count request that indicates that there should be 20 units of an item in a particular location. You count the units in the location, and there are 35. The system then will compare this number to the positive tolerance value defined in this window. This will determine if the user is allowed to make an adjustment. Since the item quantity in this location is 15 units over the tolerance, the system will put this request in a pending review status, and you will not be able to execute the cycle count. Once the cycle count is in the pending review status, it must be reviewed from the Cycle Count Request Insight screen by a supervisor.

     

  5. Use the Negative Tolerance Field to determine the number of units below the number the system thinks is present in a location that the system will allow the user to perform an adjustment to the location. For example, suppose the value in this field is 5. Then, you are presented with a cycle count request that indicates that there should be 35 units of an item in a particular location. You count the units in the location, and there are 25. The system then will compare this number to the negative tolerance value defined in this window. This will determine if the user is allowed to make an adjustment. Since the item quantity in this location is 10 units under the tolerance, the system will put this request in a pending review status, and you will not be able to execute the cycle count. Once the cycle count is in the pending review status, it must be reviewed from the Cycle Count Request Insight screen by a supervisor.

     

  6. Use the Positive Price Tolerance Field to determine the amount above the total net price value that the system thinks is present in a location, where the system will allow you to successfully perform cycle count work. If the total net price for an item/location exceeds this defined value, the system will place the "overage" quantity into suspense (thus not committed immediately so a supervisor can review this transaction). In this case, the system will close the cycle count work, and the cycle count request will be placed in a "review pending" status.

    For example, suppose the value in this field is 50.00, and you are presented with a cycle count request that indicates that there should be 400.00 dollars worth of an item in a particular location. When you count the units in the location, however, there is actually 575.00 dollars of the item present in the location. The system then will compare this number to the defined positive tolerance value. If the total net price falls within this tolerance, then the system will allow you to complete the cycle count and adjust the "overage" into the location. In this example, though, the item quantity in this location is 125.00 dollars over the defined tolerance. Therefore, the system will put this cycle count request in a pending review status. It does not update suspense quantity when the price/quantity exceeds the positive tolerance.

    Note that if you define a zero value in this field, the system will not consider net price for tolerance.

     

  7. Use the Negative Price Tolerance Field to determine the amount below the total net price value that the system thinks is present in a location, where the system will allow you to successfully perform cycle count work. If the total net price for an item/location exceeds this defined value, the system will place the "overage" quantity into suspense (thus not committed immediately so a supervisor can review this transaction). In this case, the system will close the cycle count work, and the cycle count request will be placed in a "review pending" status.

    For example, suppose the value in this field is 50.00, and you are presented with a cycle count request that indicates that there should be 400.00 dollars worth of an item in a particular location. When you count the units in the location, however, there is actually 200.00 dollars of the item present in the location. The system then will compare this number to the defined negative tolerance value. If the total net price falls within this tolerance, then the system will allow you to complete the cycle count and adjust the "overage" into the location. In this example, though, the item quantity in this location is 150.00 dollars over the defined tolerance. Therefore, the system will put this cycle count request in a pending review status, and the entire quantity (200.00 dollars worth) will be placed into suspense.

    Note that if you define a zero value in this field, the system will not consider net price for tolerance.

     

  8. Use the Work Type Field to indicate the work type associated with this preference record.

     

  9. Use the Work Team to indicate the work team associated with this preference record.
