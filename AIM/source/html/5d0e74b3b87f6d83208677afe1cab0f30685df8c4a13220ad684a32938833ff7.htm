Defining a Carrier's Postal Code Ranges

A postal code range identifies a group of postal codes that the carrier can service within a specific time frame. During routing, the system will reference these records to determine if the carrier can deliver to the destination postal code and how long it will take to deliver the package. Note that this step is required for LTL and Truckload carriers, and any other carrier not supported by Progistics.

Procedures...

  1. Identify the carrier and the service. Select the carrier from the Carrier Field. Select the service from the Service Field.

     

  2. Identify the location of the pick-up warehouse. Select the origin country from the Origin Country Field. Select the origin postal code from the Origin Postal Code Field.

    NOTE: You are not required to enter values in the Postal Code Fields. This accommodates carrier commitment records for countries that do not use zip codes.

     

  3. Identify the postal code range that the carrier will deliver product to. Note: the carrier must be able to reach all of these postal codes in the same time span (days to deliver). Select the destination country from the Destination Country Field. Use the Destination Postal Code Range to identify the start and end postal codes for this range.

    NOTE: You are not required to enter values in the Postal Code Range Fields. This accommodates carrier commitment records for countries that do not use zip codes.

     

  4. Use the Days to Deliver Field to identify how long it takes the carrier to reach this postal code range.

    NOTE: If a carrier does not have a carrier commitments record associated with it, the system will default this field's value to 999 days. If you then try to route a shipment using this carrier, the system will alert you that the package might not arrive on time, if you have less than 1000 days between the requested date and the ship date.

     

  5. Use the Effective Date Range to identify the time span when this record is valid. The system defaults today's date in both effective date fields. Change these dates to reflect when this record is valid. If this record will not expire, select the No End Date Checkbox. The system will default a non-active value in the To Date Field, but this record will never expire.
