Notes On Viewer Setup

Security Settings...

  • If you want to restrict access to this custom viewer, you will need to address it's security settings on the General Tab of the Security Window. You can also restrict the use of viewer actions on the Form Specific Tab of the Security Window.

  • Viewer Colors and Icons settings are system-wide (not based on user).

 

Server/Machine Notes...

Take the following into consideration when creating/configuring viewer windows, actions, colors, or icons:

  • While you can make viewer configuration changes on the application server or a client machine, keep in mind that the client update installer needs to run in order to see your viewer changes on a client machine.

  • Also, on a multi-server environment, the viewer changes will need to be manually-applied to the alternate server because this process is not automated. For example: 

    •  

    1. Suppose you have two application servers: A and B. Also, you have two client machines Client-A (tied to application server A), and Client-B (tied to the application server B).
     

    2. The user is on Client-A and changes the viewer color settings for the Background Job Queue Insight Screen. These changes are immediately applied to Server-A and will be applied to Client-A once the client updates are applied on the machine.
     

    3. The changes will never get to Server-B or Client-B because this process is not automated. In order for these changes to be applied to that environment, the XML file for the viewer would have to be copied to them by hand. This file can be found in the \\ILS\Viewers\XML\ directory. The files are named <FormID>_<FormKeyName>.xml.

 

 

Multi Lingual Note...

Take the following into consideration when creating/configuring viewer actions:

  • If you want your custom action to appear in a different language in your viewer, you will need to create a new resource key where the key is the Action Name that you setup on there Actions Tab of the Viewer configuration window.
