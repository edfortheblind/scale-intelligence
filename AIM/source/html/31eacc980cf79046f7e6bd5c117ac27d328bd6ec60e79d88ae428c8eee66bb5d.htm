Replenishment Configuration

Overview

A replenishment master record helps define how a replenishment request is generated. It specifies the parameters for replenishing product based on either location need or demand generated for a wave/order pool. You can also create or edit the sequence records for a replenishment rule. Each sequence rule identifies how the system will perform replenishment (strategy).

 

Configuration Hierarchy

 

 

Replenishment Configuration

 

1. Replenishment Information

Configure the name, description, priority and incremental field values.

  • Priority - Define the priority order for the replenishment record. When the system performs a replenishment , system considers the records in the priority order. The lower priority numbers are processed first. For example, the record with priority 1 is processed before the record with priority 2. Note that the system will process a record with a priority of 0 after all other records have been processed.

  • Replenishment Increment - The unit of measurement (UM) the system will replenish to the location. For example, if Case is selected, then system will move only the cases to the location.

2. Allocation Rule list

Select the allocation rule for the replenishment record.

 

3. Replenishment Details

 

Replenishment Type - The type of record for which the replenishment will be executed. Read Replenishment Type.

 

Create Work Method - Configure the way to process the replenishment request by the system.

  • Automatic - When selected the replenishment process will allocate the inventory, generate the replenishment requests for eligible locations and mark the inventory as In Transit to the destination location. Work Creation is called directly after replenishment (or during the same wave for Demand Replenishment) and the system creates work for these requests. If it cannot create work, the system deletes the requests and sets the inventory back to Available at the From Location.

  • Manual/Scheduled - the replenishment process will allocate the inventory, generate the replenishment requests for eligible locations and mark the inventory as In Transit to the destination location. Work Creation is called directly after replenishment (or during the same wave for Demand Replenishment) and the system creates work for these requests. If it cannot create work, the system deletes the requests and sets the inventory back to Available at the From Location.

  • None - the replenishment process will allocate the inventory, generate the replenishment requests for eligible locations and mark the inventory as In Transit to the destination location. Work Creation is called directly after replenishment (or during the same wave for Demand Replenishment) and the system creates work for these requests. If it cannot create work, the system deletes the requests and sets the inventory back to Available at the From Location.

3. Demand UMs

Select the unit of measurement for the configuration.

 

4. Location Criteria

Configure the Location criteria, Empty location criteria and Item criteria.

  • Location Criteria - This record determines which location(s) the system will consider for replenishment. The purpose of this record depends on the replenishment type:

  • Empty Location Criteria - identify which location, or group of locations, the system can replenish to if the either of the following situations occur:

    • The amount of product that you have to replenish exceeds the locations available for replenishment. After the system replenishes to all of the locations that currently contain the product, this field identifies the next location(s) that it can replenish to.

      OR

    • No locations currently contain the item that you need to replenish. The system uses this field to determine where to start replenishing.

     

5.Item Criteria

Identify which items in a wave or pool that the system will attempt to replenish.

 

6. Replenishment Modes

Configure the method to run the replenishment record: manual replenishment, replenishment via a wave, or real-time replenishment.

 

7. Replenishment Strategy

A replenishment strategy determines what methodology the system will use to perform a replenishment. You can use the Sequence Field to determine the order that the system will process them. This field will contain the value 10 (or a multiple of 10). You can change the sequence number, but you cannot use the same sequence number for multiple strategy records. The sequence number determines when this record will be used. The lower the sequence number, the sooner it's processed. Currently, the system supports three strategies:

  • Fill to Destination Location - he system will replenish the location until it reaches 100% capacity. It will not reference the value defined on the Maximum Replenishment Fill Percent Field defined on the item location capacity record.

  • Round down to the previous whole number increment - the system will round up to the next increment level.

  • Round down to the next whole number increment - the system will round down to the next increment level.
