Defining Replenishment Master Records

A replenishment master record helps define how a replenishment request is generated. It specifies the parameters for replenishing product based on either location need or demand generated for a wave/order pool. You can also create or edit the sequence records for a replenishment rule. Each sequence rule identifies how the system will perform replenishment (strategy).

Basic Replenishment...

 

Using the Header Fields

  1. Provide a name and description.

     

  2. Use the Replenishment Type Field to identify which records the system will attempt to run replenishment against.

     

    • If you select Item Location Capacity, the system will run replenishment based on location need. This replenishment type is often used to replenish forward locations depleted during by an earlier work crew. Note that this replenishment type uses the "Minimum Replenishment Threshold" value (defined on the item location capacity record) during processing.

    • If you select Top-Off Item Location Capacity, use this type if you want to generate replenishment requests based on location need. Note that this replenishment type uses the "Top-Off Minimum Replenishment Threshold" value (defined on the item location capacity record) during processing.

    • If you select Demand From Pool, the system will run replenishment based on item demand in the pool. This replenishment type allows you to prepare for upcoming demand. Note that this replenishment type uses the "Minimum Replenishment Threshold" value (defined on the item location capacity record) during processing.

    • If you select Demand From Wave, the system will run replenishment based on item demand in the wave that is run. Note that this replenishment type uses the "Minimum Replenishment Threshold" value (defined on the item location capacity record) during processing.

    • If you select Demand From RF Outbound Short Pick, the system will run replenishment based on item demand from a location that has been short picked (if the user is configured to allow this via their work special handling settings). Note that this replenishment type does not allow you to configure for this master the Create Work Method (it is always set to automatic), the Replenishment Criteria (since the item and location are already known to the system), or the Replenishment Modes. Note that this replenishment type uses the "Minimum Replenishment Threshold" value (defined on the item location capacity record) during processing.

 

Using the General Tab

The general tab fields tie together the different components required to generate a replenishment request.

  1. Use the Priority Field to identify when this record should be selected, in relation to the other replenishment master records. When replenishment is initiated, the system cycles through these records in priority order. The lower the priority number, the sooner the record is used: the record with priority 1 is processed before the record with priority 2. Note that the system will process a record with a priority of 0 after all other records have been processed.

     

  2. Use the Replenishment Increment Field to identify the UM that the system will replenish to the location. In the screen diagram above, the Case UM is selected. The system will therefore bring forward only cases to locations using this record.

  3. Use the Allocate All UMs to Clear Reserve Location Checkbox to determine if the system will look for all the units of measure in an allocation location inventory record to "clean up" the location during the replenishment allocation process. Keep in mind that this allocation happens in the order of the highest unit of measure to the lowest unit of measure. See the field topic to see an example of this functionality.

    NOTE: This functionality is applicable only if the “Clear Location” (on the allocation rule detail) setting is active as well.

  4. Use the Allocation Rule Field to identify the allocation rule that you want to apply to this record. During replenishment, the system will use this value to select the from location(s) for this replenishment transaction. If you leave this field blank, the system will use the allocation rule associated with the item.

     

  5. Use the Demand UMs Checkboxes to identify what unit of measure(s) the system will check for replenishment need. In the graphic above, the unit of measure selected is Each. Therefore, the system will only check to see if eaches need to be replenished in the location or pool. These checkboxes are not available if the replenishment type is Use Item Location Capacity.

     

  6. Use the Create Work Method Checkbox to indicate how you want replenishment requests to be processed.

    • Automatic: With this option, the replenishment process will allocate the inventory, generate the replenishment requests for eligible locations and mark the inventory as In Transit to the destination location. Work Creation is called directly after replenishment (or during the same wave for Demand Replenishment) and the system creates work for these requests. If it cannot create work, the system deletes the requests and sets the inventory back to Available at the From Location.

    • Manual/Scheduled Job: With this option, the replenishment process will allocate the inventory and generate replenishment requests for eligible locations. The inventory is marked as In Transit to the destination location. The process will stop there, and it will be up to the user to manually kick off work creation for request(s) in the Replenishment Insight screen. From the viewer the user can either create work on the fly (the Create Work Immediately option) or mark it so the scheduled job picks it up (Mark for Work Creation option).

    • None: With this option, the system will allocate the inventory and generate replenishment requests for eligible locations, execute those requests (which marks the quantity On Hand at the destination location), and then generate a Replenishment Pick List (if paperwork is setup properly). You would then use this document to perform the actual inventory movements.

  7. Use the Consolidate Replenishment Requests Checkbox to indicate that the system can consolidate replenishment requests that were created using this master. When this setting is active, the system will analyze each request and determine if the requests share the following criteria: Item/Company, To/From Warehouse, To/From Location, License Plate (at the From Location), and Lot (if applicable). If any requests share this criteria, then the system will determine if the To Location can physically handle combining the requests. If it can, the system will consolidate the requests. If the To Location cannot support the consolidation amount, then the system will create a new request.

    - This option is only available if you using the create work method of Manual/Scheduled Job. Note that this setting will consolidate across replenishment types and origination modes (as defined on the Replenishment Modes Tab of this window).

    - If this setting and the Create Multiple Requests For Excess Demand Checkbox are both selected, then the system will honor the user's desire to create requests that do not exceed the percentage that the To Location can hold.

    - If the system consolidates across different replenishment types, the request will take on the characteristics of the request from the replenishment master with the highest priority.

  8. Use the Create Multiple Requests For Excess Demand Checkbox if you want the system to only replenish to a permanent location instead of creating requests for empty location. This will only come into play when the replenishment quantity is greater than the amount that the location can support. See the field topic for more information on this setting.
 
Using the Replenishment Criteria Tab



You will use this tab to indicate which location(s) and/or item(s) that you want the system to consider for replenishment.

  1. Use the Location Criteria Field to identify the replenishment location criteria record that you want to associate with this record. This record determines which location(s) the system will consider for replenishment. The purpose of this record depends on the replenishment type:

     

    • If the Use Item Location Capacity Type is selected, this record determines which locations that system will check for possible replenishment. In this case, any possible replenishment is based on the needs of locations identified on the replenishment location criteria record.

       

    • If either the Use Demand From Pool Type or Use Demand From Wave Type is selected, this record just determines which locations the system can replenish. Whether or not a replenishment is required is dependent on demand from the pool or wave.

       

  2. Use the Empty Location Criteria Field to identify which location, or group of locations, the system can replenish to if the either of the following situations occur:

     

    • The amount of product that you have to replenish exceeds the locations available for replenishment. After the system replenishes to all of the locations that currently contain the product, this field identifies the next location(s) that it can replenish to.

       

      OR

       

    • No locations currently contain the item that you need to replenish. The system uses this field to determine where to start replenishing.

     

  3. Use the Item Criteria Field to identify which items in a wave or pool that the system will attempt to replenish.

 

Using the Replenishment Modes Tab

You will use this tab to identify how this replenishment master will be run: manual replenishment, replenishment via a wave, or real-time replenishment.

 

 

Using the Replenishment Strategy Tab

You will use this tab to identify the replenishment strategy(s) associated with this record. A replenishment strategy determines what methodology the system will use to perform a replenishment. You can use the Sequence Field to determine the order that the system will process them. This field will contain the value 10 (or a multiple of 10). You can change the sequence number, but you cannot use the same sequence number for multiple strategy records. The sequence number determines when this record will be used. The lower the sequence number, the sooner it's processed. Currently, the system supports three strategies: Fill Location, Round Up, and Round Down.

  • If Fill Location is selected, the system will replenish the location until it reaches 100% capacity. It will not reference the value defined on the Maximum Replenishment Fill Percent Field defined on the item location capacity record.

     

  • If Round Up is selected, the system will round up to the next increment level.

     
  • If Round Down is selected, the system will round down to the next increment level.

 

 

Real-Time Replenishment...

In order for the system to run the real time replenishment process, you first have to set up your replenishment master record to run in "real time" mode:

  1. Access the Replenishment Master Window, and open/create a record.

  2. Use the Replenishment Mode Field (the checkboxes on the Replenishment Modes Tab) to indicate that you want to use "real time" mode for your replenishment master. In this mode, the system will automatically run replenishment throughout the day (based on settings in the Scheduled Job Window), for locations that would typically need frequent replenishment (you can make a location eligible for this on the Location Window). The replenishment process will run quicker than usual because the system will check for replenishment need only for the locations that are currently in the need of replenishment, and ignore the ones that do not currently need replenishing. This type of replenishment is helpful because you can have replenishment masters running throughout the day, and keep your forward picking locations full for order processing.

  3. Next, you will need to enter values for the other fields as you would for "basic" replenishment. See the procedures above for specific field information.
