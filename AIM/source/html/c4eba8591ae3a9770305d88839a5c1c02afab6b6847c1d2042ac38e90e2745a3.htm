Establishing Customers

A customer record allows you to identify a client that you ship product to on a regular basis. The system supports parent and child customer records. This allows you to share specific field values, such as the email address, between multiple records. This is especially useful if you service large corporations which require you to ship product to multiple sites, but to send all bills to one, corporate office. Also, if you use multi-company processing, you can establish customer records for each company. This ensures that the client base for each company is recognized by the system.

 

Parent Records, Child Records, & Inheritance

Usually, the parent record represents the corporate or billing address associated with this customer. A child record represents the actual ship-to addresses where product will be delivered. For example, chains such as Wal-Mart probably have a corporate office, distribution centers and individual stores. You deliver product to the distribution centers; the corporate office handles freight bills. In this case, the corporate address is represented by the parent record, since it only manages paperwork, not product. Each distribution center will need its own child record. They can inherit shared values, such as the address where freight bills should be sent. Since you don't deliver product to the individual stores, you will not create records for them. The system will only allow you inherit values if the value in the Customer Field and the Company Field match the values on a parent record. A parent record has the Parent Checkbox selected. Company is included in this match since more than one company might use the same customer ID number.

Below are two sets of procedures for the Customer Window: how to define a parent record, and how to define a child record.

  • If the customer has one billing address and multiple ship-to addresses, complete Defining a Parent Customer Record and Defining a Child Customer Record.

  • If the customer has one ship-to address, which is also the billing address, only complete Defining a Parent Customer Record.

Defining a Parent Customer Record... 

 

Using the Header Fields

  1. Use the Customer ID Field to provide the customer's number.

     

  2. Do not provide a value in the Ship To Field since this is a parent record. This field identifies an address that receives product from your warehouse. If this customer only needs one record (does not have multiple ship to addresses), provide a value here.

     

  3. Use the Company Field to identify the company that services this customer. If you use multi-company processing, you will want to identify the company who services this customer. This will ensure that each company's customer base is maintained. This is especially helpful if duplicate customer numbers exist.

     

  4. Select the Parent Checkbox. Generally, a parent record identifies the corporate office or the billing office. The parent record can share values with its child records. This minimizes setup time and ensures that and decreases the likelihood of typos. Note that if you only ship to one address for this customer, it will not require children records. You don't need to select this checkbox.

 

Using the Address Tab

Use the Address Tab fields to define this customer's address and contact information.

  1. Use the Address Tab fields to provide the customer's ship-to address. You can also identify the contact name, his/her email address, phone number and fax number.

     

  2. Select the Residential Checkbox if this customer's shipments are delivered to a personal address, not a company address. Do not select this checkbox if the shipments are delivered to a company, or corporate address. As a rule, you will not select this checkbox because customer records are generally not created for private residences.

 

Using the General Tab

Use the General Tab Fields to define basic carrier and order entry information.

  1. Use the Carrier and Carrier Service Fields to indicate how this customer normally ships their product.

     

  2. Use the On Hold For Order Entry Checkbox to exclude a customer from having orders placed for them. If this checkbox is checked, you will not be able to place orders for this customer on the Order Entry Window. This is helpful if you have a customer who is delinquent in payment, and wish to stop processing orders for them until this due payment is received.

 

Using the Categories Tab

These fields are not required. You only need to define these fields if you want to associate category(s) to the customer record.

  1. Use the Category Tab Fields to choose a category to associate to a customer. See the topic Customer Category 1-10 Fields for more information on these values.

 

Using the Freight Bill To Address Tab

These fields are not required. You only need to define these fields if the customer wants freight bills sent to a different address.

  1. Use the Freight Bill to Address Tab fields to provide the bill-to address. You can also identify the contact name, his/her email address, phone number and fax number.

 

 

Defining a Child Customer Record...

After you define the parcel customer record, you can create the parent's child records. These records identify a specific address that you transport product to.

 

Using the Header Fields

  1. In the Customer & Company Fields, provide the same values that you provided in the parent record's customer and company fields. These values must be exactly the same (as the values defined on the parent record).

     

  2. In the Ship To Field, identify the store that receives product and is also associated with the parent record. The value in this field, along with the values in the customer and company fields, will identify this record to the system.

     

  3. As soon as you have defined the values in these three fields (and exited them), the system will recognize that you are creating a child record. It will disable the Parent Checkbox and display the Inherited Checkbox on each field that it can obtain a value from the parent record.

 

Using the Inherited Checkboxes
  • The system automatically selects the Inherited Checkbox for you, when the value is defined on the parent record. If the field on the child record should be different than the value defined on the parent record, deselect the Inheritance Checkbox. The system will automatically clear the field for you.

    NOTE: Remember that if this child record's bills should be sent to the parent record, you must identify that billing address on the Freight Bill To Address Tab. This usually occurs when a corporate office receives all bills for its stores.

After this record is created: The child record can be a Ship To name and address on a shipment record. This is the customer that you are shipping product to. Please note that if you had provided a Ship To value on the parent record, that record could also be used as the Ship To name and address on a shipment record.

 

 

 

Indicating a Customer's Carrier EDI Reference Fields...

On the Carrier EDI Reference configuration window, you can define what SCALE values (mapped to certain Symbol values) that the system will pass to the transportation system. However, you can use the checkboxes that are present on the Customer Window's Carrier EDI Reference Window to indicate, for a particular customer, whether or not these values are inherited, or select a different SCALE mapped field. You can access this window from the Actions Menu of the Customer Window. For more information on Carrier EDI Reference, see this topic.
