Work Type

A work type is a specific category within a broader work group, defined by its processing characteristics or operational needs. For example, batch picking is a type of work that falls under the general picking work group. In this case, the work type "batch picking" identifies all picking tasks that are best handled in batch mode.

The system includes several predefined work types, such as batch picking and order picking. However, you can also create custom work types tailored to your business processes. These custom types can later be used to define processing rules through the Work Profile configuration.

 

Create work Type

  • Work Type- Enter a unique name for your new work type.

  • Description- Provide a brief description of the work type.

    Note: For Vocollect processing, this description acts as a numeric identifier used in voice communication.

  • Labor Type - Specify the type of labor management record that should be generated for this work type.

  • Labor Group - Select a group of users who perform similar functions related to this work type.

  • Transaction Count Description - Define the label for a custom field that appears on the Manual Labor Entry Screen. This label will be paired with a numeric input field.

    For instance, if you create a work type called Sweeping Floors, and set the Transaction Count Description to Aisles Swept, the janitor can then log how many aisles were cleaned during a given time period.

  • Work Group - Link your work type to the appropriate overarching work group.

  • Default Priority - Set a priority level for tasks associated with this work type.

    • A user’s Work Profile includes a From Assignment setting, which controls how tasks are sorted. If this setting includes a priority-based sort (e.g., Priority/Location/FIFO), the system will use the priority defined here.

    • Note: Priority values are only applied when work is assigned through system-directed mode using an RF device. Manual (full-screen) task assignment does not support priority-based sorting.

  • Pick Management Active - select toggle button to make the work type available in Picking Management windows.

    To be eligible for display in these configurations, both this toggle and the From Work Zone field in the work instruction must be defined.

Work Initiation Method

Work Initiation Method to indicate how the work will be assigned to the user.

  • User initiated: The user selects which work he/she will process.

  • Cart Picking: User picks product into containers/totes assigned to a cart.

Container Picking Method

These settings are used to determine whether or not you are picking product into a shipping container or tote.

  • Pick Into Shipping Container - Users will be able to directly pick into the final shipping container.

  • Pick into tote - Users will be able to directly pick into a tote (transport container). Also, users can pick multiple shipment lines going to different putaway locations into a single tote.

  • Sort Picked quantity - This option is enabled only when Pick to Tote is selected. This is selected for Putwall sorting operation.

Assignment Methods

 

From Assign Method

 

This determines how the system will assign work units using system-directed work initiation.

 

Priority/Location/FIFO - The system assigns work based on priority: the lower the priority number, the higher the urgency. This way, the most important customers are handled first.

  • If the multiple pick instructions share the same priority, the system will assign the instructions in location order: the location closest to the user is assigned first.

  • If multiple pick instructions share the same priority and location, the system will assign the instructions in FIFO. The first instruction generated during work creation is assigned first.This can minimize travel time.

Location/Priority/FIFO- Work is assigned based in location proximity order: the location closest to the user is assigned first. This minimizes travel time.

Note: the system only recognizes number proximity in ascending order. In other words, if location 999-999-999 is physically next to 001-001-001, the system cannot recognize the distance between the locations.

  • If multiple pick instructions share the same location, the system will assign the instructions in priority order: the lower the priority number, the sooner the instruction is assigned.

  • If multiple pick instructions share the same location and priority, the system will assign the instruction in FIFO order. The first instruction generated during work creation is assigned first.

First In, First Out (FIFO) -All work is assigned in the First In, First Out order. The first instruction generated during work creation is assigned first.

 

To Assign Method

This determines how the system will assign putaway work instructions using system-directed work initiation.

 

  • LIFO - All putaways are assigned in the Last In, First Out order, which means the last item picked is the first item put away.

  • Location - All putaways are assigned in location proximity order: the putaway location closest to the user is assigned first. This is commonly used if you are processing product in a bin or other unorganized structure.

Picking Options

The following settings determine various behaviors during picking

  • Default LP id as container ID on full picks - This option is used to indicate that you want the system to default the location's license plate ID (from which you are picking quantity from) as the container ID of the shipping container that you are picking the quantity into. Note that you can enter a different container ID as well, this license plate ID is only defaulted into the field (its use is not mandatory).

  • Group picks by loc/LP- This checkbox is used in Warehouse Mobile picking, to indicate that if a work unit has multiple picks for the same item at the same location, you want the system to group this into one pick. Click to read more. if you are using the Cart Picking initiation method, the system always attempts to group picks.

  • Print at WM Work Start - Indicate that you want the system to print shipping container label(s) when you begin to execute work units via Warehouse Mobile. Note that the system will only print shipping container labels that have the "Start WM Work" print procedure checked on the document type record. Also, the system will only print in this manner if you are executing work that was created from shipping containers.

Putaway Options

The following settings determine various behaviors during putaway.

  • Putaway into Shipping Container - This option indicates that you want the user to place product directly into shipping containers during the WM putaway process. Using this option, the system will either create a new shipping container, or add the item to an existing shipping container (whichever is appropriate).

  • Automatic Putaway - This option is used to indicate that you want the system to automatically putaway items during the work execution process. This would bypass having to manually putaway each item on a shipment. Typically, this setting would be used when you are picking directly into shipping containers (but you can use it in any work scenario, except dock management work, where it is not supported).

  • Consolidation after putaway - This option identifies if you want to invoke the consolidation putaway process after performing a work putaway action on an Warehouse Mobile. Note that if the Automatic Putaway setting is selected, the Consolidation After Putaway setting will not be available to select.

  • Nest After Putaway - This option is used in Warehouse Mobile group picking, when you are picking into a final shipping container (only when the work unit is for a single shipment). If you check this checkbox, the system will display a nesting WM screen after you have putaway your shipping containers. If you specify a container, the picked containers are then nested under it. This allows you to do is pick into shipping containers, and then place those shipping containers on a pallet for shipping. Note that the nest after putaway functionality is not supported when performing putaway to shipping container.

     

    Also note that if receipt containers/license plates for these items were created during a wave, the system will group these as well. Suppose that 3 cases are ordered. During the wave, the system allocates the cases from the same location, and the system creates 3 full-case receipt containers/license plates. When a user performs the work via Warehouse Mobile, they will have to verify and confirm only one time for all 3 cases combined.

  • Use Cross dock LP id from Receiving - This option indicates whether you want the system to use the license plate from receiving as the container ID when creating a new shipping container on the shipping dock. If this setting is not selected, then the user will have to manually enter a container ID in this situation. Note that this is an optional setting that is only available if you have enabled the Putaway Into Shipping Container option. Note that this functionality cannot be used if there was already a shipping container created for the shipment line during the wave or WM picking.

  • Group putaway by shipping container - This setting indicates that you want the system to group putaway instructions by shipping container, when there are multiple putaway locations associated with multiple containers on the work unit. Read More
