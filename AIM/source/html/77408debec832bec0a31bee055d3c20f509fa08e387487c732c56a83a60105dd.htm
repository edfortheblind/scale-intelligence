Configuring DIF Events

To setup the SCALE Device Integration Framework (DIF), you will need to address some configuration values in the application's database. The first step in this process is to configure a DIF event. An event represents an action that occurs in material handling equipment (MHE) or SCALE that needs to be communicated via DIF. An example of this action could be the SCALE close container process. Note that there is no configuration screen to define events in the SCALE Configurations Explorer. You will need to configure these values directly in the application database's DIF_EVENT table.

 

IMPORTANT: In order for changes to the DIF_EVENT table to be reflected, you will need restart the DIF Processing Service.

 

See the SDK for detailed/additional information about DIF.

Procedures...

  1. Access your application database using a database editing tool such as SQL Server Management Studio.

  2. Access the DIF_EVENT database table. Each database row represents a separate DIF event.

  3. Define values for the following database fields:

    EVENT_ID (numeric 9,0): Represents a unique identifier for an event. This is a required field.

    EVENT_DESCRIPTION (alpha-numeric 25): Represents a short description of the event.

    ENABLED (alpha, 1): Represents whether or not an event is enabled or disabled. Supported values are Y (enabled) and N (disabled).

    EXECUTION_IDENTIFIER (alpha, 25): Represents the identifier passed into Spring.NET used to create an instance of the logic handling the execution of the business logic.

    MULTI_THREADED (alpha, 1)Represents whether or not you want DIF to create a single or multiple processing threads for messages. If this value is defined as "Y", then DIF will create multiple processing threads to handle the different messages for a specific event. For example, if there were four messages for closing four different containers, DIF would process this one at a time, unless this value was set to "Y", where it would then close all for containers at a time.

    USER DEF1 - USER_DEF6 (alpha-numeric, 25): Represents user identified values, similar to other places in the system.

    USER_DEF7 - USER_DEF8 (numeric 14, 5): Represents user identified values, similar to other places in the system.

  4. When finished entering values, commit the changes to the database and exit your database editing tool.
