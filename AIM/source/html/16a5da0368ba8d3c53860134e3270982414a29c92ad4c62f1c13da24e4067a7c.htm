Interface Process Summary

** Functionality **

Process Flows

 

 

 

Summary...

You can use the interface to transmit records between SCALE and your order system (ERP). Below is a high-level overview about the interface process, including what modes can be used to move data, and what touchpoints are available. You can invoke an interface upload/download by either starting it manually from SCALE, or have the system kick it off automatically via a scheduled job. The interface will process though all the appropriate files/records in order of last modified time (earliest to latest).

 

If there is an error in running an interface job, the system generates detailed error messages (in an XML-file format placed on the server), which can help identify what records failed, and why. Also, interface activity can be researched on the Process History Insight. Note that if you are interfacing more than one file, and the system encounters an error in processing a file's data, the system will continue to process the other files.

Interface Modes...

 

SCALE features the following methods of interfacing data to/from the system:

  • Delimited Mode: This method involves data text files (with a user-defined file extension) that the ERP places in a specified directory on your server. When the interface process is initiated, the system retrieves these files, parses the data (based on a data map record), and places the information in a SCALE database table. Typically, you would use this mode if your ERP can export data via text files, and you do not have the business need to communicate directly to the system's database tables.

  • Fixed Length Mode: This mode is similar to Delimited mode as described above, except that all the values must have a specific length, which is defined on the interface data map record.

  • Direct Mode: This mode involves writing the data directly to a system database table. The data from the ERP is placed in a temporary database table prior to the interface process being initiated. When the interface process is initiated, the system retrieves the data from this "transfer" table and places it into a SCALE database table. The purpose of these transfer tables is to preserve the integrity of the system database tables.

  • XML Mode: This mode involves the system retrieving your ERP's XML-formatted data files. These XML files are placed in a specified directory, with a file extension that the system can recognize. When the interface process is initiated, the system parses the data (based on an XML style sheet), and places it in a SCALE database table.

 

Interface Actions...

 

There are four actions that can be used when interfacing records to/from SCALE:

  • New: This involves introducing new records to the system, or providing data to the ERP.

  • Change: This involves updating records already interfaced to the system from the ERP.

  • Delete: This involves removing records from the system already interfaced from the ERP.

  • Save: This involves updating a current record that the system sees is a duplicate, rather than creating a second record with the updated information

 

Supported Touchpoints...

You can upload and/or download into SCALE the following types of data: Note: Record id need to be unique for each record being downloaded. Cannot have same record id for header and details.

 

  • Receiving: The system supports the interfacing of receipt header, detail, and container data between your ERP and the application. SCALE can also return receipt information back to the ERP after the receipt has been processed and its product has been checked into the warehouse. Receipts can be uploaded based on its receipt header, detail, or container status. Also supported are changes/deletions of parts of receipts, such as lone details or containers. In addition, you can also download purchase order header and detail data into SCALE. Duplicate serial numbers are validated if the "Allow Duplicate Serial Numbers" flag in the Inventory Control values is set to "N". The validation for the duplicate serial numbers is valid irrespective of the status in which the receipt is being downloaded.

  • Order/Shipment: The system supports the downloading and uploading of order header, detail, container, and comment data between your ERP and the application. When orders are downloaded, the interface converts them into SCALE-supported shipment and shipment line(s). These shipments then typically would be placed in the shipment "pool," and thus eligible to be placed on a wave. You can download orders directly from your ERP's database table, or from a previously-generated delimited text file or XML file. Note that you can also choose to create order records in SCALE as well as shipments. These orders are used in viewing web data. Also supported are changes/deletions of parts of shipments, such as lone details or containers. In addition, you can define outbound statuses to automatically upload shipment data when the shipment meets a certain trailing status.

  • Inventory Transactions: Inventory transaction data, such as positive/negative adjustments and transfers, can be uploaded to your ERP via the system interface. This ensures that the ERP keeps its inventory balances aligned with the system's balances.

  • Item: Item master information can be downloaded from the ERP via the interface. This allows you to populate the item master configuration table, so you do not have to define your products manually in the system.

  • Item Balance: Item balance data can be uploaded from SCALE to your ERP via the interface. This allows you to reconcile the current item quantities in your warehouse with the ERP's item master table. This is helpful so your ERP has a current and accurate listing of the items in your warehouse and how many are available.

  • Work Orders: SCALE allows you to download a work order and all of its component lines. Or, the download could contain just a work order. In this case, the components would be determined by looking up the Bill of Materials for the finished item on the work order and creating the component items in the work order detail based on that.

  • Bill of Materials: A bill of materials is a listing of the component items and quantities of those items needed to create a finished item through a work order. SCALE allows you to download a finished item and its components, along with the quantity needed to make up the finished item.
