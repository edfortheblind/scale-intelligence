Using the QC Workbench

The outbound quality control process involves taking a subset of the shipping containers that are being shipped out of the warehouse, and inspecting the contents in order to verify that they match what the system believes to be in the container. If the container passes QC, then it would continue on through the appropriate outbound status flow and eventually out the dock door. If the container fails QC, then the item quantities in question would need to be resolved before the container can move on to the next appropriate step in its status flow.

 

You can use the QC Workbench to inspect the item quantities that are in a container. The workbench includes a detailed inspection grid that allows you to view the packed, counted, and failed quantities for each item. You can also enter reason codes in the grid, which indicate why an item failed QC.

 

Note that all of a container's contents must have been picked before a container is eligible for QC inspection.

Workbench Actions Summary...

The following are descriptions of the actions available to users on the QC Workbench.

 

Workbench Actions

 

 

Description

 

 

 

Clear counted quantities

 

 

 

The system will reset the Counted Quantity values for all the container's item quantities. This is helpful if for some reason you want to stop an ongoing inspection and restart it from the beginning. Note that this action does not affect the container's QC status, the Failed Quantity value, or any values defined on the Reason Code screen. Also, any unkown items that you have counted for this container so far will not be removed from the grid.

 

 

Confirm

 

 

 

The system saves the QC inspection results for the item quantities in the container. Note that you will confirm the results for the whole container, not on a row-by-row basis.

 

Fill All Counted Quantities

 

 

 

The system will place all of a container's Packed Quantity values into the Counted Quantity fields. This is helpful if you want to quickly pass a container through QC inspection.

 

Force QC Pass

 

 

 

 

 

 

 

The system will flag a container with a QC Condition of “Complete," so it can continue on its way without having to actually pass QC. This would be used when you have a container that failed inspection, but wanted to indicate to the system that you want to pass it anyway (including the failed item quantities). This is helpful if you need to get a container out of the warehouse, and do not want failed QC to hold it up. Note that this container will retain its Failed Quantity value(s), even though the QC for the container is considered complete.

 

Print

 

 

 

 

 

The system will display the standard Print Documents screen, and you will be able to print the same documents that you can print from the Close Container screen. This is helpful if for some reason you need to reprint a document/label as a result of the QC inspection (such as a damaged shipping label or missing container document).

 

Refresh

 

The system will refresh the QC Workbench's inspection grid data. Note that the system will erase any Counted Quantities that you have entered when this action is invoked.

 

 

 

 

 

Initiating a Container...

Before you can start evaluating a container's contents, you first need to load the container into the QC Workbench.

 

NOTE: You can open the QC workbench from the Shipping Container Insight screen by selecting the Confirm QC option for a shipping container with a pending or failed QC status.

 

1. Access the QC Workbench.

 

2. Enter the ID of the container that you want to inspect.

 

3. Press the arrow button. The system will display the container's item quantities in the inspection grid.

 

 

 

 

Directly Entering Counted Quantities Into Grid...

The following procedures describe how you could inspect a container's contents by counting each item's total quantity and then directly entering that value into the grid.

 

1. For each item quantity residing in the container, count the number physically present.

 

2. Enter the item's inspection value into the Counted quantity field:

- If the Counted quantity matches the Packed quantity, then the item has passed QC, and the system will disable the Reason Code Add/View link (since there is no need to enter codes).

 

- If the Counted quantity does not match the Packed quantity, then you will need to enter a reason code to explain this discrepancy.

3. Press a row's Add/View link to enter reason codes for Failed quantities. When the Add/View link is pressed, the system will display the Reason Codes screen, where you can match quantity values to the appropriate reason code(s). Your reason code quantities must match the Failed quantity for the container before you are allowed to exit the Reason Codes screen.

 

4. Once all the container's item quantities have been inspected, you then need to confirm these results to the system. You can do this by pressing the Submit button. At the time of confirmation, the system writes transaction history for all item quantities confirmed, and writes process history indicating that the container has passed/failed QC inspection. See the Quality Control History Generation section later in this topic for more information on history.

- If all item quantities passed inspection, the system will display a message indicating that the container passed QC inspection. The QC process for this container is now finished.

 

- If there are item quantities that do not pass inspection, the system will display a message indicating that the container had some Failed quantities and did not pass inspection. Now proceed to step 6 of these procedures.

5. After the initial confirmation, you can enter reason codes for any Failed quantities (if you have not done so already). Do this by pressing the Add/View link in the Reason Code grid column for each Failed item quantity.

 

6. You will now need to resolve the Failed quantity of the container in a window outside of the QC Workbench. See the Resolving Failed Item Quantities procedures later in this topic.

 

NOTE: If you choose, you can enter different Counted quantity values for item row(s) that have previously been confirmed, and perform a reconfirm. This is possible only as long as there are Failed item rows in the grid. You cannot perform a reconfirm if all item rows have passed inspection.

 

 

 

 

Scanning Counted Quantities Into Grid...

The following procedures describe how you could inspect a container's contents by scanning the bar code of each item counted. Note that it is strongly suggested that you configure your bar code scanner to have a TAB action occur after the scan, and not an ENTER action. As a result, when you scan the item ID, the cursor will jump to the next appropriate field (either Lot or Quantity, depending on the type of item scanned). However, if you only will be scanning non-lot-controlled items, configuring an ENTER action should be sufficient.

 

The Scan Item Count Fields

 
Container Inspection

- Note that the procedures below assume your packing preferences are defined to require lot validation.

 

1. Scan the bar code of the first item you want to inspect. Note that if the item exists in the container for multiple companies, the system will prompt you to choose the correct company value. Note that you could choose to instead enter an item's cross reference ID in the Item Field.

 

2. If you scanned a lot-controlled item, you would then enter the lot ID.

 

3. In addition, you can change the unit of measure (UM) value. This is optional, as the system defaults this value to the base unit of measure for the item scanned.

 

4. Next, if needed, you can change the quantity value. This is optional, as the system defaults this value to 1.

 

5. When you are ready to apply the item count to the inspection grid, press the Count button. The system will raise the Counted Quantity of the item by the increment that you counted. Note that if you have the same item cross reference pointing to multiple items/companies, the system will count the first item (which matches this cross reference) that is listed in the grid.

 

6. To count another item quantity, repeat the steps outlined above.

 

7. Once all the container's item quantities have been inspected, you will need to provide reason code(s) for any counted quantities that do not match an item's packed quantity. To do this, press an item row's Add/View button and the system will display the Reason Codes screen.

 

8. The final step in this process is to submit your counting results for evaluation. You can do this by pressing the Submit button:

- If all item quantities pass inspection, the system will display a message indicating that the container passed QC inspection. The QC process for this container is now finished.

 

- If there is at least one item quantity that does not pass inspection, the system will display an error message. You will now need to resolve the container's Failed quantities. See the Resolving Failed Item Quantities procedures later in this topic for more information.

 

Also, at the time of confirmation, the system writes transaction history for all item quantities confirmed, and writes process history indicating that the container has passed/failed QC inspection. See the Quality Control History Generation section later in this topic for more information.

 

Last Item Counted

When you count an item using the fields above the inspection grid and press the Count button, the system will not only add that item quantity to the inspection grid, but also log the item's information into the "Last item counted" section on the right side of the workbench. This section indicates the ID, description, and quantity of the item that was just counted. Keep in mind the following about this section:

  • The "Quantity counted" value indicates the quantity and unit of measure of the item you just counted, exactly as you counted it. For example, if you counted 2 CS of an item, the "Quantity counted" value would be 2 CS, even if CS is not the item's base unit of measure.

  • The "Total quantity" value indicates the current sum of the item that you have counted so far (converted into the item's base unit of measure).

  • The "Container quantity" value indicates the whole quantity of an item that is packed into the container you are evaluating.

 

 

 

Quality Control History Generation...

 

At the time a container count is confirmed, the system writes the following types of history records. Note that the system does not log quality history as part of the outbound QC process:

  • Transaction History: The system generates a transaction history record for each item quantity that you confirm. The record includes such information as container ID, user name, item/quantity, and the reason code(s) for Failed counts.

  • Process History: The system generates a process history record indicating that the container has passed or failed QC inspection. The record includes such information as container ID, user name, previous QC status, and current QC status.

Reason Code Configuration Note: Even though the reason codes used in the QC Workbench are defined in the Quality History Reason Codes configuration, the system does not generate quality history records for a Failed count confirmation. The reason codes defined in this configuration are simply listed on the QC Workbench, and logged on the QC Confirmation transaction history record when a Failed count occurs.

 

 

 

 

Resolving Failed Item Quantities...

Once the system flags an item quantity as Failed, you will then need to resolve this quantity so the container can pass QC confirmation. You will need to perform this action in a window outside of the QC Workbench. For example, suppose you have a container that has an item quantity that was under-packed by 1 EA. The system would fail this item quantity, and you would need to remove this item from the container via the Shipping Container Insight screen. After you have resolved an item's Failed quantity, then you can refresh the inspection grid data, and the appropriate Packed quantity values will update to their current state. You can then resubmit the container for QC inspection (see Resubmitting a Container for QC Inspection section for more information).

 

 

 

 

Resubmitting a Container for QC Inspection...

 

After a container has failed QC inspection, and you have resolved this failure, then you may need to enter different Counted quantity values for certain item(s). You can enter these new values directly into the grid's Counted Quantity.

 

 

 

 

Inspecting Item Quantities With Lots, Serial Numbers, Catch Weight, and Unknown Items...

 

Lots

Lot-controlled items are fully-supported in the QC Workbench. You can choose to handle lots in one of two ways, depending on how you configure your packing preferences:

  • Requiring lot validation during inspection: The system will display each item/lot combination as a separate row in the inspection grid. Therefore, the user will need to enter quantity values for each item/lot combination that they count as being part of the container. The system displays the Lot field near the top of the screen next to the Item field.

  • Not requiring lot validation during inspection: The system will summarize all of an item's lot instances into a single grid row on the inspection grid, so the system will not display a lot column in the inspection grid.
Serial Numbers

Serial number tracked item quantities can be inspected in the QC Workbench; however, an item quantity that has serial numbers is displayed as one row in the grid. The serial numbers themselves are not displayed in the grid.

 

Catch Weight

Catch weight tracked item quantities can be inspected in the QC Workbench; however, an item quantity that has catch weights is displayed as one row in the grid. The catch weights themselves are not displayed in the grid.

 

Unknown Items (Not Currently Packed Into the Container)

You can also count items that the system does not list as part of the container (i.e., an "unknown" item). When you count an unknown item, the system will add a row representing the item to the inspection grid. Note that this action does not actually pack the item into the container, as you would need to do that separately in another window (like the Packing screen). Note that unknown item quantities are always flagged as Failed quantities when a container's count is submitted.

 

In addition, you can configure the system to prompt you when an unknown item is scanned. The setting that governs this prompt is located on the Packing Preferences Window. If this setting is active, when you scan an unknown item, a prompt window will appear alerting you of this fact. If you confirm that you want to add this item to the container, then the system will add this item quantity to the inspection grid.

 

 

 

 

Miscellaneous Screen Features...

 

You can choose to specify a custom audio file to associate for QC errors. Note that this is the same audio file that is used for errors on the Packing Screen (the system is shipped with a default audio file). The system will play this audio file when you encounter an error in QC counting and an error message is displayed. These errors include but are not limited to the following:

  • Submit a count that results in failed quantity.

  • Attempt to submit a count that does not have the proper reason code(s) defined.

  • Do not provide a lot value when counting a lot item.

  • Attempt to count an invalid item when the system is configured in Inventory System Values to validate item throughout the system.
