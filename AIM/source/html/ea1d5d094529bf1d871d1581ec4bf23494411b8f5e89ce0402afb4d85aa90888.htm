Processing Data Archiving Records

Data archiving moves records from an "active" database to an "inactive" database, based on age and any other defined criteria. This increases system speed and minimizes the number of records displayed on application screens. You can schedule archiving processes to run automatically (via "scheduled jobs") or manually, depending on your business practices. When you archive records, the system will save them to a separate database table. You can then view these records using the Archive viewers. You can also restore them back to an active state. However, if you choose to delete the records from the database, the system will remove them permanently from active database tables. You cannot access or restore deleted records.

 

Archive to external storage can also be configured to improve the performance of the application. The archiving to an external storage database can be configured using few powershell commands. See the SDK topic "How to: Configure External Data Storage for Archiving" for more information.

 

WARNING: Archiving records will take up considerable system resources. You should not run a archive job during normal operational hours or during peak processing times.

 

Note On Archiving Receiving Records

Receipts that are related to serial numbers will only be archived when they no longer relate to serial numbers in inventory

Manually Running Archive Masters...

You can manually activate the archiving of old records in the system. When you activate a master, it will archive records according to rules you define. You can define how you want to deal with this data by creating an archive master in the Archive Master Window. The system displays these masters in the Archive Data Window. You can also research archived records on one of the Archive Viewers. Note that if you have checked the Run As Default Check box on the Archive Master Window, certain master record(s) will already be checked when you open the Archive Data Window. These masters are run automatically through SCALE scheduled jobs.

  1. Use the Archive Masters Check boxes to indicate which archive master(s) that you want to activate. You can also use the Check All Check box to select all of the masters.

     

  2. Select OK. The system will display a confirmation message verifying that you want to archive this data:

     

    • If you choose Yes, the system will immediately archive/purge the records as defined on the master rule.

       

    • If you choose No, the system will return you to the Archive Data Window.

 

Researching Data Archiving Records...

You can view your warehouse's archived records in one of the Archive Viewers.

 

Viewer Window Layout

When you open an Archive Viewer, the system will display a window with two tabs. The Criteria Tab contains the fields you can use to perform a search. The Results Tab displays the record(s) that the system found to match your search criteria. You can use the fields on the Criteria Tab to search for your archived records. The fields displayed on this tab will depend on how this viewer was configured.

 

Archive to External Data Storage.

You can create and configure an external database to store archiving data for the application. This configuration will enable you to record the archive data directly to the external storage. The following are the feature capabilities. See the SDK topic "How to: Configure External Data Storage for Archiving" for more information on how to create, configure and upgrade using the PowerShell commands.

 

Create a new Archive Database

Using the Add-ScaleArchiveDB PowerShell command, create a new archive database. The external database will be of MS SQL type only.

 

Configuration of Archive DB

The new external archive database (MS SQL) can be configured using the Set-ScaleArchiveDataStorage powershell command.

The user is prompted with the following two options

  • 1- Default - The archive data will be stored in the main database and the external database will not be used for archiving.
  • 2- MS SQL - The archive data will be directed to be written in the external MS SQL database.
Archive Custom Tables

The custom tables created for user-specific environment can also be archived in the external database. Users need to add the custom table to the Archive table list and then configure and run the archive masters.

 

See the SDK topic "How to: Configure External Data Storage for Archiving" for more information.
