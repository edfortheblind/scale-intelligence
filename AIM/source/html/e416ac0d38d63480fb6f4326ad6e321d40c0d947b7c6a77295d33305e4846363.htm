Performance Management Process Summary

** Functionality **

 

 

Summary...

Performance management helps you achieve your strategic goal as a company. SCALE's Performance Management processing helps you analyze data against your warehouse goals to provide information that is actually useful in achieving your goals.

 

The SCALE system includes many key features to help your monitor and achieve your goals for performance.

  • Alerts (warehouse)

  • History

  • Reporting

 

 

Related Topics...

- Setup Overview

 

 

 

The following are key features of the performance management functional area:

 

 

History...

A history record provides information about an event that occurred in SCALE, whether or not the event was successful or unsuccessful. Examples of these events could include when inventory is impacted, the system makes a decision or performs an operation, or user performs an operation. History records can be used to troubleshoot problems or make warehouse strategic decisions. Warehouse alerts are a special type of history record that communicates to the user that a certain condition in the warehouse exists and needs urgent attention. When an alert occurs, the system can generate a history record, an email message, or both. Users can search for these records using the Warehouse Alerts Viewer.    The History Insight screens allow you to search for history records.

 

SCALE logs the following types of historical data:

  • Transaction History: Any time inventory is impacted by either system or user activity, the system generates a transaction history record identifying what happened. This allows you to view a "before-and-after" summary of the warehouse action(s). For example, when a user picks an item from a location, the system generates transaction history. This record identifies the user who picked the item, the item and quantity picked, the location that it was removed from, the time/date that the transaction occurred, and other pertinent information.

  • Process History: Any time the system either makes a decision or performs a transaction without user assistance, the system writes a process history record identifying what happened. For example, during carrier routing, the system assigns a carrier to each shipment in a wave. During this process, the system generates process history detailing how it made its decision, including which carriers were rejected and why.

  • Quality History (Reason Codes): Any time an employee provides a reason code to explain a discrepancy during processing, the system writes a quality history record identifying what happened. Reason codes identify why a particular transaction was not completed as expected and cover such problems as damaged locations and short picks. If a reason code is not required but the user experiences an error, the system will automatically assign a pertinent reason code and generate the corresponding quality history.

  • Receipt Quality History: Any time that an employee checks in a container on a new receipt, closes a receipt or reopens a closed receipt, the system generates a receipt quality history record. This record identifies the date/time that the event occurred, who processed the receipt and other pertinent information. You can use this information to track whether a receipt is complete and arrived on time. In addition, you can track employee productivity or compare expected versus actual receipts for a particular vendor.

 

 

Warehouse Alerts...

A warehouse alert communicates to the user when a certain condition in the warehouse exists and needs attention. Any time a warehouse action (that is defined as an alert) emerges or occurs, the system writes an alert request. Then, when the warehouse alerts scheduled job kicks off, the system will process this request and generate an alert record. You can configure these alerts to send an email message, write historic records, or both. You can use these alerts to learn about problem(s) in your warehouse and how to resolve them. You can assign a priority to an alert to determine when the problem should be resolved, in relation to other alerts.    For example, suppose a container fails the scan & weigh process because it exceeds the weight accepted by the carrier. If you had an alert defined for the manifesting process, the system would generate an alert that you could review on the Warehouse Alerts Viewer.

 

 

 

Reporting Alerts...

You have the ability to schedule system processes and reporting, such as data archiving and performance information. These reports and processes are executed through scheduled jobs.
