Allocation Configuration

Overview

An allocation rule set identifies the sequence rules the system will use to allocate products. A sequence rule determines the system allocate product from a location. Generally, an allocation rule set includes multiple sequence rules, which the system processes in numerical order (1, 2, 3, etc.). Each sequence rule can be tied to a location selection and/or strategy.

 

Configuration Hierarchy

 

 

Allocation Rule configuration

 

1. Rule Information

Rule name and Description are defined for the rule. Users can add sequence detail records. Users can change the sequence number, but cannot use the same sequence number for multiple detail records. The lower the sequence number, the sooner the system will process it.

 

2. Add New Sequence

Sequence records are created by defining strategy, Location selection and UMs.

 

Strategy - An allocation strategy defines the system's methodology for allocating product. It determines which from which location you will allocate, based on an operational requirement or directive. A sequence record can include both a strategy and a location selection value, or just one of these values. For example, if you select the strategy Maximize Space value, the system will attempt to empty as many locations as possible via allocation. Read Allocation Strategy for more information.

 

Location Selection

A location selection record identifies the possible allocation locations. A sequence record can include both a strategy and a location selection value, or just one of these values. These help minimize processing time and increases your control over allocation activity. The location selection can also have a sort defined, which the system will use after the strategy's sort is completed.

 

Sequence Details

Configure rules to allocate the lot-controlled items and Unit of Measurement

 

  • UMs - Select the unit of measurement for the rule. The system will only perform the allocation for locations that support UMs selected on this list.

  • Any Lot (Multiple OK): Choose this option to have the system allocate items with any lot, when allocating multiple lots to fulfill the demand is acceptable. The system will use the allocation strategy and allocation location selection records to determine the order that the locations will be allocated from.

  • Any Lot (Single Only): Choose this option to have the system allocate any lot, but just a single lot. The system will use the allocation strategy and allocation location selection records to determine ordering (just like normal allocation). But once a lot is selected, it will be the only lot allocated. If the allocation demand cannot be met with this lot, the system will reject the rest of the quantity. If not enough quantity can be found for one lot, the system will allocate the largest quantity of one lot, and fail the rest of the quantity. Note that this single lot may exist in multiple locations.

  • Specified Lot (Single Only): Choose this option to have the system allocate only a specified lot. If the system cannot find the specified lot, allocation will fail. The system will only look for the lot specified (such as on the shipment or work order). It will not look for any other lots. If not enough quantity can be found for lot specified, the system will allocate all the quantity found for the specified lot and fail the rest of the quantity. Note that this single lot may exist in multiple locations. NOTE: If no lot is specified on the shipment line, then the system will not fail allocation, but will instead process as it would if using the "Any Lot (Multiple OK)" setting. When no lot is specified (as is often the case with replenishment which does not look at the lot on the shipment line), then allocation should not fail. Allocation will only fail in this scenario if no inventory/lot can be found which matches the specified allocation location selection criteria.

  • Clear Location - When this toggle is selected, the system will allocate from a location inventory record (not the location as a whole) only if the location can be “emptied” without exceeding the demand quantity or the forward location capacity. Also, the system will filter out any location inventory records which has quantity more than the demand or the location capacity. Note: This applies to all types of allocation (shipment, replenishment, work order). Click for more information.

 

Attribute Based Shipment Allocation

 

Attribute-Based Shipment Allocation enables the system to use dynamic values from the shipment line as tokens to filter and select appropriate inventory. The inventory is allocated based on attributes that matches shipment-specific requirements provided by the host system.

 

Configuration

To enable attribute-based allocation:

  • Navigate to Allocation >> Location Selection >> Filter Builder

  • Toggle Use Shipment Line Value to enable dynamic filtering feature.

  • The Value drop-down will populate with available columns from the shipment detail table.

  • The system will validate that the selected attribute and the shipment detail value shares same data type.

Example:

A shipment arrives from the host system, requiring items to be shipped from a specific country of origin. The country is stored in User Defined Field 1 on the shipment line — in this example, Spain.

 

Inventory Setup:

  • Inventory for item exists in multiple locations, each with different attribute values.

  • Inventory Attribute 01 (ATTRIBUTE 1) is used to store the country of origin for each inventory location.

Configuration:

  • Allocation is configured to use a token referencing User Defined Field 1 from the Shipment details.

Allocation Process:

  • The system reads the dynamic value from the shipment (example, Spain).

  • It uses this value as a token to filter available inventory locations.

  • Only inventory locations where Inventory Attribute 01 is Spain will be considered.
