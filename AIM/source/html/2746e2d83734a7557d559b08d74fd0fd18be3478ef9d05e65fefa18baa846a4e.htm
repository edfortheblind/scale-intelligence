Replenishment Methods...

Capacity-Based "Lean-Time" Replenishment...

This represents the basic flavor of replenishment in the system. It is based on the capacity of a location compared to what is currently in the location, plus the quantity that is in transit to the location. When that quantity falls below a configured threshold, the replenishment process creates a request to fill the location back up. Since this replenishment method is not based on any sort of demand, it can be run at any point someone has free, or "lean," time.

 

Key Configuration Settings:

- Replenishment Type (on the master record): Item Location Capacity

- Replenishment Mode: Manual (typically in most situations)

- Replenishment Work Creation Method (on the master record): Automatic

- Item Location Assignment: Required

 

 

 

Capacity Based "Real-Time" Replenishment...

Since running “lean time” replenishment (as described above) typically takes a long time to complete (since it is analyzing all forward pick locations), the rate at which work can get done potentially will not meet the demand of shipments. To resolve this dilemma, you can use a capacity-based method called "real-time" replenishment. This method represents when a pick drives a location below its threshold quantity for a replenishment, then that location is marked as eligible for replenishment. Then you would use the real time replenishment scheduled job, which looks at all of those marked locations and attempts to replenish them. Therefore, you can run this job several times a day, whenever it is necessary. It speeds up the overall replenishment process because as it creates work for locations that got picked from recently. However, this method has nothing to do with the demand of shipments coming through the system, so it sometimes tends to create work that is not very critical (since you may not have any picks coming for the items you are replenishing).

 

Key Configuration Settings:

- Replenishment Type (on the master record): Item Location Capacity

- Replenishment Mode: Real-Time

- Replenishment Work Creation Method (on the master record): Automatic

- Location: Real-Time Replenishment checkbox selected

- Allocate In Transit (on the Location Window): Typically selected for locations being replenished

- Item Location Assignment: Required

 

 

 

Standard Demand-Based Replenishment...

In order to tie what is being replenished back to what needs to be shipped, SCALE features the demand-based replenishment method. This can be based on demand from the entire shipment pool, or just within the specific wave you are running. The replenishment process runs identically for both; the only difference is which shipments the system will consider in the demand. When this replenishment method runs, the system creates requests for the quantity needed (according to the shipment details) that is not already in the forward pick area. The main limitation here is that if your permanent forward pick location is not large enough to hold all of the demand, the only thing that the replenishment process does is try to find an empty location to put the excess quantity. The system requires everything to be brought forward at once. This will work your warehouse has a large forward pick area, and all of your locations are not assigned as permanent locations.

 

Key Primary Configuration Settings:

- Replenishment Type (on the master record): Demand from Wave or Demand from Pool

- Replenishment Mode: Wave or Manual

- Replenishment Work Creation Method (on the master record): Automatic

- Allocate In Transit (on the Location Window): Typically selected for locations being replenished

- Item Location Assignment: Not required, but generally does exist

 

 

 

Demand-Based Replenishment (small forward pick area, running large waves overnight)...

In the case where your warehouse runs large waves overnight (but has a small forward pick area), there could be demand to fill the forward pick location beyond what it is capable of holding. When there is no more space in that location, the system will create more requests for that location, but not create work yet. That way, the inventory is allocated and “queued up” to come forward to the location when there is space. Once the location gets picked below its minimum threshold, the next replenishment request gets marked for work creation. Then there is a scheduled job that will wake up whenever it is configured to, and create work for those requests that have been marked.

 

Key Primary Configuration Settings:

- Replenishment Type (on the master record): Demand from Wave or Demand from Pool

- Replenishment Mode: Wave or Manual

- Replenishment Create Requests for Excess Demand (on the master record): Checked

- Replenishment Work Creation Method (on the master record): Manual/Scheduled

- Allocate In Transit (on the Location Window): Selected

- Item Location Assignment: Required

 

 

 

Demand-Based Replenishment (running many small waves during the day)...

In the case where a customer runs many small waves during the course of a day (and the demand for a given item builds up over time), the replenishment process will create a small replenishment just for just the quantity that is needed on that wave. If multiple waves require the same item over and over, this can make for a lot of small replenishments from the same location to the same location throughout the day. In SCALE, you can consolidate replenishment quantities with existing requests. Therefore, if multiple waves run one after another, they will continue to add to the existing replenishment request for a given item. Once the scheduled job for creating work wakes up, it will take all requests that are marked for work creation at that time and it will create work for them. This will make for larger replenishment runs to satisfy the demand across all waves (that have run since the last time the work creation scheduled job ran).

 

Key Primary Configuration Settings:

- Replenishment Type (on the master record): Demand from Wave or Demand from Pool

- Replenishment Mode: Wave

- Replenishment Consolidate with Existing Requests (on the master record): Checked

- Replenishment Work Creation Method (on the master record): Manual/Scheduled

- Replenishment Strategy (on the master record): Round Up

- Allocate In Transit (on the Location Window): Selected

- Item Location Assignment: Not required, but typically does exist

 

 

 

Combination Approach (using Demand-Based and Real-Time in concert in your warehouse)...

Also, you can use a combination of methods to achieve the desired replenishment results. Suppose you run a large wave at night for scheduled shipments, and then run several smaller waves during the day for same day shipping. In addition, you want to create replenishment requests for any item that is running short in the forward area, but want to create those at a lower priority so they can be done whenever someone gets a chance. To configure this, you would use the setup outlined below:

 

Key Primary Configuration Settings:

Work Types

- Demand Replenishment: Priority 10

- Off Time Replenishment: Priority 90

 

Locations

- Real Time Replenishment checked on all forward locations

 

"Demand-Based" Replenishment Master

- Type: Demand from Wave

- Mode: Wave

- Create Requests for Excess Demand: Checked

- Consolidate with Existing Requests: Checked

- Work Creation Method: Manual/Scheduled

- Strategy: Round Up

 

"Demand-Based" Work Creation Master

- Replenishment Data Selection: Select Replenishment Master–Demand

- Work Type: Demand Replenishment

 

"Real-Time" Replenishment Master

- Type: Item Location Capacity

- Mode: Real Time

- Consolidate with Existing Requests: Not Checked

- Work Creation Method: Automatic

- Strategy: Fill Location

 

"Real Time" Work Creation Master

- Replenishment Data Selection: Select Replenishment Master-Real Time

- Work Type: Off time replenishment

 

Location Window

- Allocate In Transit: Selected

 

In this scenario, the large wave would run overnight. All demand from that wave would generate replenishment requests and get allocated to the shipments in that wave. Some locations would get multiple requests created for them. When the scheduled job for work creation runs, those locations where this was the only open replenishment request would get work created. This would all be at priority 10 so that it would get done right away.

 

As small waves ran during the day, they would continue to allocate against what was marked to be replenished. As the demand exceeded what had requests created already, new requests would be written. If there was “room” on the existing requests for the quantity, the quantity would be added to the existing requests (because of the consolidate setting being active for this method). As picking was done, any pick that drove the location quantity below the threshold would trigger an existing replenishment request to be marked for work creation. Work Creation would run periodically via a scheduled job to create concise work units for the requests that had been marked.

 

In the case where no open replenishment requests existed for the location, and a pick drove the location below its min threshold, the system would mark that location for real time replenishment. Then, when the real-time replenishment job runs, the system will create replenishment requests for that location and create work right away. The work would get created at a priority 90 so that it would be done when there are no other outstanding replenishments.

 

 

 

Setting Priorities For Replenishment Requests...

If you are using different replenishment types for your warehouse, the following indicates how you would use the Priority setting on the work type record to make sure that the system runs your replenishment types in the correct order. For example, suppose you want the system to attempt to create work for demand replenishment before real-time replenishment. You would first create a work type record for demand replenishment with a priority of 1. Next, you would create a work type record for real-time replenishment with a priority of 99. You would then tie these work types to valid work creation masters. The system would then process these in priority order, with the first being demand replenishment. So, if a location currently has multiple replenishment requests (of different types) outstanding, then the system can create work based on priority, so that the more critical replenishment requests are processed first.

EXAMPLE 1

Replenishment Increment = CS

 

Item Unit of Measure =

Unit of Measure Conversion Qty
EA 1
CS 12
PL 288

 

Replenishment process determines a need in the active location of 38.

 

Calculated Replenishment Quantity = 48.

Since the system must replenish a full case, it must bring forward a full case quantity that is equal to or greater than the needed quantity. Since 38 is more than 3 cases, the system needs to bring forward 4 cases which is a quantity of 48.

Fill Location overrides the threshold %, so you want to fill to 60. If you add 40 to the 11 there, you get 51. If you were to add 50, you would get 61 which would overfill.

 

 

EXAMPLE 6

Replenishment Increment = CS

20 shipments in wave for this item, each with a quantity of 12

Each shipment has EA demand of 2, for a total of 40. There are 18 in the location, which means you need 22 more. You have to round up to the next CS since that is your increment, which is 30.

EXAMPLE 8

Maximum Quantity = 60 EA

 

Replenishment Increment = CS

 

Demand Units of Measure = EA

 

Replenishment Strategy = Round Up

 

Item Unit of Measure = 10 EA per CS

 

Current Available = 18 EA (None currently allocated)

 

40 shipments in wave for this item, each with a quantity of 12

 

Calculated Replenishment Quantity = 40 to this location, and 30 to an empty location

EA demand is 2*40=80. This means you need 62 more. Only 4 cases will fit in the current location, meaning you need 22 to go to a second location. You must round up to the next case, which is 30.

 

 

EXAMPLE 9

Minimum Replenishment Threshold = 20%

 

Maximum Fill Percent = 100%

 

Maximum Quantity = 60 EA

 

Replenishment Increment = CS

 

Demand Units of Measure = EA

 

Create Multiple Requests for Excess Demand = Selected

 

Replenishment Strategy = Round Up

 

Item Unit of Measure = 10 EA per CS

 

Current Available = 8 EA (None currently allocated)

 

80 shipments in wave for this item, each with a quantity of 12

 

- Total quantity to be replenished is (80*2) - 8 = 152

 

- First replenishment will fill the location to the nearest CS: 50 (since 60 would overfill)

 

- Subsequent replenishments assume the location is picked down to threshold: 60*0.2 = 12

 

- Therefore each subsequent replenishment will be for a quantity of 40 since 50 would make the total 50+12 = 62.

 

- To fulfill all 152, the replenishments must be 50+40+40+22

 

- The last one must be rounded to the next CS

 

- Therefore, the replenishments to be created are: 50, 40, 40, and 30 - all for the same location.
