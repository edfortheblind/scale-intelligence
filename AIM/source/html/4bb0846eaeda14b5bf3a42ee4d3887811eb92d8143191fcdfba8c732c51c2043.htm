Allocation Process Summary

** Functionality **

Process Flows

 

 

Summary

The allocation process selects which location's inventory should be obtained to meet a request for product. The system will generate work for allocated product during the work creation process. Allocation is performed as a wave step which is designed to run before the work creation step. When the allocation step is run, the system selects the location that it will obtain product from for a shipment line. If you use the system to pick confirm, the product is reserved until it is either picked or its shipment is deleted. If you don't pick confirm, the system automatically removes the inventory when the load is confirmed.

 

The system includes several predefined allocation strategies. These strategies allow you to select allocation locations based on specific business needs, such as emptying as many locations as possible.

 

An allocation rule groups together all the components required to select an allocation location. Generally, an allocation rule set includes multiple sequences, which the system processes in numerical order (1, 2, 3, etc.). The sequence identifies the location selection and allocation strategy the system will apply during allocations. A location selection record determines which locations the allocation strategy can be applied to. For example, if the location selection includes all locations in Zone 'Bulk', the allocation strategy will consider only those locations in Zone 'Bulk'.

 

You can determine which locations product will be allocated from based on any item or location value. These values are defined on the Item Window, Item Class Window, Location Window and Location Class Window. Also, you can organize the order that locations will be considered for allocation, based on any item or location value. You can define handling rules for such criteria as particular products, employees, and work zones.

 

You can use the Transaction History Insight and Process History Insight screens to research the system's decisions during allocation. This screen will display a series of records that represent the confirmation or failure of the allocation events.

Allocation Strategies

An allocation strategy is a method for selecting picking locations based on a storage management goal, such as emptying locations. These strategies are predefined and represent a specific system algorithm that the system will use to allocate product.

 

The list below provides a brief description of each strategy:

  • Closest Match - The system attempts to allocate the product from the location whose inventory count best matches the shipment's requested quantity. It will first find the location with the lowest quantity that is greater than or equal to the requested quantity. If it cannot do that, the system will allocate locations in a manner to minimize the number of locations the picker needs to visit by allocating the location with the highest quantity first.

  • First-Expiration-First-Out (FEFO) - The system allocates the product with the lowest expiration date. An item must be lot controlled to identify the expiration date. This strategy decreases the likelihood that time-sensitive foods and pharmaceuticals will perish in the warehouse.

  • First-In-First-Out (FIFO) - The system allocates the product with the lowest aging date. The system assigns the aging date when the product is introduced to the system. This strategy ensures that the oldest inventory is removed from the warehouse first.

  • Item Location Assignment - The system attempts to allocate product from its permanent location. This strategy is valid only if you have defined permanent locations for items on the Item Location Assignment Window. This strategy is used  when you want to have picking location(s) that you always use for an item, rather than letting the system assign locations randomly.
     
  • Item Location Assignment (Over Allocation Allowed) - The system attempts to allocate an item from its permanent location. If there is not enough available quantity present at the location, then the system will allocate the quantity anyway. A location will not be rejected because it does not contain enough available quantity for your allocation request. This strategy is valid only if you have defined permanent locations for items on the Item Location Assignment Window, are performing shipment allocation, the location is not license plate tracked, and does not contain lot controlled items. This strategy is used when you want to have a single picking location that you always use for an item, and you want to be able to allocate from that location regardless of the available quantity that may or may not be present. You would be assuming that the location would be replenished before the pick is to occur.
     
    If a shipment needs a quantity of 25 for item A01, the system would allocate from Location 3 first since that is the location where the picker could perform a single pick and get all the quantity. Also, this location has the closest quantity that will meet the demand (as opposed to Location 4). However, if the shipment had a quantity of 50 on it, the system would allocate all of Location 4, followed by 10 from Location 2.
     
  • Last Expired, First Out (LEFO) - The system allocates the product with the expiration date that is the furthermost in the future. This strategy orders selected locations by Expiration Date in descending order (the furthermost expiration date on top). The Expiration Date value takes precedence over other ordering fields; that is, the system always orders the selected locations by Location, but using LEFO it orders by Expiration Date (descending) and then Location.
     
  • Last-In-First-Out (LIFO) - The system allocates the product with the highest aging date. This strategy minimizes picking time in stackable locations (and other locations where the product last located is the most accessible).
     
  • Maximize Space (Allocate Least Available First) - The system allocates product from the location with the lowest inventory count. It will continue to allocate product from those locations with the least amount of inventory, until the shipment request is fulfilled. This strategy empties multiple location via allocation; however, it increases the number of location that you must visit.
     
  • Minimize Visits (Allocate Most Available First) - The system allocates the product from the location with the highest inventory count. This strategy minimizes the number locations that you must visit.

Keep in mind that most strategies allocate based on location inventory, NOT locations. For example, if a strategy finds 5 eligible locations that translates into 5 location inventory records. Those 10 inventory locations could be 5 distinct locations or 2 locations with 2 license plates in one location, and 3 license plates in the other. In either scenario, the allocation process looks at these as 5 distinct location inventory records.

Advanced Allocation

Advanced allocation records allow allocation to use percentages when attempting to allocate quantity on a shipment line. This process is also sometimes called variable quantity (or percent) allocation. You will define these percentages on the Advanced Allocation Window. The following scenario shows how you can use the minimum and maximum fields on this window to indicate system thresholds for performing variable quantity allocation: Suppose you define an advanced allocation record for Item A (garden hose), and defined to allow percent allocation. A customer then orders 100 feet of garden hose. If the minimum percentage is equal to 100%, and the maximum percentage is equal to 110%, then the system would be able to allocate a quantity of Item A in the range of 100 to 110 feet.

 

 

 

Multi-Threaded Allocation

When allocating shipments, the system uses a type of processing called multi-threading. This helps the performance of the allocation process. Multi-threaded allocation is driven by a setting in the Technical Values Window. This value determines the number of shipments that the system will allocate at one time. This, in turn, will determine the number of threads used in the multi-threaded allocation process. For example, if this value is set at 2, the system will concurrently allocate two shipments (each on its own separate thread). When one shipment finishes allocating, the system will begin allocating another shipment on the available thread. This process continues until all shipments have been allocated.

 

 

 

Allocating Complete Quantities

SCALE also allows you to indicate to the system that if any part of a shipment fails allocation, the system will reject the entire shipment. You can define this setting at the shipment level by selecting the "allocate complete" value. This is helpful if you have items on the same shipment that absolutely have to be shipped at the same time. The "allocate complete" setting ensures this by putting the whole shipment into a rejected status when any part of it fails to be allocated.

 

 

 

Allocation of Related Lines

The system includes the ability to allocate related items that need to be shipped to the same destination. These type of items would typically not need to be put together in a kiting/work order process, but definitely would need to ship out on the same shipment. An example of this type of item would be a table, where the customer would order a table, but the warehouse actually ships a table top and four legs. Note that these items do not necessarily need to be packaged together, but do need to arrive at the same time (as you would not want to receive a table top and three legs). These components of the table (the finished item) can then be allocated separately as a group of table legs and one table top.
