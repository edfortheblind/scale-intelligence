Time Zones in SCALE

This topic discusses the time zone settings for date fields followed in the insight or web screens of the application. Primarily insight screen here is referred to insight, monitoring, details and transaction screens.

 

NOTE: Coordinated Universal Time (UTC) is the primary time standard by which the world regulates clocks and time.

 

 

Warehouse Date

 

The warehouse date is determined by the time zone specified for the warehouse. The time zone setting is present on the Warehouse configuration screen.

 

Date Offsets for Date Only Fields

 

The determination of "Today" in filter configurations, for date only fields, is based on the time zone of the warehouse where processing is taking place. The system takes the current UTC time and applies the offset from the time zone of the Warehouse configuration of the warehouse of the transaction.

 

For example, if the Receipt Date on receipt header is 2018-06-01 at 02:00am UTC and the warehouse is in US Eastern Standard Time (UTC minus 5), then the warehouse date would be 2018-05-31. Therefore, the date used for "Today" in the calculation is 2018-05-31.

 

 

Date Offsets for Date Time Fields

 

With fields that specify both date and time, the value in the database is always stored using UTC time. When the field is viewed on a browser, the date and time displayed will be the browser date and time based on the user's browser offset. The browser uses the Windows configurations setting to determine the time zone offset.

 

For example, on performing adjustment to the inventory quantity, the date and time of the Aging Date Time field will be calculated and written in UTC. When a user views the inventory in the browser, the date and time displayed will be the date and time of the user's browser.

 

 

Expiration Date

 

If the user manually enters an expiration date value (for example, during an inventory adjustment), the system will write that date value to the database as entered and no conversion will be done.
