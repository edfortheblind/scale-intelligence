Using Delayed Locating

Often there are delays between when product is received on the receiving dock and when that product is putaway to an inventory location. This delay ties up valuable floor space. Delayed locating can be used to maximize the available floor space. This process will delay locating receipt containers to inventory locations until starting the actual putaway. Instead of locating to an inventory location the receipt containers will be temporarily located to a receiving pre-locate location.

 

You can delay locating a receipt container or a parent container with nested containers by using the Delayed Locating flag on the receipt container’s locating rule and the Create Work Putaway flag on the user’s receiving preference. When these two flags are checked locating will direct the receipt container to the receiving pre-locate location. This location belongs to the Receiving Pre-locate location class. Creating this location automatically sets the location as multi-item and license plate tracked. Allocate in transit is unchecked.

 

If either the Delayed Locating or Create Work Putaway flag is unchecked, then the system will use the receipt container’s locating rule details to locate to an inventory location.

 

Receipt containers will be relocated to an inventory location when starting receipt putaway work from RF with the work instruction’s receiving pre-locate location as the ‘to’ location. Relocating uses the receipt container’s locating rule to determine the new putaway location. RF user directed, system directed, and multiple work unit assignment work initiation methods can be used to relocate “delayed” receipt containers. Parent containers with nested receipt containers always relocate by child regardless the receiving preference’s locating method.

 

Relocating is delayed when the receiving dock has an outgoing P&D location. The pick and putaway to the P&D doesn’t relocate the receipt container. Instead the pick from the outgoing P&D location relocates the receipt container.

Delay Locating to the Receiving Pre-Locate Location…

 

  1. Create a new location using the Receiving Pre-locate location subclass.

  2. Create a locating rule with Delayed Locating checked.

  3. Check Create Work Putaway on the user’s receiving preference.

  4. Locate or locate all the receipt containers or parent containers with nested containers from the Receipt Workbench or RF Receiving.

    5. a. The system will locate and create receipt putaway work for the receipt containers with both Delayed Locating and Create Work Putaway flags checked to the receiving pre-locate location. Receipt containers with only one of the two flags checked will locate to an inventory location based on the receipt container’s locating rule details.

    b. If either the Delayed Locating or Create Work Putaway flag is unchecked, then the system will use the receipt container’s locating rule details to locate to an inventory location.

  5. Review Process History to determine the locating status.

 

 

 

Relocate Delayed Receipt Containers to an Inventory Location…

 

  1. Complete the steps in the Delay locating to the receiving pre-locate location section.

  2. Log into RF and select Work.

  3. Select a work profile configured to pick and putaway receipt putaway work.

  4. In user directed mode enter the work unit for the receipt container(s) you would like to putaway. See the Processing RF Work topic for details on relocating when starting work using system directed and multiple work unit assignment modes.

  5. Click OK. If the system determines the work unit is for receipt putaway work and the work instruction’s ‘to’ location is a receiving pre-locate location, then the system will relocate the receipt container(s).

    6. a. First, the system validates the user can start the receipt putaway work to the pre-locate location.

    b. If the user passes start work validation to the pre-locate location and the receiving dock does not have an outgoing P&D, then the system relocates the receipt container to an inventory location based on the container’s locating rule.

    - If relocating is successful, then the system validates the user can start the work to the new inventory location.

    - If start work for the inventory location passes validation, then the user is presented with the Pick Confirmation screen and can pick and putaway the receipt container.

    c. If the user passes start work validation to the pre-locate location and the receiving dock has an outgoing P&D, then the work unit is picked and putaway to the P&D without relocating.

    d. If start work or relocating fails, then the system displays the error.

  6. Review Process History for more information on relocating success and failure.

    7. NOTE: Parent containers with nested receipt containers always relocate by child regardless the receiving preference’s locating method.
