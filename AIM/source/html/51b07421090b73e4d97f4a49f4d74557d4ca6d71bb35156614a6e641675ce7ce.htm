Quality Control Process Summary

** Functionality **

Process Flows

 

 

The application features modules for both inbound and outbound quality control.

Inbound Quality Control...

The inbound quality control process involves the system taking a certain portion of a receipt's item quantity and routing it to a special location so it can be inspected. The system places this item quantity in a special QC inspection status, and the remaining portion of the receipt's item quantity is placed in that same status until inspection is complete. Note that items are made eligible for quality control processing at the item master level in configurations. When the physical inspection of the item quantity is complete, the user will then need to manually transfer the QC items to their original inventory location destination (if it passed inspection), or to a different holding location (if it failed inspection), depending on your business practices. Keep in mind that inbound quality control only supports license plates created by the check in process, not downloaded receipt containers.

 

 

 

Outbound Quality Control...

The outbound quality control process involves taking a subset of the shipping containers that are being shipped out of the warehouse, and inspecting the contents in order to verify that they match what the system believes to be in the container. If the container passes QC, then it would continue on through the appropriate outbound status flow and eventually out the dock door. If the container fails QC, then the item quantities in question would need to be resolved before the container can move on to the next appropriate step in its status flow.

 

The system assigns QC to a container in one of the following manners:

  • During the wave (using the QC Assignment wave step)

  • During work execution (at work unit start). Note that QC is assigned only when starting work for shipping containers that already exist (created in the wave), not for new containers introduced during RF picking.

  • The system will assign QC when a user manually marks a container for QC using the RF Shipping Container QC screen (assuming the user has security access to perform this action).

The system evaluates the container against the active QC assignment records in ascending order of priority, and marks the container as QC Pending as soon as a matching QC assignment record is found. The system marks the container with the record's "assignment reason", which indicates how the decision was made to assign QC. The system also increments the "current container count" value as indicated on all the matching QC assignment records.

 

A container's item contents can be inspected in SCALE using one of two modules: the desktop QC Workbench and the RF Shipping Container QC Screen. The QC Workbench is a feature-rich processing window which includes a detailed inspection grid that allows the viewing of the packed/counted/failed quantities for container items. This window also features in-depth reason code tracking so you can ascertain exactly why a container failed the quality control process. The RF Shipping Container QC screen features a more streamlined approach to quality control, allowing the user to quickly scan a container's items and the system will evaluate the container contents right from the RF device from anywhere in the warehouse.
