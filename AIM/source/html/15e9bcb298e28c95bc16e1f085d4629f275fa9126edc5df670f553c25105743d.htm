Overriding Shipment Data in a Wave

The application provides a wave step that allows you to update data (that you normally would not have access to) during the wave process. You can configure this "override data" wave step to replace a specific data field with a value that you define. To configure this action, you will need to create a override data record (and a corresponding criteria record), and include this "override data" wave step in your default flow. Additionally, the system allows you to include multiple "override data" wave steps in your wave flow. This allows you to override different types of data at different times during the wave. To create additional steps, you will first need to copy the default override wave step, and then create the wave step(s) based on this base override data functionality. Note that only override data wave steps (with the specific base Namespace/Class/Method) will appear in the Wave Step Field on the Override Data Window.

 

Active Scale users note:

  • The override data configuration is available for Lower and Production level users only.
  • Customer SQL checkbox is enabled for Lower and Production Level users only.
    • User can only view the text on selecting the checkbox.
    • Custom SQL text can be selected and copied.
  • Lower and Production level users can Create, Delete, Copy existing override data.
    • When creating a new override data, users will not be able to select the SQL checkbox. The Update Criteria drop-down lists is available when creating new override data.

 

WARNING: Since you can also use this functionality to execute a custom SQL statement during the wave process, you need to be careful that the SQL that you want to execute is valid. If the system has an error when attempting to execute this SQL statement, the system will not process your custom statement, and proceed to the next wave step.

Override Data Window...

 

Using the Header Fields

Access the Override Data Window. Name a record and provide a description.

  1. Use the Wave Step Field to indicate the wave step that will initiate the data override.

     
  2. Use the Priority Field to indicate in what order the system will process the override data wave step(s). During a wave, the system processes though these steps one after another. This priority setting tells the system in what order these updates should be processed. Therefore, if you have an override data step that is dependent on data from another record, you can give the one that needs to happen first a lower priority number. Thus, the update will take place before the system starts doing the checks for the next step.

     
  3. Use the Custom SQL Checkbox to add your own SQL statement to this record. The system will display a text edit box so you can enter your own custom code. If you have entered any values in the other fields on this window, the system will display this in the text box as SQL when you select this checkbox. You can then edit these values directly from the SQL statement.



    Also there is a special token included in the custom SQL called <<LAUNCH_NUM>>. You should always leave this value unchanged unless you intend to update data for things outside of this specific wave. If you leave the value in the statement, the system will test the SQL statement when you exit. If you remove this value, the system will not test the statement because it will not know what wave you are trying to update.

 

Using the Update Criteria Tab
  1. Use the Data Selection Field to indicate the criteria record that you want to use to determine exactly what data that the system will override. For example, you could define a criteria record for a specific customer, company, etc., and the system then would only override data for that customer/company.

     
  2. Use the Override Table Field to indicate which database table includes the field-level data that you want to override. This table that you choose determines which fields you can choose from in the Override Field. Remember that you can choose to update any database table using the custom SQL option.

     
  3. Use the Override Field Field to indicate the shipping field value that you want the system to override.

     
  4. Use the Set To Value Field to indicate the new value that you want the override field to have.

     
  5. Use the Override Existing Data Checkbox to tell the system that even if the override field has a previous value, you want to replace this value with the new one. Otherwise, the system would only override this field's value if it was blank, null, 0 (if a numeric field), or *Default.

     
  6. Press OK. The system will save your record.

 

 

Override Data Criteria Window...

 

Using the Filter Tab (in the Override Data Criteria Window)

Access the Override Data Criteria Window. Name a record and provide a description.

  • You can use these records to determine which set of data that you want the system to override. For example, if you want the system to only look at a certain customer or company's data, you would define a criteria record to search for that certain customer/company. You can then choose this record on the Override Data Window's Data Selection Field.
