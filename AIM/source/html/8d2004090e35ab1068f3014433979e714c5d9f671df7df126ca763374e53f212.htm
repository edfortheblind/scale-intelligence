XML Interface Tutorial

This topic contains several discussions on how the XML interface mode would work in a real-world environment.

 

 

The following is discussed in this topic:

Order/Shipment Touchpoint

Receipt Touchpoint

Inventory Touchpoint

Order/Shipment Touchpoint...

 

New Action

- New shipments (orders) can enter the application in several areas. For example, you could have new orders enter into the system with a status of Packing Pending (they would then be available to be packed). Or, you could choose to have them enter into the pool with a status of In Pool (they would then be available to be added to a wave).

 

- Suppose your ERP functional flow allows you add order lines to an order after it has been interfaced to SCALE. You then would need to download an individual detail record in New mode. This will result in the new line(s) being assigned to the already-existing order.

 

 

Delete / Change Actions

- Suppose a customer wanted to delete or change a detail of an order after it has been interfaced into SCALE. You then would need to download the modified header and/or detail data in Delete or Change mode. This will result in the new data being removed (delete action) or assigned (change action) to the already-existing shipment.

 

- Suppose a customer canceled part of an order for a certain product, or added another item to an already-ordered shipment. You would then need to modify the order (using the delete or change action) after it had been interfaced to SCALE. Interfacing one of these actions will result in the appropriate line(s) being removed (delete action) or added (change action) to the already-existing order.

 

 

Save Actions

- When you run an interface Save action, the system will do one of two things, depending on the status of the data in the system:

 

- If the data already exists, the system will handle this data record as a Change action.If the data does not exist, the system will handle this as a New action.

 
Field Notes

- Status of New Shipments: When downloading new order headers, the interface system value "Interface Shipment New Status" identifies the status that the system will assign to the new shipment when it enters SCALE.

 

- Interface Link ID: When interfacing a container with a header/detail, you need to tie the container to the shipment using the Interface Link ID value. In the above example, since the container also includes an item quantity, the container must tie back to the detail using the ERP Order Line Number value.

 

- Parent Link ID: The Parent Link ID value is not used. Do not provide this value.

 

- Nesting Containers: To nest a child container in a parent container, you need to link the parent's Interface Record ID to the child's Interface Link ID.

 

- "Contents" Records: For each item quantity inside a container, you need to provide a "contents record," which actually represents the item quantity. If you do not provide this record, the quantity of the container will be 0, even if you provide a Quantity Field value.

 

- Shipment Comments: Shipment comments should be linked to the shipment's Interface Record ID.

 

- Shipment Line Comments: Detail comments should be linked to the shipment line's Interface Record ID.

 

- Downloading Changes to BOM Component Lines: To download a change to a BOM component line, you will need to download three types of records: one (or more) for the component detail(s) that you want to change (use the Interface Link ID to link back to the finished item); one for the finished item detail that the component is a part of (use the Interface Link ID to link to the shipment that contains this finished item); and one for the shipment. This way, the system has a way to link the component to the finished item, and the finished item to the header. You do not have to make changes to the finished item detail or the header, but they must be included in the download.

 

 

 

Receipt Touchpoint...

 

New Action

** Note that the schema for purchase orders is included inside the Receipt schemas.

 

- New receipts can enter the application in several areas. For example, you could have receipts enter the system with the statuses "Check In Pending" (they would need to be manually checked in via RF or the Receipt Workbench), or "Locate Pending" (bypassing the check-in process, these receipts would need to be located to a location via RF or the Receipt Workbench).

 

- Suppose your ERP functional flow allows you add detail lines to a receipt after it has been interfaced to SCALE. You then would need to download an individual detail record in New mode. This will result in the new line(s) being assigned to the already-existing receipt.

 

 

Delete / Change Actions

- Suppose a customer wanted to delete or change a detail of an receipt after it has been interfaced into SCALE (but not check-in/located yet). You then would need to download the modified header and/or detail data in Delete or Change mode. This will result in the new data being removed (delete action) or assigned (change action) to the already-existing receipt.
Field Notes

- New Receipt Status: When downloading new receipt headers, the interface system value "Interface Receipt New Status" identifies the status that the system will assign the new receipt when it enters SCALE.

 

 

 

 

 

Inventory Touchpoint...

 

Upload

- Inventory transactions, such as positive/negative adjustments, can be uploaded to your ERP system. This will ensure that the ERP keeps its inventory balances aligned with the system's totals.
Field Notes

- Before & After On Hand Quantity: The "before" on hand quantity value refers to an item quantity that is present in a location before a transaction is performed. The "after" on hand quantity refers to how much of an item after the inventory transaction is performed.

 

 

 

Item Touchpoint...

 

New Action

- SCALE allows you to download item master information from your ERP to the system. This allows you to populate the item master configuration database table, so there is no need to manually define your products in the system.

 

- For example, suppose that your company added a product to their sales inventory. You would then need to create an item master record for this product in SCALE. While this can be done manually via the Configurations Explorer, you can also download this item master data from your ERP.

 

 

Change Action

- Suppose there has been a change to an item's master record in your ERP. You would then need to download this information, in order to reflect this change in the system's item master table. You can use the interface for this change so there is no need to manually update item master records in SCALE.

 

- For example, suppose that one of your company's products changed characteristics (item color, dimensions, price, etc). You would then need to modify this product's item master record in SCALE. While this can be done manually via the Configurations Explorer, you can also download this modified item master data from your ERP.
Field Notes

- Numbered Field Values: The number designation after some of the item values (Weight 1, Quantity UM 1, etc) are there to identify the unit of measure definitions for this item (in lieu of creating an item unit of measure record in SCALE). For example, in the above example, each (1) and case (2) unit of measures are being defined for the item. The conversion quantity values determine how many units of an item is in a particular unit of measure (each=1, case=10). The system will take this data and create a record in the Item Unit of Measures Window for this item.

 

- Restriction: You cannot interface an item in which the Item ID does not match an existing item template in SCALE (an audit will be generated).

 

- For item master change actions, you only need to download values for the fields that you want to change. The exception is if you want to make unit of measure changes, because you will need to identify on which unit of measure you want to make the change on (in the above example, each UM). The system will make the appropriate changes on the item records and/or item unit of measure records.

 

- Deleting item cross reference / unit of measure records: You can download a delete of an item cross reference record or item unit of measure that exists for a specified item. Keep in mind the following:

* You can download a delete of a single sequence for a valid item unit of measure, but not a base unit of measure.

 

* You can download a delete of all sequences for an existing item unit of measure record.

 

* The system will error if you attempt to download a delete of base unit of measure sequence, when higher sequences exist for the unit of measure.

 

* If you perform a delete item download, the system will delete the associated item cross reference and/or item unit of measure even if those elements are not included in the download XML record.

Item Balance Touchpoint...

 

Upload

- You can upload item balance information from the system to your ERP. This allows you to reconcile the current item quantities in your warehouse with the ERP's item master table. This is helpful so your ERP has a current and accurate listing of the items in your warehouse and how many are available. In order to gather the item balance data, the system:

 

- Groups all location inventory records by warehouse, item, company, and inventory status.

 

- Excludes the records that are associated to a location classes that are not defined to be included in item balance uploads.

 

- Summarizes the quantity buckets across the remaining records in the group.

 

- Checks to see if the Include Zero On Hand Items flag is on. If so, then the system cycles through the item master and adds a record for each item/company that is not yet represented in the upload.

 

- Writes the information to the delimited output file.

 

 

 

Work Order Touchpoint...

 

New Action

- A work order is a process by which you take one or more component items and make a different finished item out of them. SCALE allows you to download a work order and all of its components. Or, the download could contain just a work order header. In this case, the components would be determined by looking up the Bill of Materials for the finished item on the work order and creating the component items in the work order detail based on that.

 

Save Action

- Instead of using 'New' or 'Change' as the action for the interface, it uses 'Save'. This writes the work order if it doesn't exist and updates the existing work order if it does exist.

 

 

Delete/Change Actions

- Changes and deletions are allowed to an existing work order in the system. For example, a change could happen if an additional component line is added to the existing work order. However, if the quantity to be built on the work order changes, the system will automatically change the components to match.

 

- A deletion could occur if there is a deletion to a component line on the work order. Or, it could be delete the entire work order from the database.

 

 

Upload

- During the inventory transactions upload process the results of the quantity of components used and the quantity of finished items created is sent to the host system. The 'Reference ID' and the 'Reference Type' on these records are used to link the transactions back to a work order on the host system. This insures that the inventory in the host system is in sync with the inventory in SCALE. It also allows the host system to perform any updates it might need to do in its own work order process. SCALE uses inventory adjustments to subtract the components and add finished items when a work order is completed. The Work Order System Values configuration stores the adjustment types used when confirming a work order.
Field Notes

- Work Order ID : This field must be unique across the entire system.

 

- Item/Company: Item and Company are fields that work together. The system standard for looking up an Item in the Item configuration is to first look for the specific Item and Company combination. If that is not found, then look for the Item with a blank (or NULL) company. Either one or the other combination should exist, but not both. When looking up an Item/Company in the Bill of Materials configuration, it always looks for the highest numbered Revision Number for that Item/Company.

 

 

 

 

 

 

 

 

Bill of Materials Touchpoint...

 

New Action

- A bill of materials is a listing of the component items and quantities of those items needed to create a finished item through a work order. SCALE allows you to download a finished item and its components, along with the quantity needed to make up the finished item.

 

Save Action

- Instead of using 'New' or 'Change' as the action for the interface, it uses 'Save'. This writes the bill of materials if it doesn't exist and updates the existing bill of materials if it does exist.

  

 

Delete/Change Action

- Changes and deletions are allowed to an existing bill of materials in the system. For example, a change could happen if an additional item is added to the existing bill of materials.

 

- A deletion could occur if there is a deletion to a an existing bill of materials from the database.
Field Notes

- Item/Company: Item and Company are fields that work together. The system standard for looking up an Item in the Item configuration is to first look for the specific Item and Company combination. If that is not found, then look for the Item with a blank (or NULL) company. Either one or the other combination should exist, but not both. When looking up an Item/Company in the Bill of Materials configuration, it always looks for the highest numbered Revision Number for that Item/Company.

 

- Build Location: If filled, the location must have a Location Class of 'Work Order Build'.

 

- Increase Quantity Type: If the Increase Quantity Eligible field is Y, this field must be filled with A (for Amount) or P (for Percentage)

 

- Increase Quantity Amount: If the Increase Quantity Eligible field is Y, this field must be greater than 0. If the Increase Quantity Type field is P, this field must be less than or equal to 100.
