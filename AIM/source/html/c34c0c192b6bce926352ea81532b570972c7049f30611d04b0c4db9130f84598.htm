Bill of Materials Touchpoint

The system supports the interfacing of Bill of Materials from your ERP into SCALE. The Bill of Materials is interfaced into SCALE via an XML file. This interface consists of a finished item and its components, along with the component quantity needed to make up the finished item.

  • Bill of Material Headers: These can be interfaced with or without associated details.
     
  • Bill of Material Details: These can be interfaced as part of a Bill of Materials download. If downloading only detail to the Bill of Materials, the Bill of Materials header must be specified.

General Guidelines

  • When downloading a Bill of Materials, the ERP can download just the Bill of Materials header information. The system creates the Bill of Materials header with no details.

  • When downloading a change to a Bill of Materials, the download information must include the Bill of Materials Header information.

  • When updating an existing record, if a value is not interfaced for a field, the system treats it as “no change” and retains the existing value.

  • When downloading a change to a Bill of Materials, the download information can specify a new Bill of Materials detail to an existing Bill of Materials header. In order to do this, the information must have the Bill of Materials header specified, along with the new Bill of Materials detail. If this is sent in a 'Save' mode, the system verifies if there is an existing record with this information. If there is an existing record, it updates the record as a 'Change'. If there is not an existing record, it is treated as a new record.
  • When downloading a delete of a Bill of Materials, the ERP should send an item/company/revision number for an existing Bill of Materials through the interface with a “Delete” action. The system will find the Bill of Materials and delete it from the database.

  • When downloading a delete to a Bill of Materials, the download information can specify a single Bill of Materials detail on an existing Bill of Materials. When this happens, only the Bill of Materials detail specified is deleted.

 

 

Rejection Causes / Validations / Notes

  • The items must be interfaced down. The items must exist in the 'Item' configuration. 'Item' and 'Company' are fields that work together. The system standard for looking up an Item in the 'Item' configuration is to first look for the specific 'Item' and 'Company' combination. If that is not found, then look for the Item with a blank (or NULL) company. Either one or the other combination should exist, but not both. When looking up an Item/Company in the Bill of Materials configuration, it always looks for the highest numbered Revision Number for that Item/Company.
  • The interface will validate (against SCALE configurations) certain values that are downloaded. Use the Table Values Spreadsheet to look up specific values to determine if they are validated.
     
  • The interface sent with the action of 'New" will reject a Bill of Materials if the Item/Company/Revision Number combination already exists in the system.
  • If the Inventory System Value “Should Item be validated throughout system?” is set to “Yes”, and the item does not exist in the item configuration, it will reject.

    •  

  • If the Build Location is interfaced down, it must be a valid location within the warehouse specified. The 'Location' configuration field 'Location Class' must be defined as 'Work Order Build'.
