Replenishment Process Summary

** Functionality **

Scenarios

Process Flows

 

 

 

Summary...

The replenishment process determines when product should be moved from bulk storage locations and transported to forward picking locations. This allows employees to efficiently complete picks for individual orders without compromising the integrity of larger UM increments. Replenishments are triggered by the system when the location's quantity falls below a minimum threshold percent. You can set this percent value at the location /location type level, or for an item/item class. A replenishment generates an allocation request from the bulk location. The product is marked as In Transit to the forward location. The allocation of product for the replenishment is managed by the allocation rule defined on the replenishment master. .

 

There are several methods of replenishment, which are described in more detail in the "Scenarios" section of this overview topic. You can research replenishment activity on the History Window. This window will display each decision made during replenishment, including why a replenishment was generated and why a certain location was selected.

The following are key features of the replenishment functional area:

 

 

Replenishment Masters...

All replenishment activity is managed by replenishment master records. You can create multiple records to replenish product to specific warehouse areas at different times.

 

 

 

Replenishment Strategies...

The system uses these strategies to help determine how the replenishment process will attempt to replace product at an inventory location. The following strategies are featured in SCALE:

  • Fill The Destination Location - The system will allocate enough product to fill the location, regardless of the value in the Maximum Replenishment Percentage Field on the Item Location Capacity Window.

  • Round Down To The Previous Whole Number Increment - If the replenishment amount is for less than a full increment (pallet, case, etc), the system will round down and replenish the full increment. For example, if the replenishment amount is for 1.75 case, the system will replenish 1 case.

  • Round Up To The Next Whole Number Increment - If the replenishment amount is for less than a full increment (pallet, case, etc), the system will round up and replenish the full increment. For example, if the replenishment amount is for 1.75 case, the system will replenish 2 cases.

 

 

Automatic vs. Manual Replenishment...

Replenishment can be run in two different manners:

  • Manually: The replenishment process is kicked off by the user from the Inventory Insight.

  • Automatically: The replenishment process can be kicked off automatically in two ways. One, during the wave, when the replenishment wave step is included in the wave flow. And two, when the capacity of a location is driven below the minimum percent threshold (when using real time replenishment).

 

 

Replenishment and Work Creation...

SCALE supports using replenishment with and without work creation:

  • If a replenishment request is generated from a wave, the system will run the work creation process if its included in the wave step flow, and the replenishment master used to create the request has a Create Work Method of Automatic (it ignores masters defined with other create work methods). If the work creation process is not included in the wave step flow, then no work will be created. Work also could be created at a later time manually in the Replenishment Insight screen.

  • If a replenishment request is generated manually (Inventory Insight), whether the system will create work or not depends on what is defined on the replenishment master that was used to create the request. If configured to create work automatically, then the system will kick off the work creation process once the request is generated. If configured to create work manually, then the user can create work for this request in the Replenishment Insight screen.

  • If a replenishment request is generated automatically (when the capacity of a location is driven below the minimum percent threshold, and real time replenishment is being used), whether the system will create work or not depends on what is defined on the replenishment master that was used to create the request. If configured to create work automatically, then the system will kick off the work creation process once the request is generated. If configured to create work manually, then the user can create work for this request in the Replenishment Insight screen.

 

 

Replenishment Insight Screen...

SCALE also includes a window called the Replenishment Insight screen, which allows the user visibility to open replenishment requests currently in the system. The user can view the information of a specific request from this screen. Also, after a request has been generated, work can be created manually from this screen. The user can "mark" a request for later work creation (which will be processed later via a scheduled job), or indicate that they want work created for this request immediately.
