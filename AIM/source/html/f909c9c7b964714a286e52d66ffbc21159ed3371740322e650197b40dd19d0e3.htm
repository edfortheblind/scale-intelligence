Immediate Needs Process Summary

** Functionality **

Process Flows

 

 

Summary...

The Immediate Needs module links the receiving and outbound processes to fulfill the immediate needs of your warehouse. There are two main components of this process: the logging of an immediate needs request, and the fulfillment of that immediate need. Logging involves the process of the system generating an immediate needs request to indicate that an entity (shipment, work order, replenishment, or short-picked shipment) cannot be completely fulfilled. Fulfillment involves the system taking newly-received item quantity and automatically allocating this quantity to fulfill the immediate need. Users can view a list of the current immediate needs requests and their statuses on the Immediate Needs Insight screen.

 

An immediate need request's priority setting determines the order in which the system will attempt to fulfill it. The system assigns a default priority setting to a request, which is defined in the Immediate Needs Trigger Window. However, you can also manually change a record's priority. Note that these priorities will only come into play for multiple immediate needs requests of the same item.

 

When the system creates an immediate need request, you can view these records in the Immediate Needs Insight screen. This window allows you to search for immediate need requests using several search criteria fields. Once an immediate need is fulfilled, the system will automatically close and delete the request from the viewer window.

The following are key features of the immediate needs functional area:

 

 

Processing Flow...

 

The following is how the system processes received-in quantities using immediate needs:

  1. If then entire quantity on the receipt container can be used to fulfill a single immediate need, the system cross docks the quantity to the shipping dock.

  2. If this quantity cannot be used to fulfill a single immediate need, then the system checks the Store Location Assignment Window to see if any immediate need is tied to a put-to-store location. If it is, the system splits that quantity off to a separate child container and locates to that location. This is done for any other immediate needs the system can find with put-to-store locations.

  3. If there remaining immediate needs that are not tied to put-to-store locations, the system decides which locating rule to use, in the following manner:

    (1) the shipment line immediate need locating rule

    (2) the locating rule indicated in the Immediate Needs System Value

    (3) the original locating rule

  4. If there is any quantity remaining, the system performs standard locating.

 

 

Immediate Needs Triggers...

There are four places where the system can trigger immediate needs requests:

  • Shipment Allocation: The system will generate an immediate needs request when allocation is run, and a detail line is partially or completely rejected. See the process flows tab of this summary topic for a detailed look at this trigger. Note that components and finished items associated with the "Add BOM Component Lines" wave step are ineligible for immediate needs processing.

  • Shipment Short Pick: The system will generate an immediate needs request when a short pick is performed at a location. The system will log the remaining quantity as requiring an immediate need in the same manner as an allocation rejection (when Immediate Needs is turned on for short picking). This functionality is supported by short picking through RF work execution, non-RF work execution, and shipment lines (without work).

  • Replenishment Allocation:The system will generate an immediate need request whenever replenishment allocation fails to bring forward the requested quantity.

  • Work Order Component Allocation:The system will generate an immediate needs request when any work order components fail allocation.
