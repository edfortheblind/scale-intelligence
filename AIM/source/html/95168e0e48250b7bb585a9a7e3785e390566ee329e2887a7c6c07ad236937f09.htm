UCC Code Field

** To read more about EPC generation, see the topic How an EPC is Generated **

 

Use this field to define a specific position of the UCC-128 barcode. The UCC-128 barcode uniquely identifies a specific shipment. It can be included on vendor compliant labels. During the container creation wave step, the system generates a UCC-128 barcode and assigns it as the container's ID. The UCC-128 barcode has 20 positions; each position helps to identify the shipment. The tables below provides the purpose of each position number.

 

 

Generating UCC-128 Shipping Container ID...

 

Position Number

 

Purpose

Positions 1 - 2

Represents the UCC-128 serial shipping container code qualifier. This value will always be '00' application identifier.

 

Position 3

Represents the packaging type. This value is the UCC Code from the Container Class associated with the container’s Container Type.

 

Positions 4 - 10

Represents the UCC/EAN Manufacturer ID (Company prefix). The value can vary from 7-10 characters.

 

IF the shipment/shipping container is associated to a Company,

AND the UCC/EAN is defined for the Company,

THEN use the Company UCC/EAN number when generating the container ID.

 

IF the shipment/shipping container is associated to a Company,

AND the UCC/EAN is NOT defined for the Company,

AND the UCC/EAN is defined for the shipment’s warehouse,

THEN use the UCC/EAN number defined for the shipment’s warehouse.

 

IF the shipment/shipping container is NOT associated to a Company,

AND the UCC/EAN is defined for the shipment’s warehouse,

THEN use the UCC/EAN number defined for the shipment’s warehouse.

 

IF the UCC/EAN is defined for neither the Company nor Warehouse

THEN use ‘04’ with zeros appended at the end, i.e. ‘0400000’.

 

Positions 11 - 13

These 3 flex positions will be used for Company prefix codes that are greater than 7 characters or for shipping container number if not needed for company prefix code. The company prefix code has precedence over the shipping container number.

 

Positions 14-19

 

Represents a next number (serial reference) that is generated by the system. The next number used has the key “Shipping Container Number” in the Next Number configuration. If the number is not long enough to fill the entire segment, this portion of the field is filled with leading zeros.

 

 

 

Notes...
  • Once the container ID is generated, the system must check to see whether that ID already exists in the database. If the ID already exists as a shipping container ID or multiple order pallet ID, then the system increments the shipping container number next number and generates the ID again. This continues until a unique number is found.

  • If the next number ever gets to 999999999, then it resets itself to 1 on the next request.

  • If the system goes through all available next numbers and cannot generate a unique ID, it is an error condition and the process of creating the container stops with an error. Note that there is a "UniqueContainerIdCreation.TimeoutInSeconds" timeout configuration in the service.properties file (the default value is 30 seconds). The system will try to find a new unique container ID for the specified amount of time, and then fail the process.

 

Example: Container ID...
  • A standard carton container class has a UCC code of 0. Suppose the container does not have a company associated with it. The EAN on the warehouse is 1146587. Also suppose the next number in the Next Number config is 2909. In this case, the container ID would be generated as follows: 00011465870000029092. If that container ID already exists, then the system would increment the next number to 2910 and try again.

 

Example: Container ID when UCC length is 10...
  • Suppose the company EAN is 1234567890, the next number is 9876543, and the container ID is 00012345678908765432. The “9” from the next number gets removed because of the UCC length.

 

 

 

Generating UCC-128 Multiple Order Pallet ID...

 

The generation of the UCC-128 multiple order pallet ID follows the basic rules as the UCC-128 Container ID. This number must be unique. If the ID already exists as a shipping container ID or multiple order pallet ID, then the system increments the shipping container number next number and generates the ID again. This repeats until a unique number is found. 

 

The differences in the generation of the multiple order pallet ID are in the retrieval of the UCC Code (extension digit) and the UCC/EAN Manufacturer ID fields. This value will be 0. The UCC/EAN manufacturer ID will be based on the value found for the multiple order pallet’s warehouse. If this value is not defined, then it will use ‘0400000’ as the UCC/EAN manufacturers ID.

 

Position Number

 

Purpose

Positions 1 - 2

Represents the UCC-128 serial shipping container code qualifier. This value will always be '00' application identifier.

 

Position 3

According to GS1-128 standards this field is an extension digit. It is used to increase the capacity of the number of unique IDs (SSCC’s). This value will be 0.

 

Positions 4 - 10

Represents the UCC/EAN Manufacturer ID (Company prefix). The value can vary from 7-10 characters.

 

Retrieve from the UCC/EAN number defined for the multiple order pallet’s warehouse.

 

IF the UCC/EAN is NOT defined for the warehouse,

THEN use ‘04’ with zeros appended at the end, (i.e., ‘0400000’).

 

Positions 11 - 13

These 3 flex positions will be used for Company prefix codes that are greater than 7 characters or for shipping container number if not needed for Company prefix code. The Company prefix code has precedence over shipping container number.

 

Positions 14-19

 

Represents a next number (serial reference) that is generated by the system. The next number used has the key “Shipping Container Number” in the Next Number configuration. If the number does not fill the entire segment, this portion of the field is filled with leading zeros.
