Reviewing & Creating Statuses; Reviewing the Default Status Flow

Three setup procedures will be discussed in this topic:

  • Reviewing the System-Defined Statuses: You can review the system defined statuses on the Functional Area Window. The system defined statuses accommodate all processes generally completed for a functional area. They are provided to minimize setup time and to support the default status flow. Review these statuses to verify that they reflect your business processes.
     
  • Creating User-Defined Statuses: You can create user defined statuses to support your warehouse's unique processes. You will create these on the Functional Area Window, since all statuses must be associated with a functional area to operate. These user defined statuses can be included in the default flow or in custom status flows. Please talk to your Manhattan representative before creating a new status.

  • Reviewing the Default Status Flow: The inbound and outbound functional areas feature a default status flow. When the appropriate detail record (receipt line for inbound, shipment line for outbound) does not identify a status flow, the system uses the default flow defined for that functional area. You can review the default status flow on the Functional Area Window. The system will use this default flow to process the majority of items. If necessary, edit this flow to better accommodate your processing. We recommend that the default status flow accommodate the majority of your products. This is especially helpful if you must manually identify the status flow on the detail record before its interfaced to the system.

Reviewing the System-Defined Statuses...

  1. Access the Functional Area Window.

  2. Review the statuses associated with each functional area. Statuses that contain a checkmark in the System Created Field were provided with the system. You cannot delete a system defined status, but you can remove it from the default status flow.

 

 

 

Creating User-Defined Statuses...

  1. Access the Functional Area Window, and select the New Action. The system will display the Functional Area Status Window.

  2. Use the Status Number Field to associate this status with its numeric value. Statuses in a flow are always processed in numeric order. The lower the number, the sooner the status is executed.

     

  3. Use the Status Name Field to identify this status. The status name should be very descriptive; the system displays the status name on-screen, not the status number.

     

  4. Use the Mandatory Checkbox if this status must be included in all flows, including the default flow. The status will be automatically added to existing flows and preselected for all new custom status flows. You cannot remove or exclude a mandatory status.

     

  5. Use the In Default Flow Checkbox if this status should be included in the default flow. Note that if the Mandatory Checkbox is selected, the system will automatically select the In Default Flow Checkbox.

  6. For information on the Include in Interface Upload Checkbox, see the Configuring an Outbound Status to Automatically Upload Shipment Data section in this topic.

    7.  

  7. Use the Related Status Field to associate this with another status if these statuses should always be run together in a flow. Since the system processes through a flow in numeric order, the related status must have a higher status number than the one that you are creating here. If it did not, the system would not know to run the related status until it was too late.

     

  8. Use the System Status Field to indicate the status that you are creating.

  9. Use the External Status Field to indicate the status that will appears in Trading Partner Management on the Web Order Status screen. Note that this type of status is valid for Outbound only.

 

 

 

Reviewing the Default Status Flow...

  • If a Status has a Y in the In Default Flow Field, it is included in the default status flow. If a status is not mandatory and contains a Y in the Change Allowed Field, you can remove it from the default flow.

  • You can include a status in the flow by either selecting its In Default Flow Checkbox or selecting its Mandatory Checkbox. If you select the Mandatory Checkbox, the system will include it in all status flow for this functional area. These checkboxes are on the Functional Area Status Window. You can access this window by selecting the status from the Detail Records Tab and opening it (right click on status, select Open).

 

 

 

Configuring an Outbound Status to Automatically Upload Shipment Data...

You can have the system automatically generate an interface upload record when a shipment's trailing status reaches a particular status. This is governed by the Include in Interface Upload checkbox. This is useful if, for example, you want your ERP to have a record of shipments that are finished with the packing process (you would have the Ship Confirm Pending status flagged to include in interface uploads).

 

Keep in mind the following:

  • This functionality applies to the outbound functional area only.

  • The upload criteria setting on the interface process defines what shipment data the system will consider for these uploads.

  • The system will not allow shipment data to be uploaded multiple times for the same trailing status change. For example, suppose you have the status In Packing flagged for uploads, and you have a shipment that reaches this status (and the data is uploaded), If, for some reason, the shipment reverts back to a Packing Pending status, when the shipment reaches an In Packing status again, the system will not upload the shipment data a second time.

  • The system will not upload shipment lines and containers that have been transferred to an existing shipment as part of shipment distribution. Only lines and containers transferred when creating a new shipment will be uploaded.

     

  • The system will not upload shipment data for manually created shipment though you have selected the include in upload option. Upload of shipment data works only when shipment status moves from one status to another.
