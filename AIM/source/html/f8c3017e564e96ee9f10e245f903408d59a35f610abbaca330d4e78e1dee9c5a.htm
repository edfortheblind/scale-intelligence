Using the Audit Log Insight Screen

The system uses the audit log to track unexpected errors and system processing. You can use the Audit Log Insight Screen to research and troubleshoot technical problems you are having with the application. There are two types of things that the audit log tracks: technical errors (called "exceptions") and system processes. Exceptions are unexpected errors that occur on an infrequent basis. Examples of these include if the database or application server is shut down, or if a .DLL file is overwritten. This type of tracking is turned on by default in the Technical Values Window.

 

The audit log also can track system processes, step-by-step, through every class and method that data travels through. This allows you to track processes from a programmer's perspective to help debug a problem that is occurring somewhere in the system. Do NOT activate audit processing in a production environment unless instructed by support or your consultant. This type of audit tracking will slow your processing down dramatically. For this reason, process tracking is turned off by default in the Technical Values Window.

Procedures: Performing a Record Search...

When you open the Audit Log Insight Screen, the system will display a series of basic criteria fields which you can use to narrow down your search for a system exception/process record. If you have more technical information available, you can use the following fields to locate the record associated with your exception/process:

  • Class Name: Indicates the actual class called where the exception occurred.

  • Method Name: Indicates the method within the class above that exception occurred.

  • Process: Indicates the process that the system logic was going through at the time the exception occurred.

- After the search is invoked, the system will display all the record(s) that meet your criteria in the List Pane grid. You can see the details of a record by using the View action.
