Defining an Item's Units of Measure

A unit of measure (UM) identifies a storage container used to move product through the warehouse. The system uses this information to calculate how much product can fit in a location based on its UM breakdown. Common examples of UMs include cases, pallets, eaches and innerpacks. When you define a unit of measure (UM), you are providing the system with the following information:

  • Which UM values are available for each item/item class.

     

  • How many units a UM can hold, for each item/item class.

     

  • When a broken UM should be still be treated as this UM.

     

  • The movement class associated with the UM.

     

  • The dimensions for the UM.
     
  • If the UM should be treated as loose in container creation.

When an item does not have item unit of measure data, the system uses the container type dimensions to populate the dimensions of the full case container. If item unit of measure data exists, the system will use those to populate the dimensions. Note that before you can define a unit of measure (UM), you must associate the item with a storage template. If you do not, the system will use the default storage record. Also, the item/company combination for an item unit of measure must exist in the Item Window.

Using the Item Unit of Measure Window...

  1. Select either the Item Class or the Item Button.

     

    • To define the UM values for an entire class, select the Item Class Button. The system will activate the Item Class Field. Use this menu to identify the class that you want to create this record for.

       

    • To define the UM values for one item, select the Item Button. The system will activate the Item Field. Select the item that you want to create this record for. Use the Company Field to identify the company associated with this item.

       

  2. Select the New Action. The system will display the Item Unit of Measure Detail Window. The Item or Item Class value that you defined is defaulted. You will use this window to define the sequences.

 

 

Using the Item Unit of Measure Detail Window...

The header will default the item/item class that you defined on the Item Unit of Measure Window. If you defined a company, it will also be defaulted.

 

Note on Record Sequence

The system sequences item UM detail records in order from lowest to highest, according to its conversion quantity value. You will be required to configure a conversion quantity of "1" for the lowest unit of measure (for example, an "each").

  1. Use the UM Field to identify the unit of measure that you want to create.

     

    • The first record that you create should be the smallest unit of measure for this item/item class. Generally, the smallest UM equals one saleable unit or one item/item class unit. Common examples include one each, one piece, one unit, etc. Subsequent records will be based on the first, smallest UM.

     

  2. Use the Conversion Quantity Field to identify how many eaches this UM contains. The system uses this value to perform UM conversions for allocation and replenishments.

      3.  

    • This value identifies how many Sequence 1 UMs can fit in subsequent UM values. For example, if you are creating a UM for a casepack and a case holds 50 units, the case's conversion value is 50. Of course, this example assumes that the Sequence 1 UM equals an each, or one unit.

       

    • For the Sequence 1 UM, this value is almost always '1' if you distribute individual units. For subsequent levels, the system converts each UM back to the first UM (Sequence 1).

       

  3. Use the Treat As Full Percent Field to indicate the percentage of an item quantity that the system will consider a "full" unit of measure, IF the system is attempting to allocate the complete quantity for a location/license plate. If the quantity is above the defined Treat As Full Percent value, then the system will treat that quantity as the next higher unit of measure (e.g., a case or pallet).



    For example, suppose the following:

    - The "full" quantity for the pallet unit of measure is defined as 100 EA

    - The Treat as Full Percent setting is defined at 50%

    - There is a quantity of 80 EA currently at the location



    Therefore, an allocation of 80 EA would be considered a "full" pallet allocation. However, an allocation of 79 EA would not.

     

  4. If appropriate, use the Movement Class Field to associate this UM with a movement class. The movement class identifies how quickly this item/item class UM moves through your warehouse.

     
  5. Use the Treat As Loose In Container Creation Check box to indicate that this unit of measure should be treated as a "loose" piece. During container creation, the system will check this setting to determine if this particular UM is a full container unit of measure, or if it should be packed as a loose piece.

     

  6. Use the EPC Package ID Field to indicate the unit of measure for an item packaged in a particular container. This value is used when computing an Electronic Product Code (EPC).

     

  7. Use the Dimensions Tab to identify the physical size and weight of the UM. The dimension values identify the height, weight, and length of the UM. The weight value identifies how much the UM weighs. For example, if a case of Item XYZ weighs 50 lbs, its Case UM would equal 50.

     
  8. Press OK. The system will add this record. It will not appear on the Detail Records Tab until you select the Refresh List Data Action.

 

 

Changing an Item's Unit of Measures...

You can change an item unit of measure's dimensions and/or conversion quantity (per item) on the Item Unit of Measure Window. This allows you to account for new container standards, such as a change in case quantity or weight. You can apply these changes to (A) new inventory, or (B) new and existing inventory in your warehouse.

 

Access the Item Unit of Measure Window. Open a unit of measure record.

  1. Change the item unit of measure's dimensions (length, width, height, weight, or conversion quantity). The system will then display a confirmation message:

     

    • Select "Yes" if you want the system to apply the new dimensions to new inventory, but you want the system to leave any existing inventory with its original dimensions. The system write "overrides" for all of the existing inventory so that it will have their previous dimensions. Any new inventory will, by default, use the dimensions specified in this configuration.  

       
    • Select "No" if you want the system to apply the new dimensions to both new and existing inventory. In this case, the system will not override any dimensions, which means that everything will use the dimensions specified in the configuration.

     

  2. Press OK. The system will save your changes.
