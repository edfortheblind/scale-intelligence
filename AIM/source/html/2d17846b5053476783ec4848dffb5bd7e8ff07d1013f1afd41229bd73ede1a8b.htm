Creating Initiation Workflow Records

In order to associate a RF receiving initiation workflow to a user's receiving preference, the workflow first needs to be defined in the system. This is done by creating an initiation workflow record.

 

Important Notes
  • The system ships with several default workflows, representing the initiation methods that SCALE supports. These workflows are shipped with all the activities (such as QC, GS1, etc.;) included as part of the workflow. Therefore, you may need to edit these workflows (or copy-and-create your own) to better match your warehouse's processing.

  • When you update the receiving workflow by either amending the .xaml file being used, or point the configured workflow to a different .xaml file, the RF check-in process does not refresh the workflow automatically; typically, the old workflow file is cached and therefore will require an IIS reset in order for the changes to take effect. For more information, see the workflow section in the SDK.

Using the Header Fields

 

Access the Initiation Workflow Window. Create a new record.

  1. Use the Identifier Field to provide a name for your workflow record.

  2. Use the Description Field to provide a helpful text summary of what activities are included in the workflow file.

  3. Use the Workflow File Field to indicate the actual .xaml file that you want to assign to this workflow record.

  4. Press OK. The system will then perform a validation in which it determines whether or not the activities in the workflow are in a logical order for processing. Note that during validation, the system ignores any custom activities that may have been added to the workflow. Also note that even if a workflow has been validated previously, every time you press OK, the system will perform validation on the workflow.

    - If the workflow passes validation, the system will save your initiation workflow record.

    - If the workflow does not pass validation, the system will display an error and allow you to choose another workflow file.

    For more detailed information on workflow (including listings of valid activity orders), see the SCALE SDK.
