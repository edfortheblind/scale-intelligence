Wave Configuration

Overview

 

A wave represents the different steps that the system uses to retrieve orders from the pool, and process them into the outbound portion of SCALE. All wave activity is defined on the wave record. The system uses this record to identify how to execute the wave during the run wave process, and what entities to create from the shipments included in the wave (such as allocation requests, containers, etc). Waves consist of a series of wave steps (called a wave flow), and each of these steps control a particular function of the wave (such as replenishment, allocation, work creation, etc).

 

Configuration Hierarchy

 

 

Configure Wave Profile

This record manages the movement of specific shipments through the wave cycle.

 

1. Wave Information

The wave name information is entered.

 

  • Mode - This selection determine how waves will be run for this record. If automatic is chosen, as soon at a wave is built, the system will run it. If you select automatic mode, determine if you want to exclude rejected shipments from being processed using this wave master record. To exclude rejected shipments, make sure that wave criteria record associated with this wave master includes the following criteria: the attribute 'rejection code' and the operand 'is null' (no value required).

  • Priority - Sets when this wave will be executed in relation to other waves. The system initiates waves in priority order. The lower the priority, the sooner a wave is initiated. If a shipment is processed in a wave, the system will not process it again through a later wave.

  • Auto Release - Enable to automatically release work to the warehouse. If you select this checkbox, the system will automatically release this work to the warehouse floor as soon as the run wave process is complete. If you don't select this checkbox, someone will need to manually release this work from the Wave Insight screen. You cannot cancel a wave that is released automatically.

  • Maintain Allocated replenishment upon wave cancellation. - this determine if the system should "maintain" a replenishment request from the wave if it is canceled. If this checkbox is selected and the system leaves the replenishment, the system will remove the request from the wave (along with its corresponding work). Note that the only time a replenishment will stay out on the system is if some other process has allocated the inventory that is being replenished. In this case, the system will leave the replenishment out there so as not to cause problems with the subsequent activity that allocated it. The system also generates history records that indicate the replenishment request and work was left from the wave.

    For example:

    • Suppose you run Wave1 which creates a replenishment for 10 of an item, and Wave1 allocates 3 of those.

    • You then run Wave2, which allocates 5 of the same item from that same location.

    • If you now cancel Wave1 the system will leave a replenishment for 10 out there so that it does not cause problems with Wave2.

 

2. Wave Flow

Select a wave flow. The wave flow determines what steps will be executed during the wave.

 

3. Wave Criteria

Select a wave filter. During the build wave, this value determines which shipments will be selected into this wave.

 

Users can create a new Wave Criteria using Create New.

 

4. Wave Maximums

Select a wave maximums record. During the build wave, this value determines how much product will be processed in this wave. It allows you to manage work flow through the warehouse.

 

5. Labor Plan

Select the the labor management data plan that you want to calculate estimated labor data for (when running waves using this master). A labor plan is a record that determines which labor group(s) to calculate values for in the wave, and in what sequence order to process them. Note that the labor plan execution wave step must be a part of your flow to use this value.

 

6. Container Creation

This defines which items/shipments you want the system to create containers for during the wave. In other words, container creation criteria determines which allocation requests get assigned to which containers. These criteria records also can define the certain order in which the system will attempt to pack certain items.

 

7. Pallet Building Master

Define how the system will build pallets during waves that include the pallet building wave step. This master record determines such things as which shipping container(s) will be eligible to be placed on a new pallet, and which strategy the system will use to arrange the pallet's contents.

 

8. Wave Pick Location Group

Select the wave pick location group record used by the wave for warehouse and criteria-based location grouping. Read Wave Pick Location Group Configuration.

 

9. Wave Picking Group

This identify the picking group record that the system will run during the wave. If the wave flow includes the pick group creation step, this record determines where in the warehouse the picking group can be used and how many full or loose cases constitute a group.

 

10. Document Master

the document master record that the system will run during the wave. The document master determines which document types will print for particular wave records, such as work instructions. This menu is only available if paperwork is a step in the wave flow selected for this record.

 

11. Warehouses

Assign wave flow records to warehouses. Note that when creating a wave or building a wave then only the wave masters for the selected warehouse will be available.
