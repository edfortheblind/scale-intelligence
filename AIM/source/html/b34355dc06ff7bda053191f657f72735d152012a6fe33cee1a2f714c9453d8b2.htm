Receiving Process Summary

** Functionality **

Process Flows

 

 

Summary...

The receiving process has two key components: check in and locating. Check in is the process of accepting product, which arrived at the receiving dock, into your warehouse. Item quantities can be checked in, unchecked in, and rechecked in multiple times, as long as it is not successfully located. During check in, the system creates a receipt container to support the quantity on a receipt line. This container can include either the entire detail line's quantity or part of the quantity. The system attempts to consolidate the received quantity into the largest UM it will accommodate. For example, if you receive 50 units and 10 units fit in a case, the system will check in 5 cases. Locating is the process of selecting the appropriate storage location(s) for the checked in product. The locating process is described in its own process summary topic. The system supports both interfaced receipts and receipts created via the application.

The following are key features of the receiving functional area:

 

 

Workflow Enablement...

The application's RF Receiving check in functionality is now driven by workflow. This allows you to be able to view and define the functionality/screen flow via a graphical interface. You can easily then add custom screen(s) to the RF check in functional flow, or move existing screens to different places in the workflow (according to certain rules, see the SDK for more information).

 

SCALE ships with several default workflows, which represent the common RF check in initiation methods that existed in earlier versions of the product. These workflows (.xaml) are made up of several "activities" that each represent a piece of functionality. You can view/edit a workflow record by opening it up in Microsoft Visual Studio's workflow designer (licensed separately from SCALE). The shipped workflow records contain all appropriate check in activities enabled, so you may need to edit these to match your warehouse's specific practices.

 

You can configure the RF check in workflow per user in the Receiving Preferences Window.

 

 

 

Receipt Containers...

When you check in product, the system creates a receipt container. Product in a receipt container is always of the same item and unit of measure. If you want to nest multiple receipt container into one container, you can manually create one. If you select the Group During Check in Checkbox, the system will consolidate the received product into the largest unit of measure possible. For example, if you receive 50 eaches and a case contains 10 eaches, the system will consolidate the 50 eaches into 5 cases. During check in, the system can create multiple receipt containers if the units cannot be consolidated into one unit of measure. For example, suppose item ABC has two units of measure: a case and a each. A case contains 10 eaches. You want to check in 58 eaches. The system would create two containers: one container of 5 cases and one container of 8 eaches.

 

Consolidating Receipt Containers

If you have multiple receipt containers with same item and unit of measure, the system will not attempt to consolidate them. However, you can manually nest them using the Receipt Workbench.

 

Checking In Into an Existing Receipt Container

To check in into an existing receipt container, the product you want to check in has to be the same item and same UM as the existing container's contents. The system will add the new contents to the existing container and consolidate the contents. So if the receipt container has 5 cases and there are 10 units in each case and you try to move over 25 eaches, the system will create 7 cases and 5 eaches.

 

Manually Created Containers

Manually created containers are storage containers that you can move any receipt container into. This allows you to locate different items together to the same location. This is especially helpful if you want to store all returned product in a salvage location until it can be checked and returned to the appropriate storage locations. It can also be used to hold product in one place until it all can be located to its individual locations. When you move a receipt container into a manually created container, the system will continue to consolidate same items/unit of measure when possible. For example, if manually created container 88 holds 2 cases of item ABC and you move 3 more cases of ABC into it, the system will consolidate the cases into one receipt container of 5 cases. Note that product in a manually created container can be located individually instead of to one location. However, the primary benefit of a manually created container is that you can locate mixed items to one location.

Blind Receiving...

Blind receiving allows users to create a receipt "on the fly" without having to enter a receipt into the system. When the user enters the header and detail information (during the check in process), the system will create the header and detail records behind the scenes. This allows the user to check in quantity quickly. One can also use this method to add detail(s) to an existing receipt (as long as it is located in the user's default warehouse). Users can be set up to perform blind receiving according to their receiving preference record.

Appointment Scheduling...

Warehouses can also use SCALE to schedule appointments for inbound receipts. Appointments provide the warehouse a way to schedule a certain receipt to arrive at the receiving dock. For example, suppose a certain carrier arrives at the warehouse at a specific time each week. You can then schedule an appointment for each of this carrier's receipts, so the flow through your receiving docks can be managed more efficiently.

 

 

 

Purchase Orders...

SCALE allows you to review, maintain, and create purchase order information in both the full-screen application and the web module. Purchase orders indicate what item(s) your warehouse should be expecting to arrive at the receiving dock. PO's are used by a warehouse's suppliers/vendors to supply receipt information ahead of the arrival of the truck to their warehouse. You can create and manage purchase orders in SCALE on the Purchase Order Insight Screen. From the Purchase Order Insight Screen, you can choose to create a receipt and line from the information contained on a purchase order. This is helpful if your ERP interface does not download receipts into SCALE, but you want to use receipts in your inbound processing flow. Using this functionality, you are able to bypass the need for these downloaded receipts by creating them directly from purchase orders. For example, suppose your warehouse's supplier is planning on sending you 500 pallets of Item A over the course of a year. They would first create a purchase order for Item A, adding a quantity of 500. When they are ready to ship some of Item A to your warehouse, they would create a shipment associated with this PO, which would indicate how many of the item they are going to send out. When the year is over, and all the Item A quantity has been shipped, the supplier would close the purchase order.
