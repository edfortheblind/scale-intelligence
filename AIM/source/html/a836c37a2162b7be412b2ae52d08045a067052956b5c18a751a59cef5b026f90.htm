Receiving Touchpoint

NOTE: The term "receipt header" / "receipt" and "receipt detail" / "receipt line" are used interchangeably in this topic.

 

 

The system supports the interfacing of receipt, receipt line, and container data between your ERP and the application. SCALE can also return receipt information back to the ERP after the receipt has been processed and its product has been checked into the warehouse. Receipts can be uploaded based on its receipt, receipt line, or container status. Also supported are changes/deletions of parts of receipts, such as lone lines or containers. In addition, you can also download purchase order and purchase order line data into SCALE.

 

SCALE can place newly-interfaced receipt data in several places, which are determined by settings on the Interface System Values Window. You can have each receipt enter or leave the system with a certain status. The receipt interface (download and upload) processes the following entities:

  • Receipts: These can be interfaced with or without associated details, containers, or comments.
     
  • Receipt Lines: These can be interfaced either as part of a receipt header download, or as a lone detail (which must be associated with an existing header). Details are not required in a download. Note that if you interface details, they must be associated with a header. A receipt detail cannot be deleted once a container has been checked in.
     
  • Receipt Containers: These can be interfaced as either separate or nested containers. If you interface containers, they must be associated with a detail (or multiple details). The container types can be authorized by company and warehouse and the authorization applies to the downloaded parent receipt containers. Generally, you will want to download containers if you are only using SCALE for manifesting or for web purposes, and you are NOT creating containers via system processing. Containers are not required in a download.

    To determine which containers can be uploaded, the system completes the following process to determine eligibility:

    A) It verifies that the container has not previously been interfaced.

    B) It checks the status of the container (which itself is defined on the "Receiving Upload Level" value, from the Interface System Values Window). This status must be equal to or greater than the value defined on the "Upload receipt containers at this status or higher" value. For example, if the interface is configured to upload "Containers" at a "Closed" status, then any closed container in the system will be eligible for uploading.
     
  • Purchase Order Headers: These can be interfaced with or without associated details.
     
  • Purchase Order Details: These can be interfaced either as part of a purchase order header download, or as a lone detail (which must be associated with an existing header). Details are not required in a download. Note that if you interface details, they must be associated with a header.

Receipt Header Rules...

  • The interface can retrieve address and item information from the system, if it is not defined on the downloaded record. For example, if either the Source ID or the Ship From values on the receipt header are supplied, the interface will load the appropriate address information defined in the system. If items are defined, the interface will load the appropriate item information on the receipt detail. However, the interface will never override interfaced values with values retrieved from the system.

 

 

Receipt Container Rules...

  • Once a container on a receipt header has reached this processing point, you cannot change/delete it.
     
  • Since a container may include multiple items, a container record should not display values in either the Item Field or the Item Quantity Field.
     
  • Quantities on receipt containers are always assumed to be in the base unit of measure for the item.
     
  • Nested Containers: A nested container is one that has been physically placed into a larger, parent container. The parent container is the box that other containers are nested into. The nested container needs to be linked to its parent container. To link these two records, the nested container's Interface Parent Link ID Field should contain the parent container's interface record ID. For example, if you interface a pallet, which includes five cases, the pallet is the parent container. A container that is placed into a larger one is the child container. In the example above, each case is considered a child container.

    - When downloading a child container for a receipt, the child container has to be in the same delimited file as it parent container. SCALE does not support the downloading of a lone child container.

    - If you are processing in delimited or fixed length mode, a parent container must be entered in the text file before its children.

    - If you are processing in direct mode, nested container order is not relevant.
     
  • Lone Containers: The application allows you can interface a lone container, which is in a different interface file than its receipt header and receipt detail (the receipt header and detail were interfaced previously). The lone container needs to be linked to its receipt header already in the system. To link these two records, the lone container's Receipt ID Field should contain the receipt header's receipt ID.

    - If you are processing in delimited or fixed length mode, a parent container must be entered in the text file before its child containers. If you are processing in direct mode, container order is not relevant.

    - The lone container's Temporary ERP Line Number Field should contain the detail's ERP Line Number.

 

 

Purchase Order Download Notes...

  • You will not be able to link a receipt header/detail to a purchase order in the same interface record.  You will, however, be able to download a receipt header/detail that is linked to a purchase order in the same interface file; they will just be two separate records. Note that in the example below, the top two lines represent one record.  The last two lines are a separate record.  

    For example, suppose you have a delimited download file with the data maps configured as the following:

    - PO Header: Map Name | Interface Record ID | PO ID

    - PO Detail: Map Name | Interface Record ID | Interface Link ID | PO Line Number | Item | Total Quantity

    - Receipt Header: Map Name | Interface Record ID | Receipt ID | Receipt ID Type

    - Receipt Detail:  Map Name | Interface Record ID | Interface Link ID | ERP Order Number | Item | Total Quantity | PO ID | PO Line Number

    Your data records, then, would look something similar to this:
    - POHEADERMAP | 100 | JACPO-1
    - PODETAILMAP | 101 | 100 | 1 | NOR0001 | 1000
    - RECHEADERMAP | 200 | JACREC-1 | PO
    - RECDETAILMAP | 201 | 200 | 1 | NOR0001 | 250 | JACPO-1 | 1

 

 

Locating Rule Assignment Note..

  • If you download a receipt with containers, the system will assign the same locating rule to both the detail and the containers IF the appropriate locating rule assignment criteria has criteria rules defined at the container level.

 

 

General Guidelines...

 

  • When updating an existing record, if a value is not interfaced for a field, the system treats it as “no change” and retains the existing value.

 

Rejection Causes / Validations / Notes...

  • The interface will validate (against SCALE configurations) certain values that are downloaded. Use the Table Values Spreadsheet to look up specific values to determine if they are validated.
     
  • When downloading, the interface will reject a receipt ID if it already exists in the system. However, you can configure the system to allow the same receipt ID to exist multiple times. Use the Interface Receipt Allow Duplicate Field (located in the Interface System Values Window) to indicate how the application will handle duplicate receipt ID's:
     
  • The SCALE interface process does not support using a comma as a "seperator" for numeric values. These values will need to be interfaced into the system using decimals as separators (4.95, not 4,95). The system can, however, display these values with a comma separator on SCALE windows, but in the database they must be in a decimal format.

  • Note that you cannot perform multiple actions on a single receipt in a single interface download file. For example, you cannot save/create a receipt and also delete it in a single XML file (they will need to be two XML files). One for save/create the receipt, and the second one for deleting the receipt.

  • In order to maintain the best performance when downloading receipts with many detail lines, your host ERP system should send the receipt header along with the details in the same file. This will create a single XML file during the interface.

  • The system allows downloading new receipt line with 0 quantity in XML mode. However, the system does not support creating zero quantity entry using user interface. Additionally, updating a line with zero quantity through the receipt interface download is also not allowed.
