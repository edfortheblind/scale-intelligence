Researching Warehouse Alerts

A warehouse alert communicates to the user when a certain condition in the warehouse exists and needs attention. Any time a warehouse action (that is defined as an alert) emerges or occurs, the system writes an alert request. Then, when the warehouse alerts scheduled job kicks off, the system will process this request and generate an alert record. You can configure these alerts to write "history" (special records that are viewable in the Warehouse Alert Viewer), send an email message, or both. You can use these alerts to learn about problem(s) in your warehouse and how to resolve them. Also, you can assign a priority to an alert to determine when the problem should be resolved, in relation to other alerts. For example, suppose a container fails the scan & weigh process because it exceeds the weight accepted by the carrier. If you had an alert defined for the manifesting process, the system would generate an alert that you could review on the Warehouse Alerts Viewer. Note that warehouse alerts are referred to as "email alerts" in SCALE's Trading Partner Management web module.

Warehouse Alert Descriptions...

The following are the default alert records shipped with the system:
  • Delete Shipment Alert – This alert is logged anytime a shipment is deleted from the system.
     
  • Inbound Alert - This alert is logged when a receipt first reaches a configured leading status.
     
  • Interface Alert – This alert is logged when interface process failures occur that cause the system to generate audits. If you receive such an alert, you would look at the Audit Log Window to get more information (though both the error file and history). Note that normal interface validation errors (for example, X field is required) would not trigger alerts of this type.

  • Interface Rejection Alert - This alert is logged during interface processing when the system encounters an issue with the actual interface data file. Note that normal interface validation errors (for example, X field is required) would not trigger alerts of this type.

  • Interface Validation Alert - This alert is logged during download interface processing when the system encounters a validation error with the downloaded data. For example, these validation errors could be such things as X field is required, or X field value does not exist, etc.
     
  • License Key Warnings – This alert is logged anytime a license key is violated. License key warning warehouse alerts are written as follows
    • Once per day starting 15 days before the current date range ends.
    • On the first day of a new date range, when the user count increases.
    • On the first day user profiles have been deactivated.
  • Manifesting Alert – This alert is logged when errors are encountered in the Scan and Weigh Scheduled Job.  The following are the scenarios in which alerts of this type would be triggered:
    - shipment not found
    - shipment id not found
    - errors returned from close container/manifesting logic
    - errors returned when creating a new container
     
  • Order Entry Alert – This alert is logged when an error occurs during the order entry process.
     
  • Outbound Alert – This alert is logged when a shipment first reaches a configured leading status.
     
  • Pro Number Alert – This alert is logged when the number of pro numbers left for a certain pro number set falls below the configured percentage (which is set in the Rating System Values Window).

 

 

 

Procedures...

The procedures below identify how to open, update, close, delete, or reprocess warehouse alerts. Note that some alert records do not have a warehouse associated with them. Therefore, even though the Warehouse Alert Tab defaults a value to the Warehouse Field, the system will return alert records that have no warehouse associated with them, along with your warehouse's records.

  1. Access the Warehouse Alerts Viewer.

     

  2. To narrow the records displayed in the record list, provide any appropriate filter criteria on the Criteria Tab. For example, if you only want to view alerts created today, you would provide today's date in the date range field. Press the Search Button. The results will appear in the record list on the Results Tab. You can then perform the following actions:

    - Open/Review an Alert:To open an alert, select if from the record list. Select the Open Action. The system will display the alert on the Warehouse Alert Window. Each time you view a record on this window, the system will identify it as reviewed. Your name will appear in the Last Reviewed By Field when someone accesses it again. You can access a different alert by using the Previous and Next Buttons. When you access an alert, the system indicates that you have reviewed it, whether you accessed it from the Warehouse Alert Viewer Window or by using the Previous and Next Buttons.

    - Update an Alert's Priority: Priority identifies when you believe an alert should be addressed, in relation to the other open alerts. The lower the alert's priority number, the sooner it should be addressed. To change an alert's priority, first open it, and then change its priority value. The system will identify the record as reviewed by you.

    - Close an Alert:You will want to close an alert after you have resolved the issue. You can only close an alert from the record list (on the Warehouse Alert Viewer). Select the alert from the record list and select the Close Action. The system will close the record. You will be identified as the person who closed the record on Closed By Field. The system will log the date and time that the record was closed.

    - Delete an Alert:The system will allow you to delete any alert that appears in the record list. The alert can be deleted even if it has not been either reviewed or closed. Simply right-click an alert, and choose Delete.

    - Reprocess an Alert:You can also reprocess email alerts that were not correctly processed by the system. To do this, right-click an alert and choose Reprocess. Note that you can only choose this option if the alert is in an error status.
