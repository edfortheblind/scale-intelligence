Order Touchpoint - Downloading New Order Header, Detail, Nested Containers, & Comments on the Header and the Detail

 

Functional Scenario

This scenario describes the type of records that you would download in a typical outbound flow. Also, this example includes such complexities as nested containers and comments on the header and the detail. The database value list below represents a full order taken from the ERP system, complete with basic customer/shipping data (header), item data (detail), container data, and additional order comments. Downloading this data would result in a completely new shipment being created in SCALE.

 

New shipments (orders) can enter the application in several areas. For example, you could have new orders enter into the system with a status of Packing Pending (they would then be available to be packed). Or, you could choose to have them enter into the pool with a status of In Pool (they would then be available to be added to a wave).

Field Notes

- Status of New Shipments: When downloading new order headers, the interface system value "Interface Shipment New Status" identifies the status that the system will assign to the new shipment when it enters SCALE.

 

- Interface Link ID: When interfacing a container with a header/detail, you need to tie the container to the header using the Interface Link ID value. In the above example, since the container also includes an item quantity, the container must tie back to the detail using the ERP Order Line Number value.

 

- Interface Action Code: You need to provide this value in order to indicate to SCALE what type of action the system will perform on the data record you will be interfacing (New, Change, Delete, or Save). See the Direct Mode Overview for more on these actions).

 

- Receipt ID: This value is optional for the detail in this scenario because the Link ID makes the association between the header and the detail.

 

- Parent Link ID: The Parent Link ID value is not used. Do not provide this value.

 

- Nesting Containers: To nest a child container in a parent container, you need to link the parent's Interface Record ID to the child's Interface Link ID.

 

- "Contents" Records: For each item quantity inside a container, you need to provide a "contents record," which actually represents the item quantity. In the example below, the line below the "NESTCONT74334" child container is the contents record for that container. If you do not provide this record, the quantity of the container will be 0, even if you provide a Quantity Field value.

 

- Header Comments: Header comments should be linked to the shipment's Interface Record ID.

 

- Detail Comments: Detail comments should be linked to the shipment line's Interface Record ID.

 

 

Direct Interface Example (New Action)

The following is a sample listing of the database values (and the tables they should be on) that need to be present to directly download this type of data.

 

Download_Order_Header: Interface Record ID, Interface Action Code, ERP Order, Warehouse, Shipment ID, Ship To Name, Ship To Address 1, Ship To City, Ship To State, Ship To Postal Code, Ship To Country, Scheduled Ship Date, Customer

 

Download_Order_Detail: Interface Record ID, Interface Link ID, Interface Action Code, ERP Order, ERP Order Line Number, Item, Total Qty, Quantity UM, Warehouse, Shipment ID

 

(for Parent Container) Download_Order_Container: Interface Record ID, Interface Link ID, Interface Action Code, Container ID, Container Type

 

(for Child Container) Download_Order_Container: Interface Record ID, Interface Link ID, Interface Action Code, Container Type, Container ID

 

(for Child Container's contents) Download_Order_Container: Interface Record ID, Interface Link ID, Interface Action Code, Quantity

 

(for Header Comment) Download_Order_Comment: Interface Record ID, Interface Link ID, Interface Action Code, Comment Type, Comments

 

(for Detail Comment) Download_Order_Comment: Interface Record ID, Interface Link ID, Interface Action Code, Comment Type, Comments

 

 

 

Order Touchpoint - Downloading New Order Detail Only

 

Functional Scenario

Suppose your ERP functional flow allows you add order lines to an order after it has been interfaced to SCALE. You then would need to download an individual detail record in New mode. This will result in the new line(s) being assigned to the already-existing order.
Field Notes

- Interface Link ID: This value is not needed in this scenario because you are not interfacing a header record, therefore you do not need to provide a link ID to associate the detail with the header. The ERP Order value provides this association.

 

- Interface Action Code: You need to provide this value in order to indicate to SCALE what type of action the system will perform on the data record you will be interfacing (New, Change, Delete, or Save). See the Direct Mode Overview for more on these actions).

Order Touchpoint - Downloading a Delete/Change Action for an Order Header & Detail

 

Functional Scenario

Suppose a customer wanted to delete or change a detail of an order after it has been interfaced into SCALE. You then would need to download the modified header and/or detail data in Delete or Change mode. This will result in the new data being removed (delete action) or assigned (change action) to the already-existing shipment.

 
Field Notes

- Required Fields: The delete and change actions share the same "required" fields; however, these fields are different than those required for a New Action.

 

- ERP Order Line Number/Shipment ID: Make sure that the ERP Order Line Number (detail) and Shipment ID (header) correspond to the existing values.

 

- Interface Action Code: You need to provide this value in order to indicate to SCALE what type of action the system will perform on the data record you will be interfacing (New, Change, Delete, or Save). See the Direct Mode Overview for more on these actions).

Order Touchpoint - Downloading a Delete/Change Action for an Order Detail Only

 

Functional Scenario

Suppose a customer wanted to delete or change a detail of an order after it has been interfaced into SCALE. You then would need to download the detail data in Delete or Change mode. This will result in the new data being removed (delete action) or assigned (change action) to the already-existing shipment

 
Field Notes

- Required Fields: The delete and change actions share the same "required" fields; however, these fields are different than those required for a New Action.

 

- ERP Order Line Number/Shipment ID: Make sure that the ERP Order Line Number (detail) and Shipment ID (header) correspond to the existing values.

 

- Interface Action Code: You need to provide this value in order to indicate to SCALE what type of action the system will perform on the data record you will be interfacing (New, Change, Delete, or Save). See the Direct Mode Overview for more on these actions).

 

- Shipment ID: Need to provide this value because there is no way to associate this detail with the existing header (because there is no link ID).

 

- Downloading Changes to BOM Component Lines: To download a change to a BOM component line, you will need to download three types of records: one (or more) for the component detail(s) that you want to change (use the Interface Link ID to link back to the finished item); one for the finished item detail that the component is a part of (use the Interface Link ID to link to the shipment that contains this finished item); and one for the shipment. This way, the system has a way to link the component to the finished item, and the finished item to the header. You do not have to make changes to the finished item detail or the header, but they must be included in the download.

Order Touchpoint - Using Save Actions For Order Downloads

 

Functional Scenario

When you run an interface Save action, the system will do one of two things, depending on the status of the data in the system:

 

- If the data already exists, the system will handle this data record as a Change action.

 

- If the data does not exist, the system will handle this as a New action.

Functional Scenario

This scenario describes the type records that you would download in a typical receiving flow. The data map below represents a full receipt taken from the ERP system, complete with basic vendor data (header), item data (detail), plus additional receipt comments.

For example, you could have receipts enter the system with the statuses "Check In Pending" (they would need to be manually checked in via RF or the Receipt Workbench), or "Locate Pending" (bypassing the check-in process, these receipts would need to be located to a location via RF or the Receipt Workbench).

Inventory Touchpoint - Uploading Inventory Transaction Data

 

Functional Scenario

Inventory transactions, such as positive/negative adjustments, can be uploaded to your ERP system. This will ensure that the ERP keeps its inventory balances aligned with the system's totals.

 
Field Notes

- Before & After On Hand Quantity: The "before" on hand quantity value refers to an item quantity that is present in a location before a transaction is performed. The "after" on hand quantity refers to how much of an item after the inventory transaction is performed.

 
What Data Does The System Upload

The system will upload records for all inventory transactions that have occurred since the interface was last run. The exception to this are transactions that are associated with an adjustment type that is configured not to be included with interface uploads.

 

 

 

 

 

 

Item Touchpoint - Downloading New Item Master Data

 

Functional Scenario

SCALE allows you to download item master information from your ERP to the system. This allows you to populate the item master configuration database table, so there is no need to manually define your products in the system.

 

For example, suppose that your company added a product to their sales inventory. You would then need to create an item master record for this product in SCALE. While this can be done manually via the Configurations Explorer, you can also download this item master data from your ERP.

 
Field Notes

- Numbered Field Values: The number designation after some of the item values (Weight 1, Quantity UM 1, etc) are there to identify the unit of measure definitions for this item (in lieu of creating an item unit of measure record in SCALE). For example, in the above example, each (1) and case (2) unit of measures are being defined for the item. The conversion quantity values determine how many units of an item is in a particular unit of measure (each=1, case=10). The system will take this data and create a record in the Item Unit of Measures Window for this item.

 

- Restriction: You cannot interface an item in which the Item ID does not match an existing item template in SCALE (an audit will be generated).

 

- Item Cross References: The item field must be the item defined in the item master. Any item cross references are not looked up by the interface. You can download a cross reference but it is not used.

 

 

Direct Interface Example (New Action)

The following is a sample listing of the database values (and the tables they should be on) that need to be present to directly download this type of data.

 

Download_Item: Interface Record ID, Interface Action Code, Item, Description, List Price, Conversion Quantity 1, Quantity UM 1, Weight 1, Weight UM 1, Conversion Quantity 2, Quantity UM 2, Weight 2, Weight UM 2

 

 

 

Item Touchpoint - Downloading Changes In Item Master Data

 

Functional Scenario

Suppose there has been a change to an item's master record in your ERP. You would then need to download this information, in order to reflect this change in the system's item master table. You can use the interface for this change so there is no need to manually update item master records in SCALE.

 

For example, suppose that one of your company's products changed characteristics (item color, dimensions, price, etc). You would then need to modify this product's item master record in SCALE. While this can be done manually via the Configurations Explorer, you can also download this modified item master data from your ERP.

 
Field Notes

- Numbered Field Values: The number designation after some of the item values (Weight 1, Quantity UM 1, etc) are there to identify the unit of measure definitions for this item (in lieu of creating an item unit of measure record in SCALE). For example, in the above example, each (1) and case (2) unit of measures are being defined for the item. The conversion quantity values determine how many units of an item is in a particular unit of measure (each=1, case=10). The system will take this data and create a record in the Item Unit of Measures Window for this item.

 

- For item master change actions, you only need to have the fields that you want to change present on the data map. The exception is if you want to make unit of measure changes, because you will need to identify on which unit of measure you want to make the change on (in the above example, each UM). The system will make the appropriate changes on the item records and/or item unit of measure records.

 

- Item Cross References: If you download a change and include an item cross reference that the system does not have, it will be added. However, item cross references are not used or looked up by the interface. Only the item defined in the item master is used by the system using an interface.

 

 

Direct Interface Example (Change Action)

The following is a sample listing of the database values (and the tables they should be on) that need to be present to directly download this type of data.

 

Download_Item: Interface Record ID, Interface Action Code, Item, List Price

 

 

 

 

Item Balance Touchpoint - Uploading Item Balance Data

 

Functional Scenario

You can upload item balance information from the system to your ERP. This allows you to reconcile the current item quantities in your warehouse with the ERP's item master table. This is helpful so your ERP has a current and accurate listing of the items in your warehouse and how many are available. In order to gather the item balance data, the system:

 

- Groups all location inventory records by warehouse, item, company, and inventory status.

 

- Excludes the records that are associated to a location classes that are not defined to be included in item balance uploads.

 

- Summarizes the quantity buckets across the remaining records in the group.

 

- Checks to see if the Include Zero On Hand Items flag is on. If so, then the system cycles through the item master and adds a record for each item/company that is not yet represented in the upload.

 

- Writes the information to the upload table.

 

 

Direct Interface Example

The following is a sample listing of the database values (and the tables they should be on) that need to be present to directly upload this type of data.

 

Upload_Item_Balance: Interface Record ID, Interface Action Code, Warehouse, Item, Item Description, On Hand Quantity, Inventory Status
