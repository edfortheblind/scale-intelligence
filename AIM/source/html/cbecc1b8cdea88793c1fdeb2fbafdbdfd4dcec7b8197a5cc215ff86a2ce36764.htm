Inventory Attributes Defined...

Inventory Attributes represent values that are assigned to inventory, typically when it is checked into the warehouse. These attributes fill the need to track specific information about warehouse inventory. Typically, this type of information would need to be captured during receipt check in, maintained in inventory, items allocated and picked based on these attributes, and then uploaded to your ERP system. Also, you can add/edit these attributes to inventory at select places in the system. Examples of inventory attributes include such values as Country of Origin, Region, or Product Owner. The system supports inventory attributes for both license plate and non-license plate tracked locations. All of the functional areas that support inventory attributes are listed in the System Support for Inventory Attributes section below.

 

All of the inventory attributes are stored in a separate database table called LOCATION_INVENTORY_ATTRIBUTES. The application supports twenty attribute fields, which are generically named Inventory Attribute 01, Inventory Attribute 02, etc. You can rename these attribute field names in the System Text Editor to reflect the specific attribute being captured, such as Country of Origin, Tax Seal, or Product Owner. Also pre-defined inventory attribute values can be created in the configurations that allow you to select from these values on certain processing screens. For this list of values to be displayed onscreen, they first need to be activated (per attribute) in the configurations.

Allocation Based On

One Attribute and

Attributes Combinations

 

 

 

 

 

Allocating attributes works similar to what it does for lot controlled shipment details without the lot ID. The system allocates based on each location inventory record at the location. If you request 15 EA and the location has 5 EA of attribute A, 5 EA of attribute B and 5 EA without attributes, then the system allocates all three regardless the attributes. You can filter location selection by inventory attribute values.

 

 

Picking Into a

Shipping Container

 

 

Picking into a shipping container is the only method of linking attributes to a shipping container. It does not matter if it is a full pallet (case) or loose container or whether the container was created in the wave or during picking. In all cases, the link is established during the RF pick/putaway process.

 

Override Pick From

a Different Location /

License Plate

 

Override pick is permitted from both full screen and RF, as long as the new pick location has the same attribute values as the original pick location.

 

 

Override Putaway

 

Override putaway is supported with attributes from both full screen and RF.

 

Manual Packing

 

 

 

Inventory attributes are not linked on the shipping dock inventory. This requires picking, regardless of loose or full quantity picking, to be picked into a shipping container from RF. Since the attributes are not linked to inventory on the shipping dock manual packing does not link attributes to the container.

 

Shipment Upload Interface

 

Attributes are uploaded with the shipping container in all interface modes.

Cycle Count: Creation

and Execution, Add

a New License Plate

With Attributes

 

 

 

 

 

 

 

 

 

 

 

 

 

 

 

 

Cycle count creation for attributes is handled in the same manner as it is for lots. The system creates a request for each unique set of attributes at the location.

 

Both full screen and RF work execution are available. However, there is no visibility to the attributes when confirming the work.

 

You can add an item (lot and license plate) with attributes from RF.

 

There is an exit point from RF inventory management that permits capture attributes (from a custom capture screen - see SDK).

 

The Cycle Count Request Insight screen has a column in the results view for attributes, and the Cycle Count Request screen has a checkbox indicating whether the request has attributes.

 

Cycle count reconciliation is permitted with attributes. As with work confirmation, there is no visibility to the attributes.

 

You can define location criteria for cycle count creation using attributes.

 

Replenishment With and

Without Attributes

 

 

 

Replenishment allocates from reserve locations in the same manner as shipment allocation. You can filter location selection by inventory attribute values. Note that if you want to perform replenishment based on inventory attributes that more advanced than SCALE currently offers, then you will need to customize this logic.

 

Replenishment Override

 

Replenishment override during picking and putaway is permitted in the same manner as is for inbound and outbound work.

 

View Inventory Attributes

 

 

 

Supported from the following screens: RF Location Inquiry, RF Inventory Management (when accessed from RF Location Inquiry), RF Cycle Count Work Execution, and RF Cycle Count Reconcile. Also supported is viewing during the RF Pick and Putaway of replenishment and inventory management work.

 

 

 

Transaction History

 

Area

 

Supported Inventory Attribute Functionality

 

Transaction History

Messages

 

 

 

 

 

 

 

Attributes are written for transactions involving the adjusting of inventory during check in, locating, allocating, inventory adjustment/transfer/status change, picking, putaway, etc. If the location inventory is linked to attributes, then the system writes the attributes as part of the history. Since attributes are not tracked in location inventory on the shipping dock, they are not written when delivering or moving containers on the dock.

 

Notes:

- The "Edit Inventory Attributes" action writes Inventory Attribute Change transaction history.

- The "Delete Inventory Attributes" action writes Inventory Attribute Delete transaction history.
