Activating Rejected Quantity...

 

You can move a portion (or all) of a shipment's quantity out of a "rejected" status and into a status between Picking Pending and Ship Confirm Pending. This action can be used to pack/ship a portion of a shipment that the system had previously rejected during the allocation process. For a shipment line to be eligible for this action, it must have quantity in the Rejected (999) status. Also, the leading status of the detail line must be less than or equal to the Ship Confirm Pending status.

 

When you activate a detail's rejected quantity, that inventory gets positively adjusted into the Packing location (or Put-To-Store location, if that is where the allocation request is for). It is important to note that this inventory doesnot get subtracted from any location, so you must manually find the location where this inventory was taken from, and perform a negative adjustment at that location.

 

Note that if the system rejects a detail quantity in the wave (or during a short pick) and the quantity gets written back to the pool, and then later you use the Activate Rejected Quantity action, the quantity is still in the pool and will likely get shipped again later. Also, if you end up canceling that shipment or detail after activating the quantity, that quantity is going to get written back to the pool again. Therefore, if you plan to use Activate Rejected Quantity in your process, it is highly recommended that you set the "Default Status When Shipment Is Rejected" setting (as well as the "Default Status Of Short Picked/Short Putaway Portion Of Shipment" status action) to "Complete Rejection to Pool" or "Delete Rejected." So, if you activate rejected quantity, there is not a duplicate quantity in the pool to be shipped.

 

Procedures
  1. Access a shipment line.

  2. Right-click a detail line and choose the Activate Rejected Qty action. The system will display the Activate Rejected Quantity Window.

  3. Confirm that the Line Number, Item, Company, and Item Description match the quantity that you want to activate.

  4. Review the item quantity that the system rejected during allocation in the Rejected Quantity Field.

  5. Enter the quantity whose status you want to change in the Quantity To Move Field.

  6. Choose the new status you want to associate with the item quantity.

  7. Press OK. The system will change the status of the shipment line quantity, and will adjust inventory into the packing location or put-to-store location.

 

 

 

Canceling Shipments...

You may need to cancel a shipment if you decide you do not want to ship a shipment at this time, but you do not want to lose the shipment in the system. When you cancel a shipment, the system sends the shipment back to the shipment pool. If containers exist for a shipment that was canceled, then the system deletes the allocated inventory from the location where the container exists. The inventory will still be on hand at the Shipping Dock location. If containers do not exist for a shipment that was canceled, then the system will subtract the allocated or in transit inventory (depending on whether it's been picked and put away or not) from the To Location on the shipment's allocation requests. Note that the system will only allow you to cancel a shipment if the shipment's leading status falls within Packing Pending and Ship Confirm Pending.

 

Procedures

  1. Access the Shipment Insight Screen.

     

  2. Access the shipment that you want to cancel, and select the Cancel shipment action.

     

  3. The system will display a confirmation window. Verify that you want to cancel this shipment.

     

  4. Press OK. The system will cancel the shipment.

 

 

 

Confirming Shipments...

After you confirm a shipment, the system cannot change the shipment's properties or lines. All shipments must be confirmed before physically leaving the warehouse. You cannot confirm shipments that have not been released from a wave. Also, you can have the system automatically confirm shipments (of a certain status) via a scheduled job. See the topic Creating a Scheduled Job for more details.

 

Leading Confirmation Status

Ideally, a shipment is only confirmed when all its lines are in the leading confirmation status. However, the system will allow you to confirm any line within the entire confirmation status range. If you do not want to confirm a line outside of the leading status, you can split the shipment. All lines in the leading status will remain on the original shipment, which is automatically shipped confirmed. All lines not in the leading status are moved to the new shipment, which will remain open.

 

Confirmation Status Range

A shipment can only be confirmed if its lines are within the confirm status range, which is defined on the Shipping Preferences Window. If one or more lines are outside of this range, the system will allow you to split the shipment. All lines ready for confirmation will remain on the original shipment, which is automatically shipped confirmed. All lines not ready for confirmation are moved to the new shipment, which will remain open. Also, you can choose not to confirm the shipment at all if any quantity is in a status less than Ready For Ship Confirm. The shipment will instead be transferred to an alternate load.

 

Split Shipments & Shipment ID Values

When a shipment is split, both shipments retain the same Shipment ID. This allows you to easily identify the shipment and associate it with the original order number. The system will assign a new Internal Shipment Number to the new shipment.

 

Procedures

  1. Access the Shipment Insight screen.

     

  2. Access the shipment record that you want to confirm. Select the Confirm action.

     

  3. How the system will proceed is based on the status of each detail line on the shipment.

     

    • If all lines are in the leading shipping status, the system will attempt to confirm the entire shipment.

    • If all lines are within the shipping status range, you can either attempt to confirm the entire shipment, split it, or move it to a different load. Exactly what the system will do depends on the split shipment setting on your shipping preferences record. You can configure your preferences to either display the split options for you to choose from, or to have the system perform the split action (after confirming with the user that this is ok.

    • If at least one line is not in the shipping status range, the system will let you split the shipment. You can confirm all lines within this range. The system will not allow you to confirm a line that is not in the shipping status range:

       

      If you decide to split the shipment, you can confirm all of the lines within the shipping status range or only those lines in the leading status range.

       

      a. If you decide to confirm all of the lines within the range, all of these lines will remain with the original shipment. The system will attempt to confirm this shipment. All lines below the range the system will be associated with a new shipment, which cannot be confirmed.

       

      b. If you decide to confirm only the lines in the leading shipping status, only those lines will remain with the original shipment. The system will attempt to confirm this shipment. All lines below the leading shipping status will be associated with a new shipment, which cannot be confirmed.

       

      If you decide to NOT split the shipment, the system will not confirm any of the lines. The entire shipment will remain open.
       

     

    Confirming the Shipment...
    After the lines are confirmed or split, the system will attempt to confirm the actual shipment. At this point, the system references the shipment information, such as postal code and carrier information. As long as this information is correct, the shipment is confirmed as its lines are already confirmed. If for some reason this information is incorrect (bad postal code, carrier does not deliver to postal code, etc), the system will not confirm the shipment. Instead, it will display a confirmation message indicating why the shipment failed confirmation.

     

    Upon ship confirmation, the system will remanifest any containers that are not manifested for today's date and not on a closed manifest. The system will either remanifest the containers for today's date (the true shipping date), or split them into another shipment (if chosen).

     

    Pending/Failed QC Inspection Note...
    If a container has pending or failed QC inspection associated with it at the time of ship confirmation, then the system will prompt the user indicating that they cannot confirm the container's shipment until the QC is performed/resolved.

    "ERROR" Container Note...
    If you attempt to confirm a shipment that has containers of an ERROR container type, then the system will move any of these ERROR containers (if they are in the appropriate status), to a new shipment (assuming that you have your shipping preferences configured to split shipments), and the ship confirmation action will succeed. However, if these ERROR containers are not in a status to be split, then they will stay on the shipment, and the ship confirmation action will fail.

     

  4. After the shipment is confirmed, the system will complete the following tasks, based on your system configurations:

      5.  

    • Assign a carrier.

       

    • Freeze the freight charges.

       

    • Transmit shipment information back to the ERP.

 

 

 

Consolidating Shipments...

You can manually consolidate shipments to minimize packaging costs.

 

Procedures

  1. Access the Shipment Insight screen.

     

  2. Access the shipment that you want to consolidate.

     

  3. Select the Consolidate action. The system will display the Shipment Consolidation screen. Information about the shipment that you want to consolidate is provided in the window's header. The system locks the shipment. This prohibits other workers from trying to consolidate the same shipment.

     

  4. The record list displays all possible consolidation opportunities. These shipments can be divided into two categories:

     

    • Shipments that meet all required and non-required criteria. This shipment is the perfect consolidation opportunity since it shares the same criteria values as the shipment that you want to consolidate.

       

    • Shipments that do not meet all the non-required criteria. All consolidation opportunities must meet the required criteria. However, shipments in this category do not share the same non-required criteria values as the shipment that you want to consolidate. These shipments are denoted with a caution icon to ensure that you recognize that consolidation can occur, but might not be appropriate. You will need to review the shipments in this category before consolidating.

     

  5. Determine which shipments in the record list should be consolidated with the header shipment. Select one of the shipments. To consolidate the shipment to the shipment you just selected, select the Consolidate. The system will consolidate the shipments.

     

  6. Any transferred containers that were manifest on the original shipment will be remanifested using this load's data. If necessary, you can re-route and re-rate both loads.

 

 

 

Deconsolidating Shipments...

 

You can deconsolidate the shipments to set aside canceled or held orders for further processing. The ERP order gets deconsolidated for a unique order and shipment.

 

Procedures

  1. Access the Shipment Line Insight screen.

     

  2. Find the shipment line for the ERP order that you want to deconsolidate.

     

  3. Select the Deconsolidate action for a shipment line with the ERP order that you want to deconsolidate. The system will request confirmation on whether you want to continue with deconsolidating the ERP order from the shipment.

    1. If you click Yes to continue, it will submit the ERP order for the shipment for deconsolidation. A message will be displayed indicating that the ERP order was successfully submitted for deconsolidation.

    2. If you click No, it will navigate back to the selected record.

     

Notes: The system will deconsolidate the ERP order for the unique order and shipment from the original (from) shipment. The unique order is based on the internal order number and internal shipment number of the selected ERP order. The deconsolidate process transfers all shipment lines and shipping containers to a new (to) shipment for the selected ERP order. The new shipment will have the same shipment ID as the shipment the ERP order was deconsolidated from. See process history for information on the status of the deconsolidated order.

 

 

 

Deleting Shipments...

Occasionally, you might need to delete a shipment that was canceled or entered incorrectly. You can delete any shipment as long as its status is greater than or equal to Picking Pending and less than Load Confirm Pending. Deleted shipments are completely removed from the system.

 

Notes:

  • If containers exist for a shipment that was deleted, then the system deletes the allocated inventory from the location where the container exists. The inventory will still be on hand at the shipping dock location.

  • If containers do not exist for a shipment that was deleted, then the system will subtract the allocated or in transit inventory (depending on whether it's been picked and put away or not) from the To Location on the shipment's allocation requests.

  • Each time you delete a details from a shipment, the system will create upload records for the shipment and the related detail that was deleted.

 

Procedures

  1. Access the Planned Shipment Insight screen or the Shipment Insight screen.

     

  2. Select the Delete shipment action.

     

  3. The system will display a confirmation window. Verify that you want to delete this shipment.

     

  4. Press OK. The system will delete the shipment.

 

 

 

Transferring Shipments

You can transfer any non-confirmed shipment(s) to a new load unless the load is closed. When you perform this action, the system will transfer all selected shipment(s) to the same load. See Creating/Processing a Shipping Load

 

 

 

 

Editing Shipping Containers...

You may need to edit a shipping container's information if changes have occurred since the container was created.

  1. Open the Planned Shipment Insight screen or the Shipping Container Insight screen.

  2. Access the shipping container you want to edit.

  3. Select the Edit action.

  4. Change the values of the field(s) you wish to edit.

  5. The available container types shown can be authorized based on a shipment header's company and warehouse. See the Defining Container Types for more details.

  6. Press the Save button. The system will save your changes.

 

 

 

Deleting Shipping Containers...

You may need to delete a shipping container to accommodate a customer's request. The system will allow you to delete a container as long as the container's status is greater than or equal to Picking Pending and less than Load Confirm Pending.

 

Procedures
  1. Access the Shipping Container Insight screen.

  2. Access the shipping container that you want to delete, and select the Delete action.

  3. The system will display a confirmation window. Verify that you want to delete this container.

  4. Press OK. The system will delete the container.

 

 

 

Container X of Y Values...

When manually adding , deleting , removing from nesting, nesting, or combining containers, the system will recalculate the X of Y values on the parent shipping containers. However, the system will not do this for the X of Y values on the child containers (they are set to a "0 of 0" value). Only the "Pallet UM Conversion" wave step will recalculate both the parent AND child container X of Y values.

 

 

 

 

Transferring Shipping Containers...

You may need to transfer a container to a new shipment. The system will allow you to transfer a container until the shipment is confirmed. If the new shipment is associated with a different carrier and/or service, the system will remove any accessorials that applied to the first carrier/service, but not to the new one.

 

Procedures

  1. Access the Shipping Container Insight screen.

     

  2. Access the container that you want to transfer to a new shipment.

     

  3. Select the Transfer action, and the system will display the Transfer Container screen.

     

  4. Identify the destination shipment to identify the shipment that you want to transfer the container to. Press the Transfer button.

  5. Does the system display a message indicating that this shipment has different destination information than the original shipment?

     

    • If Yes, decide if you want to send this container to a different destination. To continue, select Ok and continue to Step 6. To stop the transfer, select Cancel.

       

    • If No, press OK. Continue to Step 6.

     

  6. The system will transfer the container. If the container was manifested on its original shipment, the system will remanifest it using this shipment's data. If necessary, you can re-route and re-rate both shipments.

 

 

 

UPS Returns Processing...

The system supports UPS return service accessorials for the following services: UPS Ground, UPS 2nd Day Air, UPS 3rd Day Select and UPS Next Day Air:

  • Print Return Label Accessorial: This produces a "returns" shipping label (which is printed with at the same time as the regular shipping label) that you will include in the shipping container. The customer then would affix this return label onto the package if they want to send the product back to the warehouse.

  • Electronic Return Label Accessorial: This does not include a physical label; instead, UPS sends an email copy of the return label to the end customer. If the customer does not want to keep the product, they can print out the emailed return label, affix it to the package, and ship it back to the warehouse. Note that for this accessorial, you must provide the return delivery address email.

 

When a container is manifested with the UPS Return accessorial applied, the system will retrieve a tracking number and an MSN for the return package.

  • Returns Tracking Number Field: This field is a unique identifier assigned to a parcel when is manifested.

  • Returns MSN (Master Sequence Number) Field: This field is an internal identifier assigned to a shipping container by Progistics. It is assigned at the same time as the returns tracking number. Progistics uses it to search for containers in its system.

  • Returns Shipping/Accessorial Charge Field: This value represents how much UPS will charge to ship the returned package back to the warehouse, plus the accessorial charge it levies for the return label.
