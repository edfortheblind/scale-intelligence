Defining Work Special Handling Constraints

A special handling constraint record defines processing validations or restrictions required for a specific group of work instructions. You can use them to increase security for expensive product, support a customer account's requests, provide guidelines for new employees, and minimize errors occurring in specific warehouse zones. Note that these special handling constraints are only reflected in RF work processing, not in the full-screen Work Insight Screen.

Using the General Tab

You will use this tab to identify when the system will require special handling.

  1. To require special handling when a particular item is processed, identify that item in the Item Field. If a company is associated with that item, the system will automatically default it in the Company Field.

     

  2. To require special handling when product is processed for a particular account, identify that account in the Account Field.

     

    NOTE: If you are defining this record for inbound receipts, the account field identifies the vendor supplying the product. If you are defining this record for outbound receipts, the account field identifies the customer ordering the product.

     

  3. To require special handling to meet warehouse requirements or special conditions, use the Work Fields. You can use any combination of the following fields: User Name, Work Type, Work Zone. Work level validation allows you to provide additional guidelines for new or inexperienced personnel.
 
Using the Key Values Tab

You will use this tab to identify what special handling the system will require. You can use any combination of these fields. If you define multiple values here, the system will require that employee commit all validations.

  1. Use the Shipping Container Verification Field to verify shipping container IDs during picking:

    - None: The system will show the container ID in display mode (no additional user verification needed). Note that if the user partial picks the quantity, they will have to scan the container ID for the next instruction.

    - Container Verify: The system will require the user to correctly verify (by entering or scanning the ID) the shipping container that is being picked into.

    - Container Spot Verify: The system will require the user to correctly identify the shipping container's spot on the picking cart. Note that this setting is only valid when using group user picking (otherwise the system ignores it).

    - Allow Override: The system will default the container ID in the field, and the user can change this value if desired. The system then would validate this new ID to make sure that it does not already exist.

    For more information on this setting, see the field topic.

  2. Use the Maximum Pickup Quantity to define the maximum number of units that can be picked at one time. When the employee is picking the product, the system will require him/her to only pick the amount displayed here. If the work instruction requires more than the value defined here, the system will ask the user to pick this amount as many times as required to fulfill the work instruction. This constraint increases the likelihood that the employee will count the product.

  3. Use the Allow Splitting Of Container Checkbox to define whether or not you will be allowed to split off and pick a portion of the quantity into another container. To accommodate this action, the system will create a new work unit and container for the split quantity. This is helpful if the container that you are picking into gets full before you are done picking the current quantity. Typically this situation would occur if you created containers in the wave, and the current pick physically will not completely fit into the container that the system created for it.

  4. Use the Allow Over Picking Checkbox to allow the user to pick more quantity than exists on a work instruction, as long as this quantity is within the location's available quantity. When an over pick is performed, the system will increment the transaction quantity, and process the pick as a complete/normal pick. This option is only available for RF replenishment and work order picking. For example, suppose a work order component work instruction calls for 980 eaches of an item. It may be easier physically, then, for the worker to pick two cases of 500 (for a total of 1,000 eaches) rather than breaking one case open and leaving 20 eaches loose at the location. If this checkbox is checked, the system will increment the instruction by 20 eaches, and process the pick as normal.

  5. Use the Allow Pick in Transit Checkbox to allow the user to pick in transit quantities. If there is not enough quantity in the location to be picked but there is additional inventory that is 'on the way', this allows the user to pick from what is coming or 'in transit'. If the inventory is picked against what's in transit, the inventory will show a negative quantity.

  6. Use the Close After Partial Pick Checkbox to allow the user to partial pick the quantity of a work instruction, and the system will delete the remaining quantity from the work instruction. The system will then close the work instruction. Therefore, the remaining quantity will never actually be picked. This option is only available for RF replenishment and work order picks. For example, suppose you have a replenishment request that calls for 620 eaches of an item. The user, however, may only want to pick 600 eaches of the item (because that is a more round number in regards to how things are packed), so they just want the other 20 eaches to “go away.” If this checkbox is checked, the system would delete the remaining 20 eaches from the work instruction (after the user picks the 600), and close the work instruction.

  7. Use the Replenish On Outbound Short Pick Checkbox to indicate that when the user short picks an item quantity at a location, the system will attempt to run replenishment (based on the location's item demand resulting from the short pick). If there is enough In transit quantity that is on its way to the location for this item, then the system will display to the user a message asking whether or not they want to continue with the short pick. For more detailed information about this replenishment process, see the process diagram on the Replenishment Process Summary topic.

  8. Use the Use Converted Quantity Checkbox for users who do not pick in the base UM and pick in either cases or pallets. If the user is not picking any item in eaches and always picks in an UM which is not the base UM, then the picks should also happen with the converted quantity (CS, PL etc.). For example, if 1 CS= 10 EA and a user picks 2 CS, the converted quantity is 20 EA.

     

    So the system uses the converted quantity as the main pick quantity value and the base value as the secondary read-only values when the pick quantity is a multiple of the converted quantity. If the pick quantity is not a multiple of the converted quantity, the system uses base quantity UM as the pick quantity. Also, the system updates work, inventory, shipment, and transaction history correctly based on converted UM quantity picks.

     

    NOTE: User cannot enter a decimal quantity for the converted quantity to a partial/short pick.

     

  9. Use the Item Verify Checkbox to require that the user verify what item is processed. Employees can verify an item by either scanning or manually entering its barcode. The system will accept the item number or any value associated with it on the Item Cross Reference Window, such as a UPC number.

    NOTE: The system only applies item verification during RF device processing; it is not applied to work processed on the Work Insight Screen.
     
  10. Use the Quantity Verify Checkbox to require the user to identify how many item units he/she is processing. For example, if this checkbox is selected, the system will display a blank quantity field, and the user will have to actually enter the quantity, thereby "verifying" it. If this checkbox is not selected, the system will default the quantity value in the field, and the user will not have to manually enter a value.
     
  11. Use the License Plate Verify Checkbox to require the user to identify the ID of the license plate that he/she is picking from. If this is not checked, the License Plate Field on the RF Pick Confirmation screen will be read-only. If it is checked, the system will display the correct ID, and the user will need to scan the license plate to verify the value.

  12. Use the Lot Verify Checkbox to require the user to identify the lot ID associated with the item quantity that he/she is picking. If this is not checked, the Lot Field on the RF Pick Confirmation screen will be read-only. If it is checked, the system will display the correct ID, and the user will need to scan the lot to verify the value.
     
  13. Use the License Plate Putaway Verify Method Buttons to determine how the system will require you to enter license plate IDs during putaway:

    - If Use Existing License Plate (No Override Allowed), the system will show the existing license plate ID in display mode, and not allow you to enter a new value.

    - If Verify Existing License Plate, the system will require you to enter the existing license plate ID for confirmation. An error will occur if you enter a new value.

    - If Existing License Plate (Allow Override), the system will show the existing license plate, and you can either use the existing license plate or enter a new value.

    - If User Specified, the system will not show the existing license plate. Therefore, you will have to enter a new value.

  14. Use the Override Pick Checkboxes to determine what value(s) that a user can change during RF pick confirmation. Note that this setting does not apply to work done in the full-screen Work Insight Screen. You can enable the user to override any/all of the following values: Location, Lot, License Plate. See this topic for rules that the system enforces for override picks.

    - Prompt On LP/Location/Lot Override Checkbox: When this setting is active, the system will display an alert message when you attempt to override one of the pick values described above.

  15. Use the Prompt for Quantity to perform Inline Partial Pick for Container Creation During Pick. The system will prompt with quantity field to enter the partial quantity.
 
Using the Cycle Count Tab 

You will use this tab to configure work special handling constraints related to cycle counting.

 

Note on Adding Items During Cycle Counting: The system can provide the opportunity for you to add an item to a location when performing an RF cycle count. In order to activate this option, you must configure the user's "Add New Inventory" security setting in the RF Cycle Count security form (this setting is active by default). Also note that this add item functionality only applies when performing RF cycle counting (not during full-screen cycle counting).

  1. Use the License Plate Selection Method Buttons to indicate how you want to initiate license plate cycle counts:

    - System Initiated: This indicates that the system will tell the user the order of the license plates that they are required to cycle count.

    - User Initiated: This indicates that the user will be able to specify which license plate that they want to count.

  2. Use the Count Level Field to indicate what entity the user will count at a location:

    - Standard Count: The user will count the individual cycle count(s) present for the location.

    - Blind Count: As in a standard count, the user will count the individual cycle count(s) present for the location. However, the system does not present any information on screen *except* for the location ID. Therefore, the user is forced to count each item that is physically present in the location without the system guiding them in what should be counted.

    - Count License Plates: The user will count the number of license plate(s) that are currently present at a location. For example, suppose a certain product is housed in a second story location. Since users would not be able to easily access and count the quantity contained in these license plates, you could configure counts for this product to ask for the number of license plates present at the location, rather than a count of the actual quantity. Note that if a license plate count differs from what the system expected, the system will require the user to count the actual quantity contained per license plate and license plate count is allowed for multi locations. Also note that multi-item locations always force the user to count individual quantities (even if you have this setting selected on your work special handling).

    - Group Count By Item/Company: The user will count all of the quantity at a given location for the same item/company (regardless of the lot ID, inventory attribute, and/or license plate values):

    * If the user's total-quantity count does not meet the system's total-quantity count, the system will ungroup the cycle count work and display an error message.

    * If you are cycle counting multiple items at the same location OR an empty location, then you will have to confirm the counts individually (even if this setting is enabled).

    * If you choose to add an item when confirming a grouped count, the system will ungroup the cycle count work and you will need to confirm each count individually. Note that after you add an item, the system will give you the option to continue with the add item action, or to return to the group count.

    * If this setting is enabled AND lot/license plate verification is enabled, the system will ungroup the cycle count work and you will need to confirm each count individually.

    * The system logs group count labor activity as individual cycle counts.

  3. Use the Add License Plates During Cycle Count Checkbox to allow (when enabled) you to identify a new license plate to the system when performing a cycle count for a location.

    Important: If you want to confirm less license plates than the system thinks exist in the location, then this checkbox will expose the Done button on RF so that you are not forced to count all of the license plates in order to complete the cycle count work.

    Notes
    - This setting is only available when you are using a License Plate Selection Method of user initiated.

    - When the user attempts to add a new license plate, the system will reference the user's cycle count preferences:

    * If the license plate falls within the user's positive tolerance, then the system will add to the location the new license plate/item quantity.

    * If the license plate falls above the user's positive tolerance, then the system will set the count of this location to pending review.

    - You can have the system set all counts that involve new license plates to a pending review status using the Set New License Plates To Pending Review Checkbox.

    - The system will ignore this setting if you have the ability to add items during a count. Since you are always allowed to add license plates when adding an item to a location's count, this setting is not recognized.

  4. Use the Set New License Plates To Pending Review Checkbox to indicate that you want the system to place in a pending review status all cycle counts that involve new license plates created by the user (while executing counts). A warehouse supervisor then will have to review the count before it is made official in the system. This option is only available when you are using a License Plate Selection Method of user initiated.

    NOTE: The system will ignore this setting if you have the ability to add items during a count. Since any new additions during counts is automatically put into a pending review status, this setting is not recognized.
