Defining Billing Management Triggers

Each functional point in the system that can potentially send information to Billing Management is called a trigger. These triggers are made up of a header record and multiple detail record(s). You can use header records to activate or deactivate each trigger. All Billing Management triggers are setup to be deactivated by default. Additionally, each trigger record will contain control information for how the trigger operates, such as whether the trigger is automatically activated (in-line) or manually activated. Each trigger will also be associated with an XML schema (called a system Template). This tells the system which XML template document to use with this trigger. Click here for a complete list of Billing Management triggers in the system. The system-supplied records should be sufficient for your business needs. You cannot change the "trigger type" of these default records. Ask your system consultant if you believe you need to make changes to this configuration.

 

Trigger Details

Each trigger header record contains one or several detail-level records. These records determine what information the trigger will send to Billing Management. They correspond to a different data element in the XML schema. The sequence of these detail records should match the ordering of the elements of the system template. The system provides default detail records that should meet your business needs; however, you can modify these to your specifications. For example, the XML schema for “receipt container” accepts header data, detail data, and container data, so each one of these will need to be a different detail record of the header. This detail level allows the user to control the actual mapping of which fields in the system go to which fields in Billing Management.

Creating a Trigger Header...

  1. Use the Key Field to view the identification number of this record.

  2. The Event ID Field corresponds to Billing Management's MsgId field.

  3. Use the Activity Type Field to provide a description for the activity type of this Billing Management trigger header record. This value corresponds to Billing Management's ActivityType field.

  4. Use the Activity Code Field to provide a description for the activity code of this Billing Management trigger header record. This text description can be any value you choose, as long as it corresponds to this value in Billing Management. This value corresponds to Billing Management's Activity Code field.

  5. Use the SCALE Template Field to indicate the XML schema that you want this trigger to use. Each trigger is tied to an XML schema (called a system Template). The system Template values represent a list of the available schemas that the user can choose from to use for their mapping. This document is the schema that is translated to a pure XML formatted document, and modified to work with the system. After the user chooses a template, it will be used when defining records in the Billing Management Trigger Detail Map screen. The system uses this template to grab each of the attributes from that template and place them in the Billing Management list. It uses Resource Keys to translate the text, but if a key does not exist it will use the original text from the system Template file.

  6. Use the Trigger Type Field to indicate how this trigger will be activated.

    - If you choose In-Line, the trigger will activate automatically when an event (such as closing a shipping load) occurs in the system. In-line triggers include events that are embedded in the system functional flow, such as Packing or Receiving. To use this type of trigger, you first have to activate it, and then when a particular event happens, the system will send the data resulting from the trigger to Billing Management. No further user intervention is required.

    - If you choose Manual, the user will have to manually activate a trigger via the Billing Management Manual Generation Window. Manual triggers include any events that are unrelated to a functional event, such as the storage snapshot trigger. To use this type of trigger, you would access the Billing Management Manual Generation Window and select the appropriate trigger. The system will then send the data resulting from the trigger to the defined output directory.

 

 

Creating a Trigger Detail...

 

Open an existing trigger header record or create a new one. Access the Details Tab, and open an existing record, or create a new one.

 

Using the Header Fields
  1. Use the Header Key Field to view the header record identification number of this query in Billing Management. This value for the detail is the same as the "Key" value for its corresponding header. It is what associates the detail records with the header record. This helps give the header and detail records a "parent/child" relationship.
Using the General Tab
  1. Use the Sequence Field to indicate the order of processing for this detail record.

  2. Use the Element Mapping Fields to associate an action in the system with a corresponding element in Billing Management. You can use this field to load the proper "attributes" from the system Template into the Billing Management list on the Billing Management Trigger Detail Map Window. Each XML statement is split up into "elements" and "attributes." Each trigger header has a corresponding trigger detail for each of its available elements that you can send to Billing Management.

  3. Use the Parent Element Field to indicate the parent XML element for this detail record. XML has a hierarchy and elements can be children of other elements. This field is necessary so that the trigger details that are sent to Billing Management are in the proper order. When the trigger occurs, the XML that is sent to Billing Management is created in the hierarchy given by the details. This hierarchy matches the system Template. The lowest sequence Billing Management Trigger Detail record must have a null parent. Note that when you are choosing a parent element on the trigger detail record, the system does not display a warning if the user picks an element that isn't truly a parent to the detail that you are defining. You should review the system template to make sure you are selecting the actual parent.

  4. Use the Detail Map Style Sheet Field to identify the style sheet that has been associated with this element. If a value does not appear in this field, the system will open the Billing Management Trigger Detail Map Window upon exiting this window.

  5. Press OK. The system will save your record.
