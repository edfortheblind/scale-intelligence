Configuring DIF Endpoints

To setup the SCALE Device Integration Framework (DIF), you will need to address some configuration values in the application's database. The second step in this process is to configure a DIF endpoint. An endpoint represents the connection that an MHE and SCALE use to communicate actions (events) via DIF. Note that there is no configuration screen to define endpoints in the SCALE Configurations Explorer. You will need to configure these values directly in the application database's DIF_ENDPOINT table.

 

Note: In order for changes to the DIF_ENDPOINT table to be reflected, you will need restart the DIF Processing Service.

 

See the SDK for detailed/additional information about DIF.

Procedures...

  1. Access your application database using a database editing tool such as SQL Server Management Studio.

  2. Access the DIF_ENDPOINT database table. Note that each database row represents the configuration record for a separate DIF endpoint.

  3. Define values for the following database fields:

    DESCRIPTION (alpha-numeric 25): Represents a short description of the endpoint.

    ENDPOINT_ID (numeric 9,0): Represents a unique identifier for an endpoint. This field is required.

    ENDPOINT_HANDLER (alpha-numeric 50): Represents the identifier passed into Spring.NET used to create an instance of the logic handling the protocol communication for the endpoint. The three endpoint handlers provided with the system are: IncomingTCPServerEndpointHandler, OutgoingTCPClientEndpointHandler, and IncomingTCPClientEndpointHandler

    EVENT_ID (numeric 9,0): Represents the event tied to this endpoint. This field is required.

    NAME (alpha-numeric 25): Represents the name of the endpoint.

    USER_DEF1 - USER_DEF6 (alpha-numeric 25): Represents user identified values, similar to other places in the system.

    USER_DEF7 - USER_DEF8 (numeric 14,5): Represents user identified values, similar to other places in the system.

    DIRECTION (numeric 9,0): Represents the direction of the endpoint (0 for incoming, 1 for outgoing)

  4. When finished entering values, commit the changes to the database and exit your database editing tool.
