Device Integration Framework Process Summary

** Functionality **

Process Flows

 

 

Summary...

Larger warehouses often implement additional automation software with material handling equipment (MHE) to help handle the high volume of production. Some examples of this are executing picks using a pick to light system, or a conveyor system which closes containers when packing is complete. The information captured from these MHEs then needs to be sent to SCALE for processing. Also, the MHEs may need to receive information back from SCALE to complete this functionality. The Device Integration Framework (DIF) component serves as a communicator between SCALE and the MHE. The Device Integration Framework (DIF) is made up of a set of services designed for the simple and efficient integration of SCALE with outside systems and devices in order to fulfill the demands of a supply chain.

 

The file transfer feature is a new way of handling the data received from the MHE into the SCALE DIF Incoming Message table via files. It handles files, in multiple formats (xml, delimited, fixed, etc.), sent from an MHE, and picks and puts them into the incoming message table. The table and the files are then processed by the existing functionality or feature.

 

The setup will have designated folders into which the MHE files are placed and these files are picked and processed based on the different extensions used for them. After processing, the user can configure the file to have the 'To Ext' extension updated (marked as processed), move the file to another folder (To directory), and insert a record in the DIF Incoming message table (Insert message set to Y). If a message is placed in the DIF Incoming Message table, the system will pick up the record and process it like in the past utilizing the existing framework.

DIF Concepts...

The following are definitions to important DIF terms and concepts:

DIF Event: An event represents an action that occurs in material handling equipment (MHE) or SCALE that needs to be communicated via DIF. An example of this action could be the SCALE close container process.

 

DIF Endpoint: An endpoint represents the connection that an MHE and SCALE use to communicate actions (events) via DIF.

 

DIF TCP Properties: A protocol property record containing the specific TCP data that is used to define the properties of a DIF endpoint.

 

ACK: A positive acknowledgment sent for an incoming or outgoing message.

 

NAK: A negative acknowledgment sent for an incoming or outgoing message.

 

Heartbeat: A heartbeat is the mechanism that the application (MHE or SCALE) uses to verify that a connection is still active, without having to depend on TCP to determine this.

 

Keep Alive: A keep alive is what the TCP protocol uses internally to determine whether or not a connection is still active. This is inbuilt into the protocol itself. This differs from a heartbeat, which is at the application level.

 

Incoming Message: An incoming message represents data sent (via DIF) from an MHE to SCALE.

 

Outgoing Message: An outgoing message represents data sent (via DIF) from SCALE to an MHE.

 

DIF Communication Service: This service handles the movement of incoming/outgoing messages sent to/from DIF.

 

DIF Message Processing Service: The DIF Message Processing service reads messages and sends them to appropriate API (created by the customer). It then waits for a success or failure indication from the API, and updates the record accordingly. It features the ability to configure multi-threading processing, and can handle multiple endpoints simultaneously.

 

Custom API (Application Program Interface): A custom API is .NET logic that modifies the messages sent by the MHE before the message is by processed by SCALE.

From Directory: Directory into which the records are placed in to be processed.

From Ext: File extensions that the records must have to be eligible for processing.

To Directory: Directory into which the records will be placed after processing.

To Ext: Extension the records are marked as after processing.

Insert Message: Determines if a message should be inserted into the incoming DIF Message table. Supported values are Y or N. If Y, the message will be inserted. If N, the message will not be inserted.

Sleep Time: Duration of time between the checking of new records by the system.

DIF Functionality...

- The DIF framework consists of two services. One service is a “communication” service that handles the capturing and sending of messages between SCALE and the MHE. The other service is a “message processing” service that processes messages by sending them to the proper custom API code, which then parses the data and passes the information to the appropriate SCALE logic (incoming messages) or MHE (outgoing messages).

- Supports out-of-the-box integration with MHE’s using the TCP/IP protocol.

- DIF has the ability to receive a positive (ACK) or negative (NAK) acknowledgment message and automatically resend messages if an ACK/NAK is not received. You can also configure the number of times a message is resent.

- You can integrate DIF with multiple MHEs at the same time.

- DIF can handle incoming or outgoing heartbeat messages. Also, DIF will write SCALE history records when an endpoint is shut down, if the MHE does not send back an ACK (if configured) after a heartbeat is sent.

- You can also configure "keep alives" for the connection at the TCP socket level.

- You can archive incoming and outgoing messages.

- You can perform debugging.

- There are insight screens in SCALE for both incoming and outgoing messages, including the ability to manually reset error records.

- DIF features TCP/IP socket communication, i.e. the ability to connect and be “server” or listen and be “client."

- DIF has the ability to process different message formats, such as delimited, fixed length, and XML.

- You can configure different start/end characters for messages. The standards for TCP/IP are ASCII 02 and ASCII 03, but others can be used.

- DIF also features configurable multi-threaded processing of messages, for scalability and performance.

- Supports TCP/IP and File transfer

- File transfer is only supported for incoming DIF processing.

- Multiple MHE, folder, file format, and processing are all supported for file transfer processing.

 

- MHE has the ability to insert incoming message tables (records) into DB using the web API’s.
