RF Immediate Dock Transfers (Without Work)

Typically, in a warehouse, you will either use work to facilitate the movement of containers into and through your shipping dock, or you will choose not to use work. The purpose of the RF Immediate Dock Transfer screen is to allow you to perform container transfer movements without using RF work execution. Instead, you need to scan the container ID, move the container to its new location on the dock, and then scan the destination location ID. If the transfer passes validations, the system will then move the inventory on hand from its original location to the destination location. The status on the container and its associated shipment line(s) are updated without creating work.

 

IMPORTANT: You can only use this dock transfer option if there is no work associated with the container you want to move. If the container has work created for it, then the system will not allow the transfer, and you will need to perform work execution to move the container.

 

NOTE: This function not only enables you to move containers to the dock door, but you can also use it to move containers from any dock location to another dock location.

Note About Transferring Multiple Order Pallets...

If you are transferring a multiple order pallet, the transfer will process just as it would with any shipping container. However, the Customer Name and Ship To informational field values will be represented with the term "Multiple" and the actual number of customer/ship to values are enclosed in parenthesis.

 

 

Performing an Immediate Dock Transfer...

  1. Log onto an RF Device.

  2. Select the Immediate Dock Transfer option from the RF Main Selection screen. The system will display the Immediate Dock Transfer screen.

    3.  

  3. Scan the ID of the "top-level" (parent) container that you want to transfer to the shipping dock door.

    The following needs to be true of the container:

    - The container must currently exist in the system.

    - The container must be a "top-level" (parent) container.

    - The container or its children cannot be associated with open or in process work instructions.

    4.  

    NOTE: This RF screen does not support special characters as follows: , / ? : @ & = < + $ #


  4. Physically move the container to its destination location. Note if the container is associated with a load (and that load is assigned a dock door), the system will default the dock door location into this field.

  5. Scan the destination location.

    The following needs to be true of the destination location:

    - The destination location cannot be frozen.

    - The destination location needs to have a location class of Shipping Dock.

    - There needs to be a dock management flow detail record for the location subclass of the destination location.

    - If the destination location is a dock door location, then no other load can be assigned to that dock door.

    - The load that the shipment is assigned to must either be assigned to that dock door or no dock door.

  6. Press the Transfer Button. If the transfer is successful, then the system will display a success message at the bottom of the screen.

    - If the container's shipment is not assigned to a load, then the system will create a shipping load and assign it to the appropriate dock door.

    - If the container's shipping load was not previously assigned to a dock door, the system will assign the appropriate dock door to the container's load.

    - If the carrier on the container's shipment matches the load at the door (but the shipment is not assigned to that load), the system will add the shipment to that load.

    - The system will not allow the transfer if the container's shipment is unassigned to a load and does not have a carrier.

    - If, during the execution of a transfer, the system creates work for this container, and you then press the Transfer Button to close the transaction, the system will not allow the transfer to complete.

  7. You can then perform another dock transfer (go back to step 3 above), or exit the screen.

 

Tip: One or more shipping containers (but not all) on a Multiple Order Pallet fails to transfer to the "to" location...

 

The multiple order pallet will have one or more containers at the "to" location and one or more containers at the "from" location.

  1. Review Process History for Dock Transfer failure records for the multiple order pallet. The multiple order pallet ID found in the Identifier 3 field of the history record.

  2. Investigate and resolve the problem.

  3. Transfer the multiple order pallet to a location (Staging) other than the current locations on the shipping containers. There should be only two different locations on the multiple order pallet containers. If the problem was resolved, then all the containers on the multiple order pallet will be transferred to the "to" location. This gets all the shipping containers back to the same "from" location.

  4. Transfer the multiple order pallet to the original "to" location.
