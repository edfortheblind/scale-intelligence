Defining Interface Process Records

*** Interface process records are required for all interface modes. ***

 

Each functional area has its own process settings for the interface, which determines how its data can be downloaded and/or uploaded between SCALE and the ERP. You may need to address these settings when configuring the SCALE interface to work with your ERP's data. The following topic outlines how you can review/edit these process records to meet your business needs. When you open a functional area record in the Interface Process Window, the system will display a series of detail records in a list. These detail records indicate the different processes that have been defined for this particular functional area. The sequence of these records determine in what order the system will execute them. You can create/edit/delete process detail records according to your business needs.

 

Active Scale users note:

  • The override data configuration is available for Lower and Production level users only.
  • Lower level users
    • All editable fields will be enabled
    • Can Create, Delete, Copy interface process records
  • Production level users
    • Can view all editable fields. No permission for editing
    • Can select and copy text values
    • Cannot Create, Delete, Copy interface process records.

 

Exit Point Parameters Note

Regarding the exit point that you can add as a process flow step on the Flow Control Tab of this window, the following basic parameters (from the interface process detail record) are passed every time the exit point is fired:

  • Parameter 01: Session Value

  • Parameter 02: Internal Detail Number

Procedures (Header Window)...

Access the Interface Process Window. Open the functional area record for which you want to review. The system will display a list of the current process detail(s). Right-click on the list and select Open. Note that Work Order and Bill of Material interface records are only available in XML mode.

 

Using the Header Fields
  1. Use the Sequence Field to indicate in what order you want the system to execute this interface process. For example, suppose you assign a sequence of "10" to a delimited download process record, and "20" to a direct download process record. When you run the interface, the system will first look to download any delimited files that are present in the specified directory. If it finds some, it will interface them into the application. If it finds none (or when it is finished), the system will try to perform a direct download of the data.
     
  2. Use the Description Field to provide a text description for your process detail record.

 

Procedures (Detail Window)...

 

Using the General Tab
  1. Use the Interface Mode Field to indicate what method this process will interface data into the application: by using a delimited text file (fixed length or not), directly from the interface tables, or via XML files. See the Interface Overview topic for detailed mode descriptions.
     
  2. Use the Max Trans Per XML File Field to indicate the maximum number of data entities (header-detail-container combinations) that the interface will convert into XML at a time.

    Take, for example, a shipping delimited download. Suppose this value is set at 200 and there are 600 entities ready to be processed. The interface will convert 200 of these entities to XML and place them into the appropriate SCALE database table. The system then will go out and retrieve the next 200 records and repeat the process, until all eligible data has been converted.
     
  3. Use the Data Source Batch Size Field to indicate the maximum number of interface data sources (files, or rows in a database table) that the interface will retrieve at a time.

    Delimited Mode...
    Take, for example, a shipping delimited download. Suppose this value is set at 100, and there are 500 delimited files ready to be processed. The interface will retrieve the first 100 files (no matter how much data is contained in each file), and begin processing them. Next, the system then will go out and grab the next 100 files, repeating the process until all eligible files have been processed.

    Regarding record processing order, the system will process them first according to logical priority (i.e. shipments then shipment lines, receipts then receipt lines, etc.), and within those tables it processes by Interface Record ID. For example (Interface Record ID in parenthesis):

    (1) Receipt Detail A1
    (2) Receipt Header B
    (3) Receipt Detail A3
    (4) Receipt Detail A2
    (5) Receipt Detail B1
    (6) Receipt Header A

    The system will process these records in this order:
    Receipt Header B
    Receipt Header A
    Receipt Detail A1
    Receipt Detail A3
    Receipt Detail A2
    Receipt Detail B1

    Direct Mode...
    For direct downloads, the interface will act as described above, except that it would grab the first 100 data rows from the database table, and process them. When direct downloading items, receipts, or orders, the system will process each batch's rows according to their interface record ID value.
     
  4. Use the Upload Criteria Field to filter the records to be uploaded for the upload process detail. Refer Upload Criteria Field for more details.

  5. Use the Upload Delete Criteria Field (shipment upload only) to indicate the filter criteria record that the system will use to determine for which shipments the system will write header/detail upload records when a shipment is deleted.

  6. Use the Upload Directory Field to define the directory where the system will place interface upload data files. This can allow you to configure uploads going to multiple directories (by creating multiple interface process records, each defined with a different upload filter criteria and upload directory).

  7. Use the Process Field to determine if this interface process will download data from your ERP to SCALE, or upload system data to your ERP.
     
  8. Use the XML Encoding Field to indicate the type of text encoding that you want the system to use when interfacing data files. If you are reading/writing a file (in delimited, fixed length, or XML mode), this field defines the format of the file itself. Note that interface error files also honor this encoding setting.
     
  9. Use the File Extension Field to indicate to the system what files this process should be looking for when interfacing delimited/XML data. These delimited/XML files reside in the directory that is defined in the Interface System Values Window.
     
  10. Use the Error File Extension Field to indicate the extension that the system should place on the error files it automatically generates if a problem occurs when interfacing data.
     
  11. Use the Processed File Extension Field to indicate the extension that the system will add to files that have been processed by the interface.
     
  12. Use the Save Processed Data Checkbox if you want the system to not delete interfaced data:

    - In Direct Mode: The system will leave the data in the database, and label it as processed.

    - In File-Based Modes: The system will add a user-defined file extension to processed data files. The system will not delete these files from their output directory.

  13. Press OK. The system will save your record (if you made changes), and return you to the process detail list.

 

Using the Flow Control Tab

 

- Use the Interface Process Steps section to define what actions you want the system to execute before and/or after the interface is run (such as performing XML data translation or running exit point programs).

          * Interface Process Detail Field  provides a name for this process step.

          * Sequence Field  indicates in what order the system will execute this process step.

          * Timing Field indicates if you want this process step to run its custom code before or after the system has run the interface.

          * Action Type Field indicates what action you want this interface process step to execute. Select "XSL Transform" if you want the system to take SCALE data and perform a custom translation, using a specific XSL style sheet (specified in the Process Field). Note that any XSL transforms configured in the Interface Process Window will be ignored when processing error files.

          * Process Field identifies the specific XSL style sheet that the system will execute when this process step is run.

 

- Press OK when finished. The system will save your process detail record.
