Recovering an SQL Server Database

In the event that data recovery is needed, the complete database backup (along with the transaction logs) are used to rebuild the data to a specific point in time. The process below outlines the steps taken to perform this recovery task. These steps assume that a backup strategy is in place and functioning correctly. If for some reason the backup files are corrupt or missing, data loss will likely occur. Note that the recovery process will vary based on the disaster that occurred. The procedures listed below assumes that you can connect to the database, but the data is now corrupt from a scenario such as a user accidentally corrupting the data. See your consultant for any further questions that this topic does not answer.

 

IMPORTANT: It is always best to contact support if any form of recovery is necessary to help you evaluate your options. They will also be able to work with you on more advanced recovery procedures.

 

 

Procedures...

 

Access the database server.

  1. Save off the current transaction log to a backup. You can perform this task from SQL Server Enterprise Manager. If you go to the management folder, you will see an entry for SQL Server Agent. Upon expanding that level in the tree, you will see a category for Jobs. One of the jobs listed should be "Transaction Log Backup Job for DB Maintenance Plan." Right-click on the job and select "Start Job." This will backup the transaction log for you and save it to the usual location. Be sure that you wait until the job status is "Not Running" to continue. You can refresh the status by right-clicking the job and selecting "Refresh Job."
     
  2. Once the log is backed up, it is also recommended that you retrieve a complete database backup to allow for restoring the database to its present state. This backup provides options if the recovery process fails for some reason.
     
  3. Overwrite the existing database with a prior copy. Expanding the Database folder allows you to see all of the databases running on this server. Select the application's database and right-click it. Choose All Tasks | Restore Database. The system will display a window.

    SQL Server knows about all of the database backups that have occurred in the past for the database and selects the proper files for you. The basic goal behind this process is to restore the most recent successful complete database backup and then apply as many transaction log backups since that time that you may have. By making a backup of the transaction log at the start of this process, you can recover right up to the point that you started this step. In the graphic above, the Point In Time Restore option is selected and specifies that the database is to be restored to its state as of 2:00 PM on 9/23/2002. This can be changed as long as you have the backups. In this scenario, a user ran a bad SQL statement at 2:01, so we want to restore as close a possible to the point before that statement was ran.

    By default, you will need to estimate the time to recover to. There is no way to examine the transaction logs for a specific SQL statement unless you have purchased a third-party product intended for that purpose. You can always recover to a different point in time, if you find that you have restored to the wrong time.
     
  4. When finished, click the OK button and the recovery process will start.
