Routing Items To Inbound Quality Control (RF & Non-RF)

Below is a discussion of how the system will route a particular item quantity from a receipt to an inbound quality control location. If an item is defined to require quality control inspection (on the item master), the system will have the option of routing it to a QC location after the check in action is performed. The system will initiate this by displaying a window that shows how much of the quantity being checked in will be routed to a quality control location versus a standard storage location. The user can then choose to have the system divert the required quantity to QC, or cancel the check in request.

 

Notes...
  • The system will only check each receipt once for QC-eligible items. So, if you partially check in an item quantity that does not meet the full inspection quantity that is expected, the system will not check any further item quantities that you check in for this receipt. On the next receipt that includes this item, the system will check for the full QC inspection quantity again.

  • Keep in mind that inbound quality control only supports license plates created by the check in process, not downloaded receipt containers.

 

Setup Prerequisites for This Topic's Examples...

  • The receiving preference for the quality control flag is set to active.
     
  • The item (CMP-01) that you are receiving is QC eligible, and is slated to have 5 eaches inspected from each incoming receipt.
     
  • There is not already a checked in container for item CMP-01 that is currently participating in quality control.

 

Discussion: How the System Computes the QC Item Quantity...

The amount that the system will route to quality control is defined on the item master. This can either be a raw amount (for example, 50 eaches, 2 cases, etc), or a percentage value (for example, 5 percent of the total item quantity on each receipt that the warehouse receives).

  • If the configured QC amount is a discrete amount the system will convert it to the lowest unit of measure. If the user does not choose a UM, the system will treat the number as being in the lowest unit of measure.  
     
  • If the QC amount is a percentage the system will compute the quantity by applying the percentage against the total open quantity on the receipt for that item. The system will also convert this to the lowest unit of measure.

The system will then make some additional calculations in order to avoid sending an inappropriate quantity to quality control (such as 2.67 cases or 1.23 pallets). The system will take the amount it computed for the base UM above, and obtain the UM that is the second from the top increment in your storage template (for example, a case in an each-case-pallet hierarchy). Then, the system will take the original quantity (computed with the base UM) and round it down to the next whole increment of the new UM. If the quantity is not large enough to complete 1 whole increment of this unit of measure, the system will simply leave it in the base UM and not perform any rounding. The system will indicate that it has made special rounding calculations on the QC Inspection Verification Window.

 

For example (assume the each-case-pallet hierarchy; 20 pieces per case and 5 cases per pallet, which would make case the UM that the system would use for rounding):

 

Original QC Computation

 

System Would Round To

 
10 EA 10 EA (would not round down to 0 cases)
20 EA 20 EA (1 case)
30 EA 20 EA (1 case)
85 EA 80 EA (4 cases)
120 EA 120 EA (6 cases)

 

 

The following examples illustrate the process outlines above:

 

Procedures: Non-RF...

  1. Your warehouse receives in 50 EA of item CMP-01
     
  2. A receiving dock user checks in the full item quantity of item CMP-01 (50) in the Receipt Workbench. As a result of the settings for this item on the item master, the system will want to route a quantity of 5 of item CMP-01 to a quality control location. The system then will display the QC Inspection Verification screen. Any additional rounding calculations that the system needs to make will also be indicated in this window.
     
  3. If the user chooses OK the system will compare the quality control inspection amount versus the total amount of the item being checked in. Then, the system will split this item quantity into two check in requests. Below are the three scenarios depending on the quantity being checked in:

    a) If the inspection amount IS LESS THAN the checked in amount, the system will split off the inspection amount quantity. This is the correct scenario for this example; when the user locates the quantity, the system would split off 5 eaches for so it can be routed to a quality control location. The remaining quantity (45 eaches) will be checked in and as normal.

    b) If the inspection amount IS GREATER THAN the checked in amount,when the user locates the quantity, the system will route the entire item quantity to the quality control location. As a result, the checked in amount does not meet the requested inspection amount. In our example, this scenario would have been correct if the total checked in quantity had been less than 5 eaches, not 50.

    c) If the inspection amount IS EQUAL TO the checked in amount, when the user locates the quantity, the system will route the entire item quantity to quality control. In our example, this scenario would have been correct if the total checked in quantity had been 5 eaches exactly, not 50.If the user chooses Cancel the system will return you to the Receipt Workbench without checking in the item quantity.
