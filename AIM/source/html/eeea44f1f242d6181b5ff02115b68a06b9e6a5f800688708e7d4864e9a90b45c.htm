Configuring DIF TCP Protocol Properties

To setup the SCALE Device Integration Framework (DIF), you will need to address some configuration values in the application's database. The third step in this process is to configure the DIF protocol properties. A protocol property record contains the specific TCP data that is used to define the properties of a DIF endpoint. Note that there is no configuration screen to define protocols in the SCALE Configurations Explorer. You will need to configure these values directly in the application database's TCP_PROTOCOL_PROPERTIES table.

 

IMPORTANT: In order for changes to the TCP_PROTOCOL_PROPERTIES table to be reflected, you will need restart the DIF Processing Service.

 

See the SDK for detailed/additional information about DIF.

Procedures...

  1. Access your application database using a database editing tool such as SQL Server Management Studio.

  2. Access the TCP_PROTOCOL_PROPERTIES database table. Each database row represents the properties of a separate DIF endpoint.

  3. Define values for the following database fields:

    ACK (alpha 1): Represents whether or not the endpoint requires positive acknowledgments for messages. Supported values are Y (enabled) and N (disabled).

    ACK_DATA (alpha-numeric 50): Represents the value to use for acknowledgments.

    ACK_NAK_TIME_OUT (numeric 9,0): Represents the time (in milliseconds) for DIF to wait for an endpoint to send a positive/negative acknowledgment for a message.

    CONNECT_MODE (numeric 1,0): Reserved for future use.

    ENCODING (numeric 1,0): Represents the encoding type used. Supported values are 0 ASCII, 1 UTF8, 2 UTF16, UTF7.

    END_OF_MESSAGE (alpha-numeric 25): Represents the end of the TCP message.

    ENDPOINT ID (numeric 9,0): Represents the endpoint tied to this protocol. This is a required field.

    HEARTBEAT_ACK (alpha 1): Represents whether or not to send an acknowledgment for a heartbeat message. Supported values are Y or N.

    HEARTBEAT_ACK_DATA (alpha-numeric 50): Represents the value to use for acknowledgments for heartbeat messages.

    HEARTBEAT_DATA (alpha-numeric 50): Represents the regular expression data to use for heartbeat messages.

    HEARTBEAT_INTERVAL (numeric 9,0): Represents the time interval (in milliseconds) for DIF to wait between sending heartbeats.

    HEARTBEAT_TYPE (numeric 1,0): Represents the heartbeat type. Supported values are None (0), Constant (1), or Idle (2).

    KEEP_CONNECTION_OPEN (alpha 1): Represents if the connection needs to be kept open. Supported values are Y or N.

    KEEPALIVE_INTERVAL (numeric 9,0): Represents the keep alive interval for connected socket.

    KEEPALIVE_TIMER (numeric 9,0): Represents how often the TCP will send keep alives. This value is represented in milliseconds.

    LOCAL_PORT (numeric 9,0): Represents the TCP port that the endpoint will listen or connect on.

    MAX_QUEUE_INCOMING_CONNECTIONS (numeric 9,0): Represents the maximum number of connections that can be queued for the socket listener.

    NAK (alpha 1): Represents whether or not the endpoint requires negative acknowledgments for messages. Supported values are Y or N.

    NAK_DATA (alpha-numeric 50): Represents the data to be used for negative acknowledgments.

    PROTOCOL_TCP_ID (numeric 9,0): Represents the unique protocol identifier. This is a required field.

    REMOTE_ADDRESS (alpha-numeric 25): Represents the IP address of the endpoint machine. Note that this field is required only if the connect mode is 1 (connect).

    REMOTE_PORT (numeric 9,0): Represents the port of the endpoint machine. Note that this field is required only if the connect mode is 1 (connect).

    RESPONSE_RETRY_MAX_COUNT (numeric 9,0): Represents the maximum number of retries if no response from the MHE is received.

    RETRY_ATTEMPTS (numeric 9,0): Represents the maximum number of retries at reconnecting the endpoint connection (if no heartbeat is returned, or a bad ACK is returned).

    RETRY_INTERVAL (numeric 9,0): Represents the time between retry attempts at reconnecting the endpoint connection (if no heartbeat is returned, or a bad ACK is returned).

    SOCK_RCVBUF (numeric 9,0): Represents the number of bytes the Receive buffer is set to 1024.

    SOCK_SNDBUF (numeric 9,0): Represents the number of bytes the Send buffer is set to 1024.

    START_OF_MESSAGE (alpha-numeric 25): Indicates the start of the TCP message.

    USE_KEEPALIVES (alpha 1): Represents a system setting which facilitates to check if the socket is healthy. This is a setting at .NET socket level. It tells the socket to use internal keep alives.

    USER_DEF1 - USER_DEF6 (alpha-numeric 25): Represents user identified values, similar to other places in the system.

    USER_DEF7 - USER_DEF8 (numeric 14,5): Represents user identified values, similar to other places in the system.

  4. When finished entering values, commit the changes to the database and exit your database editing tool.
