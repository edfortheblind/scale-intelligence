Order Entry Values

These values are used by the system for various purposes in the Order Entry system. You can edit these values to meet your business needs.

 

 

Value Key

 

Value Description

 

10

Perform Item Availability Checking? - This value indicates that the system will check to see if an item quantity is in stock in the warehouse. This system check will occur during order entry or shipment creation.

 

20

Should In Pool Quantities Count As Allocated? - This value indicates whether or not the validation performed by the "Available Checking" value (described above) will include quantities for shipments already in the order pool. For example:

 

- When the value is Y, shipments in the pool that need this item will actually decrement the available quantity for the purposes of availability checking. Suppose you have 20 of item AA001 in the warehouse with 10 allocated. You also have a shipment in the pool that requires 4 of AA001. The system thinks there are 6 available (20 on hand - 10 allocated - 4 for the shipment in the pool = 6).

- When the value is N, (using the example above), the system thinks there are 10 available (20 on hand - 10 allocated = 10).

 

30

Header Customer Field Required - This value allows you to configure the Customer Field (header level) as being required during the order entry process. This validation will be enforced for both orders entered on the Order Entry Window (for multiple orders), and the Shipment Screen (for single orders).

 

40

Order Entry Ship To Max - This value defines the number of ship to addresses you can add to an order before the system will display a warning about loading default fields. When you leave the Ship To Selection screen, the system will alert you asking if you want the option of not populating the default customer information fields on the following screens: the Default Carrier/Service Field on the Routing Selection Screen, and the Default Categories Field on the Miscellaneous Selection screen. This is helpful because the large number of ship to's that the system has to retrieve data for could increase load time significantly.

 

50

Header Ship To Field Required - This value allows you to configure the Ship To Field (header level) as being required during the order entry process. This validation will be enforced for both orders entered on the Order Entry Window (for multiple orders), and the Shipment Screen (for single orders).

 

60

Order Id Prefix - This value defines the default value for the Order ID Prefix Field (in the Order Entry Window). The system will insert this value if no Order ID Prefix has been defined for the company in the Company Window.

 

70-140

Shipment Header User Defined Fields 1-8 Required - These values allow you to configure the user defined fields in order entry as being required fields. The system will perform a validation (in the Order Entry Window for multiple orders, and the Shipment Screen for single orders) to ensure that the user enters a value for the specified user defined field.

 

150

Allow different company on Shipment Hdr and Dtls? - This value indicates whether or not the system will allow the creation of a shipment that has different company values on the header and detail(s). Note that this affects shipments created via the Order Entry Window and the interface, not shipments manually created using the Shipment/Shipment Line Screens.
