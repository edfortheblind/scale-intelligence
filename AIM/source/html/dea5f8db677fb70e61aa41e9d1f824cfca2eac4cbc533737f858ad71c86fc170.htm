Create Multiple Requests For Excess Demand Checkbox

Use this checkbox to indicate that you want the system to create additional replenishment requests for "overflow" quantity that remains after a location is completely replenished. When demand replenishment is run, the system retrieves the replenishment master for an item. If the item needs replenishing, the system will check the master to see if the Create Multiple Requests for Excess Demand Checkbox is selected. Instead of visiting empty locations when the amount the system brings forward surpasses what the location can hold, the system creates additional requests for this one location.

If the checkbox is selected, the system will see if the following records exist for this item/company/location: an item location assignment record and an item location capacity record. If both exist, the system divides the demand quantity by the Maximum Replenishment Fill Percent. It will create enough replenishment requests to accommodate the quantity needed at the location. Note that if there is available quantity at the location (either On Hand or In Transit), the system will subtract that amount before generating requests. Note that when this checkbox is selected, demand replenishment will only support a single permanent location per item within the location selection. It will not fill other permanent locations. Also note that this setting only applies to permanent locations.

 

Example:
- Suppose you have a location that can hold 100 EA, and it is currently empty.
- Suppose then the system creates a replenishment request is created for 400 EA. If this setting is active, the system will create five replenishment requests for this location/item in the following manner:

[request 1] 100

[request 2] 80

[request 3] 80

[request 4] 80

[request 5] either 60 or 80 (depending on whether "Fill location" strategy is being used for this master)

 

Note that the system takes into account the Minimum Replenishment Threshold value when creating these requests. Therefore, in this example, the minimum threshold was set 20%, and the system created each request (after the first one) for a quantity of 80 EA (instead of 100 EA).

If the checkbox is not selected, the system will follow this process. If the amount to bring forward exceeds the location’s capacity (minus existing On Hand), the system will check for other To Locations defined in the empty location criteria record (identified on the replenishment master). Once these empty locations are filled, the system will not honor any remaining replenishment requests.

 

NOTE: It is not recommended that you use this setting if your warehouse uses the "round down" replenishment strategy.

  

Processing Steps...

The following are the system processing steps when using the Create Multiple Requests for Excess Demand setting:

  1. The wave creates all of the requests and marks the first one for work creation. It puts the wave number on all of these requests.

  2. The "Create Replenishment Work" scheduled job wakes up and creates work for the one request marked for work creation. When this is done, the system changes the wave number on all requests that it creates work for. The reason for this is that there could have been multiple waves that created requests or other requests that got marked for work creation since the last time the job ran. The job processes these all at once and creates work for them all at once. Note that the system does not put this work on hold since there is no way to release the “wave” that created it (since it was just a scheduled job that created the work).

  3. When the quantity in the location falls below the Minimum Replenishment Threshold, the system marks the next request for work creation so that the next time the scheduled job wakes up, work gets created for it.

  4. Then if you cancel the original wave, the system at this point removes all of the requests that have not had work created for them and are still associated with the original wave. It leaves any requests that have had work created. Since the scheduled job is meant to be “wave independent”, once it creates the work that work and replenishment request is no longer associated with the original wave.
